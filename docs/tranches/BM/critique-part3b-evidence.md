## Blocking

### 1. BM-1's reduced crossfade cannot run through glass's helper or its view-transition sheet

- **Where.** `waves/BM-1.md:22-23`, `:44`; `BM.md:167` (§9, "through `composables/motion/core/useViewTransition.ts`"); precepts `motion-canon.md` P6 (the toggle's change "rides the theme's one crossfade ... of 150 ms"); `messages/atlas.md:13`, `keyframes.md:11`, `gaggle.md:11`, `slides.md:11`, `dns-analysis.md:11`.
- **Claim.** The flip goes through glass's own `useViewTransition`; under Reduce Motion the page's crossfade runs 150 ms, carved by an `!important` rule in `styles/view-transition.css`, "so nothing cuts". If an engine lacks `document.startViewTransition` the wave stops, "since a second path would be a cut".
- **Evidence.** `R111` `src/composables/motion/core/useViewTransition.ts:144-150`: `if (!doc || typeof doc.startViewTransition !== "function" || prefersReducedMotion()) return runInstant(mutate);`, and `:18-20`: "Unsupported engines and reduced motion share one immediate state-update path; neither captures snapshots." `R111` `src/styles/view-transition.css:28-34`, in `@layer components`: under `prefers-reduced-motion: reduce`, `::view-transition-group(*), ::view-transition-old(*), ::view-transition-new(*) { animation: none !important; }`. So the helper BM-1 names starts no view transition under Reduce Motion, and the sheet it names already cuts every one. The helper is a public export (`@mkbabb/glass-ui/motion-core`), which daraksha imports (`src/veil/film/Layer.vue:20`); changing its reduced-motion branch changes that export's meaning, which `BM.md:34` puts in a major. The same helper already carries the no-API instant path BM-1 calls a cut (`:144-149`), and glass states no engine floor for the wave to read (`R111` has no `.browserslistrc`; `useViewTransition.ts:46-50` names Firefox 144 and callback-only Safari builds). An untyped theme transition would also pick up every untyped `::view-transition-*` rule a site writes (daraksha's `dk-ground-field` and `dk-ground-tint` groups, `src/styles.css:238-249`), and `useViewTransition.ts:90-98` says callback-only Safari builds reject the typed form.
- **Remedy.** BM-1 starts the theme's transition itself in `useGlobalDark` (typed `theme`, with an `html` class standing in where types are not supported), leaves the public helper's reduced-motion branch alone, and writes the reduced crossfade as a `theme`-scoped `!important` carve that out-specifies `view-transition.css:28-34`, scoping every theme rule to the type or class. It names the engine floor it reads (with its source) and what the flip does below it. Until that text exists, the five messages drop "the crossfade runs 150 ms, so nothing cuts".

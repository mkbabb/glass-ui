### W-7 · A-5 — the button stadium bound, resolved against the control rung

Atlas asked for a `min()` bound. **The mechanism is REFUSED as written**, per the GF-DOCK §STRIKE
precedent (*"the second is a token coupling; `from: 50%` IS the resolved corner"*): `min(9999px, …)`

The defect is real all the same. `--radius-pill` is `9999px`, which the engine clamps to half the


`--button-size` **is** the `--control-h-*` cohort, which is exactly what A-5's seating specifies

to the stadium it replaces; a wrapped or multi-line button **keeps single-line curvature**; the icon
arm (`:143-145`, `inline-size == block-size == --button-size`) still reads a circle; a
narrower-than-tall box still clamps, because the engine's own radius scaling is the resolved corner.

### W-9 · O-7 — the `class-names.ts:141` regex hole

O-7 widened this row from "which radius expresses which role" to **radius inheritance**, and named
the mechanism: *"`rounded-3xl`/`rounded-badge`/`rounded-card` silently no-op; Card, Toast and Dialog
already sit in it."*

The rule at `:141` was:

```ts
["rounded", /^rounded(?:-(?:none|sm|md|lg|xl|2xl|3xl|full|t|r|b|l|tl|tr|bl|br))?$/],
```

Two holes, both live:

1. **Every ROLE utility Tailwind emits from a `--radius-*` theme key matched nothing** —
   `rounded-card`, `rounded-pill`, `rounded-panel`, `rounded-dialog`, `rounded-tab`,
   `rounded-dock-card`, `rounded-media`, `rounded-xs`, and the arbitrary/var forms
   (`rounded-[6px]`, `rounded-(--radius-card)`). Unbucketed means **never conflicting**: a
   consumer's `rounded-card` and a recipe's `rounded-panel` both survived `cn()` and the winner was
   decided by **stylesheet order, not call order**. That is precisely "the override silently
   no-ops".
2. **`rounded-t-lg` matched nothing either** — the rule accepted a bare side, never side + value.
   `DialogContent.vue:263-266` ships four of these (`rounded-t-dialog` &c.).

Cured with **per-corner/per-side buckets**, mirroring the CSS longhands each utility writes, and an
**open value segment**. One radius bucket would be wrong: the corner longhands are disjoint from the
shorthand's other corners, so `rounded-card rounded-t-none` must keep BOTH. Ordering is corner
(2 letters) → side (1 letter) → shorthand, because `^rounded-t…` would otherwise swallow
`rounded-tl-…`.

Role names that merely *start* with a side letter are safe by construction — the side rules require
`-` or end-of-token right after the letter, so `rounded-tab`, `rounded-tooltip`, `rounded-badge`,
`rounded-lg`, `rounded-sm` all fall through to the shorthand bucket, which is correct: they set all
four corners. Five tests pin exactly that, because getting it wrong would make a tab radius and a
top-corner radius fight and one vanish.

Traces: `class-names.ts:140-175` · gate `radius-role-canon.test.ts:540-585` (§8, 5 tests) · the
pre-existing `tests/utils/cn.test.ts:76,112` cases stay green unchanged.

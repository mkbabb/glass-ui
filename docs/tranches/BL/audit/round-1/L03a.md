### P-03 — L03a-03 · fill-tint axis dead (HIGH)

`--glass-fill-tinted` is declared once, on `:root` (`src/styles/tokens/glass.css:6` opens `:root {`; the mix is at `:203-207`), and reads `var(--glass-fill-tint …)` there. `Chip.vue:69-77` writes `--glass-fill-tint: <tone>` on the chip element, but the inherited `--glass-fill-tinted` was substituted at `:root`, so the chip's input never reaches its own plate. The token comment at `:194-197` claims the opposite ("It reads the tint/strength axis DIRECTLY, so a consumer's `:tone`/`:section` hue reaches the plate"). The same file names this exact trap for `.glass-well` at `:180-181` ("composes it AT the element so a per-scope override re-resolves"). BK's CURSOR record (`execution/2026-09-17-o20-cure/CURSOR/RECORD.md:~157`) measured `--glass-fill-tinted` as "an ORDINARY custom property … that READS the two registered ones" and stopped there. It never checked where it resolves.

```

Three tones produce byte-identical paint. Wave shape, W-CHIP-GLASS: compose the mix at the consuming element (`.glass-chip`, `.glass-atom`), in the spirit of `.glass-well`, and delete the `:root` composite. No alias.

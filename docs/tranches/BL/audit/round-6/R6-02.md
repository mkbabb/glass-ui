## 2. Findings

### R6-02-01—`form.reset()` splits the model, the view and the submitted value; the Select submits a value nobody picked

- **Severity**: HIGH. **Relation**: NEW (proposed F-81, below). **Disposition**: BUILD. **Wave shape**: W-FORM-PARTICIPATION.
- **Evidence**: `reset-chromium.json`, `reset-firefox.json`, `reset-webkit-modelset.json`, `reset-*-select-mismatch.png`; `form-chromium.json` step `fa-after-reset`.
- **Probe**: in `#fa`, pick Plum in the Select, fill the rest, press Reset, retype the two text fields the reset visibly cleared, press Submit.
- **Observed**: the trigger shows "Plum" and `v-model` holds `plum`, and the form submits `fruit=apple` (Chromium, Firefox, Playwright WebKit). reka's BubbleSelect drops its empty option once the model has a value (`SelectRoot.js:163-166`), so the reset selects the first option, and no `change` fires to carry it back. Input and Textarea views clear while their models keep `me@example.com` and `hello`. Writing the same value back into the model does not restore the view (`remodel`: model `me@example.com`, view empty), because the model never changed. Checkbox, Switch, RadioGroup, Slider, NumberField and Command ignore the reset in model, view and FormData alike (`agree=yes`, `vol[0]=41`, `qty=25` stay).
- **Mechanism**: each control keeps its state in the Vue model and writes it one way into a form-associated element: reka's hidden proxy (`VisuallyHiddenInputBubble.js`, `BubbleSelect.js`) or the native `<input>` behind `v-model` (`Input.vue:35`, `Textarea.vue:46`). Nothing listens to the form's `reset`, so the platform's write to the form element never reaches the model or the view. 0 `reset` listeners in `src` or in reka's form controls (grep).
- **Born-RED**: after Reset, for every control, FormData, the model and the painted value agree, and all three equal the control's `defaultValue` (HEAD: `fruit` apple ≠ trigger Plum; `email` "" ≠ model).

### R6-02-02—Constraint validation reaches only the native text fields; the first invalid control's focus lands on an aria-hidden proxy

- **Severity**: HIGH. **Relation**: NEW (proposed F-81). **Disposition**: BUILD. **Wave shape**: W-FORM-PARTICIPATION.
- **Evidence**: `form-chromium.json` / `form-firefox.json` steps `fa-requestSubmit-invalid`, `fa-paint-after-invalid-submit`, `fa-reportValidity-focus`, `ax`; `form-{chromium,firefox}-invalid-submit.png`.
- **Observed**: after a blocked submit, `:user-invalid` matches Checkbox's, Switch's and RadioGroup's hidden proxies and Select's native `<select>`, but the visible controls keep their resting ink (Checkbox face border `oklab(0.216 … / 0.48)`, Select trigger border `…/0.14`, no `aria-invalid`, no `data-invalid`), and the AX tree reads `invalid: false` on each. Only Input and Textarea paint the rim (`control.css:236` keys `:user-invalid`). NumberField's `required` rides the hidden proxy (`<input aria-hidden name="qty" required>`), so the spinbutton is never `:invalid`. `requestSubmit()` and `reportValidity()` move focus to the proxy (`INPUT|agree|aria-hidden=true|tabIndex -1`, 2 engines): no ring is painted, and Chromium exposes the focused proxy as a nameless `checkbox` with `invalid: true`, the only invalid node in the tree.
- **Mechanism**: the platform's validity lives on the proxy, and the library's one invalid grammar (`controlStateAttrs`, `_shared/control.ts:45-48`) is driven only by the `invalid` prop. The `:user-invalid` arm reaches only controls whose native element is the visible one. `input/types.ts:46-47` says native validation "reach[es] the same one grammar"; for the reka-backed controls it does not.
- **Born-RED**: after a blocked submit, each empty required control paints the destructive rim, reads AX `invalid: true` with its own name, and the first one takes focus on its visible, named element (HEAD: 5 of 7 unpainted; focus on the proxy).

### R6-02-03—`<fieldset disabled>` does not reach the Slider thumb, the RadioGroup root or the field register's paint

- **Severity**: MED. **Relation**: NEW (proposed F-81). **Disposition**: BUILD. **Wave shape**: W-FORM-PARTICIPATION.
- **Evidence**: `form-{chromium,firefox}.json` steps `fb-*`; `form-{chromium,firefox}-fieldset-disabled.png`.
- **Observed**: the Slider thumb (`span[role=slider] tabindex=0`) stays focusable, reads AX not disabled, and ArrowRight moves the model 70→72, a value the form then drops (FormData is empty, correctly). The RadioGroup root `div` takes a tab stop (Shift+Tab walk, 2 engines), because reka counts natively-disabled items as focusable. Input, Textarea and NumberField are `:disabled` but keep `data-state="default"`, so they paint full ink with `cursor: default`, where the `disabled` prop paints 45% ink and `not-allowed` (`control.css:274-287`, `Input.vue:37,42`); the hover well still answers (`control.css:208` guards on `data-state` only). SegmentedTabs' buttons are `:disabled` at opacity 1 while ToggleGroup's dim to 0.5.
- **Mechanism**: disabledness is read from the `disabled` prop (`useFieldControlState`, `field/control.ts:25-40`; reka's `disabled` props), not from the element's own `:disabled`, so an ancestor fieldset, a platform state, never enters the state grammar.
- **Born-RED**: inside `<fieldset disabled>`, 0 focusable descendants, and each control's paint equals its `disabled`-prop paint (HEAD: Slider thumb and RadioGroup root focusable; 3 fields at default paint).

### R6-02-04—The proxy is written after the event that reads it, and a write to it is not read back

- **Severity**: MED. **Relation**: NEW (proposed F-81). **Disposition**: BUILD. **Wave shape**: W-FORM-PARTICIPATION.
- **Evidence**: `numberfield-enter-submit.txt` (Firefox, 3 of 3); `autofill-proxy-chromium.json`.
- **Observed**: in Playwright Firefox, typing `3` into the NumberField and pressing Enter submits nothing (the required proxy is still empty when implicit submission validates); typing `4,5` and Enter submits `qty=3` while the model is 45. Chromium submits the current value. A Checkbox proxy set `checked` with `input` and `change` (what autofill and form-filling extensions do) leaves the model `false` and the face unchecked while FormData says `agree=yes`. The Select proxy is the counter-example: the same write reaches its model (`plum`).
- **Mechanism**: the proxy is patched by a Vue watcher (`VisuallyHiddenInputBubble.js`, `watch(valueState)`) after the keystroke's handler returns, and reka's Checkbox, Switch, Radio, Slider and NumberField proxies carry no listener back to the model. It is R6-02-01's one-way sync seen from the other two sides: time, and a write from outside.
- **Born-RED**: Enter in a NumberField submits the value on screen in both engines; a proxy `change` moves the model (HEAD: stale `3` in Firefox; Checkbox model unchanged).

### R6-02-05—NumberField rewrites its text outside the editor's history and composition; redo multiplies digits and IME text wipes the value

- **Severity**: MED. **Relation**: NEW (proposed F-81). **Disposition**: BUILD. **Wave shape**: W-FORM-PARTICIPATION (the NumberField leg), or an upstream report to reka with a wrapper cure.
- **Evidence**: `undo-paste-{chromium,firefox,webkit}-*.json`, `numberfield-undo-repeats.txt`, `numberfield-locale-chromium.json` (step "IME commit '日本' …"; that file's paste step fires a synthetic `ClipboardEvent`, which inserts nothing, so it is a probe artefact; the real clipboard paste is in `undo-paste-chromium-*.json` and lands correctly).
- **Observed**: type `7`, Tab (commit), refocus, Cmd+Z: nothing changes; Cmd+Shift+Z: the field reads `777` (de-DE) or `77` (en-US), and blur commits it as the model (Chromium 3 of 3 runs, Playwright WebKit 2 of 2; Firefox treats both as no-ops). In Playwright WebKit an undo after a stepper write concatenates `1,212.11,234.5`, which blur wipes to `null`. Composing `日本` after a committed `5` leaves `5日本` in the spinbutton, and blur sets the model to `undefined`: the 5 is lost, and `update:modelValue` emits `undefined` against the declared `[value: number]` (`NumberField.vue:29-31`). Input and Textarea keep history and model in step in all three engines.
- **Mechanism**: reka writes the formatted string straight into the element (`NumberFieldRoot.js:163-164`, `inputEl.value.value = val`) on every commit, outside the undo stack; its `beforeinput` filter returns early while composing (`NumberFieldInput.js:108`) with no check at `compositionend`; and an unparseable commit sets the model to `undefined` (`NumberFieldRoot.js:175`) instead of reverting. The editing history and the composition belong to the platform; the model keeps a second copy.
- **Born-RED**: commit `7`, then undo and redo: the field reads `7` or empty, never `777`; commit `5`, compose letters, blur: the model stays 5.

### R6-02-06—`form` and `name` land on elements that carry no form association, with no warning

- **Severity**: MED. **Relation**: EXTENDS F-70 (round 5's landing clause). **Disposition**: FOLD into F-70's type-surface wave. **Wave shape**: the strictTemplates consumer fixture adds a form-attribute landing row.
- **Evidence**: `form-chromium.json` steps `fc-state`, `fc-submit`, `fa-filled`; DOM dump in the harness (`dom.mjs`).
- **Observed**: `form="fc"` on a Checkbox outside `#fc` lands on the `button` root (`<button data-slot="checkbox" form="fc" …>`) and renders no proxy, so `#fc` submits only the Input's `email=outside`; the Slider with `form="fc"` submits nothing. reka decides form participation by DOM ancestry (`shared/useFormControl.js:6`, `closest("form")`), so the platform's `form` attribute can never enable it. `name="view"` on SegmentedTabs and `name="align"` on ToggleGroup land as attributes on a `div` and submit nothing. ToggleGroup dropped reka and its form proxy (`ToggleGroup.vue:36-39`), and neither component declares or rejects `name`. Vue logs no warning (`warns: []`).
- **Mechanism**: F-70's: a consumer binding that names nothing is dropped silently. Round 5 asked every exported root to land an attribute on the element that carries its role; for form attributes that element is the form-associated one, and for SegmentedTabs and ToggleGroup there is none.
- **Born-RED**: a Checkbox and a Slider with `form=` outside the form submit their values; SegmentedTabs and ToggleGroup either submit `name=value` or reject `name` at type level (HEAD: 0 entries, no signal).

### R6-02-07—Keystrokes owned by an input method are acted on: the dock search routes, overlays dismiss, the container collapses

- **Severity**: HIGH. **Relation**: EXTENDS F-42 (R4-01-16's missing `event.repeat` read is the same mechanism: a key handler reads `e.key` and not the event's own state). **Disposition**: BUILD. **Wave shape**: the F-42 sweep takes one keystroke predicate, "owned by an IME" (`e.isComposing || e.keyCode === 229`), at the three dispatch seats below; the overlay leg's cure lands in F-22's dismissal seam, which already owns the Escape contract.
- **Evidence**: `dock-search-ime_dock_dock-search.json`, `dock-search-ime-enter.png`; `ime-dialog.json`, `ime-expandable.json`, `ime-consumer.json`.
- **Observed** (every keydown below carried `isComposing: true`, keyCode 229):
  - Dock search (`/dock/dock-search`, query `s`, then compose): Enter, meant to commit `日本`, selects "Surface axis", closes the results and scrolls the section list to it (the capture shows the scrolled list under `s日本`). Escape closes the results. ArrowDown, which cycles IME candidates, moves the result highlight to "Spacing scale" and calls `preventDefault`. Tab and ArrowRight, which move between IME segments, accept the ghost completion. Japanese, Chinese and Korean alike (15 of 15 cells as listed).
  - ExpandableContainer: Escape, meant to cancel a composition in its own Input, collapses it (`expOpen=false`) and drops focus to BODY, 3 of 3 languages.
  - Dialog: the same Escape closes the Dialog (`dlgOpen=false`), focus to BODY, 3 of 3.
  - Inline Command: Escape closes the list and wipes the query (`cmdOpen=false`, value `""`).
- **Mechanism**: `useFuzzySearch.onKeydown` switches on `e.key` alone (`src/composables/search/useFuzzySearch.ts:101-130`), exported through `useDockSearch` (`dock/index.ts:102`) and composed by the demo's documented handler (`demo/stories/dock/dock-search.vue:146-155`). The registry's `allowInInput` path skips the editable filter and reads nothing else (`useKeyboardShortcuts.ts:326-331`), and ExpandableContainer registers its Escape on that path (`ExpandableContainer.vue:213-217`). reka's DismissableLayer dismisses on any Escape (`DismissableLayer.js:77-82`, reka 2.10.5). No `isComposing` read exists anywhere in `src` or `demo` (grep: 0). Vue's `v-model`, reka's ComboboxInput and the registry's editable filter do guard, which is why Input, Textarea, the Command's Enter and arrows, and the app's `k`/`Escape`/`Enter` shortcuts stayed clean.
- **Born-RED**: in each seat above, a keydown with `isComposing` or keyCode 229 changes no state: the dock search keeps its results and highlight, the Dialog and the container stay open, the Command keeps its query (HEAD: 15 of 15 dock cells act; 6 of 6 overlay cells dismiss).

## 3. Proposed family

**F-81—The platform's form and editing state is a second copy, synced one way** (band E, beside F-40). Members: R6-02-01 to R6-02-05. Every reka-backed control keeps its value in the Vue model and writes it into a hidden proxy; Input and Textarea write it into their own element through `v-model`. The platform then reads and writes that element: reset, constraint validity, `<fieldset disabled>`, implicit submission, autofill, and the editor's undo history and composition. None of those writes is read back into the model, the view or the state grammar, and the one read that exists (Select's proxy `change`) is the exception that shows the others are absent.

Weighed against F-70: F-70 owns bindings the consumer writes that name nothing, and its round-3 clause "a write to the model must move the view" covers the model→view direction of a declared binding. The five rows here are the platform→model direction, through a contract no consumer binding names (`FormFieldProps`, `_shared/primitive.ts:17-21`, "stable public fields shared by form-associated Glass controls"; `NumberField.vue:21`, "native form behavior stay[s] Reka-owned"). Their cure is not a type surface or a runtime witness but one participation seam per control: `reset` restores `defaultValue` through the model; validity, disabledness and the form owner are read from the form-associated element into `data-state` and ARIA; the proxy is written synchronously, or implicit submission is deferred; the NumberField commit reverts instead of clearing. If the fold seat prefers F-70, R6-02-01 and R6-02-04 are its closest members; R6-02-02, -03 and -05 have no F-70 leg.

W-FORM-PARTICIPATION (new, one fixture): the `form.html` battery above as a consumer test in two engines, asserting FormData = model = paint after fill, reset, blocked submit, fieldset disable and Enter.

## 4. Coverage and gaps

- Driven: all 11 controls in the charter inside a native form (FormData on submit, reset, required and `:user-invalid`, `reportValidity`, `<fieldset disabled>`, the `form` attribute, `name` round trips); an autofill-style proxy write; IME composition in ja, zh and ko on Input, Textarea, NumberField, CommandInput, the Select trigger, a Dialog's Input, an expanded ExpandableContainer's Input and the dock search, with Enter, Escape, Tab, ArrowDown and ArrowUp (plus ArrowRight on the dock search) mid-composition while `k`, `Escape` and `Enter` shortcuts were registered; undo, redo and a real clipboard paste on Input, Textarea and NumberField; NumberField in en-US, de-DE and ar-EG, including full-width digits; Slider `aria-valuetext`; CDP AX name, invalid, required, disabled and value text per control.
- Clean (measured, not filed): Vue's `v-model` IME deferral; the registry's editable filter under composition; reka ComboboxInput's Enter and arrow guards; NumberField locale parsing and formatting in all three locales; Input and Textarea undo, redo and paste; Select proxy `change` → model; open-list typeahead on CJK characters; Command's `name` round trip (`cmd=b`); Checkbox and Switch `aria-required`.
- Not filed: closed-trigger Select typeahead selects nothing in any script, but a bare reka 2.10.5 Select behaves the same (`raw.html`), so it is upstream.
- Gaps: real browser autofill (headless Chromium has no `Autofill.trigger`; the UA `:autofill` fill over the glass well is unmeasured, and `src` has 0 `:autofill` rules); a real OS IME (CDP composition stands in, and Safari delivers the committing Enter with `isComposing: false` and keyCode 229, which the proposed predicate covers but no cell here measured); Playwright WebKit's Select click hangs in this harness, so its reset leg writes the model instead; the `/data/search` route composes the same `useFuzzySearch.onKeydown` and was not driven separately; VoiceOver and real Safari are unverified.

**Method.** A state's paint is a pixel diff of the control's box plus 8 px, rest against state: `changed` counts pixels whose largest channel moved by more than 10; `c3` counts pixels whose own contrast against the rest pixel is at least 3:1 (the WCAG 2.4.13 comparison); `p95` is the 95th percentile of that per-pixel contrast; `perim2` is 2 px times the box perimeter, the 2.4.13 minimum area. Row separation is a 5×5 median patch inside the highlighted row against the same patch in a neighbour row. Text contrast is the 98.5th-percentile pixel of each text run against the run box's median.

### R3-02-01—coarse pointers latch `:hover`

`node stickyhover.mjs` (cell P: `isMobile`, `hasTouch`, `matchMedia("(hover: hover)")` false, `(pointer: coarse)` true; tap with `page.touchscreen.tap`, then `activeElement.blur()` so the focus ring is not counted; load 18-43):

```
/containers/accordion             :hover true  bg oklab(0.28 … / 0.114)
```

The dock icon case is clean: it is a nav-mode control with no state, so every changed pixel is hover residue, and it clears only when the user taps something else. The library states the law itself at `src/styles/utilities/base.css:216-219`: "On touch `:hover` latches on tap and STAYS latched until something else is tapped, so an unguarded hover rung paints a control as permanently pointed-at." Menu rows (`menu.css:57-80`), Button's quiet arm (`button/styles.css:194`) and `.interactive-item` keep it. `node hovercensus.mjs` (postcss over every `.css` and `<style>` block in `src`) lists 26 `:hover` rules with no `(hover: hover)` ancestor; 22 set paint (the other four are a `will-change`, a `transition` and two reduced-motion scale resets). The G7 test (`tests/styles/engage-ladder.test.ts:249`) asserts that exactly one rung of the engage ladder is pointer-fine; it reads the token table, not these selectors.

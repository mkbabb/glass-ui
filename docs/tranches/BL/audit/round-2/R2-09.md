The mechanism line is from the WebGPU canvas contract, not from a Chromium trace: the drawing buffer is replaced after presentation, so a read from a later task returns transparent black; the probe shows the result (alpha 0 in 147/147 WebGPU readbacks). WebGPU has no equivalent, and the demo's live-path witness uses a Canvas2D stand-in, so the WebGPU path has never been exercised by that witness. This is the F-08 pattern (the WebGPU primary never gated) at the level of a feature.

At 120 fps, 300 ms/s is 2.5 ms of GPU per frame at the 1.5 DPR cap (canvas 2160×1350). This is on the fastest integrated GPU Apple ships; on a GPU with a tenth of its bandwidth the same work would not fit in a frame. That last point is a bound, not a measurement.

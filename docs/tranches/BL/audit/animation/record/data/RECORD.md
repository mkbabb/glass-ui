# The data family, frame by frame

Recorder: claude-opus-5-5. Read on 2026-11-13.

Components: card, surface, table, data-table, metric and animated numbers (countup), progress, skeleton, badge, alert, avatar, status-dot, scroll-progress-rim, fading-scroll, infinite-scroll.

## How this was read

- **Tree:** the published v11.0.1 (`e42bc2705`). Source lines below are v11.0.1's (`harness/tree-v11.0.1/src/`).
- **Server:** this recorder's own port, 5398. It served a build into `tree-v11.0.1/dist-demo-data` (`tools/build-data.sh`, `tools/serve-data.sh`), so the shared `dist-demo` was not touched. The build adds one page, `?c=data-state` (`mount/data-state.vue`), which binds the props the stories hold fixed to `window.__dat`: progress value, status and indeterminate; metric value; status-dot state; alert `v-if`; avatar src; badge text and variant; skeleton-to-content `v-if`; rim value; surface tier; and an x fading-scroll strip. Every other motion was driven on the component's own story page.
- **Engine:** headless Chromium 149 with GPU compositing. Every cell rendered at a median of 7.5 to 7.8 ms a frame, and no run dropped a frame (no gap over 25 ms in motion). Only the faults ranked first were re-read in Playwright WebKit (see "WebKit").
- **Cells:**
  - 1440 fine, light: every motion.
  - 390 coarse (CDP touch), light: card, card condense, surface scrub, data-table cards, progress, alert, infinite scroll.
  - 1440 dark: wherever colour animates (card fill, surface, row hover, progress error, badge, status dot).
  - 1440 reduced motion: once per component.
- **Scenarios:** `scenarios/*.json`, generated by `scenarios/make.mjs`, run by `run.sh` (batch 1, log `logs/batch1.log`) and `tools/batch2.sh` (log `logs/batch2.log`).
- **Rows:** `rows/<scenario>.tree-v11.0.1.chromium.<cell>.rows.json`, each with its analyser output beside it (`.faults.txt`, `.faults.json`) and its strips (`.segN.start.png`, `.segN.end.png`). WebKit rows are in `rows/webkit/`.
- **Pseudo-elements:** the status-dot silhouettes, the indeterminate band, the shimmer and the card header's backplate are pseudo-elements, which the harness sampler cannot read. `tools/pseudo.mjs` reads them on requestAnimationFrame (specs in `scenarios/pseudo/`, rows in `rows/pseudo/`), and `tools/psread.mjs` prints each run of change with its frame count. `tools/bandcheck.mjs` and `tools/bandcheck-runtime.mjs` read the indeterminate band directly. The rAF read of that band's opacity returned the base value, so that one property comes from these direct reads.
- **Text changes:** the sampler reads attributes, not text. Where a number or a glyph changes (countup, metric value, sort glyph), a `MutationObserver` mirrors the text into `data-txt` before the frame paints.
- **Frame numbers:** these are row indices in the rows file named with them. A frame number given without a file is in the 1440-fine-light rows of that scenario. `tools/rd.mjs <rows> <from> <to> <as.key>...` prints any channel per frame.
- **Strips:** the ones cited are copied to `strips/`. A strip tile's label is the row matched to the screencast frame, which can be a few rows after the analyser's frame; the rows are the record.

### Two things that run through the family

**A. The spring curves end with a step.** `--spring-dock`, `--spring-present` and `--spring-press` (`styles/tokens/scheme-spring.css:59-61`) end `0.973 97.959%, 1`. The last 2 % of the clock carries about 2.5 % of the travel, about 4 ms, so it lands in one frame. The step before it is about 0.4 %, which makes the last step about six times its neighbour. The curve is cut at the 2 % band and then forced to 1. Every dock-spring and present-spring motion in this family ends this way:

| Motion | Last step |
|---|---|
| Progress fill 40 → 80 (`prog-step` f113 → f114) | 5.05 px after 1.49 px |
| Progress fill 100 → 30 (f288 → f289) | 8.02 px after 2.31 px |
| Value-mark fades | 0.027 after 0.008 |
| Rim clip (`rim-step` f192 → f193) | 2.71 % after 0.52 % |
| Alert enter (`alert-mount` f33 → f34) | opacity 0.027 after 0.0045; blur 0.109 px after 0.018 px |
| Dot-ring fission (`inf-append` f38 → f39) | 0.021 after 0.013 |

The same curves run the dock, the switch and the tabs, so other families will see it too.

**B. Reduced motion cuts.** Every colour fade, every mount and every value change in the family lands in one frame under reduced motion. The universal carve sets `transition-duration: 0s !important` and `animation-duration: 0.01ms !important` (`styles/utilities/a11y-overrides.css:50-52`). That also overrides the reduced fades the recipes do declare: `gl-liquid-enter-reduced` (`styles/glass/liquid-enter.css:229`) never runs, and the alert appears whole (`alert-mount.1440-rm` f8, opacity 0 → 1). Two motions keep moving in the wrong way under reduced motion:
- The selectable card's press still scales to 0.97, now in one frame (`card-option.1440-rm` f1636 and back at f1661). P6 strips the transform; this cuts to it instead.
- The countup lands on its target in one frame.

This is census item 4, confirmed by frame here; it is not repeated under each component below.

# The overlay family, frame by frame

Recorder: claude-opus-5-5. Read on 2026-11-12 and 13.

Components: dialog, sheet (open and close), popover, tooltip, menu, select, command, toast.

## How this was read

- Tree: the published v11.0.1 (`e42bc2705`), served from the harness build on this recorder's own port (5395). Source lines below are v11.0.1's (`harness/tree-v11.0.1/src/`).
- Engine: headless Chromium 149 with GPU compositing. Every cell rendered at a median of 7.5 to 8.3 ms a frame. The faults ranked first were confirmed in Playwright WebKit (see "WebKit").
- Cells:
  - 1440 fine pointer, light, for every motion.
  - 390 coarse (real CDP touch), light: dialog, sheet, popover, tooltip tap, menu, select, toast.
  - 1440 dark: the menu row fill and the dialog close plate (the only colour tweens in the family that differ by scheme).
  - 1440 reduced motion, once per component.
- Scenarios: `scenarios/*.json`, generated by `scenarios/make.mjs`. They ran through `run.sh` (batch 1), `batch2.sh` (re-runs with strips anchored at marks, traced runs, the custom probes) and `webkit.sh`.
- Rows: `rows/<scenario>.tree-v11.0.1.chromium.<cell>.rows.json`, each with its analyser output beside it as `.faults.txt`. Re-runs with mark-anchored strips are in `rows/r2/`. Traced runs are in `rows/trace/` and WebKit runs in `rows/webkit/`.
- Custom probes in `tools/`:
  - `frost.mjs`: holds the reveal at fixed progress and crops the plate. Output in `rows/frost/`.
  - `pseudo.mjs`: reads the dialog close button's `::before` plate per frame. Output in `rows/pseudo-dialog-x.json`.
  - `tail.mjs`: real clicks during a closing surface's tail.
  - `survey.mjs`: lists the overlays each trigger opens. Output in `logs/survey.log`.
- `tools/rd.mjs <rows> <from> <to> <as.key>...` prints any channel per frame. The frame tables below come from it.
- Frame numbers are row indices in the rows file named with them. A frame number given without a file is in the scenario's 1440-fine-light rows in `rows/`.
- Strips: `strips/`, only the ones cited. Each is consecutive screencast frames, about every other rendered frame.

### Animations that run on more than one component

Five of the eight components enter and leave on one recipe, `.glass-reveal` (`styles/glass/reveal.css`). They are popover, tooltip, menu (with its submenu), select, and toast. The toast leaves by the vaporize instead.

- **Enter.** An `@starting-style` from-state on `[data-state="open"]` (`reveal.css:136-161`):
  - `scale` comes from 0.94 × (1.06, 0.945), on the register's spring;
  - `opacity` 0 → 1 and `filter: blur()` → 0, on `--ease-out`;
  - for a sided popover, an 8 px `translate`.
- **Exit.** The keyframe `glass-reveal-out` (`styles/animations.css:157-185`) runs from `opacity: 1; scale: 1 1` to the closed values, fade-led (opacity reaches 0 at 60 %), on `--ease-out` = `cubic-bezier(0, 0, 0.2, 1)`.
- **Registers**, as computed:

| `data-reveal` | Used by | Enter clock and curve | Exit |
|---|---|---|---|
| `overlay` | popover, toast | 450 ms, `--spring-panel` `linear()` (ζ 0.71, designed overshoot) | 250 ms keyframe |
| `menu` | menu, submenu, select | 200 ms, `--spring-present` `linear()` (ζ 1.0) | 120 ms keyframe |
| `tooltip` | tooltip | 200 ms, `cubic-bezier(0.16, 1, 0.3, 1)` | 120 ms keyframe |

The dialog and the side sheet do not use `.glass-reveal`. Each runs one JS spring (`useSpringMount`) whose scalar drives the plate and the scrim together.

## Faults

Each block gives the component, the motion, the fault kind, the frames and values, the strip, the cause where it can be named, and the smallest cure.

**O-1 · popover, menu, submenu, select, tooltip · reversed mid-open, or reopened mid-close · INTERRUPTION (a flash to full open)**

- Reversing the open at 30, 50 or 80 % does not turn from where it is. On the frame the state flips to `closed`, the surface jumps to fully open (opacity 1, scale 1 1). It then plays the whole 120 or 250 ms exit from there.

Menu (`rows/r2/menu-interrupt...`):

| At | Frames | Opacity |
|---|---|---|
| 30 % | f11 → f12 → f13 → f14 | 0.325 → **1.000** → 0.680 → 0.460 |
| 50 % | f87 → f88 → f89 | 0.526 → **1.000** → 0.674 |
| 80 % | f168 → f169 → f170 | 0.824 → **1.000** → 0.665 |

- Popover (`rows/r2/popover-interrupt...`):
  - At 30 %: f15 → f16 → f17 is 0.330 → **1** → 0.833, and the scale goes from (0.997, 0.912) to (1, 1) in the same frame.
  - At 50 %: f113 → f114 is 0.528 → 1.
  - At 80 %: f226 → f227 is 0.806 → 1.
- Reopening at 50 % of the close (popover, f426 → f427): 0.438 → **1**. There is no enter at all, because `@starting-style` applies only to a newly inserted element.
- Any quick open-then-dismiss hits it: a click and then Escape, a toggle on the trigger, or a hover popover crossed on the way past. It reads as a flash of the whole surface. The tooltip shares the recipe, but its enter is whole (O-5), so only its reopen-mid-close applies.
- Strips:
  - `strips/O1-menu-reverse-30.png`
  - `strips/O1-popover-reverse-30.png`
  - `strips/O1-popover-reopen-50.png`
- Cause:
  - `styles/animations.css:157-162` starts `glass-reveal-out` at an explicit `from { scale: 1 1; opacity: 1; filter: blur(0) }`. The enter is a transition, and a keyframe animation replaces it whole on the flip.
  - `reveal.css:199` binds that keyframe to every `[data-state="closed"]`.
  - The reopen has no keyframe and no `@starting-style` leg to run, so it lands open.
- Smallest cure: drop the `from` block from `glass-reveal-out`. A keyframe without a `from` starts at the element's current computed value, so the exit begins where the enter was interrupted. The reopen needs a transition leg back to the open values. Once the keyframe has no `from`, the base `.glass-reveal` transition list already gives one if `[data-state="open"]` is reached from a mid-exit computed value. Verify in both engines.
- Release: patch (CSS only, no API).

# R7-02—Content extremes: collection size and content shape

Seat R7-02, model claude-opus-5-5. HEAD 844eddc1 (src and demo byte-identical to 10.0.1). The consumer installs the same HEAD tarball as R7-01 (`mkbabb-glass-ui-10.0.1.tgz`, sha256 `de1bfe9a…8c05`), cloned into scratch. A single-page consumer harness (`captures/R7-02/harness/H.vue`, `ua.js`, `lib.js`) mounts one control per URL (`?c=&n=&shape=&dir=&v=`), exposes `__mount`/`__unmount`, and has a persistent-app variant that toggles the control with `v-if`. It was served on 5472. The built demo (`dist-demo`) was served on 5372, and only `/dock/overflow` was driven there. Chromium only: Playwright's headless shell. No WebKit or Safari cell was run, so none is claimed. Load average during runs was 9.9 to 37.3, recorded per cell in every JSON. Timing findings rest on growth ratios repeated in two passes, not on absolute numbers. Every cell ran at least twice with the same result, and the 60 shape cells differ in 0 measurements between passes A and B.

Probes and logs are in `captures/R7-02/probes/`, and the JSON and PNG outputs sit beside them (`count-*`, `scale-*`, `leak*`, `shape-*`, `values-*`, `toast-*`, `dock-*`, `demo-dock-overflow-*`).

## Findings

### R7-02-01 (HIGH, EXTENDS F-19): a wrapped overflow row pins the dock run to the wrapper, so keyboard focus lands off-port and End is undone

- **Mechanism**: F-19's `seatsOf = run.children` (`dock/composables/useDockRun.ts:71-75`). When the consumer wraps its seats in one element, as `/dock/overflow` does with a `div role="radiogroup"` (`demo/stories/dock/overflow.vue:67-75`), the run has one seat: the wrapper. Two consequences follow.
  - Every `focusin` inside the row calls `reach(wrapper)` (`useDockRun.ts:290-293`, bound at `:302`). The wrapper is always wider than the port, so `occluded` is true (`:158-167`). `anchorFor` resolves index 0 and returns scroll 0 (`:132-151`), and the spring glides the port back to 0 (`:181-197`). The focused control is never scrolled into view, and the story's own promise ("clicking a control past the fold recenters it into view", `overflow.vue:97`) does not hold.
  - The run's `keydown` (`:244-279`) sees `seats.length - 1 === 0` on End, so `to` is 0, which is in range. It calls `preventDefault` and `moveTo(seats, 0)`, which re-focuses the wrapper's first focus target. The inner radiogroup's End therefore lands on the first seat. Arrow keys survive only because `to = from ± 1` falls out of range and returns.
- **Probe**: `probe-demo-overflow.mjs` → `demo-dock-overflow-390-{a,b}.json` on the built demo at 390×800. Five ArrowLefts from Home wrap focus to "Camera" at x 360-400 while the port is 52-338. `scrollLeft` stays 0 of a 238 px range, so the focused control is fully outside the port (2 of 2 runs). End leaves focus on "Home" (2 of 2). At 1280 the row fits (`max 0`), so the defect needs overflow. Consumer cell `dock-40-a.json`: 40 `DockControl`s in one `div.flex` inside `GlassDock`. `focus()` on the last seat, "Zebra last", leaves it at x 1752-1792 against a 1208 px port with `scrollLeft` 0. `dock-40-lastfocus-a.png` shows no focused seat on screen.
- **Relation**: EXTENDS F-19, same mechanism. It adds the reach and End consequences to the snap-lattice consequence R3-01-15 recorded on the same story. R7-01-07 covered separators and foreign siblings, not wrappers.
- **Disposition**: BUILD, a W-DOCK-KEYBOARD row. **Wave shape**: seat resolution by `[data-dock-seat]`, or through groups, serves reach and the key map, not only the roving stop. The run defers Home and End to an inner composite that handled them (`defaultPrevented`). Born-RED on `/dock/overflow` at 390: after focus moves to any seat, that seat's rect lies inside the port. End focuses "Settings".

### R7-02-02 (HIGH, CONFIRMS F-18): a 40-seat dock rests as a 616×28 px lens

- **Mechanism**: F-18's `--dock-cap-rest: 50%` (`dock/styles/run.css:468`). A long run is F-18's first arming route. At 40 seats the plate is 1232×56, so the leading 50% resolves to a 616 px by 28 px ellipse.
- **Probe**: `probe-dock.mjs` / `probe-dock2.mjs`, `dock-40-a.json`: plate `border-radius: 50% calc(0% + 16px) calc(0% + 16px) 50%` at rest. The same dock with 8, 20 or 26 seats computes `9999px`. Frames at +50, +300, +1000 and +3000 ms (`dock-40-t*-a.png`) show the settled teardrop, and it is identical in pass B (`count-dock-40-b.png`).
- **Relation**: CONFIRMS F-18, at the count axis. No new mechanism.
- **Disposition**: FOLD into W-DOCK-EXTENT. **Wave shape**: unchanged. The born-RED gains a 40-seat horizontal dock whose rest corner computes a circular half cross-size.

### R7-02-03 (MED, EXTENDS F-51): SortableList and ToggleGroup mount, unmount and reorder in quadratic time

- **Mechanism**: each item does an O(n) lookup of its own place during render or registration, so the mount path is O(n²).
  - SortableList: every `SortableItem` computes `label = getItemLabel(id)` (`sortable-list/SortableItem.vue:17`), which is `items.value.find(...)` (`useSortable.ts:63-66`), and `SortableHandle` reads it for its name (`SortableHandle.vue:15`). Every reorder invalidates all n labels.
  - ToggleGroup: every item's `tabindex` is `ordered.value.indexOf(entry)` (`toggle-group/ToggleGroup.vue:132`, read at `ToggleGroupItem.vue:90`). `ordered` re-sorts the registry by `compareDocumentPosition` (`:68-78`) on every `triggerRef`. Unregister is `indexOf` + `splice` + `triggerRef` per item (`:125-128`).
- **Probe**: `probe-scale.mjs` → `scale-{a,b}.json` (mount ms at 1k/2k/4k, 2 passes), and `count-*-10000-{a,b}`.
  - SortableList: 72/228/934 ms, and 7,460-8,362 ms at 10k. Each doubling costs ×3.2 then ×4.1.
  - ToggleGroup: 41/126/520 ms, and 6,496-7,495 ms at 10k (×3.1, ×4.0). Unmount takes 11/40/200 ms and 1,981-2,034 ms at 10k.
  - Control: DataTable, which renders more DOM (180,053 nodes at 10k against SortableList's 170,036), is linear: 26/40/70 ms, and 186-193 ms at 10k. SegmentedTabs is 12/16/25 ms.
  - A keyboard lift → End → drop at 10k takes 3.1-3.9 s (both passes), and the announcement is correct.
- **Relation**: EXTENDS F-51 (synchronous costs on the mount path). The sub-mechanism is new to the family: a per-item linear lookup of the item's own position or label.
- **Disposition**: BUILD, a row in F-51's mount-path pass. **Wave shape**: a `Map<id, item>` or `Map<entry, index>` computed once per membership change (and the label map once per `items` change), never a scan per item. Born-RED: mount time at 4k over mount time at 2k is ≤ 2.5 for both controls (HEAD ≈ 4.0).

### R7-02-04 (MED, EXTENDS F-29): label slots have no inline overflow policy, so one unbroken token spills out of the plate or pans the page

- **Mechanism**: the label slots of the collection controls take their min-content width from their text and have no wrap, truncation or ellipsis owner. `overflow-wrap`, `word-break`, `text-overflow`, `ellipsis` and `truncate` have 0 hits in `select`, `command`, `sortable-list`, `carousel`, `tabs`, `toggle-group` and `toast`. SegmentedTabs is `white-space: nowrap` (`tabs/styles/segmented.css:275`). ToggleGroup items are `flex: none` (`toggle-group/styles.css:60,140`). The Select trigger's `[&>span]:line-clamp-1` (`select/SelectTrigger.vue:59`) clips a token without an ellipsis, because a single unbroken line never reaches the clamp. This is R4-02-15's "no overflow mode" on every sibling control, not only SegmentedTabs.
- **Probe**: `probe-shape.mjs` → `shape-{a,b}.json` + `shape-*-long-*.png`, with a 200-character unbroken label in fixed seats, LTR and RTL, 2 passes, 0 console output.
  - SegmentedTabs in a 384 seat: document `scrollWidth` 9,612.
  - ToggleGroup: 3,219, the page pans, and the stadium plates stretch to 3,195 px.
  - Toast: the title's ink runs from x 901 to x 4,070 while the plate ends at 1,264, so the text leaves the plate and the viewport (`toast-long-full-a.png`, `toast-long-390-a.png`: 41→2,814 over a 390 viewport).
  - SortableList: the row text runs to x 3,683 over a 320 list and is cut by the list's `overflow: clip`.
  - Command: the option text runs past its highlight pill and is cut at the list edge (`shape-command-long-ltr-a.png`).
  - Select trigger: the value is cut at 150 of 3,169 px with `text-overflow: clip`, and a bidi value is cut by 3 px.
  - DataTable scrolls inside its own `overflow-auto` wrapper, which is correct. Accessible names stay whole in every AX snapshot.
- **Relation**: EXTENDS F-29, through R4-02-15's row-budget clause. The mechanism is the same (content with no overflow policy breaks the row budget), and this adds the six other collection controls and the plate-spill half.
- **Disposition**: BUILD, a row of the W-DENSITY-DECIDE sweep. **Wave shape**: one label-slot rule in the control register: `min-inline-size: 0` on the flex item, and `overflow-wrap: anywhere` for multi-line holders or `text-overflow: ellipsis` for one-line seats, chosen per role. A clipped label keeps its full accessible name. Born-RED: every collection control with a 200-character label in a 384 px seat has `<main>` `scrollWidth` equal to `clientWidth`, and no descendant rect leaves the control's plate.

### R7-02-05 (MED, EXTENDS F-29): position rails and tab strips grow one pip or tab per member with no default window

- **Mechanism**: PagerDots renders every dot unless the consumer passes `windowFit` (`pager-dots/PagerDots.vue:136-143`, "Off (undefined) → show every dot", `:42-46`), and Carousel inherits it. SegmentedTabs has no overflow mode (R4-02-15). Each strip's width is linear in the member count, and nothing bounds it to its container.
- **Probe**: `count-{pager,carousel,tabs}-*-{a,b}` and `probe-390.mjs` (`w390-*`, 2 passes).
  - Rails: 8 dots make a 236 px rail. 20 dots make a 564 px rail over a 384 seat, and the phone page pans to 588 against 390. 10,000 dots make a 280,012 px rail, and the page's `scrollWidth` is 280,036.
  - Tab strips: 8 tabs are 957 px in a 384 seat, and 10,000 tabs pan the page to 1,195,244.
  - End still reaches the last member in both controls, and the focused member is scrolled into the viewport.
- **Relation**: EXTENDS F-29, R4-02-15's clause on the count axis, beside R7-02-04's content axis.
- **Disposition**: BUILD, the same W-DENSITY-DECIDE row. **Wave shape**: a rail windows by default to its container (container-measured `windowFit`), and a tab strip takes a scroll or collapse overflow mode. Born-RED: a 20-member Carousel and an 8-tab strip in a 384 px seat at 390 leave `<main>` `scrollWidth` equal to `clientWidth`.

### R7-02-06 (MED, NEW): the toast store evicts live toasts; a burst of 50 shows 5 and announces 5

- **Mechanism**: `ADD_TOAST` is `[new, ...toasts].slice(0, TOAST_LIMIT)` with `TOAST_LIMIT = 5` (`toast/use-toast.ts:5`, `:62`). This is a drop-oldest array, not a queue. A sixth toast removes the oldest entry whatever its state, so an open toast unmounts in the same frame with no exit (the `.glass-vaporize` path and `removeToast` in `Toaster.vue:48-66` never run), and a same-tick burst discards everything but the last five before any of them render. A `duration: Infinity` toast is the documented way to keep an actionable toast until it is dismissed (`use-toast.ts` `ToastOptions.duration`), so its action is lost.
- **Probe**: `probe-toast.mjs` → `toast-{a,b,c}.json` + `toast-5open-*.png`, `toast-after7-*.png`. Seven toasts 400 ms apart, all with `duration: Infinity`: at +2,075 ms "Toast 1" is removed from the DOM while it is still `data-state="open"`, and at +2,478 ms "Toast 2" is removed the same way (3 of 3 runs). A burst of 50 renders Burst 46-50 only, the 45 others are never rendered or announced (`role=alert` count 5), and the five open toasts before them vanish at once. The 10,000-toast cell (`count-toaster-10000-*`) is identical: 5 rendered.
- **Relation**: NEW. F-41 owns the toast's placement, its announce channel and its viewport owner. F-76 owns the stack's insertion geometry. No family owns the store's admission policy. It could ride W-TOAST.
- **Disposition**: BUILD (FOLD into W-TOAST). **Wave shape**: the store holds an unbounded queue and a visible window of `limit`. An arrival beyond the window waits, or it dismisses the oldest through the normal exit, never by splice. A toast with `duration: Infinity` is never pre-empted. Born-RED: 7 infinite toasts leave toasts 1-2 open or queued, with 0 DOM removals while `data-state="open"`. A burst of 50 eventually renders or announces all 50.

### R7-02-07 (LOW, NEW): a zero-member collection has no empty state; it paints chrome and announces "Slide 1 of 0"

- **Mechanism**: the count-0 arm is computed as if one member existed. PagerDots clamps a non-finite or zero count to 0 (`PagerDots.vue:88-90`), then sets `activeIndex` to 0 (`:91-95`) and announces `Slide ${activeIndex + 1} of ${count}` (`:326`). It renders its worm layer over an empty bed. GlassDock with no seats paints its plate. Select opens its content with no empty slot, while Command (`CommandEmpty`) and DataTable ("No rows yet") have one.
- **Probe**: `count-{pager,carousel,dock,select}-0-{a,b}`, `carousel-empty-a.png`, `dock-empty-a.png`, and `values-{a,b}.json`.
  - PagerDots and Carousel with 0 members: a live status reads "Slide 1 of 0", and an 8 px worm fragment is painted. The same happens for `count` null, undefined and NaN (2 of 2).
  - Dock with 0 seats: a 24×56 empty glass plate, with a `toolbar` that has no members.
  - Select with 0 items: opens a 10 px empty listbox. The trigger stays "Pick one", and no message is given.
  - Carousel `active` NaN or null is rewritten to 0 with no warning. `undefined` is left in the model while the rail paints slide 1 as current.
- **Relation**: NEW. No family owns the degenerate count. R7-01's families are UA-feature mechanisms.
- **Disposition**: BUILD, a small row. **Wave shape**: count 0 is a state. The rail and dock render nothing, or a consumer `#empty` slot. The announcer is silent at count 0. Select takes an empty slot like `CommandEmpty`. Born-RED: count 0 gives no live-region text, no painted plate or worm, and a Select with 0 items shows the empty slot.

## Measured and not filed

- **Memory after unmount: flat, and the first reading was a harness artefact.** The first count pass showed Select and CommandDialog retaining their trees after unmount (280,145 nodes at 10k, and +5,719 nodes per cycle at 200). The heap snapshot's retainer path (`probe-retainer.mjs`) runs from the `DevTools console` global handle to `div[data-dismissable-layer]`. That is Playwright's `waitForSelector` ElementHandles, which were never disposed. With locator waits (`probe-leak2.mjs` → `leak2-200-b.json`), all six overlay cells (glass Select, raw reka Select, CommandDialog, glass Dialog, raw reka Dialog, closed Select) hold DOM nodes flat across 4 mount/open/close/unmount cycles in a live app. The listener count steps once, 13 → 26 or 28, and then stays flat. The inline controls were flat in both passes (DOM counters return to 16).
- **Select and Command at 10,000 items are slow upstream.** Glass Select's first paint takes 8.8-9.5 s and opening to a painted listbox takes 15.6-21.0 s. Raw reka `SelectRoot` in the same harness takes 7.5-8.4 s and 13.4-13.8 s (`R7-02-selopen.log`, 2 passes), so reka accounts for most of the cost and the glass-ui wrapper adds 10-30%. Command at 10k takes 0.56-0.59 s to mount and 4.5-4.9 s to first paint, and typing five characters takes 4.5-5.2 s (reka Combobox filtering). The library offers no windowed door for either control. That is a scale ceiling to document, or an ask to reka, not a glass-ui mechanism.
- **Keyboard reach and typeahead are correct at every size.** Select End reaches the last option and "Zeb" types ahead to "Zebra last". At 10k the End-focused option's rect was outside the list viewport 250 ms after the key in both passes, which was not re-measured with a longer settle, so it is unverified. Command End and ArrowUp work, and "Zebra" filters to one row. The DataTable's last row is reachable by scroll. The SortableList keyboard drop moves the row to the end.
- **ZWJ sequences, combining marks and mixed-direction strings, LTR and RTL**: AX names are intact, nothing is written to the console, and RTL strips anchor to the inline start. The only overflow comes from count (R7-02-05).
- **A failing icon image in a dock seat**: the seat keeps 40×40, the image box is 20×25, the name comes from the seat's `aria-label`, and there is no layout overflow (`dock-img-fail-*`).
- **`null`, `undefined` and `NaN` on Select, Command, SegmentedTabs and ToggleGroup**: no errors or warnings, no selection, one tab stop, and the first interaction commits a value (`values-{a,b}.json`). The only degenerate cases are PagerDots and Carousel, in R7-02-07.
- **Console**: 0 warnings, 0 errors and 0 Vue warnings in every count, shape and value cell, both passes.

# R7-01—User-agent features acting on a mounted library

Seat R7-01, model claude-opus-5-5. HEAD 844eddc1; the consumer installs the HEAD tarball `mkbabb-glass-ui-10.0.1.tgz` (sha256 `de1bfe9a…8c05`, the same bytes as R6-01 and R6-02). Consumer harness: one Vite page (`captures/R7-01/harness/`) served on 5471. Built demo (`dist-demo`) served on 5371. Chromium only: Playwright's headless shell, plus `channel: "chromium"` for the minimum-font cells, because the headless shell ignores the `webkit.webprefs.minimum_font_size` preference (a 9 px probe stayed 9 px there and computed 20 px under `channel: "chromium"`). Load average during the runs was 18 to 27. No finding rests on a timing number. Every behavioural cell ran at least twice, and each run returned the same result.

Probes are in `captures/R7-01/probes/` and the JSON and PNG outputs sit beside them.

## Findings

### R7-01-01 (HIGH, NEW → F-83): closed disclosure content is outside find-in-page and text fragments, and the library strips the platform's opt-in

- **Mechanism**: reka's CollapsibleContent can keep closed content findable. With `unmountOnHide: false` it renders `hidden="until-found"`, and a `beforematch` listener opens the root (`reka-ui/dist/Collapsible/CollapsibleContent.js:64-69`, `:82`, reka 2.10.1). glass-ui deletes that attribute from the consumer's attrs at all three roots: `Collapsible.vue:44-45`, `Accordion.vue:46-47` and `AccordionItem.vue:32-33`. The default `unmountOnHide: true` therefore always applies, so closed content is not in the DOM and the browser's find machinery cannot reach it.
- **Probe**: `probe-find.mjs` → `find.json`, `find-tf-*.png`. For the needles in a closed Accordion item (ZEPHYRACC, QUOKKAACC) and a closed Collapsible (NARWHALCOL), each probe found the text 0 times in the DOM. `window.find` returned false. A text-fragment load (`#:~:text=…`) did not open the item, and the model stayed `undefined`/`false`. Control in the same page: a consumer tab panel with `hidden="until-found"` and `@beforematch` was revealed by the same text fragment (model `a` → `b`). The harness can therefore drive the UA's find-and-reveal path. A typed Ctrl+F cannot be driven headless because the find bar is browser UI, and CDP has no `Page.searchInPage`. Text fragments and `window.find` run the same matcher and fire `beforematch`.
- **Relation**: NEW. No family owns find-in-page or `until-found`. The registry has 0 hits for `until-found`, `beforematch` and `find-in-page` outside the round-7 charter row.
- **Disposition**: BUILD. **Wave shape**: W-FINDABLE. Closed disclosure content renders `hidden="until-found"` (`unmountOnHide: false` as the library default, or the consumer's attr forwarded instead of stripped). `beforematch` opens through the model, so a controlled `v-model` sees the change. Born-RED: in the consumer fixture, loading `#:~:text=<needle>` against a closed AccordionItem gives `modelValue === item.value`, and the needle's rect is inside the viewport.

### R7-01-02 (MED, NEW → F-83): off-snap Carousel members are inert, so find cannot reach them and nothing scrolls them in

- **Mechanism**: `CarouselItem.vue:54-55` puts `inert` and `aria-hidden` on every non-active member. Inert subtrees are excluded from find-in-page, text fragments and selection. The strip is a native scroll-snap container (`CarouselContent.vue`), so if the members were not inert, the platform's own find would scroll the strip to the match.
- **Probe**: `find.json` cell PANGOLINCAR (slide 3 of 3). The text is in the DOM, but `window.find` returns false. The text fragment leaves `active` at 0 and `scrollLeft` at 0. `find-tf-PANGOLINCAR.png` shows slide 1.
- **Relation**: NEW, in the same family as R7-01-01 because the mechanism is the same: collapsed or off-screen content is withheld from the UA's find machinery rather than hidden in a way find can reveal.
- **Disposition**: BUILD (a W-FINDABLE row). **Wave shape**: off-snap members drop `inert` and take the tab-order exclusion on their focusables instead (`tabindex=-1`, which the member already governs). The platform's find then scrolls the snap strip, and `scrollsnapchange` commits the index. Born-RED: `#:~:text=<slide-3 needle>` gives `active === 2`.
- **Observed, not filed**: the collapsed dock layers (`/dock/layers`) are inert crossfade faces at opacity 0, so find skips them. That is chrome, not document content. The demo's virtual section window (`/data/virtual-section`) cannot find "Section 850" because the section is not rendered. That window is demo-owned (`demo/composables/virtual`), and not rendering is inherent to windowing.

### R7-01-03 (HIGH, NEW → F-84): a force-mounted disclosure paints its content while closed

- **Mechanism**: with `forceMount`, reka's Presence is always present, so the content never takes `hidden` (`CollapsibleContent.js:74`, `:82`). The only closed rule is `.disclosure-content[data-state="closed"] { animation-name: disclosure-close }` (`_shared/disclosure/disclosure.css:111-113`). The keyframes (`:13-23`) have no fill mode, and no closed rule sets `block-size: 0`, `hidden` or `inert`. When the close animation ends, the box returns to its natural size. "Closed" exists only as the last frame of a transition.
- **Probe**: `probe-inject.mjs` → `inject.json` (fmLoad, fmOpen, fmClosing, fmClosed) and `forcemount-closed-after-cycle.png`, `find-tf-AXOLOTLFM.png`. At load, with the model false, the content is `data-state="closed"`, 21 px tall, opacity 1, and the trigger reads `aria-expanded="false"`. 150 ms into a close the box is 2 px at opacity 0.07, and 1.2 s later it is 21 px at opacity 1 again. The AX tree exposes a `region` containing the "closed" text, `window.find` matches it, and select-all copies it.
- **Relation**: NEW. The public `forceMount` prop (`CollapsibleContent.vue:12,45`, `AccordionContent.vue:12,45`; its JSDoc says "Keep the region mounted while closed") produces a closed state that is visually and semantically open. The Accordion shares the same stylesheet rule. That claim is from source; only the Collapsible was driven.
- **Disposition**: BUILD (a W-FINDABLE row, since `hidden="until-found"` gives the closed state a rung). **Wave shape**: the closed state is a state, not a frame. Closed content carries `hidden="until-found"` (or `block-size: 0; visibility` after the exit) whether mounted or not. Born-RED: force-mounted and closed after one open-close cycle gives box height 0, no AX `region` text, and the text is still findable through `beforematch`.

### R7-01-04 (MED, NEW → F-85): the typewriter hands its phrase to the clipboard twice, plus its cursor glyph

- **Mechanism**: `TypewriterText.vue` publishes three text copies of one phrase: the `sr-only` accessible span (`:4`), the `visibility: hidden` reserves (`:8-15`) and the `aria-hidden` visual layer with a literal `|` cursor text node (`:17-40`). `aria-hidden` removes nodes from the AX tree only. Selection, copy, find and translation still read every DOM text node that is not `visibility: hidden` and not inert.
- **Probe**: `probe-copy.mjs` → `copy.json`. Select the component and copy. Mid-typing, the clipboard reads `"Typewriter says hello world\nTyp |"`. Settled, it reads `"Typewriter says hello world\nTypewriter says hello world |"`. Select-all copy of the page contains the phrase twice with the cursor glyph. `probe-twfind.mjs` → `typewriter-find.json`: at 300 ms, `window.find("hello world")`'s only match is the 1 px clipped `sr-only tw-accessible` span, so find highlights an invisible match. At 4 s, the invisible match still comes first and the painted one second.
- **Relation**: NEW. F-76 owns the typewriter's reserved extent (R3-01-08), not its text copies.
- **Disposition**: BUILD. **Wave shape**: W-TEXT-ONCE. Each phrase has one DOM text copy. The visual layer and the cursor paint from generated content (`content: attr(data-…)` on pseudo-elements, which selection, find and translation do not read), or the visual layer carries `user-select: none` plus `translate="no"`, and the settled phrase becomes the one selectable copy. Born-RED: copying the settled component yields exactly the phrase, once, with no `|`, and the first find hit's rect is the painted glyphs.

### R7-01-05 (MED, NEW → F-85): page translation freezes a stale glyph into the typewriter and spills it past its reservation

- **Mechanism**: the same one-DOM-copy rule, applied to translation. A translator replaces the visual layer's text nodes with `<font>` wrappers. Vue then patches `{{ leadingText }}` with `textContent`, which wipes the wrapper and shows live English. It patches `{{ tailChar }}` (a text node beside the cursor `<span>`, `TypewriterText.vue:19-31`) on the detached node, so the translated tail glyph stays. The visual layer is `position: absolute` over reserves sized from the untranslated phrase, so it overflows into the next block (F-76's absolute-layer clause, reached through translation).
- **Probe**: `probe-translate.mjs` → `translate.json`, `translate-after.png`, `translate-after-crop.png`. Translation is simulated Google-Translate style: every text node becomes `<font><font>«…»</font></font>`. After it, the typewriter reads `"Typewriter says hello worl«r»«|»"` for over 3 s, the final "d" never paints, and the crop shows the phrase wrapping over the SortableList below. Everything else stayed intact: the Accordion opened and switched, Tabs switched, the keyboard reorder moved the right rows (`tasks` model and DOM agree), pushing a row rendered it, and `app.unmount()` emptied `#app` with 0 console errors and 0 page errors.
- **Relation**: NEW, in the same family as R7-01-04: presentational text copies are exposed to the UA's text features. `translate="no"` has 0 hits in `src`.
- **Disposition**: BUILD (a W-TEXT-ONCE row). **Wave shape**: the per-glyph layer is `translate="no"` or generated content, and the accessible span is the phrase a translator rewrites. Born-RED: after the simulated translation, the settled visual text equals the settled source phrase, and the visual layer's rect stays inside `.tw-root`.

### R7-01-06 (MED, NEW → F-86): SortableList row bodies cannot be selected, contradicting the handle-only contract

- **Mechanism**: `.sortable-item { user-select: none; -webkit-user-select: none }` (`sortable-list/styles.css:74-75`) sits on the whole `<li>`, but the default `handleSelector` is `[data-sortable-handle]` (`SortableList.vue:22`, `useSortable.ts:38-42`), so the row body starts no drag. The demo claims the opposite: "Only the grip button starts a drag—the row body stays selectable text" (`demo/stories/data/sortable-list.vue:98`). The same `select-none` sits on the non-interactive static Chip (`chip/chipVariants.ts:4`), a display tag with nothing to press.
- **Probe**: `copy.json` sortDrag. A mouse drag across "Beta task" selects `""` (computed `user-select: none` on both the span and the li) and fires 0 reorders. A double-click selects `""`. Select-all copy of the consumer page leaves out all three row labels. `copy-demo.json` shows the same on `/data/sortable-list`: 6 row labels are unselectable, the handle-only story included. On `/forms/chip`, the "Static", "Pill" and "Cell" chips are unselectable.
- **Relation**: NEW. No family owns `user-select`.
- **Disposition**: BUILD. **Wave shape**: `user-select: none` moves to the grip (`.sortable-handle`), and to the row only while it is lifted (`[data-sortable-lifted]`). On the chip it moves to the interactive and removable modes. Born-RED: select-all copy of a handle-mode list contains every row label, and a drag across a row body selects its text with 0 reorders.

### R7-01-07 (HIGH, EXTENDS F-19): Arrow keys cannot cross a DockSeparator, and an injected sibling breaks Home and End

- **Mechanism**: F-19's `seatsOf = run.children` (`dock/composables/useDockRun.ts:71-75`). A `DockSeparator` is a direct child of the run, so it becomes a seat. `moveTo` returns early when the seat has no focus target (`:229-233`), and `onKeydown` has already chosen that index (`:244-273`). Focus therefore stops at the seat before any separator. A zero-size sibling injected by an extension is also a seat. Prepended, it makes `Home` a no-op. Appended, it makes `End` a no-op.
- **Probe**: `probe-dockinject.mjs` → `dock-inject.json`, on `/dock/controls`, run 2, seats Search, Notifications, separator, Overview, Activity. With no injection, five ArrowRight presses give `Search → Notifications → Notifications ×4`, so Overview and Activity are reachable only with `End` (2 of 2 runs). With a prepended `<span style="display:none">`, `Home` leaves focus on Notifications. With it appended, `End` leaves focus on Search (2 of 2 runs each).
- **Relation**: EXTENDS F-19. The mechanism is the same (seats resolve from `run.children`), and this adds two members the family does not yet list: separators and foreign siblings.
- **Disposition**: BUILD (W-DOCK-KEYBOARD). **Wave shape**: the family's `[data-dock-seat]` resolution also covers these members. Separators and unmarked nodes are never seats. Born-RED: ArrowRight ×4 from the first seat on `/dock/controls` run 2 visits all four buttons, and Home and End work with a foreign `<span>` prepended and appended.

### R7-01-08 (MED, EXTENDS F-19): the Carousel indexes members by strip children, so one injected node shifts the active member by one

- **Mechanism**: F-19's mechanism in another component. `CarouselContent.vue:39-42` `members()` is `el.children`, the MutationObserver re-counts on `childList` (`:81-85`), and `deck/composables/useDeckSnap.ts:63-66` measures pitch and commits the snap index from the same children. A foreign first child becomes member 0.
- **Probe**: `probe-car.mjs` → `carousel-inject.json`, `carousel-*-scroll1.png`. Scroll the strip to 380 px, which shows slide 2. With no injection, states are `prev, active, next` and `active` = 1. With a prepended zero-size `div`, states are `prev, prev, active` and `active` = 2: slide 2 is painted but is `inert` and `aria-hidden`, and off-screen slide 3 is announced as current. Appending leaves states correct. 2 of 2 runs each.
- **Control, CONFIRMS F-70 R3-01-01**: in all six runs, writing `active = 2` from the parent leaves `scrollLeft` at 0 and states `active, next, next`.
- **Relation**: EXTENDS F-19. The member set comes from the element children of a container the library does not own exclusively. It is filed here by mechanism, and the family title should widen from the dock to "member sets resolved from element children".
- **Disposition**: BUILD. **Wave shape**: members resolve from `[data-slot="carousel-item"]` (and the deck's own member marker), not from `children`. Born-RED: with a foreign first child, scrolling to pitch 1 gives `active === 1`.

### R7-01-09 (MED, EXTENDS F-43): Back and Forward land at the top, and a fragment URL never arrives

- **Mechanism**: an arrival that no one owns, now for scroll position. `<main>` owns route scroll, and the shell's one scroll owner resets it to 0 on every `route.path` change, popstate included (`demo/shell/AppShell.vue:135-144`). The router has no `scrollBehavior` (`demo/router.ts:100-105`), and the window-level scroll it saves is `{0,0}`. For fragments: the route content mounts after `load`, after the browser's fragment scroll has already given up. Nothing replays `location.hash`: the router has no scrollBehavior, and the library's sidebar kit (`composables/sidebar/useScrollTo.ts`, `useLazyLoader`) reads no hash. An in-page ToC jump writes no hash either. The library already owns this seam for the deck (`deck/composables/useDeckHashSync.ts`) and not for the sidebar kit.
- **Probe**: `probe-restore.mjs` → `restoration.json`. On `/display/badge`, scroll `main` to 700 and push `/display/card` through the shell nav. `goBack()` gives `/display/badge` with `scrollTop` 0 (`history.state.scroll = {0,0}`). Scroll to 250 on Card, then `goForward()` gives 0. 2 of 2 runs. `probe-frag2.mjs` → `fragment-load.json`: fresh loads of `/navigation/toc-tracking#sec-{0-1,1-2,2-0,9-1}` give `:target` null and `scrollTop` 0 in 12 of 12 cells. `sec-9-1` never renders, because the lazy loader holds 24 sections. `probe-frag.mjs` → `fragment-restoration.json`: a ToC click scrolls to `sec-6-0` and leaves `location.hash` as `""`. A same-document `location.hash = "#sec-2-2"` does land (`:target` set), because the node exists by then.
- **Relation**: EXTENDS F-43. The registry holds popstate's missing transition (R2-02-13), not its scroll position or the fragment arrival.
- **Disposition**: BUILD (W-ARRIVAL's router row). **Wave shape**: the arrival owner restores per-entry scroll of the owning scroller on popstate, and resolves a hash after the route's content commits. The sidebar kit gains the deck's hash seam: read `location.hash` into `ensureTargetLoaded` plus `scrollTo`, write it on a ToC jump, and honour the target's `scroll-margin` instead of the literal `scrollOffset = 16`. Born-RED: Back restores 700 ± 1, and a fresh load of `#sec-9-1` gives `:target` = `sec-9-1` inside the scroller's port.

### R7-01-10 (MED, NEW → F-87): the shell's destinations are buttons, so the browser's link features do not exist

- **Mechanism**: the demo shell's nav seats (the rail and the bottom-dock page strip) are `<button>`s that call `pushRoute` (`demo/shell/useShellNavDock.ts:6`, `SidebarDock.vue:77-82`). The ToC entries on `/navigation/toc-tracking` are `<button data-scroll-target>` (`demo/stories/navigation/toc-tracking.vue:131-147`). No destination carries an `href`, so open-in-new-tab, middle-click and modifier-click, "Copy link", the status-bar URL and prefetch are all absent. `useDockRun.ts:77-81` itself treats `RouterLink`'s `aria-current` as the route-dock seat.
- **Probe**: `restoration.json` `nav` and `modClick`. The "Card" destination is `{tag: BUTTON, href: null}`. A ControlOrMeta+click on "Badge" navigates the current tab, and the page count stays 1 → 1 (2 of 2 runs). `/display/buttons` exposes 4 `a[href]`, none of them a destination.
- **Relation**: NEW. F-20 is phone-cell geometry and F-19 is dock ARIA; neither owns link semantics.
- **Disposition**: BUILD (small). **Wave shape**: the shell's seats and ToC entries are `RouterLink`s (the dock seat already accepts one), and `pushRoute` hooks `RouterLink`'s navigate rather than replacing the anchor. Born-RED: a Meta-click on a rail seat opens a second page, and every destination has an `href`.

### R7-01-11 (LOW, NEW → F-88): the chip's remove glyph and the xs Button seat do not follow the user's minimum font size

- **Mechanism**: the × is a text glyph inside a fixed `1.25rem` square (`styles/glass/glass-chip.css:73-78`), and the xs Button has a fixed `block-size: 28px`. A minimum font size clamps computed `font-size` but not `rem` or `px` boxes, so the glyph outgrows its seat. R4-02's root-size sweep scales rem boxes with the text and so could not see this.
- **Probe**: `probe-minfont2.mjs` → `minfont2.json`, `minfont2-*.png` (`channel: "chromium"`, minimum 0 vs 24). On `/forms/chip`, the remove glyph box is 20×20 with text 15×34, a 14 px vertical spill. On `/display/buttons`, the "Extra small" box is 28 px with text 30 px (1 px). Badges, dock labels, the pager, the avatar, metric, data table, checks, slider and number field show no new clip at 20 (`minfont-*-{0,20}.json`, pairs in `minfont-*-pair.png`). The `/display/buttons` matrix's Delete buttons already spill 15 px at the default size, which is F-33 specimen layout, not this finding.
- **Relation**: NEW, LOW. It may FOLD into R7-02's content-extremes family if that seat registers one for fixed-size seats.
- **Disposition**: FOLD. **Wave shape**: icon glyphs in seats become SVG icons (the library's lucide register), and seat block sizes become `min-block-size`.

## Clean cells (driven, expected result held)

- An external text drop onto Input (CDP `Input.dispatchDragEvent`) writes `DROPPED` to both the DOM and the model, with `input` fired (2 of 2 runs, `dnd.json`). A file drop onto Input, a SortableList row or a grip does not navigate and does not change the model. SortableList ignores foreign drops, which is correct for a pointer-only sortable.
- A password-manager-style `<span tabindex=0>` injected after the Input's `<input>` changes neither the input's rect nor its parent's. The shortcut registry fires `k` and `/` with focus on the injected icon, which is correct because the icon is not editable. Typing `k/` into the Input fires neither (`inject.json`).
- Translation left no console errors across interaction and unmount, and dropped no models (R7-01-05).

## Gaps

- A typed Ctrl+F needs the browser's find bar, which headless does not expose, and CDP has no `Page.searchInPage`. The find cells use text fragments and `window.find`, the same matcher and the same `beforematch` path. A headed pass with the real find bar is still owed.
- Only Chromium was driven. Playwright WebKit and Firefox were not run for these cells, and no Safari cell exists (safaridriver not enabled).
- No real extensions were installed. Injection is simulated with a zero-size or `display:none` node and a key icon. Grammarly-style contenteditable overlays were not driven, and their shadow-root keystroke path is F-81's.
- A native text drag from a selection did not start in headless Chromium, so the drops come from CDP-synthesised external drags.
- The Accordion's `forceMount` closed paint is from source only (the shared rule). The dock's `scroll-margin` under a fixed consumer dock was not driven, because the demo lays the dock out as a grid row and nothing overlaps content. `useScrollTo`'s `document.getElementById` (F-81's mechanism) and its fixed `behavior: "smooth"` under reduced motion were read in source and not driven.

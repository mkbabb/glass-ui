## Library faults met

- **N1 (new, not in LIBRARY-FAULTS.md): an icon-shaped Chip squeezes its glyph.**
  - `src/components/chip/chipVariants.ts:7-16`: `SIZE[size]` (for example `px-5 py-2` at `lg`) and `SHAPE.icon` (`p-0`) are joined without a merge.
  - In the built CSS, `px-5` beats `p-0`, so a 48×48 `lg` icon chip has an 8 px content box. A 24 px lucide glyph renders at 8×24 (measured: chip 48×48, svg width 8, height 24).
  - Every icon chip size is affected the same way.
  - Cure: merge the classes (`cn`/tailwind-merge) or give `SHAPE.icon` an inline padding that out-ranks the size row.
  - Release: patch.
  - The Icons page shows the icons without a Chip rather than patching the padding.
- **Observed, not a fault:** a static Chip ignores `tone`. The tonal fill paints only in its active state (`accent-tone.css`), so a "pop" plate needs a selectable chip that is on.
- **F3 (muted ink):** not met. The page authors no muted text.
- **Shadows in dark:** the three elevations are hard to tell apart on the dark stage (crop `shadows-d1440.png`). That is the shadow tokens' strength over a dark ground (`src/styles/tokens/shadow.css`). It is reported, not recoloured.

## 1 · H10-1: DEL exits 2 when nothing is in scope

### 1.1 · What landed (`deleted-mechanisms.mjs`)

After the scope is read (H8-1: `src/`, `demo/`, `tests/`, and every path the patch touches that exists), DEL checks how many text files it holds. With **0**, it prints `0 text files in scope under <root>: nothing read`, then `FAIL (nothing read: the tree does not exist)` or `FAIL (nothing read: no text file in scope)`, and exits 2 before any row is read. This matches H9-4's `rows.mjs` refusal (`variantOrExit`). It used to print a ✓ for every declared name and `PASS (n gated rows)`.

**Departure: the same refusal in SWEEP** (`prose-sweep.mjs`). With 0 touched files read it prints `0 touched files read under <root>: nothing read` and exits 2. Without `--rulings` it used to print `LIST (0 lines to read …)`, exit 0, on an absent tree, so a seat could take an empty list for a clean one. With `--rulings` it already failed, every ruling stale, exit 1. This is the same E-2 class on R-21's other instrument, and it costs one line. The critic may strike it.

## 2 · H10-2: a ruling's verdict, true or reported

### 2.1 · What landed (`prose-sweep.mjs`)

| piece | behaviour |
|---|---|
| the entry | `{ at, says, verdict, why }`. `verdict` is the string `"true"` or `"reported"` (`VERDICTS`, frozen) |
| `"true"` | the seat read every clause of the line, and of the sentence it belongs to, as true (R-26); `why` names what makes each clause true. Prints `✓ true` |
| `"reported"` | a clause is false, was false before the patch, and the patch did not write it (R-26). Prints `◦ reported`, and again in `REPORTED (not gated; a false clause the patch did not write, for the landing docs pass): n` with its `why`. It covers its line, so the line is not unread. It gates nothing |
| stale | unchanged, and the same for both verdicts: a ruling whose line no longer prints, or no longer carries `says`, prints `✗ stale <verdict> ruling …` and FAILs |
| the tally | `SWEEP lines=… files=… ruled=… true=… reported=… unread=… stale=…` |
| the verdict line | `PASS (n lines: t ruled true, r reported)`. The FAIL line is unchanged: `FAIL (u unread, s stale of n lines)` |
| refused (exit 2, nothing read) | a rulings file that is not a list; an entry with no `at`, `says` or `why`; a `verdict` missing or other than the two; verdict `"true"` over a `why` that carries the word `REPORTED` (the pass-9 workaround, P9-5 H10-2). Each refusal names the entry |

No default verdict exists. An entry without one is refused rather than read as `true` (E-1: no shim). The record therefore cannot call a reported line true by omission.

## 3 · The migration

### 3.1 · How

The pass-9 generators wrote the banked JSON from the banked sweep logs. Before touching either, I re-ran both generators unchanged on those logs, and all three outputs came out `cmp`-identical to the banked files. I then migrated the generators so they emit `verdict`, and re-ran them in place on the same logs (`H10-run.sh migrate`):

- `FV8-rulings.py`: `REPORTED = {"src/components/dock/styles/dock.css:15"}`, so that ruling is verdict `reported` and every other is `true`. No `why` text changed.
- `MS7-rulings.py`: a ruling whose `why` starts with `REPORTED`, or carries `REPORTED:`, is verdict `reported`, with the leading `REPORTED, ` removed from its `why`. Every other ruling is `true`. This is the generator's own pass-9 count rule (its last line counted "10 of them REPORTED" the same way). The `LINE` text in the generator is unchanged; the prefix is stripped at output. The header's `REPORTED` paragraph now says so.

`H10-migrate-check.py` reads each banked file from git `HEAD` and the migrated file from the checkout. It checks the same `(at, says)` list in the same order, the four keys, each verdict against the banked reading, and each `why` equal to the banked one less the prefix. The result is `MIGRATE-CHECK PASS`, exit 0:

| file | rulings | true | reported | sha1 after |
|---|---:|---:|---:|---|
| `FV8-rulings.json` | 214 | 213 | 1: `dock/styles/dock.css:15` | `6e572194` |
| `MS7-rulings.json` | 369 | 359 | 10 | `6256b96b` |

- **`FV8-rulings.json`, `dock/styles/dock.css:15`.** Its `why` opens "true as to the patch" and ends "that misattribution is pre-existing at HEAD … so it is reported for the landing docs pass, not ruled into the row". The pass-9 generator already counted it among the 10, and it is migrated with them. Its `why` keeps its words, `REPORTED:` included. Under verdict `reported` that is not refused.

Only the PASS line. `PASS (214 lines, each ruled true)` becomes `PASS (214 lines: 213 ruled true, 1 reported)`, and R-25's fixture text `PASS (371 lines, each ruled true)` becomes `PASS (371 lines: 361 ruled true, 10 reported)`. ## 5 · Departures, recorded for the critic

1. **SWEEP refuses an empty scope too** (§1.1). P9-5 names DEL only.
2. **Verdicts are the strings `"true"` and `"reported"`**, not a JSON boolean beside a string, so one field has one type.
3. **Four refusals** (§2.1): malformed file, missing field, missing or unknown verdict, and verdict `true` over a `why` carrying `REPORTED`. The last is lexical and catches only the pass-9 convention. A seat that calls a false clause true in other words passes the instrument. R-26 and the critic own that reading (HARNESS §4, "A verdict is the seat's word").
4. **`FV8-rulings.json` `dock.css:15` migrated by name** (§3.2).
5. **The generators were migrated with their JSON** (§3.1), so the JSON still regenerates from the banked sweep logs, and the regeneration is the migration.
6. **The self-test's `fv8` is the real floor v8** (§4.1, §4.2), and H9's stand-in leaves the self-test.

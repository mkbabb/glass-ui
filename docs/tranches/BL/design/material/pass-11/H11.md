## 1 · H11-1: the report survives a pipe

### 1.1 · The cause

On macOS node writes to a pipe asynchronously. A tool that prints its report with `console.log` and then calls `process.exit()` leaves whatever the pipe has not taken yet in node's queue, and the exit drops it. A file is written synchronously, which is why every seat's `> file` log was whole. The self-test runs every tool through spawnSync's pipe, and the parent reads as fast as it can, so the loss needs load to show: the pass-10 critic saw it 2 times in 12 at load about 40 (`../pass-10/crit-records/pipe-truncation.log`), and it flaked one H10 row. A reader that sleeps before it reads fills the pipe (about 64 KB) at once, and the loss happens every run:

| harness | run | exit | bytes | last line |
|---|---|---:|---:|---|
| HEAD (the worktree's own copy) | 1, 2, 3 | 1 | **65,457** | `✓ true src/components/dock/styles/index.css:85 [word "tint"]` |
| H11 | 1, 2, 3 | 1 | **213,593** | `FAIL (2 unread, 0 stale of 371 lines)` |

(`H11-pre-slowpipe.sh`, `H11-records/pre-h11-slowpipe.log`; load 41.1. `wc -c` counts bytes; the self-test rows below count JS characters, 211,729 for the same report.) The exit code is right in every run. A reader that checks only the exit code passes a list it never saw the end of. That is the E-2 class P10-5 names.

### 1.2 · What landed

| file | change |
|---|---|
| `lib.mjs` | On import, for stdout and stderr: no handle (a file) needs nothing; a handle with `setBlocking` is set blocking; a handle without it throws (`H11-1: … cannot be written synchronously`). Every harness `.mjs` imports `lib.mjs` (the self-test checks it), so every report is written synchronously and every exit, at any depth (rows.mjs `variantOrExit`, the Q-11 and Q-1 option refusals, usage lines), leaves it whole |
| `prose-sweep.mjs`, `deleted-mechanisms.mjs` | The CLI is `main()`, which returns its code; `process.exitCode = main()`. No `process.exit` remains. Every printed line and every verdict is unchanged |
| `launch-law.mjs` | Its one `process.exit` at the end is `process.exitCode` |
| `neighbourhood.mjs` (new, §2) | Written the same way |
| `selftest.mjs` | `judge(expect, status, out)`: the last non-empty line must be the tool's verdict and agree with the expectation. PASS: `PASS (…)`, `LIST (…)`, `PRINT (…)` or `GLANCE PASS: …`. FAIL: a measured `FAIL (…)` or `GLANCE FAIL: …`, never a refusal. LOUD: `FAIL (nothing read …)`, `FAIL (rulings refused …)`, `FAIL (declaration refused)` or `…: nothing read (…)`. Both `staticWitness` and the capture `witness`, and the four GLANCE blocks, use it |

## 2 · H11-2: the neighbourhood of a re-valued token, printed

### 2.1 · What it reads

`node harness/neighbourhood.mjs --root <patched tree> --patch <file.patch>`. Scope: the touched files that exist in the tree, the set R-21 reads.

| part | what prints |
|---|---|
| re-valued | a custom property declared on the removed side and on the added side of one `src/` stylesheet's hunks (`.css`, a `.vue` style) with a different value, whitespace aside. Each hunk's old side is its context and removed lines, its new side its context and added lines, so a multi-line value is read whole, and so is one whose first line is context. A token the patch only adds or only deletes is not re-valued (DEL reads deletions). This is wider than DEL's value arm, which reads scalars only: `--dock-control-press-bg` changes from a five-line `color-mix(` to one line, and DEL's line reader cannot see it |
| (a) declared | every declaration of a re-valued token in a touched file, and the comment block above it: up past the rule's own code lines (its selector, sibling declarations) to the nearest comment line, then every contiguous comment line. A blank line ends both walks |
| (b) fallback | every touched-file line holding `var(--A, …)` whose fallback names a re-valued token, the comment block above that line, and every touched-file prose line naming the alias `--A` |
| (c) relation | every touched-file prose sentence carrying "bound" or a rung name. A rung name is a name segment shared by two or more re-valued families of one file (a family is DEL's H9-2 rule, three or more re-valued tokens of one file differing in one segment, here over every value). The sentence is the hit line, extended up and down through worded prose lines until a sentence end (`.`, `!`, `?` before a space or the line's end) |

Each line prints once, as `file:line [why; …] | text`, sorted by file and line, then `NEIGHBOURHOOD lines= files= declared= fallback= alias-prose= relation=` and `PRINT (n lines in m files; not gated)`, exit 0. No tree, no patch or 0 touched files read prints `nothing read` and exits 2 (H10-1's law). It does not open `sweep-frozen.json`, adds no word to it and gates no row.

## 4 · Departures, recorded for the critic

1. **The cure is the synchronous write, in `lib.mjs`, for every tool; `process.exitCode` only in the four tools whose exit is their verdict.** P10-5 allows either. Writing synchronously covers the twelve tools that still exit early, `variantOrExit` included, without touching its 24 callers. It reaches node's stream handle (`_handle.setBlocking`), which is not public API. A handle without it throws at import, so the cure fails loud rather than silent (E-2). A blocked stdout waits on a reader that stops reading; it does not lose the report (HARNESS §4).
2. **The judge tightens every row, the capture rows included.** The capture witnesses end on `report()`'s own verdict line (`PASS (n gated rows)` or `FAIL (…)`), and 24 of the 25 that call it print nothing after it. The 25th, `lighting-literals.mjs`, prints after the `report` call only on its no-capture path, where its own last line is the verdict. The capture rows did not run this pass (no browser), so their reading under the judge is UNMEASURED until the next battery.
3. **The printer's scope is the touched files, and it does not print direct uses.** R-30 names the declaration's block, the lines naming a falling-back `var()`, and ladder relations. Direct `var(--T)` uses are not printed; `icon-button.css:118-120` prints through (c), "a tier below resting". `tab-button.css:75` and `triggers.css:85` lie outside the touched set, and P10-5 sends them to the landing docs pass.
4. **The rung-name rule** (segments shared by two or more re-valued families of one file) gives `dialog` and `chassis` on floor v9, so every touched sentence naming the Dialog component prints. Floor v9's print is 1,597 lines. A narrower rule (the segments of every family) would drop `dialog` and `chassis` and still print all six lines. I kept the wider one because R-30 names "a named rung" and both are rungs of the veil and plate ladders.
5. **The fixtures are floor v9 and the minor v8** (the driver's task), where P10-5 wrote "floor v10 and the minor v9", which do not exist yet. R-28's and R-29's cuts (fv9p, minor8p) are read as well, as the PASS 207 and PASS 369 the critic and MS8 measured, so the floor v10 and minor v9 seats start from a self-test that already holds their fixture.
6. **Two records beyond the brief:** `H11-pre-slowpipe.sh` (the HEAD harness against H11 on the real sweep, §1.1) and the printer over the minor v8 (§2.3).

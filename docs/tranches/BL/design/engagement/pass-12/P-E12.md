### 1.1 The frame, and the one frame source (P-1)

Every length the stage writes is a painted length over `frameOf(the box it writes on)`, and nothing else:
- the lens's `--lens-dx/-dy`, `--lens-sx/-sy` and the span of its travel (unchanged since P-E11);
- the room in the reach;
- the re-render glide.

The glide's painted move is `travelled(old, new)`:
- Σ over each box of each offset chain of offset × `frameOf(box)` (old chain +, new chain −);
- plus, for each scaled ancestor in both, (1 − s) × (old origin − new origin) × `frameOf(ancestor)`.

The frames and the scale are read **now**, so an ancestor's running animation contributes nothing. Layout alone decides how far the place moved. The glide writes that painted move over `frameOf(host)`.

The frame is read once per mutation, never per frame. Per frame, `heard` reads only offsets and the sizes of the scaled ancestors (`moved`), which is the same cost as P-E11's `flowBox`.

**Why not paint.** Reading the painted rect would have been simpler, but it reads an ancestor's running animation as a move whenever the mutation falls between the animation's tick and the stage's read. That is C-A11's `glideframe` class, which H12's `animating` cells catch.

The recorded non-plant shows the model's margin. `framethen` (§2.4) weights each offset by its own box's frame as read at the time. It does **not** separate (26/26 in both engines), because a box's own frame does not move with its own animation. Only C-A11's exact shape, each offset over the host's frame, fails: `glideframe`, 24/2.

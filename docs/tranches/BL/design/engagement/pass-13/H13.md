### 1.1 · CK-20 (a): what can move a held host's painted place between two frames

The held host's painted place is `P = M(L)`: its layout place `L` (an offset chain) carried through the paint maps `M` of every box between it and the root, then shifted by the scroll offsets of its scrollers. Between two frames it moves when, and only when, one of these moves.

**(i) Layout `L`.** Script reaches layout only through the DOM and the CSSOM. The DOM's change grammar is the `MutationObserver` record grammar, which has exactly three record types:
- `childList` (a node inserted or removed: a block above the host, a `v-if`): **driven**, `kind · insert|remove`;
- `attributes`, which moves layout through exactly three channels: the inline `style` attribute (`v-show`'s `display`, a `:style` binding), a selector that matches on the attribute (`class` and any `[attr]` rule), and the UA's `[hidden]` rule: **driven**, `kind · style|class|hidden`;
- `characterData` (text interpolation reflowing a line): **driven**, `kind · text`.

Each kind runs under no card, `scale 0.8` and `rotate 10deg`, outside the box (18 cells). Moves no record carries, named and not driven as glide cells: a CSSOM rule edit (`insertRule`, a constructed sheet) is **REPORT** (`cssom · <card>`, 3 cells): it is a layout move with no record, so a record-driven glide cannot hear it, and a frame-driven one can; a viewport resize is E-10's existing `stale place` family (pass 5); web-font swap, image decode and `:hover`/`:focus` restyles above the host are not driven (they are layout moves of the same shape as a style change, with no record; the critics may drive them).

**(ii) Paint maps `M`.** A box's paint map is the CSS transform matrix: the individual properties `translate`, `rotate`, `scale` and the `transform` list, about `transform-origin`, composed with the parent's `perspective` about `perspective-origin`, and with `zoom`. Its parts, by what each does to a translate written on the host:
- the **linear part** (2×2): scale (pass 10-12 cards), rotation and skew (`facts13` C: under `rotate: 10deg` a host translate `0 40px` paints `(-6.946, 39.392)`; under `skewX(15deg)` `(10.718, 40)`; under `skewY(8deg)` `(0, 40)` and `40px 0` paints `(40, 5.622)`; a `matrix()` with rotation paints `(-5.56, 31.52)`);
- the **projective part** (`perspective`, a 3D transform): the map depends on depth, so a layout move scales by where it lands (`perspective(600px) rotateX(25deg)`: `(-2.92, 37.309)` against 40);
- **size-dependent maps**: a percent `translate`, a percent or default (50 %) `transform-origin`, `perspective-origin`. These move the paint when the box resizes, with no offset moving: the `below` place (the act after the root, inside C) isolates them;
- `zoom` on any box and on `<html>` (pass 11-12 cards, kept).

Cards driven, each inside (the act inside C, the host's own box), outside (the act before C, under C's map), nested (C's parent carries the map) and, on the size-dependent cards, below: `rotate 10deg` about `0 0` and about the centre (the default origin), `rotate 10deg + scale 0.8`, `skewX 15deg`, `skewY 8deg`, `matrix(0.788, 0.139, -0.139, 0.788, 0, 0)` and `matrix(0.8, 0, 0, 0.8, 0, 0)`, `perspective: 400px` on the parent with `translateZ(-50px)`, `perspective(600px) rotateX(25deg)`, `translate 0 20%` and `10% 20%`, the Dialog's `translate -50% -50%` with `position: relative` (inside, outside, below; nested is off the viewport under the parent's −50 %), `scale 0.8` about the centre, `zoom 0.5`, `zoom 2.5`, `scale 1.25`, `zoom 0.5 + scale 0.8`, and `zoom 1.25` on `<html>` (outside only). ### 1.2 · CK-21 (b): the grammar each token's consumer accepts, per engine

A token's value reaches two readers: CSS, through the consumer property that names it, and the script, through the custom property's computed text. The custom property is unregistered, so its computed text is the author's tokens, not a value. The grammar the script must accept is the consumer's: `<time>` for a clock (`transition-duration`), `<number>` for a scale, `<length>` for a gutter, `<easing-function>` for an easing; each a single value (the consumer is a list-valued property, but the token is one item of it).

The value forms of a `<time>`, `<number>` or `<length>`, by the CSS Values grammar:
- a dimension with its unit's case (`210MS`), exponent (`2.1e2ms`, `1e-3s`), sign (`+0.21s`, `-0s`), a comment, whitespace;
- the math functions: `calc()` (sums, products, nesting), `min()`, `max()`, `clamp()`, the stepped functions (`round()`, and `mod()`, `rem()`), the sign-related (`abs()`, `sign()`), and the constants (`infinity`, `pi`, `e`);
- `var()` with a fallback, inside `calc()` and alone;
- the CSS-wide keywords (`inherit`, `initial`, `unset`);
- relative units for a length (`rem`, `em`, `vw`, percent).

`facts13` B (Chromium, `logs/facts-chromium.log`) reads every form three ways. **CSS** takes every math form, including `round(nearest, 214ms, 10ms)` (0.21s) and `abs(-210ms)` (0.21s); `calc(infinity * 1s)` computes to `1.79769e+308s`; `1e-3s` to `0.001s`; a bare `210`, a two-value list and `inherit` (an empty computed text in the custom property) give `0s` on the consumer. **The Typed OM** (`CSSNumericValue.parse(text).to(unit)`, the pass-12 `tokenOf`) **throws on `round()` and `abs()` in Chromium**, a member pass 12 did not have (C-A12 found WebKit throws on every math function), and throws on `1rem` and `min(16px, 5vw)` converted to `px`. **A registered property** computes to a canonical value (`round(…)` → `0.21s`), so a registered token (`--rung-crest`, `--scrub-pitch`) never hands the script an unparsed form. **`KeyframeEffect`** refuses `cubic-bezier(1.5, 0, 0, 1)`, `steps(0)` and `inherit`, and CSS falls back to `ease` for them.

## 0 · In brief

**Score: 6 of 27 rows closed (22 %).** Applicable rows are CK-01..CK-27, all of them. Closed: CK-09, CK-11, CK-15, CK-23, CK-24 and CK-26. Every other row is open, with a replayed counterexample or a cell I could not read.

With the harness's unmodified scene app it passes 81 of 108 in each. It also paints `background: var(--background)` under every scene. Both may be right harness fixes. But they are H2's to make, they were made by the author of the route the harness grades, and no plant was added for either (CK-27, gates that cannot fail). The geom arm's "108/108" is in fact 104/108 on the harness's own app.
3. **The light commit fails silently.** I planted `--engage-control-engage-{attack,release}: nonsense` on the root. The seat's `transition` then computes `all`, the light jumps straight to its committed end state, and the rise is 0 in every frame. The console shows 0 errors, in both engines (`logs/collide-light-a-*.log`, `ck21-lightclock-planted`). In the clean read, the light peaks at an alpha of 0.12 and drains by 210 ms. The fixture's E-11 plant `--scale-commit-pop=1` is not read on the light path (UNMEASURED in both engines), so it cannot catch this. CK-21 is open.
4. **The light seat collides with the coarse dock trigger's hit-slop.** `DockTrigger for="dropdown"` renders `DropdownMenuTrigger`, which composes `engage-disclosed` (`DockTrigger.vue:43-47,68-76`), and its `::after` is the coarse touch-floor hit-slop (`touch-floor.css:44-52`). On the light build, the seat's `inset: 0` beats the slop's `50%` start. The 44 × 44 slop lands at inset 0 0 with `translate(-22px, -22px)`: 22 px up and left of the face it should centre on. On open it paints the commit light (alpha 0.085-0.109, opacity 0.79-1) on that displaced square. Without the seat (the geom build), the inset reads 16.45 / 18.66 px, which is the correct centring. The probe built a synthetic element with the exact class list the component renders, under (pointer: coarse), in both engines (`logs/collide-*`). CK-14 is open.
5. **Two `held` members are stamped and never engaged.** NumberField and Timeline compute `--rung-class: held`, but the door never reaches either (`useEngage` is imported only by Button, Chip and Slider). Under a held pointer, both read `data-engaged` false, `data-held` false and `scale 1`, in both engines and both themes (`logs/collide-light-a-*.log`). The census counts them as adopted. This is pass 1's finding #2 again, "census proves classification, not adoption", one level down (CK-01, CK-27).
6. **The geom arm replaces members' own transition lists.** Its utilities-layer `transition` outranks the components layer, so on a selectable Card the transitioned properties change from `--card-fill, box-shadow, border-color, scale` to `--rung-commit, background-color, border-color, box-shadow, color, opacity`. SegmentedTabs loses its `background` leg in the same way. The Card's fill and scale now snap (CK-20, geom build; `logs/collide-geom-a-chromium.log` against `collide-light-a-chromium.log`, roots).
7. **What holds.** CK-01's plants all fail as they must. The commit-free mount holds 18/18 in each engine, which cures the tabs' mount glide. E-3's keyboard contract and afterdrag hold, 20/22 per engine. E-8 reads 19/19 and E-9 60/60 on four reads (both engines × both arms). The E-10 hand-off and Escape cells pass. The coarse Button no longer latches at ×1.015 (×1.000 released in my Chromium capture). `.tap-squish` and `.interactive-item` are gone with no alias.

## 4 · Next-pass defect classes (fit no row; the score is unchanged)

1. **A route seat edits the harness it is graded by.** `A2/scenes/App.vue` changes the commit definition and the page ground. The harness needs one owner, and the stateless "programmatic commit" needs a definition H2 rules on (NOT DRIVEN rather than FAIL when the component never sees the counter).
2. **A shared pseudo-element claimed by a utility.** Any library rule that already uses `::after` on an element that composes `engage-chosen/pressed/disclosed` will collide. The dock touch-floor is the one I measured, and it does not appear in any scene.
3. **The census reads a stamp, not a behaviour,** for classes whose recipe needs a writer (`held` needs `data-engaged`). The latch can go green over members the door never reaches.
4. **E-5 sustain on the toggle in dark flips between reads** (2 of 3 fail). H2's "one green read is not a cure" applies here as it does to the Button's reduce squish.
5. **`ExpandableContainer` composes `engage-disclosed` on its whole root,** which in fullscreen is a dialog. Its `:active` wash would cover the whole region on any press inside it. My probe's press did not make the root `:active` (Chromium and WebKit, `rootActive false`), so this is NOT-REPRODUCED and recorded only as a class to read next pass.

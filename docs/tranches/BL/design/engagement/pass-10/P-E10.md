`placeLens` and `glide`, in order of what they do:

1. **Hysteresis.** `below = L.below ? room <= HOLD_SLOP_PX : room < 0`, where `room` is the track's painted top less the lens's painted height. `room` reads no lens paint, so the lens's own travel cannot feed it.
2. **The change's frame.** Read the lens's painted centre, cancel any travel, toggle the side, read again, and compute the correction on the new edge in that same pass. The travel's span is painted centre before minus resting centre after, so the frame of the change does not move the lens, wherever an earlier travel had it. The first lay takes its side with no travel.
3. **The correction leaves the travel alone.** The lens's box includes its running `translate` animation, so a plain read would close the travel in one frame. `owed = span × (1 − effect.getComputedTiming().progress)` is added back. `progress` is the eased progress, the same value the keyframes are painted at. `plant-owed` deletes this and reads 101.8 px.
4. **`glide(el, dx, dy)`** is now two keyframes on the row's token: `{ translate: [from, "0 0"] }`, `{ duration: rowClockMs("dock", el), easing: <--spring-dock>, composite: "add" }`, returning the Animation. An unreadable token says so (`loud`) and no travel runs (standing law E-2, no masking fallback). It replaces 24 keyframes sampled by `settleFrames` in this file; `settleFrames` keeps its reader in `useEngage.ts`. The host's re-render glide takes the same path, and E-10's glide and stale-place cells re-read it (§3.1).
5. **On a scroll, a resize or a re-render, a released holder's lens is laid** (`onMove`, `onMutation`), which covers the exit. No frame runs for it (O-103f (3)).

**Why these figures (CK-12).** The row: `springPresets.ts` names `dock` for "the coordinated travel — member FLIP, the selection lens, indicator glide", and this stage already travels every moved place on it, so a lens's moved place is the same case. The band: `HOLD_SLOP_PX` (8 px) is the library's one figure for how far a hand moves before it counts as moving. A wobble smaller than a hand's own is not a move. It reuses that row rather than minting one, and its size was not read from a witness: a band only had to exceed about 5 px to pass `at-change` (§3.3).

**No construction without a side change.** The side change meets the row: it keeps the lens whole and pinned at rest on either side, and H10's cells read it as written. A clamp would read off its edge. I did not build one.

**No lighting layer, no blur token, no radius (O-87, CK-26).** The diff to the lens's CSS is the two placement declarations and their comment.

## 3 · Harness defects this seat found and fixed

### 3.1 · A crash cascaded through every later scene

In the inherited self-test, T-6's Chromium clean run failed its gating cells after `f1-verbatim`: every later scene printed `browser.newContext: Target page, context or browser has been closed`. Chromium had died under load, and `lib.browser()` kept handing out the dead handle. That early log was not banked, so no number from it is cited here. The same failure class appears, banked, in `logs/aborted-run5-selftest-driver-killed.log`.

Fix: `lib.browser()` relaunches a disconnected browser and records the disconnect, and every witness prints a note per disconnect. T-6 keeps each segment's cells only when the segment finishes, so a segment abandoned on a hang cannot write late cells. A segment whose engine closed is re-run once on the relaunched browser: if the re-run finishes, its cells stand beside a NOT-REPRODUCED line; if it dies again, the segment fails loud. T-7's four-state read does the same. One level up, `run.mjs`'s `runOne` re-runs a witness process once when it ends in a HARNESS ERROR because its engine closed, which is what `logs/aborted-run5-selftest-driver-killed.log` shows the need for (`t1-coarse`, Playwright WebKit, "page.waitForTimeout: Target page, context or browser has been closed"). It is a recovery path, not a check, and ships without a plant. No retry fired in any log this document cites.

### 3.2 · T-6 read a resting scale as motion

An early baseline T-6 Chromium run (not banked) failed chipcell Tab entry on a scale departure from 1. The selected Chip rests scaled (its flood, PORTFOLIO §1.2 S6; the banked baseline reads its settle at 1.07 after a programmatic commit, `baseline/head-src/T-6-chromium.json`), so focus entering the group had moved nothing. For the same reason the commit bar measured the pop's amplitude from 1: a Chip at rest earned "amplitude ok" by resting, and a trough of 1.07 could never read as a bounce below 0.998.

Fix (`measure.mjs`): Tab entry measures each item's scale range across the frames. The commit bar measures peak and trough against the settle, the last sampled frame's scale (`POP = 0.015`, `BOUNCE = 0.002`). For every fixture plant (settle 1) the two readings are the same number. The control `t6-rest` gives the selected tile a resting scale of 1.05 and a pop that overshoots and bounces around it, and it must PASS Tab entry and all three commits, which the old reading would have false-failed. It passes 72/72 in both engines (`logs/selftest-T-6.log`).

### 3.3 · The travel arm of the commit bar had no fixture

H-4 names "travel if a body moves", which is D4-G's commit, and no fixture had a body. `t6-body` (control) has no pop: a `[data-selection-body]` springs to the committed tile with an 8 % overshoot on every commit (pointer, keyboard, programmatic) and does not move on Tab entry. `t6-glide` has the same body on a 240 ms linear glide with no overshoot. `t6-body` PASSES 72/72 and `t6-glide` FAILS 48/72 in both engines (`logs/selftest-T-6.log`).

### 3.4 · T-6's hover-scale and press cells failed a clean fixture on one late read

The first T-6 self-test on the final commit bar failed its Chromium clean fixture 70/72: "chipcell hover scale · 1.00 (1)" and "[migrated] specimen-migrated press · scale 1.01×1.01" (`logs/aborted-selftest-T-6-before-reread.log`, started at load 53.99 / 47.70 / 52.71). Both cells waited a fixed time and read the scale once, so a late frame under load read the transition before it moved.

Fix (`measure.mjs` `hoverScale`, `pressScale`; `t6-engagement.mjs` `reread`): both cells sample every frame over their wait and print the median frame interval and the load. A failing read on janky frames (median > 20 ms) is re-read twice: it passes as NOT-REPRODUCED if a re-read passes, and fails as "reproduced in 2/2" if neither does. A failing read on smooth frames is never re-read. The new plant `t6-still` removes the fixture's hover scale and press squish. It must fail both cells on smooth frames rather than be re-read away, and it FAILS 56/72 on "hover scale" and "press" in both engines (`logs/selftest-T-6-t6-still.log`). After the fix the clean fixture passes 72/72 in both engines.

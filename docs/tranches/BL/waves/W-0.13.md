# W-0.13: the demo site at glass.babb.dev

The source is the owner's order of 2026-11-09, verbatim: "we should plan to deploy the site to glass.babb.dev, too. Mark." (INBOUND O-192.)

glass-ui's demo has no public home today. `npm run demo:dist:build` writes `dist-demo/` (base `/`, deep SPA routes), and nothing ships it. `docs/precepts/infra/domains.md` and `deploy.md` describe sudoku.babb.dev rather than glass, which is a stray copy, so this wave rewrites both for glass.

## Scope

- **Host.** A Cloudflare Pages project `glass` serves `dist-demo/`, and `glass.babb.dev` is a proxied CNAME to it on the babb.dev zone, covered by Universal SSL. An SPA fallback (`_redirects`: `/* /index.html 200`) keeps deep routes working, and `_headers` sets a CSP built from what `dist-demo/` actually requests.
- **When it ships.** The site tracks the published package. The release workflow deploys the demo after a successful `npm publish` on a `v*` tag, so the site never shows unpublished work. A prerelease or a `--tag v10` maintenance publish does not deploy. The token is a repo secret `CLOUDFLARE_API_TOKEN` scoped to Pages edit on the babb.dev account; until the secret exists, the owner-side `npm run deploy:demo` (`npm run demo:dist:build && wrangler pages deploy dist-demo --project-name glass --branch main`) is the path.
- **Records.** `docs/precepts/infra/domains.md` and `deploy.md` become glass's: the host, the project, the deploy trigger, the rollback (redeploy the prior tag's tree), and the secret's scope.

## Gates

- `https://glass.babb.dev/` and one deep route each return 200 with the built index, and every asset they request resolves (no 404 in the network log), in headless Chromium and WebKit at 390 and 1440.
- The served build's version string equals the npm `latest`.
- `git grep -n sudoku -- docs/precepts/infra` returns nothing.

## Addendum 2026-11-10: what the sibling sites do (from value-js-65), and the owner's two acts

Facts, as value-js-65 holds them and as read from daraksha's `.github/workflows/deploy-pages.yml`:

- The babb.dev zone sits in the owner's personal Cloudflare account. Local wrangler is logged in to the Friday Institute account and cannot reach it. Nothing on this Mac creates the project or attaches the domain; the deploy runs only in CI.
- value.js, keyframes.js, fourier and daraksha each carry two repo secrets, `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`. glass-ui has only `NPM_TOKEN` (checked with `gh secret list`, 2026-11-10). The token cannot be read back from GitHub and is not hunted for on disk.
- The sibling custom domains were most likely attached in the dashboard (Pages project → Custom domains), which writes the proxied CNAME.

This replaces the plan above where they differ:

1. **The deploy is a workflow of its own, `deploy-demo.yml`,** copied from daraksha's shape. It runs after the `release` workflow succeeds on a `v*` tag whose npm dist-tag is `latest` (never a prerelease or a `--tag v10` publish), and on manual dispatch. No local `deploy:demo` script and no local wrangler.
2. **`--branch=master` equals the project's production branch.** Any other name cuts a Preview deployment that exits 0 and never reaches the domain.
3. **The project exists before the first deploy:** a guarded `wrangler pages project create glass --production-branch=master` step that tolerates "already exists".
4. **Absent secrets skip loud:** the job warns "deploy SKIPPED" and exits green, and the asserts do not run.
5. **After the deploy it asserts** that a Production deployment references the built commit, that every built asset is served as itself and not as the fallback HTML with a 200, and that the live pages raise no console error and make no third-party request.
6. **`_headers`:** `no-transform` on every response, immutable caching on `/assets/*`, `no-cache` on `/` and `/index.html`, and the CSP. **No `_redirects`:** Pages serves `index.html` for unknown paths when no `404.html` ships.
7. `npx --yes wrangler@4`, with `--commit-hash` and `--commit-dirty=true`.

**The owner's two acts (nothing else is his):**
- On mkbabb/glass-ui: `gh secret set CLOUDFLARE_API_TOKEN` and `gh secret set CLOUDFLARE_ACCOUNT_ID`, the same pair the sibling repos carry.
- In the Cloudflare dashboard, once the first deploy has created the project: Pages → glass → Custom domains → add `glass.babb.dev`. (If the token also has Zone DNS edit, the workflow attaches the domain itself and this act falls away; the workflow tries and reports which.)

## 2 · The defect at HEAD

`.toggle-group__item[data-state="on"]` paints `color-mix(in oklab, var(--foreground) 12%, transparent)`, ink `var(--foreground)` and weight 600, with a 16 % hover (`src/components/toggle-group/styles.css:116-124`). Its edge is `.glass-control-edge`'s box-shadow stack, read from `--control-edge-ring` (`src/styles/glass/control-edge.css:53-59`). No rule reads a per-item colour, so a consumer can restore the pressed fill and ink through `class` (fourier does, `BasisSelector.vue:222-227`) but not the edge, which glass owns. `grep -rn "toggle-tint" src` returns nothing.

## 3 · The cure

The pressed rule reads one optional per-item input, `--toggle-tint`, through the three channels the ask names. The shape, with D3's converged percentages in the slots:

```css
.toggle-group__item[data-state="on"] {
    --control-edge-ring: 0 0 0 1px color-mix(in oklab, var(--toggle-tint, transparent) <edge>%, transparent);
    background-color: color-mix(in oklab, var(--toggle-tint, var(--foreground)) <fill>%, transparent);
    color: color-mix(in oklab, var(--toggle-tint, var(--foreground)) <ink>%, var(--foreground));
    font-weight: 600;
}
.toggle-group__item[data-state="on"]:hover:not(:disabled) {
    background-color: color-mix(in oklab, var(--toggle-tint, var(--foreground)) <hover>%, transparent);
}
```

- **The neutral state paints HEAD's bytes.** With no tint, the fill and hover resolve to `--foreground` at HEAD's own 12 % and 16 % (so D3's `<fill>` and `<hover>` apply to the tint, and the neutral arm keeps today's values), the ink resolves to `--foreground`, and the ring slot resolves to `transparent`, which is what `--control-edge-ring` computes to at HEAD (`rgba(0, 0, 0, 0) 0px 0px 0px 0px`, measured by fix-2). An earlier form of this spec fell back to `var(--foreground)` in the ring, which would have added a 40 % foreground ring to every untinted pressed item; G2's edge clause is the bite against that.
- **One path.** Each fallback is a token default for an optional input, not a literal masking a dead primary (E-2, F-64), so there is no second code path.
- **Where the tint lives.** It is set per item (inline style or a consumer class on the item). It is not declared on `.toggle-group__item`, so a consumer may also set it once on the group and the items inherit it.
- **Where the edge lives.** The edge is the one slot `.glass-control-edge` already reads (`--control-edge-ring`), so no new shadow layer is minted and the focus ring's precedence is unchanged.
- **The numbers are D3's.** The formation prototype used a 12 % fill, 16 % hover, 60 % ink and a 40 % ring (fourier's own pressed border). It turned G1 green on 11 of 12 rows over HEAD's grey plate; the twelfth, chebyshev in Chromium light, read a fill shift of 0.0099 against the 0.01 floor, because the warm grey plate cancels the blue tint (O-62's grey again). Those readings are an input to D3, which converges the pressed register with the other state registers. The wave ships D3's numbers. If D3 has not converged at the 10.2.0 cut, W-0.2 does not ship in 10.2.0 and lands at 11.0.0 with W-H.1 under the same gates.
- **The forced-colours arm** (`styles.css:151-155`) is unchanged: `Highlight` wins, and a tint is not a system colour.

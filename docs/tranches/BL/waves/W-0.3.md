## 2 · The defect at HEAD

The heading is one flex row, `configurator-layer-heading flex min-w-0 items-baseline gap-2` (`src/components/configurator/ConfiguratorLayer.vue:147`). The name and the sub-label are both `truncate` flex items with the default `flex: 0 1 auto` (`:152`, `:155`). With free space negative, each shrinks in proportion to its basis, so the name loses width at the same rate as its annotation. `#actions` and the chevron sit in their own grid tracks (`components/configurator/styles.css:190-215`) and are not affected.

Measured with the band-0 paint probe (`W-0.1.md` appendix A, scene `layer`, a 342 px column at a 390 px viewport; three layers: with `#actions`, bare, and a name longer than the track):

| layer | engine | heading px | name scroll / client | sub-label scroll / client | verdict |
|---|---|---|---|---|---|
| with `#actions` | Chromium | 263 | 171 / 117 | 203 / 138 | FAIL (name cut) |
| bare | Chromium | 280 | 171 / 124 | 203 / 148 | FAIL |
| long name | Chromium | 280 | 466 / 189 | 203 / 83 | FAIL (sub-label kept 83 px while the name is cut) |
| with `#actions` | Playwright WebKit | 262 | 188 / 122 | 203 / 132 | FAIL |
| bare | Playwright WebKit | 280 | 188 / 131 | 203 / 141 | FAIL |
| long name | Playwright WebKit | 280 | 510 / 195 | 203 / 77 | FAIL |

The fine and coarse 390 cells paint the same bytes for this surface in each engine (sha256 prefixes: Chromium `7c27e612962a` both, Playwright WebKit `20cf84483ce9` both), so the defect does not depend on the pointer; the probe keeps both cells because the registry's born-RED names 390 coarse (`REGISTRY.md:638`).

## 3 · The cure

The sub-label takes a zero basis and grows into what the name leaves:

```css
/* components/configurator/styles.css, beside the heading's other track rules */
.configurator-layer-heading > .configurator-layer-sub {
    flex: 1 1 0;
    min-inline-size: 0;
}
```

and the sub-label span gains the class `configurator-layer-sub` (`ConfiguratorLayer.vue:155`).

Why this and nothing more:

- With a zero basis, the heading's free space goes to the name first, at its natural width. The sub-label receives the remainder and truncates within it.
- The name shrinks only when the free space is negative with the sub-label already at 0. That happens only when the name alone is wider than the heading track. The cap the ask names is therefore the heading track itself, which is the only cap that neither wastes space nor lets the name push `#actions` or the chevron. The name keeps its `truncate`, so a name longer than the track ends in an ellipsis.
- The two grid tracks for `#actions` and the chevron (`styles.css:190-215`) are untouched. The gate below reads their widths as a hold line.
- The ask's other two choices ("wraps below" or "hides") are not taken. A wrapped sub-label changes the header's block size between layers and breaks the one-line header row. Hiding is what a zero-width sub-label already does when there is no room.

A prototype of exactly this change was built in the scratch worktree. It turned every O77 row green in both engines (§5).

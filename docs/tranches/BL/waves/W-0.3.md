## 2 · The defect at HEAD

The heading is one flex row, `configurator-layer-heading flex min-w-0 items-baseline gap-2` (`src/components/configurator/ConfiguratorLayer.vue:147`), with no wrap. The name and the sub-label are both `truncate` (`:152`, `:155`), so each ends in an ellipsis when the row is short. The header grid centres its tracks (`components/configurator/styles.css:190-199`, `align-items: center`), which holds `#actions` and the chevron on the label's line only while the heading is one line.

Measured with fix-2's probe (the band-0 pattern of `W-0.1.md` appendix A: a Vite build of the worktree `src`, Chromium with `--force-color-profile=srgb`, and Playwright WebKit). Three layers in columns of 600, 342 and 260 px: with `#actions`, bare, and a name longer than the track ("Decomposition and reconstruction bases"). ## 3 · The cure

```css
/* components/configurator/styles.css */
.configurator-layer-trigger > .configurator-layer-heading {
    grid-column: 1;
    flex-wrap: wrap;            /* intrinsic: the sub-label drops to line 2 when the pair does not fit */
    row-gap: 0;
}
.configurator-layer-heading > * {
    min-inline-size: 0;
    overflow-wrap: break-word;  /* a word longer than the whole track breaks; nothing ellipsizes */
}
```

- `ConfiguratorLayer.vue:152` and `:155` drop `truncate`. The sub-label span gains no new class.
- With `flex-wrap: wrap`, the pair sits inline when both fit and stacks when they do not; the sub-label is the item that moves to line 2 because it follows the label. The label wraps only when its own max-content is wider than the whole track, which is the last resort the ask names.
- The header grid holds `#actions` and the chevron on line 1: the header's `align-items: center` (`styles.css:193`) becomes a first-line alignment (`align-items: start` with the tracks offset by half the label's line box, or `first baseline`), chosen by the form that passes G3 in both engines.
- **O-89.** `EasingPicker.vue:574` drops `truncate`: the readout `<code>` takes `overflow-wrap: anywhere` and `white-space: normal`, the copy Button's row aligns to the first line (`items-start`) so the Button grows in block size and the copy glyph stays on line 1. `ConfiguratorRow.vue:149` drops `truncate` on the `name` span and takes `overflow-wrap: anywhere`. Neither site gains a second form: no `title` attribute, no tooltip of the full text.
- The shrink/wrap/hide cure this spec first carried (a zero-basis sub-label with a truncating name) is withdrawn. It kept both ellipses, which O-77a rejects.

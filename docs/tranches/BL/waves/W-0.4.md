## 2 · The defect at HEAD

**The z leg.** `overlayContentAttrs` (`src/components/_shared/overlay/content.ts:48-66`) writes the plate classes, `data-slot` and the register attribute, but no z rung. Two callers add a rung themselves: `PopoverContent.vue:127` (`"z-popover"`) and `TooltipContent.vue:62` (`"z-tooltip"`). `DropdownMenuContent.vue:86-90` and `DropdownMenuSubContent.vue:44` pass only `props.class`. reka's PopperContent copies the content's computed `z-index` onto its fixed wrapper, so the menu wrapper is `auto` and paints under any positioned sibling with a tier.

**The attribute.** The seam writes `data-reveal: "tooltip" | "menu" | "overlay"` (`content.ts:39,63`), and so do `toast/Toast.vue:80` and `select/SelectContent.vue:80`. The register reads it in `styles/glass/reveal.css:97,107,118` and `styles/glass/overlay-plate.css:75,88,114`. `data-reveal` is also the fragment hook of slides' and atlas' own reveal systems (slides `src/deck/reveal.ts` writes it; `src/views/HomeView.vue:255-261` documents a global `[data-reveal]{opacity:0}`). A consumer rule on the bare name therefore reaches glass's overlay plates.

A second library concern shares the name: the exported `vReveal` directive (`src/index.ts:511`) writes `data-reveal` on the elements a consumer marks (`composables/motion/reveal/vReveal.ts:21`), and the deck reads it (`deck/styles/reveal.css:21-37`, `deck/styles/capture.css:73-75`). That is the directive's documented output, written only where the consumer asks for it (see §3, decision 3).

**The waits.** `tests/components/menu/contract.test.ts` sleeps a fixed 30 ms six times (`:87`, `:117`, `:132`, `:148`, `:292`, `:387`). `:117` is the one that failed on the release runner (run 36053041265 attempt 1, `FORMATION-PROGRESS.md:44`). `:148` and `:387` wait for the same focus return, and `:87`, `:132` and `:292` wait for the menu to open. All six are the same defect: a wait on time, not on the event.

## 3 · The cure

1. **The seam owns the z rung.** `content.ts` gains one table, beside `ROLE_REVEAL`:

   ```ts
   const ROLE_Z: Record<OverlayRole, string> = { hint: "z-tooltip", menu: "z-popover", panel: "z-popover" };
   ```

   `overlayContentAttrs` adds `ROLE_Z[o.role]` to the class list before `o.class`, so a consumer class still wins through `cn()`. `PopoverContent.vue:127` and `TooltipContent.vue:62` drop their own rung, and the comment at `TooltipContent.vue:50` is rewritten to say the rung comes from the seam. One site then decides every portalled overlay's tier. The rung values are today's tokens (`tokens/scheme-motion.css:210-211`). Re-ranking the tooltip above its hosts is W-E.4's host-relative leg, not this wave.

2. **The overlay register moves to `data-glass-reveal`.** Every writer (`content.ts:39,63`, `Toast.vue:80`, `SelectContent.vue:80`) and every reader (`reveal.css`, `overlay-plate.css`, the comments in `transitions.css`, `tokens/motion-registers.css`, `styles/index.css`, the demo's `stories/motion/curve-gallery.vue:153`, `stories/foundations/motion.vue:42`) change in one commit. The tests that read the register (`tests/components/tooltip.contract.test.ts:117`, `tests/styles/overlay-plate-available-height.test.ts:49-50`) change with them. `demo/capture/capture.css:60` lists both attributes, because its rule forces overlays and fragments to rest. The name follows the library's existing namespace (`data-glass-dock-portal`, `data-glass-dock-owner`, `data-glass-sample`, `data-glass-field-canvas`). The attribute was never documented: 0 hits in `README.md`, `DESIGN.md`, `docs/canon` and every component README, and `overlayContentAttrs` is not exported. The rename is therefore internal, which makes it minor-lawful. The MIGRATION line in §7 serves any consumer whose CSS reached into it.

3. **The `vReveal` directive's hook is not renamed in this minor.** It is a documented, exported output that the consumer opts into per element, so a rename is a public break and cannot ride 10.2.0. Its disposition is W-L.6's per-symbol wire-or-delete, since it has no consumer: 0 of the eight sibling consumers import it, and slides runs its own copy at `src/deck/reveal.ts`. If W-L.6 wires it, the same 11.0.0 cut namespaces it to `data-glass-fragment` with its MIGRATION row and the deck's two readers. If W-L.6 deletes it, the deck's readers go with it. That is a decided placement, not a re-booking: F-66's census is the wave that rules unconsumed published symbols (PLAN §3, W-L.6).

4. **The waits become event waits.** Two helpers go at the top of `contract.test.ts`. `untilFocused(el)` resolves on the element's own `focus` event, or at once if it already holds focus. `untilOpen()` resolves when a `[role="menu"][data-state="open"]` node is present, watched with a `MutationObserver` on `data-state` and `childList`. All six sleeps use one of them. If focus never returns, the wait never resolves and the test fails on vitest's timeout, so the helpers cannot pass vacuously.

A prototype of 1, 2 and 4 was built in the scratch worktree. Every gate below passed on it (§5).

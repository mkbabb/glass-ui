# BD.W-DOCK-LINK-API — the KISS dock LINK facade: toSurface / split / silhouette / receive as VERBS over the ONE FLIP spine

**Band 2 · depends: W-DOCK-INTEGRATE · W-SILHOUETTE-REALIZE · W-FLIP-SPINE** (the facade composes the shipped bloom entry points which compose W-FLIP-SPINE's ONE `useElementBloom` runner; it takes the fission/silhouette handles as EXPLICIT options, never through `defineExpose`; it READS the `--dock-silhouette-fuse-t` scalar that W-SILHOUETTE-REALIZE mints+renames — LINK-API is a downstream reader of that scalar, NOT its rename owner)

## The defect / the ask

SEED-DRAFT §Band-2 line 24 names the **largest API gap**: a KISS dock **LINK facade** — `useDockLink(dockRef)` exposing `toSurface(controlRef, surfaceRef)` / `split` / `silhouette` / `receive` as VERBS, a GlassDock `:silhouettes`/`:context` data-prop pass-through, and DockSelect/DropdownTrigger bloom-from-rect — plus the link-scalar registry table in ONE README section. ORCHESTRATOR-NOTES §"THE DOCK = the now-playing pill" frames the dock as a living organism that links OUT (to dropdowns, to other docks, to bloomed surfaces); SEED §Band-2 line 40 calls this "link to dropdowns/other docks".

The gap is real and three-sided against the shipped HEAD:

1. **There is no ONE facade — the link primitives are scattered + verb-less.** `src/composables/motion/useLiquidReveal.ts` (the `reveal()`/`conceal()` source-rect bloom), `src/composables/motion/useDockCtaReceive.ts` (the `receive()`/`setPending()`/`clearPending()` external-CTA-into-dock seam), and `src/components/custom/dock/composables/useDockContextSilhouette.ts` (the `setSilhouette()` context state machine) + `useDockFission.ts` (the `split()`/`registerPiece()` detach orchestrator) are FOUR separate composables a consumer must wire by hand against four different rect/ref conventions. There is no single `useDockLink(dockRef)` that exposes them as ONE coherent verb surface keyed off the dock's own root — the KISS+DRY "one facade per facility" charter point (SEED §4) is unmet for the dock-LINK facility.

2. **The portaled overlay triggers DON'T bloom from their rect.** Read `src/components/custom/dock/DockSelectTrigger.vue` + `DockDropdownTrigger.vue` — each is a thin reka `SelectTrigger`/`DropdownMenuTrigger` wrapper carrying `v-specular` + the dock class. The reka-portaled `SelectContent`/`DropdownMenuContent` overlay appears via the shared `.glass-reveal` data-state recipe (the everywhere floor), but it does NOT bloom FROM the trigger's rect via `useLiquidReveal` — so a dock dropdown opens with the generic center/anchor zoom, not the iOS-27 source-rect bloom the dock-CTA-receive inverse (`useDockCtaReceive`) and the dialog-from-button (`useLiquidReveal`) already ship. The trigger HAS the rect (the popper anchors to it); nothing composes the bloom from it.

3. **GlassDock cannot be handed its silhouette/context declaratively.** Read `src/components/custom/dock/GlassDock.vue` (`defineProps<DockProps>()` line 46, `defineExpose` line 308). The dock exposes `expanded`/`expand`/`collapse` but takes NO `:silhouettes` descriptor array or `:context` id prop — so wiring `useDockContextSilhouette` onto a real dock (W-SILHOUETTE-REALIZE's job for `<DockNowPlaying>`) requires a bespoke SFC. There is no ADDITIVE pass-through that lets a plain `<GlassDock :silhouettes :context>` host the silhouette state machine as DATA.

## The mechanism

ONE facade composable + ONE additive prop pass-through + the two trigger blooms — every leg COMPOSES a shipped primitive, NONE re-forks. The link is **DATA** (a signature/silhouette-map/control-ref registry), never an SFC-per-transition (SEED §4 KISS+DRY: one declarative-data idiom).

1. **`useDockLink(dockRef, options)` — the verb facade (`src/components/custom/dock/composables/useDockLink.ts`, new, feature-dir colocation).** It takes the dock's root `Ref<HTMLElement | null>` and returns FOUR verbs, each a thin delegation to the shipped engine — it owns NO rAF, NO spring, NO second physics core (SEED §3 no-re-fork):
   - **`toSurface(controlRef, surfaceRef, opts?)`** — blooms a foreign surface (a panel, a dialog) FROM a dock control's rect: composes `useLiquidReveal(surfaceRef, { trigger: controlRef, preset })` (the SAME `ElementMorph` + `springTimingFunction` substrate, sampled from `SPRING_PRESETS` — `useLiquidReveal.ts:120`). Returns `{ reveal, conceal }`. This is the dock→surface LINK (open a sheet bloomed from the dock control).
   - **`receive(ctaRef, controlRef, opts?)`** — the INVERSE: morphs an external CTA INTO a dock control via `useDockCtaReceive(ctaRef, { dockControl: controlRef, preset, onReceived })` (`useDockCtaReceive.ts:152`) — the CTA flies + congests onto the dock control, the seat reserves. Returns `{ receive, setPending, clearPending, pending, reset }`.
   - **`split(signature?)`** / **`silhouette(toId)`** — delegate to the dock's `useDockFission().split()` and `useDockContextSilhouette().setSilhouette()` (the shipped orchestrators W-DOCK-INTEGRATE / W-SILHOUETTE-REALIZE wire) — NOT a second fission/silhouette engine. **THE HANDLE-BOUNDARY FIX (the defineExpose trap closed).** `useDockLink` NEVER reaches through `defineExpose`/a `dockRef.value.someHandle` template-ref to discover the fission/silhouette handles (a `defineExpose` surface is a TEMPLATE-ref contract — not reactively reliable mid-mount, an undocumented coupling that silently no-ops the moment the SFC re-orders its expose; the reka-binding silent-no-op trap class the MEMORY warns of, applied to our own expose). Instead the handles arrive ONE of two explicit ways: **(i)** as EXPLICIT options — `useDockLink(dockRef, { fission, silhouette })` takes the already-constructed `UseDockFissionReturn`/`UseDockContextSilhouetteReturn` the host passes in; OR **(ii)** the facade is CONSTRUCTED INSIDE the dock SFC (`<DockNowPlaying>.vue`'s `<script setup>`) where the fission/silhouette composables are in lexical scope, so `useDockLink(dockRef, { fission: dockFission, silhouette: dockSilhouette })` binds the live returns directly. When NEITHER handle is supplied (a plain `<GlassDock>` with no fission/silhouette), `split`/`silhouette` are documented no-ops that warn-once in dev. The `dockRef` is used ONLY for the bloom rects (`toSurface`/`receive` need the dock-control geometry), NEVER as a handle-discovery channel.

   Every verb resolves the SAME `SpringPresetName` register (`springPreset(name)` — `useLiquidReveal`/`useDockCtaReceive`/`useDockContextSilhouette` all sample it), so the link reads as ONE spring family, two directions (bloom-out `1→0`, receive-in `0→1`). Published from `src/components/custom/dock/index.ts` beside `useDockCtaReceive`/`useDockFission` — the `/dock` keyframes-bearing chunk (the heavy-peer home, the `useDockSearch` precedent).

2. **GlassDock gains ONE additive `:silhouettes` / `:context` data pass-through.** Extend `DockProps` (`src/components/custom/dock/composables/useDockShellProps.ts`) with OPTIONAL `silhouettes?: readonly DockSilhouetteDescriptor[]` + `context?: string` (+ `v-model:context` via a `context` model). When `silhouettes` is bound, `GlassDock.vue` constructs `useDockContextSilhouette` internally (the descriptor-driven state machine W-SILHOUETTE-REALIZE ships) keyed off the dock root + writes `data-context` + the `--dock-silhouette-fuse-t` scalar (RENAMED off `--silhouette-fuse-t` — the `--dock-*` convention, clean break, no alias) onto the `.glass-dock` root, and a `watch(context)` calls `setSilhouette`. When `silhouettes` is UNSET the dock is BYTE-IDENTICAL to HEAD (the no-op floor — the descriptor machine never constructs). This is the SEED §2 "the dock is ONE living organism on ONE orchestrator, not N feature-flags" — the silhouette is DATA the plain dock accepts, not a second SFC. The pass-through is additive default-OFF; `proof:dock-link` C4 fences the rest-identity.

3. **DockSelectTrigger / DockDropdownTrigger bloom the portaled overlay FROM the trigger rect.** Each trigger composes `useLiquidReveal(contentRef, { trigger: triggerRef })` against the reka-portaled content node. **THE CONTENT-REF FIX (the internal-selector trap forbidden).** The content node is obtained ONLY via reka's DOCUMENTED API — the `SelectContent`/`DropdownMenuContent` `:ref` (the exposed forwarded element ref reka publishes), NEVER a `document.querySelector('[data-reka-popper-content-wrapper]')`/`[data-reka-*]` internal-selector reach into reka's teleport DOM (an undocumented internal data-attr is the silent-no-op reka-binding trap the MEMORY warns of — it breaks the moment reka renames the wrapper, vue-tsc + units never catch it, only e2e does; FORBIDDEN). The trigger owns its own `triggerRef`; the content ref forwards through reka's published `:ref` contract. Driving `reveal()` on the open transition: the trigger ALREADY carries `v-specular`; this ADDS the source-rect bloom on top of the `.glass-reveal` CSS floor (the floor stays the un-JS Safari-safe default; the bloom is the JS refinement — the `useLiquidReveal` "CSS recipe is the everywhere floor, the JS leaf is the source-rect refinement" doctrine). Compositor-only (`transform`/`opacity`/`filter` on the OWN pixels — `useLiquidReveal` writes only those; `filter` not `backdrop-filter`, so Safari paints the bloom). PRM-snap by construction (`useLiquidReveal.respectReducedMotion`).

4. **The link-scalar registry table — ONE README section, a LIVING census.** Add a `## The link-scalar registry` section to `src/components/custom/dock/README.md` (after the "One driver per concern" `--dock-morph-t` section, line 75) enumerating EVERY dock LINK scalar + its ONE authority + its direction.

# BD.W-GLASS-EVERY-ELEMENT — the glass-for-every-element COVERAGE LAW (the census gate)

**Band 7 · depends: BE.W-ICONCHIP-GLASS · BE.W-GLASS-CONTROL · BE.W-SHEET-TRANSLUCENT · BD.W-CONTROL-GLASS (the switch/checkbox/radio glass-track — closes the last coverage PARTIAL) · BE.W-CLEAR-VARIANT (the surface-axis `clear` rung) — these waves are the BUILDS the census enrolls; this wave is the LAW that asserts the coverage is complete**

## The defect / the ask

The user mandate (ORCHESTRATOR-NOTES §"GLASS FACILITY FOR EVERY ELEMENT"): "The library must ship a glass register for EVERY element — not just cards/docks: buttons, icons, inputs, tabs, dropdowns, chips, controls, etc. The glass audit must enumerate every component and assert it has a glass facility (or a recorded reason it stays opaque — the AX.W54 allowlist). This is a coverage law for the union." The birthdaycolor audit (birthdaycolor-glass-audit §"Glass-for-every-element coverage (the law)") closes with the verdict "glass-ui already exceeds birthdaycolor's per-element coverage" — but that verdict lives in PROSE, not a gate. The SEED-DRAFT Band-7 names the wave: `W-GLASS-EVERY-ELEMENT [NEW]` ("enumerate ~92 packages; gate a glass facility or recorded opaque reason").

The HEAD gap is structural and a real source fact: **`proof:glass-cohesion` is a COHESION gate, not a COVERAGE gate.** Read `scripts/proof-glass-cohesion.mjs:133-140` — its inventory walk SKIPS any file that does NOT already match `GLASS_MARKER` (`:137`: `if (!GLASS_MARKER.test(body)) continue; // not a glass surface — out of scope`). So the gate asserts every surface that ALREADY paints glass routes through the ONE model — but it can NEVER catch a component that ships NO glass facility at all (an element with no glass register is silently "out of scope", not flagged). The coverage question — "does EVERY package have a glass facility OR a recorded opaque reason?" — is exactly the question the cohesion gate's `continue` evades. A new element shipped with no glass register, no opaque-allowlist entry, sails past `proof:glass-cohesion` green.

The verified component surface: 42 `ui/` dirs (41 packages + `_shared`) + 49 `custom/` dirs = ~92 packages (`ls -d src/components/{ui,custom}/*/ | wc -l` → 42 + 49). The cohesion gate's `ALLOWLIST` (`:83-101`) names the opaque-exempt set (avatar/label/separator/skeleton/table/data-table/badge/checkbox/radio-group) — but that allowlist is the cohesion gate's SKIP set, not a census-asserted COVERAGE ledger; nothing asserts that every package is EITHER glass-bearing OR on the allowlist (a third state — a non-glass, non-allowlisted package — is the silent gap).

## The mechanism

A NEW census gate `proof:glass-every-element` (EXTENDS `proof:glass-cohesion` — it imports the cohesion gate's `GLASS_MARKER` + `ALLOWLIST` + `walk` so the two share ONE marker/allowlist source, never a second copy). The gate enumerates EVERY `src/components/{ui,custom}/` package and asserts each falls into EXACTLY ONE of three states — the coverage law. This is the census discipline (the `proof:dock-unify` W5 census-CLOSURE precedent: every dock appears on exactly one list; here every package appears in exactly one state).

The three coverage states (the anti-gameability floor — a package is in EXACTLY one, no package un-accounted):

1. **GLASS-BEARING** — the package's source matches `GLASS_MARKER` (it ships a glass tier / surface axis / glass register / `backdrop-filter` / `--glass-*` token). The cohesion gate's existing inventory already enforces that these route the ONE model; this census asserts they EXIST. The ~bulk of the surface (cards, buttons, inputs, selects/dropdowns/menus/command/context-menu, tabs, chips, dock+controls, dialogs/sheets/drawers/popovers, toast/notification/alert, progress/border-progress, icon-chip glass register, glass-control, glass-panel, …).

2. **OPAQUE-ALLOWLISTED** — the package is on the RECORDED opaque allowlist with a NAMED reason (the AX.W54 legibility allowlist — avatar/label/separator/skeleton/table/data-table/loud-badge/checkbox/radio-group). The census reads the SAME `ALLOWLIST` set the cohesion gate owns + a co-located rationale map (`docs/tranches/BD/union/glass-coverage-roster.md` — each allowlisted package + its one-line opaque reason, e.g. "avatar — a photo carrier, glass-frost would muddy the face; label/separator — sub-perceptual at hairline scale; skeleton — a loading placeholder reads as solid; table/data-table — dense data wants flat legibility; badge — the loud-saturated pill register; checkbox/radio — 16px selection atoms below the glass-reads-as-glass scale, the AY.W-PRIM-POLISH D7 ratify"). The rationale map is the census's evidence — an allowlist entry with NO recorded reason REDS (no silent exemption).

3. **NON-COMPONENT / INFRASTRUCTURE** — `_shared` (the resolver/CVA leaf dir, no rendered surface) + `focus-scope` (a behavior-only focus-trap host, no painted surface) + `controls` (the DarkModeToggle dir) are NOT element-surfaces owing a glass facility; they carry a recorded INFRA tag in the roster. This state is BOUNDED (a closed named set in the gate — a future agent cannot dump a new un-built element into "infra" to evade coverage; a new dir lands in state 1 or 2 or fails the census).

The census asserts: **every package is in exactly one of the three states, and the union of the three states ≡ the on-disk package set** (the no-package-un-accounted closure — born-RED on any package matching neither `GLASS_MARKER` nor `ALLOWLIST` nor the bounded INFRA set). This is the coverage law: a NEW element shipped with no glass facility + no allowlist entry + not infra REDS the census (the exact gap the cohesion gate's `continue` evades, now closed).

The gate is a CENSUS — it builds NOTHING (the BUILDS are the dep waves: ICONCHIP-GLASS gives the chip its glass register, GLASS-CONTROL the floating control, CONTROL-GLASS the switch/checkbox track, CLEAR-VARIANT the clear rung). This wave is the LAW that makes the coverage assertable + the roster the evidence; when a dep wave lands, its package flips from a census-flagged gap to a GLASS-BEARING state.

**Compositor-only / Safari-safe / KISS+DRY**: a device-free source census — no paint, no engine, no fork. It IMPORTS the cohesion gate's `GLASS_MARKER`/`ALLOWLIST`/`walk` (the single-source — a second marker/allowlist copy is forbidden; the gate re-exports them from `proof-glass-cohesion.mjs` so the census reads ONE source). The roster is the recorded evidence; the gate is the closure assertion. ZERO new component, ZERO new register (the registers are the dep waves'; this is the LAW).

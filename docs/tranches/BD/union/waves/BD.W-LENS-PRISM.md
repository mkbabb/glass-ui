## The mechanism

The chromatic rim is a PER-CHANNEL displacement split in the SVG filter graph — the SAME squircle bevel map, displaced at THREE slightly-different magnitudes (R less, G mid, B more — the dispersion ordering), then re-composited per-channel. It composes the shipped `.glass-lens` seam (and the W-LENS-SAFARI regular-filter clone); it edits ONLY the SVG filter data-URI + the `@property` axis, never a GL shader, never the squircle CURVE (the map stays the baked Apple-preferred quartic profile).

### Phase 2 — the perf-gated build (IFF the per-frame cost clears)

1. **The filter-graph evolution — three per-channel displacement passes (`glass-refract.css`, the `--glass-refract-filter` data-URI).** The shipped single `feDisplacementMap` is evolved to the canonical SVG chromatic-aberration chain:
   - **Isolate each channel** off the SourceGraphic with three `feColorMatrix` channel selectors (R-only, G-only, B-only — the standard channel-mask matrices).
   - **Displace each by the SAME squircle map at its OWN scale** — `feDisplacementMap scale='<base - δ>'` for R, `scale='<base>'` for G, `scale='<base + δ>'` for B (the dispersion: blue bends most, red least — n_blue > n_red). δ is the dispersion amount.
   - **Re-composite the three displaced channels** with `feBlend mode='screen'` (additive recombination — `screen` over black recovers the full color where the channels align, FRINGES where they diverge at the steep rim — exactly the prismatic edge).
   - The `feImage` specular catch-light + the final `feBlend screen` are PRESERVED (the polished-glass highlight untouched). The whole graph stays ONE self-contained `url("data:…")` token (the DDR-LENS-BAKE discipline); the squircle MAP is byte-REUSED (the dispersion is the SAME map at three scales, NOT three maps — the rim concentration is the squircle's, the split is the scale-delta).
2. **The `--glass-edge-dispersion` axis (the dispersion-amount knob).** A new token `--glass-edge-dispersion` (default the iOS-faint whisper — a small δ in the [0, ~6px] band off the base `scale='28'`, so the fringe is a subtle prismatic hairline at the rim, NOT a neon rainbow blowout — the §6 calm register / warm-cream identity). At `--glass-edge-dispersion: 0` the three scales collapse to the base scale and the graph reduces to the ACHROMATIC shipped lens BYTE-IDENTICAL (the no-op floor — dispersion off === today's lens). **The DDR-LENS-BAKE constraint is inherited (binding, CSSWG #542):** a `feDisplacementMap scale` cannot be CSS-`var()`-driven inside a self-contained data-URI (a var()-spliced `scale` emits a multi-token `url(…) <n> url(…)` a filter property rejects AND breaks the bundler url()-rewriter). So `--glass-edge-dispersion` is a DOCUMENTED knob with the δ BAKED into the shipped graph at the default whisper, and a consumer who wants a different δ re-bakes via a successor variant — the EXACT tradeoff the shipped `--glass-refract-bevel: 14%` knob already records (the knob documents the encoded magnitude; the data-URI bakes the literal).
3. **Rides INSIDE the shipped `@supports (backdrop-filter: url(#…))` block** — the dispersion is a Chromium-supported graph; WebKit (bug 245510) NEVER reaches it. **The Safari fall is W-LENS-SAFARI's restored floor:** Safari paints the W-LENS-SAFARI regular-filter clone (the cross-engine DEPTH bend) + the blur + tint + the `.glass-material::before` achromatic edge-glint; the chromatic FRINGE is the Chromium-only refinement OVER that floor (the sequence is why PRISM depends on LENS-SAFARI). The `safari-support-matrix` row records: `lens-prism · backdrop-filter: url() chromatic-split UNSUPPORTED on WebKit · degrade fall = the W-LENS-SAFARI regular-filter DEPTH bend + blur + tint + achromatic ::before edge-glint`.

**Compositor-only / Safari-safe / PRM:** the filter graph is a paint property (no layout animates — `proof:no-layout-animation` GREEN); the dispersion is STATIC (the baked δ, no per-frame re-rasterize), so PRM is a no-op.

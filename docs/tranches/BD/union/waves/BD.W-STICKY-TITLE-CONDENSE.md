## The defect / the ask (Pass-D code-grounded — `ADDENDUM-DEMO-CHASSIS.md` ask #1, substrates audit `§3`)

The user reported it as a BUG, verbatim: "Scrolling titles OCCLUDE the whole page. Page titles persist + occlude on scroll. After scrolling they must be SCROLLABLE-FROM (release, not sticky-occlude). Sub-titles get the SAME facility — both sticky, one SUBSUMES the other (arbitrarily — title condenses, subtitle takes over, or vice-versa)."

The mechanism is present but HALF-BUILT — the intent is there, the OCCLUSION bug is live (substrates audit `:78-90`, live-confirmed):

1. **The sticky cluster has NO backing plate — bare floating text at `z-index: 2`.** Read `demo/stories/story-hero.css:227-232` — `.story-hero-shrink { position: sticky; top: 0; z-index: 2; transform-origin: left top; }`. It is a `position: sticky` cluster at `z-index: 2` carrying a `scroll()`-timeline `scale(1 → 0.5)` shrink (`:243-261`, gated under `@supports (animation-timeline: scroll())` + the `prefers-reduced-motion: no-preference` carve). But the cluster is **TRANSPARENT TEXT** — there is NO `background` / `backdrop-filter` / backing bar on `.story-hero-shrink`. As the body scrolls up, the page content slides UNDER the still-visible (shrinking) title text — the "titles persist + occlude the whole page" defect the user saw. A condense register needs a slim GLASS BAR behind the shrunk title (a sticky header the page scrolls FROM), not bare floating text the page scrolls UNDER.

2. **The title↔subtitle SUBSUME is not built — the three rungs just scale together.** The cluster is the `StoryHeader` unit (`StoryHeader.vue:65-105`: eyebrow `<p>` → subpath `<code>` → the display `<h1>` slot → blurb `<p>`). On scroll the WHOLE `.story-hero-shrink` cluster scales `1 → 0.5` as a block — the eyebrow, title, AND blurb all shrink together. The user's "both sticky, one SUBSUMES the other" mechanic (the title condenses into a compact identity while the subtitle/blurb FADES out and hands the bar over to the persistent route identity — the subpath chip `:80-89`, which "persists into the shrunk sticky header" per its own docstring `:42-45`) is absent: nothing fades, nothing takes over, the descriptor just shrinks.

3. **The condense is `src/`-substrate-correct but `demo/`-chassis-incomplete.** The native `scroll()`-timeline register is already the right substrate (`scroll-choreography.css` `.scroll-build` / the `.story-hero-shrink` `animation-timeline: scroll()` — NO Lenis/GSAP/rAF, the binding native-first fence). This wave does NOT touch the substrate — it COMPOSES it. The missing pieces are demo-chassis-local: the glass backing bar + the subsume choreography, both on the ONE `.story-hero-shrink` register (DRY: one edit → 118 pages).

(NOTE — this wave DEPENDS on W-HEADER-SCALE: at HEAD the substrates hero title is 244.8px — `text-display-hero`, wraps 2 lines — so the condense barely starts before the viewport is full of title; the title must be halved first, then this wave makes the condensed result a real bar. ### Arm 1 — the glass backing BAR (the scroll-FROM register, the occlusion fix)

`.story-hero-shrink` gains a sticky GLASS BACKING that materializes as the title condenses — a slim sticky header BAR the page scrolls FROM (never bare floating text the page scrolls UNDER):

1. **A glass backing layer that fades IN on scroll, keyed off the SAME `scroll()` timeline.** A `.story-hero-shrink::before` (or a dedicated `.story-hero-bar` backing element) paints the glass plate — the SHIPPED glass tier vocabulary (`backdrop-filter: var(--glass-blur-floating)` + `background: color-mix(in oklab, var(--glass-bg-floating), var(--glass-tint-source) var(--glass-tint-strength))`, the `glass/ladder.css:105-106` `.glass-floating` recipe, NOT a re-authored opaque slab — the glass reads the page scrolling THROUGH it, the AX.W54 glass-first identity). The backing's `opacity` animates `0 → 1` on the SAME `animation-timeline: scroll()` source the shrink rides (`:258`), over the SAME tightened range — so at scroll-0 the hero is the large bare title (NO bar, NO occlusion plate over the resting hero) and past the condense range the title sits IN a fully-painted slim glass bar. The backing is COMPOSITOR-ONLY (`opacity` + the static `backdrop-filter`, never a layout property — the `proof:no-layout-animation` floor; the bar's box is the sticky cluster's own resolved box, no width/height/padding animates).

2. **The bar has a bottom HAIRLINE seam (the bar/body boundary).** The condensed glass bar carries a bottom edge on the dark-adaptive `--configurator-divider`/`--story-header-rule` token (W-PAGE-CHASSIS's header→body seam, REUSED — NOT a new token) so the bar reads as a distinct surface the body scrolls beneath, not a fuzzy gradient. The seam fades in COUPLED to the backing opacity (one register, the body slides cleanly UNDER the seam).

3. **The body content NO LONGER overlaps the bare title (the occlusion kill).** With the glass backing present, the sticky bar OCCLUDES (correctly — it is a header bar) what scrolls beneath it, and the body content scrolls FROM the bar (the page reads as content sliding under a settled glass header), instead of the prior bare-z-index:2-text the body scrolled UNDER while it stayed readable-through (the defect). The body's `scroll-padding-top` reserves the settled bar height so an anchor-jump lands BELOW the bar (no content hidden behind the condensed header).

### Arm 2 — the title↔subtitle SUBSUME (one condenses, the other takes over)

The three rungs no longer scale as one block — they SUBSUME on the same `scroll()` timeline (the user's "one subsumes the other"):

1. **The title CONDENSES into the compact bar identity; the eyebrow+blurb FADE OUT and hand the bar over to the persistent subpath chip.** On the SAME `scroll()` timeline: the display `<h1>` shrinks toward the bar's compact title size (the title-condenses leg, the leading rung that survives); the eyebrow `<p>` + blurb `<p>` animate `opacity 1 → 0` (the subordinate descriptor rungs fade as the bar condenses — they are the full-hero descriptor, redundant in the slim bar); and the subpath `<code>` chip (the route identity, which "persists into the shrunk sticky header" per `StoryHeader.vue:42-45`) STAYS — it is the thing the title subsumes INTO (the compact bar = condensed title + persistent subpath chip). So the resting hero is `eyebrow → subpath → big-title → blurb`, and the condensed bar is `small-title · subpath` — the descriptor is SUBSUMED, the route identity persists. (The arm is the user's "arbitrarily — title condenses, subtitle takes over, or vice-versa" — the canonical choice recorded: the TITLE condenses + persists, the eyebrow/blurb subsume away; the subpath chip is the persistent route identity beside the condensed title.)

2. **The subsume is per-rung `opacity`/`scale` on the SAME timeline — NO second register.** Each rung's fade/condense rides `animation-timeline: scroll()` off the SAME `<main>` route-scroller source the `.story-hero-shrink` shrink already reads (`:258`) — there is no second scroll source, no rAF, no `IntersectionObserver` subsume driver. The subsume is disjoint from the 3-stage GRAVITY ENTRANCE (`story-hero.css:308-336`, the `.story-hero-cluster--enter` mount stagger): the entrance is the MOUNT keyframe (a `0.36s` time-based animation), the subsume is the SCROLL-timeline animation — two disjoint registers on disjoint timelines (mount-time vs scroll-position), they never collide (the entrance plays once on mount, the subsume plays continuously on scroll). PRM drops BOTH (below).

3. **PRM keeps the bar, drops the motion (the vestibular floor + the legibility floor).** Under `prefers-reduced-motion: reduce` the WHOLE condense register lives inside the shipped `@media (prefers-reduced-motion: no-preference)` gate (`:235`) — so under reduce the hero paints its static LARGE state with NO shrink + NO subsume + NO backing fade (the vestibular floor; the title is the large resting hero, the page scrolls normally, no sticky occlusion because the un-animated sticky cluster is the correct static fallback per `:222-224`). The glass-bar BACKING is OUTSIDE the motion gate (a static backing is harmless on every engine) BUT only materializes via the scroll-keyed opacity which IS inside the gate — so under reduce there is no condensed bar, the large static hero holds (the user reads the whole title, never an occluding fragment). This is the `.story-hero-shrink` `:221-224` "non-shrinking sticky header is the correct static fallback" discipline EXTENDED to the backing.

The condense is native CSS (zero runtime — the `scroll()` timeline is the browser's own compositor scroll, no JS scroll lib). Safari-safe: `animation-timeline: scroll()` is Baseline (Chrome 115+/Safari 26+ per `:217`); off-support the hero paints the static large title (`@supports` fall, `:234`) — the bar/subsume is a pure progressive enhancement, never a break.

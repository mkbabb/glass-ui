## The defect / the ask

birthdaycolor.com (the union's "best-it" reference) crossfades the color field on date selection with an sRGB `mix()` — which GREYS the warm→cool midpoint (a violet→teal crossfade passes through a muddy grey). birthdaycolor-glass-audit §"The 4 genuine BD waves" item 3 / SEED-DRAFT Band-7 name the better: "the aurora seed→palette MORPH on selection — animate `--aurora-seed` → re-derive palette on `onFlipSettled` / `useLiquidFlex`, OKLCh shorter-hue, no hard cut — perceptually superior to their sRGB `mix()`." This is the GENERIC engine (BD.W-AUR-ALBUM's protagonist cross-fade + BD.W-COLOR-PROTAGONIST's seed-change cross-fade are its two consumers — SEED-DRAFT: "DEDUP with BD.W-AUR-ALBUM's cross-fade (this is the generic seed-morph; album is the consumer)").

The HEAD gaps, each a real source fact:
1. **A seed/palette change is a HARD CONFIG SWAP.** The aurora config is reactive (`useAurora.ts:228` deep-watches it → `runtime.ts:469` `update(cfg)` re-uploads palette + wakes). A consumer changing the seed sets `config.palette` to the new derived ramp in ONE assignment — the field hard-cuts to the new color (one frame old, next frame new). There is NO interpolated transition between two seeds; `grep -rn "interpolateHue\|crossfade\|morph.*palette" src/components/custom/aurora/` returns the per-frame DRIFT terms, not a seed→seed transition.
2. **The OKLCh shorter-hue walk exists on the `/color` leaf but is not wired to a palette transition.** `src/composables/color/index.ts:191` `deriveHue` + value.js `interpolateHue` walk a hue across a ramp parameter (the `analogous`/`monochrome` arcs), and `HARMONY_METHOD` (`:173`) maps to `"shorter"`/`"longer"` arcs — but this walks ACROSS the ramp at a fixed seed, never BETWEEN two seeds over time. The shorter-hue interpolation primitive is present; the seed→seed MORPH that drives it over a clock is absent.
3. **`useLiquidFlex` is the right scalar driver but has no palette-morph consumer.** `src/composables/motion/useLiquidFlex.ts:135` is a pure scalar→squish projection (no clock, no element) — the EXACT shape to drive a 0→1 seed-morph progress. It has the dock/tabs/metaball consumers; no aurora-palette consumer.

## The mechanism

ONE new composable `useAuroraSeedMorph(config, options)` (`src/components/custom/aurora/composables/useAuroraSeedMorph.ts`, on `/aurora`) — the generic seed→palette OKLCh shorter-hue cross-fade. It COMPOSES `useLiquidFlex` (the 0→1 progress) + the `/color` leaf's `cssToOklch`/`gamutMapStop` + value.js `interpolateHue("shorter")` + the EXISTING reactive `config` → `runtime.update()` re-upload. NO new rAF, NO new spring, NO second color core.

1. **The seed→seed morph driver (the headline).** `morphTo(nextSeed)` captures the CURRENT palette (the FROM ramp) + derives the NEXT palette via the SHIPPED `deriveAurora(nextSeed, …)` (the TO ramp), then drives a 0→1 progress `t` via `useLiquidFlex.drive(t)` over a SLOW breathing clock. Per tick, each stop's `palette[i]` is interpolated FROM→TO in OKLCh:
   - **hue** via value.js `interpolateHue(fromH, toH, t, "shorter")` (the `/color` leaf's exact arc primitive, normalized-turns domain — `proof:single-color-core` holds; NO hand-rolled hue lerp);
   - **L and C** via plain scalar lerp (`from + (to − from)·t`);
   - each interpolated stop gamut-mapped through the SHIPPED `gamutMapStop` (`color.ts` import) so no in-flight frame falls out of sRGB.
   The interpolated `palette` is written to the reactive `config.palette` per tick → the EXISTING deep-watch (`useAurora.ts:228`) re-uploads via `runtime.update()`. So the cross-fade rides the SAME config-update path a slider drag rides — NO new uniform, NO new shader, NO second renderer.
2. **The clock — `useLiquidFlex` over a breathing tempo (no new rAF, no new spring).** The 0→1 progress is driven by `useLiquidFlex.drive(t)` fed off a SLOW tempo. The tempo source is the substrate's OWN frame clock (the aurora already owns a frame loop; the morph reads `t` off the substrate's `renderAt` tick or a shared `useRAFLoop` the aurora composes — NOT a new private rAF, the one-loop / `proof:offscreen-pause` discipline). The breathing clock is SLOW (~600-900ms, the V2/birthdaycolor calm morph register — NOT a snappy spring; a color field morph is a slow breath, not a press). `useLiquidFlex`'s squish is UNUSED here (this is the scalar-only `drive` consumer — the size span is the 0→1 progress; the morph reads `t`, not `stretch`).
3. **The `onFlipSettled` coupling (the dark-flip re-theme batch).** When a seed-morph coincides with a dark↔light flip (the page re-themes AND the protagonist changes), the palette re-derive batches into the SINGLE coalesced `onFlipSettled` post-flip task (`useGlobalDark.ts:159`) so the re-theme + the seed-morph kick off in ONE post-paint beat (no double-recompute, no race with the scroll-to-top reset). The morph itself rides its breathing clock; `onFlipSettled` only batches the KICK-OFF when it coincides with a flip.
4. **PRM — the instant seat.** Under `prefers-reduced-motion: reduce` the morph seats the TO palette directly (one `config.palette =` assignment, zero interpolation frames) — a hue shift is not motion (the vestibular floor; the morph confirms the color change, the cross-fade physics off). The PRM signal is the substrate's existing live `matchMedia` monitor (no new listener).

**Compositor-only**: the morph writes CONFIG (palette ramp), the shader reads it — no DOM layout animation; the per-tick re-upload is the SAME cost as a slider drag (the runtime owns the buffer reuse, `color.ts:48` `flattenPalette`). **Safari-safe**: pure JS + value.js color math (universal) + the config-only re-upload; NO `backdrop-filter: url()`, NO goo, NO new shader. **PRM**: instant seat. **KISS+DRY**: ONE composable COMPOSING `useLiquidFlex` + the `/color` leaf + value.js `interpolateHue` + the existing config-update path; ZERO new clock/spring/color-core; the whole engine is the seed→seed OKLCh interpolation + the slow drive.

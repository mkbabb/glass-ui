## The defect / the ask

SEED-DRAFT §Band-3 line 25 names the iOS-26 liquid-dock move: the dock/sheet **grows + shrinks under the user's hand** — it condenses in-place as the user scrolls (giving the content room while keeping the chrome present, not collapsed-away) AND it can be PULLED to grow (a touch-drag-to-grow on the live chrome). This is the SIZE-SCALE axis — the box scales smoothly with the user's scroll position / drag, the iOS-27 "physically morphs maintaining the translucent material" read on the dock's footprint.

The defect is precise and lives at two seams, and the FIRST seam is the disjoint-axis fence with the sibling wave:

1. **The dock has NO continuous scroll-position SIZE response.** `grep -rn "dock-grow\|condenseOnScroll" src/` returns ZERO — the dock cannot scale-condense on scroll. The shipped dock scroll-reactivity is `W-SCROLL-MINIMIZE`'s `minimizeOnScroll` feed: a DIRECTIONAL `--dock-morph-t` collapse-to-circle (scroll-down → collapse, scroll-up → expand), keyed off scroll DIRECTION + a dead-band. That is the collapse↔expand box-MORPH axis. This wave is the disjoint SIZE-SCALE axis: a continuous `transform: scale` condense (1→~0.78) keyed off scroll POSITION (a magnitude, the first ~240px), riding the native `scroll()` timeline — NOT a directional state flip. `W-SCROLL-MINIMIZE.md` already names this fence verbatim (its §"the wrong axis for this move" + the C7 mutual-exclusivity guard); this wave is the SIZE-axis owner the sibling defers to.

2. **There is no `scroll()`-driven SIZE recipe + no drag-to-grow feed.** `src/styles/scroll-choreography.css` ships the native `scroll()`/`view()`/`timeline-scope` substrate (`.scroll-build`/`.scroll-cascade`/`.scroll-pin`/`.smooth-scroll`) — but it has NO continuous-condense `scroll()` recipe mapping position onto a `transform: scale`, and NO drag-to-grow gesture feed. The dock chrome reads `--dock-scale` (the geometry cascade, AZ.R5-TOKENS) but nothing maps a scroll position or a drag delta onto a multiplicative grow-scale BESIDE it.

## The mechanism

ONE registered `--dock-grow` scalar + ONE native `scroll()`-timeline condense recipe + ONE drag-to-grow feed composing the shipped `useDragMorph` — the dock chrome READS `--dock-grow` multiplicatively beside its `--dock-scale` geometry, never a second geometry cascade. The whole SIZE-axis is disjoint from (and mutually-exclusive with) the sibling `--dock-morph-t` collapse axis.

1. **`--dock-grow` — a registered `@property <number>` (the registered-property interpolation floor).** Mint `--dock-grow` in `tokens/property-regs.css` (the `--dock-morph-t`/`--dock-local-scale` twin): `@property --dock-grow { syntax: "<number>"; inherits: true; initial-value: 1 }`. Registered so it INTERPOLATES (a bare unregistered `var()` snaps — the `--border-progress-fill`/`--dock-morph-t` registered-property precedent); `initial-value: 1` is the safe resting full-size on a non-supporting engine (the no-op floor — at `1` the dock paints byte-identical to HEAD). `inherits: true` so a host sets it on any ancestor.

2. **The `scroll()`-timeline POSITION condense (`src/styles/dock/grow.css`, the native register).** The dock's `condenseOnScroll`-bound surface drives `--dock-grow` off a `scroll(<scroller> block)` timeline over `animation-range: 0 var(--dock-grow-condense-range)` (default ~240px): `--dock-grow` walks `1 → var(--dock-grow-floor)` (default `0.78`, the iOS condense floor) across the first scroll segment, and the dock chrome reads `transform: scale(var(--dock-grow))` (a multiplicative condense BESIDE the `--dock-scale` geometry, never replacing it). The recipe rides the `scroll-choreography.css` discipline: under `@media (prefers-reduced-motion: no-preference)` + `@supports (animation-timeline: scroll())` (the native register; a gap engine gets the static full-size dock — the condense is a legibility-neutral enhancement, never a broken silent scale). Compositor-only (`transform: scale` over the box, never a layout property). This is the POSITION map — distinct from `W-SCROLL-MINIMIZE`'s DIRECTION read (a `scroll()` timeline reads position, which is exactly why the SIZE-axis rides it and the collapse-axis cannot).

3. **The `condenseOnScroll` feed (the consumer opt-in, the `scroll()` substrate wired).** The dock's `condenseOnScroll?: { scroller; range? }` feed binds the `scroll()` timeline to the bound scroller (the native CSS register does the work — NO rAF, NO JS scroll listener for the condense; the `scroll()` timeline IS the driver, the `useScrollProgress` dual-path-single-writer precedent where the native path needs no JS). When unbound the dock is byte-identical to HEAD (`--dock-grow` stays at its `initial-value: 1`). The feed is the SEED §2 one-registry bar realized on the SIZE axis: the condense is DATA the dock accepts, not a second machine.

4. **The touch-drag-to-grow feed composes the SHIPPED `useDragMorph` (no second pull engine).** The dock can be PULLED to grow (a touch-drag on the live chrome that scales `--dock-grow` UP under the finger, 1 → an upper cap, then springs back). The drag composes `useDragMorph` (the platform's ONE pull-gesture primitive — the kf `Draggable` follow + the velocity-windowed squish + the C¹ fling, BB.W-DRAG-MORPH) mapping the drag travel onto `--dock-grow` (the multiplicative grow-scale), capped LOW (the anti-taffy bar — `useLiquidFlex`'s `"tanh"` velocity-squish capped at the dock's grow cap, ≤1.2). On release the spring settles `--dock-grow` back toward its scroll-position-resolved value (or `1`). It owns NO hand-rolled pointer-velocity sampler, NO second rAF spring — `useDragMorph` IS the pull engine (the W-DRAG-MORPH no-second-engine fence). PRM: the drag STILL FUNCTIONS (the grow follows + commits) but the squish is OFF + the release is an instant settle (the `useDragMorph` PRM policy).

5. **The dock chrome READS `--dock-grow` multiplicatively, beside `--dock-scale` (one geometry, one grow factor).** The dock's `transform` composes `scale(var(--dock-grow))` (the grow-scale) over its `--dock-scale`-resolved geometry box (the AZ.R5-TOKENS geometry cascade is UNTOUCHED — `--dock-grow` is a multiplicative scale ON the box, not a re-tune of `--dock-scale`/`--dock-control-size`/`--dock-layer-height`). The grow scales the WHOLE box uniformly (it is a `transform: scale`, not a per-axis geometry re-solve) so it is compositor-only + CLS-free (no reflow). The corner clip (`W-CORNER-AA-WIDEN`'s `backdrop-filter` clip-path) rides the scaled box (the clip is in the box's local space, so the scale carries it — the corner stays AA-clean at every grow value).

6. **The mutual-exclusivity fence with `W-SCROLL-MINIMIZE` (the not-both-bound guard, OWNED here too).** `condenseOnScroll` (this wave, the continuous `--dock-grow` SIZE-condense) and `minimizeOnScroll` (`W-SCROLL-MINIMIZE`, the directional `--dock-morph-t` collapse-to-circle) BOTH fire on scroll-DOWN — binding BOTH on one dock double-shrinks it (the box collapses to the circle AND scales down, two facilities fighting). They are DISJOINT AXES for DISJOINT consumers: a hero/sheet dock condenses-in-place (`condenseOnScroll`), a content-reading dock minimizes-to-circle (`minimizeOnScroll`). `useDockState` throws-in-dev / warns-once if both are bound on one dock (the C7 guard, specced in BOTH waves so it lands whichever sequences first; this wave is the SIZE-axis half). The demo exercises them on DISTINCT stories.

Compositor-only throughout (the condense + the drag-grow are `transform: scale` on `--dock-grow`; `proof:no-layout-animation` holds — `--dock-grow` resolves onto `transform`, never a layout property). The scroll-condense is native `scroll()` (zero JS); the drag-grow rides `useDragMorph`'s shipped pointer engine. Safari-safe: the `scroll()` timeline is Safari-26 Baseline (the `scroll-choreography.css` `@supports` gate falls to the static full-size dock off-Baseline); the drag-grow is plain pointer-capture + a compositor `scale` (no `backdrop-filter: url()`).

- **No-legacy / clean break.** No second geometry cascade, no minimize-specific morph — `--dock-grow` is a multiplicative `transform: scale` factor BESIDE `--dock-scale` (the geometry cascade byte-untouched, C4). No dual scroll-size path beside the `--dock-morph-t` collapse sibling.

- **The disjoint-axis + mutual-exclusivity fence.** `condenseOnScroll` (this wave's continuous `--dock-grow` SIZE-condense, POSITION-keyed) is DISJOINT from `minimizeOnScroll` (`W-SCROLL-MINIMIZE`'s directional `--dock-morph-t` collapse, DIRECTION-keyed); the two are MUTUALLY-EXCLUSIVE per-consumer (the C5 not-both-bound guard, owned in both waves). This wave NEVER writes `--dock-morph-t` (C2 fences it); the sibling NEVER writes `--dock-grow`.
- **The Safari fall.** The `scroll()` timeline is Safari-26 Baseline (the `@supports` gate falls to the static full-size dock off-Baseline — a legibility-neutral fall, never a broken silent scale); the drag-grow is plain pointer-capture + a compositor `scale` (no `backdrop-filter: url()`). Enrolled on the webkit Playwright project + a `safari-support-matrix` row.
- **Presets-in-consumers.** The `--dock-grow-condense-range`/`--dock-grow-floor` magnitudes are consumer/demo tunables; the library owns the registered scalar + the native condense recipe + the `useDragMorph`-composed drag-grow. The default (no feed bound) is byte-identical at `--dock-grow: 1`.
- **The anti-pattern this must NOT become:** a `--dock-grow` folded into `--dock-scale` (a geometry re-solve → a reflow — C4 kills it), OR a JS rAF scroll loop driving the condense (the native `scroll()` IS the driver — C2 kills it), OR a direction-read condense (that is `minimizeOnScroll`'s axis — C2 kills it), OR a re-forked pull engine (C3 kills it), OR the scroll DOUBLE-SHRINK (`condenseOnScroll` + `minimizeOnScroll` on one dock — C5 kills it).

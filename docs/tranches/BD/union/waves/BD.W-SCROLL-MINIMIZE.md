# BD.W-SCROLL-MINIMIZE — the dock collapses to the perfect circle on scroll-down, expands on scroll-up (iOS `.tabBarMinimizeBehavior.onScrollDown`)

**Band 3 · depends: W-DOCK-INTEGRATE · BF.W-LIQUID-GROW-ON-EVENT (the scroll-condense sibling — disjoint axis, sequenced)**

## The defect / the ask

SEED-DRAFT §Band-3 line 25 (`W-LIQUID-GROW-ON-EVENT` — scroll-minimize shrunken state) names the iOS-17/26 `UITabBar.tabBarMinimizeBehavior = .onScrollDown` move: scrolling DOWN minimizes the tab-bar/dock to a compact pill, scrolling UP restores it — the directional auto-minimize that gives the content the full viewport while reading and brings the chrome back the moment the user reaches for it. The prompt scopes this wave as **the scroll-minimize arm** of `W-LIQUID-GROW-ON-EVENT`.

The defect is precise and lives at the seam between two shipped facilities:

1. **The dock has the collapse morph but no scroll TRIGGER.** Read `src/components/custom/dock/composables/useDockState.ts` — the ONE dock state machine drives `collapsed | hover | pinned` off pointer/focus (`onMouseEnter`/`onMouseLeave`/`onFocusIn`/`onClickCollapsed`) + the AZ.W-DOCK-FLICKER hysteresis (`HOVER_INTENT_MS = 60`ms intent-dwell `:258-265`, the `EDGE_BAND_PX = 24` morphing-edge recheck). The collapse↔expand box morph runs on the ONE `--dock-morph-t` scalar (`dockMorphContext.ts`, the perfect-circle summary the AY.W-DOCK-NAV B4/B15 collapsed floor paints). But NOTHING feeds a SCROLL-DIRECTION read into this machine — `grep -rn "scroll.*minimize\|scrollDown\|scroll-direction" src/components/custom/dock/` returns ZERO. The dock cannot minimize on scroll.

2. **The sibling `--dock-grow` axis is the WRONG axis for this move.** BF.W-LIQUID-GROW-ON-EVENT mints `--dock-grow` (a continuous `scroll()`-timeline-driven `transform: scale` condense, 1→0.78 across the first ~240px). That is a SIZE-SHRINK of the whole box riding the scroll POSITION (a magnitude). The iOS minimize is a DIRECTIONAL state flip — scroll-down COLLAPSES (the dock goes to its perfect-circle summary, the controls tuck), scroll-up EXPANDS (the full bar returns) — keyed off scroll DIRECTION + a small dead-band, NOT scroll position. These are two disjoint axes: `--dock-grow` is the continuous position-keyed scale (BF.W-LIQUID-GROW-ON-EVENT owns it), `--dock-morph-t` is the collapse↔expand box morph (this wave drives it via the existing state machine). Conflating them re-collapses two distinct facilities into one feature-flag (the SEED §2 anti-pattern). This wave is the COLLAPSE-arm; it sequences AFTER and reads BESIDE `--dock-grow`, never re-implements it.

3. **There is no scroll-direction READER composing the native substrate.** `src/styles/scroll-choreography.css` ships the native `scroll()`/`view()`/`timeline-scope` substrate (`.scroll-build`/`.scroll-cascade`/`.scroll-pin`/`.smooth-scroll`, all PRM-no-preference + `@supports`-gated, compositor-only) — but it has NO scroll-DIRECTION recipe (a `scroll()` timeline reads position, not sign-of-velocity). A direction read is a tiny stateful comparison (last-scrollTop vs current), which the dock state machine is the natural home for (one registry).

## The mechanism

ONE scroll-direction read feeds the EXISTING `useDockState` collapse machine through an ADDITIVE optional input — never a second machine, never a re-forked morph. Scroll-down → `collapse()` (the dock runs its EXISTING `--dock-morph-t` morph to the perfect-circle summary), scroll-up → `expand()`. The W-DOCK-FLICKER hysteresis is RE-USED as the dead-band so a jittery scroll never thrashes the morph:

1. **Add an OPTIONAL `minimizeOnScroll` feed to `useDockState` (one registry).** Extend `UseDockStateOptions` with `minimizeOnScroll?: { scroller: Ref<HTMLElement | null> | (() => HTMLElement | null); threshold?: number }`. When bound, `useDockState` attaches a rAF-COALESCED scroll listener (the `useFadingScroll`/scroll-choreography coalesce precedent — NOT a per-event handler) on the scroller that compares `scrollTop` deltas: a net DOWN delta past `threshold` (default ~8px dead-band, debounced through the EXISTING `HOVER_INTENT_MS` 60ms intent-dwell so a flick never thrashes) calls the EXISTING `collapse()`; a net UP delta (or reaching scroll-top) calls the EXISTING `expand()`. The collapse/expand are the SHIPPED verbs (`useDockState.ts:216-242`) — the morph runs on the ONE `--dock-morph-t` scalar with the perfect-circle summary already painted (AY.W-DOCK-NAV B4/B15). NO new state, NO second morph: `state` stays `collapsed | hover | pinned`; a scroll-minimize is just a `collapsed` reached from scroll instead of pointer-leave. The `keepOpen`/`release` ref-counts win (a held dock — a dragging slider, an open overlay — never minimizes mid-gesture); `alwaysExpanded` short-circuits it (a pinned nav column never minimizes). This is the SEED §2.2 one-registry bar: scroll-minimize FEEDS the ONE machine, never a parallel ref.

   **The scroll double-shrink reconcile — `minimizeOnScroll` and `condenseOnScroll` are MUTUALLY-EXCLUSIVE per-consumer.** Both this wave's `minimizeOnScroll` (the directional `--dock-morph-t` collapse-to-circle) AND BF.W-LIQUID-GROW-ON-EVENT's `condenseOnScroll` (the continuous `--dock-grow` position-keyed scale-condense) fire on scroll-DOWN — two scroll-reactive size responses on the ONE dock. Binding BOTH on a single dock double-shrinks it (the box collapses to the circle AND scales down — a compounding shrink the user never asked for, two facilities fighting on one surface). They are DISJOINT AXES meant for DISJOINT consumers: a content-reading dock minimizes-to-circle (`minimizeOnScroll`), a hero/sheet dock condenses-in-place (`condenseOnScroll`) — NEVER both on the same dock. `useDockState` enforces it at construction: if a consumer binds `minimizeOnScroll` while `condenseOnScroll` (the BF feed) is ALSO bound on the same dock, `useDockState` throws-in-dev / warns-once (the not-both-bound guard) — the disjoint-axis fence made structural, not a documentation hope. The demo exercises them on DISTINCT stories (the scroll-minimize story binds `minimizeOnScroll` only; the W-LIQUID-GROW story binds `condenseOnScroll` only).

2. **Direction-read, not position-read (the iOS `.onScrollDown` semantic).** The feed compares CONSECUTIVE `scrollTop` reads (last vs current) inside the rAF coalesce → the SIGN of the delta is the trigger (down=minimize, up=restore), NOT the absolute position. This is distinct from the BF `--dock-grow` `scroll()` timeline (which maps the position 0→240px onto a scale). The dead-band (`threshold`) + the 60ms hysteresis kill the jitter-thrash (a 2px wobble at the bottom of a list never flips the dock). A genuine sustained scroll-down minimizes; a genuine reach-up (or scroll-to-top) restores — the iOS reading posture.

3. **The minimize re-uses the EXISTING collapse morph + hysteresis — ZERO new motion.** The minimize is the SHIPPED collapse↔expand box morph (the `--dock-morph-t` compositor transform over the reserved footprint, BB.W-DOCK-MORPH-FAMILY — the box scales, the controls tuck, the perfect-circle summary shows, PRM-seats synchronously). There is NO new keyframe, NO new scalar, NO second clock — the scroll read just calls the verbs the pointer path already calls. The hysteresis (`HOVER_INTENT_MS`/`EDGE_BAND_PX`) is byte-untouched (the dead-band uses the SAME `HOVER_INTENT_MS` dwell to debounce the scroll feed — REUSE, not a re-tune). This is the architectural-over-patches charter point (SEED §2): the dock is ONE organism whose collapse is reachable from pointer OR scroll, not two minimize implementations.

4. **PRM + always-expanded carves.** Under `prefers-reduced-motion: reduce` the collapse/expand morph already SEATS synchronously (the `dockMorphContext` PRM sync-seat — the dock minimizes/restores with zero morph frames, a state flip, vestibular-safe — the chrome STILL minimizes to give content room, but instantly). An `alwaysExpanded` dock NEVER minimizes (the `getAlwaysExpanded()` short-circuit in `collapse()`/`expand()` already no-ops — a pinned nav column or a shell dock that must stay present ignores the scroll feed). The feed is opt-in default-OFF (a dock with no `minimizeOnScroll` bound is byte-identical to HEAD).

Compositor-only (the minimize IS the shipped `--dock-morph-t` box morph — `transform: scale` over the reserved footprint; `proof:no-layout-animation` holds). Safari-safe by construction (the scroll-direction read is plain JS `scrollTop` comparison in a rAF — no `scroll()` timeline dependency for the TRIGGER, so it works on every engine; the morph is the shipped compositor transform — no `backdrop-filter: url()`). The native `scroll()` substrate is NOT needed for the direction trigger (a direction read is stateful, which a `scroll()` timeline cannot express) — this is the documented divergence: the BF `--dock-grow` position-condense rides the native `scroll()` timeline, this directional minimize rides a tiny rAF-coalesced `scrollTop`-delta read in the ONE state machine.

# W-NO-HARDCODED-REFS — zero app-specific hardcoded refs (no "maps"); generalized glass precepts

**Surfaced by:** the user — "we should have NO hardcoded or referenced facilities like 'maps' — these are generalized precepts and glass concepts." (the dock-hub directive; the D7 no-hardcoded-app-refs invariant made enforced).

## The ask
The library + the demos ship GENERALIZED glass/dock/viz precepts. No app-specific facility names ("maps", a brand, a domain) hardcoded into `src/` or referenced as an overfit facility. App names + presets live in CONSUMERS (presets-in-consumers).

## The mechanism (a census + gate)
`proof:no-hardcoded-refs` — a census of `src/` (+ the demo chassis) for app-specific/overfit refs: grep for facility names ("maps", domain names, brand-specific strings) + the overfit-facility class (a dock-expand hardcoded to a named surface, a component named/scoped to one app). Assert ZERO in `src/`; the demos use GENERIC content (a generic card/panel/viz, never a named app facility). The dock-hub (W-DOCK-HUB-API) is the generalized replacement for any "expand into maps"-style hardcode. Born-RED on any found ref; the fold either generalizes it (a precept) or re-homes it to a consumer preset.

## Gate
`proof:no-hardcoded-refs` (the grep census, src/ zero app-refs, the demo-generic-content assert, a self-test bite) + the existing D7 invariant. Composes W-DOCK-HUB-API (the generalized expand) + the presets-in-consumers fence.

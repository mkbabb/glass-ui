### 1. `scripts/lib/shader-eval-harness.mjs` — the ONE numeric net (new, the shared leaf)

The single import surface for every parity/round-trip gate — the `reflect-capture-verify.mjs` "minted ONCE, re-exported" discipline applied to the numeric axis (NO second oracle copy per gate). It exports four pure functions:

- **`sampleOracle(evaluatorFn, lattice)` — the JS-oracle arm.** The gate `await import()`s the field evaluator's compiled JS from the TS source via the repo's `tsx`/`vite-node` loader already on the `vitest.config.ts`/`scripts/**` path (the harness runs under node with the TS-aware loader the suite uses for `tests/**` + `scripts/**`), e.g. `const { sampleRingField, RING_GRAVITY } = await import("../../src/components/custom/concentric/composables/ringField.ts")`. `lattice` is a deterministic set of `(p, t)` (or `(index, t)`) samples — `makeLattice(N, domain)` returns the SAME fixed lattice every run (seeded, no `Math.random`), so the gate is reproducible. Returns a `Float64Array` of scalar field values.

- **`sampleShader(shaderSrc, fnName, lattice, { lang })` — the SHADER arm.** Resolves the shipped shader STRING (splice-following — see §2), extracts the named function body (`fn sampleRingField`/`float sampleRingField`), and evaluates it at the SAME lattice via a tiny WGSL/GLSL→JS arithmetic transpiler (the shipped bodies are clean uniform-flow arithmetic — `sampleRingField` is loops + `sqrt`/`sin`/vec swizzles + `max`, fully transpilable; verified in-source at `concentric.wgsl.ts:111-134`). The transpiler maps `vec2<f32>`/`vec2`→`{x,y}`, `sqrt`/`sin`/`cos`/`max`/`min`/`abs`/`smoothstep`→`Math.*` twins, `let`/`var`→`let`/`var`, the `for`+`break` loop form, and the uniform reads (`u.u0.y`, `RING_GRAVITY`) to the constants the gate binds from the JS oracle's exported constants (so the SHADER constant and the JS constant are READ FROM THE SAME source-of-truth — a flipped shader constant is caught because the oracle binds the JS value and the transpile binds the shader value, and they MUST agree). **Where a body is NOT cleanly transpilable** (a texture sample, a compute-storage read, an `fwidth`), the harness falls back to `headless-gl` (`gl` npm — a real WebGL2 raster of a 1-tap fragment shader that writes the field value to a float RT, the `readPixels` decode), the known headless pattern the census names; the transpiler is the cheap path, headless-gl the raster path, both produce the SAME `Float64Array`. Returns a `Float64Array` parallel to the oracle.

- **`fieldDeltaE(a, b)` — the GATE-WRITTEN number.** RMS field-delta `sqrt(mean((a-b)²))` for the scalar-field arm AND, for the COLOR arm (the gpu-parity-table case), the OKLab ΔE: the harness imports the ONE `oklabFromRgb` decompose already minted in `reflect-capture-verify.mjs` (NO second color-math source — the W-CANVAS-UNIFY no-second-copy discipline), runs each field value through BOTH color chunk variants (the JS `procedural-color` twin + the transpiled `procedural-color.wgsl.ts`/`.glsl.ts`), and computes `mean`/`p99` OKLab ΔE over the lattice. Returns `{ mean, p99, rms }` — the number the gate WRITES, never reads.

- **`assertParity(oracle, shader, bar, { label })` — the assert.** `fieldDeltaE(oracle, shader)` ≤ the PER-VIZ calibrated `bar` (see §3) → pass; else the violation carries the COMPUTED number (`"${label}: ΔE mean ${mean} > bar ${bar.mean}"`). The bar is a field of the harness call, never a global — the D2 calibration insight (a generic 0.02 RMS bar MISSED a 1.7% amplitude drift at RMS 7.3e-3; each viz calibrates tight enough to catch its smallest meaningful drift).

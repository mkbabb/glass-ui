# BD.W-TABS-LIQUID — the 5-phase liquid-tab indicator: grow → blob-overshoot → travel → settle → shrink-to-fit

**Band 5 · depends: W-DOCK-INTEGRATE (the liquid spine) · W-TAB-IOS-CAPSULE (the ONE glass-capsule indicator material)**

## The defect / the ask

ORCHESTRATOR-NOTES §"The LIQUID-TAB indicator morph" (USER-VERBATIM) + SEED-DRAFT §Band-5 line 27 (`W-TABS-LIQUID [NEW]`). On tab selection the active indicator must run a **5-phase liquid morph**, NOT a rigid slide:

1. **Grow** in a liquid fashion (the indicator inflates from the current tab).
2. **Blob OVERSHOOT** — it becomes *slightly BIGGER than needed* (a metaball over-inflation).
3. **Transition/travel** to the destination tab (the swollen blob glides).
4. **Settle in liquid** at the destination (a soft liquid settle, ζ<1).
5. **Shrink** slightly to the *appropriate* tab-selection size (de-inflate to fit).

The HEAD gap is the SHAPE of the envelope, not the engine. Read `src/components/custom/tabs/composables/useTabIndicator.ts` — today's `squishOnTravel(toIdx)` (`:200-255`) drives ONE move: a travel-DISTANCE-keyed `--stretch` volume-preserving squish via the shared `useLiquidFlex` (`:172-178`, `"linear"` law, capped at `--tab-indicator-max-stretch` = 1.15 `constants.ts`), opened synchronously with the glide (`:243`) and RELEASED-at-arrival (`:249-254`, keyed to `INDICATOR_RELEASE_AT_ARRIVAL` × the calibrated clock). That is phases 1+3+4 SMEARED into one squish-and-release — there is NO distinct GROW phase (the indicator does not inflate FROM the current tab before travelling), NO blob OVERSHOOT (it never goes *bigger-than-the-target*; the cap is a travel-squish along the axis, not an area over-inflation), and NO SHRINK-to-fit close (the release returns `--stretch`→1, a de-squish, but the indicator never first over-grew past the destination footprint then de-inflated). The travel-squish reads as a gel-stretch DURING the glide; the user's ask is a metaball that **grows past the target, glides swollen, settles, then shrinks to fit** — the 5-beat envelope.

The CSS already pairs `--stretch` reciprocally (`segmented-tabs.css:121` `scale: var(--stretch) calc(1/var(--stretch))`) and the indicator is CENTER-ANCHORED (`useTabIndicator.ts:124-136`, the BA-VJS-3 fix) — so a scale-up centred on the indicator is byte-safe. The mechanism is to ADD the grow-overshoot-then-shrink AREA envelope ON the existing squish, not replace it.

## The mechanism

The indicator carries a NEW `--tab-blob` area-scale custom (1 = fit, >1 = inflated) the CSS reads as a uniform `scale(var(--tab-blob))` ON TOP of the reciprocal `--stretch` squish (compositor-only, both scales compose). 1. **Mint `--tab-blob` (the area-inflation scalar) + register it.** `@property --tab-blob { syntax: "<number>"; inherits: false; initial-value: 1; }` in `property-regs.css` §18 (the `--stretch`/`--dock-morph-t` registered-scalar precedent — a bare `var()` snaps; the `@property` reg lets it INTERPOLATE between frames if the CSS glide carries it). `1` = the fit-the-tab footprint (byte-identical resting); the envelope drives it UP to the overshoot peak then back to 1. The CSS reads it as a uniform `scale(var(--tab-blob, 1))` on `.segmented-indicator` (a SECOND compositor scale composing with the reciprocal `--stretch` squish — `scale` is multiplicative, both ride the center-anchor).

2. **Compose a SECOND `useLiquidFlex` for the blob envelope (the area channel).** Beside the existing squish `useLiquidFlex` (the `"linear"` travel channel, untouched), add `const blob = useLiquidFlex({ from: 1, to: <overshoot-peak>, axis: "width", squishLaw: "linear", maxStretch: () => blobCap })` where `blobCap` reads a NEW `--tab-indicator-blob-max` token (default ~1.12 — the metaball over-inflation, capped LOW ≤1.2, the anti-taffy bar the squish already honors). `blob.drive(t)` projects the 0→1 envelope progress onto the area scale; `blob.size`/the `--tab-blob` write carries the grow→overshoot. The envelope is the SAME volume-preserving primitive the squish + the metaball shader + the dock-fission recoil all compose — ONE squish law, now the indicator's 5-beat consumer (SEED §3 idiomatic reuse).

3. **Drive the 5-beat envelope off the calibrated clock (NO second spring/timer).** `squishOnTravel(toIdx)` shapes `--tab-blob` across the travel as a HUMP that peaks during the first ~40% (grow→overshoot), holds swollen across travel, then de-inflates to 1 at arrival (settle→shrink) — re-using the EXISTING `clockMs(el)` + `INDICATOR_RELEASE_AT_ARRIVAL` schedule the release already reads (`:249`). The grow-open writes `--tab-blob` to the overshoot peak synchronously with the squish open (`:243` — the SAME frame, ONE write site); the shrink-close fires at the SAME `releaseAt` the squish release fires (`:250-254` — the two channels release in lockstep, ONE timer, never a second clock). The blob peak rides the FIRST portion of the glide (grow+overshoot read as the inflation BEFORE the swollen travel), the squish `--stretch` rides the travel (the gel-stretch along the axis), and both shrink at arrival — the 5-beat read composed from two channels on ONE schedule. PRM: under `prefers-reduced-motion: reduce` the EARLY-RETURN (`:206-209`) already skips the squish; the blob write is gated by the SAME branch → `--tab-blob` stays 1 (no inflation, the indicator snaps to fit — vestibular-safe).

4. **The CSS reads `--tab-blob` as the area scale (compositor-only, both materials).** `segmented-tabs.css` `.segmented-indicator` composes `scale(var(--tab-blob, 1))` with the existing `scale: var(--stretch) calc(1/var(--stretch))` reciprocal squish — but `scale` is a single property, so the two combine into ONE `scale: calc(var(--tab-blob) * var(--stretch)) calc(var(--tab-blob) / var(--stretch))` write (the blob inflates BOTH axes uniformly, the squish stretches one / compresses the other reciprocally — the area-times-squish composition, volume-preserving-squish ON a uniform inflation). The `pill` material (the glass capsule) inflates; the `underline` hairline does NOT (it has no indicator element to deform — the existing `isUnderline` early-return gates it, byte-untouched). Center-anchored so the blob grows from the indicator center (the BA-VJS-3 center-pin preserved).

Compositor-only throughout (`scale`/`transform` + the registered `--tab-blob`/`--stretch` customs — never a layout property; `proof:no-layout-animation` scans `src/styles` + `src/components`). Safari-safe by construction (the envelope is pure pointer-free CSS `scale` on the indicator's own box — no `backdrop-filter: url()`, no WebGL, no SVG goo — the BC.W-LIQUID-TAB cross-engine precedent: "pure compositor transform, works identically on WebKit").

## The defect / the ask

V2 (the Apple-generative-aurora reference, f_009→f_010 / f_018) and ORCHESTRATOR-NOTES §"The DOCK = the now-playing pill": the now-playing field is NOT static — it ABSORBS the playing album's color (violet over "Your Essentials", teal over "Chill") and the whole field re-derives toward that hue when the protagonist changes. SEED-DRAFT Band-6 W-AUR-ALBUM names the facility verbatim: `deriveAuroraPalette(img)` — a dominant-OKLCh-hue + lightness-walked companion-stops extractor → writes the aurora `palette`; a SINGLE-HUE lightness-walk palette MODE; a palette CROSS-FADE on protagonist change (slow OKLCh shorter-hue interp over a breathing clock, no hard-cut); the immersive-media per-route register (mount `<Aurora>` ONLY where a media protagonist is present); a calm-CEILING (cap at breathing, never drifting); uniform anti-band grain.

The HEAD gaps, each a real source fact:
1. **There is no IMAGE-derived palette path.** `src/components/custom/aurora/composables/color.ts:182` `deriveAurora(seed, …)` takes a CSS color STRING or an `OklchStop` — never an `HTMLImageElement` / album-art URL. `src/composables/glass/useGlassBackdropLuminance.ts:179-221` already extracts a chroma×alpha-weighted modal OKLCh hue from a CANVAS via `accumulateHuePixel`/`resolveAmbientHue` (the BE.W-AMBIENT-TINT histogram), but it samples a LIVE backdrop canvas at ≤4Hz for the `--glass-ambient-hue` legibility cast — it is not a one-shot album-art extractor and it writes a CSS token, not the aurora `palette` config. The image→dominant-hue→palette path is absent.
2. **W-AUR-REACTIVE re-seeds `nuclei[].color` / `flow.focal*` off a HUE token, demo-locally.** `BE.W-AUR-REACTIVE` wires a DockStage watcher to read `--glass-ambient-hue` and bias the field — but it nudges the EXISTING palette toward a hue; it never RE-DERIVES the palette as a coherent single-hue lightness-walk from the album, and it has no protagonist-change cross-fade (a hue swap is an instant config change). The "the field IS this album" register the V2 frames show (a coherent violet→cream ramp, not the wispy-sky palette tinted violet) is unbuilt.
3. **There is no immersive-media per-route gate + no calm-ceiling.** Aurora mounts wherever a story declares it (`demo/stories/dock/DockStage.vue:50` mounts ONE static `DEFAULT_AURORA_CONFIG`); there is no "mount the protagonist field ONLY where a media protagonist is present" register, and the `motion` atom (`atoms.ts:341-353`) can drive `drifting` — the album field must cap at `breathing` (the V2 reference is a slow living breath, never the busy `drifting` register).
4. **No anti-band grain.** A two-color OKLCh ramp over a smooth gradient bands on a real panel; the V2 field carries a uniform sub-perceptual grain that kills the banding. The aurora has the medium-texture grain but no uniform anti-band dither on the smooth core.

## The mechanism

ONE new composer `deriveAuroraPalette(source, options)` (`src/components/custom/aurora/composables/albumPalette.ts`, on `/aurora`) + ONE consumer register (the DockStage immersive seam, presets-in-consumers). NO new viz, NO new rAF, NO second color core — it COMPOSES the shipped primitives.

1. **`deriveAuroraPalette(source, options)` — the image→palette extractor (the headline).** `source` is an `HTMLImageElement` | album-art `string` URL | `HTMLCanvasElement`. It downsamples to a 32×32 offscreen canvas (`drawImage + getImageData`, the SAME `SAMPLE_DOWNSAMPLE=32` discipline `useGlassBackdropLuminance.ts:110` runs), then bins every pixel through the EXISTING `accumulateHuePixel`/`resolveAmbientHue` chroma×alpha-weighted 12-bucket OKLCh histogram — the histogram leaf is the **ALREADY-HOISTED `src/composables/color/hueHistogram.ts`** (minted by `W-HUE-HISTOGRAM-HOIST`, the T1 Band-1 consolidate that hoists it out of `useGlassBackdropLuminance.ts`) — this one-shot extractor READS that shared accumulator (the no-dual-path discipline — NOT a re-fork of the binning math; the live observer AND this extractor both re-import the ONE leaf, behaviour byte-identical). The modal chroma-weighted hue is the album's dominant OKLCh hue; its lightness is the median pixel L (a second free Float accumulator in the same pass). The dominant `{L,C,h}` becomes the SEED handed to the SHIPPED `deriveAurora(seed, { harmony })` (`color.ts:182`) — so the companion stops are the value.js gamut-mapped lightness-walk the aurora already speaks (`proof:single-color-core` holds; NO hand-rolled rgb→palette). The OUTPUT is `OklchStop[]` (the `AuroraConfig.palette` shape) PLUS the dominant hue (for the consumer's tint reads). The image read is value.js-math only; the downsample is one canvas reused per call.
2. **The SINGLE-HUE lightness-walk palette MODE.** `deriveAuroraPalette(source, { mode: "single-hue" })` passes `harmony: "monochrome"` to `deriveAurora` — every stop holds the album's ONE dominant hue, only L and C travel (`color.ts` `deriveHue` `monochrome` case, `composables/color/index.ts:201`). This is the V2 "the page IS this color" coherent ramp (deep album-hue base → near-white cream apex, ONE hue). The default `mode: "harmony"` keeps the analogous spread (a richer field for a multi-hue album); the mode is the calm-vs-rich axis, both off the ONE `deriveAurora`.
3. **The protagonist-change CROSS-FADE (composes BD.W-SEED-MORPH).** On a protagonist change the new palette does NOT hard-cut — it rides BD.W-SEED-MORPH's generic seed→palette OKLCh shorter-hue morph (the `useLiquidFlex` scalar driving the `interpolateHue("shorter")` walk from the old dominant hue to the new, over a SLOW breathing clock). The cross-fade re-uploads the interpolated `palette` through the EXISTING runtime `update(cfg)` (`runtime.ts:469`) per breathing tick — no hard swap, no second engine. This wave is the album CONSUMER of SEED-MORPH (SEED-MORPH is the generic; ALBUM supplies the source-hue extraction + the immersive register).
4. **The immersive-media per-route register + calm-ceiling.** A thin demo-local `useAuroraProtagonist(mediaRef)` seam (presets-in-consumers — `demo/stories/`, NOT a library file) mounts `<Aurora>` ONLY when a media protagonist (`mediaRef.value`) is present, derives its palette via `deriveAuroraPalette`, and caps the `motion` atom at `breathing` (never `drifting` — the calm-ceiling). The aurora config is the demo's reactive object; the library composer + the SEED-MORPH cross-fade are the shipped half. When no protagonist is present the field un-mounts (the one-GL-context-per-route budget; no idle protagonist field).
5. **The uniform anti-band grain.** The smooth-core aurora gains a NEW bounded `uGrain` scalar (default 0 — the no-op floor) reading the EXISTING medium-grain texture chunk as a uniform sub-perceptual dither over the whole field (NOT a per-medium texture — a flat ordered-dither alpha over the smooth gradient). Additive, default-off, byte-identical at `uGrain=0`; the `.frag` + WGSL in lockstep (the GL-fence: bounded, additive). The album register sets it to a low value so a two-color ramp does not band.

**Compositor-only**: the consumer writes CONFIG (re-derives `palette`), which the shader reads — no DOM layout animation; the cross-fade is a per-tick `update()` re-upload on the substrate's own clock. **Safari-safe**: `deriveAuroraPalette` is JS + value.js (universal); the `uGrain` term rides the `.frag` + WGSL lockstep (WebKit-26 / WebGL2 floor); the cross-fade is config-only. **PRM**: the cross-fade collapses to an instant seat (the new palette is set directly, no morph frames — a hue shift is not motion); `uGrain` is static under PRM (the substrate freezes `t`). **KISS+DRY**: ONE extractor over the SHARED histogram leaf + the SHIPPED `deriveAurora`; the cross-fade is SEED-MORPH; no second color core, no second canvas loop, no new rAF.

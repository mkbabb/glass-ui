## The defect / the ask (Pass-D code-grounded — `critique/passd-dots.md §D4 + §D5`)

The dot-matrix family's "the dots draw an IMAGE" register — the dots form a target coverage `T(uv,t)` (a generative pattern, an uploaded texture, an SDF shape) and a directional WAVE washes across it revealing/concealing the coverage — is the dot-trio's expressive headline. Pass-D traces three findings:

1. **The `target` source axis (generative/texture/sdf) is REAL + un-built; the GLYPH 2D-trap is CUT.** A glyph-as-dot-target (text → dots) is a 2D-canvas rasterize-the-glyph trap (the FRedrawOverlay Canvas2D D1-violation class — it drags a `getContext("2d")` glyph raster into a GPU-only suite). CUT it. The honest source axis is generative (a procedural `T(uv,t)` field — the W-FIELD-ENGINE value-noise host), texture (an uploaded image's luminance → coverage), and sdf (an analytic shape distance → coverage) — each a GPU-native coverage source, no 2D canvas.

2. **The wash is a STATELESS `f(uv,t)` (confirmed against the EXISTING dot-flow — the NEW front must match its discipline).** `critique/passd-dots.md §D5`: the existing dot-flow `sampleHeight(o,t)` (`flowField.ts:240`) is a pure Gerstner sum `Σ aᵢ·sin(k·(d·o) − ω·t + φ)` — STATELESS, the phase sweeps spatially along `d` over time, `waveBand(h,center,width)` lights the iso-band — so the band genuinely WASHES as `f(o,t)`, no accumulated state, no re-seed. W-DOT-IMAGE's NEW directional front (the wash revealing the target coverage) MUST be the SAME stateless discipline: a `revealWash(uv, t)` that is a pure `f(uv,t)` (a directional phase front, NOT an accumulated reveal buffer). A per-frame "accumulate which dots have been revealed" state buffer is FORBIDDEN (it is the stateful re-seed the dot-flow retopology explicitly killed).

3. **The TEXTURE path is cross-backend Safari-DIVERGENT, and the analytic parity CANNOT catch it.** `critique/passd-dots.md §D4`: `copyExternalImageToTexture` (WebGPU) vs `texImage2D(ImageBitmap)` (WebGL2-WebKit) carry DIFFERENT `UNPACK_PREMULTIPLY_ALPHA_WEBGL` / `UNPACK_COLORSPACE_CONVERSION_WEBGL` / `flipY` semantics — a genuine cross-backend luminance divergence. None of these appear in `src/` (re-grepped) — the texture path is 100% net-new on BOTH backends. The deeper point: the "ONE math source round-trips → ΔE 0.0" discipline CANNOT certify a texture-upload divergence (the upload is not arithmetic the transpiler/oracle reach — it is a GPU resource-creation semantics difference). The parity gate for the texture arm MUST be a REAL rendered-capture-pair (a WebGPU-rendered frame vs a WebGL2-rendered frame of the SAME uploaded image, decoded + compared), NOT a numeric eval and NOT a name-presence.

The ask: add the `target` coverage `T(uv,t)` source axis (generative/texture/sdf — glyph CUT) to the `<DotViz>` shell; the reveal wash STATELESS `f(uv,t)`; a TEXTURE-PARITY sub-wave with a real rendered-capture-pair (the Safari-divergent upload caught by a binding pixel comparison, never a name-presence).

## The mechanism — the `target` coverage source + the stateless wash + the texture-parity sub-wave

### 1. The `target` coverage `T(uv,t)` source axis — a CONSTRUCTION-TIME permutation on the `<DotViz>` shell

`T(uv,t) ∈ [0,1]` is the per-dot TARGET coverage (the dot's "should I be lit / how big" coverage at its lattice position) — the image the dots draw. The shell (W-DOT-UNIFY's `<DotViz>`) takes a `source: "generative" | "texture" | "sdf"` permutation (a CONSTRUCTION-TIME pick, NOT a runtime god-branch — the gate B1 asserts each source is a separate shader program, never a runtime `if (uSource)` three-way switch):

- **`source: "generative"`** — `T(uv,t) = generativeCoverage(uv, t)`, a procedural value-noise / SDF-combination field (the W-FIELD-ENGINE value-noise host — `valueNoise`/`fbm` from the shared `field/noise` chunk, NOT a re-fork). Stateless, GPU-native, no upload.
- **`source: "sdf"`** — `T(uv,t) = 1 - smoothstep(0, aa, sdShape(uv, t))`, an analytic shape distance (a circle/star/the warm-cream identity glyph as an SDF, NOT a rasterized text glyph) → coverage. GPU-native, no 2D canvas.
- **`source: "texture"`** — `T(uv,t) = luminance(textureSample(uImage, uv))`, the uploaded image's luminance → coverage. The ONLY source that needs an upload (the §3 texture-parity sub-wave owns its cross-backend divergence).
- **GLYPH is CUT.** A `source: "glyph"` (text → dots via a 2D-canvas glyph raster) is FORBIDDEN — it drags a `getContext("2d")` into a GPU-only suite (the D1-violation class). A consumer wanting a glyph target authors it as an SDF (`source: "sdf"`) or pre-rasterizes it to a texture in THEIR app (presets-in-consumers). The gate (B4) asserts no `glyph` source + no `getContext("2d")` in the dot-image path.

### 2. The reveal wash is a STATELESS `f(uv,t)` (the dot-flow discipline — no accumulated reveal buffer)

The directional front that washes across the target coverage (revealing the dots that form the image) is a PURE `f(uv,t)`, the SAME stateless Gerstner-front discipline the existing dot-flow `sampleHeight` uses:

- **`revealWash(uv, t) = waveBand(directionalPhase(uv, t), center(t), width)`** — `directionalPhase(uv,t) = k·(d·uv) − ω·t` (a directional phase front sweeping along `d` over `t`), `center(t)` a slow sweep of the band center across the domain. The lit coverage is `T(uv,t) · revealWash(uv,t)` (the wash gates the target — a dot is lit IFF the wash front has reached it AND the target wants it lit). PURE `f(uv,t)` — the same phase-sweeps-spatially discipline as `flowField.ts:240` `sampleHeight`, no accumulated state.
- **NO reveal buffer.** A per-frame "which dots have been revealed" accumulation buffer is FORBIDDEN (it is the stateful re-seed the BC dot-flow retopology killed — `gpu-parity-table.md:78` "NO advection, NO re-seed"). The wash is reproducible at any `(uv, t)` with no frame history. The gate (B2) asserts the wash is a pure `f(uv,t)` (no storage-buffer accumulation read in the wash path; a `revealedState[i]` buffer read REDs).
- **The wash COMPOSES the shipped `waveBand`** (the dot-flow iso-band, `flowField.ts:294`) + the shared field-engine front — NOT a second wave-band primitive. The gate (B2) asserts the wash reads the ONE `waveBand` / `field/wave` chunk, not a re-fork.

### 3. The TEXTURE-PARITY sub-wave — the real rendered-capture-pair (the Safari-divergent upload caught by pixels, not a name-presence)

The `source: "texture"` arm's cross-backend divergence (`copyExternalImageToTexture` vs `texImage2D`) is NOT analytic — the parity gate is a REAL rendered-capture-pair:

- **The upload path is named on BOTH backends.** WebGPU: `device.queue.copyExternalImageToTexture({ source: imageBitmap }, { texture, premultipliedAlpha: false, colorSpaceConversion: "none" }, size)` (the explicit premultiply + colorspace control). WebGL2: `texImage2D(TEXTURE_2D, 0, RGBA, RGBA, UNSIGNED_BYTE, imageBitmap)` with `pixelStorei(UNPACK_PREMULTIPLY_ALPHA_WEBGL, false)` + `pixelStorei(UNPACK_COLORSPACE_CONVERSION_WEBGL, NONE)` + `pixelStorei(UNPACK_FLIP_Y_WEBGL, false)` (the explicit-match of the WebGPU semantics — the Safari-divergence FIX is making both backends declare the SAME premultiply/colorspace/flipY, never relying on the engine default). The image is decoded via `createImageBitmap(blob, { premultiplyAlpha: "none", colorSpaceConversion: "none" })` (the ONE decode, both backends share the ImageBitmap).
- **The parity is a RENDERED-CAPTURE-PAIR, not a numeric eval.** `proof:dot-image` clause T3 does NOT call `assertParity` (the field arm's transpiler — the upload is not transpilable arithmetic). It runs a REAL rendered-capture-pair: the binding π (`tests-visual/dot-image.spec.ts`) renders the SAME uploaded test image through the WebGPU primary AND the WebGL2 fallback (the webkit project — the Safari path), decodes both via `getImageData`, and computes the OKLab ΔE over the dot field. The gate (T3) READS the recorded capture-pair ΔE from `docs/tranches/BD/audit/dot-image-texture-parity.json` (a gate-WRITTEN measurement with a `measuredBy: "tests-visual/dot-image.spec.ts"` provenance + the webkit-vs-chromium pair) and asserts it ≤ the texture bar. A `verified ΔE 0.0` with a hand-typed number / a name-presence `/copyExternalImageToTexture/.test()` round-trip REDs (the false-green-texture bite — the `proof:gate-truth` G5 class for the texture axis). The premultiply/colorspace/flipY semantics MUST match across backends — a missing `pixelStorei(UNPACK_PREMULTIPLY_ALPHA_WEBGL, false)` produces a NON-zero ΔE the capture-pair catches.

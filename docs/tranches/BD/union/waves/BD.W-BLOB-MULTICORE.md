## The defect / the ask (Pass-D code-grounded — `critique/passd-blob.md FINDING 1`, the HARDEST finding)

The blob is a SINGLE-CORE metaball today — ONE body term in `sceneDistG` (`metaball.frag.ts:97-167`) + N satellites + a trail. The ask (`UNIFIED-ROSTER.md:162`, `VIZ-FINAL-ROSTER.md §Band 13`) is to generalize the body into N cores (M merged blob-bodies, the lava-lamp / multi-creature register) — AND to do it inside a REAL perf budget, because the multicore multiplies a per-fragment cost that is ALREADY 15× the framework's claimed number. The exact, code-traced arithmetic (`critique/passd-blob.md FINDING 1`, re-verified against the live shader):

1. **`sceneDistG` is ~20 SDF evals TODAY, not "33 at the cap."** `sceneDistG` (`metaball.frag.ts:97-167`) = `1 body + MAX_SATS + TRAIL_N` circle evals. With `MAX_SATS=4`, `TRAIL_N=15` (`constants.ts:13,16`), that is **up to 20 `sdgCircle`+`sminG` evals per CALL** today. Each eval is an `sdgCircle` (`sdf-body.glsl.ts:31`: `length` + a `normalize` divide) + a `sminG` (`sminCircularG`: `sqrt(1 - h(h-2))`, `sdf-body.glsl.ts:78-86`); the body term ALSO runs a 3-octave `fbmWarpedG` (`metaball.frag.ts:130`).

2. **`sceneDistG` is called inside a 24-STEP soft-shadow raymarch.** `softShadow2D` (`metaball.frag.ts:193-208`) is `for (i<24) { sceneDistG(ro+rd*t).x }`, gated `uShadow > 0.5` (`:385`). The WGSL twin is byte-identical (`metaball.wgsl.ts:236-251`, `for (var i=0;i<24…) sceneDistG(...)`). So **shadow-ON cost = `sceneDistG(main) + 24×sceneDistG(shadow)` = 25 × 20 ≈ up to 500 SDF evals/frag at M=1 TODAY.** The framework counted ONE `sceneDistG` and FORGOT the 24× multiplier — "~33" is the cost of a single call, not a fragment.

3. **At M=6 / K=12 / J=15 the count explodes to ~825/frag.** Each `sceneDistG` becomes `M + K + J` = 6+12+15 = 33 terms → shadow-ON = `33 + 24×33 = 825 evals/frag`. At 825 evals over a hero canvas at mobile DPR this is a real frame cliff. **The single most likely real conclusion the trace forces: shadow MUST be force-OFF in multicore (the 24× term IS the killer), and M caps at ≤3, not 6.** (`critique/passd-blob.md FINDING 1 VERDICT`.)

### 2. Force shadow OFF in multicore (the 24× killer — the structural budget fix)

The shadow march is the 24× multiplier; at M>1 it dominates. **The shader gates `uShadow` OFF whenever `uCoreCount > 1`** — the `if (uShadow > 0.5)` block (`metaball.frag.ts:385`, `metaball.wgsl.ts` twin) is re-gated `if (uShadow > 0.5 && uCoreCount <= 1.5)` (the float-compare guard). So a single-core blob keeps its soft contact shadow (the BC.W-GOOBLOB-MEATBALL register, the calm-bead identity); a multicore blob renders SHADOWLESS (the 24× term evaporates → 33 evals/frag, not 825). This is the structural fix the trace forces — NOT a runtime cap that hopes the GPU keeps up. The JS uploader (`uploadBlobUniforms.ts:316` — the `uShadow` write) ALSO clamps `uShadow=0` when `cores>1` (the belt-and-suspenders: the uniform is OFF AND the shader gates it — a single source of truth would be the shader gate, but the JS clamp avoids uploading a dead-flag). The gate (B2) asserts BOTH the shader `uCoreCount<=1.5` guard AND the JS clamp.

# BD.W-PAGE-CHASSIS — the page-chassis header rule + the systemic duplicate-header fold + the section label→heading re-key

**Band 16 (demo-chassis) · Tier T16 · depends: — (a demo-chassis-only refactor; zero src/ paint) · folds the ADDENDUM-DEMO-CHASSIS asks 3+10 + the batch-2/3 SYSTEMIC duplicate-header finding · pairs with W-HEADER-SCALE (the heroScale rung halve, the manifest `assignDepths` map — its territory, NOT this wave's) + W-STICKY-TITLE-CONDENSE (the sticky-bar backing — its territory)**

## The defect / the ask

Three live-confirmed page-chassis defects, each on EVERY storybook page (118 pages, 11 categories). The KISS/DRY law (the user's binding mandate): the fix lands ONCE in the shared chassis (`StoryPage.vue` / `StoryHero.vue` / `StoryHeader.vue` / `StorySection.vue` + the manifest) → propagates to all 118 pages. A per-page bespoke fix is the anti-pattern this wave RETIRES.

1. **No DIVIDING LINE below the header on ANY page (ADDENDUM ask 3 + 10).** Live `getComputedStyle` on the chrome `<header>` computes `border-bottom: 0px` and `--story-header-rule` is `(unset)` at `:root` (forms.md §2, batch-1 §W-PAGE-CHASSIS). There is NO header→body separation — the audacious title and the first body section blur together with no hierarchy seam. The in-BODY `.story-sections--delimited` hairline DOES paint (story-hero.css:428, reading the dark-adaptive `--configurator-divider` token), but the header→body seam was never minted.

2. **The SYSTEMIC duplicate hand-rolled in-card `<header>` (the double-header root — batch-2/3 SYSTEMIC finding).** 11/12 forms, 13/14 containers, 3/4 nav, 6/8 feedback, 4 motion, 2 data — **36 demo files** (grep-confirmed: `<header>` + `IconChip` co-present) each HAND-ROLL a SECONDARY in-card `<header>` IconChip cluster that DUPLICATES the chassis descriptor the `StoryHeader` already renders above the card. The block is a byte-identical copy-paste, e.g. `forms/inputs.vue:24-42`:
   ```vue
   <header class="flex items-center gap-4 pl-5"
       :style="{ '--section-label-accent': `var(--section-color-${FORMS_STOP})`,
                 borderLeft: '3px solid color-mix(in srgb, var(--section-label-accent) 55%, transparent)' }">
       <IconChip :icon="TextCursorInput" :section="FORMS_STOP" bloom reveal />
       <div class="flex flex-col gap-1">
           <span class="section-label--tinted text-admin-label">Forms · Text input</span>
           <p class="text-small text-muted-foreground">…blurb…</p>
       </div>
   </header>
   ```
   Each page hardcodes its own `const FORMS_STOP = 3` (the per-category color identity — forms-stop-3 teal, data-stop-9, feedback-stop-8, etc.), its own icon, and re-pastes the eyebrow + blurb the chassis ALREADY renders. Result: the descriptor renders TWICE (the chassis `StoryHeader` cluster + the hand-rolled in-card header) — the "title rendered ~3×" the user saw (batch-1 §W-STICKY: chassis `StoryHeader` + this in-card header + the aurora masthead). `containers/spa-view.vue` + `containers/toc-tracking` + `feedback/toaster.vue` are the CLEAN reference models (no duplicate in-card header — they render the body directly under the chassis descriptor).

3. **Most pages render ZERO section `<h2>` — `<StorySection label=>` eyebrow-only (the genuinely-per-page arm).** The audit table (forms.md §1) measured: only 3 of 12 forms pages use the canonical `<StorySection heading=>` (the semantic `<h2 class="text-subheading">`/20.4px); the other 9 (+ most of data/feedback/display) use `<StorySection label=>` (the mono-caption eyebrow, NO heading) or a raw unlabeled `<section>`. So most pages have NO section-level heading hierarchy — the "design hierarchy + affordance is AWFUL" defect (ADDENDUM ask 10). `forms/inputs.vue`, `feedback/toaster.vue`, `forms/checks.vue` are the reference models (`heading=` → real `<h2>`).

All three are CHASSIS-or-near-chassis fixes: arms 1+2 land ONCE in the chassis (the rule token + the descriptor-fold prop), arm 3 is the per-page `label`→`heading` re-key that the SHARED chassis already supports (the `heading` prop exists on `StorySection` — the pages just don't use it).

## The mechanism (3 arms, ONE chassis)

Demo-only (zero `src/` paint — the library `StorySection.vue` heading rung + the `--configurator-divider` token already exist and are byte-untouched). KISS+DRY: the single-writer seam is the chassis; per-page bespoke is the anti-pattern.

### Arm 1 — the `--story-header-rule` dividing line below the header (the chassis-once fix)

Mint `--story-header-rule` and draw a hairline on the BOTTOM of the chrome `<header>` (the descriptor band), REUSING the existing delimiter vocabulary — NOT a new color:

- **The token (`story-hero.css`, beside the `.story-sections--delimited` block at :428).** `--story-header-rule: 1px solid var(--configurator-divider)` — the EXACT dark-adaptive hairline the in-body `.story-sections--delimited` seam already reads (the `light-dark()` warm-ink that survives the dark glass plate — CLAUDE.md §BA.W-CONFIG-CHASSIS). NEVER an inline `border-border/N` alpha (vanishes on the dark card). ONE retune knob.
- **The paint.** `StoryPage.vue`'s `<header v-if="variant === 'page'">` (the chrome header, the descriptor band) gets `border-block-end: var(--story-header-rule)` + a touch of `padding-block-end` breathing room so the rule does not crowd the first body section. The rule sits on the header WRAPPER, so it is ONE edit reaching all 118 content pages. On a HERO page the chrome header is suppressed (the descriptor re-homes into the StoryHero cluster over the live field — already correct), so the rule is content-page only by construction.
- **The sticky interaction.** The rule rides the cluster wrapper, so as the `.story-hero-shrink` register shrinks the header on scroll the rule shrinks WITH it (it is a `border` on the same box — no second sticky element). W-STICKY-TITLE-CONDENSE owns the backing-bar scrim; this arm owns only the hairline seam.

### Arm 2 — FOLD the systemic duplicate per-page header INTO the chassis (the ~30+ copy-paste retire)

The per-page in-card `<header>` IconChip cluster is RETIRED across all 36 files; its ONLY non-chassis content — the per-category COLOR IDENTITY (the `--section-color-N` stop + the lucide icon) — is routed through the chassis via a per-CATEGORY map (the `CATEGORY_DEFAULT_BG` architectural precedent, manifest.ts:181):

- **The `CATEGORY_STOP` map (manifest.ts, beside `CATEGORY_DEFAULT_BG`).** `const CATEGORY_STOP: Record<string, number> = { forms: 3, data: 9, feedback: 8, containers: 2, navigation: 12, … }` — the per-category `--section-color-N` ramp index, ONE literal per category (the 11 hardcoded `const FORMS_STOP = 3` re-pastes collapse to ONE map entry). The category's lucide icon ALREADY lives on the `Category.icon` field (manifest.ts:90) — REUSED, never re-declared per page.
- **The chassis IconChip POP (`StoryHeader.vue`).** The chassis `StoryHeader` cluster gains an OPTIONAL leading `<IconChip :icon="categoryIcon" :section="categoryStop" bloom reveal>` (resolved from the manifest row's category, threaded through `StoryPage`→`StoryHero`→`StoryHeader` like `subpath`/`depth` already are). So the ONE deliberate section-color POP (the W-SUFFUSE one-color-event vehicle) now lives in the chassis descriptor cluster — rendered ONCE, beside the eyebrow→title→blurb the chassis already owns. The `--section-label-accent` borderLeft rail folds onto the same chassis cluster (a `:style` derived from `categoryStop`).
- **The 36 per-page `<header>` blocks are DELETED (clean break, no alias).** Each page drops its hand-rolled `<header>` + its `const FORMS_STOP = …` + the `IconChip` import + the duplicate eyebrow/blurb. The page body becomes the `<StorySection>` stack directly under `<StoryPage>` (the `spa-view.vue`/`toaster.vue` clean-reference shape). Result: ONE descriptor per page (the chassis cluster), the double-header GONE, ~30+ copy-pastes retired in ONE chassis edit + 36 trivial per-page deletions.

### Arm 3 — the `label`→`heading` section re-key (the per-page arm, on the SHARED chassis)

The `<StorySection heading=>` prop ALREADY renders a semantic `<h2 class="text-subheading">` (StorySection.vue:79, the AZ.W-HIERARCHY canonical rung — byte-untouched). The per-page arm re-keys the pages that render 0 `<h2>`: every `<StorySection label="…">` that NAMES a section (not a bare eyebrow caption) becomes `<StorySection heading="…">` (or keeps `label` AND adds `heading` where both a caption + a heading read). Raw unlabeled `<section>` blocks (e.g. `number-field.vue`'s grids, `multi-select.vue`/`select.vue`'s `<Label>`-only sections) adopt `<StorySection heading=>`. The reference models (`forms/inputs.vue`, `feedback/toaster.vue`, `forms/checks.vue`) already do this. This is the genuinely-per-page arm (the chassis SUPPORTS it; the pages just don't use it) — NOT a new primitive.

This is NOT a re-fork — arm 1 reuses the `--configurator-divider` vocabulary, arm 2 reuses the `Category.icon` + the `CATEGORY_DEFAULT_BG` map precedent + the shipped `<IconChip>`/`StoryHeader` cluster, arm 3 reuses the shipped `StorySection heading` rung. It mints NO new chassis primitive beyond the ONE `--story-header-rule` token + the ONE `CATEGORY_STOP` map; it DELETES 36 redundant in-card header recipes.

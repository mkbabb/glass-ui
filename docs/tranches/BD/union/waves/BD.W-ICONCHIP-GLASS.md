## The defect / the ask

`IconChip` has exactly ONE backplate register today — a `color-mix(in srgb …)` flat foreground-over-transparent overlay, ZERO `backdrop-filter` (verified: `grep -c backdrop-filter src/styles/icon-chip.css` → **0**). iOS-27 icon chips are FROSTED GLASS discs (the backdrop reads through the chip — the Maps POI chip over the live map) OR SATURATED FILLED tiles (an opaque tone plate with an auto-contrast glyph that never reads broken on any tone). And the f_073 Control-Center cluster fuses N chips into ONE frosted superellipse group — the idiom that reads MOST broken on Safari without the cross-engine silhouette.

This wave adds two new registers on the EXISTING recipe (the substitution-over-redeclaration discipline — NO parallel chip): `surface="glass"` (a frosted disc — real `backdrop-filter` + the tone reads THROUGH the ONE `--glass-fill-tint` per-instance plate axis, so the page bleeds through the chip the way a Maps POI chip reads over the map) and `surface="filled"` (an opaque tone plate + a value.js `safeAccentColor`-resolved glyph that auto-darkens/lightens until it clears AA, never a fixed ink that drops illegible on a saturated tone) — PLUS the cards-domain BETTERS: the f_073 grouped-squircle CLUSTER (`<IconChipCluster>` — N chips FUSED into ONE frosted superellipse group with concentric nested radii + a shared rim-lensing). The iOS-27 betters-claim: the chip stops being a flat tinted dot and becomes a genuine frosted lens over the live field OR a saturated auto-legible tile, and N controls read as ONE liquid-glass cluster, not N detached dots.

## The mechanism

One CSS register-add + one prop + one new colocated component, on the existing recipe — no parallel chip:

1. **The `surface` prop** (`"plate" (default) | "glass" | "filled"`). `"plate"` is the byte-identical HEAD register (the flat `color-mix(in srgb …)` overlay — clean keep, no behaviour change at the default; `proof:icon-chip` W1 stays GREEN). `IconChip.vue` binds `:data-surface="props.surface"` (the `[data-surface]` decoration hook the shared surface-axis idiom uses) and threads it through `:class`.
2. **The `glass` register** (`icon-chip.css`, a `.icon-chip[data-surface="glass"]` rule). Frosted disc: `background: var(--glass-bg-quiet)` (the content-tier translucent rung) + `backdrop-filter: var(--glass-blur-quiet)` (the REAL frost — the born-RED-killing line), the page/aurora reading THROUGH the chip (the Maps-POI register) while the tone whispers the event hue. **THE TONE-TINT CONSUMES the ONE `--glass-fill-tint` per-instance plate axis (W-TINTED-CHIP), NOT a parallel icon-chip glass-tint** (the 3-way chip fork killed — the LEDGER DRY fix). `IconChip.vue` writes the resolved event hue onto `--glass-fill-tint` (+ a bounded `--glass-fill-strength`, default the chip register ~14%) when `surface==="glass"`, so the body tints through the SAME `color-mix(in oklab, <the W55-composed plate>, var(--glass-fill-tint) var(--glass-fill-strength))` seam `glass/ladder.css` composes (the W-TINTED-CHIP consume-wire) for every glass surface — the icon-chip is TINTED-CHIP's genuine 2nd plate-fill consumer, never a re-minted `--icon-chip-glass-tint`. NO new `--icon-chip-glass-tint-strength` token, NO parallel oklab mix on the chip recipe. The `--glass-border-quiet` rim hairline rides the rung; `contain: paint` (the `.glass-btn:62` nested-backdrop-cost precedent) keeps the chip's own backdrop sample in-box when it nests in a glass card.
3. **The `filled` register** (`.icon-chip[data-surface="filled"]`). Opaque tone plate: `background: var(--icon-chip-plate-color)` at FULL opacity (no transparency — the saturated tile), the glyph reads `--icon-chip-filled-glyph` — the value.js-resolved auto-contrast ink. CSS cannot call value.js, so (mirroring `useAccentTone`'s `--accent-ink-resolved` seam) `IconChip.vue` resolves `safeAccentColor(plateColor, bandLightnessOf(plateColor), 4.5)` when `surface==="filled"` and writes `--icon-chip-filled-glyph`; the CSS reads `color: var(--icon-chip-filled-glyph, var(--foreground))`. ZERO re-rolled contrast math (imports the SAME `safeAccentColor` from `@mkbabb/value.js` — `proof:single-color-core` holds). The `var(…, var(--foreground))` fallback is the safe SSR/no-tone seat.
4. **The CLUSTER — `<IconChipCluster>`** (new colocated component in the icon-chip dir, the f_073 betters). Renders a slotted row/grid of `<IconChip surface="glass">` children inside ONE frosted superellipse group plate: the group is a `surface="glass"` plate that ALSO reads the cross-engine squircle silhouette (composes BE.W-SQUIRCLE-COVERAGE's `clip-path` superellipse floor + the `corner-shape` Chromium PE) and the shared rim lens (composes BE.W-LENS-SAFARI's `.glass-lens` — ONE shared rim, not per-chip). The CONCENTRIC radii: the group root radius drives the child chip radius via `--radius-concentric(<group-radius>, <gap-inset>)` (BE.W-CONCENTRIC-RADIUS), so the nested chip corners are mathematically concentric with the group corner (the Apple containerConcentric law) — NOT a hand-picked per-chip radius. COMPOSITOR-ONLY (no animated layout); a hover-bloom rides the existing `--spring-smooth` register.

**Compositor / Safari / PRM:** the `glass` `backdrop-filter` inherits the build-time `-webkit-backdrop-filter` prefix pass for free (`proof:webkit-backdrop`).

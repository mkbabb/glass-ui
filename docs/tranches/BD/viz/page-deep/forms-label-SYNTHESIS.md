**The ONE conflict — the path-label chip (demo says PASS, design says BUG; design is right):**
- **demo §5**: scores the chip a PASS — it renders the standardized `@mkbabb/glass-ui/<subpath>` SHAPE (`/label`), singular and clean.
- **design §8 + component §5(#2)**: it is a real BUG — `Label` is NOT a published subpath (there is no `dist/label.js`); it is a `ui/`-barrel export reachable via the root `@mkbabb/glass-ui` or the `/forms` family subpath. The manifest declares a chunk that does not exist. AND the page composes FIVE primitives (Label/Input/Checkbox/Switch/RadioGroup) — no single subpath labels it honestly.
- **Resolution: design + component win — it is a fabricated chip.** The chip is standardized in SHAPE but factually wrong in REFERENT. The fix is the band convention: a forms-family page chips `@mkbabb/glass-ui/forms` (the band's real published subpath) — NOT a per-primitive `/label`. This folds into the existing header-fold wave's referent sweep. (The demo lens scored shape-conformance and missed that the subpath is unpublished — a one-line correction, not a disagreement on direction.)

**The net-new SRC finding (component lens only — the page's distinguishing src signal, but TINY):**
- **`peer-disabled` opacity hard-snaps** (component §1, F1): `opacity-70` flips with zero `transition` — when a peer toggles `disabled`, the label hard-cuts. Per motion-canon **P1 (EFFECTS→bezier)** an opacity change should ride `--ease-standard`. A real, sub-perceptual dead-transition; the fix is a one-line `transition: opacity var(--duration-fast) var(--ease-standard)` on the disabled rung, library-wide, PRM-safe (opacity-only). This is the ONLY src paint this page owes — and it is a polish micro-fix, NOT an architectural defect (cf. `forms/toggle-chip`'s genuine dual-path + AA-contrast bug, which this page does not have).

**Dropped/merged as low-signal:**
- "Demo the unexercised `required` asterisk + an `IconTooltip`-help-label register" (demo §1, design §2) — VALID but SUBSUMED by the page redesign (the re-scaffold composes the fuller Label API as specimens). Not a standalone wave.
- "The `peer-disabled dims the label` section eyebrow is implementation-jargon" (demo §6) — folds into the copy-tighten, not its own item.
- The four-state contract is N/A for a `<label>` (delegates focus to its `for` target) — correct by design, do not force hover/press onto a label. Component §1. No action.

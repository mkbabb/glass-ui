## 1. Reconciled findings (deduped, conflicts resolved)

### Total agreement across both reports (high confidence)
1. **Single flat outer plate, not sections-as-cards (the user's #1 ask, UNMET).** The whole `StoryPage` body sits on ONE resting-tier plate; the ten sections are hairline-delimited flat regions inside it. A page that documents the 5-rung tier ladder fails to *use* it structurally — the floating/overlay sections render as un-elevated flat copy. Both reports lead here (design #1 "single-plate problem", component D1).
2. **The aurora is a flat warm-peach wash, not a colorful high-frequency field (user ask #5 + DESIGN §L1, UNMET).** `DEFAULT_AURORA_CONFIG` paints a calm low-frequency field, so the §L1 backdrop-blur + saturate channels have nothing to refract and the tier-alpha steps (0.30→0.95) the page exists to reveal are **imperceptible** — all five matrix cards read nearly identical (design #4, component V1/D4). **Plus 2 live Aurora GL contexts on ONE route** violates the one-GL-per-route budget (component V1) — 6 `Aurora` references in the SFC.
3. **~90% static against the iOS-27 / affordance-map bar (user ask: HIGH animation affordance, UNMET).** Only the page-build entrance + the cartoon hover-lift are alive. The 5 tier cards, polymorphic card, nested cards, veil plates, CardAction card are **static on hover, never press, never gleam-track**; the shadow/grain toggles hard-cut instead of cross-fading the §L1 layers. The protagonist surface demonstrates none of its own four-state contract (design #3 "biggest miss", component A1).
4. **Zero dock-API composition (user ask #3, UNMET).** No `<GlassDock>` / `<DockStack>` / `<DockLayerGroup>` / contextual-switching anywhere — yet the tier ladder + surface-axis (glass/veil/opaque/cartoon) + scroll-card family are three textbook *facet axes* the dock contextual-switcher is built to host (design #4, component D3).
5. **Main card area too small (user ask #2, UNMET).** Cards render in a `gap-6 p-6` grid; the tier-matrix + veil hero plate need substantially more viewport to read at premium scale, not as a `p-6` thumbnail strip (design #6, component D2).
6. **Superfluous language (user ask #7, UNMET).** Blurbs over-explain seam internals ("the class merge happens at the single `cn(...)` seam in Card.vue", "field-for-field", "a latent a11y regression this recipe fixes") — tighten to one declarative affordance line per section (design #7, component D6).
7. **The √φ ladder is used ONCE (the masthead) and never again; paper morphism entirely absent.** No second display landmark (no oversized numeral, no pull-quote), no `paper-grain` / `.paper-ink-mark` register on the cartoon/scroll-list specimens that would sing on paper — the GLASS+PAPER north-star half is unmet (design #1, #5).
8. **Import label IS already standardized** — the displayed chip reads `@mkbabb/glass-ui/card` (correct); the SFC's own deep relative import is fine for demo (component D5). **KEEP** — this page is the convention reference, not a defect site.

### Conflicts / nuances resolved
- **Is the base-`<Card>` hover-deadness a SRC gap or a DEMO gap?** The component report frames A1 as a potential **src** finding — "a default `<Card>` is animation-DEAD … the library SHIPS the entrance vocabulary but Card consumes none of it" — and floats a NEW `BD.W-CARD-AFFORDANCE` src wave (default-on hover-lift for content cards). The design report frames the SAME observation as a **demo** gap (opt the *specimens* into `:pressable` + `v-specular`). **Resolution: this is DEMO-side for this page, with a NARROW src question deferred.** The card page's job is to SHOW the four-state contract by opting specimens into the already-shipped `:pressable`/`specular`/cartoon-lift axes — zero src paint needed to fix the page. Whether a *bare* content `<Card>` should ship a default-on hover-lift is a real but SEPARATE library-identity decision (it risks animating every static content plate library-wide, a regression surface) — it does NOT block this page and should NOT be minted as a card-page action. Book it as a question to the affordance-map owner, do not mint a src wave off one page.
- **Two Aurora contexts:** not a conflict — fold to ONE shared offscreen-paused field (the `DockStage` idiom) AND swap `DEFAULT_AURORA_CONFIG` for a saturated/high-frequency preset. Both moves land in `W-PAGE-BACKGROUND`.
- **veil regex-strip smell (component I2):** `surfaceClass('veil').replace(/^glass-\w+\s+/, '')` is a mild src smell — the resolver could expose a `decorationOnly` flavor. Low impact, transpose-don't-patch; folds into the existing `BD.W-FORMS-CARD-FOLD` surface-axis cleanup. NOT a card-page action.

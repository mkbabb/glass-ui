# forms/combobox — FRONTEND-DESIGN critique (Pass-E)

**SFC** `demo/stories/forms/combobox.vue` · **live** http://localhost:5173/forms/combobox · **manifest** `forms/combobox` → `@mkbabb/glass-ui/forms`, `background: "grid"` (CATEGORY_DEFAULT_BG[forms]), content-page (no hero).

The single most damning fact: this page is a 125-line story that renders ONE combobox alone inside a ~410px-tall card whose right two-thirds is dead empty gray. A library whose DESIGN.md opens with "real-time refractive surface, not a Gaussian frost" and a six-layer optical composite is showing a flat slab with a faint grid you have to hunt for. It reads like a Storybook stub, not a glass-ui specimen. Against the BD bar (each sub-section its own glassy card · bigger main area · dock APIs · a SERIES of glass-ui components per page · glass over COLORFUL aurora) this page fails almost every clause. Below, exhaustive and concrete.

---

## 1. VISUAL HIERARCHY — the eye lands, then has nowhere to go

- **The 67px `text-display-4` "Combobox" wins the page, then abandons it.** The audacious √φ title (DESIGN.md §Typography `--type-display-4`, peak 86px) is correctly large and is the right move per StoryPage's depth-keyed `heroScale`. But it crowns a body that is a single 14px label + one 40px pill. The mass ratio of title-to-content is grotesque — the headline promises a feature page and delivers a control demo. The eye lands on COMBOBOX, drops to a tiny pill, and falls off a cliff into 1100px of empty card. There is no second focal beat, no rhythm, nothing to scan.
- **DOUBLE eyebrow — the descriptor is shown twice.** "FORMS · COMBOBOX" renders in the chrome `<header>` (StoryHeader eyebrow, line 102 of StoryPage) AND AGAIN inside the card as the `<IconChip>` + `.section-label--tinted` masthead (combobox.vue:45-63). The chrome header already owns eyebrow → subpath chip → title → blurb in correct reading order (the W-HIERARCHY2 cluster). The in-card masthead repeats "Forms · Combobox" and a blurb that paraphrases the same idea. This is a reading-order inversion the chassis explicitly fixed at the page level, re-introduced by hand inside the body. Pick ONE descriptor home — the chrome header — and delete the in-card masthead, OR make the in-card header a genuine section header for a genuine multi-section page.
- **The typography-forward ladder collapses after the title.** Everything below the `<h1>` is `--type-small` (14px label, blurb) and `--type-caption` mono (the SELECTED readout). There is no `--type-subheading` (20.4px) section rung, no `--type-body`. The √φ ladder DESIGN.md sells as "kinetically typographic" is used for exactly one glyph-run. A specimen page should walk the ladder — a section heading per card, body copy explaining the affordance, the mono readout as the quiet caption.
- **The SELECTED readout (line 120) is a mono caption floating with no container** — it reads as debug output, not a designed state surface. It should live in its own quiet glass-quiet cell or a `<MetricStack>` row, not as orphaned `text-mono-caption`.

## 2. AFFORDANCE — the one control is a hand-rolled `<button>`, not a glass-ui component

- **The trigger is a raw `<button class="glass-wash focus-ring ... rounded-full">` (lines 70-85), not `<ComboboxTrigger>`'s styled affordance.** This is the cardinal sin against DESIGN.md's pillar 2 ("Component over CSS class — interactive elements are Vue components, not utility-class recipes"). The page hand-assembles a glass-wash pill with `h-10 px-3 py-2`, manually places the `ChevronsUpDown` at `opacity-50`. It carries `.focus-ring` (good — the §L5 / affordance-map FOCUS-RING floor) but NOTHING else: no `.tap-squish` press-squish (§L3 — the universal `--scale-press` 0.96 rung), no `v-specular` gleam-track (affordance-map GLEAM-TRACK), no `--scale-hover` lift (HOVER-LIFT). Per the affordance-map gate this trigger is an inert pointer-element: it answers focus but is dead to hover and press. The affordance-map says glass triggers carry H + G + P + F; this carries only F.
- **`glass-wash` is the WRONG tier for a control trigger.** DESIGN.md §Glass Surfaces: wash is 30% opacity / `blur(1px)` — "Dock bg, input bg, hover overlays." It is the permeable veil for chrome that must read the backdrop through. A picker trigger sitting over a flat near-white card has NOTHING behind it to admit — so the wash reads as a barely-there gray gray-on-gray pill with no edge. The control "Glass cannot sample glass" rule isn't even the issue; the issue is there is no backdrop for the wash to lens. Over the colorful aurora the BD bar demands, a `.glass-quiet` or the canonical `.input-pill` control-surface register (CLAUDE.md `--control-surface-bg`) would actually refract.
- **No clear interactive cue.** At rest the pill is gray with a 50%-opacity chevron. There is no hover state visible, no pressed state, no "this filters as you type" hint until you open it. A first-time viewer cannot tell it's a type-ahead combobox vs a plain select.

## 3. ANIMATION AFFORDANCE — almost everything is static; the iOS-27 bar is missed

DESIGN.md §L3 ("tap-squish is universal — Buttons squish, sliders squish... a primitive that wants press feedback consumes the squish-press recipe") and the affordance-map's five-primitive vocabulary are the bar. Against it:

- **The trigger has ZERO motion affordance** — no entrance beyond the page-build, no hover-lift, no press-squish, no gleam-track. It is the single most-touched element on the page and it is dead. This is the headline animation failure.
- **The `<IconChip>` is the ONLY alive element** (`bloom reveal`, line 53) — it rides the W-SUFFUSE3 spring entrance + bloom hover. Ironically the decorative chip is animated while the functional control is static. Exactly inverted from where the energy should go.
- **The dropdown LIST/items** — `<ComboboxItem>` rows inherit the menu-row register (affordance-map: `--menu-row-lift` -1px on `--spring-smooth`, `data-highlighted`), which is correct and good. But it's hidden until open; the page never demonstrates it. A specimen page should show the open state, the type-ahead filter narrowing, the check-indicator landing.
- **No state choreography for selection.** When you pick an option, the trigger label swaps with a hard text replacement (`selected ? ... : "Pick one"`). No crossfade, no `--spring-smooth` pane-swap (§L2 "metric crossfade, pane swap"). The SELECTED readout updates with no animation. The whole "I made a choice" moment is inert.
- **The empty card area is motionless** — no aurora, no procedural backdrop, no ambient life. Per the BD bar and DESIGN.md §L4 Appeal ("`<Aurora>` + the disco-grain" as the distinctive-personality tier), a glass demo page over a static near-white slab has thrown away the library's signature.

## 4. POLISH + DISTINCTIVENESS — reads generic-AI-template, not bespoke-premium

- **This is the generic-AI aesthetic the frontend-design skill exists to AVOID.** Centered-ish single control, flat card, gray-on-gray, one accent, vast dead space. Nothing here says "iOS-26 Liquid Glass." Strip the IconChip and this could be any bootstrap form demo. There is no six-layer composite visible (no rim catch-light reading, no grain, no saturate-lensing), no spring life, no typographic audacity past the title.
- **The card is a flat `bg-card` plate, not a glass surface.** Whatever StoryHero wraps it in, the rendered result is opaque warm-gray with a hard hairline and a subtle drop — it does not read as ANY of the seven tiers. DESIGN.md's whole thesis (the surface IS a lensing layer) is invisible.
- **The single combobox is not a "deftly-composed series of glass-ui components"** (the BD mandate verbatim). It's one control. A combobox specimen should show: the trigger, the open glass-floating list, an empty-state, a multi-group layout, perhaps a "recently picked" chip row, the selected-state surface — each potentially in its OWN glassy card, over aurora, with the dock switching between variants.

## 5. iOS-27 / GLASS / PAPER NORTH-STAR FIDELITY

- **Glass six-layer composite (§L1): absent.** wash over no backdrop = no refraction, no saturate-concentration, no rim halo, no catch-light, no grain reads. The page demonstrates the OPPOSITE of the design language.
- **GLASS + PAPER both (BD bar): neither lands.** The `background: "grid"` paper wash is so faint at the dark-recalibrated light strength it's nearly invisible (you can see faint vertical lines only on the right third). PaperGrid / paper-grain as a real paper material is unused. There is no glass tier reading as glass.
- **Spring physics (§L2): unused on the control.** The named springs (`--spring-snappy` for tap, `--spring-smooth` for swap) touch nothing the user operates here.
- **Dock APIs (BD bar): completely unleveraged.** There IS a dock on the page (the demo shell BottomDock + the layer-rail), but the PAGE does nothing with the contextual-switching / morph / silhouette APIs the prompt calls for. A combobox page could use a `<DockStack>` facet rail to switch between "single · grouped · async · multi" combobox modes, each morphing the demo card — that's the "leverage the dock APIs" move.
- **Suffusion proportion (§one-color-event): technically correct but starved.** The teal `--section-color-3` is the ONE color event (IconChip + accent rail + tinted eyebrow), which is the right discipline. But on a page this empty the single teal event is a lonely dot. The proportion rule is for RICH pages — here there's nothing to be proportional against.

## 6. SPACING / RHYTHM — golden-ratio unused inside the card

- The card uses `gap-3` (12px) and `gap-4` between masthead elements — flat, not the √φ / `--card-pad-*` golden ladder (CLAUDE.md W-CARD-PAD: `--card-pad-inline` → `block` ×1.272 → section-gap → footer ÷1.618). The interior rhythm is generic Tailwind spacing, not the card padding ladder.
- `max-w-sm` (line 65) pins the control to ~384px while the card spans ~1700px — the content occupies <25% of its container width. This is the "main card area BIGGER but EMPTIER" anti-pattern; the BD ask is bigger area USED, not bigger area wasted.
- Vertical rhythm: title → card has a reasonable gap, but inside the card the masthead → divider → label → control → readout is a cramped top-left huddle with a 1000px void to its right and below.

---

## TOP DESIGN MOVES (ranked — make this exceptional)

1. **Put the demo over a COLORFUL `<Aurora>` (or PaperGrid) backdrop and make the card actual glass.** Wrap the body in `<DockStage>`-style aurora and host the combobox card as `.glass-resting`/`.glass-floating` so the six-layer composite (§L1) finally READS — backdrop blur+saturate lensing the aurora, rim halo, grain. This single move flips the page from generic to signature. (BD: "glass demos over colorful aurora backgrounds.")
2. **Replace the hand-rolled `<button>` trigger with the real composed affordance** — route it through `<Button>`/`.input-pill` control-surface so it inherits the full affordance-map floor: `--scale-hover` lift + `v-specular` gleam-track + `useSpringPress` `--glass-btn-press-t` squish + `.focus-ring`. Kill `glass-wash`; use the `--control-surface-bg` register. (DESIGN.md pillar 2 + §L3 + affordance-map.)
3. **Break the demo into a SERIES of glassy sub-section cards** (BD: "each sub-section in its OWN glassy card"): (a) the basic trigger+list, (b) the OPEN `glass-floating` list with type-ahead filtering shown live, (c) grouped basis/palette, (d) the selected-state surface in a `<MetricStack>` cell. Each its own card, golden-ratio padded, entrance-staggered on the `.scroll-cascade`.
4. **Leverage the dock contextual-switching API** — a `<DockStack mode="facets">` rail that switches the demo between combobox modes (single / grouped / async / multi), the active card morphing on `--spring-snappy`. This satisfies "leverage the dock APIs (contextual switching/animating)" directly and gives the empty right-area a job.
5. **Animate the selection moment** — crossfade the trigger label on `--spring-smooth` (§L2 pane-swap), land the `<Check>` indicator with a spring, pulse the SELECTED readout. Make every state ALIVE per §L3/§L4-strong.
6. **De-duplicate the descriptor** — delete the in-card `<IconChip>` masthead (or promote it to a real per-card section header) so "Forms · Combobox" appears ONCE, in the chrome header where the W-HIERARCHY2 cluster already owns reading order.
7. **Walk the type ladder** — a `--type-subheading` (20.4px) heading per sub-section card, `--type-body` explanatory copy, the mono readout as the quiet caption. Use the ladder DESIGN.md sells.

(Import-path label `@mkbabb/glass-ui/forms` is already standardized via the manifest subpath chip — correct; keep it. The blurb "Type-ahead filtered selection — the section identity is the ONE color event" is half-documentation-of-itself; tighten to "Type-ahead filtered selection." — drop the self-referential design-note tail per the tighten-superfluous-language bar.)

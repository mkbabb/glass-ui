## The reconciled verdict (one paragraph)

This is the thinnest, flattest page in the forms band, and uniquely it fails on BOTH layers at once. The PAGE is a monochrome spec-sheet — three near-duplicate `max-w-sm` (384px) control sections pooled in the left ~35% of an 1086px card, ~700px of dead cream void, ONE shared plate divided by hairlines (not per-section glassy cards), over a static gray `grid` field (0 GL contexts) so the six-layer glass composite cannot read, terminating on a raw `model summary` debug grid — composing ZERO other glass-ui surfaces (no dock, no tabs, no buttons, no procedural-anim, no `<Card>`), with a header rendered TWICE and a blurb that recites the design-system suffusion rule instead of describing multi-select. The COMPONENT is the band's one outlier: a bespoke composite that re-assembles Popover+Command+Button+Badge into a THIRD selection shape the canonical Combobox/ToggleGroup families already own (the no-dual-path class), whose TRIGGER is `variant="outline"` shadcn-neutral (zero of the six layers, off the `.control-surface` seam), whose SELECTED CHIPS are flat `Badge variant="secondary"` gray with NO entrance/exit animation (the dead headline — selection IS the subject and it animates nothing), whose X-remove button uses an opaque `bg-destructive` slab (off the tone-glass register) AND carries no `aria-label` (a real a11y defect the demo propagates), and which ships via NO import path at all. The squandered asset both PAGE auditors name: multi-select selects the SIX orthogonal-basis brand hues (`--viz-fourier`/`-chebyshev`/`-legendre`/`-hermite`/`-laguerre`/`-bessel`) and renders every one flat ink/gray — the data-protagonist register unused at ~5% of the suffusion budget. The fix is TWO coordinated waves: a NEW Band-16 component rebuild (chips-in-a-`.control-surface`-well over the inherited `.glass-reveal` Command list, animated, accessible, PUBLISHED as a real subpath — one transposition closing the entire component report) + a NEW Band-7 page redesign (per-section glassy cards over a live colorful aurora, basis-hue kinetic tags, dock contextual-switching, the debug-dump cut). **Phantom-wave correction:** the component report maps its findings onto `BD.W-CONTROL-SMOOTH` and "a subpath-mint arm" as if they exist — **neither is on disk** (`ls waves/` confirms: the forms band has ONLY `W-FORMS-CARD-FOLD` (zero-src demo fold) + `W-DESHADCN-CANON` (doc-only); there is NO control-rebuild wave, NO forms-page-redesign wave, and NO Band-16 chassis family). Every finding is re-homed below onto a REAL or NET-NEW wave.

### 1 — Publish + rebuild MultiSelect as chips-in-a-well over the unified control seam [NEW · highest leverage · closes 7 findings + the import-path ask] {#r1}
The single architectural transposition all three reports orbit. Today MultiSelect is a four-component composite OFF the shared seam: trigger `variant="outline"` (A1 — shadcn-neutral, zero of the six layers, no glass-tint-on-focus, no `--invalid-ring`), selected chips `Badge variant="secondary"` flat gray with no `<TransitionGroup>` (A2 — the dead headline; selection animates nothing), the X-remove a raw `hover:bg-destructive` opaque slab (A3 — off the `.feedback-tone` tinted-glass register the cohesion gate forbids) with NO `aria-label` (the a11y defect), the selected set shown TWICE (I4 — a comma-string in the trigger AND chips below), the chip block a separate `flex-wrap` div that reflows the page on every tag change (P1 — un-reserved CLS), and the whole control reachable by NO import path (I0 — unpublished). The elegant shape: the trigger becomes a `.control-surface` WELL displaying selected chips INLINE (animating on `--spring-snappy`/`--spring-bouncy`, the X on the tone-glass register, single-source selection, chips reserved IN the well so no reflow), the dropdown stays the inherited `.glass-reveal` `<Command>` list with the `Check` indicator (already correct — KEEP), and it ships as a real `@mkbabb/glass-ui/multi-select` subpath (barrel + `src/subpaths/multi-select.ts` + the `exports` entry + the `manifest.ts:239` label fixed to the published path). One transposition closes A1+A2+A3+P1+I0+I1+I4. This is SRC paint — it earns its own component-rebuild wave, NOT a demo fold.
→ **NEW: `BD.W-MULTISELECT-WELL` (Band 16 — control material + publication).** Gate: (a) the trigger reads `.control-surface` (no `variant="outline"` residual) — the six-layer composite present on the most-touched surface; (b) chips render INLINE in the well with a `<TransitionGroup>` on `--spring-snappy`, reserved (no post-select reflow), single-source (no comma-string dual display); (c) the X-remove carries `aria-label="Remove {label}"` AND routes its destructive hover through the `.feedback-tone` tinted-glass register (not opaque `bg-destructive`); (d) the subpath is MINTED (`src/subpaths/multi-select.ts` + barrel + `package.json` exports + `/api` if a type is owed) and `manifest.ts:239` resolves `@mkbabb/glass-ui/multi-select`; (e) a `proof:no-dual-path` clause asserts MultiSelect reads the Combobox/Command substrate, not a parallel Popover+Badge recipe. + a `proof:ba-gestalt` forms-band verdict + the binding π (chip spring-in/out, the trigger glass focus glide, the a11y tree carrying the remove labels, both modes).

### 3 — Make tag selection KINETIC + the basis hues the data-protagonist [NEW · the iOS-27 headline; folds into #1's chips] {#r3}

The right move recognizes that a multi-select OF brand bases where each selected TAG carries its OWN `--viz-*` hue is ONE coherent color SYSTEM (the data-protagonist register, like the 13-stop chart-chassis palette is one event), NOT N competing color events — so it does NOT break the one-color-event discipline. This is the "deftly uses a SERIES of components" ask: MultiSelect + SelectableChip + a procedural micro-viz + W-GLASS-ACCENT, composed. The chip ANIMATION (spring-in/out) is owned by #1 (the well-rebuild); the HUE keying + the basis-accent ripple + the demo-page composition is owned here.
→ **NEW: `BD.W-FORMS-MULTISELECT-SPECIMEN` (Band 7), same wave** (the data-protagonist arm).

## 1 · One-line verdict

A correct, idiomatic, performance/Safari-clean FLAT TOKEN-TOUR (14 inert cream specimen swatches over a sub-perceptual paper wash) that misses the BD north star on FOUR of the user's named bars at once — no glass-over-colorful-field, no own-card-per-subsection / bigger area, near-zero animation affordance, zero dock-API composition — while the ONE axis it should demonstrate MOST (shape: round↔squircle↔pill is the most kinetic, least-shown capability the library ships) is entirely static. The bones are sound (tokens correct, specimen-swatch triplet correctly KEPT, route chip standardized, no bugs); the EXECUTION layer is a near-total redesign that COMPOSES already-shipped primitives. Convergence is demo-side and systemic, NOT a component rewrite.

## 2 · Reconciliation — where the 3 lenses AGREE (high-confidence, binding)

All three converge on the same defect spine; this is the load-bearing set:

- **A. GLASS over a COLORFUL field is ABSENT — the #1 user-named gap (design §4/§5/move-1, demo §3, component §6).** The swatches are OPAQUE `bg-card` (`rgb(251,248,244)`) over a static `paper` wash that is sub-perceptual at this card tier. There is no aurora, no constellation, no colorful field — and even if there were, the opaque swatches would occlude it (the BG-2 black-plate class the `tier="field"` host exists to fix, unused here). The user's explicit bar "glass demos over COLORFUL aurora backgrounds" is violated on a GLASS-LIBRARY's own foundation page. A radius IS the silhouette of a glass tile — it should read as a lit liquid edge transmitting color. **Unanimous, highest impact.**
- **B. Each sub-section in its OWN glassy card + bigger main area — UNMET (design §4/move-2, demo §4, component §AUGMENT).** "Scale" and "Semantic aliases" share ONE flat outer `resting` plate split only by the `.story-sections--delimited` hairline — the "one undelimited slab" anti-pattern the user explicitly rejects. The main card under-fills a huge empty plate (occupies ~half-width with vast dead margin); the `h-20 w-20` swatches are tiny inside it. **Unanimous.**
- **C. Animation affordance near-zero — and worst here, because SHAPE is the subject (design §3/move-3, demo §1/§2, component §1).** ONE animation exists: the `.scroll-cascade` entrance (idiomatic, compositor-only, PRM-correct — all three CONFIRM this is clean and KEEP). After it, the page is frozen: zero hover, zero press, zero state, zero ambient life. The library SHIPS the exact vehicle — the AX.W56 `--corner-shape` superellipse axis + W42's animated-`k` register — and NO foundations page demos it. A live `border-radius`/`--corner-k` morph (a square liquefying to a circle on `--spring-bouncy`, a hover that springs the corner up one rung with `useLiquidFlex` squish) is the iOS-27 moment the page is missing AND the page's literal reason to exist. **Unanimous, highest-leverage single move.**
- **D. Dock-API composition ENTIRELY absent (design §5/move-4, demo §1/§2).** Zero dock on the page beyond the global nav shell. `rounded-dock` is the dock's OWN radius token, shown as a cream circle with "GLASS PILL DOCK" written beneath instead of a live `<GlassDock>`. The user names this specifically ("leverage the dock APIs — contextual switching/animating"); a `<DockLayerGroup>`/`<DockStack mode="facets">` switching Scale ↔ Semantic ↔ live-component-preview is the contextual-switch lever, unleveraged. **Unanimous.**
- **E. The semantic aliases TELL instead of SHOW (demo §1/§2, design §1/§2, component §6).** The aliases name their consumers in prose — `rounded-card` "cards", `rounded-button` "buttons", `rounded-dock` "glass pill dock" — yet render NONE of them; the demoed radius is an abstract empty box. A `rounded-card` swatch should BE a `<Card>`; `rounded-dock` should BE a live dock pill. This is the demo-congruence miss + the "deftly uses a series of components" gap (the SFC imports exactly 3 things, composes ZERO library components). **Unanimous.**

## 3 · Conflicts resolved

- **The specimen-swatch triplet: FOLD vs KEEP.** The component lens flags it CORRECT-as-is (the `border + bg-card + shadow-cartoon + r.cls` triplet IS the demoed token; folding onto `<ShowcaseFrame>` — itself `rounded-card shadow-cartoon` — would MASK the radius/shadow; explicitly allowlisted by `BD.W-TOKEN-TOUR-GLASS` §2 KEEP + gate clause M12-2). The demo/design lenses say "make the fill glass." **Resolved — BOTH are right, no conflict:** the BORDER GEOMETRY (the corner — the demoed token) stays bare and un-masked; the FILL PLATE (incidental) moves off opaque `bg-card` onto a transmissive `tier="field"` / glass tier so the page wash reads THROUGH the corner. M12-2 stays GREEN because the radius is the box geometry, not the fill. This is `W-TOKEN-TOUR-GLASS` Arm-B verbatim — the glassiness upgrade WITHOUT the over-fold.
- **The colorful-aurora ask vs the one-GL-per-route + GL-free-token-tour contract.** Demo/design want a live aurora behind the page; `W-TOKEN-TOUR-GLASS` is GL-FREE by contract (M8 reds a GL stage on a static-wash route), and the page already declares a `paper` wash. **Resolved exactly as the sibling typography SYNTHESIS resolved the identical ask:** TWO paths — (a) the GL-FREE default (in-scope NOW): per-section glass cards + the deep/lens/accent band read over the EXISTING designed paper-grain wash via `tier="field"`, M8 GREEN; (b) the live-aurora path is a SEPARATE manifest `background:` change + an M8 carve = the NEW decision-gated `BD.W-FOUNDATIONS-AURORA-FIELD` wave (shared across the foundations token pages that want it — typography + colors name the SAME ask; ≥2 consumers, one budget per route). Default to (a); (b) is the orchestrator scope-call.
- **The `--corner-shape` squircle augment + Safari.** Design/demo want the kinetic corner morph; the component lens flags it Chrome-139-ONLY (correctly `@supports (corner-shape:…)`-gated over the universal `border-radius` round contract). **Resolved — no conflict:** the morph rides `--radius` (universal, Safari-safe) as the BASE animated axis, with the `--corner-shape` squircle as the `@supports`-gated progressive-enhancement layer over the round fallback (the recorded radius.css:75-78 contract: NEVER make corner-shape the contract). The augment ships Safari-degrading by construction.
- **No conflict on the path-label.** All three confirm `/foundations/radii` resolves + does not drift (PASS as a resolution). The component lens RAISES a convention question — a CSS-token page is consumed via `@mkbabb/glass-ui/styles`, so should the chip read the styles cascade root, not a route path? This is the user's "standardize the import-path label" ask, and it is CROSS-CUTTING (28 route-path pages), NOT radii-specific. **Resolved:** book the styles-root convention decision to the systemic path-label standardization (sibling synthesis names the same cross-cut); radii is not the place to decide it. The current chip is non-drifting and acceptable as-is until that systemic call lands.

## 4 · Ranked changes (by impact)

1. **[HIGHEST] Glassify the specimen fills over a colorful field + own-card-per-subsection.** Re-host each radius swatch's FILL on `tier="field"` / a transmissive glass tier (corner stays un-masked — M12-2 GREEN) and split Scale / Semantic into their OWN glassy sub-cards over the field, main area widened. The deep/lens/accent BC band reads through the corners. Default GL-free over the paper-grain wash; the live-aurora upgrade is decision-gated. (A+B; the user's two loudest bars.)
2. **[HIGH] Animate the SHAPE — the page's reason to exist.** A hero specimen that liquefies `xs → pill` on `--spring-bouncy` (`@property`-typed `--radius` interpolation, universal) + per-swatch hover that springs the corner up one rung with `useLiquidFlex` squish + W-LIQUIDHOVER specular gleam; the `--corner-shape` squircle as the `@supports`-gated enhancement. The un-demoed corner-SHAPE axis becomes the canonical animated-corner showcase. (C; the single highest-leverage move.)
3. **[HIGH] Make the aliases REAL + leverage the dock APIs.** `rounded-card`→`<Card>`, `rounded-dialog`→a Dialog preview, `rounded-button`→`<Button>`, `rounded-dock`→a live `<GlassDock>` pill; wrap the contextual switch (Scale ↔ Semantic ↔ live-component) in a `<DockLayerGroup>`/`<DockStack mode="facets">` so the dock's morph animates the transition. Turns the page into a deft series of glass-ui components AND satisfies the dock-API mandate. (D+E.)
4. **[MED] Typography-forward focal moment + click-to-copy affordance.** Promote ONE giant `pill`/`2xl` specimen to a `text-display`-scale hero gesture (the audacious √φ tail the page abandons — it is literally ABOUT proportion); make every swatch click-to-copy its token (`rounded-card`→clipboard) with the affordance-map tooltip primitive (the token-tour's primary affordance, absent). (design §1/§2, demo §2.)
5. **[MED] Differentiate the two rows by weight.** Scale = QUIET reference strip (the primitive vocabulary); Semantic = LOUD applied showcase (real components wearing their radius). Never two clones stacked. The 80×80 swatch is too small to read `xs`/`sm`/`md` apart — the corner is the content, the corner needs to be BIG. (design §1.)
6. **[LOW] Tighten language.** The 7-line SFC docstring over-explains a trivial swatch grid → one line. Blurb "Radius tokens from xs to pill." → "Radius scale + semantic aliases." (optional). Confirm the hardcoded hint strings (`2/4/6/12/16px`) are not stale vs `--radius-*` (a drift risk; `rounded-lg` correctly defers to `var(--radius)`). No src/ prune — the page is already minimal. (all three §language.)

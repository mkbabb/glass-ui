# motion/animated-digit — FRONTEND-DESIGN critique (Pass-E, design lens)

Page: `demo/stories/motion/animated-digit.vue` · live `http://localhost:5173/motion/animated-digit`
Captures: `_cap-animated-digit-light.png` · `_cap-animated-digit-dark.png`
North star: DESIGN.md (§L1 six-layer composite · §L2 spring physics + the 3 named springs · §L3 tap choreography · §L4 motion tiers · §L5 a11y brackets · the 7 tiers · glass-cannot-sample-glass) · motion-canon.md (P1–P7) · design-idioms.md · affordance-map.md · PROCEDURAL-SUITE.md · the dock APIs.

Verdict in one line: a 63-line SFC that gets the ONE thing its sibling countup page got wrong RIGHT — the numbers ARE the protagonist at 245px hero scale — but stops there: two heroes collide in a single bare flex row, no per-subsection cards, a dead near-white constellation that turns the glass to flat gray, zero coupled motion on the count itself, and not a single dock/tab the user's ask names.

---

## 1. VISUAL HIERARCHY — the eye lands RIGHT (the one real win), but the two heroes brawl

- **The figures ARE the protagonist — credit where due.** Verified `getComputedStyle`: both figures render at **244.8px** (`text-display-hero`, the metric-value tier whose fast.com peg is EXACTLY "a metric value" per the §Typography audacious-tier table). On the sibling countup page the most-animated value was buried at 41.9px under a prose paragraph; here the number IS the loudest thing on the screen, which is correct. This page understood the typography-forward north star where countup did not.
- **But the two heroes collide.** The figures sit in a single `flex flex-wrap items-end gap-10` row (line 28). At 1440px both `248.6` and `14` paint side-by-side at full 245px, and `248.6` (5 glyphs, ~470px wide) plus `14` blows past comfortable measure — in the capture the `.6` of `248.6` nearly kisses the `1` of `14`, and `248.6` crowds the card's right padding. Two 245px heroes on one line is not a hierarchy; it is two protagonists fighting for the same frame. ONE should lead (the download metric, the page's natural headline), the latency a smaller satellite — a `text-display-hero` lead + a `text-display-2/-3` satellite, not two coequal 245px slabs (§6).
- **No section weight.** Both `StorySection`s render `label` (a mono eyebrow) + `blurb` (14px `text-small`) — there is NO `heading` rung (`StorySection` exposes a semantic `<h2 class="text-subheading">`, unused here). So the page is eyebrow → blurb → giant-number, twice, with no `text-subheading` organizing tier between the page `<h1>` and the body. The §AZ.W-HIERARCHY caption-vs-heading register is half-used: the eyebrow is present, the heading rung is skipped.
- **The placeholder section is a runt.** The second `StorySection` ("placeholder") prints a single `—` em-dash at `text-display` (41.9px verified) in `text-muted-foreground`. It is the right idea (show the null state) but reads as a stray dash floating below the giant numbers, with no card, no frame, no relationship to the hero stage above it. It looks like leftover scaffolding, not a designed state demo.

## 2. STRUCTURE — one card, bare flex rows inside it (the user's explicit ask, unmet)

The user's binding directive: *each sub-section in its OWN glassy card; the main card BIGGER; deftly uses a series of glass-ui components (docks/cards/tabs/buttons).* This page meets none of it.

- **Everything lives in ONE `glass-wash` StoryPage card.** Verified ancestry: the figures sit inside `…glass-wash shadow-card story-hero-card story-hero-card--page story-hero-card--live`, and each `StorySection` is a bare `flex flex-col gap-3` (NOT a glass surface). So the "value tween" stage and the "placeholder" state are NOT their own glassy sub-cards — they are flex stacks in the single chassis card. The user asked for per-sub-section cards; there are zero. Each natural unit (the live-metric stage · the controls · the placeholder state) wants its OWN `glass-resting`/`glass-quiet` sub-card, and the metric stage specifically wants to be ENLARGED as the protagonist surface.
- **The StoryPage card is `glass-wash`, the lowest tier — and over a flat field it reads as a gray rectangle.** Verified: the host card is `glass-wash` (`color(srgb … / 0.328)` tint, `backdrop-filter: blur(9px)`). Per DESIGN.md §L1, glass is a *lensing* layer — over a backdrop with structure it bends and concentrates light; over a flat near-white field it has nothing to refract and "reads iOS-7-flat, not iOS-26-liquid." In the LIGHT capture the card is exactly that — a flat warm-gray slab. The dark capture proves the diagnosis: over the near-black field the SAME card's edge rim and tint read markedly more glass-like. Per §L1's tier-selection rule the host stage should also be lifted off `wash` to `resting` (the canonical translucent + frosted plate, 65%/blur-12) — `wash` is the permeable-veil tier for dock/input chrome, not a hero demo stage.
- **The card is half-empty.** In both captures the bottom third of the chassis card past the Resample button is dead air. The user wants the *stage* bigger and full of content, not the container padded with whitespace.

## 3. BACKGROUND — a dead constellation, not the colorful aurora the ask names

- Verified live: the field is `constellation story-hero-bg` (the motion-band manifest default). In LIGHT it is near-white with a scatter of faint grey dots — near-invisible, and it gives the glass nothing to bend (see §2, the gray-slab root cause). In DARK it is near-black with sparse dots — atmospheric but still empty.
- The user's ask is explicit: *glass demos over COLORFUL aurora backgrounds.* And the page already HAS its color seed — the motion-family violet identity `--motion-accent` = `oklch(0.739 0.134 318.1)` (the `--viz-legendre` twin, verified live), used as the four accent bars. A violet-tuned `<Aurora>` (offscreen-paused, one-GL-per-route, the W-STAGE / `<DockStage>` pattern) would (a) make the glass figure-stage POP as real §L1 liquid glass, (b) unify the page's color into one designed field instead of an accent dab, and (c) fix §2's gray-slab problem at the ROOT. This is the single highest-leverage visual upgrade on the page. As shipped the constellation reads as "a default background was placed here."

## 4. ANIMATION AFFORDANCE — the count tweens, but nothing AROUND it is alive (the deep gap)

Per the brief: *every element ALIVE at the iOS-27 bar — entrance, hover, press, state.* The `AnimatedDigit` component itself is honest (it tweens `textContent` over `useAnimatedNumber`, the §L2 spring substrate — a metric never snaps, which is the whole point). But the value's MOTION is invisible-by-design and everything around it is static:

- **The count has no coupled physical read (motion-canon P3 + DESIGN.md §L3 violated).** The number tweens its glyphs and NOTHING else moves — no scale-settle pop as it lands, no brightness/specular leg, no `--*-press-t`-style drive, no overshoot READ on the figure or its card. motion-canon P3 (fade coupled to transform) and §L3 (every settle has a physical read, the ~7% `--spring-snappy` overshoot "pops back") want the figure to PULSE/scale-settle on arrival on a `--spring-snappy` clock. As shipped, if you are not staring at the exact glyphs you cannot tell anything happened — the most kinetic value on the page reads as static.
- **The accent bars are dead decoration.** Lines 30/39: `h-1 w-8 rounded-pill bg-[var(--motion-accent)]` — a static 32px violet tick above each figure. On a page whose SUBJECT is a number animating toward a target, this is the obvious place for a live read: a `<BorderProgress coverage="bottom-edge">` fill, a draw-on, or a 0→100% sweep synced to the tween so the bar IS the progress of the count. It is currently the least-alive element on a page about being alive.
- **No entrance, no auto-play.** The figures sit at their resting value; the page rides `.scroll-build` from the chassis (the only free motion), but the metric stage does NOT `.scroll-cascade` stagger in, and the count does not re-fire on scroll-into-view. A visitor who never clicks Resample sees two static numbers and never sees the primitive DO its one trick. An animated-digit demo should pulse/re-settle on arrival (a `view()`/`useIntersectionPause` trigger) so the kinetic primitive demos itself.
- **Resample is a low-affordance ghost.** Line 47: `<Button variant="outline">` carries the library four-state contract (the only true affordance on the page) but it is an outline button against a gray slab — it does not read as THE action that drives the whole demo. It should be the primary/`default` glass register with a liquid-reveal lead, or better: a dock control (§7). And "Resample" only re-rolls the data; the actual TWEEN is the show, so the button should read as "watch it count," not a quiet utility tucked bottom-left.
- **The placeholder state never transitions.** The `—` placeholder section is static; the interesting moment — null→number, where the placeholder dissolves and the reel spins up — is never shown. A toggle that flips a figure null↔value, letting the viewer watch the placeholder hand off to the tween, would make that section earn its place.
- **The dock APIs the user named are entirely absent.** No dock, no `dock-morph`, no contextual switching. The canonical move for a multi-metric reel: a `<DockStack mode="facets">` / `<DockLayerGroup>` rail that switches the metric DATASET (download · latency · jitter · packet-loss), the figures re-tweening to the new dataset with a contextual crossfade on the dock's own `--spring-dock` clock. That is the user's "deftly uses docks/cards/tabs/buttons + contextual switching" ask, and a multi-metric animated reel is its natural home.

## 5. POLISH + DISTINCTIVENESS — closer to bespoke than countup, but still a stat-strip

- This page is a notch above the generic-AI dashboard template precisely because the numbers are huge — a 245px tabular figure has presence. But the COMPOSITION is still "eyebrow → blurb → two big numbers in a row → small button," which is one editorial step away from a SaaS "trusted by the numbers" strip. A world-class animated-digit page would let the NUMBER author the layout: ONE giant hero metric that re-counts on interaction as the protagonist, the secondary metrics as smaller satellites, the accent bars as live fills, the dataset switchable from a dock rail. The bones are here; the arrangement is timid.
- **Tabular figures are ON — verify the face.** Verified: the figures resolve `font-variant-numeric: lining-nums tabular-nums` (the `tabular-nums` class works) over **Plus Jakarta Sans** (the brand display sans). Unlike the sibling countup page, this SFC does NOT request `.fira-code`, so there is no silent mono-clobber bug here — but it also means the counting digits ride a proportional brand sans with tabular figures rather than a true mono. Plus Jakarta's tabular figures DO ship (the box stays stable as it tweens 1→128→1280, which is the non-negotiable for a counting figure), so this is acceptable — but a deliberate `text-display-mono`/Fira-Code register would read as more intentionally "a meter" and is worth a design call. Either way: keep the tabular contract, it is doing its job.
- **Color suffusion is correct but timid.** The violet honors the one-color-event rule (the value+unit stay ink `rgb(28,25,23)`, verified; the SFC comment at lines 25–27 names the discipline). But violet appears ONLY as four static 32px ticks — it never becomes the aurora seed, a gradient, or a live fill. It is an accent dab, not the page's identity (see §3, §4).

## 6. SPACING / RHYTHM

- The card padding is the BB.W-CARD-PAD √φ ladder (chassis-owned, verified in the class list `[--card-pad-inline:--spacing(6)] [--card-pad-block:…*1.272]`) — correct golden-ratio block-over-inline rhythm. `gap-10`/`gap-3`/`gap-1` are on the √φ-adjacent scale — fine.
- The deliberate-geometry miss: two 245px figures in an even `gap-10` flex row is not a golden composition — it is two equal masses that collide (§1). A `[φ_1fr]` lead-plus-satellite split, OR stacking the metrics with one dominant, would be the intentional move on a φ library. The dead bottom third of the card is dead rhythm — the stage should breathe with content (more metrics, the dock rail, the live placeholder toggle), not air.

## 7. COPY + IMPORT LABEL — mostly clean (the "tighten language" ask)

- **The import-path label is correct and standardized — KEEP.** Verified live: the chrome chip reads `@mkbabb/glass-ui/animated-digit` — the canonical subpath form, matching manifest line 319, no local-route drift. This page is on the right convention; no change.
- **The body blurb leaks the internal name.** Line 23: *"…tweens toward it on the useAnimatedNumber spring."* and line 22's `label="value tween"` — `useAnimatedNumber` is the composable name, not visitor copy. → blurb: *"A null value paints the placeholder; a number tweens smoothly toward its target so the metric never snaps."* The composable name belongs in a code comment, off the rendered surface.
- **The chrome subtitle is dense.** Manifest: *"Single-figure smoothed reel over useAnimatedNumber — tweens a metric toward its bound value so it never snaps; null reads the placeholder."* → *"Numbers that count smoothly to their target — a metric that never snaps."* The "single-figure smoothed reel over useAnimatedNumber" is maintainer vocabulary.
- The `label="value tween"` / `label="placeholder"` eyebrows are fine as supporting tags; if §1's heading rung is added, those become the eyebrow ABOVE a `heading="Live metric"` / `heading="Empty state"` semantic `<h2>`.

## TOP DESIGN MOVES (ranked, concrete)

1. **Live violet field.** Swap the dead constellation for a `--motion-accent`-seeded `<Aurora>` (offscreen-paused, one-GL-per-route, the `<DockStage>` pattern). Fixes the §2 gray-slab root cause — the glass stage finally gets something to bend and reads as §L1 iOS-26 liquid, not iOS-7-flat — and turns the timid accent dab into the page's color identity. Single highest-leverage move.
2. **ONE hero, satellites below.** Promote the download metric to the lead `text-display-hero` (or `-mega`), demote latency (and add jitter/packet-loss) to smaller `text-display-2/-3` satellites. Kills the two-heroes-collide brawl (§1) and gives the page a single numeric anchor that re-counts as you interact.
3. **Couple physical motion to the count (motion-canon P3 + §L3).** As each figure lands, scale-settle / brightness-pulse it on a `--spring-snappy` clock with the ~7% overshoot READ; turn the dead accent bar into a live `<BorderProgress coverage="bottom-edge">` / draw-on fill synced 0→target. The number should SETTLE like it has mass, the bar should READ the count.
4. **Auto-play + replay on scroll-in.** Wire the reel to a `view()`/`useIntersectionPause` trigger so the figures spin up on first paint and re-settle on re-entry — the kinetic primitive demos itself; Resample becomes "re-roll," not "the only way to see anything happen."
5. **Each unit → its OWN glassy sub-card; the stage BIGGER.** Wrap the live-metric stage, the controls, and the placeholder state in distinct `glass-resting` sub-cards (lift the host stage off `glass-wash` → `glass-resting` per §L1 tier-selection); enlarge the metric stage as the protagonist surface. Fills the empty card with content, meets the user's "own card / bigger stage" ask.
6. **Bind the dock APIs.** Add a `<DockStack mode="facets">` / `<DockLayerGroup>` metric-facet rail — pick download · latency · jitter, the figures re-tween to the new dataset with a contextual morph/crossfade on `--spring-dock`. The user's contextual-switching ask; the natural fit for a multi-metric reel.
7. **Make the placeholder→value handoff a real demo.** A toggle that flips a figure null↔number so the viewer watches the `—` placeholder dissolve and the reel spin up — the actual interesting transition, currently never shown. Give the placeholder section a card and a frame so it reads as a designed state, not stray scaffolding.
8. **Lift the primary action.** Resample → a `default`/glass-register Button with a liquid-reveal lead (or a dock control), labelled to read as "watch it count," not a bottom-left outline ghost. `.scroll-cascade` stagger the stage + controls in.
9. **Add the heading rung.** Use `StorySection`'s `heading` (`text-subheading` `<h2>`) so the page reads as composed sections ("Live metric" / "Empty state"), not eyebrow→blurb→number twice.
10. **Tighten copy.** Replace the `useAnimatedNumber`-naming blurb + dense chrome subtitle with one human sentence each; the composable name moves to a code comment.

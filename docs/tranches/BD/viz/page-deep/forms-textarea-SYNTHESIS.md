# forms/textarea — Pass-E SYNTHESIS (binding per-page verdict)

**Route:** `/forms/textarea` · **SFC:** `demo/stories/forms/textarea.vue` (99 lines) · **Import label:** `@mkbabb/glass-ui/forms` · synthesized from the demo / design / component reports in this dir.

The three auditors agree almost perfectly: this is a **flat single-card spec-sheet** — four near-identical textareas stacked in ONE resting card over a near-invisible grid wash — that fails the BD mandate on the same five systemic axes as its sibling `forms/inputs` (no aurora field · no per-section glass cards · ~2 library families · near-zero animation affordance · undersized main area), **plus three textarea-specific defects:** a FALSE "auto-grow" header claim (the flagship `autosize` API is advertised in copy and OFF in code), the resize gesture demonstrated as inert prose, and an undersized hero (86px vs the sibling's 110px). No real conflicts across the three reports — they differ only in emphasis (the design lens leads with the aurora/card structure, the component lens leads with the animation/six-layer composite, the demo lens leads with the dead `autosize` claim). All resolved below.

The work splits cleanly: ONE shared src wave (`BD.W-CONTROL-LIQUID`, identical to the inputs ask — armed once, both pages inherit), ONE demo page-rebuild (a Band-16 NEW wave, because the forms text-entry rebuild is a full composition beyond `BD.W-FORMS-CARD-FOLD`'s narrow residual-triplet charter), plus three small folds.

## What is RIGHT — do not regress (unanimous)

- **The `Textarea` primitive is idiomatic + lovely.** `inheritAttrs:false` + explicit `v-bind` passthrough (every native `aria-*`/`required`/`maxlength` lands on the focusable element), the `useControlSize` token-substitution axis, the shared `--control-surface-*`/`--input-on-glass`/`--invalid-ring` register seams, `rounded-field` overriding the pill stadium (AW.W25). No dead code, no dual-path, no workaround.
- **`field-sizing: content` autosize is best-in-class** (control-surfaces.css:144-150): native CSS auto-grow between `3lh` and `--textarea-autosize-max` (12lh), NO JS resize loop, NO ResizeObserver, NO scroll-height mirror, graceful degrade to the fixed `min-block-size: 3lh` floor. **The API is SOTA — the page just never turns it on.** Keep the component; fix the demo.
- **PERFORMANCE + SAFARI are clean.** Compositor-safe color-only transitions (zero layout-thrash), `backdrop-filter` Safari prefix build-injected + `proof:webkit-backdrop`-gated, `lh` units safe (Safari 16.4+). Record as a positive — no wave needed.
- **The path label `@mkbabb/glass-ui/forms` is correct + standardized** (all 3 reports PASS). Unlike `forms/inputs` there is NO third in-prose path dialect on this page. **Do NOT touch it.**
- **Color suffusion proportion is on-doctrine.** The one-color-event rule (AZ.W-SUFFUSE) is honored — the `--section-color-3` teal IconChip backplate at 25% + the tinted eyebrow, the field controls stay ink. The fix is NOT more color events; it is giving the single teal event something to sit against (the aurora field + the glass cards). Do NOT tint the field controls.

## RANKED changes (impact-ordered; reconciled across all 3 reports)

### R1 [P0 · BUG] The flagship `autosize` API is advertised in copy and OFF in code — the header claim is a LIE
Unanimous, named by all three (demo B1, design §5, demo §1). The header blurb (textarea.vue:41) advertises **"Multi-line text entry with auto-grow"** — yet all four fields render `data-autosize` ABSENT and `field-sizing: fixed` (DOM-probed `data-autosize` count = 0; `rows=2`, `min-height:80px` FIXED, scrolls inside the well). The single most distinctive, demo-worthy affordance of this component — the one thing no plain `<textarea>` has, the page's reason to exist beyond `inputs` — is **named-but-unexercised**. A showcase page must not advertise an affordance it does not have.
**Resolution:** ship real `autosize` on the protagonist (the field grows to content on its own settle clock, 3-line floor → 12lh ceiling — the visible showpiece: type and watch it grow), AND fix the blurb to be true. This is the lead demo. (Demo-only — the API already ships; this is wiring `:autosize` in the SFC.)

### R2 [P1 · HEADLINE-SRC] The control register is COLOR-only four-state — no specular, no focus/press spring, no entrance
Unanimous component verdict (component §1, design §5, demo §1) — **identical to the `forms/inputs` finding** (the textarea IS the same `.input-pill` register, and the LARGEST glass plate in the band, so the deficit is most conspicuous here). What exists: a single bezier `transition` over `background-color/border-color/box-shadow/color/opacity` (the EFFECTS leg only — correct but it is the WHOLE animation budget). MISSING vs the band's own SOTA: the `useSpringPress`/`useLiquidPress` + `--*-press-t` register (on Button + Card), the `vSpecular`/`useSpecularTracking` tier-root gleam (on Button-glass + the four dock controls), and any `.glass-reveal`/`vReveal` entrance. A focused field is a static color swap — it never reads "alive."
**Resolution:** the shared src wave `BD.W-CONTROL-LIQUID` arms the `.input-pill` register with the `vSpecular` tier-root gleam + a focus-engage spring (`useSpringPress`/`--control-press-t`, the focus-bloom on the ring/scale) + a `.glass-reveal`-class entrance — **reusing the shipped Button/dock primitives, no fork.** Textarea is the highest-value target (biggest plate); inputs/NumberField inherit the same arm. ONE wave serves both forms pages.

### R3 [P1 · HEADLINE-SRC] The six-layer glass composite is only 3/6 — the well is a flat-bordered slab
Unanimous (component §6, design §3, design §1) — **also identical to inputs.** The `.input-pill` paints (1) backdrop blur+saturate ✓ · (2) surface tint ✓ · (5) drop-shadow ONLY as the focus/invalid ring (no resting elevation) ✗. **MISSING: (3) edge rim, (4) inner catch-light, (6) grain** — a flat `1.5px solid border`, NO `--glass-material-rim` inset ring, no `::before` specular core, no grain `::after`. Most conspicuous on the textarea (a 12lh well over a live aurora is a big dead rectangle).
**Resolution:** same `BD.W-CONTROL-LIQUID` — re-base `.input-pill` onto `.glass-material` rim+core+grain (or compose the rim group) so the well is a full composite. **Coordinate with `BD.W-GLASS-LENS-CHROMA`** (the rim/lens owner) so the two do not double-author the rim.

### R4 [P1 · STRUCTURE] No card-per-section + no aurora + main area too small — the lens has nothing to refract
Unanimous, user-named verbatim (design §3/§4, demo §3/§4). Three compounding structural failures, one root cause:
- **One card, not per-section.** All four StorySections live inside the single `story-hero-card--page` resting Card, separated by `--configurator-divider` hairlines (the `.story-sections--delimited` seam). The user's "each sub-section in its OWN glassy card" is the exact opposite of the divider-stack shown. (Probed: the only glass surfaces are the two shell docks + the ONE header card + the four wells; ZERO glassy sub-cards.)
- **No aurora.** `canvasCount = 0`; background is the static `grid` wash (`CATEGORY_DEFAULT_BG.forms = "grid"`, lines at 11% α of near-cream ink → effectively invisible). The `.input-pill`'s genuine `blur(8px) saturate(1.05)` lenses NOTHING; dark mode reads as a near-black void. §L1: "surfaces are lensing layers, not blur swatches" — the lens has nothing behind it.
- **Main area too small.** The card is 1152px wide but every field is `max-w-md` → 448px (~39% of the card), ~600px dead wash to the right of every field. A thin left gutter, not the generous "BIGGER" the user asks for.
**Resolution (the architectural transposition — the design lens's key move):** use the **`surface="veil"`** glass tier the library already ships (BA.W-SURFACE-AXIS) — a permeable veil card per section that reads as a real glassy card AND admits the backdrop through onto the well, satisfying "own glassy card" + "glass over the live field" at once with NO occlusion. Run a **colorful multi-nuclei `<Aurora>`** behind the protagonist (ONE GL context per route, offscreen-paused, budget-safe) so the focal glass actually lenses varied color; keep the supporting-matrix fields on the calm wash (the §L1 tier-selection discipline — save the spend for the hero). **Critical constraint:** glass-cannot-sample-glass — the veil cards and the input wells must share ONE composition container (they do — a monotone Z-stack; NOT two stacked `backdrop-filter` plates). Lift the body cap toward a generous width, kill `max-w-md` on the protagonist, apply the BB.W-CARD-PAD √φ ladder. Verify dark-mode chroma survives the well's `brightness(1.16)` glow (don't collapse to black). Flip the manifest `background` row off "grid"; the M8 GL-on-static-wash detector follows.

### R5 [P1 · COMPONENTS] ~2 library families + zero dock contextual-switch
Unanimous (demo §2, design §1). In-article glass-ui surface = `{Textarea ×4, Label ×4, IconChip ×2}` — no Button, no Dock, no Tabs, no per-section Card, no procedural anim. The four states (default · autosize · resize · disabled) are the IDEAL contextual-switch content, yet the page that should "leverage the dock APIs" has zero in-page dock.
**Resolution:** wire a **`<DockStack mode="facets">`** (or `<DockLayerGroup>`) that swaps the protagonist textarea across its states with a live crossfade + per-facet `--glass-accent` context hues (BE.W-DOCK-RAIL-REALIZE + BB.W-GLASS-ACCENT) — this single move satisfies the **dock contextual-switching/animating headline** the brief names. Compose a SERIES: pair the autosize protagonist with a live char-count (`MetricBadge`/`Progress`), a `<Button>` submit firing a validation state / `<CompletionSeal>`, and the `size` rungs — 4-5 families in one deft scene.

### R6 [P1 · ANIMATION] The resize gesture is inert prose; the hero is undersized; the page is dead
Reconciled (design §2/§5, demo §1). Three sub-findings:
- **The resize gesture — the textarea's single most-kinetic, most-defining affordance — is shown only as a caption** ("grab the bottom-right corner") + the native OS handle. A premium page stages resize as a *designed* `useLiquidFlex` volume-preserving gel-squish drag (affordance-map DRAG-MORPH — the grip is the same "earns a pull" class as the tab pill / Slider track / SortableHandle), not a hard native handle.
- **The hero is SMALLER than its coequal sibling** — 86.1px (`--type-display-mega`) vs inputs' 109.7px. Lift it to the sibling's poster weight; a foundational forms surface should command the same protagonist weight.
- **No entrance, no liquid focus.** The `.scroll-cascade` wrapper is present but nothing visibly *builds in*; focus is a static ring.
**Resolution:** mostly FREE once R2 + R4 land — R2's `useSpringPress` focus-bloom delivers liquid focus; R4's per-section cards + the `.scroll-cascade` gravity entrance (wired to land on each field card, per-field `--spring-snappy-duration` stagger, W-HIERARCHY2 generalized) deliver arrival. The resize gel-squish is the one net-new demo gesture (compose the shipped `useLiquidFlex`/`useDragMorph` on the grip). Lift the H1 vw-clamp to the sibling's poster weight.

### R7 [P2 · LANGUAGE + HYGIENE] Tighten copy + delete the SFC changelog comment (user-named)
Reconciled (demo §6, design §6/§8). Every section blurb is a documentary caption of a CSS bit, not a demo affordance: "The baseline pairing — `Label` above, field below" (restates the obvious markup), "Forced `resize: none` — height stays where you put it" (redundant with the heading), "`disabled` drops opacity and blocks interaction" (pure API doc). The header blurb leaks internal jargon ("the section identity is the ONE color event"). The SFC top-comment (lines 9-11, `BC.W-SUFFUSE-reconcile … PH3-safe`) is internal-changelog noise (MEMORY: greenfield — no version history in artifacts).
**Resolution:** compress each caption to one showcase line stating the field's *value* not its *prop*; drop the internal-jargon header tail; **fix the false "auto-grow" claim** (true once R1 lands); delete the lines 9-11 changelog comment. Folds into the R4/R5 SFC rewrite — no standalone work.

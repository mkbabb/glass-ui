**Page:** `demo/stories/foundations/icons.vue` · live `http://localhost:5173/foundations/icons`
**Lens:** the frontend-design skill bar (distinctive, production-grade, AVOID generic-AI) APPLIED to glass-ui's own language — DESIGN.md §L1–L5, design-idioms / motion-canon / affordance-map, the dock system.
**Captures:** `_cap-icons-{light,lower,dark}.png` (this dir), 1440×900, both modes.

This is the **icons foundation page** — the page that documents the icon system: the lucide set, the sizing/stroke axes, and (promoted to the lead at W-DEMO-DESIGN) the `<IconChip>` "Pops" color-event register. The verified census: `canvas:0` (no aurora), `dock:2` (shell chrome only, not page content), `tabs:0`, `button:0` (in body), `colorSwatch:0`, `iconChip:26` (live, animated), `glassCards:1` (the single outer body plate). The page has exactly **one genuinely strong move** — the IconChip Pops row, which is on-doctrine, animated, and distinctive — surrounded by **three flat spec-sheet sections** (a token-export Lucide grid + two bare unframed Sizing/Stroke clusters) over **no aurora**, in **one** glass plate. It is the W-DEMO-DESIGN intent realized only at the top inch of the page.

## What is already RIGHT (do not regress)

- **The IconChip "Pops" row is the corpus reference for the one-color-event idiom.** 13 chips, 1:1 onto the `--section-color-0..12` ramp, each a `color-mix(… 25%, transparent)` backplate (measured `srgb 0.766 0.175 0.431 / 0.4`) under a full-chroma glyph (`oklch(0.552 0.192 359.8)`), `48×48`, `saturated bloom` axes engaged. This is exactly the §"Suffusion register + one-color-event rule" idiom and it reads as bespoke glass-ui, not a Figma token-export. Do NOT flatten it.
- **The chip entrance is genuinely alive and on-clock.** Each chip blooms in via `animation: icon-chip-reveal` at `0.34s` — the `--spring-snappy-duration` clock (DESIGN.md §L2, the ~7% confident-tap overshoot), staggered by `:reveal="i+1"` (`--d`), PRM-gated through `vReveal`, no demo-local `@keyframes`. This is the W-SUFFUSE3 spring-clock entrance done correctly. It is the ONLY element on the page that meets the iOS-27 animation bar.
- **The √φ ladder is present at the page head.** "Icons" resolves a measured **86.1px** `text-display` `<h1>` (Plus Jakarta Sans, brand face) — audacious and correct as the page title.
- **The monochrome discipline is on-doctrine.** The Lucide reference glyphs stay `--foreground` ink (no color event), the proportion rule is respected — one color event (the Pops row), the rest documentary. Do NOT "fix" the reference grid by tinting it.
- **The section-heading rung is canonical.** All four `<h2>` resolve `20.35px / 600` `text-subheading` (AZ.W-HIERARCHY) — the single section register, distinct from the page title and the mono eyebrow. No hand-rolled `text-sm font-semibold` stragglers.

## TOP design problems (ranked, opinionated, concrete)

### 1. THE GLASS DEMOS OVER NOTHING — no aurora field, so §L1 lensing is inert (the headline mandate)
Verified: `document.querySelectorAll('canvas').length === 0`. The body sits in ONE `glass-resting` plate (`backdrop-filter: blur(10px) saturate(1.05)`) — a real six-layer surface — but **there is nothing behind it to bend**. DESIGN.md §L1 is explicit: "Liquid Glass *bends and concentrates* light … glass-ui surfaces are lensing layers, not blur swatches." A blur over a flat warm-paper wash is the iOS-7-flat read the precept condemns. In **dark mode it is the W-DARK-MATERIAL failure re-introduced at the composition layer** (`_cap-icons-dark.png`): a near-black slab on a pure-black void — the exact "charcoal slab on a dead void" that register was built to kill. The user mandate is verbatim: "glass demos over COLORFUL aurora backgrounds." This page — whose Pops row is literally a walk across the colorful section ramp — has the **least** color behind its glass of any page that should sing.
**Fix:** declare a **colorful `<Aurora>`** as the page background (the manifest `background` row → a live field, ONE GL context per route per the budget). Thematically exact: seed the aurora from the same `--section-color` ramp the Pops row walks. Then the single body plate AND every sub-section card (move #2) lenses a real chromatic field — §L1 demonstrated, not asserted — and dark mode stops reading as a dead slab.

### 2. EACH SUB-SECTION IS NOT ITS OWN GLASSY CARD — the user-named structure ask is unmet
Verified: the four sub-sections (`Pops`, `Lucide reference`, `Sizing`, `Stroke width`) are bare `flex flex-col gap-3` wrappers — `backdrop-filter:none`, `background:transparent`, no card. There is exactly ONE glass plate on the page (the outer body, `glassCards:1`). Inside it, the content is a flat scroll: a Pops row in a `tier="field"` ShowcaseFrame, then a Lucide grid of opaque `bg-card/40` tiles, then **two completely unframed clusters** (Sizing + Stroke floating in the body — see `_cap-icons-lower.png`). The user mandate is explicit: "each sub-section in its OWN glassy card; the main card area BIGGER." This page is the opposite — one outer plate, four undifferentiated transparent stacks, two of them with no container at all.
**Fix:** promote each sub-section to its OWN glass specimen card (a `glass-quiet`/`glass-resting` inner plate per `<StorySection>`), each lensing the aurora from move #1. Respect **glass-cannot-sample-glass** (§L1): the inner cards and the outer plate must share the ONE composition container — so the outer body drops its own `backdrop-filter` and the four children carry the glass tiers, OR the children are `veil`/`quiet` rungs composed inside the single outer filter context. Then enlarge the composition (the "main area BIGGER" ask): the Lucide grid + Pops row are the dominant bento spans; Sizing/Stroke are supporting cards — not a flat list.

### 3. THE PAGE LEVERAGES ALMOST NO GLASS-UI COMPONENTS — the "deftly uses a series of components" mandate is largely absent
Verified in body: `dock:0, tabs:0, button:0, colorSwatch:0` (the `dock:2` is the AppShell's own nav chrome, not the page). The ONLY library primitive the page composes is `<IconChip>` (×26). Everything else is demo-chassis (`StoryPage`/`StorySection`/`ShowcaseFrame`) + raw `<component :is>` glyphs. The mandate ("docks / procedural-anims / cards / tabs / buttons") is met by one component. This is a missed opportunity precisely because the icon system has axes that BEG for interactive components:
**Fix:** (a) make the **Sizing + Stroke axes interactive** — a `<SegmentedTabs>` to switch the live preview between `sm/md/lg` and `1/1.5/2px`, so the foundation page demonstrates the axes instead of listing three frozen specimens (the tabs mandate + real utility). (b) Leverage the **dock APIs** — a `<DockStack mode="facets">` whose facet chips ARE the icon families (Pops / Reference / Sizing / Stroke), each carrying its `--glass-accent` context hue (BE.W-DOCK-RAIL-REALIZE + BB.W-GLASS-ACCENT), contextually switching which specimen card is in focus. That single dock move satisfies the contextual-switching/animating headline AND makes the page navigable. (c) Render the Lucide grid cells as **`<IconChip bare>`** (the `:bare` no-plate register) so each glyph inherits the four-state contract + hover-bloom for free, instead of a dead `<component :is>` in a `transition: transform` frame.

### 4. ANIMATION AFFORDANCE COLLAPSES BELOW THE FOLD — alive at the top, inert everywhere else (motion-canon P1–P6, §L3)
The mandate is "HIGH animation affordance for EVERY component." Measured:
- **Pops chips: alive** (`icon-chip-reveal`, 0.34s spring-snappy, hover-bloom). Correct.
- **Lucide reference frames: half-dead** — `cursor:auto`, `transition: transform` with a 1px hover translate (`hover:-translate-x-px -translate-y-px`) but **no `:active scale-press`** (§L3 mandates the `--scale-press` squish for every primitive that LOOKS liftable — and these framed tiles advertise an interaction they don't deliver). They also have no entrance beyond the `.scroll-cascade` on the whole grid; the glyphs themselves are static.
- **Sizing + Stroke specimens: fully dead** — bare Compass icons, `transition: all` is not even present, no hover, no press, no entrance. Three frozen glyphs in a row (`_cap-icons-lower.png`). On a page whose subject is icons, the size/stroke axes are presented as the least alive thing in the system.
**Fix:** route the Lucide cells through `<IconChip bare>` (four-state + press-squish for free); add `:active scale(--scale-press)` (§L3) to any liftable frame; give Sizing/Stroke a **live morph** — a `<SegmentedTabs>`-driven single preview glyph that springs between sizes/strokes on `--spring-snappy` (the icon literally grows/thickens as you switch the axis), so the foundation demonstrates the axis kinetically instead of statically.

### 5. THE LUCIDE REFERENCE IS A GENERIC TOKEN-EXPORT — the page's largest surface is its least distinctive
The 21-glyph reference grid (`_cap-icons-lower.png`) is `bg-card/40` rounded tiles in a `gap-3` grid — pleasant, legible, and **indistinguishable from any Storybook/Figma icon export**. It is the largest visual surface on the page and the most generic-AI-template read. The Pops row proves the page can be bespoke; the reference grid leaves the bulk of the page at the lowest bar. It is also `bg-card/40` opaque — so even when the aurora lands (move #1), these tiles will OCCLUDE it rather than lens it (the BG-2 black-plate anti-pattern the W-STAGE `tier="field"` register exists to kill).
**Fix:** re-render the grid as **glass-lensing `<IconChip bare>` cells over the aurora** (drop the opaque `bg-card/40`, use a `veil`/`field` rung so the chromatic field reads through), arranged on the BB.W-CARD-PAD √φ block-over-inline padding ladder rather than a uniform `gap-3`. Add a hover-bloom + press to each cell. The reference becomes a wall of living glass icon tiles over a color field — distinctly glass-ui — instead of a token-sheet.

### 6. SPACING/RHYTHM — competent at the head, ragged in the tail; no golden relationship
The Pops section is well-spaced (the ShowcaseFrame `pad="lg"`, the 13-col grid `gap-4`). But below it the rhythm degrades: the Lucide grid uses uniform `gap-3`, and Sizing/Stroke are `flex items-end gap-8` rows floating with no card-padding ladder, no √φ relationship to anything. The outer body plate carries the generous `--card-pad-*` sqrt-φ ladder (BB.W-CARD-PAD) but it is wasted because the inner content is a flat stack. The `<h1>` + blurb consume a tall band before the first specimen, then the specimens get progressively more cramped toward the bottom.
**Fix:** apply the BB.W-CARD-PAD sqrt-φ ladder to the inner specimen cards (from move #2); give Sizing/Stroke real cards with the same padding rhythm; let the Pops + Reference cards take the dominant bento spans and the axis demos the supporting spans — a composed rhythm, not a decaying list.

### 7. THE IMPORT-PATH LABEL IS ON THE WRONG CONVENTION (user-named: "standardize the import-path label")
Verified: the path chip reads **`@mkbabb/glass-ui/icon-chip`**. But this is a **demo foundations page**, not the `<IconChip>` component page — its peer pages use the demo-route form (`/foundations/colors` reads `/foundations/colors`, confirmed in the sibling critique). The icons page documents the icon SYSTEM (lucide set, sizing, stroke, AND the chip), of which `icon-chip` is one part. Labeling the whole foundations page with one component's subpath is the inconsistency the user named.
**Fix:** standardize to the demo-route form `/foundations/icons` (matching `/foundations/colors`), OR — if the convention is "name the focal exported primitive" — make that convention explicit and apply it across the whole foundations band. One rule, applied uniformly. The current state is the colors page on route-form and the icons page on subpath-form: drift.

### 8. SUPERFLUOUS LANGUAGE (user-named, minor)
- The Pops `<p>` is a 4-line paragraph of internal-doc framing in visible UI copy: "a surface gets ONE color event — either a field behind glass or a chip cluster like this, never both at full volume; a chip never exceeds icon scale, and body ink is never tinted." That is the **proportion-rule rationale** — a code comment, not visible copy. A foundations page speaks in specimens.
**Fix:** cut to one code-voiced line: "The color event — `<IconChip :section>` walks `--section-color-0..12`." Demote the proportion rationale to the SFC comment (where it already lives). The page blurb "Lucide, 2px stroke, semantic sizes." is fine — keep.

## Verdict (5 lines)

1. The IconChip "Pops" row is a genuine reference-class move — 13 chips 1:1 onto `--section-color-0..12`, full-chroma glyphs over color-mix backplates, blooming in on the 0.34s `--spring-snappy` clock — and the monochrome discipline + the 86px √φ `<h1>` are on-doctrine; but the strength is confined to the top inch of the page.
2. The headline mandate fails: `canvas:0` — no aurora, so the single `glass-resting` body plate lenses nothing (§L1 inert), and in dark mode it reads as the W-DARK-MATERIAL "charcoal slab on a dead void" re-introduced at the composition layer.
3. The "each sub-section its own glassy card / main area BIGGER" ask is unmet — `glassCards:1`; the four sub-sections are bare transparent `flex` wrappers, two of them (Sizing/Stroke) entirely unframed clusters floating in the body.
4. The page leverages almost no glass-ui components (`tabs:0 button:0 colorSwatch:0`, dock is shell-only) — `<IconChip>` is the lone primitive; the Lucide reference is a generic opaque token-export grid, and animation affordance collapses to zero below the fold (no §L3 press-squish, dead Sizing/Stroke); the path label is on the wrong convention (`@mkbabb/glass-ui/icon-chip` vs the colors page's `/foundations/colors`).
5. Net: one world-class hero row over an accurate-but-generic spec-sheet — CONVERGENCE ~30%; needs the aurora field + per-section glass cards + the IconChip-bare reference grid + interactive Sizing/Stroke (tabs) + a facets dock + the label/copy tighten before the icon-foundations page demonstrates the icon system at the iOS-27 bar its own Pops row already reaches.

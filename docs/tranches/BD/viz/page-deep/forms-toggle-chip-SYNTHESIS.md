All three lenses AGREE on the page shape: a **correct, disciplined spec-sheet** — two near-identical caption→control→readout sections in ONE tall `glass-resting` card over a FLAT cream wash (`canvasCount: 0`), the thinnest forms page yet (~70% of a 72rem card is dead whitespace). ## Reconcile + dedupe

**Agreed across all three (no conflict):**
- The four-state §6 transition register is CORRECT and post-GLASS-CAL (scale on `--spring-smooth`, surface legs on the bezier) — do NOT regress. Component §1 + design §2 both confirm.
- The page fails the North-Star structure/suffusion/dock bars: ONE card not own-cards, `canvasCount: 0` not a colorful field, no dock contextual-switch, no protagonist. Demo §2-4, design §1/§3-5 agree verbatim.
- Copy carries internal design-system jargon leaked to audience voice ("the section identity is the ONE color event", "deliberately unopinionated about ToggleGroup", prop-syntax `variant=cell — exclusive selection` headings). Demo §6, design §1/§5 agree.

**The CONFLICT — why does the selected chip read gray? (root-cause split, both correct):**
- **demo §1**: `--tone` is unset ON THE PAGE → the `.accent-tone` band falls back to a warm-ink-over-cream mix that resolves achromatic. The PAGE never threads a tone (cf. `selectable-chip.vue` which threads `tone: var(--section-color-N)` per chip).
- **design §2**: the register is RIGHT (`glass-floating`, "selected reads as glass") but with NO colorful backdrop the translucent warm-cream plate composites against flat cream → muddy mid-gray. The defect is from STAGING, not the token.
- **component §5**: the SRC half — ToggleChip never threads `useAccentTone`, so even WITH a `--tone` the active-band INK is un-contrast-floored.
- **Resolution: all three are the SAME defect at three layers, and the fix is layered.** (a) the page must thread a real per-chip `:tone` AND stage a colorful aurora behind a `tier="field"` frame so the glass refracts color not cream (demo + design); (b) the component must thread `useAccentTone` so the active ink is contrast-safe regardless of `--tone` (component). Neither alone is sufficient: a tone over flat cream still reads weak; a field with `--tone` unset still reads gray. Both land.

**The net-new SRC findings (component lens only) — the page's distinguishing signal:**
- **DUAL-PATH** (component §5a): `ToggleChip` and `SelectableChip` are near-duplicate reka-`Toggle` wrappers reading the SAME `.accent-tone` register. SelectableChip (BC.W-ACCENT-TONE) is the public face + threads `useAccentTone`; ToggleChip predates it, was retrofitted onto `.accent-tone` but NOT `useAccentTone`. The distinguishing value is ToggleChip's `cell` variant (square icon-card; SelectableChip has none). The no-dual-path SOTA bar (BB.W-PRUNE-CONSOLIDATE) is violated in spirit → fold `cell` into the accent-tone family, retire ToggleChip clean-break (no alias), which fixes the contrast ink for free.
- **No glass six-layer composite** (component §6): a flat opaque `color-mix` pill — no blur/tint-plate/rim/catch-light/shadow/grain. SelectableChip SHARES this gap → register-wide AUGMENT, not a per-component patch (route the active state through a glass tier + the `--glass-accent` per-instance rim, the `--tone` already in hand).
- **No entrance/exit + CSS-transition press** (component §1): no `vReveal`/staggered build, and the press is a CSS `:active` transition not the interruptible `useSpringPress`/`useLiquidPress` register (no velocity-continuity, no `useLiquidFlex` squish). The `cell` grid in particular should build-in (the IconChip `:reveal` precedent).

**Dropped/merged as low-signal:**
- "Surface a first-class `tone` prop on ToggleChip" (demo §5/B-note) — SUBSUMED by the fold: post-consolidation the family already exposes `tone` (SelectableChip's surface). Do not add a prop to a component being retired.
- Path label is CORRECT here (single-family page, `@mkbabb/glass-ui/toggle-chip` matches) — but the fold re-points it to `/selectable-chip`. One-line AUGMENT, not a defect.

## Ranked changes (by impact)

1. **Card-per-section bento over a colorful aurora + thread real `:tone` (the user's headline structure + suffusion ask, and the gray-kill, in ONE move).** Retire the single-tall-card layout. Now the §L1 six-layer composite refracts a colorful field, the selected cell reads as glass-over-color instead of gray-over-cream, and the wide frame fills. Closes: own cards · bigger area used · glass-over-colorful-field · the dead-gray defect. All three lenses rank this #1.
2. **Fold ToggleChip into the accent-tone family — kill the dual-path + the AA contrast bug (the one real SRC architectural defect).** Fold the `cell` variant into the accent-tone chip family (a `shape`/`variant` axis on `SelectableChip`, or a shared CVA), retire `ToggleChip` clean-break (no alias), and thread `useAccentTone` so the active ink is contrast-floored on any `--tone`. The fix for the contrast bug (component §5b) falls out free. This is the no-dual-path discipline (BB.W-PRUNE-CONSOLIDATE) and the only `src/` defect unique to this page.
3. **Route the active chip/cell through a glass tier + `--glass-accent` rim (register-wide; SelectableChip shares it).** The active state should read as liquid glass over the aurora — the `.glass-menu-row` element-level oklab-tint + the W-LIQUIDHOVER tier-root specular auto-arm + the `--glass-accent` per-instance chromatic rim (keyed to the per-chip `--tone` already in hand) are the shipped seams to COMPOSE, not fork. Plus `vSpecular` so each chip gleams pointer-following on hover (the §L1 inner-catch-light alive) and the elastic gliding/squishing indicator (`useLiquidFlex` reciprocal-squish on `--spring-snappy`) on the exclusive cell group so selection glides not hard-repaints.
4. **Leverage the dock APIs for contextual variant switching (the user's explicit ask).** A `<DockStack mode="facets">` rail (BE.W-DOCK-RAIL-REALIZE) whose facet chips carry per-variant accent hues via `--glass-accent`, OR a `<DockLayerGroup>` whose layers ARE the variants (Chip / Cell / Icon-cells) — the rail contextually switches the foregrounded demo with the dock crossfade + size FLIP. The page teaches the dock system while demoing toggles. Promote the shell SidebarDock from chrome to content.
5. **Kill the double-header + tighten copy + canonical section rungs.** Remove the hand-rolled in-card `<header>` (re-introduces the D1-4 double-descriptor inversion `StoryHeader.vue` kills) — the chassis chrome header is the single source. Rename prop-syntax headings ("variant=cell — exclusive selection") to product titles ("Multi-select chips" / "Exclusive cells") at the canonical `text-subheading` rung (AZ.W-HIERARCHY; the page has `h2Count: 0`). Drop "the ONE color event" / "unopinionated about ToggleGroup" jargon. Animate the `selected:` mono readout with a `<Transition>` so the state echo is alive not hard-cut.

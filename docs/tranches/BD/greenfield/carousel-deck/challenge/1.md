## REFUTATION 1 (TOP) — the carousel squash-refraction collides with embla's transform ownership; the spike sidesteps it

The C3 distortion ("the outgoing/incoming slide PAIR squashes through the waist, reuses
`useLiquidFlex`, no new primitive") is proven in the spike by **overwriting** each slide's
`style.transform = translateX(baseDx) scaleX(..) scaleY(..)` (spike line 236). That works in the
spike **only because the spike owns `placeSlides()` and there is no embla.**

On the REAL carousel the slides are children of **embla's transformed container** — embla writes
`transform: translate3d()` on the container every frame during drag/momentum/Next-settle
(embla-carousel-vue ^8.6). The deck is free (full-viewport slides `inset:0`, opacity-faded — the
squash maps cleanly there), but the **carousel slide pair cannot have its `transform` overwritten**
without fighting embla's own translate. The GOLDEN's §6 lists embla as **UNTOUCHED** and never
addresses this composition. So the headline distortion mechanism is de-risked for the deck but has
an **unresolved application surface on the carousel** — the exact "deftly integrable?" question my
lens exists to ask. As written, a literal port of the spike's `s.style.transform = ...` onto a
carousel slide is a bolt-on that stomps embla.

**HARDENING:** the carousel squash must apply to a **dedicated inner wrapper** (a `.slide-squash`
child of each embla slide) OR via a CSS custom-prop the slide composes
(`transform: var(--embla-translate) scale(var(--goo-squash-x), var(--goo-squash-y))` is not how
embla works, so a wrapper is the clean answer). The GOLDEN §2.3 must state explicitly: *the
squash-refraction targets a per-slide wrapper element, NEVER the embla-driven slide/container
transform; the spike's `placeSlides()` overwrite is a spike-only shortcut.* C3's π must assert the
squash reads on the wrapper while embla's container translate is simultaneously live (a real
Next-click, mid-momentum) — not a static deck-style cross-fade.

## REFUTATION 2 — the golden's OWN proof spike violates the §5 cardinal bar (synthetic profile, not a raster)

GOLDEN §5/§7 mandate the born-RED be `rasterize → getImageData, NEVER arithmetic` ("the cardinal
bar"). But `squash-refraction.html` **self-admits** (lines 278–286): *"Simpler + robust for a spike:
sample the COMPUTED geometry transforms… walk a **synthetic cross-axis alpha profile reconstructed**
from the painted geometry."* The spike's PASS therefore reads the **pre-filter** transform scaleY
(0.349) and reconstructs an alpha curve arithmetically — it never rasterizes the `#glass-goo`
`feGaussianBlur(11)+feColorMatrix(…18 −7)` output through `getImageData`. The metaball **threshold**
is precisely what decides whether the post-blur alpha actually has a concave `hasLocalMinimum` at
the rendered waist; a thin pre-filter neck (scaleY 0.349) can be *swallowed* by the blur+threshold
into a single convex blob. So the spike de-risks the transform PROJECTION but **not the rendered
metaball waist** — the very claim §5 says must be a real readback. (The inherited
`goo-barbell.spec.ts` per WAVE-AMENDMENT.md:155 DOES do the real `getImageData` raster, so the
binding gate is sound — but this golden's own artifact does not de-risk what it rests on, and a
reader could mistake the spike's "PASS" for proof of the rendered waist.)

**HARDENING:** add a real raster arm to the spike (the `feColorMatrix(…18 −7)` threshold is the
risk: confirm the post-threshold cross-axis alpha at the rendered neck has `hasLocalMinimum` +
`waistRatio ≤ 0.45` via `getImageData`, with the `stdDeviation=11` blur applied — at bead D≈173 vs
gap 193 the two beads may *merge* under an 11px blur into a convex slab, which is the whole point of
the gate). Annotate the spike PASS as "transform-projection only — the rendered-alpha waist is
proven by `proof:goo-barbell`, not here."

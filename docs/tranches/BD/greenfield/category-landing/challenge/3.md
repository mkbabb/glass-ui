## THE REFUTATIONS (specific)

### R1 — TEAL LEAK IN THE GOLDEN'S OWN MARQUEE SPECIMEN (precept violation, self-inflicted)
The boldest specimen — substrates lead = "the full frozen aurora field" (§M3) via
`<Aurora render-mode="css">` (§M2/M4) — paints `paletteToCssGradient(props.config.palette)`
(`Aurora.vue:160`). For substrates that palette is **`cat-substrates` = palette index 3 =
"teal — the GL field band (aurora-blue family)"** (`aurora-hero.ts:112`). So the most
prominent, largest specimen on the landing the golden is *named after* renders a TEAL
aurora gradient sitting ON TOP of the warm `--card-field-h` window. The golden's M2 table
hand-waves this as the field having "its OWN warm palette, bounded" — but substrates' own
aurora palette is the teal one. The golden abolishes the teal CHIP-tint by construction
(via the unlanded fence) yet re-introduces teal in the FROZEN-AURORA specimen it foregrounds.
A user lands on `/substrates`, sees the hero's teal aurora AND a teal aurora in the lead
bento card — the precept ("NEVER teal") fails on the page that matters most.

### R2 — THE SPIKE DOES NOT PROVE THE §3 "DEFINED EDGE" IT CLAIMS
§3 gate B6: "the lit corner exceeds the opposite by ΔL keyed off `--glass-key`." The spike's
actual edge (`spike.html:143/150`) is a SYMMETRIC plain-white inset rim:
`inset 0 0 0 1px oklch(1 0 0 / .35)` — uniform on all four sides, no corner asymmetry, no
`--glass-key`. The "lit corner / key-edge" asymmetric mechanism is UNBUILT and UNPROVEN; the
spike de-risks only a flat white hairline (which is fine, but is not what §3/B6 specifies).
The §7 claim "B6 reads GREEN on the spike" is unsupported — B6 needs an asymmetric ΔL the
spike never paints. This is a born-GREEN-by-omission gate: it would pass on the spike's flat
rim, which means B6 is not actually born-RED for the mechanism it names.

### R3 — `:model-value` PROP MISMATCH (overfit / integration bug — vue-tsc won't catch the array)
§M2/§4 specify the `control` specimen as `<Slider :model-value="62"> + <Switch :model-value="true">`.
Slider's `modelValue` is an **array** (`Slider.vue:161` iterates `v-for="(_, key) in modelValue"`).
`:model-value="62"` passes a number where an array is required — at runtime `for...in 62` yields
nothing, the slider renders ZERO thumbs (an empty track). The golden's literal prop values are a
hand-rolled guess, not verified against the shipped signature. This is exactly the
glass-ui-binding-verification class (MEMORY: stale prop bindings silently no-op, vue-tsc misses
them). The "live `<Button>+<Slider>+<Switch>` cluster" the golden sells as the forms-card hero
would paint a thumbless slider unless the props are corrected to `[62]`.

### R4 — THE FROZEN-FIELD "BREATHES ON HOVER" CONTRADICTS THE ZERO-GL / STILL CLAIM, weakly
§2: a `field` specimen is a FROZEN STILL (§M4, "zero canvas, zero RAF"), yet §2 also gives it a
"sub-perceptual `--field-h` drift (a 6° warm hue-walk over 1.2s)." A CSS hue-walk on a custom
property that feeds `oklch()` backgrounds is a paint-every-frame animation on a non-compositor
property (background-color is not compositor-accelerated) — the opposite of the "costs nothing,
single-paint" budget the golden's whole §4 rests on. It is sub-perceptual by design (6°/1.2s) so
the user barely sees it — which means it spends paint cost for a near-invisible result: weak
gestalt-per-watt. Either commit to motion (and pay) or stay still; the in-between is neither
cartoon-punch nor free.

### R5 — CARTOON-PUNCH IS ASSERTED, NOT DE-RISKED (the §2 motion is unspiked)
The spike (§7) explicitly de-risks only "the specimen-stage card over the warm field + the
defined edge + the frozen specimens + the goo-merge lead." The §2 cel-slam cascade (anticipation
squash → arc → follow-through overshoot, overlapping stagger, specimen-lags-frame parallax) and
the §2.1 goo-merge *animation* are NOT in the spike's verified-live list — only the goo's static
metaball waist paint is shown. So the headline cartoon-register (the FLOW & PUNCH, the
squash/stretch with weight) is a paper promise. B11 ("cel-slam mid-flight has scale≠1 + an
overshoot frame") has no spike artefact; it is born-RED but un-de-risked. The current shipped
hover is `translate(-1px,-1px)` (live-confirmed `SectionPreviewCard.vue:111`) — tight, no squish,
no cast-travel — exactly the "too tight" the golden flags, but the golden's fix is unspiked.

### R6 — GOO `id` FORK-TELL (#goo vs #glass-goo) — a small DRY/integration crack
§2.1/§4 say the lead neck reuses "the SHIPPED `#glass-goo`/fission-bridge.css metaball pattern."
The spike mints its OWN `<filter id="goo">` locally (`spike.html:212`), NOT `#glass-goo`. The
shipped `GlassGooFilter.vue` documents the slide bridge references `url(#glass-goo)` and the
dock scale uses `#dock-fission-goo`. The golden must reuse the shipped filter mount (one `#goo`
singleton, DRY) — the spike's local `#goo` is a third goo id. Minor, but it is the seam where a
"union" quietly becomes a parallel filter. The build must mount the SHIPPED filter, not the
spike's.

### R7 — `--field-h` DEFAULT 62 COLLAPSES PER-CATEGORY VARIETY (gestalt: 11 identical fields)
The golden's window CSS is `--field-h: var(--card-field-h, 62)`. `--card-field-h` is set by
`SectionLanding` "passing the warmed hue" — but that warmed hue is derived from the UNLANDED
warm-fence. Until then (and live, right now) `--card-field-h` is unset → every card on every
landing falls to `62` (amber). The whole premise ("the route's OWN warm §3 field," per-category
identity) degrades to one global amber. The variety the golden sells is contingent on a sibling
that may land later or never; the wave must either mint its own warmed-hue derivation (then it is
NOT pure-consume — it edits the fence's territory) or accept a monochrome bento (gestalt loss).

### R8 — BOTH-MODES DARK ARM IS SPIKE-VERIFIED BUT GATE B7 IS LOOSE
B7: dark window `C≥0.045 warm, L∈[0.25,0.6]`. The spike dark floor is `oklch(0.30 0.040 var(--field-h))`
(`spike.html:149`) — **C=0.040, BELOW the B7 floor of 0.045.** The spike's own dark floor fails its
own gate's chroma minimum by 0.005. Either the gate threshold is wrong or the spike is — they
disagree. A born-RED gate the proving artefact fails is not de-risked; it is contradictory. (The L
is fine at 0.30; the chroma is the miss.)

## THE HARDENING (concrete — turns the spike into a buildable wave)

1. **Gate the wave on its dependencies, or inline the minimums.** `BD.W-BENTO-SPECIMEN` MUST be
   sequenced AFTER (or co-bundled with) the four sibling waves it consumes: mint `--phi` (and the
   φ-ladder `max-inline-size` scale) in `src/styles/theme/`, `--glass-key`, `paper-field`+`warmFieldHue`,
   and the `BD.W-SECTION-HUE-WARM-FENCE` re-index — OR fold the minimal `--phi` token + a local
   `warmHue(sectionHue)` clamp INTO this wave (then it owns them, no phantom DEPEND). Add a born-RED
   bite: "`getComputedStyle(:root)['--phi']` is unset" → RED on current, GREEN only once minted.

2. **WARM-CLAMP THE SPECIMEN PALETTE, not just the field (R1).** The `field` specimen's Aurora
   `palette` must be passed a WARM-clamped palette (H∈[25,95]) for cool categories — substrates'
   frozen aurora must paint warm-amber, NOT `cat-substrates` teal. Either add a `warmField` palette
   variant or clamp `paletteToCssGradient`'s hue for the specimen context. Gate B2 must read the
   SPECIMEN pixels, not only the window floor (the fraud bite: "a teal field" must also catch "a teal
   frozen-aurora specimen ON a warm field").

3. **Build + spike the asymmetric `--glass-key` edge (R2),** or downgrade §3/B6 to the symmetric
   white rim the spike actually proves. Pick one: if the key-edge is the precept, the spike must paint
   the ΔL corner asymmetry and B6 must measure it; if the flat rim is acceptable, drop the "lit corner
   exceeds the opposite" language so the gate isn't born-GREEN-by-omission.

4. **Fix the `control` specimen props (R3):** `<Slider :model-value="[62]">` (array), verify `<Switch>`
   takes `:model-value` (not `:checked`/`:pressed` — the reka-ui binding trap, MEMORY). Live-mount the
   cluster and confirm the slider paints a thumb before claiming "a real glass control row."

5. **Spike the §2 cartoon motion (R5)** — capture a frame-series (cel-slam overshoot frame, hover
   squish+cast-travel, specimen parallax-lag) so B11 has a de-risk artefact, not a paper promise. Until
   then mark §2 motion CONVERGENCE < 100%.

6. **Reconcile the dark chroma (R8):** raise the spike dark floor to `C≥0.045` (e.g.
   `oklch(0.30 0.05 var(--field-h))`) so it clears its own B7, or lower B7 to 0.040 with justification.

7. **Mount the SHIPPED `#glass-goo` filter (R6),** not the spike's local `#goo`; assert exactly one goo
   filter id on the landing (DRY bite).

8. **Decide the field-drift (R4):** either drop the 6°/1.2s hue-walk (keep the still truly free) or
   move it to a compositor-safe channel; do not pay background-repaint cost for a sub-perceptual effect.

## REFUTATIONS THAT LAND

### R1 (CORRECTNESS BUG — the top refutation): `--phi` does not exist; the spec-as-written emits invalid CSS

The GOLDEN body uses **bare `var(--phi)` with NO fallback** at three load-bearing sites:
- §M3: `aspect-ratio: var(--phi)` (line 109)
- §M3: `gap: calc(1rem * var(--phi))` (line 114)
- §4 mechanism table (line 217)

Grep: `--phi` is **UNSET** in `src/styles/` AND live (`--phi: ""` measured). Only the SPIKE
hedges with `var(--phi, 1.618)`. As written, the build's `aspect-ratio: var(--phi)` resolves
to the initial `auto` (invalid var → guaranteed-invalid → initial), so M3's headline "φ
proportion, NOT a 7rem void" **silently no-ops** and the window collapses to content height —
re-creating the very "large+empty/wrong-proportion" defect B4 is meant to kill. B4 would then
pass on the spike but FAIL on the real build, undetected by a source-green read.
**This is the exact class the gate exists to catch, hiding in the spec's own CSS.**

### R2 (DEFT-INTEGRATION / SEQUENCING): born-GREEN is blocked on FIVE unbuilt sibling GOLDENs

§4 brackets these as "CONSUME/DEPEND, NO edit here." Grep confirms **none exist on disk**:
- `paper-field` (@utility) — **absent**
- `warmFieldHue` / `warmHeroHue` (the warm clamp) — **absent**
- `--glass-key` (the §3 lit-corner / B6 key-edge) — **absent**
- the warm-fence: `categoryHue("substrates")` still returns **3 (teal)**; the live chip is teal
  RIGHT NOW. B2 (no-teal) cannot go GREEN until `BD.W-SECTION-HUE-WARM-FENCE` re-indexes.
- `BD.W-CONCENTRIC-RADIUS` — no wave file, no utility on disk.

The GOLDEN is a UNION in *intent*, but as a buildable unit it is **inert without 5 upstream
landings**. If this item ships first, B2/B6 are RED-by-dependency, not RED-by-this-item — a
false signal. The "union not fork" claim is true structurally but the **execution order is
unstated and the gate conflates this-item-RED with dependency-RED.** A diverse-lens hardening
must pin the build order or inline a local warm-clamp/edge floor so this item is self-GREEN.

### R3 (KISS / the goo lead card is the weakest cost/benefit): §2.1 is a bolt-on risk on transmissive glass

§2.1's goo-merge neck is the one place the "no backdrop-filter:url over the transmissive glass"
fence is fragile. The spike puts the goo on a SIBLING `.goo-bridge` layer with `filter:url(#goo)`
— correct. But the GOLDEN narrates the chip "pouring out" INTO the live specimen across the
card's z-stack; on the real `SectionPreviewCard` the chip (`IconChip`, z-raised) and the stage
sit in a flex column with the glass plate's own `backdrop-filter: blur(10px)`. A goo filter on
any ANCESTOR of that transmissive plate triggers the dock-goo-tear (design.md §183). The spec
SAYS sibling-only, but provides no structural guard that the integrator won't nest it. **KISS
verdict: the goo lead card is ~40% of the motion spec's risk for one card; it should be the
FIRST thing cut if the budget tightens, and B8's "goo on an ancestor → RED" bite must be a
real DOM-ancestry assertion, not a string check.** (B12 lists it; make it teeth.)

### R4 (OVERFIT / STALE ANCHORS): the cited line numbers have drifted

`SectionPreviewCard.vue:91` (the `#preview` seam) is actually `:90-97`; `:93-94` is `:93-95`;
`category-hero.ts:48` (previewKind) is `:61`. The `:140-141` gray thumb is correct (lucky).
Minor, but an integrator following the spec by line-anchor will mis-edit. Harden: cite by
SELECTOR/SYMBOL (`.section-preview-card-preview`, `previewKind`), not line number.

### R5 (KISS / DRY edge): the OPTIONAL per-story `specimen?` override risks a second source of truth

§M2 adds a `specimen?` field to manifest `Story` AND a `SPECIMEN` registry AND reads
`categoryHero(id).previewKind`. That's **three** places a card's specimen can be decided
(story override → registry → previewKind floor). The spec calls it DRY ("never a second switch")
but it is a 3-tier resolution. For 11 categories this is over-built; the `previewKind` floor +
the registry is enough. The per-story override is YAGNI until a real heterogeneous category
(forms input/slider/switch) is in hand — and even then, `previewKind` could just be per-story.
Harden: DROP the manifest `specimen?` field unless forms actually needs >1 kind; keep ONE
registry keyed off `previewKind`.

### R6 (CROSS-ENGINE, minor): the `in oklab` interpolation pin is asserted, not shown in the spike

§3 says "oklab interpolation pinned where mixing warm stops" but the spike's `radial-gradient`
stops are plain oklch with no explicit `in oklab` — they rely on the default. Safari and Chrome
default differently for some gradient color spaces; the page-background RASTER lesson is cited
but not de-risked in THIS spike (the spike was only verified in Chrome, per §7 — "Verified live
in Chrome", no WebKit capture). **B8 (WebKit-real) is the one gate assert with NO spike evidence
behind it.** The boldest cross-engine claim (the goo waist in sRGB on WebKit) is unproven; §7's
"both modes" means light/dark, NOT both engines. Harden: actually run the spike in WebKit and
attach the capture before claiming B8-ready.

## HARDENING (concrete, ordered)

1. **Define `--phi: 1.618` (and `--inv-phi`) as a real token** in `src/styles/tokens/` (or use
   the literal `1.618` in the rules) BEFORE any `var(--phi)` rule lands; never ship a bare
   `var(--phi)` without the `, 1.618` fallback. Add a gate bite: `aspect-ratio` computes to a
   ratio ≈1.618, not `auto`.
2. **Pin the build order** in §4: this item's GREEN depends on `SECTION-HUE-WARM-FENCE` +
   `PAGE-FIELD`/`FIELD-SCRIPT` + `GLASS-KEY-EDGE` + `CONCENTRIC-RADIUS` landing first. Either
   sequence them as hard predecessors, OR inline a local warm-clamp + edge floor so this item is
   self-GREEN (B2/B6 not dependency-RED). State which.
3. **Make B8 a DOM-ancestry assertion** (goo on an ancestor of the transmissive plate → RED),
   and **actually capture the spike in WebKit** (the goo waist + the warm field) before claiming
   B8/§2.1 cross-engine — §7 only proved Chrome.
4. **Cut the manifest `specimen?` override** (R5) unless a category genuinely needs >1 kind;
   keep ONE `previewKind`-keyed registry. DRY by subtraction.
5. **Re-anchor the spec by selector/symbol, not line number** (R4); the cited lines have drifted
   (`:91`→`:90-97`, `category-hero.ts:48`→`:61`).
6. **Mark §2.1 (goo lead card) as the first budget cut** — highest risk-per-card; the cel-slam
   cascade carries the cartoon punch without it if needed.

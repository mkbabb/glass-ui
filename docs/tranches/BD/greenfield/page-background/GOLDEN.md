## 4 — CROSS-ENGINE (Chrome AND Safari — the §L7 hard gate)

- **The field path is pure compositor CSS:** `radial-gradient` + `conic-gradient` + `oklch()` stops
  + a `transform` drift on a `::before`. All WebKit-native (`oklch` ≥ Safari 15.4; `@property` ≥
  16.4; gradients/transform forever). **NO `backdrop-filter: url`, NO SVG goo, NO trig in the field
  path.** Identical compositor behaviour both engines.
- **sRGB interpolation:** stop COLORS are authored in oklch for gamut-correct chroma; the
  INTERPOLATION between stops is the default sRGB (no `in oklab` hint WebKit handles differently),
  so the mesh is byte-comparable Chrome↔Safari. The `@supports not (color: oklch(0 0 0))` arm falls
  to an sRGB-hsl warm triad (slightly muddier, still warm, still clears a relaxed floor).
- **No glass-samples-glass trap:** the field is a fixed `-z-1` sibling BEHIND all glass; the glass
  `backdrop-filter: blur()` samples the field's COMPOSITED output (a normal painted layer), never
  another filter. The §L1 "glass cannot sample glass" rule holds by construction.
- **MEATBALLING stays where it belongs** — the metaball/goo (dock-fission + goo-blob) is static-SVG
  sRGB `filter:url()`; the FIELD path has ZERO goo. The field never carries a `backdrop-filter:url`.
- **The `<Aurora field>` rung** inherits Aurora's shipped WebKit fences (`renderMode="auto"` →
  CSS-gradient placeholder on low-power/PRM/Safari-fragile; itself a warm wash ≥ the static).
- **Acceptance = paired-engine π** (Chromium + WebKit captures of the composited page pixel behind a
  real glass control); the oklch gamut-map differs slightly per engine, so the floor is verified
  per engine, never assumed. The de-risk spike (`golden/spike.html`) must be re-run in Safari and
  clear the same floor before build-close.

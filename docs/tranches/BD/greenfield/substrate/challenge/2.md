## R2 — G1's promoted `sizeBacking` is NOT aurora's verbatim logic; the spike SILENTLY UPGRADES it (full ancestor-walk vs aurora's single parent)

The golden says (§G1) the body is "aurora's verbatim logic promoted, not re-invented." It is not.

- **aurora `runtime.ts:303`** (live source): `const parentRect = canvas.parentElement?.getBoundingClientRect(); const cw = rect.width || parentRect?.width || 1;` — exactly **ONE** ancestor level, then `|| 1`.
- **spike + G1 codeblock**: `let el = canvas.parentElement; while ((cw===0||ch===0) && el) { ... el = el.parentElement; }` — a **full ancestor chain walk**.

This is a genuine improvement (the born-skipped trap often has the `content-visibility:auto` on
a *grandparent*, which aurora's single-level fallback would miss → `1`), but presenting it as
"verbatim" hides that the golden is shipping NEW behavior into the leaf. The walk also has an
unstated risk: walking to a flex/grid ancestor that is wider than the intended canvas box yields
an OVER-sized backing (a stretched field). aurora's `|| 1` is conservative by design.

**HARDENING:** state honestly that G1 GENERALIZES aurora's single-parent fallback to an
ancestor-walk, and **bound the walk**: stop at the first ancestor with a non-zero box AND assert
the recovered box is the canvas's own intended box (e.g. cap at the nearest `position`/`contain`
ancestor, or the CV-host found in G2), never an arbitrary wide grid parent. Add a spike check
that the walk does not over-size when an ancestor is wider than the canvas slot.

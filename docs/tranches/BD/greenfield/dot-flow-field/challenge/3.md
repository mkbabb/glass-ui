The GOLDEN says `flow` "CANNOT sit under the `proof:viz-dotflow` math-frozen fence … The

the witness rather than re-scoping it to `field` only.

## R4 (PARTIAL) — "morph MORE on move / liquid-weight" is asserted for the cursor, ABSENT for the field at rest

LIQUID-WEIGHT UNIVERSAL requires inertia/weight/bounce on ALL motion and "morph MORE on move."
The GOLDEN's vortex spec (§2.3) is genuinely good — anticipation→impact→follow-through→settle, ~1s
burst decay, eased velocity. But the AT-REST field motion is `v = lerp(v, field(p), turnRate)` with
"low turnRate → weight." A low lerp coefficient gives **lag**, not **weight** — there is no
overshoot, no bounce, no squash/stretch on the *resting* current; the only squash-stretch mentioned
is velocity-anisotropic elongation (a stretch, never a squash; no spring). The reference edict is
weight+bounce+squish, not merely damped lag. Per the law this is the "tight/springy" failure's
mirror: **over-damped is as wrong as under-damped.**

### R4 HARDENING
Give the resting current a **slow breathing overshoot** (the §2.2 "breathing" `windSpeed` should
carry a √φ-phased ease-out-back, a gentle bounce at the turn of each macro-cycle, not a linear
drift) and add **squash on deceleration** to the cartoon-cast (a mote braking into an eddy
compresses along velocity, then rebounds) so squash-&-stretch is bidirectional. State the
`--motion-weight` coupling explicitly as an overshoot ratio (√φ), not just an offset scalar.

## R5 (PARTIAL) — non-golden proportion is ASSERTED, never specified

§1 claims "Aristotelian √φ proportion in spawn density / trail half-life / vortex radius / bloom

proportion" in a sentence.

### R5 HARDENING
Replace the bare ranges with an explicit **√φ ladder** anchored on one base: e.g.
`vortexRadius = r₀`, `bloomRadius = r₀·√φ`, `trailHalfLife = τ₀`, `lifetimeSec = τ₀·√φ²`,
`spawnPitch = p₀`, with r₀/τ₀/p₀ the single tuned anchors — so the proportion is structural and
auditable (a gate can assert the ratios), not prose. Tie trail-decay to half-life via the frame
rate so `trailDecay` is *derived* from `trailHalfLife·√φ`, not a free knob (DRY).

## R6 (MINOR) — DRY/overfit watch-items

- **Three dot-vizzes** now coexist: `dot-flow-field`, `dot-matrix`, `goo-dot-matrix` (+ `goo-dot`).
  The GOLDEN asserts "no dup vs dot-matrix/goo-dot" (§1.1) but doesn't show the boundary. With
  `flow` mode restoring advected particles, the line between `dot-flow-field:flow` and any future
  advected dot-matrix must be stated, or this becomes a fourth near-neighbour. HARDEN: one sentence
  pinning flow-field = *streamline-advected ribbons*, dot-matrix = *static/anchored*, goo-dot =
  *metaball-merged* — and a gate that the three don't share a default preset.
- **`preserveDrawingBuffer:true` "benefits every viz"** (§3, §7) is true but has a **memory/perf
  cost** (forces a non-discardable backbuffer; can disable some compositor fast-paths). Landing it
  globally at the substrate for every viz to fix a *readback-only gate* is a tax on production paint
  to serve the test harness. HARDEN: gate `preserveDrawingBuffer` behind a **measurement/dev flag**
  (or readback via a dedicated `readPixels` from the trail FBO, which needs no preserve flag), so
  production paint isn't penalised to make the π lane measurable. The spike already proves the
  mechanism; the substrate fix should be the *narrow* one.

## R7 (MINOR) — cross-engine reality is reasoned, not yet WebKit-captured

§4/§8 correctly avoid `backdrop-filter:url`/SVG-goo/naive-ellipsoids (compositor-only trail
texture + point-sprites — sound). The spike is verified in **Chrome only**; the WebKit leg is
asserted ("the path Safari actually runs") but not captured. Real WebKit gaps the GOLDEN should
prove away before "PERFECT in Safari": `EXT_color_buffer_float` + `RGBA32F` **render-target**
(not just texture) support is historically spotty in WebKit; `gl_PointSize` caps low on some WebKit
GPUs (the 2.4px sprite may clamp, thinning the field); `premultipliedAlpha:false` + additive blend
interacts with WebKit's compositor differently. HARDEN: the gate's "paired-engine π (Chromium +
WebKit)" must be a **captured WebKit artefact** (Playwright-webkit screenshot + π), not a single
Chrome spike + an assertion. State the `gl_PointSize` clamp fallback (scale point count up / size
down, or instanced quads on WebKit too) explicitly.

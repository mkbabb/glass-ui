# Challenge 2 — CROSS-ENGINE / SAFARI / PERF adversarial lens

Verdict: **SURVIVES with a load-bearing crack** — the GOLDEN's *direction* is right and most
counts/claims verify on disk, but its single headline promise ("the design-consistency gate is a
machine-checkable matrix cell, the convergence % is a computed fraction not a vibe") is **false as
shipped**. The `audit.mjs` prototype that the whole thesis rests on does NOT gate the things the
golden says it gates. The refutations below land on the *mechanism*, not the prose.

Source of truth: ran `node audit.mjs` (exit 1, born-RED confirmed), grepped the 158 on-disk waves +
37 amendments, read the linter line-by-line. Counts that VERIFY: 116 union / 42 BD-waves / 37
amendments; `comm -12` disjointness = 0; foundation tokens 0 src hits (born-RED correct).

## R1 (TOP) — PASS-2, the consistency gate, contributes ZERO to the exit code. It is a printout, not a gate.

The golden's boldest claim (§0, §4): *"the design-consistency gate is a matrix cell … the
convergence % is a computed fraction, not a vibe … immune to the fake-gate fraud."* The mechanism
does not deliver this.

- `lintTotal` (audit.mjs:179-181) sums ONLY `phantom + dupMint + danglingPrefix + scopeBleed +
  xengine`. **PASS-2 (`matrix`, `green`, `total`) is never added.** `process.exit(lintTotal ? 1 : 0)`.
- Therefore a row can carry `—` in EVERY axis and the audit still goes green once PASS-1/PASS-3 are
  clean. The "consistency verdict" never fails the build.
- Worse, the script has **no notion of "owed."** `green-where-owed` is asserted in the golden 5×,
  but there is no per-item applicability map in the code — a `—` cannot be distinguished from
  "N/A for this wave" vs "OWED but MISSING." The cell `aurora.GLASS = —` and a hypothetical
  `cards.GLASS = —` (a real divergence) are the same character. The gate that is supposed to make a
  "divergent row visible at a glance" is **blind to divergence by construction.**

This is precisely the fake-gate fraud the corpus legislates against (parse-as-pass), re-committed
in the gate that is meant to abolish it. The golden's self-description ("structural twin of the
paint-arm chroma π") does not hold: the chroma π REDs on a wrong pixel; PASS-2 reds on nothing.

**Hardening:** PASS-2 must (a) carry an explicit `owed[item][axis]` table (derive from tier/role:
every TIER-4 consumer OWES GLASS+MOTION+REGISTER; every §3 viz OWES PAPER+AURORA; etc.), (b) emit a
`matrixRed` count for `owed ∧ ¬green` cells, and (c) **fold `matrixRed` into `lintTotal`** so a
missing OWED carve actually fails 2-consecutive-clean. Until then the consistency % is exactly the
vibe the golden disclaims.

## R2 — GREEN in PASS-2 is substring presence, not canonical consumption — green is inflated, divergence is invisible.

Each axis is `RE.test(a.text)` over the whole amendment body. Consequences that break the gate's meaning:

- `buttons/WAVE-AMENDMENT.md` matches the GLASS regex 36× — but a GREEN here proves only that the
  string `glass-capsule` appears *somewhere*, including inside a `DEPEND` fence, a prohibition, or a
  prose aside. It does NOT prove the wave consumes the ONE canonical `.glass-capsule` floor vs.
  re-minting its own (the literal DUP the golden's §3 table exists to forbid). A second-mint wave
  scores GREEN.
- The AURORA axis regex (`aurora|--field-h|sectionHue|warmFieldHue|§3|vivid`) matches **33 of 37**
  amendments — `§3` and `vivid` are near-ubiquitous. That column is noise; it cannot surface the
  one teal/navy divergence the golden itself calls the sole globally-divergent violation (§4). The
  gate that should catch TEAL-NAVY scores the teal-carrying heroes GREEN on AURORA.

**Hardening:** GREEN must assert *consumption of the canonical source* (cite-of-mint-wave +
absence of a competing local `@property`/`@utility`/recipe mint), not substring presence. Tie each
axis to the §3 canonical-source slug and RED a row that both (mints OR re-declares) AND (does not
cite the canonical owner).

## R3 — PASS-3, the cross-engine floor, reads 37/158 files. "0 — consistent across the WHOLE corpus" is unproven for the 116 union waves.

The golden's §6 calls PASS-3's `0` "lens-b's headline good-news, confirmed … across the whole
corpus." But `for (const a of amendments)` (audit.mjs:146) iterates **only the 37 greenfield
amendments.** The 116 union waves + the brainstorm/DELTA-ASSAY bodies are never scanned by the
forbidden-literal floor.

- 62 union waves mint goo/morph/`backdrop-filter` content that PASS-3 never reads.
- The WebKit-fatal `backdrop-filter:url(#…)` ungated form, the `-58deg` leak, and animated
  `box-shadow` could ride through any of the 116 union specs invisibly. (I grepped: the union waves
  are in fact clean today — 0 ungated `url(#`, 0 `-58deg`, 0 animated `box-shadow` — so the corpus
  *discipline* is genuinely good. But the GATE does not prove it; the claim is true by luck, not by
  the linter.) That is the same "green-by-not-looking" failure mode the golden indicts.

**Hardening:** PASS-3 must scan the full corpus (union waves + amendments + the DELTA/brainstorm
bodies the dispositions cite), not just the 37 amendments. Then the `0` is earned.

## R4 — The single most-emphasized cross-engine precept (the metaball waist gate / "never a naive ellipsoid") is checked ZERO times.

§3a is the binding heart of my lens: M2 = `max_t S.ratio ≤ 0.45 ∧ hasLocalMinimum` from rendered
pixels, "a real blob↔meatball metaball merge, never a naive ellipsoid, never a hand-drawn polygon";
M4 tier-ladder parity ≤ 0.10; M6 the OWED Safari-26 capture as a RED-that-blocks-green. These
strings appear 149× (`waist`/`S.ratio`/`0.45`) and 231× (`smin`/`barbell`/`metaball`) across the
corpus. `audit.mjs` checks them **0 times** (grep of the script: no `ellipsoid|waist|smin|metaball|
S.ratio|hasLocalMin`). The golden asserts these are gated; the mechanism does not encode a single
one. They live, exactly like the findings the golden criticizes, as **prose the reader must trust.**

**Hardening:** add a PASS-4 metaball-precept lint over every goo/morph wave: assert the body
declares the waist gate (`S.ratio` bound + `hasLocalMinimum`), names sRGB `color-interpolation-
filters`, declares the Tier-S↔Tier-G parity bound, AND carries the M6 Safari-capture-as-RED clause
or the Tier-C teardrop fallback. A goo wave missing any → RED, folded into `lintTotal`. The
"never a naive ellipsoid" law must be a lint, not a sentence.

## R5 — PRM/a11y is asserted ("PASS-2 adds a PRM column") but does not exist; reduced-transparency is never gated.

§3b binds PRM/reduced-transparency on every motion/glass row, and §3b/§6 promise "PASS-2 adds a PRM
column; a missing carve is a RED cell." There is no PRM column in PASS-2's `AXES` (GLASS/PAPER/
AURORA/RADII/CARTOON/MOTION/REGISTER — 7 axes, none PRM). The only `prefers-reduced` token in the
whole script is ONE alternative inside PASS-3's §L7-arm OR-regex (audit.mjs:154) — a wave satisfies
that arm by mentioning `Safari` alone, with zero PRM carve. So the binding a11y law is unchecked,
and the specific over-carve defect the golden flags (PRM-zeroing the cartoon INK itself) is not
detectable by the gate. `reduced-transparency → opaque` is never matched at all.

**Hardening:** make PRM a real, exit-code-bearing axis: every motion/glass/goo wave must declare
`--motion-weight → 0` (or `--ease-standard`) under PRM AND a `reduced-transparency` opaque arm AND
must NOT zero `.cartoon-cast` ink. Missing → RED in `lintTotal`.

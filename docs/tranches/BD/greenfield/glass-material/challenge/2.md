## REFUTATION 3 — the CEL KEYSTONE cast formula is SIGN-INVERTED (the cast falls TOWARD the light)

Leg (c) is "the single boldest move": rim + cast agree on ONE key so the brain reads a lit
object. The load-bearing formula (spike + GOLDEN §4(B)):

```css
box-shadow: calc(cos(var(--glass-key)) * -14px) calc(sin(var(--glass-key)) * 14px) … ;
/* --glass-key: -58deg */
```

Evaluated: `cos(-58°)*-14 = -7.4px`, `sin(-58°)*14 = -11.9px` → offset **(-7.4, -11.9) =
UP-LEFT**. The key light is "top-left" (§4). A coherent cel casts the shadow OPPOSITE the
light — DOWN-RIGHT, `(+x, +y)`. **The formula casts the shadow UP-LEFT, the same quadrant
as the light.** The rim brightens top-left AND the shadow falls top-left — the exact
"iOS-7 sticker" incoherence the golden claims to defeat is what the math produces. §4(B)'s
prose ("offset opposite the key, down-right") and its code DISAGREE, and the code is what
ships. This is not cosmetic: it is the keystone's defining behaviour, wrong.

**HARDENING:** Fix the sign convention. If `--glass-key` is the light VECTOR (direction the
light comes FROM), the cast is `+sin(key)*d` on X and `-cos(key)*d` on Y mapped to the
down-AWAY-from-light quadrant — work the trig from the actual CSS axis (X+ right, Y+ down)
and ASSERT it in the gate (F3 must check the cast offset SIGN puts it opposite the rim-lit
edge, not just "non-none"). Add a born-RED unit on the offset quadrant.

## REFUTATION 7 — `cos()/sin()` in box-shadow is a FIRST-USE with no `@supports` floor

§6 lists "`box-shadow` + `cos()`/`sin()` (CSS Values 4, both engines)" as cross-engine-safe.
Grep: **zero `cos(`/`sin(` in all of `src/styles/`.** This is a NET-NEW CSS-math dependency in
the box-shadow path. Safari shipped trig functions in 15.4 (mid-2022), so the floor is real —
but the golden lists NO `@supports (top: cos(0deg))` fence and NO degraded arm. A non-supporting

drops the WHOLE box-shadow to invalid → no cast → the defined-edge floor (the §3.c insurance)
VANISHES on exactly the old engine it's meant to protect. Recall the MEMORY lesson: a single bad
fragment inside a box-shadow nukes the whole declaration (the light-dark inset-shadow trap is the
same failure class).

**HARDENING:** Either author the keyed cast offsets as STATIC per-key constants (precompute the
`-58deg` offsets to literal px — DRY-er, no runtime trig, no parse risk), or wrap the trig arm in
`@supports (left: cos(1deg))` with a literal-px fallback cast. Add the trig-drop to the F3 born-RED
arms.

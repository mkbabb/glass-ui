## REFUTATIONS (all land on §5, the optional dogfood face — none kills the spine)

### R-1 (TOP) — §5 names primitives that DON'T EXIST under those names → an un-buildable card-wall spec
§5 says the headline bar "composes `<ProgressBar>`" and the chip "reuses … the static SVG
`<GooFilter>`" and "rides the Safari-verified `DockGooFilter`." Disk reality:
- **There is no `ProgressBar` component.** `src/components/ui/progress/` ships `Progress.vue`,
  `ProgressDefault.vue`, `ProgressGradient.vue`, `ProgressSectioned.vue`. `grep -rn "ProgressBar" src/`
  = **0 hits.** A "deft union, reuse extant primitives" spec that cites a non-existent primitive is a
  latent bolt-on: an implementer either invents a new `ProgressBar` (a fork — DRY violation) or has to
  guess the real name.
- **There is no `<GooFilter>` component** — it is `GlassGooFilter` (id `#glass-goo`) /
  `DockGooFilter` (id `#dock-fission-goo`). §5 mixes both wrong-and-right names in one paragraph.
- **`--ease-cartoon-punch` and `.cartoon-cast` are spec-only, born-RED, NOT landed in `:root`.**
  `HARDENING-PLAN.md` line 233 states verbatim: "`--ease-cartoon-punch` … all EMPTY on :root → both
  new gates born-RED." `grep` of `src/styles/` finds `.cartoon-surface` but NO `--ease-cartoon-punch`
  token and NO `.cartoon-cast` utility. §5's bar "fills with `--ease-cartoon-punch` WEIGHT … casting a
  moving … cartoon cast (the `.cartoon-cast` inert-child caster)" composes a token and a caster that
  do not yet exist in shipped CSS. Building §5 today would FAIL the very born-RED gate the corpus
  legislates — §5 silently assumes the `BD.W-CARTOON-PUNCH` / `BD.W-MOTION-WEIGHT` `·auth` waves are
  already materialized, but the oracle itself classes them `·auth` (un-materialized). §5 is
  *self-inconsistent with the manifest it ships beside.*

### R-2 — §5's PRM degrade contradicts itself (a11y/PRM gap)
§5 enumerates THREE motions: (a) the balance-bar fills with cartoon-punch overshoot, (b) a chronic
chip "goo-splits off the deferred spine-rail and morphs," (c) a GAP row "flashes … anticipation-dip-
then-punch." Then it asserts "the goo-fold is the **ONE** SVG-filter motion." That is true only of the
SVG-filter count, but the PRM clause then says "PRM → the bar fills instantly, the chip relocates with
no neck frames, the crimson is static" — i.e. THREE separate degrades for THREE motions. A reader who
trusts "ONE motion" under-implements the PRM floor (forgets to kill the bar overshoot and the crimson
flash). The "anticipation-dip-then-punch crimson UNTIL it gains a carrier" is an **indefinitely
looping attention-grab** — that is exactly the kind of persistent motion `prefers-reduced-motion` and
WCAG 2.2.2 (pause/stop/hide) exist to stop. §5 says "the crimson is static" under PRM but does not say
the *loop* stops for non-PRM users either; an un-dismissable infinite technicolor pulse on a
documentation surface is an a11y defect, not a feature.

### R-3 — §5 "warm-cream six-layer transmissive composite over a §3 colorful field" cites a §3/§L7 that isn't where it claims
§5 binds every card-wall surface to "design.md §L7" (the blob↔meatball neck) and "§3 = a COLORFUL
FIELD." The binding-law file the task names — `design.md` — **does not exist at any `design.md` path**;
the real precept doc is `docs/tranches/BD/viz/critique/design-language-congruence.md`, and the §L7
content lives in `design.md`-as-amended-by-`BD.W-DESIGN-PRECEPT-AMENDMENT` (per HARDENING-PLAN line 232:
"NEW §L7 cross-engine"). The citations are *probably* resolvable, but §5 cites section anchors
(`§L7`, `§3`, `§L4 weak/medium`) without a resolvable path — and HARDENING-PLAN line 232 records a
CARRY-FORWARD defect that design.md "~L499/501/1069 still cite RETIRED CartoonCard/.glass-cartoon as
live." So §5's surface-spec inherits a doc whose own cross-engine anchors are mid-correction. A
card-wall built against today's design.md risks re-citing the retired `.glass-cartoon`/CartoonCard
(the exact overfit-to-a-dead-ref trap). This is a doc-grounding gap, not a paint gap.

### R-4 — perf: the §5 "composes `<ProgressBar>` + the cartoon-shadow register … casting a MOVING layered-offset cartoon cast" is a per-frame box-shadow animation
A "moving layered-offset cartoon cast" on a filling bar means animating `box-shadow` offsets per
frame. Animated `box-shadow` is a known non-compositor, paint-bound property in BOTH Chrome and WebKit
(triggers raster every frame, no GPU promotion). §5's own header promises "pure compositor
(opacity/transform)" — a moving multi-layer box-shadow cast VIOLATES that promise. The shipped
discipline (`.cartoon-surface` reads a STATIC `--shadow-cartoon`) is compositor-cheap precisely
because it does NOT animate the shadow. §5 should cast via a pseudo-element/inert child translated by
`transform` (the `.cartoon-cast` *caster* pattern it names), NOT by animating the bar's own
`box-shadow`. As written, "moving … cartoon cast" reads as the expensive path.

### R-5 (minor, spine) — the `authoredSlugs` regex is greedy across collapsed newlines (a false-authored risk)
`recap.mjs:77` does `raw.replace(/\n\s+/g, " ")` then `matchAll(/\b(?:NEW|MINT|…)\b[^\n]*?\b(BD\.W-…)/g)`.
After the newline-collapse there are fewer `\n`, so `[^\n]*?` can span what were multiple wrapped
lines, potentially binding a `NEW` verb to a `BD.W-` slug that belongs to a LATER sentence — minting a
phantom into `authoredSlugs` (67 today). A spuriously-authored slug would let a row that should be
`partial`/`gap` read as a live `authored` carrier — a *silent up-grade*, the inverse of born-RED. Not
firing today (lints clean), but it is an un-fenced parser fragility in the spine's most important
classifier. KISS fix: match per physical line (don't collapse), or bound `[^\n]` → `[^\n.]` so a
sentence-period stops the span.

## HARDENING (concrete, applied to §5 + the spine — all KISS/DRY, no fork)

1. **Fix every primitive name in §5 to the shipped reality (kills R-1's un-buildability):**
   `<ProgressBar>` → `<Progress>` (or `BorderProgress` for the rail-fill variant);
   `<GooFilter>` → `<GlassGooFilter>` / `<DockGooFilter>` (name the exact one, id `#dock-fission-goo`);
   `.cartoon-cast` → the shipped `.cartoon-surface` caster + cite that `--ease-cartoon-punch` is a
   `BD.W-CARTOON-PUNCH·auth` dependency (the bar uses the EXISTING `--ease-*` springs until that wave
   materializes). State explicitly: **§5 is gated on the `·auth` motion waves landing — born-RED on
   them, not a standalone build.** This makes §5 consistent with the manifest beside it.

2. **R-2 PRM rewrite:** declare THREE degrades, not "ONE motion": bar fills instantly (no overshoot),
   chip relocates with no neck frames (the one SVG-filter motion), GAP crimson is a STATIC tint with NO
   loop. Add: the GAP crimson pulse is a finite N-cycle (or single anticipation-dip then settle) for
   ALL users, never an infinite loop (WCAG 2.2.2). PRM kills it to a static tint + an aria-live="polite"
   text "GAP — no carrier" so the signal survives without motion.

3. **R-3 doc-grounding:** replace `design.md §L7`/`§3` anchors in §5 with resolvable paths
   (`viz/critique/design-language-congruence.md` for the precept congruence + the
   `BD.W-DESIGN-PRECEPT-AMENDMENT` design.md §L7 anchor) AND add a one-line note: the surface must NOT
   reference the retired `.glass-cartoon`/CartoonCard (the HARDENING-PLAN line 232 carry-forward) — use
   `.cartoon-surface`/`.shadow-cartoon-*` only.

4. **R-4 compositor-honesty:** the cartoon cast is cast by an inert pseudo/child translated via
   `transform` (compositor-only); the bar's own `box-shadow` stays STATIC. Make §5's "pure compositor"
   promise literally true by forbidding animated `box-shadow`.

5. **R-5 spine parser fence:** change `recap.mjs:77` to scan per physical line (drop the
   `\n\s+`→space collapse for the authored-mint pass) or bound the span at a sentence period, so a
   `NEW` verb cannot bind a slug from a later wrapped sentence. Add a unit-style assertion that the
   67 authored slugs each appear within ~12 tokens of their minting verb.

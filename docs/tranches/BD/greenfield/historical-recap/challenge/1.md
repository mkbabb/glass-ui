## R1 (TOP) — the "nothing is lost" GUARANTEE is structurally FALSE: 46 distinct sub-asks have no row and no per-sub-ask JOIN

The manifest has **38 canonical rows** but the de-dup collapses **46 distinct itemized sub-asks**
into `recurrence[]` arrays with NO row of their own and, crucially, **no per-sub-ask carrier JOIN**:

```
A11, A6, A7, B1, B2, C3, C4, C5, C6, R1.A1..A12, R1.B1, R1.B2, R1.C1..C3,
R2.A1..A7, R2.B1..B5, R2.C1..C6, R3.1, R3.5, R5.A8   (46 tokens)
```

The carrier JOIN is a logical **OR** over a row's carriers: `addressed = ≥1 LIVE carrier`. So a
macro-row goes green when ANY ONE of its carriers is live. Concretely: `R2.C_VIZ` collapses six
distinct deliverables (R2.C1 blob, C2 fourier, C4 "warp the CELLS not the lines", C5 dot-matrix 2d
bg, C6 concentric level-set) onto six greenfield dirs. If the **C4 cell-warp** regressed while the
other five stayed `delta✓`, the row would STILL derive ADDRESSED — the C4 ask is invisible to the
oracle. The recap can therefore lose a specific user ask while reporting "addressed," which is the
exact `batch3-A1`/`live_verify_capture` disease the GOLDEN claims to cure, reintroduced one altitude
up. "Nothing lost" is true only at MACRO-row granularity, not at the granularity the user actually
spoke in.

**Hardening:** make `covers` a per-sub-ask map (or add a `subAsks[]` array each with its own
`covers`), and derive the macro-row as the **AND** over its sub-asks (a macro-row is ADDRESSED only
when EVERY collapsed sub-ask has ≥1 live carrier; otherwise PARTIAL with the unmet sub-ask named).
At minimum, assert `covers.greenfield.length ≥ (count of distinct R*.C* sub-asks in recurrence)` so a
6-way collapse cannot ride on one carrier. This converts the OR-blindness into a real loss-fence.

## R2 — PASS 4 "no-silent-drop attestation" `orphanOrigins` is a PROVEN TAUTOLOGY (the gate cannot fire)

`recap.mjs` lines 163-167:
```js
const orphanOrigins = [...allRecurrence].filter((id) =>
  !id.startsWith("mem:") && !canonicalIds.has(id) &&
  !rows.some((r) => (r.recurrence || []).includes(id)));   // ← always false
```
`allRecurrence` is built as the UNION of every row's `recurrence[]`. Therefore every `id` in it
satisfies `rows.some(r => r.recurrence.includes(id))` BY CONSTRUCTION, so the third clause is always
false and `orphanOrigins` is **always empty** — verified: `orphanOrigins = 0`, and it is unreachable,
not merely zero-today. The code comment even concedes it ("an origin id is OK if it is listed in SOME
row's recurrence (it is, by construction)"). The headline PASS-4 "no-silent-drop attestation" — the
literal mechanism the GOLDEN sells as the no-loss guarantee — **can never go RED.** Only the
`selfDrops` half of PASS 4 is live; the orphan half is dead.

**Hardening:** the real no-loss fence must compare the manifest against an EXTERNAL enumeration, not
against itself. Build `allRecurrence` from the SOURCE corpus (parse the section ids out of
`viz/refine/USER-FEEDBACK-*.md` + `MASTER-REQUEST-RECAP.md §A1-15/§B/§C1-6/§D`), then born-RED any
source-id that appears in NO row's `recurrence`. THAT catches a dropped ask. Self-referential
orphan-checking proves nothing.

## R3 — `falseGreens` (PASS 3 "anti-inflation fence") is dead code — a strict subset of `gaps`

Line 173: `falseGreens = findings.filter(f => f.mismatch && f.derived === "gap" && typed !== "gap")`.
But `derived === "gap"` is produced ONLY by `!hasCarrier || !anyCarrier` (line 136) — the same

inflation it NAMES — a typed-`addressed` row whose ask is actually only PARTIAL — is **unreachable**
by the derive rule: a row with all-live carriers always derives `addressed`, never `gap`, regardless
of whether the underlying ask is truly met. The "false-green" line in PASS 3 is theater; the genuine
false-green class (the OR-blindness of R1) sails straight past it. The GOLDEN's §0 boast that "its own
gate caught FOUR real defects" is also now **unfalsifiable** — the manifest was hand-corrected to
clean before commit, so the claim cannot be re-derived from disk (the very sin the doc legislates
against). Today the gate fires 1 lint (the R2.D2 gap) — a single hardcoded GAP, not a self-proving
anti-inflation engine.

**Hardening:** delete the dead `falseGreens` line and replace it with the R1 sub-ask AND-derive (a
real typed-addressed-but-actually-partial detector). Re-add a regression FIXTURE under `golden/` (a
deliberately-broken mini-manifest) so the "caught 4 defects" claim is a re-runnable test, not prose.

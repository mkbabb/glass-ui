# CHALLENGE 3 — DESIGN-FIDELITY / GESTALT lens on historical-recap GOLDEN

Default: REFUTED. The golden's mechanism (recap.mjs + manifest) is REAL — it runs, exits 1,
is deterministic, and the §7 numbers (29 addr · 7 part · 1 defr · 1 GAP · 87.3%) reproduce on
disk to 4 decimals. The primitives §5 claims to compose (ProgressBar, useDockFission,
GlassGooFilter) all EXIST in src/. The GAP (R2.D2 flowers) is genuine. So the SPINE survives.

But my lens is design-fidelity-AS-A-USER, and on THAT bar the golden has a load-bearing crack:
**the oracle certifies "addressed" on citation-existence ALONE, enforcing ZERO of the edicts it
is sworn to.** It is a no-gray-glass-blind, cartoon-punch-blind, proportion-blind ledger that
can render the headline "Gray glass → warm-cream: addressed" while the surfaces it cites are
measurably gray ON DISK in the very HARDENING-PLAN it ingests. Plus a phantom binding-law cite.

---

## R1 (TOP) — the oracle is DESIGN-FIDELITY-BLIND: "addressed" ≠ "adheres to the edict"

`grep -c 'chroma|oklab|no-gray|warm|cartoon|squash|screenshot|paint|backdrop' recap.mjs` = **1**
(the lone hit is a `backdrop-filter:url` mention inside a CODE COMMENT). The gate is a pure
*citation-existence JOIN*: a row derives `addressed` iff it cites a greenfield DIR that owns a
`DELTA-ASSAY.md` (or a materialized/authored wave). **It never reads a pixel, a chroma value, a
spring curve, or a screenshot.** The "verify-once-upstream, cite-many" framing (§0) assumes each
DELTA-ASSAY already proved warm-cream/cartoon-punch/golden-proportion at its close — but the
golden INGESTS the HARDENING-PLAN that says otherwise, in writing:

- **cards row (HARDENING-PLAN:254):** converged `delta✓`, yet `composite C 0.0097 GRAY` (K2 RED),
  `border 4%-α melt` (K3 RED), `dark fill charcoal` (K4 RED), `--ease-cartoon-punch EMPTY`,
  `CardHeader linear both ×4` (no weight). "Remaining 20% = build-time."
- **tabs row (HARDENING-PLAN:252):** converged, yet `indicator chroma 0.0128 < 0.02 NEAR-GRAY`
  (the capsule IS the gray), `--motion-weight/--ease-cartoon-punch EMPTY on :root`.
- **blend-morph row (:268):** converged, yet the V↔H morph is a `view-transition crossfade`
  with `--dock-morph-t≡0.000` (no squash/weight), `--ease-cartoon-punch ABSENT`.

So the recap maps **R3.GRAY → partial** and **R1.B_ANIM → ADDRESSED (law codified)** — but the
LAW being "codified" as a token name is not the same as the SURFACES being warm/weighted, and the
recap has no way to tell the difference. A user reading "87.3% converged, animation law addressed"
sees a green headline over a storybook that is, by the plan's own π readbacks, still gray and
springless on multiple converged surfaces. **This is precisely the `feedback_live_verify_capture`
disease the golden claims to cure — "addressed is a citation, not a captured delta" — relocated up
one level: the recap inherits proof BY CITATION but never checks that the cited DELTA-ASSAY's π
actually went GREEN, only that the FILE exists.** A `DELTA-ASSAY.md` that documents a RED π still
counts as a live carrier.

**Hardening:** add a PASS 1.5 fidelity-lien. For every row whose `class:"precept"` (gray, anim,
proportion, paper, goo-Safari), the carrier JOIN must additionally parse the cited
`DELTA-ASSAY.md` for a machine token (e.g. a `PI: GREEN`/`PI: RED` or `gate: green` line, or a
`_delta-*-π.json` sidecar) and DOWNGRADE `addressed`→`partial (fidelity-owed)` when the cited
delta's own π is RED or absent. The precept rows MUST NOT go green on file-existence; they go
green only when the cited delta carries a GREEN paint-π. This makes the recap honest about the
gap between "spec converged" and "surface actually warm/weighted/proportioned" — the distinction
it already draws for materialization (`·auth`) and assembly, but conspicuously NOT for fidelity.

## R2 — phantom BINDING-LAW cite: `design.md` does not exist on disk

The golden's header BINDING LAW and §0/§1 cite `design.md` (Philosophy, §L preamble, §L6, §L7) as
the governing source, and §5 cites "a real blob↔meatball neck — `design.md §L7`". But
`find docs -iname design.md` returns **NOTHING**. The §L preamble + §L6 + §L7 actually live INSIDE
`GREENFIELD-HARDENING-PLAN.md` (the amendment was applied there, per :232). So the golden's own
binding-law citation is a **phantom-cite** — the exact false-green class its PASS 3 is built to
catch on WAVE slugs, but the oracle does not scan the GOLDEN's prose citations, only the
manifest's `covers{}`. A recap whose thesis is "a citation MUST target the live successor, the
oracle enforces it" cannot itself dangle its top binding-law reference. (Note: `wave-spec-audit/`
golden cites design.md too — so this is a tranche-wide dangling anchor, not a one-off typo.)

**Hardening:** either (a) point every `design.md` cite to the real path
(`GREENFIELD-HARDENING-PLAN.md §L*` or the actual file once it lands), or (b) add a PASS-0
binding-law existence check to recap.mjs that asserts every doc named in the manifest's `law`
field resolves on disk (it currently has a `law` field — extend the JOIN to verify it). The
oracle that polices dangling wave cites must police its OWN governing-doc cite.

## R3 — the §5 fidelity FACE is unfalsifiable prose; if it is the design, it is unbuilt

§5 is the only part of the golden that carries any actual design (warm-cream six-layer composite,
√φ proportion, cartoon-punch balance-bar, goo-split chronic chip, technicolor-crimson GAP flash).
But it is fenced as "optional dogfood — the doc is the spine," and `grep -rn '/meta/recap|recap-card|
cartoon-cast' demo/ src/` = **0 hits**. So none of the design claims are testable: there is no
route to live-test in Chrome OR Safari, no `.cartoon-cast` caster, no balance-bar instance. The
challenge mandate ("live-test via chrome-devtools-mcp if a prototype exists") finds the prototype
is the .mjs ledger, NOT a visual surface — so the iOS-27 fidelity claims (warm floor, cartoon
shadow, Safari-safe goo neck, golden proportion) are asserted, never demonstrated. This is fine IF
the golden honestly scopes itself as doc-only — but then §5 should not be written in the
confident present-tense ("Every surface IS the warm-cream six-layer composite… proportion ON the
√φ ladder") as if it ships. As written it reads as a fidelity GUARANTEE for a surface that does
not exist.

**Hardening:** demote §5 to an explicit FUTURE-WORK arm with a born-RED carrier of its own — if
the `/meta/recap` card-wall is a real deliverable, it gets a greenfield dir + DELTA-ASSAY and the
recap tracks IT (reflexively, like R0.7). If it is NOT a deliverable, strike the present-tense
fidelity prose and label §5 "illustrative, unbuilt." Do not let a 0-hit storybook face read as a
shipped warm-cream/cartoon-punch guarantee. Reuse-check passes (ProgressBar/useDockFission/
GlassGooFilter all exist) — so the deft-union claim is credible, but credible ≠ built.

## R4 — recency weight is editorialized as "computed," but the BAND assignment is hand-typed

§2d sells `convergence = Σ(w·score)/Σ(w)` as "recency as a function, never a vibe." True for the
arithmetic. But each row's `band` (which fixes its weight 6…2) is a HAND-TYPED manifest field —
there is no disk-derived recency (no mtime, no git-date, no batch-file ordering). So the "freshest
asks dominate" property is only as honest as the author's band tags. R0.7 (this recap) sits at
weight 6 and is `partial` (0.5) — it deliberately drags the headline DOWN, which is honest. But
nothing stops a future author parking a weak-coverage ask in R6 (weight 2) to minimize its drag on
the headline. The weight is a vibe wearing a formula's clothes.

**Hardening:** derive `band` from disk where possible — the batch feedback files carry dates
(`USER-FEEDBACK-2026-06-23{,-batch2,-batch3}.md`); map a row's primary `recurrence[]` origin to
its source file's date and ASSERT the typed band matches the date-derived band (born-RED on a
mis-banded row). At minimum, add a PASS that flags any row whose typed band contradicts its
cited source-file stratum.

## R5 (minor) — the GAP/deferred score asymmetry inflates the headline

§2d scores `deferred:1.0` (full credit, "held not lost"). R6.METAL (Real-Metal-GPU parity) is the
single biggest owed engineering deferral in the whole corpus, yet contributes a PERFECT 1.0 to
convergence. Combined with `partial:0.5`, the 87.3% headline counts a permanently-deferred item as
fully discharged. A user asking "are we done?" gets a number that treats "we decided not to do
this" identically to "we did this." Defensible as a policy, but it is a design choice that flatters
the headline and should be surfaced, not buried in a scoring table.

**Hardening:** either split the headline into two numbers (`% addressed` vs `% addressed-or-held`)
or weight deferred at <1 (e.g. 0.75) so the headline visibly distinguishes done from held. The
GAP-report is loud; the deferred-credit should be equally honest in the top-line %.

## VERDICT

**SURVIVES?  NO — a real refutation lands (R1).** The spine (the oracle, the manifest, the
born-RED gate, the GAP, the disk-true %) is sound and reproduces exactly. But the golden is the
HISTORICAL-RECAP for a DESIGN tranche whose binding law is no-gray/cartoon-punch/golden-proportion,
and its oracle enforces NONE of that — it certifies `addressed` on file-existence while ingesting,
in the same breath, a HARDENING-PLAN that records the cited surfaces as gray and springless. The
recap can fly a green "warm-cream addressed" headline over a measurably-gray storybook. That is the
exact anti-inflation disease it claims to cure, displaced up one altitude. Add the precept-row
fidelity-lien (R1) + fix the phantom `design.md` cite (R2) + demote/carrier the unbuilt §5 face
(R3) and it converges to a recap that is honest about DESIGN, not just about file presence.

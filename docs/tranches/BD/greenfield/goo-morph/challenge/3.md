## R1 (LANDS — the headline) — the §8 "de-risk spike" is CIRCULAR; the waist 0.272 was NEVER measured, it is an arithmetic ECHO of a hardcoded constant

The GOLDEN's entire credibility rests on §8: "built + verified live … the π readback …
waist/body 0.272 (measured in the spike)." I read `golden/barbell-neck.html` and ran it live.

The spike's `measure()` is:
```js
const throat = D * d.neckGirth * 0.34;   // 0.34 == the --neck-waist constant
const ratio  = throat / D;               // == neckGirth * 0.34
```
Live readback (chrome-devtools `evaluate_script`): `usesCanvas:false`, `usesHardFactor:true`.
At p=0.5: `neckGirth=0.800`, so `waistRatio = 0.800 × 0.34 = 0.272` — **the number is the
input echoed back through a hardcoded multiplier.** It NEVER calls `getImageData`,
`drawImage`, or reads a single rendered pixel of the blur→threshold output. The §8 table's
whole "✓ REAL WAIST (measured)" column is the FORMULA reporting its own assumptions.

This directly contradicts the GOLDEN's OWN born-RED gate (§7), which demands
`hasLocalMinimum(crossAxisProfile)` from "a **canvas readback** of the warm-cream alpha
band." The spike that allegedly de-risks the boldest mechanism performs ZERO canvas
readback. **The de-risk is non-existent; §8 is a self-fulfilling assertion.** Per
`feedback_live_verify_capture` (the cardinal-lesson inflation), "live-verified" requires a
captured DELTA artefact — and a number that is `0.34 × neckGirth` is not a measurement.

Worse: the design RUNS a `stdDeviation=13` Gaussian over a structural throat whose pre-blur
half-height is only ~7.8px (I computed the union profile live: `minUnionHalf 7.79px`,
structural ratio 0.118). A 13px-sigma blur spreads alpha ±~26px — it will substantially
**FILL** a ~15px-wide throat before the threshold cuts. The actual rendered post-blur waist
is therefore FATTER than the structural 0.118 AND unrelated to the analytic 0.272. Nobody
has measured what `blur 13 / slope 15 / offset −7` actually produces at this throat width.
The headline G1 gate (waist/body ≤ 0.45) is asserted, never demonstrated.

**HARDENING:** rebuild the spike to do a REAL readback — render the `.goo` layer (SVG filter
output) to a canvas (`html-to-image`/`drawWindow`/CDP screenshot → `getImageData`), then
measure the cross-axis warm-cream alpha profile along the travel axis at p∈{0,.25,.5,.75,1},
assert `hasLocalMinimum` on the ACTUAL post-blur profile, and report the TRUE
post-blur-post-threshold waist/body. Tune `blur`/`slope`/`offset`/`neckGirth`/`--neck-waist`
**against the rendered minimum**, not against `0.34·neckGirth`. Capture a paired Chromium AND
real-Safari-on-Metal readback (§L7) BEFORE this is golden. If the rendered waist is > 0.45
because the 13px blur fills the throat, the blur must drop or the throat must narrow — and
that re-solve is the actual de-risk that has not happened.

## R2 (LANDS) — "lift the `--neck-filament` HOURGLASS clip-path idiom (reuse, no fork)" is FALSE-REUSE: the extant idiom is a rectangular `inset()`, the hourglass `polygon()` is NET-NEW geometry

The GOLDEN sells its WebKit insurance as deft reuse: §1 "the fission `--neck-filament`
clip-path hourglass idiom — already proves the answer at dock scale"; §3 "the `--neck-filament`
hourglass clip-path idiom … are REUSED (imported as the shared neck recipe), NOT forked";
§9 "lifts the fission `--neck-filament` hourglass." This is the load-bearing KISS/DRY claim.

It is false. I read `src/styles/dock/fission-bridge.css`. The actual extant neck idiom is:
```css
clip-path: inset(var(--neck-inset) 0 var(--neck-inset) 0 round 999px);
```
A **rectangular inset that thins a capsule** from top & bottom toward a centerline — there is
NO hourglass, NO concave `polygon()`, NO mid-pinch. `--neck-filament: 42%` is the inset
*depth* of that rectangular thinning, not a throat polygon. The dock neck produces a *uniformly
thinning bar*, the exact silhouette the GOLDEN's own §0 diagnosis says CANNOT make a waist
("a single constant-cross-section rectangle … can only yield a fatter rounded rectangle").
lens-a even hedges this itself ("a `clip-path` hourglass `polygon` **(or a `path()` with
concave Bézier sides)**") — proving the hourglass is being *invented*, not lifted.

So the GOLDEN's central cross-engine de-risk — "the clip-path concavity is engine-agnostic,
guaranteed on both engines before the blur fuses" — depends on geometry **that does not exist
in the codebase**. It is a brand-new `polygon()` with 14 vertices (born in the throwaway
spike), presented as a battle-tested dock idiom. That is precisely the bolt-on / parallel-fork
the binding law forbids, dressed in reuse language. NO LEGACY is satisfied, but DEFT-UNION is
violated: this is new invention mislabeled.

**HARDENING:** state honestly that the hourglass `polygon()` is NET-NEW and that the fission
neck uses `inset()` thinning. Then EITHER (a) genuinely unify — refactor the fission neck to
the same concave throat primitive so both dock and carousel share ONE real hourglass recipe
(true DRY, and it would *improve* the dock waist too), OR (b) drop the "reuse" framing and
justify the new polygon on its own merits with the R1 rendered proof. Do not claim dock-scale
provenance for geometry the dock has never shipped.

## R5 (PARTIAL — a genuine thesis-crack) — the PagerDots "migration PROOF" is the SAME single-worm topology the GOLDEN calls BROKEN; it is not a two-mass barbell

The GOLDEN leans hard on the pager as social proof: §1 "The pager dot (already two pips + a

I read `PagerDots.vue`. The pager renders **N opaque static `.goo-dot` pips + ONE opaque
`.goo-worm` capsule** — and the worm is the EXACT single-element `useGooMorph` two-edge
silhouette (same `morphRef`, same `paint()`). The dots are static; only the worm moves. This
is structurally the SAME "one stretching worm over static masses" the §0 diagnosis condemns
as "a warm TRAY with one scalloped edge … no geometry that can produce a waist." So either:
- (a) the pager's single-worm-over-static-pips ALREADY reads as a correct goo morph at dot
  scale — in which case the §0 "this is a SHAPE problem, no blur/threshold tune can fix the
  single-plate" thesis is OVERSTATED (the pager IS a single worm and it works), and the real
  carousel defect may be the N-FULL-HEIGHT-plate bed / scale, fixable more cheaply; OR
- (b) the pager is ALSO a tray and the GOLDEN mislabels a broken thing as "proof."

Either way the "pager already proves the two-mass barbell" claim is false — the pager is NOT
a barbell, it is the condemned single worm. The GOLDEN cannot cite it as both the broken
pattern AND the correct-topology proof.

**HARDENING:** drop the pager-as-proof framing OR actually convert the pager to a true
two-bead barbell and re-verify it reads better than today's worm-over-pips (a real fidelity
GAIN, not an assertion). Resolve the thesis tension: is the carousel defect the single-worm

## R6 (LANDS — visible defect) — the rendered metaball is FACETED, not a smooth liquid blob; the 14-vertex polygon shows through the threshold

The `golden/peak-waist.png` (which I viewed) shows a real waist — BUT bodyA carries a hard
**angular dark crease** down its right flank where the polygon's straight edges meet the
circle. The neck is not a smooth liquid throat; it is a piecewise-linear hourglass whose
facets survive the blur+threshold (slope 15 is not soft enough to fully round 14 straight
segments at this scale). This violates the cartoon/liquid-glass edict directly: the user's bar
is "real blob↔meatball metaball merge … NO naive ellipsoids," and a faceted polygon throat is
its own naivety — a *polygon* artifact instead of an *ellipsoid* artifact. A user reading this
sees "low-poly," not "mercury." The gestalt is the bar; a visible crease fails it.

**HARDENING:** replace the 14-vertex `polygon()` with a `path()` using concave Bézier (cubic)
sides — a true smooth throat — OR raise the blur locally / lower the slope until the facets
fully dissolve, verified by the R1 rendered readback (no straight-segment luminance steps in
the cross-axis profile). The √φ proportion edict should govern the throat curve's control
points, not 14 hand-placed percentages (which are themselves an overfit hardcode — see R7).

## R7 (LANDS) — the engine rewrite is more invasive than "projection re-authored, drive verbatim" admits; single `morphRef` → a 3-child group is a structural API break, and PRM/`drive`/`placeStatic` all assume ONE element

§3: "RE-INVENT `paint()` … Same `--goo-t` drive, same `travel`/`snap`/`drive`/PRM … verbatim."
I read all 353 lines of `useGooMorph.ts`. `paint()` is not the only thing that touches the
silhouette — EVERY method writes `morphRef.value.style.transform` for ONE element:
`placeStatic` (the rest authority), `snap`, `drive`, and the `tick` rAF all assume a single
silhouette. The barbell needs THREE coordinated transforms (`cA`/`cB`/`sep`/`neckGirth` +
clip-path) every frame. That means `placeStatic` (coalesce to one body at target), `drive`
(live-drag the gap), `snap`, and the PRM early-return ALL must be re-authored to drive a group
of three children — not just `paint()`. The PRM carve ("one body snaps") is a different code
path than today's single-morph snap. The "drive verbatim" claim undersells a near-total
internal rewrite, which raises the regression surface on the three SHIPPED consumers (pager,
carousel, deck) that the GOLDEN promises stay working. `feedback_glass_ui_binding_verification`
warns this class of "looks-unchanged but the projection changed" breaks silently past vue-tsc.

**HARDENING:** scope the rewrite honestly — name `placeStatic`/`drive`/`snap`/PRM as ALSO
re-authored, not "verbatim." Specify the three-child group contract (one ref or a children
array?) and how `placeStatic` coalesces to a single resting body without leaving a ghost neck.
Add a regression gate that the pager + deck still pass their EXISTING π after the rewrite (the
de-dup G6 claim is only true if all three consumers survive the new projection).

and its INTEGRATION HONESTY. Fix the proof to be a real rendered readback, stop calling new
work reuse, correct the numbers, and it stands.

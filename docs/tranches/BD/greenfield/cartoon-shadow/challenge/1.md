# Cartoon-shadow GOLDEN — Challenge #1 (CORRECTNESS / DEFT-INTEGRATION / KISS)

Lens: idiom · deft-integration (union vs bolt-on/fork/legacy) · KISS/DRY · gate-born-RED ·
overfit/hardcoded · a11y/PRM · cross-engine. Default: REFUTED. Live-tested the `golden/spike.html`
in Chrome (devtools-mcp) + read the actual `src/` carriers.

**Verdict: SURVIVES with one BLOCKING defect that must be fixed before the wave can land.** The
strategy (own warm ink, transform-only caster, reuse the two composables, ship the two motion
tokens) is genuinely the deft union it claims and three of its gate arms are genuinely born-RED. But
the SINGLE BOLDEST MOVE — the press caster — is **specified BROKEN** (dead on arrival, proven live),
and the §4a pseudo-budget premise that justifies putting it on `::before` is **factually wrong about
the actual carrier**. Both are concrete, both are fixable, neither is fatal to the design — so:
harden, don't discard.

---

## R1 (BLOCKING, proven live) — the press caster is DEAD ON ARRIVAL: missing `@property` registration

The GOLDEN registers `@property --cartoon-cast-dx/dy` (§4b) but does NOT register `--cartoon-press-t`,
`--cast-travel`, or `--cast-spread`. Those are the props that actually drive the punch. An
**unregistered** custom property is an untyped token string; when a `calc()` built from unregistered
vars feeds `translate`/`scale`, the engine cannot resolve it to a `<length>`/`<number>` and falls
back to the property's initial value. The punch never fires.

**Live proof** (Chrome, `golden/spike.html`, pressed state):

```
hostPressT          : 1                              ← the host var IS set
beforeCastTravel    : calc(6px * 0.62 * 1)           ← computes as a LITERAL STRING, never a length
beforeCastSpread    : calc(1 + 0.18 * 0.62 * 1)
::before translate  : 0px        ← DEAD (should be ~3.7px)
::before scale      : 1          ← DEAD (should be ~1.11)
```

Registering the missing prop live FIXES it on the spot:

```js
CSS.registerProperty({name:'--cartoon-press-t', syntax:'<number>', inherits:true, initialValue:'0'});
// → ::before translate "3.72px 3.72px", scale "1.1116"   ← punch now fires
```

So §1's "single boldest move", §4's whole caster, §7's PRESS/DRAG acceptance bar, and §8's G3 are
**all non-functional as written** — in BOTH engines, not a WebKit quirk. Worse, §8 claims "the spike
is the executable seed of G3 — it proves the caster mechanism live before the src/ wave lands." It
does the opposite: the spike, when actually pressed and read back (its own `__spikeProbe`), DISPROVES
the caster. Nobody ran the spike's press path. This is the exact `@property`/oklab-paint-arm class of
trap the project memory already records (a value that "looks computed" but resolves to the invalid
initial because the type isn't registered).

**HARDENING (required):** add to §4b / scheme-motion / the wave —
```css
@property --cartoon-press-t { syntax: "<number>"; inherits: true; initial-value: 0; }
@property --cast-travel     { syntax: "<length>"; inherits: false; initial-value: 0px; }
@property --cast-spread     { syntax: "<number>"; inherits: false; initial-value: 1; }
```
and fix the spike identically, then RE-CAPTURE the pressed-state readback as the G3 seed artefact.
G3 must additionally assert `getComputedStyle(el,'::before').translate !== '0px'` under `:active`
(the current G3 only asserts the value is "non-`none`", which a dead `0px` would falsely pass).

## R2 (BLOCKING) — §4a pseudo-budget is WRONG about the real carrier: `::before` is NOT free

§4a: "the host `::before` is the moving-specular catch-light — but specular is OFF on a flat cartoon
surface … so on `.cartoon-surface` the `::before` is FREE." This conflates *intensity 0 at rest* with
*the pseudo not existing*. In the real `src/`:

- `<Card surface="cartoon">` ALWAYS composes a `glass-${tier}` base class (`Card.vue:352-356`) — it
  is a decoration ON a tier, never a tier replacement (the GOLDEN itself says so in §9).
- `glass/material.css:80-95` paints `.glass-resting::before, .glass-floating::before,
  .glass-card::before { content:""; position:absolute; inset:0; z-index:1; … }` **unconditionally**
  for every tier. Only the `--specular-intensity` is gated to `0` at rest — the **pseudo element
  fully exists and occupies the `::before` slot**.
- `cards.css:45-46` states this verbatim: "already claims BOTH pseudos — `::before` is the
  moving-specular catch-light (glass/material.css) and `::after` is the grain overlay" — and the
  paper-grid wave (cards.css:55) treated exactly this as a real "pseudo contention" hazard.

So the GOLDEN's `.cartoon-surface::before { box-shadow; z-index:-1; translate; scale }` would
OVERRIDE the glass-material catch-light `::before` on every cartoon Card. Consequences: (a) any
cartoon Card that opts into `specular` loses its catch-light; (b) the unified PRM/PRT guards
(`glass-specular-track.css:35-71`) that target `.glass-card::before` now fight the caster's
transform; (c) z-index flips from `1` (specular, above content) to `-1` (caster, behind) on the SAME
pseudo — a real cascade collision. This is a **bolt-on that clobbers an extant primitive**, the exact
anti-pattern the lens guards against, hidden behind a premise that reads plausible but is false.

**HARDENING:** drop the "::before is free" fiction. Either (a) the caster rides a dedicated **real
child element** the Card emits when `surface="cartoon"` (`<span class="cartoon-cast" aria-hidden>`),
sidestepping every pseudo entirely — costs one inert span, keeps both glass pseudos intact, and
remains transform-only/compositor-cheap; or (b) explicitly **un-paint** the glass `::before` for
cartoon (`.cartoon-surface::before { all: revert; … }`) AND document that `surface="cartoon"` is
mutually exclusive with `specular` (and patch the PRM/PRT guard list). Option (a) is the cleaner
union (no fighting the glass family); §4a must be rewritten to state the truth that the tier's
`::before` is occupied.

## R3 (MAJOR) — the down-LEFT → down-RIGHT flip is an unjustified, unenumerated breaking change

The landed tokens cast **down-LEFT** (`shadow.css:92-100`: `-3px/-4px/-6px` X). The GOLDEN flips all
three to **down-RIGHT** (§3) and justifies it as "coherent with the upper-left key light the rest of
the system paints from." That key light **does not exist** as a system constant:

- The house specular rest position is **centered** (`material.css:104`: `--specular-x: var(--mouse-x,
  50%)`), pointer-tracked — there is no fixed upper-left key.
- The elevation family `--shadow-md/-lg` is **straight-down** (`0 4px …`) — a top-down key, if
  anything, not upper-left.
- The only top-left light is the `@supports`-gated `#glass-refract` feImage garnish
  (`glass-refract.css:30`) — an optional filter, not the system key.

So the coherence argument is post-hoc. Flipping direction is fine as a *deliberate* aesthetic call,
but it is a **visible breaking change to every existing consumer** of `--shadow-cartoon-*` — the
metric-badge (`components.css:66` reads `--shadow-cartoon-sm`), every `.shadow-cartoon-*` utility
swatch, and the dark-arm `--shadow-modal` plane — and §0's "live verdict" table never lists "the cast
is currently down-LEFT" as a defect, while §10 claims "same carriers, same consumers … no re-fork."
A direction inversion is not "same look."

**HARDENING:** either (a) pick down-LEFT to preserve the landed direction (the BD memory mandate is
"REFINE what is weak", and the *direction* isn't the defect — the gray/blur/weakness is), keeping the
key-light claim honest by deleting it; or (b) keep down-RIGHT but ADD a row to the §0 verdict
("current cast is down-LEFT, incoherent with the top-down elevation family") and an explicit
consumer-impact line in §10 enumerating metric-badge + the swatches as intentionally re-cast. Don't
assert an upper-left key the code doesn't have.

## R4 (MINOR) — overfit / hardcoded refs

- **§2 dark-arm pins `--cartoon-ink: oklch(0.22 0.07 70)`** — a hardcoded literal, abandoning the
  `oklch(from --foreground …)` hue-extraction the light arm uses and the GOLDEN praises as "no
  hardcoded literal." Hue `70` is a magic number with no token lineage; if a consumer retints the
  dark `--foreground`, the dark ink won't follow. Derive it: `oklch(from var(--foreground)
  clamp(0.20,calc(1-l),0.26) max(c,0.07) h)` (invert L for the dark ground, keep the extracted hue),
  or at minimum source the hue from a warm-anchor token, not `70`.
- **§3 `@supports` fallback `#4a3320`-ish** — a hardcoded warm-sRGB literal with no token name; give
  it a `--cartoon-ink-fallback` so it's overridable, per the no-dead-local contract the file cites at
  shadow.css:78.
- **§5 `--motion-weight: 0.62`** is `1/φ` — fine — but it's asserted in §8 G2 as `≈ 0.62` with an
  exact-match flavour; the gate should assert the φ relationship or a tolerance band, not a frozen
  literal that drifts if the rest-weight is ever retuned.

## What SURVIVES (steelman — to be fair to the golden)

- **G1 (ink) is genuinely born-RED and the fix genuinely works.** Live: the own ink resolves
  `oklab(0.216 0.039 0.058 / 0.32)`, chroma ≈ 0.070 > 0.05 (warm, not gray); landed defect is
  `color(srgb …)` near-black at 0.12α/1px blur. `oklch(from)` + `color-mix(in oklab)` are Baseline /
  Safari 16.4+. The chroma floor + oklab-mix vs srgb is the correct BA.W-NO-GRAY discipline.
- **G2 (motion tokens) is genuinely born-RED.** Verified: `--motion-weight` and
  `--ease-cartoon-punch` have **zero** occurrences in `src/` — design.md fiction, never shipped.
  Shipping them to scheme-motion.css §2 as raw `--ease-*`/scalar (not a SPRING_PRESETS/MOTION_CURVES
  row) is correct — a `linear()` with a negative anticipation leg is neither a spring nor a bezier.
- **The composable reuse is real, not aspirational.** `useLiquidPress` exists with a `pressVar`
  option that writes a `0..1` press-t style, compositor-only, PRM-instant
  (`composables/motion/useLiquidPress.ts:74,127,177`); `usePointerVelocityField` exists
  (`composables/motion/usePointerVelocityField.ts`). ZERO new composable / ZERO new SFC is honest.
- **Cross-engine surface is the safest in the tranche** — opaque ink, no `backdrop-filter`, no
  `filter:url()`, no metaball; transform-only caster composites identically in Blink/WebKit. The
  `linear()` → `--ease-out-expo` and `@property` snap fallbacks are correct graceful degradations.
- **PRM/PRT carve is correct** — `--motion-weight:0` collapses every `calc(…*--motion-weight…)` to
  rest (one-assignment), the static stamp survives as a legibility anchor, and PRT correctly leaves
  the opaque ink alone.

## Bottom line

The DESIGN is fit and is a true union; the SPEC ships it broken. R1 (unregistered press vars → dead
punch, proven live) and R2 (the `::before`-is-free premise is false for the real carrier) are both
blocking but both have clean, KISS-preserving fixes (register three props; move the caster to an inert
child or explicitly un-paint + mutually-exclude specular). R3 (silent direction flip on a non-existent
key light) needs honesty in §0/§10. With those three, the golden stands.

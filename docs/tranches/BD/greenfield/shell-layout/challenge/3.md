## Refutations

### R1 — "ONE source" is FALSE: the hero hue is a SECOND, duplicated source (DRY violation the GOLDEN inherits and hides)

The GOLDEN §2 asserts leg-(a) re-index is DEFT because "the chip + eyebrow + facet-rail accent
ALL auto-track — they read the same `--section-color-N` … ONE source, so leg-(a) fixes every
consumer at once."

Source says otherwise. `aurora-hero.ts` carries a **hardcoded JS mirror** of the CSS ramp:

```ts
const SECTION_COLOR_OKLCH: readonly string[] = [
  "oklch(0.552 0.192 359.8)", // 0 rose
  ...
  "oklch(0.542 0.089 222.8)", // 3 teal-cyan   ← DUPLICATE of the CSS --section-color-3
  ...
];
const css = SECTION_COLOR_OKLCH[((n % 13) + 13) % 13]!;   // sectionColorToHeroPalette
```

So there are **TWO sources of every section hue**: the CSS token ramp
(`src/styles/tokens/color-radius.css` + the `.dark`/`light-dark` arms) AND this JS array. The
hero FIELD (the teal wash I screenshotted) reads the JS array; the chip reads the CSS var. The
GOLDEN's leg-(a) "re-index the `sectionHue` index" does **not** touch either color value — the
index 3 still points at a teal literal in BOTH stores. To actually purge teal you must edit:
1. the CSS ramp values `--section-color-{3,9,2,11}` (+ each `.dark` arm + `light-dark.css`), AND
2. the `SECTION_COLOR_OKLCH[{3,9,2,11}]` literals in `aurora-hero.ts`.
Two stores, four+ rows each. The GOLDEN's "re-index, one source, fixes every consumer at once"
is wrong on the mechanism and on the blast radius.

### R2 — The eyebrow does NOT track the section hue (auto-track over-claim)

Live: the substrates eyebrow class is `text-admin-label text-muted-foreground` and computes
`rgb(124,102,80)` — a mode-invariant warm-muted token, **decoupled** from `sectionHue`. The
GOLDEN's §2 "chip + eyebrow + facet-rail accent ALL auto-track" is partly false: the eyebrow is
already warm-decoupled, so leg-(a) neither helps nor hurts it. Minor, but it inflates the
"one move fixes everything" framing.

### R3 — `useTabIndicator` is a TABS-INTERNAL composable, not a free primitive — wiring it into `<DockSection>` IS a bolt-on/fork (the exact thing the GOLDEN claims to avoid)

The GOLDEN §1/§5/§9: "we do NOT build a `<DockFacetRail>` parallel component … we bring the
SHIPPED `useTabIndicator` glide+squish … INTO the existing `<DockSection>` render. KISS, no
fork." But `useTabIndicator` lives at
`src/components/custom/tabs/composables/useTabIndicator.ts`, is **NOT exported** from any
package barrel (`src/index.ts`, `src/composables/motion/index.ts`), and takes an 11-field param
harness coupled to SegmentedTabs internals: `containerRef, indicatorRef, buttonRefs, model,
anchorSupported, jsSliderActive, activeValues, vertical, …`. To "bring it into `<DockSection>`"
you must reconstruct the entire SegmentedTabs ref/anchor harness inside the dock — that is a
**parallel reproduction**, the bolt-on the GOLDEN says it avoids.

Worse, it collides with the GOLDEN's OWN scope fence: §0 says the dock ENGINE owns
"the `useTabIndicator` glide/squish" (dock-core). The dock already ships `DockLayerGroup.vue`
+ `useDockOrientationMorph` — its own seam machinery. So the deft move is to drive the switch
through the DOCK's indicator seam, not import the tabs composable. The GOLDEN cites the wrong
`useTabIndicator` (tabs') vs the one its scope-fence reserves (dock-core's) — an internal
contradiction.

### R4 — `BD.W-DOCK-TAB-INDICATOR` is UNBOOKED; the §9 "AUGMENT of the BOOKED wave" is false

§9 calls the contextual switch "an AUGMENT of the BOOKED `W-DOCK-TAB-INDICATOR`." Grep of
`docs/tranches/BD` (and `docs/tranches`) finds **no `*TAB-INDICATOR*` wave**. The GOLDEN's
own §9 parenthetical even says "(dock-core, **propose**)". So the headline liquid-switch fix
DEPENDS on a wave that does not exist and is only proposed — it is NOT a confirmed seam to ride.
The GOLDEN should either book the wave or own the switch-motion wave itself.

### R5 — The born-RED hue gate is mis-specified (T5 naming collision + wrong file scope)

§8/§9 says the fence adds "`proof:teal-navy-purge` clause T5 (born-RED)." But
`scripts/proof-teal-navy-purge.mjs` ALREADY HAS a T5 — the *live-paint* arm
(`tests-visual/teal-navy-purge.spec.ts`, deferred to orchestrator). And T1 (the source arm)
explicitly fences "**library viz-substrate constants** (aurora/concentric/dot-flow/fourier/
goo-blob/constellation)" and explicitly scopes OUT non-substrate tokens. The per-category demo
`sectionHue` / `SECTION_COLOR_OKLCH` lives in `demo/stories/` — **not a library viz constant**,
so today's gate is GREEN on the teal hero (the GOLDEN even admits "the per-category demo hero
sectionHue slipped the binding"). Adding a clause numbered "T5" collides with the existing live
arm. The fence needs a genuinely NEW source predicate (call it T6) that extends T1's
`[180,270]` hue scan to cover `demo/stories/{category-hero.ts,aurora-hero.ts}` AND the
`SECTION_COLOR_OKLCH` array AND the CSS `--section-color-N` rows the hero indices reference —
born-RED on today's `222.8/265.5/239.6/208.0`. As written, "T5 clause" is not born-RED against
the right surface.

### R6 — The warm-fence leg-(b) `warmHeroHue()` is DEAD CODE after leg-(a) (KISS tension)

The GOLDEN proves leg-(b) is "identity on already-warm hues" and "fires structurally only on a
hypothetical future cool leak." After leg-(a) re-indexes all 11 to warm, `warmHeroHue` runs on
every call and changes nothing — it is a guard with no live consumer. That's defensible as a
fence, but it adds a code path the no-dead-token / overfitting-audit discipline will flag unless
the gate (R5) is what actually keeps it honest. Recommend: leg-(b) is only justified IF the
new born-RED source gate is what proves it live (a `--selftest` arm feeding a synthetic cool
hue through `warmHeroHue` and asserting it folds). Otherwise it is ornamental.

### R7 — M1 "defined edge" is asserted, not shown; the live hero is full-bleed with NO rim

Live screenshot: the teal hero wash bleeds full-width to the sidebar with no concentric card
edge — confirming M1's premise but also that M1 is entirely unbuilt and unverified. The GOLDEN
cross-links it to "the page-background / hero-field wave; no new engine" without confirming that
wave gives the hero a *bounded* surface. If that wave keeps the hero full-bleed, M1's
"defined edge — the iOS-27 signature" has no home. Needs a concrete owner + a born-RED edge π
(assert a non-zero border-radius + a rim inset on the hero field rect), not a cross-link.

### R8 — Gray bento is a BA.W-NO-GRAY violation the GOLDEN under-files

The GOLDEN files the dead bento under defect-3 ("dead glyph stills" / liquid-weight). But the
live thumb is `rgba(0,0,0,0)` over a near-zero-chroma `oklab(0.763 0.005 0.011)` card — it

"calm/dead" motion gap. `BD.W-BENTO-SPECIMEN` should carry an explicit warm-cream-floor +
no-gray π on the preview card/thumb, not only a "specimen renders" assertion.

## Hardening (concrete, all UNION/REFINE — no re-invent)

1. **De-duplicate the hue source (R1).** Make `SECTION_COLOR_OKLCH` READ the CSS ramp at build
   (or generate both from one TS table consumed by a CSS-emit step) so there is genuinely ONE
   source. Then leg-(a) edits ONE place. Add `proof:no-dual-path`/`proof:color-acyclic`-style
   coverage asserting no second hue literal table exists for the section ramp.
2. **Drop the eyebrow from the "auto-track" claim (R2).** It's already warm-decoupled; say so.
3. **Own the switch motion through the DOCK seam, not tabs (R3+R4).** Either (a) book a real
   `BD.W-DOCK-TAB-INDICATOR` in dock-core that EXPORTS a reusable indicator primitive and have
   the shell consume THAT, or (b) drive the `<DockSection>` switch through the existing
   `DockLayerGroup` + `useDockOrientationMorph` seam. Do NOT import the SegmentedTabs-internal
   `useTabIndicator` into the dock — that's the bolt-on the GOLDEN forbids.
4. **Re-number and re-scope the born-RED gate (R5).** New clause **T6** (not T5) in
   `proof-teal-navy-purge.mjs`: extend the `[180,270]` source scan to
   `demo/stories/category-hero.ts`, `demo/stories/aurora-hero.ts` (incl. `SECTION_COLOR_OKLCH`),
   and the referenced `--section-color-N` CSS rows. Add a `--selftest` bite (a synthetic cool
   `sectionHue` reds it). Verify it is born-RED on the four current cool literals BEFORE the fix.
5. **Justify or delete leg-(b) (R6).** Keep `warmHeroHue` ONLY if the T6 gate's `--selftest`
   exercises it on a synthetic cool input; otherwise it's dead code.
6. **Give M1 a concrete edge owner + π (R7).** A born-RED hero-field-rim assertion
   (radius + inset > 0) wired to a named wave, not a cross-link.
7. **No-gray π on the bento (R8).** `BD.W-BENTO-SPECIMEN` asserts the preview card+thumb clear
   the warm-cream chroma floor (no `[180,270]` and no near-zero-chroma gray), both modes.

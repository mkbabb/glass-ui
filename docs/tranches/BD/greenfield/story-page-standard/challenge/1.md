## TOP REFUTATION — the five "zero-logic re-exports" are BROKEN as written: they drop the slot

§2a/§2b ships the sub-types as:

```ts
export const DemoStage = (p) => h(DemoFrame, { variant: "stage", ...p });
```

A bare functional component `(p) => h(...)` receives **props only**; `h(DemoFrame, {...})` with no third argument passes **no children/slots**. But the entire DemoFrame contract (§2a template) is `<slot/>` — "the ONLY per-page free content: the demo." So `<DemoStage><ButtonDemo/></DemoStage>` renders an **EMPTY stage** — the demo content is silently discarded. This is the exact class of "silent no-op binding" the user's own MEMORY warns about (`glass_ui_binding_verification`: stale bindings that vue-tsc + units miss, only e2e catches). There is **zero precedent** for this `=> h(Comp,{...p})` pattern in the codebase (grep `=> h(`: 0 hits in demo/stories or src/components) — it is invented, untested, and wrong.

**Hardening:** the re-exports must forward slots and attrs, or (KISS-better) NOT be functional re-exports at all. Either (a) thin SFCs `<template><DemoFrame variant="stage"><slot/></DemoFrame></template>`, or (b) drop the five names entirely and let pages write `<DemoFrame variant="stage">` directly (the variant string IS the fingerprint the gate's S1 already keys on; the five aliases buy nothing but a broken indirection). Option (b) is the most KISS and removes a whole net-new file (`index.ts`).

## REFUTATION 4 — the spike de-risks the WRONG bleed mechanism (cqw / container-type) — §2c is UNTESTED

§2c achieves the φ² stage bleed via:
```css
.demo-frame[data-variant="stage"][data-bleed] .demo-frame-frame {
  inline-size: var(--story-stage-w);
  margin-inline: calc(50% - 50cqw);   /* center-bleed past the prose column */
}
```
This needs a **container-query length context** (`cqw`) — i.e. an ancestor with `container-type: inline-size`. The spike does NOT use `cqw` at all: it sets `inline-size: var(--story-stage-w)` with `margin-inline: auto` (live: `marginLeft/Right = 0px`) on elements that are DIRECT CHILDREN of `.story-article`. The spike's stage is wide because article==stage==`--story-article-w`; it never bleeds PAST a narrower prose-bound parent. But the real DemoFrame nests the frame inside `StorySection` (a `flex flex-col` block) inside the prose-measure article — so §2c MUST bleed a child out past a constrained parent via `cqw`, a mechanism the spike never exercises. Worse: this codebase **removed `container-type` to fix dock-collapse** (per MEMORY `glassui_340_published`). Re-introducing a `container-type` ancestor for `cqw` risks reviving that collapse class. With no container, `50cqw` resolves against the small-viewport fallback, not the article — the bleed math silently mis-computes.

**Hardening:** re-spike the ACTUAL component tree (StorySection → frame nested in a prose-bound article) and prove the bleed there, OR abandon `cqw` for the spike's proven approach: hoist the stage variant OUT of the prose-measure wrapper (render stage cels as direct article children at `--story-stage-w`, prose cels at `--story-prose-measure`) so no negative-margin/cqw bleed is needed. The spike already proves THAT form; spec it.

## REFUTATION 5 — the field is MONOCHROME amber; the reference (and §3 binding law) demands a POLYCHROME field + a DEFINED EDGE

Live side-by-side: the SHIPPED `/substrates/aurora` hero (the golden's own cited "proof") is **polychrome** — purple→blue→amber painterly, with real hue variation across the plane and a crisp glass edge. The golden's spike field is a **single-hue amber wash** (`--field-h: 58`, all stops within h48–h92). Consequence: the glass cels have almost no transmit-delta to reveal — tone-on-tone amber rectangles melting into an amber ground, with a faint edge. The §3 binding law is "a COLORFUL FIELD behind glass **+ a defined edge**." The monochrome field starves the glass of something to bend and weakens the edge. It fled gray-glass and landed in monochrome-amber-glass. The S2 gate (`C ≥ 0.045 warm, H ∈ [25,95]`) actually ENFORCES monochromaticity (a narrow 70° hue band) — it would PASS the flat amber wash and FAIL a richer multi-hue warm field that strayed below H25 or above H95. The gate codifies the weakness.

**Hardening:** the field must carry intra-field hue VARIATION (a warm spread, e.g. amber→coral→gold, h35–h85 across stops) per route, matching the aurora reference's painterly polychrome. Loosen S2 from a single-hue band to "warm-DOMINANT with chroma variation" (assert a hue spread Δ ≥ 25° across sampled patches AND warm centroid), and ADD an S-edge assertion: the cel border must raster a contrast delta ≥ X against the field at its rim (the "defined edge" half of §3, currently unmeasured by any gate).

## R1 (TOP, lands) — the §9 spike is NON-REPRODUCIBLE and FAILS its own gate

GOLDEN §9 is the de-risk keystone: "fitDelta 0.000 — GREEN", "peak 1.163×", "the boldest
mechanism is proven sound BEFORE any src/ change." I ran the spike's OWN `window.__gate()`
live in Chrome **5 times**:

| run | overshoot | fitDelta | frames | shrink_PASS | ALL_PASS |
|---|---|---|---|---|---|
| 1 | 1.210 | 0.061 | 8 | **false** | **false** |
| 2 | 1.226 | 0.054 | 7 | true | true |
| 3 | 1.208 | **0.208** | 5 | **false** | **false** |
| 4 | 1.211 | **0.211** | 6 | **false** | **false** |
| 5 | 1.211 | 0.071 | 7 | **false** | **false** |

- **4 of 5 runs FAIL** `shrink_PASS` (`fitDelta < 0.06`). The single GREEN cited in §9
  is the *outlier*, not the norm. "fitDelta 0.000" was never reproduced — best live was
  0.054.
- **overshoot 1.21–1.23**, not the cited 1.163×, and ABOVE GOLDEN's own anti-taffy
  fence (§3 "area blob caps ≤1.12", §1 "1.16× total overshoot — strong but legible").
  The spike over-deforms past the golden-restraint bar it sets for itself.
- **5–8 frames captured** across a 700ms morph (~12–17ms/frame would be 40+ frames). The
  rAF sampler is racing the morph; the gate measures noise. A gate that reports
  `fitDelta` swinging 0.054→0.211 between identical runs is **measuring timer jitter, not
  the morph**, and is unfit as the §8 acceptance precedent it's offered as.

The flake root: `__gate` self-collides — prior runs' `releaseTimer` + the 3 flood
`setTimeout`s from the previous `select()` are still pending when the next gate's
`select(0)` reset + `select(3)` fire; the `--tab-blob`/`--stretch`/`--tab-flood-t` writes
interleave non-deterministically. The shipping `useTabIndicator` has the SAME structural
hazard (one `releaseTimer`, cleared but the flood/blob timers per GOLDEN §3c/§4 are
additional pending timers) — **rapid tab-switching will desync the blob release from the
glide**, the exact "grow-but-never-shrink RED" the §8 self-test names but the spike
itself trips.

**HARDENING:** (a) Re-run the spike gate ≥20× headless and report the DISTRIBUTION
(median + p95 fitDelta), not a cherry-picked single GREEN; require median `fitDelta < 0.04`
AND p95 `< 0.06` before claiming GREEN. (b) Make the sampler frame-dense (capture on a
fixed ~8ms cadence via `setInterval` in addition to rAF, or extend to ≥30 frames) so the
peak + shrink are actually resolved. (c) Bind the blob + flood + stretch releases to ONE
cancellable timer-set that a new `select()` flushes atomically (a single
`AbortController`-style guard), and add a §8 gate arm that fires `select()` 4× in 200ms
and asserts the indicator still lands `fitDelta < 0.06` — the rapid-switch desync case the
current gate never exercises. (d) Bring the spike's `STRETCH_PEAK 1.12` × `BLOB_PEAK 1.10`
down so live overshoot lands ≤1.16 (the cited bar), not 1.22.

## R2 (lands) — the live HEAD capsule paints GRAY; the warm-floor fix is asserted, not proven

GOLDEN §0 grades "Active = warm-glass capsule … never gray" as **REAL + WARM both modes**
and frames the no-gray fix as a TRACK concern. But I measured the LIVE `/navigation/tabs`
selected indicator's resolved paint over the real glass backdrop:

```
indicator background: oklab(0.793492 0.00516049 0.0116924 / 0.84)
  → chroma = √(0.0052² + 0.0117²) ≈ 0.0128
```

That is **BELOW the GOLDEN's own §8 `meanChroma ≥ 0.02` warm gate.** The *capsule itself*
— the lifted lozenge that is the whole "glassy gold standard" the user wants buttons to
emulate — reads **near-gray** on HEAD over a neutral panel (visually confirmed in the
screenshot: the "Grid" selected plate is a flat beige-gray slab, barely separable from the
track, no readable lift, no recess). The track measures warm (`srgb 0.994 0.960 0.926`),
so the GOLDEN's track-focused warm-floor narrative misdiagnoses where the gray lives: it's
the **`--glass-bg-floating-tinted` capsule fill**, not the quiet track, that desaturates.

The spike does NOT exercise this: it hardcodes warm `hsl(36 70% 98%)` for
`--glass-bg-floating`, bypassing the real `color-mix(in oklab, light-dark(...))` W55 seam
that actually paints gray. So the spike "GREEN both modes" proves a DIFFERENT material
than ships. The §8 gate's `meanChroma ≥ 0.02` arm is correctly specified — but as written
it would fire RED on the *capsule* too, and the GOLDEN's §2b "factored verbatim" extraction
**preserves the gray** because it copies the seam as-is. Extraction-of-a-gray-plate is
still gray.

**HARDENING:** (a) The §8 gate's chroma arm must scan the CAPSULE meanChroma, not only the
track — and the warm-admit floor (the small compose-toward-`--glass-tint-source`) must be
added to `.glass-capsule` itself, not only `.glass-capsule-track`. (b) Add a born-RED row:
"HEAD capsule meanChroma over the aurora field reads `< 0.02` → RED" — this makes the gray
capsule a NAMED defect the wave fixes, not a latent one it copies. (c) Paint-verify the
extracted `.glass-capsule` over the live aurora field BOTH modes with a real-cascade
spike, not the hardcoded-hsl spike — the de-risk is invalid until it exercises the actual
`light-dark()`/`color-mix(oklab)` seam.

## R3 (partial) — the "registered-scalar precedent" for `--tab-blob` is misattributed

GOLDEN §3b: "the `--stretch`/`--glass-accent`/`--specular` registered-scalar precedent
(verified). Registration lets the CSS glide INTERPOLATE it; a bare custom snaps." But on
disk **`--stretch` is NOT `@property`-registered** (`grep '@property --stretch'` → 0 hits;
only `--specular-x/y/intensity/angle`, `--glass-accent`, etc. are). `--stretch` works
*without* registration precisely because `useLiquidFlex` writes it imperatively per-frame
(no CSS interpolation needed). So the cited precedent is half-wrong, and worse: it implies
the blob will glide via CSS interpolation, but §3c ALSO drives `--tab-blob` imperatively
via the 2nd `useLiquidFlex` channel — so the `@property` registration may be **redundant**
(if JS writes every frame) OR the two mechanisms (registered CSS interpolation + imperative
JS writes) **fight** (double-driving one property). The GOLDEN never resolves which drives:
the CSS transition on `--ease-cartoon-punch` (§3b) or the `useLiquidFlex` hump (§3c).

**HARDENING:** State explicitly that `--tab-blob` is driven IMPERATIVELY by the 2nd
`useLiquidFlex` (matching `--stretch`), and the `@property` registration exists ONLY so the
*release* frame's discrete write doesn't snap-flicker — NOT so a CSS `transition` animates
it (remove `--tab-blob` from the §3b CSS `transition` list, or the JS writes and the CSS
transition will double-animate). Fix the §3b prose: `--stretch` is the *imperative* sibling
precedent, the @property-registered precedent is `--glass-accent`/`--progress`.

## R4 (minor, survives) — the underline fence is satisfiable but un-named

Gate #9 ("variant=underline reads a crisp SLIDE, zero area inflation") holds ONLY because
the underline `::before` writes `scale: var(--stretch) 1` (disk `:311`) — it does NOT
compose `--tab-blob`. GOLDEN §3b composes the blob into the `.segmented-indicator` scale,
which the underline pseudo does not share. So the fence is structurally sound — BUT the
GOLDEN never names this seam, and §3b's "compose `--tab-blob` into the ONE existing scale
write" is ambiguous: an implementer reading "one indicator grammar" (the disk comment at
`:294`) could naively add `--tab-blob` to the underline scale too, silently breaking gate #9.

**HARDENING:** Add one sentence to §3b: "`--tab-blob` is written ONLY on
`.segmented-indicator` (the pill slider); the underline `::before` keeps its
`scale: var(--stretch) 1` untouched — the blob is a pill-material channel, the underline is
paper-ink and never inflates." Cite disk `:311` as the fence line.

- **Born-RED material is REAL** — `--tab-blob`, `--motion-weight`, `--ease-cartoon-punch`,

  per-mode pair, matching the binding MEMORY lesson. The §8 self-test bites it RED. Correct.
- **Compositor-only / Chrome==Safari floor holds** — every channel is `scale`/`inset`/
  static `box-shadow`/`plus-lighter` opacity; NO `backdrop-filter:url`, NO SVG goo, NO

  spring cannot express) and peaks > 1.10 (overshoot past the spring fence). It IS the
  missing cartoon-punch the user wants, opt-in via `--motion-weight`, PRM→0 in one line.

  static recess+lift survive as legibility anchors; roving-tabindex untouched; ≥44px tap.

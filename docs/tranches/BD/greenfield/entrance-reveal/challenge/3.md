## TOP REFUTATION — the §2b BASE recipe CLOBBERS a centering transform (it violates its OWN §4 law)

The GOLDEN's §4 cross-engine law (lines 332–334) states, emphatically:

> "Use the `scale:`/`translate:` **LONGHANDS (not `transform:`)** so the recipe composes
> with a centering transform and mints no stacking context."

But the §2b BASE keyframe `gl-liquid-enter` (GOLDEN lines 181, 183) does exactly the
forbidden thing — it writes the squish leg as a `transform:` **shorthand**:

```css
0%   { … transform: scale(var(--lq-stretch-x,1.06), var(--lq-stretch-y,0.945)); … }
100% { … transform: scale(1,1); … }
```

**LIVE-PROVEN clobber** (ran on the spike page): a `div` with
`transform:translate(-50%,-50%)` (the standard centering of a Dialog/popover) under an
animation whose keyframe sets `transform:scale(1.06,0.945)` computes to
`matrix(1.06,0,0,0.945,0,0)` — **the centering translate is GONE** (e=0, f=0). Any centered
surface that opts into `.liquid-enter` snaps to the top-left corner for the whole entrance,
then jumps back. This is the EXACT failure `.glass-reveal` was hand-engineered to avoid (it
uses only `scale:`/`translate:` longhands). The GOLDEN re-introduces the bug it claims to have
designed out. The spike never caught it because the spike's cards are NOT centered (static
flex children) and the spike only runs `.is-cel` (whose `gl-cel-slam` keyframe ALSO uses
`transform:` — same latent trap on any centered `.is-cel` surface).

**Hardening:** the squish leg MUST ride the `scale:` longhand, composed with the bloom
scale, NOT a second `transform:`. Two clean options: (a) **fold the reciprocal squish into the
ONE `scale:` longhand** as an anisotropic value — `scale: calc(var(--lq-enter-scale)*var(--lq-stretch-x))
calc(var(--lq-enter-scale)*var(--lq-stretch-y))` (the CSS `scale` longhand accepts two values;
this is the iOS-grace bloom×squish product on a single compositor channel that does NOT touch
`transform`); (b) if a translateY rise is needed too, add it on the `translate:` longhand.
The cel-slam `gl-cel-slam` must be rewritten the same way: its `translateY(...) scale(...)`
splits into a `translate:` longhand + a `scale:` longhand. NO `transform:` shorthand anywhere
in either keyframe. Re-run the spike with a CENTERED card to prove the centering survives.

## REFUTATION 2 — `.scroll-build > *` is CLOBBERED, not "AUGMENTED" (prose ↔ code disagree)

§5 promises `.scroll-build`/`.scroll-cascade` are **"AUGMENT — mount-clock floor + view()
enhancement structure UNCHANGED."** §2b prose (line 244) says their keyframes "gain the squish
leg." But the §2b CODE BLOCK (line 185) instead binds a **whole new `animation:`** to the same
selector:

```css
.liquid-enter, .scroll-build > *, .scroll-cascade > * {
  animation: gl-liquid-enter …;            /* a NEW animation on .scroll-build > * */
}
```

`.scroll-build > *` **already** carries `animation: gl-page-build …` (verified at
`scroll-choreography.css:88`). Two `animation` shorthands on the same selector from two
partials do NOT compose — last-declared wins outright. So either `gl-page-build` (the existing
chrome→hero→body translateY build with its `--scroll-build-step` beat clock) is silently
destroyed, or `gl-liquid-enter` never fires, depending on `@import` order. This is a **clobber
masquerading as an augment** — the opposite of the §5 promise. It is also live-relevant:
`/display/buttons` already mounts **1 `.scroll-build` + 1 `.scroll-cascade`** wrapper (verified
via DOM query), so this lands on a real page on day one.

**Hardening:** honor the prose. Do NOT re-target `.scroll-build > *` with a new `animation`.
Instead **edit `gl-page-build`/`gl-cascade-build` in place** to add the reciprocal-squish leg
(on the `scale:` longhand, per Refutation 1) and the `var(--ease-cartoon-punch,…)` curve on the
opt-in `-cel` modifier. Bind `.liquid-enter` (the genuinely-new class) to `gl-liquid-enter`
ALONE; leave the two scroll selectors out of that rule entirely. The mount-clock floor stays
its own keyframe — that is what "UNCHANGED structure" means.

## REFUTATION 3 — the cartoon CAST is a WHISPER, not the "BOLD 1940s technicolor" the edict demands

§2c reuses `--shadow-cartoon` verbatim as the lagging cast and narrates it as "its **bold
technicolor shadow** catches up a beat behind." Source value (verified):
`3px 3px 0 0 color-mix(in srgb, foreground 8%, transparent)` (light) / **6%** (dark) — a
single 3px hard offset at 6–8% ink. That is a tasteful EDITORIAL offset, the right call for a
RESTING card edge — but as a *moving cartoon cast meant to read as PUNCH*, at 6–8% opacity and
one un-layered 3px stamp it is near-invisible in flight. The BINDING LAW calls for "**BOLD
layered-offset shadows** + FLOW & PUNCH … the 1940s technicolor register." The cast as specced
does not clear that bar — it is DRY-correct (reuse the token) but gestalt-weak. The user-as-
viewer will not perceive a "lagging cartoon cast"; they'll perceive a faint static drop-shadow
that was already on the card.

**Hardening:** the lagging cast needs its OWN bolder value for the cel register — either a
dedicated `--shadow-cartoon-cast` (e.g. a 2-layer `6px 6px 0 0 …18%` + a tint catch) that is
`--motion-weight`-scaled so it inks UP at weight 1 and vanishes at weight 0/PRM, or layer the
existing `-hover` over the base for the in-flight beat. Keep the static-paint discipline (the
child-layer transform moves, the box-shadow never animates) — only the *value* gets bolder for
the cel. Add a gate assert that the cast's painted ink at peak is materially > the resting card
shadow (a luminance-delta readback), so "the cast reads" is measured, not asserted.

  them and re-introduce the clobber).

## Survival ruling

The ARCHITECTURE survives (one grammar / three registers / one squish engine / hoisted
resolver / Band-0-gated cel-slam is the right shape, and the born-RED is real). The GOLDEN does
**not** survive as a verbatim-shippable recipe: the §2b/§2c code blocks would break centered
surfaces and clobber the `.scroll-build` floor, and the cartoon cast under-delivers the audacious
PUNCH. All four refutations are recipe-level and fixable without re-planning — fold the squish
onto the `scale:` longhand, edit the scroll keyframes in place, bolden the cast value for the
cel, and extend the spike to the base + centered + reduce + WebKit. Harden these and it is golden.

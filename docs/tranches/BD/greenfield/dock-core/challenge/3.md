# CHALLENGE 3 — DESIGN-FIDELITY / GESTALT lens (adversarial)

Verdict: **SURVIVES (qualified)** — the core mechanism (measure-once + clamped size) is
sound and the root-cause diagnosis is source-accurate, but **five real refutations land**
that must be hardened before build. The single strongest is the squish-channel collision
(`--stretch` is already multi-owned). Default was REFUTED; the mechanism earned partial
survival, the *gestalt/audacity* claims did not.

Lens: attack as a USER + against the edicts (no-gray, cartoon-punch, golden proportion,
liquid-weight, cross-engine, deft union, born-RED gate). Live-tested on `/dock/overview`
(warm-cream floor confirmed) + the GOLDEN's own `golden/morph-spike.html` (gate + squish
re-run in Chromium).

## R1 (STRONGEST) — the squish channel is NOT free: `--stretch` is already multi-owned → the channel-cross the GOLDEN claims to have killed is merely relocated

GOLDEN §1(c) routes the cartoon PUNCH through `--dock-squish × --motion-weight → --stretch`,
calling it "the EXISTING `--stretch` machinery... which the dock already imports." Live grep
of `src/` shows `--stretch` is written by **at least six concurrent JS owners**:
`useLiquidMorph.ts:300` (V↔H orientation morph), `useGooMorph.ts:308/328`,
`useDockFission.ts:407` (the split), `useTabIndicator.ts`, `useTabDragMorph.ts`,
`useDragMorph.ts`. `shape.css:127` already folds `--stretch × --dock-root-scale` on ONE
`scale:` property.

The GOLDEN explicitly says "the collapse/expand morph, the V↔H morph, AND the fission split
(the DRIVER motions) drive `--dock-squish`." But fission (`useDockFission`) and the V↔H morph
(`useLiquidMorph`) write `--stretch` **imperatively from JS, every frame**, while the new
collapse squish would write `--stretch` via the **CSS** `--dock-squish` path. When a
drag-past-threshold COMMITS a fission split mid-collapse (the GOLDEN's own A12 gesture), the
JS `el.style.setProperty("--stretch", ...)` and the CSS `--dock-squish`-derived `--stretch`
are the **same custom property** — last writer wins, they clobber. This is the exact
"boring channel can't be exciting, exciting channel can't be wrong" guarantee the GOLDEN
sells, *broken in the one case (fission-during-morph) the GOLDEN itself nominates.*

HARDENING: do NOT reuse `--stretch` for the collapse squish. Introduce a DISTINCT
`--dock-punch-stretch` (CSS-only, `@property`) and fold THREE factors on the one `scale:`:
`--dock-size-scale × --stretch × --dock-punch-stretch` (orientation/fission squish stays on
`--stretch`, owned by JS; the collapse cartoon-punch on `--dock-punch-stretch`, owned by CSS).
Make the gate assert that a fission split fired during a collapse leaves BOTH stretches
composing (no clobber) — born-RED on the shared-`--stretch` design.

## R2 — "ratio-FREE" is a misnomer; the real cure is "measure-ONCE", and the GOLDEN never gates measurement freshness → the SAME degenerate endpoint can recur

HEAD (`layers.css:130-140`, source-confirmed) is `--dock-root-scale =
max(ratio + (1-ratio)·t, 0.06)` where `ratio = from/to`. Algebraically this is
`lerp(ratio, 1, t)` — a convex blend identical in SHAPE to the GOLDEN's `--dock-live`
blend. The seizure (59→200→33→41 / 2452px) is NOT caused by the ratio *expression*; the
GOLDEN itself admits the cause is a "degenerate `--dock-root-morph-to` (12.96px/4.02px)" —
i.e. **a bad measurement**, not bad math. So "ratio-free" oversells: the fix is "measure the
expanded width ONCE, off the laid-out row, not per-swap via FLIP." The convex blend survives
essentially unchanged.

The danger this hides: a measure-ONCE `--dock-expanded-px` written by a `ResizeObserver` can
STILL be stale/degenerate if read before web-fonts settle, before async icon SVGs paint, on
a route swap that re-mounts the dock with `display:none`→0px, or when the dock mounts inside
a `content-visibility:auto`/collapsed parent (RO fires with 0). A `--dock-expanded-px: 0`
→ `--dock-size-scale = collapsed/0 = ∞` → the SAME detonation, now without the per-swap
re-measure that could self-correct. The GOLDEN deletes the floors (`max(...,0.06)`,
`morphMinFloorPx`) as "masking a bad measurement" but provides no freshness guard for the
single measurement everything now depends on.

HARDENING: gate `--dock-expanded-px` with a sane floor (`max(measured, --dock-collapsed-px)`)
AND re-measure on `fonts.ready` + on the FIRST non-zero RO callback + on visibility-enter.
Add a born-RED test: mount the dock hidden then reveal, assert no detonation frame. The
divisor `var(--dock-expanded-px, 240px)` in the spike hardcodes a `240px` fallback — an
overfit magic number (see R5).

## R3 — the audacity bar FAILS in the GOLDEN's OWN spike: the gate runs squish-ON and returns `widthMonotonic:false`; the anticipation dip is 0.6% (imperceptible); the painted punch is the shipped 16% squish

Live-ran `window.__runGate()` on `golden/morph-spike.html` in Chromium AS-SHIPPED:

```
{ expanded:268, widthMonotonic:false, maxBackstep:6.43, widthBounded:false, maxWidth:318.89 }
```

The spike hardcodes `:root{ --motion-weight:1 }` and the gate **never zeroes it**, so the
de-risk artifact, invoked as written, FAILS its own monotonic+bounded assertions. §7 narrates
this as "the diagnostic that validates the channel split" — but the boolean the function
returns is `false`. The "monotone + bounded by construction" claim in §7 is the OTHER
(3-point static) path, not what `__runGate` computes. A reviewer running the spike's named
gate sees RED and a paragraph explaining why RED is fine. That is a born-GREEN-rationalized
gate, the precise anti-pattern §6 swears off.

The anticipation (§6.3, "dips BELOW rest before blooming"): the punch curve's negative lobe
is `-0.038`, fed through `--s = 1 + 0.16·squish·weight` → `--s = 1 + 0.16·(-0.038) = 0.994`
— a **0.6% pinch**. Live capture: `squishMin: 1`, `squishDipsBelowRest: false` (the dip is
below rAF/quantization visibility). The painted scale pinned at `1.16 / 0.862` — i.e. the
overshoot tops out at **16%**, indistinguishable from the SHIPPED `--dock-morph-max-stretch:
1.14` orientation squish. The "AUDACIOUS 1940s cartoon punch" reduces, in paint, to a 16%
squish the dock already does — and a 0.6% anticipation no user perceives.

The static `golden/spike-expanded.png` (re-captured live) confirms the gestalt shortfall: a
**pastel, washed-out** field (faint pink / faint blue, low chroma — not an "audacious
colorful field with a defined edge"), a **barely-visible** cartoon cast (not "bold
layered-offset shadows"), tiny gray glyphs. This is the polite/medium register the directive
says to ELEVATE, presented as the proof of audacity.

HARDENING: (a) the spike's `__runGate` MUST set `--motion-weight:0` before the size sweep
and assert the overshoot in a SEPARATE squish-on pass — make the artifact do what §6.1/§6.2
say, or it is not a de-risk. (b) Raise the punch amplitude so anticipation is VISIBLE
(target ≥3% cross-axis pinch, ≥20% overshoot that is NOT clamped by the 1.14 cap — see R4),
and re-shoot the spike over a REAL high-chroma §3 field with a defined edge + a bold offset
cast, or the audacity precept is unmet.

## R4 — the 22%/16% punch overshoot collides with the shipped `--dock-morph-max-stretch: 1.14` cap; the GOLDEN never reconciles them

`density.css:69` ships `--dock-morph-max-stretch: 1.14` — `useLiquidFlex` caps the existing
`--stretch` squish at ~14%. The GOLDEN's `--ease-cartoon-punch` overshoots to **1.22 (22%)**
and the spike's squish formula is `1 + 0.16·squish` (**16%**). Both exceed 1.14. Two outcomes,
neither addressed: (a) if the punch rides the capped `--stretch` path, it is **clamped to
1.14** — the 22% audacity is silently throttled to the existing squish; (b) if the cap is
raised to admit 22%, the orientation/fission squish (tuned to 1.14) regresses to a bouncier
register that was deliberately "capped LOW" (`shape.css:102`). The GOLDEN's §3 table says
A11/A13 "share the re-tuned register" — that admits (b)'s regression without owning it.

HARDENING: with the dedicated `--dock-punch-stretch` (R1), the collapse punch is NOT subject
to `--dock-morph-max-stretch` and can carry the full audacious amplitude while
orientation/fission keep their 1.14 cap. State this explicitly. Add a gate asserting the
orientation-morph squish peak is UNCHANGED from HEAD (anti-regress on the shared cap).

## Net

The mechanism's CORRECTNESS leg survives (measure-once + clamped convex blend is bulletproof
and the diagnosis is real). The AUDACITY/GESTALT leg does NOT survive the lens: the de-risk
spike fails its own gate as-shipped (R3), the punch is throttled by an unreconciled cap (R4),
the anticipation is imperceptible (R3), the proof image is pastel/polite (R3), the squish
channel collides with six existing `--stretch` owners (R1), and the named born-RED gate does
not exist yet (R5). Harden R1–R5 — chiefly the dedicated `--dock-punch-stretch` channel and a
spike/gate that actually runs squish-off for size + a VISIBLE punch over a real high-chroma
field — and the golden becomes fit. Until then the gestalt bar (not the metric) is unmet.

## REFUTATION 1 (TOP — KILL) — §L7 is the headline edict and the gate proves NONE of it; the one cross-engine fact it states is mis-rationalized and contradicted by the live tree the GOLDEN claims it audited

§L7 "The Cross-Engine Floor" is edict #5, the entire reason this challenge lens exists, and
its acceptance proof is asserted to be "a **paired-engine π capture** (Chromium AND WebKit),
never a single-engine green." Yet:

1. **`gate.sh` contains ZERO cross-engine assertions.** `grep -c
   "WebKit\|Safari\|sRGB\|engine\|backdrop\|goo\|metaball\|linear()" gate.sh` → **0**. The
   born-RED gate validates §L4/§L6 prose-string presence and nothing about §L7. The
   single boldest edict for THIS lens has no born-RED proof at all — it is asserted, not
   gated. By the GOLDEN's own §5 standard ("a precept's spec is incomplete if it ships a
   motion or goo mechanism without naming its §L7 arm… the acceptance proof is a paired-engine
   π capture") the §L7 spec is itself incomplete: it ships a rule with no test.

2. **The prototype is single-engine.** `cartoon-punch-verified.png` is a 2880×1612 RGB
   capture from ONE engine (the de-risk doc §7 says "Verified live on localhost"). §L7's own
   law demands paired Chromium+WebKit. The keystone spike violates the keystone precept's
   acceptance bar. There is no WebKit capture of the cartoon curve, and `linear()` easing +
   `color-mix()` in keyframes have real historical WebKit version-skew — exactly the class
   §L7 exists to catch — so "compositor-safe on both engines" is an untested assertion.

3. **The stated sRGB rationale is BACKWARDS vs the live tree.** §L7 says: *"sRGB is mandatory
   (WebKit defaults to linearRGB and blows the threshold edge → halo/gray seam)."* But the
   live code the GOLDEN cites as proof says the opposite: `WatercolorDot.vue:150-153` —
   *"Safari renders SVG filters in sRGB **regardless of** `color-interpolation-filters` (a
   known WebKit limitation)."* So WebKit does NOT "default to linearRGB"; it **forces sRGB**.
   The goo `sRGB` declaration is correct as a *prescription* (it matches what Safari will do
   anyway, and avoids the linearRGB-lighten mismatch the goo-filter README calls "bug
   136418"), but the GOLDEN's stated MECHANISM ("WebKit defaults to linearRGB") is a factual
   inversion. A precept that mis-states the engine behavior it legislates is the exact "cites
   substrate it didn't read" failure §1 was supposed to have eliminated — §1 fixed the
   composable phantoms but introduced a fresh engine-behavior phantom in §L7.

This is a KILL because §L7 is *this lens's* whole subject, it is asserted with no gate, the
de-risk artifact is single-engine, and its load-bearing technical claim is provably inverted
against the codebase the GOLDEN swears it read at HEAD.

**HARDENING:** (a) Extend `gate.sh` (or add `gate-engine.mjs`) with a paired-engine live-π
arm: Playwright Chromium + WebKit both load a goo test surface and a `--ease-cartoon-punch`
surface; assert (i) the merged waist alpha-edge is within ΔE tolerance across engines, (ii)
the cartoon-punch translateY series shows the sub-zero dip in BOTH engines. Born-RED today
(no DESIGN.md curve, no §L7 fixture). (b) Rewrite the §L7 sRGB clause to the *correct*
mechanism: "WebKit renders SVG filter compositing in sRGB regardless of the attribute (the
`color-interpolation-filters` no-op, the WatercolorDot note); declare `sRGB` so Chrome/FF
match Safari's forced-sRGB neck rather than diverging into linearRGB-lighten (the goo-filter
README's bug-136418 mismatch)." Cite `WatercolorDot.vue` + `goo-filter/README.md` as the
source of truth, not an invented "WebKit defaults to linearRGB."

## REFUTATION 2 (LANDS) — §L7 "NEVER `backdrop-filter: url()`" is a flat falsehood about the live tree; the real glass refraction SHIPS it `@supports`-gated, so the absolute prohibition is a legacy-creating over-claim

§L7 Forbidden: *"`backdrop-filter: url(#goo)` — NEVER; WebKit drops an SVG-filter reference
through `backdrop-filter`."* But the live glass-refraction path **uses exactly this**:

- `useGlassRenderer.ts:203` — `el.style.backdropFilter = url(#${id}) blur(...) saturate(1.6)
  brightness(1.05)` + the `-webkit-` mirror on the next line.
- `glass-refract.css:106` + `surfaces.css:311` — `@supports (backdrop-filter: url(#…))`-gated,
  with an un-gated blur base for non-supporting (WebKit) engines.

So the real architecture is **`@supports`-gated `backdrop-filter:url()` for the Chromium
refraction lens, with a graceful WebKit blur fallback** — a nuanced, legitimate, shipped
pattern. The GOLDEN flattens this into an absolute "NEVER," which would either (a) force a
delete of the live glass-refract refraction lens (a real visual capability regression on
Chrome), or (b) immediately make the live tree non-conformant to its own brand-new precept —
i.e. born-LEGACY on day one, the exact "NO LEGACY EVER" sin. The prohibition conflates two
different things: `backdrop-filter:url()` for the **goo merge** (genuinely forbidden — WebkKit
bug 245510) vs for the **Chromium-only refraction enhancement** (legitimately `@supports`-gated).

**HARDENING:** Split the §L7 rule. Forbidden: "`backdrop-filter: url(#goo)` as the metaball
merge mechanism (the goo is a regular `filter` on the surface's own layer; WebKit bug 245510)."
Sanctioned-with-fence: "`@supports (backdrop-filter: url(#…))`-gated refraction enhancements
(the `glass-refract` lens) are permitted IFF they ship an un-gated blur base that is the
WebKit floor — the enhancement is a Chromium bonus, never the legibility-load-bearing layer."
This makes the live `useGlassRenderer`/`glass-refract` path conformant instead of instant-legacy.

## REFUTATION 4 (LANDS, PARTIAL) — `--motion-weight` is presented as a one-line PRM cascade but no such cascade exists; the live `--dock-stagger-step` is a sibling, not the named `--stagger-step`, and the "co-scales four channels" mechanism is unspecified hand-waving

§2e: *"PRM → `--motion-weight: 0` (the §L5 cascade zeroes the extra squash, overshoot,
anticipation, arc, and stagger in one assignment)."* This presumes every one of those five
channels is authored as `calc(... * var(--motion-weight))`. None are: `--motion-weight` is ∅
in `src/` (correctly forward-ref), but the claim that one assignment "zeroes" five
independently-authored channels is an unproven architectural promise — CSS does not propagate
a scalar into five pre-existing engines (`useLiquidFlex` squish, spring overshoot,
`--ease-cartoon-punch` dip, `--split-*` arc, `--dock-stagger-step`) unless each was rewritten
to read it. The live stagger token is `--dock-stagger-step` (`shell.css:53` = 0.08),
**dock-scoped**, not the global `--stagger-step` the GOLDEN names; folding a dock-local beat
into a universal motion-weight cascade is a non-trivial refactor sold as a "one assignment."

**HARDENING:** Demote the cascade claim to a spec obligation, not a free property: "each of
the five channels MUST be authored `calc(base * var(--motion-weight))` at its token home so the
PRM zero propagates; the encoding waves (`BE.W-ANTICIPATE-FOLLOW` et al.) own the rewrite. The
live `--dock-stagger-step` is renamed/derived from the global `--stagger-step` (NO LEGACY: one
token, dock reads the global) — flag the rename as a breaking token change." Add a born-RED
gate line: `grep` that every cartoon/squish channel multiplies by `--motion-weight`.

## REFUTATION 5 (MINOR) — naive-ellipsoid mandate is asserted, never gated; "real metaball waist" has no measurable acceptance criterion

§L7 forbids "Naive ellipsoid 'blob' tweens masquerading as metaballs." The live goo
(`DockGooFilter`/`GlassGooFilter`/`PagerDots`, all `feGaussianBlur`+`feColorMatrix` threshold)
IS a real metaball — granted. But the precept gives no *measurable* line between a real waist
and a naive ellipsoid, so "real metaball" is unfalsifiable prose. An encoder could ship two
`feGaussianBlur` circles that never actually fuse (blur too low / threshold too steep → no
neck) and pass every string-grep gate.

**HARDENING:** Add a born-RED waist metric to the engine-π arm: at the merge midpoint, the
alpha-channel cross-section between the two centers must stay above the threshold for ≥ N px
(a connected neck), measured in BOTH engines — RED if the two shapes are alpha-disconnected at
any merge frame (the naive-ellipsoid signature). That converts "real metaball" from prose into
a pixel assertion.

## VERDICT

strong, and the cartoon-punch anticipation spike is real. But the precept this lens exists to
test — §L7, the Cross-Engine Floor — is the weakest section: it has ZERO gate coverage, its
de-risk artifact is single-engine, its load-bearing sRGB rationale is **inverted** against the
very tree it claims to have audited (WatercolorDot proves WebKit forces sRGB, not defaults to
linearRGB), and its "NEVER `backdrop-filter:url()`" absolute is falsified by the live
`@supports`-gated glass-refract path — making the live tree born-legacy against its own new
precept. Plus §2f re-commits the §1 phantom-citation sin with `<CartoonCard>`. These are not
polish items; the cross-engine edict is asserted, not proven, exactly where this lens looks.

**Top refutation:** §L7 (the headline cross-engine precept) has no born-RED gate, a
single-engine de-risk artifact, an inverted sRGB rationale (WatercolorDot proves WebKit forces
sRGB regardless of the attribute), and a "NEVER backdrop-filter:url()" prohibition the live
`@supports`-gated glass-refract path already violates.

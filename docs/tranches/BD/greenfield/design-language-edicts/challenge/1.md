## REFUTATION 1 (LANDED — the top refutation) — §2g √φ radius ladder is arithmetically false AND self-failing its own §L6 gate

This is the one that lands. §2g asserts the live radii "mostly already sit on or
near the [√φ] ladder, so this is a *derivation re-statement … not a visual break*."
**Both halves are false.**

**(a) The derivation column is wrong arithmetic.** The GOLDEN's §2g table:
```
--radius-xl   | base·φ·√φ | ~10px → 12px (holds)
--radius-2xl  | base·φ²   | ~13px → 16px (holds)
```
Actual: with base=4, `4·φ·√φ = 8.23` (not ~10), `4·φ² = 10.47` (not ~13).
The "≈" values in the spec are fabricated to look close to the live 12/16.

**(b) The live values are NOT on any √φ or φ ladder.** Live (from
`src/styles/theme/radius.css` + `DESIGN.md:306`): `4, 6, 8, 12, 16`.
- 8→12 ratio = **1.5**; 12→16 ratio = **1.333**. Neither is √φ (1.272) nor φ (1.618).
- A true √φ ladder from base 4 is `4, 5.09, 6.47, 8.23, 10.47, 13.3` — so 12 and 16
  are OFF it by ~15-20%. The claim "live values mostly already on it" is false.

**(c) It fails the GOLDEN's OWN selection rule.** §L6 (2g) says: *"a non-φ value
that is not a documented physical constant … is a defect the overfitting audit
flags."* By that rule, shipping `--radius-xl: 12px` and `--radius-2xl: 16px` under a
"√φ ladder" banner ships TWO self-flagged defects. The precept indicts itself.

**(d) Bonus drift:** `radius.css:16` ships `--radius: 0.625rem` (10px); `DESIGN.md`
AND the GOLDEN both say `--radius: 0.5rem` (8px). The GOLDEN read the stale DESIGN.md
value, not the live token — the very sin §1 was created to prevent.

**Why it matters to MY lens:** "name a √φ ladder, then hold arbitrary px under it" is
exactly the overfit/hardcoded-ref defect. It is also a KISS violation: a proportion
PRECEPT that doesn't actually proportion is worse than no precept — it's a lie a
future wave will cite as license to keep magic numbers.

### HARDENING 1
Pick ONE honestly, do not fake "holds":
- **Option A (true ladder, accept the visual break):** re-derive to the real √φ
  rungs `4, 5, 6, 8, 10, 13` (round each `4·√φ^n`), and DELETE the "(holds)"
  language. State plainly that `--radius-xl` 12→ **10** and `--radius-2xl` 16→ **13**
  is a real value change (NO LEGACY: the old px are retired). This is the
  precept-honest move and matches the "survival of the fittest — re-invent what's
  broken" law.
- **Option B (honest hybrid):** keep the live 4/6/8/12/16 but rename §L6's claim from
  "√φ ladder" to "**φ-FAMILY-anchored, optically tuned**": base + √φ region for the
  small rungs, with 12/16 declared as documented optical/hit-target anchors (the same
  carve-out §L6 already grants the 1px hairline). Then the values stop being
  self-flagged defects because they're documented constants.
Either way: fix the §2g derivation column to TRUE arithmetic, and fix `--radius` to
the live `0.625rem`.

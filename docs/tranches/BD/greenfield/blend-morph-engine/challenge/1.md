## R2 — the §1.1 keystone bets the DRIVE half on a NON-EXISTENT file while a FIT, shipped drive is ignored — a bolt-on of the composition law, not a union (the deepest deft-integration crack)

This is the refutation that bites hardest on the "DEFT INTEGRATION — a UNION, never a bolt-on; keep
what is FIT" binding law. §1.1 declares the DRIVE atom is `useElementMorph` (the dock-hub

`assert(exists('useElementMorph')) || BLOCK`. **But the drive the dock collapse/expand/V↔H actually

- `useLayerTransition.ts` (AX.W01) is *literally* a DRIVE atom by the GOLDEN's own §0-finding-3

  single-clock authority, already cross-engine, already consumed.

So the GOLDEN's keystone has it backwards: it names the drive as a sibling file **that does not exist**
and makes the engine BLOCK on it, while the **fit, shipped, single-clock dock drive is invisible to the
design** (0 mentions). That is the opposite of "Survival of the fittest: keep what is FIT." Two real
hazards follow:

1. **A bolt-on dependency.** The composition law (§1.1, "the move that prevents an eighth fork") rests
   entirely on `useElementMorph`. If `W-DOCK-HUB-API` slips at execution, the engine BLOCKS — but the

   shipped file already does. KISS/DRY says: COMPOSE the extant `--dock-morph-t` drive
   (`useLayerTransition`) for the dock signatures; reserve `useElementMorph` for the genuinely-new
   *arbitrary-rect element→element* travel (`silhouette:'capture'`, `inwardMerge`) it is actually for.
2. **The "eighth fork" risk is mis-located.** The GOLDEN frets that folding the drive into the WELD
   would mint an 8th fork — but the live 8th/9th/10th/11th forks (`useDragMorph`, `useTabDragMorph`,

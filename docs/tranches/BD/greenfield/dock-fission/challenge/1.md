> "`--dock-bridge-goo-filter` is **set NOWHERE** in `src/`/`demo/` (grep: 0 hits) → the V↔H
> 'Liquid teardrop' always resolves to `none`" (§0.2, §2.2, §5, §7).

```
demo/stories/dock/morph-showcase.vue:277   :style="{ '--dock-bridge-goo-filter': gooFilter }"
demo/stories/dock/morph-showcase.vue:79-80  gooFilter = morph.t>0.18 && morph.t<0.82 ? "url(#dock-morph-goo)" : "none"
demo/layout/AppShell.vue:488                :style="{ '--dock-bridge-goo-filter': morphGooFilter }"
demo/layout/AppShell.vue:118-120            morphGooFilter = ... ? "url(#shell-dock-morph-goo)" : ...
```

The token IS assigned in BOTH consuming surfaces, gated to the morph window. On
`/dock/morph-showcase`, during the morph (`t∈(0.18,0.82)`) the bridge-goo resolves to
`url(#dock-morph-goo)` — **NOT `none`**. So the gate `gooFilter(morphBridge) !== 'none' at the
peak` would **PASS on HEAD** at the showcase. It is **NOT born-RED there.** The "one-token fix"
the GOLDEN proposes (set the token in `morph-bridge.css` under `[data-morphing]`) is real per the
CSS default (`morph-bridge.css:60` is `var(--dock-bridge-goo-filter, none)`), but the *premise*
that the V↔H teardrop "always resolves to none" is a CSS-default read that ignores the consumer
binding that already overrides it. The dead-wire is dead only when consumed WITHOUT a binding —
which neither shipped consumer does.

Why it matters: the gate sketch (§7) and G5/G6 cite the morph dead-wire as a born-RED arm. If
the gate is run on `/dock/morph-showcase` (the GOLDEN's own named live-test target,
§7/§title) it is **GREEN on HEAD** → a false-RED claim → the cardinal "live-verify inflation"
lesson. **HARDENING: drop the "set NOWHERE / always none" claim. Re-scope the morph fix to the
ACTUAL defect (see R2 — the wrong graph), and re-ground the born-RED arm on a surface that truly

## R3 — THE `inset()` NECK ATTRIBUTION IS HALF-WRONG (the headline fix targets the wrong selector)

The GOLDEN claims (§0.1, §2.1, §5, §9) that **BOTH** `.dock-fission-neck` AND
`.dock-fission-piece::before` carve the throat with `clip-path: inset(var(--neck-inset) 0 …)`:

> "Both the spanning `.dock-fission-neck` (`fission-bridge.css:462`) AND the per-seam
> `.dock-fission-piece::before` (`:462`) carve the throat with `clip-path: inset(…)`" (§0.1).

Source on HEAD refutes the spanning-neck half:
- `.dock-fission-piece::before` (`:462`) — TRUE: `clip-path: inset(var(--neck-inset) 0 var(--neck-inset) 0 round 999px)`. Constant cross-section. Correctly diagnosed.
- `.dock-fission-neck` (`:172-214`) — **uses NO `clip-path` at all.** Its only `inset` is
  `inset: 50%` (a *positioning* shorthand, not the clip-path function). It thins via
  `scale: ... calc(1 - 0.55 * clamp(0, var(--neck-len), 1))` — a uniform `scaleY` capsule with
  `border-radius: 999px`. The `:462` line number is the `::before` block, NOT the neck block.

The *substance* survives — both shapes are constant-cross-section convex capsules with no
concavity, so the no-local-minimum diagnosis holds for both. But the GOLDEN's edit instruction
("REPLACE its uniform `scaleY` thinning + ADD a clip-path" — §2.1) for `.dock-fission-neck` is
the right action, while its claim that the neck "carves with `inset()`" and its
`fission-bridge.css:462` citation are wrong for that selector. An executor following the cited
line will edit the `::before`, not the spanning neck. **HARDENING: correct the citation — the
spanning `.dock-fission-neck` (`:172`) thins via `scale:`/`border-radius`, NOT `clip-path:
inset()`; the `inset()` constant-pinch lives ONLY on `.dock-fission-piece::before` (`:434-462`).
The fix adds a clip-path to the FORMER and replaces the inset on the LATTER — two distinct
selectors, one wrong line number.**

## R4 — THE SPIKE'S `hasLocalMinimum`/`waistRatio` ARE NOT PIXEL-MEASURED — they are MODELED

The §8 de-risk table is presented as "verified live … the π readback" with a `peak-waist.png`
screenshot as "authoritative pixel evidence." But the spike's `measure()`
(`dock-fission-barbell.html:192-207`) does NOT read the canvas:

```js
const throat = dockThick * d.neckGirth * 0.34;        // an ANALYTIC formula, not a readback
const bodyGirth = dockThick;
const ratio = throat / bodyGirth;                      // 0.34 baked in → waist/body is DEFINED, not measured
const hasLocalMinimum = d.islandScale > 0.2 && d.neckGirth < 0.95;  // a boolean of the DRIVE scalars
```

`waistRatio` is `neckGirth · 0.34` by construction (the 0.34 is the hourglass waist-fraction
ASSUMED, not measured from the filtered alpha). `hasLocalMinimum` is a predicate over the input
scalars (`islandScale`, `neckGirth`), never a `getImageData` cross-axis scan of the FUSED goo
output. So the table proves the *model* is self-consistent — it does NOT prove the
blur→threshold actually yields a local-minimum in painted pixels. The screenshot DOES show a
real concave waist (the visual is genuine and persuasive), but the §8 numeric "π readback" is a
restatement of the drive curve, not a measurement of the render. The §7 born-RED gate, by
contrast, correctly demands a `canvas-readback of the warm alpha band` — so the gate is sound;
the **spike's claim to have already π-measured it is overstated.** **HARDENING: either (a) add a
real `getImageData` cross-axis scan to the spike's `measure()` so the de-risk table is an actual
pixel readback (closing the gap between §8 and §7), or (b) downgrade §8's language from "the π
readback" to "the drive model + the painted screenshot" and let the §7 gate be the first true
pixel measurement. Do not let §8 stand as pixel-proof of the local-minimum.**

## R5 — `waistRatio ≤ 0.45` GATE vs SPIKE 0.31: the gate is loose enough to pass a non-hourglass

The gate is `waistRatio ≤ 0.45`; the spike reports 0.31 at peak. But because `waistRatio =
neckGirth · 0.34` (R4), even the SHIPPED `inset()` neck — if its `--neck-inset` thins to a
similar residual — could produce a cross-axis minimum band ≤ 0.45 once blurred, since a thinned
capsule's blurred alpha ALSO dips relative to the two end masses. The discriminator that actually
separates an hourglass from a constant-pinch capsule is **`hasLocalMinimum` along the FUSED
silhouette**, not the ratio. The gate leans on `hasLocalMinimum`, but that predicate (per R4) is
not yet a real readback. So the born-RED claim "the shipped `inset()` → MONOTONE convex → no
local minimum" (§7) is plausible but UNPROVEN against pixels — a thinned-enough `inset()` capsule
blurred at stdDev 10 can read a shallow waist too. **HARDENING: make `hasLocalMinimum` a true
second-derivative test on the canvas cross-axis profile (sign change, not `girth<0.95`), and add
a born-RED CONTROL: capture the SHIPPED `inset()` neck under the SAME filter and show it FAILS
`hasLocalMinimum` — without that paired control the born-RED is asserted, not demonstrated.**

# CHALLENGE 3 — DESIGN-FIDELITY / GESTALT lens vs the DOCK FISSION GOLDEN

Verdict default: REFUTED. The headline geometry fix is sound and source-grounded, but TWO of
the three named root causes are FALSE on HEAD, the §8 de-risk spike PROVES NOTHING it claims to
(the π table is a tautology, not a pixel readback), and several load-bearing reuse anchors are
PHANTOM. The gestalt thesis survives; the *diagnosis*, the *born-RED gate*, and the *deftness*
claims do not. Net: SURVIVES WOUNDED — the design idea is right, the spec around it must be
hardened before it can be trusted as a build contract.

Everything below is source-grounded (file:line) or live-verified on `localhost:5173`.

## R1 (THE KILL SHOT) — the "dead morph-goo wire" is NOT dead. Born-RED arm + a whole file-change are FICTION.

GOLDEN §0.2 / §2.2 / §5 / §7 assert, as a headline root cause and a born-RED gate arm:
> "`--dock-bridge-goo-filter` is **set NOWHERE** in `src/`/`demo/` (grep: 0 hits) → the V↔H
> 'Liquid teardrop' always resolves to `none`." … gate: `assert gooFilter(morphBridge) !== 'none'`.

**This is FALSE.** The token is wired in BOTH live consumers, gated to the occlusion midpoint

  where `morphGooFilter = morph.t > 0.18 && morph.t < 0.82 ? "url(#shell-dock-morph-goo)" : "none"` (`:118-122`).

So on `/dock/morph-showcase` mid-morph (the exact page + window the born-RED gate samples) the
filter is ALREADY `url(#dock-morph-goo)`, NOT `none`. The gate arm
`gooFilter(morphBridge) !== 'none' at the peak` is **born-GREEN**, not born-RED. The "one-token
fix" + the `morph-bridge.css` row in the §5 file table + the §9 "FIXES the dead wire" bullet are
all NO-OPS — there is no dead wire to fix. The grep was run wrong (or against a stale tree); the
token is two-sited and idiomatically gated.

**Severity: the whole "two convergent dead-wire/shape defects" framing collapses to one.** A
challenger is supposed to default REFUTED, and here the strongest single claim of the diagnosis

**Hardening:** DELETE the dead-wire root cause, the `morph-bridge.css` file row, the §9
dead-wire bullet, and the `gooFilter(morphBridge)` born-RED arm. IF the spec wants to improve the
V↔H goo, the real defect is different and named in R2 — re-scope to that.

## R2 — the V↔H "fuse a waist at the midpoint" promise FIGHTS a binding platform limit the shipped page already respects.

GOLDEN §2.2: wiring the goo "so the V↔H 'Liquid teardrop' actually **fuses a waist at the
midpoint** instead of crossfading two plates."

The shipped `/dock/morph-showcase` page copy (live-read this session) states the binding reality:
> "The shipped morph is a View-Transitions crossfade… The topology reflow (column → row) is
> hidden inside the crossfade — **the platform cannot continuously interpolate a
> mismatched-topology silhouette (a binding platform limit)**; the showcase respects that limit."

And `morph-bridge.css:153` documents the goo bridge only paints in a narrow mid-window
("endpoints, the goo teardrop never paints"). The goo is a **jump-cut concealer over an occluded
topology swap**, NOT a continuous metaball that necks a waist between two persistent bodies. A
V→H dock is a column→row REFLOW: there are not two persistent masses with a throat between them —
there is one plate being crossfaded into a differently-shaped plate. The fission topology
(plate + travelling bud + spanning neck) does NOT exist in the V↔H morph case. The GOLDEN
conflates two different mechanisms (fission = bud-off; morph = topology crossfade) and promises a
fission-grade waist where the platform forbids one.

**Hardening:** Drop the "fuses a waist" language for the morph case. Scope the morph-goo retune
to "a slightly gooier crossfade conceal in the existing 0.18–0.82 window" — an aesthetic dial on
an existing mechanism, not a new waist. The waist claim is ONLY honest for the *fission* (bud-off)
path, never the *morph* (reflow) path. Keep `/dock/morph-showcase` as a goo-tune target, not a
waist target.

## R3 — the §8 "de-risk spike" π table is a TAUTOLOGY, not a pixel readback. The "painted-pixel evidence" claim is overstated.

GOLDEN §7/§8 lean on the spike as "painted pixel evidence… waist/body 0.31 at the peak,
π-measured via canvas-readback of the warm alpha band." **The spike does NO canvas readback.**
`dock-fission-barbell.html:196`:
```js
const throat = dockThick * d.neckGirth * 0.34;   // ANALYTIC restatement of the inputs
```
`measure()` re-runs `paint()` and computes `throat` from the SAME `neckGirth` it just set, times
the constant `0.34`. `waistRatio = throat / dockThick` is therefore `neckGirth * 0.34`
deterministically — it can never exceed `0.34` regardless of what the filter actually paints.
`hasLocalMinimum = islandScale > 0.2 && neckGirth < 0.95` is true by construction for any
mid-slider value. There is **no `getContext`, no `getImageData`, no `getComputedStyle`** in the
file (verified: 0 hits). The "π readback" is a closed-form echo of the slider, not a measurement
of the rendered silhouette.

So §8's table proves the *parameter design* is internally consistent — it proves NOTHING about
whether the static `#dock-fission-goo` filter, applied to a clip-path hourglass + a scaleY bell,
actually thresholds to a concave waist in painted pixels on either engine. The only real evidence
is `peak-waist.png` — a SINGLE Chrome screenshot, no Safari, no readback. The §3 claim "de-risked
live in the spike (waist/body 0.31 in painted pixels)" is **not supported by the spike's own
code**; the number 0.31 is `0.906 * 0.34`, an arithmetic identity.

**Hardening:** EITHER (a) make the spike actually read pixels — draw the goo layer to a canvas
(html2canvas or an SVG-rasterize path), `getImageData` the warm-alpha band along the travel axis,
and report the *measured* min-cross-section / body ratio — OR (b) demote §8 from "de-risk proof"
to "parameter sketch + one Chrome screenshot" and move the burden of the waist-is-real proof to
the born-RED gate (§7), which MUST canvas-read the live component. The screenshot does look like a
real concave waist — so the design likely holds — but the spec must not cite a tautology as
cross-engine de-risk. And §8's "the boldest cross-engine mechanism is proven" with zero Safari
capture is exactly the single-engine-green the binding law forbids.

## R4 — the headline "BOTH necks carve `inset()`" claim is HALF FALSE; the load-bearing fix targets a neck that may not even be the one on screen.

GOLDEN §0.1 / §2.1: "Both the spanning `.dock-fission-neck` (`fission-bridge.css:462`) AND the
per-seam `.dock-fission-piece::before` (`:462`) carve the throat with `clip-path: inset(...)`."

  var(--neck-inset) 0 round 999px)` at `:462`. Constant-cross-section pinch — refutation valid HERE.
- `.dock-fission-neck` (`:172-216`, the one actually mounted: `GlassDock.vue:659`
  `<div class="dock-fission-neck">`) — **carries NO `clip-path` at all.** It thins via
  `scale: … calc(1 - 0.55 * clamp(0, neck-len, 1))` (`:204`) — a uniform `scaleY` squash on a
  `border-radius:999px` capsule. So the spanning neck is a constant-cross-section *capsule*, not
  an `inset()` capsule. The "both carve `inset()` at `:462`" citation is wrong for the spanning
  neck and double-cites a single line number for two different blocks.

The refutation's *spirit* survives (neither neck has a structural concavity), but the headline's
precision does not — and that matters, because §6 G1 says born-RED on "the shipped `inset()`
neck." If the gallery actually renders the *spanning* `.dock-fission-neck` (it does — that's the
mounted div) then born-RED must be proven against the *scaleY capsule*, not the `inset()` filament.
A gate that asserts RED against the wrong neck silhouette could pass spuriously.

**Hardening:** Fix the citation: the spanning `.dock-fission-neck` thins by `scale` (`:204`), the
per-piece `::before` by `inset()` (`:462`). State the defect once, generally: "NEITHER neck has a
structural concavity — one is a scaleY capsule, one is an inset capsule; both, blurred+thresholded,
yield a fatter rounded capsule, never a waist." Then born-RED against the silhouette of the neck
that PAINTS on each surface (spanning on the gallery split; per-piece on the n>2 burst).

## R5 — PHANTOM reuse anchors: `--motion-weight` and `--ease-cartoon-punch` do not exist in `src/`. The "DEFT UNION / reuse extant idiom" claim is partly fabricated.

The GOLDEN repeatedly grounds its deftness on reusing shipped idioms:
- "`--dock-goo-weight` (= the **Band-0 `--motion-weight` idiom**)" — §1, §2.3 (twice), §9.
  **`grep -rn motion-weight src/` → ZERO hits.** There is no `--motion-weight` token/idiom to
  alias. The reuse anchor is invented.
- "a `--ease-cartoon-punch` pre-dip… a `linear()` dip no spring expresses" (§2.3 anticipation row;
  §4 PRM `--ease-cartoon-punch → --ease-standard`). **`grep -rn ease-cartoon-punch src/styles/`
  → ZERO hits.** Another phantom.
- `--shadow-cartoon` (§2.3 moving-cast) — this ONE is real (`bridges.css:298`, `cards.css:180`).

So 2 of the 3 named "reuse the extant cohort" levers are NET-NEW tokens dressed as existing idioms.
That is the opposite of the deftness the binding law demands ("reuse extant primitives… a UNION,
never a bolt-on") — and it's overfit: a spec that claims to alias a Band-0 idiom that isn't there

**Hardening:** Either (a) point `--dock-goo-weight` / the cartoon-punch ease at the ACTUAL shipped
levers — find the real motion-weight equivalent (`bridges.css`/the spring config) and the real

## R6 (GESTALT, the design lens proper) — the asymmetric barbell screenshot reads as a SLAB+TADPOLE, not the iOS-27 Apple-Music bud-off. Cartoon-punch is asserted, not shown.

Judging `peak-waist.png` AS A USER against the iOS-27 reference (the guiding light):

- The waist IS concave — credit where due. But the SILHOUETTE is a fat lozenge with a tiny
  tadpole tail, not the iOS read where a *tab* visibly lifts off a *bar* and rounds into a peer
  pill. The island bud at p=0.55 is a small ellipse 0.40-scale; the plate is a giant stadium.
  The asymmetry is so extreme (`D = thickness/φ`, reach `= thickness·φ`) that the bud reads as a
  *droplet flicked off*, not a *control migrating into its own dock*. iOS-27's fission keeps the
  budded element RECOGNIZABLE (the transport controls are legible mid-flight). A featureless
  warm-cream blob is not that.
- **No cartoon-punch is visible** because a static screenshot can't show anticipation /
  overshoot / arc / moving-cast — and the spike's `measure()` doesn't gate on any of them. The
  entire §2.3 cartoon-punch table is UNTESTED by §8. The "1940s technicolor FLOW & PUNCH" bar is
  asserted in prose and proven nowhere. The arc is `±reach·0.06·sin(π·p)` ≈ a 6px lob on a ~104px
  reach — sub-perceptual; that is not "exaggeration," it's a rounding error.
- **§3 colorful field:** the screenshot's field does read through (purple/teal/green visible) —
  this bar passes in the spike. But the bridge opacity 0.80 with the threshold may crush the
  field on the actual `.glass-floating` token cohort (different from the spike's flat
  `oklch(0.93 …)`); unproven on the real material.

**Hardening:** (1) Add a born-RED arm for the cartoon-punch that is NOT a tautology: capture a
frame-series and assert the island's velocity profile has an overshoot (position exceeds target
then returns) and the arc apex is ≥ a perceptual floor (e.g. ≥ `0.12·reach`, not `0.06`). (2)
Re-judge the bud proportion against iOS: consider `D = thickness/φ` may be TOO small for a
"becomes its own dock" read — the landed island grows, but the *mid-flight* bud should read as a
shrunk version of the control, not a generic droplet. Carry a glyph/label silhouette on the bud,
not bare cream. (3) Prove §3 transmission on the real `.glass-floating` cohort, not the spike's
flat cream.

## R8 — born-RED integrity: the headline G1 waist gate may be born-GREEN on the per-piece path, and the gate never specifies WHICH neck/surface it samples.

§7 says born-RED because the `inset()` neck → monotone convex profile → `hasLocalMinimum` FAILS.
But (a) the SPANNING neck (the one on the gallery split) thins by `scale`, not `inset()` (R4), and
(b) crucially, even a constant-cross-section capsule, when a SEPARATE round island has travelled
far enough that the blur no longer bridges them, produces TWO masses with a gap — i.e. the cross-
axis alpha profile DOES dip to zero between them once they separate. So `hasLocalMinimum` can be
trivially true on HEAD at high `--island-t` (two disjoint blobs) WITHOUT any hourglass. The gate
must distinguish "a CONNECTED throat with a local minimum" (the goal) from "two disjoint masses
with empty space between" (a trivial pass on HEAD). As written, `hasLocalMinimum(crossAxisProfile)`
+ `waistRatio ≤ 0.45` could both pass on the shipped engine at the moment of separation — i.e.
NOT born-RED.

**Hardening:** Tighten the gate: assert the local minimum occurs while the band is CONNECTED
(non-zero alpha across the whole plate→island span at the sampled p) — i.e. `min(crossAxis) > 0`
AND `min < 0.45·body` AND the minimum is interior (not at a separation gap). Sample at the DWELL
peak (p≈0.55) where the spec claims the throat is held open, and prove on HEAD that at that p the
shipped neck is either a fat connected capsule (ratio > 0.45, fails the ≤0.45 → RED correctly) OR
already separated (no connected throat → also RED). Make the RED-ness explicit per surface
(gallery spanning neck; n>2 per-piece neck) — the current gate conflates them.

## What SURVIVES (fit — do not re-invent)

- **The core geometry thesis is RIGHT.** A constant-cross-section pinch (whether `inset()` or
  `scaleY`) cannot threshold to a concavity; a static clip-path hourglass + a girth bell can. The
  `peak-waist.png` screenshot, taken at face value, shows a genuine concave waist. The headline
  SHAPE fix is the correct load-bearing move and is honestly the fittest of the three lenses.
- **The Safari floor reuse is sound** — regular `filter:url`, sRGB, static literals, non-zero
  host; the structural-concavity-before-the-filter insight is genuinely the right WebKit insurance
  (the concavity does not depend on a filter nuance reading identically).
- **REJECTING lens-c's portal + the 1.18 taffy cap is correct** — the frame escapes the clip
  (`overflow:visible`), and volume-preserving ≤1.08 is the right anti-taffy fence.
- **The scroll-fission composition (`useScrollChrome`→`useDockFission`) is the genuinely
  born-RED, genuinely missing trigger** — `useScrollChrome.ts` exists, the composition does not.
  This one gate arm (G5) IS legitimately born-RED. It's the strongest part of the spec.
- **`--shadow-cartoon` reuse is real** (`bridges.css:298`).

## VERDICT

**SURVIVES — WOUNDED.** The design GESTALT (hourglass neck + asymmetric bud + scroll trigger) is
the right idea and the geometry fix is load-bearing and correct. But as a BUILD CONTRACT the spec
is not yet trustworthy: R1 (the morph-goo dead-wire is fiction — born-GREEN, not RED), R3 (the §8
de-risk is a tautology, not a pixel readback), and R8 (the headline waist gate is not reliably
born-RED) are real refutations that land. R2/R4/R5/R7 are precision/deftness failures that must be
corrected before "DEFT UNION, KISS/DRY, born-RED" can be claimed honestly. Fix R1/R3/R8 and the
golden converges; leave them and the acceptance gate will green on a half-built change.

**TOP REFUTATION:** R1 — the V↔H morph-goo "dead wire (grep: 0 hits, always `none`)" is FALSE.
`--dock-bridge-goo-filter` is wired and midpoint-gated in BOTH `morph-showcase.vue:277` and
`AppShell.vue:488`; the `gooFilter(morphBridge) !== 'none'` born-RED arm is born-GREEN, and a
whole named root cause + file change + gate arm are no-ops.

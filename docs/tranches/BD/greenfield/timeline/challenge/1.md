# CHALLENGE #1 — TIMELINE GOLDEN — CORRECTNESS / DEFT-INTEGRATION / KISS

Lens: idiom · union-vs-bolt-on · KISS/DRY · gate-is-born-RED · overfit/hardcoded refs ·
cross-engine. Default verdict: REFUTED unless it survives. Everything below is verified
against `src/`, the live `:5173/data/timeline*` routes, and a run of the GOLDEN's own
`golden/timeline-pi.mjs` (chromium + webkit, both modes).

VERDICT: **SURVIVES with one LANDED refutation** — the design thesis is sound and deftly
integrated, but the **born-RED claim is materially false on its headline arm (R1)**: the
GOLDEN's OWN gate scores R1 GREEN on the shipped route in 3 of 4 engine×mode cells. That is
a gate-integrity defect, not a design defect, but §9's "Born-RED today on all five arms"
is untrue and must be corrected before the wave can claim a born-RED gate.

## TOP REFUTATION (LANDS) — R1 is NOT born-RED; the gate green-passes the broken rail

§0 asserts the shipped track composites at "OKLab **C ≈ 0.0002–0.0142** — DEAD FLAT, below
the 0.018 warm floor", and §9 R1 says it is "born-RED today." I ran the GOLDEN's own
`timeline-pi.mjs --target=http://localhost:5173/data/timeline`:

```
── chromium ──
  GREEN R1-warm-.glass-track-light — L0.928 C0.0196 H70.4   (C≥0.018 → PASS)
  GREEN R1-warm-.glass-track-dark  — L0.374 C0.0300 H54.6   (PASS)
── webkit ──
  RED   R1-warm-.glass-track-light — L0.928 C0.0144 H65.3   (only RED cell)
  GREEN R1-warm-.glass-track-dark  — L0.348 C0.0191 H57.3   (PASS)
```

R1 is **GREEN on 3 of 4 cells** on the very route §9 claims it fails. Root cause (verified
via live `getComputedStyle` + ancestor walk): the rail's *own* bg is the gray ink film
(`color(srgb 0.11 0.098 0.09 / 0.06)`, backdrop `blur(1px) saturate(1.4)` — §0 is right
about the rail itself), BUT it sits over `bg-card: rgb(253,245,236)` (warm cream) and a
`story-hero-card` painting `oklab(0.928 0.0055 0.0132 …)`. The screenshot-composite the gate
samples therefore inherits the **card's** warmth, not the rail's transmission. So:

- The visual defect (gray, flat, fieldless rail) is REAL — confirmed in the live screenshot
  (`challenge/timeline-shipped-real.png`: a pale flat lozenge with bare colored dots, no
  field, no glass).
- But the gate as written **does not measure the rail's contribution** — it measures
  rail-over-warm-card and passes. A born-RED gate that the broken artefact passes is not a
  gate. §9's "Born-RED today on all five arms" is false for R1.

HARDENING: R1 must isolate the rail's TRANSMISSION delta, not the absolute composite. Two
fixes, either suffices: (a) assert `C(rail-over-field) − C(bare-card-region) ≥ Δ` so a rail
that adds zero chroma over its own backing fails regardless of how warm the card is; or
(b) place the field as the *immediate* backing in the π fixture and subtract the card. Also
add an explicit chroma CEILING witness against the shipped rail's `srgb 0.11/0.098/0.09 0.06`
ink film so the born-RED state is pinned to the rail token, not the page. Until then, do not
advertise R1 as born-RED — it is born-GREEN on HEAD.

## REFUTATION 2 (LANDS, smaller) — R4-volpreserve is a VACUOUS GREEN (false-pass baked in)

The gate run shows `GREEN R4-volpreserve` on ALL four cells while `R4-squish` is RED on all
four. The volpreserve assert is `frames.every(f => |sx*sy − 1| < 0.06)`. On the stiff thumb
`sx=sy=1` (transform is `matrix(1,0,0,1,-6,-8)` — translate only, scale 1), so `sx*sy=1` and
the assert passes TRIVIALLY. A "vol-preserving" GREEN that fires when there is NO deformation
is a confound: it will read GREEN both when the head is broken (no squish) and when it is
correct. HARDENING: gate volpreserve only on frames where `|sx−sy| > ε` (i.e. only judge
volume-preservation where squish actually occurs), else it is unconditioned and meaningless.

## REFUTATION 3 (PARTIAL) — the PROTOTYPE de-risks the WRONG position channel (Safari)

§4/§6 are emphatic: "compositor `transform`/`clip` for the scrub (**NEVER `left`/`width` for
the head** — Safari composites transform, not left)." The prototype's `frame()` loop does
exactly the forbidden thing:

```js
head.style.left = (p*100)+'%';   // line 330 — rAF-driven LEFT animation on the head
fill.style.width = (f*100)+'%';  // line 331
```

The head's CSS `transform` carries only the squish `scale()`; POSITION is driven by `left`
on every rAF frame — the precise non-compositor path §6 says must never happen. So the spike
proves the squish but **does not de-risk the Safari-critical position channel** it claims to
de-risk; it actively demonstrates the anti-pattern. The §0/§9 framing of the shipped thumb as
"pure translate" is also imprecise — the shipped thumb is `left:`-inline-style + width/height
`--ease-standard` transitions (verified live `matrix(1,0,0,1,-6,-8)`), not a transform
translate; the substance (stiff, opacity:0, non-liquid) is right but the mechanism label is
wrong, which matters because the GOLDEN reuses that label to specify the fix.

HARDENING: the prototype (and the production head) must drive POSITION via
`transform: translateX()` on a center-pinned layer (compose the squish `scale` into the same
matrix), NOT `style.left`. The fill edge is the ONE sanctioned non-compositor channel and must
stay gated to `will-change:width` only during `[data-scrubbing]` (the prototype leaves
`will-change:width` permanently on `.scrub-fill` — a standing compositor-memory cost; §6 says
drop at rest). Re-run R4 asserting the head's matrix `e` (translate-x) moves while `left`
stays 0 — that is the real Safari de-risk.

## REFUTATION 4 (PARTIAL) — "cites only what ships" is violated by 2 phantom tokens

§0 makes a point of honesty ("GOLDEN cites only what ships") and correctly flags
`--ease-cartoon-punch` as a depend-on. But two further tokens are written as if extant:

- `--sqrt-phi` (§5 `--timeline-rivet: calc(var(--timeline-h) / var(--sqrt-phi))`, and the
  prototype `:root`): does NOT exist as a CSS custom property. The √φ value `1.272` ships only
  baked into typography tokens (`--type-subheading: 1.272rem`). The √φ math token must be
  MINTED — fine, but then say so (it is a new token, like `--ease-cartoon-punch`), do not
  present `var(--sqrt-phi)` as a reuse.
- `.glass-opaque` (§6 "the W54 `.glass-opaque` endpoint"): there is no `.glass-opaque` class to
  add; `glass/deep.css` calls it a "precedent" in prose. The real mechanism is the
  `--glass-level: 0` path in `glass/a11y-fallback.css` — which IS real and IS the right hook —
  but the rail cannot "use the `.glass-opaque` endpoint"; it must set `--glass-level`. Name the
  actual hook.

HARDENING: relabel both as MINT/HOOK, not reuse. Add `--sqrt-phi: 1.272` to the sizing/typography
token root ONCE (DRY — typography already hardcodes 1.272 in three places; minting the token and
re-pointing them is a net DRY win, not a new surface). State the PRT fallback as
"`--glass-level: 0` via a11y-fallback.css", drop the `.glass-opaque` class reference.

## NET

The DESIGN is fit, deftly integrated, KISS/DRY, cross-engine-sound, and survives the idiom and
union lenses. The single LANDED refutation is **gate integrity**: R1 (the headline warm-rail
arm) is born-GREEN, not born-RED, on the shipped route because it measures rail-over-warm-card
instead of the rail's transmission delta — so §9's "born-RED on all five arms" is false as
written. Plus a vacuous-GREEN volpreserve confound, a prototype that de-risks `left` (the
forbidden Safari channel) instead of `translateX`, and two "cites only what ships" slips
(`--sqrt-phi`, `.glass-opaque`). Harden the gate (transmission-delta R1 + conditioned
volpreserve), fix the prototype's position channel to `transform`, and relabel the two phantom
tokens as MINT/HOOK. None of these break the design; all four make the born-RED claim true.

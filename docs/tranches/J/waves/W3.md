**Hard gate**: dock collapse animates spring continuously; `<DockPopover>` deleted; `<Popover>` ships keep-dock-open + hover-open-delay extensions; max-w/h overflow scrolls with mask-fade; dock blur 0px; vertical-rail dev-text gated; Playwright probes confirm; orchestrator commits W3 close.
**Status**: pending W1.

## Purpose

The user's cornerstone finding: dock collapse animation jerks. R1+R6 diagnosed the root cause: `dock.css:213` + `width: auto/fit-content` non-interpolation. R1 also surfaced DockPopover as a 273-line custom floating element re-implementing reka-ui's `<Popover>`.

This is the largest architectural transposition in J. Per I invariant 5 + J invariant 2: collapse at the canonical root, retire the original.

## Lane A — Collapse animation cornerstone

Per R1 §A + R6 cornerstone-1 diagnosis:

1. Compose `useLayerTransition` for the `<GlassDock>` outer collapsed↔expanded pair (currently bare CSS `transition: width`).
2. Replace `width: auto/fit-content` keyword endpoint with FLIP-measured pixel value at transition start; `useLayerTransition` already does this correctly for `<DockLayerGroup>` inner pair — same mechanism, outer pair.
3. Drop `dock.css:213` `visibility: hidden` (no opacity transition); replace with `useLayerTransition` opacity crossfade on the layer roots.
4. Bracket all spatial motion in `prefers-reduced-motion` (already canonical pattern; verify).
5. Verify spring easing token is canonical (`--spring-smooth` 320ms, or `--spring-snappy` 220ms — pick per R1 recommendation).

**Hard gate (Lane A)**: Playwright `getBoundingClientRect()` samples every 25ms over the transition duration confirm continuous interpolation (no >40% width delta between consecutive frames after t=0). Reduced-motion probe confirms instant snap.

## Lane B — DockPopover collapse onto Popover

Per R1 §A:

1. Read `<DockPopover>` 273-line implementation. Identify the 4 features that distinguish it from reka-ui's `<Popover>`:
   - dock-keep-open sink integration (W3.γ I-tranche: token-based `acquire`/`release`)
   - `hoverOpenDelay` prop for hover-triggered open (defer-on-leave)
   - direction-flip + horizontal-nudge collision logic
   - mount-time positioning seed
2. Migrate features 3 + 4 onto reka-ui's `<Popover>` collision-detection (already supported via `side` + `align` + collision avoidance).
3. Add features 1 + 2 as glass-ui-side extension props on `<Popover>`:
   - `keepDockOpen?: boolean` → wires the sink integration (DockPopover's existing token acquire/release)
   - `hoverOpenDelay?: number` (ms) → adds hover-triggered open with defer-on-leave
4. Delete `src/components/custom/dock/DockPopover.vue`.
5. Delete `src/components/custom/dock/DockPopover` re-export from dock barrel.
6. Delete `pop-up-*` / `pop-down-*` keyframes at `dock.css:499-531`.
7. Migrate every consumer (in-repo + cross-repo speedtest if reachable) from `<DockPopover>` to `<Popover keepDockOpen>` or `<Popover hoverOpenDelay>`.

**Hard gate (Lane B)**: rg `DockPopover` returns 0 hits in src/ + demo/; cross-repo speedtest consumers migrated or coordinated; `<Popover>` test coverage extends; per-story consumption sweep confirms all dock+popover patterns now compose `<Popover>`.

## Lane C — Overflow scroll + blur reduction + dev-text scrub

Per R1 §C + §D + §F + R6 cornerstone-2:

1. **Dock blur reduction**: `tokens.css:275,283` — reduce `--glass-blur-dock-radius` from `1px` to `0px`, drop `saturate(1.025)`. Dock becomes purely opacity-driven (which `prefers-reduced-transparency` already does via `glass.css:229`). User finding 3.

2. **Max-w/h overflow scroll**: add `--dock-max-inline-size` token (e.g., `min(80vw, 64rem)`) + corresponding block-size token. Apply `overflow-x: auto` / `overflow-y: auto` (axis-aware) to dock inner container. Compose `.scroll-fade-{x,y}` mask-fade on the dock root so the overflow boundary feathers instead of cliffing. User finding 1 + 5.

3. **Vertical-rail dev-text gate**: per R1 §F, `manifest.ts:80-92,246` `INTERNAL_CATEGORY` (Wrench-iconed "Internal · Debug") inserts unconditionally in DEV. Gate behind `localStorage.getItem('glass-ui:internal') === '1'` opt-in. Documented in CLAUDE.md as a developer affordance. User finding 5.

4. **Vertical-rail viewport overflow** (R6 cornerstone-2): at small viewports (< 600px tall), dock overflows by 39px. Solution composes naturally with point 2 (overflow-y: auto + scroll-fade-y); also ensure scrollbar visibility hint via `.scrollbar-thin` (currently `scrollbar-width: none` hides the indicator).

**Hard gate (Lane C)**: `--glass-blur-dock-radius` token = 0px at HEAD; Playwright at 1024×768 + 375×667 viewports confirms dock content scrolls without clip; localStorage opt-in toggles `INTERNAL_CATEGORY` visibility.

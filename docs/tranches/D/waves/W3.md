## Phase sub-items

### D.W3.A — Per-`generalize` doc creation

**Mechanism**: for each `generalize`-verdict from W0.B, create `docs/forward-compat/<artefact-name>.md`. Each doc contains:

```markdown
# <artefact name>

## Artefact path
`<src/path>` (file:line of definition)

## Current consumer
`<single consumer site path:line>`

## Named roadmap consumer
**Project**: `<consumer repo name>` (e.g., `fourier-analysis/web`)
**Use case**: `<concrete use case in 1-3 sentences>` (e.g., "the planned spectrogram view will use `text-mono-micro` for tick labels at sub-15px scale")
**Roadmap entry**: `<reference to consumer's roadmap or issue tracker>` (cite specific path or URL; or document as "ICR consumer-XYZ-N" for project-internal)

## Keep rationale
`<2-4 lines explaining why the artefact has semantic value worth preserving despite single current consumer>`. Cite naming + invariants (e.g., "text-mono-micro completes the mono scale text-mono-{caption,small,micro} per typography.css golden-ratio convention").

## Re-audit immunity
This document satisfies §Invariant 5 (no silent overfitting) for `<artefact>`. Future overfitting audits assign `keep` with citation `docs/forward-compat/<artefact>.md` rather than `library-orphan`.
```

**Demands**:
- No doc body contains "future use" / "may be useful" / "TBD" / "will be useful" — these are hand-waves, not roadmap entries.
- Every doc has a named project + use case. Roadmap-less artefacts flip to `delete` and route through W2 follow-on.
- `Use case` section ≥ 5 lines (forces specificity).

**Files touched**: `docs/forward-compat/<each-artefact>.md` (create — one per `generalize` verdict).

**Sub-gate**: every `generalize`-verdict has a corresponding doc; named-consumer grep per doc passes (≥ 1 specific consumer-repo name + ≥ 1 use-case line); zero docs match `rg '(future use|may be useful|TBD|will be useful)'`.

## 0. The natural experiment (frame the whole analysis)

Two poles ran back-to-back on ONE product, and both are on the record:

- **Pole A — maximal rigor (the Perfected-BI formation).** 134 waves, receipts, disk cursor,
  one fail-closed verifier, 194,730 formation checks, a DAG path-calculus, a repair-lease
  transaction type, and 35 ROOT precept amendments. **The user abrogated it after TWO waves**
  ("delayed publication without exercising product behavior" — commit 319cd711/ea3c002c bodies).
- **Pole B — maximal velocity (the conventional band).** ~66 unreceipted commits in ~19 hours.
  Delivered a LOT of real product: the MS structure flatten, motion retuned to the *measured*
  iOS-27 bands (dock 0.30/ζ0.82, drawer {0.32,0.80}, tempo=1.0, the CSS/JS parity fix), the
  component apotheoses, three published majors. **But it silently dropped** all π/paint, every
  consumer outbound, the gestalt ledger, the chronic meta-gates, and the release preconditions —
  and orphaned eight disease clusters (this audit's FAM-A).

**The meta-trap that governs everything below:** the POSTMORTEM was written by Pole A, and its
prescriptions are *more Pole A* — a stricter transaction machine. But Pole A is exactly what the
user killed for friction. A postmortem that diagnoses the tail correctly (permissive close →
terminal batching → drift) and then prescribes the machine that got abrogated has not learned the
load-bearing lesson. **The cost was never rigor. It was rigor's representation** — process-ceremony
welded so tightly to product-verification that abrogating the ceremony took the product checks down
with it. That single sentence is the spine of this report.

## 3. THE SYNTHESIS — the minimal durable spine

The middle path is not "less rigor." It is **rigor that only ever exercises product behavior, with
zero process-ceremony welded to it.** Litmus for every check: *does its RED correspond to a
user-observable product defect?* If yes, keep it. If it goes RED because a file/count/receipt/route
is "wrong" while the product is correct, delete it.

**The per-wave contract (what a wave MUST carry to land — and nothing more):**
1. **Subject exists on disk** and the work is real (non-contrived).
2. **Invariant = a product property**, phrased so a realistic mutation turns real evidence RED
   (a test, a type error, a paint delta) — never "a gate must fail," never a count/filename.
3. **π-owed OR device-free-declared, explicitly.** π is owed when the claim is about rendered
   pixels/motion/paint/a11y-in-composition. Device-free honesty suffices for types, exports,
   structure, logic, dependency topology. **The only dishonesty is claiming a painted property
   device-free** (the P044/P059 lie). A tool outage makes a painted wave BLOCKED — never a lower
   success floor.
4. **One commit**, single writer, orchestrator-owned index.
5. **Terminal DONE or DEAD** — no `complete_with_misses`, no `paint-pending`, no successor-routing.

**Product-gate set vs process-gate set:**
- *Product gates (keep, wire to CI/release):* typecheck, build, `npm test`, public-surface
  reproduction, the demo-BOOTS check, the visual/π lane, a11y-in-composition, the structure
  contract. Each RED = a real defect.
- *Process gates (delete, do not re-mint):* receipt shape, cursor terminality, enrollment rosters,
  count locks, filename rosters, "N families exactly," self-citing prose checks. The user's
  "abrogate these gates if possible" applies to *this set, always*; never to the product set.

**Consumer coordination without a cursor:** a **pre-publish checklist line in release.sh**, not a
134-row terminal cursor. It greps the ask registry + `npm view` the producer peers, and blocks the
tag if a staged peer range is unsatisfiable on the registry (the E-1 hazard). An ACK is a real
consumer commit that builds against the candidate tarball — never a routing label.

**User-gated judgments batch, never ride:** ONE roster (judgment a–g + inline-edit + Baseline
books + DP-A), each row carrying its *evidence* (the measured trace, the A/B capture), fired once
as a single decision. A ruling-owed item is not "in progress"; it is BLOCKED on one batched ask.

**FINAL as a projection, not a ceremony:** a generated file that reflects terminal graph state,
present as a tag precondition — cheap, continuous, never a tail body of work.

## 4. CODIFIED TRIUMVIRATE DISPATCH (the error/uncertainty protocol, planning AND execution)

An anomaly — a smell, a contradiction, a failed probe, a surprise — is classified by its **evidence
grade**, and the grade selects the lane. Fable adjudicates the classification; the registry absorbs
every dispatch with a terminal disposition. Five lanes (the user's named set):

| Lane | Trigger (evidence grade) | What it does | Returns | Adjudication |
|------|--------------------------|--------------|---------|--------------|
| **RESEARCH** | *Unknown* — we don't know the truth | read-only fan-out; gathers evidence | file:line / SHA / measured number; no edits | Fable folds into registry; may spawn a HARDEN if the answer is a claim |
| **HARDEN** | *Suspicious* — a "done"/claim that smells | adversarial; tries to REFUTE (refute-default) | CONFIRMED / REFUTED / CORRECTED + evidence | Fable; a REFUTED claim is struck, a CORRECTED one re-worded in place |
| **WAVE-UPDATE** | *Spec-wrong* — the plan states something stale/false (formation-time) | amend the spec/DAG in place; re-run topology | the amended wave + edge diff | Fable; the amendment is the fix — no source edit |
| **MODIFY** | *Small + in-scope + unambiguous* (execution-time) | the owning wave edits directly, one commit | bounded diff + product evidence | the wave owner; orchestrator integrates |
| **ADDENDA** | *New real obligation, out of current scope* | schedule a new wave/fork; never smuggle into the current commit | a born-RED wave row | Fable; folds into the tranche or a named addenda |

**The classification rule (non-greedy):** grade the *evidence*, not the urgency. Unknown→RESEARCH.
Suspicious-claim→HARDEN. Plan-defect→WAVE-UPDATE. Obvious-small→MODIFY. New-and-real→ADDENDA. A
tempting shortcut (edit directly when the grade is "unknown") is the greedy failure — it ships an
unverified change. The dispatch is *idempotent*: the same anomaly always routes the same way, so a
crash/wall resumes cleanly.

**Grounded in real incidents:**
- *Fabricated pins* (muster/words): a suspicious R1 claim → **HARDEN** → REFUTED. The lane exists
  because a briefed auditor would have propagated the fabrication.
- *Eyeglass "absent"*: suspicious → **HARDEN** → REFUTED (it's the pill default). Saved a wave that
  would have re-built shipped work.
- *Stale repair paths* (POSTMORTEM class 7): a formation-time spec defect → **WAVE-UPDATE** (project
  through ancestor renames) — never a MODIFY, because no source is wrong yet.
- *Dead file / empty husk*: obvious+small → **MODIFY**.
- *This whole BI-addenda*: new real obligations surfaced by audit → **ADDENDA**, scheduled, not
  smuggled into codex's transaction.
- *The reboot / walls*: durability is orthogonal to dispatch — state lives outside /tmp, workflows
  resume by runId, batches ≤3. (Applied this session.)
- *The protocol abrogation itself*: the missing lane was an **OFF-RAMP** (N-1) — when a process
  element imposes friction without exercising product, retire it *proactively via WAVE-UPDATE*,
  don't wait for a mid-flight abrogation that takes product checks down with it.

Lie (that is the non-greedy discipline; it is exactly the axis Pole A ignored).

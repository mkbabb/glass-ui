### Step 2 — Extend useConfiguratorState with cloneMode

Add a `cloneMode?: 'commit-on-write' | 'per-preset'` option to `useConfiguratorState<T>(initialConfig: T, presets, options)`. Default `commit-on-write` (matches metaballs current behavior). `per-preset` mode:

- Each preset slot holds an independent clone.
- Writing to current preset slot does NOT mutate other slots.
- `applyPreset(key)` switches to the named slot's clone.
- `resetCurrent` re-clones from preset definition.

Verify metaballs still works at HEAD with `cloneMode: 'commit-on-write'` (default).

### Step 3 — Refactor AuroraConfigDock to consume useConfiguratorState

`demo/stories/aurora/AuroraConfigDock.vue`:
- Replace `useAuroraStudio` consumption with `useConfiguratorState<AuroraConfig>(initialConfig, AURORA_PRESETS, { cloneMode: 'per-preset' })`.
- Render `<ConfiguratorLayer>` per axis (Palette, Nuclei, Medium, Flow, Composition, Texture).
- Render `<ConfiguratorRow>` per row within each axis.

### Step 4 — Migrate useAuroraStudio

Two options:
- **Option I — Delete useAuroraStudio**: aurora consumes useConfiguratorState directly. Cleanest.
- **Option II — Keep useAuroraStudio as a thin wrapper**: useAuroraStudio is a `cloneMode: 'per-preset'` wrapper around useConfiguratorState with aurora-specific defaults. Marginal value.

Default Option I (KISS).

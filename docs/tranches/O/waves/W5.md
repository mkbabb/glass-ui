## Purpose

Per Rε pipeline-orchestration audit:

- 25 npm scripts + 11 scripts/ files + 1 CI workflow (lint.yml—bundle-budget only).
- 6 duplication sites; 5 special-case branches; 6-layer orchestration proposal.
- Freshness DRY drift: `walkNewestMtime` implemented twice (`scripts/freshness-gate.mjs:43` + `src/freshness.ts:32`).
- `release.sh` runs typecheck + test + build, then `npm publish` runs `prepublishOnly` which also runs build + test—duplication.

## Lane A—`proof:all` cohort runner

Per Rε §"orchestration improvement 1":

5 `proof:*` scripts have no orchestrator (`proof:consumers-build`, `proof:consumers-static`, `proof:package`, `proof:runtime`, `proof:theme-style`). Add a top-level `proof:all` script that runs each in sequence (or parallel where safe). Author canonical orchestration shape so consumers / CI invoke a single entry point.

## Lane B—`verify-export-types` unconditional in release.sh

Per Rε §"orchestration improvement 2":

`scripts/release.sh` currently gates `verify-export-types` on `GLASS_UI_RELEASE_SURFACE_GUARD` env var. Per L.W0 Lane III "subpath publication is binary": every release MUST run the subpath typing probe. Remove the env-gate; make unconditional. Also drop the hardcoded 7-subpath bash probe loop (already superseded by `verify-export-types`).

## Lane C—Freshness algorithm DRY

Per Rε §"freshness DRY verdict":

`walkNewestMtime` exists at both `scripts/freshness-gate.mjs:43` AND `src/freshness.ts:32`—same algorithm, two copies. Per directive O5 (DRY).

Extract canonical implementation to `scripts/freshness-walk.mjs` (an ESM module with no TypeScript loader requirement; consumable from both the prebuild script + the runtime TS file via dynamic import).

Update `src/freshness.ts`:

- Either dynamic-import the canonical shared `walkNewestMtime` (matches the docstring's design intent; closes Rα E3 / W1 docstring drift).
- OR keep the pure-TS walk in `freshness.ts` for the runtime path + cite the snapshot-test verification that the two implementations remain in sync.

Recommend Path A (closes Rα E3 + DRY).

## Lane D—`release.sh` dedup with `prepublishOnly`

Per Rε §"top duplication 2":

`release.sh` runs typecheck + test + build; `prepublishOnly` runs build + test again at `npm publish` time. Eliminate the duplication: either `release.sh` calls `npm publish` directly (relying on prepublishOnly), or `prepublishOnly` becomes a no-op when invoked from `release.sh` (via env-var sentinel).

Recommend: `release.sh` runs typecheck + verify-export-types + profile:budget + bundle-budget gate, THEN `npm publish` (which runs prepublishOnly = build + test). Single ownership: typecheck + lint upstream of build; build + test inside prepublishOnly.

## Lane E—CI gates expansion

Per Rε §"orchestration improvement 3":

`.github/workflows/lint.yml` currently runs bundle-budget only. Expand to:

- `npm run typecheck`
- `npm run test`
- `npm run verify-export-types`
- `npm run profile:budget`

Goal: every PR closes on the same gate matrix the release path uses. Single source of truth for "what makes a build green".

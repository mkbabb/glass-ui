## 2. THE TESTS CODEMOD — DRY-RUN RAN, SAFE

`codemod-tests-glass-alias.mjs` rewrites `(../)+src/X` → `@glass/X` in import/export **specifier position only**
(static `from`/`import`/`export…from`/`require`, dynamic `import(...)`, and `typeof import(...)`), reading repo
read-only and writing the report under proto/ only.


**The one tests-specific edge class the demo codemod did not face — fs-path literals (correctly NOT rewritten):**
4 occurrences of `resolve(__dirname, "../../../../src/...")` (readFileSync-style filesystem paths in the
instrument-chassis CSS/SFC-text tests). These are FILESYSTEM paths, not module specifiers — the `@glass` alias is
module-resolution-only, so `resolve(__dirname, "@glass/...")` would break. The codemod buckets them as a SAFE
non-rewrite class (`FSPATH_RE` over `resolve|readFileSync|join|…`), leaving them relative. Reconciliation check:
117 depth-4 rewrites + 4 depth-4 fs-paths = 121 total depth-4 `../src/` tokens. ✓

**0 REVIEW hits → 0 regex-unsafe** (no template-literal/concat src specifiers, no `?raw`/`?url`, no `.css`/`.glsl`
module imports — the lone `.glsl` import `mediums.glsl` is a real module import and IS rewritten correctly to
`@glass/.../mediums.glsl`).

**Codemod application note:** the dry-run is replace-the-specifier-substring (`spec.replace(/^(\.\.\/)+src\//,
"@glass/")`). To APPLY, swap the report-write for an in-place `writeFileSync` of `src.replaceAll` over the SAME
`SPECIFIER_RE` (capture-group-preserving replacement of group 3), guarded by `SAFE===true`. fs-path refs are left
untouched by construction (different regex, never matched by SPECIFIER_RE).

## 3. public-surface.spec.ts — THE EXPORT-RESHAPE BINDING TEST (not a casualty)

`tests/public-surface.spec.ts` (485L) is the **export-enumeration no-silent-vanish proof**. It imports 38 surfaces
as `* as X` and asserts: per-symbol presence (`subpathRuntimeExports`), root-barrel inclusion/exclusion
(`uiRuntimeExports`/`composableRuntimeExports`/`nonCoreRootRetirements`), and the strongest arm
`exactSubpathRuntimeSurfaces` — `expect(Object.keys(surface).sort()).toEqual([...names].sort())` (currently pins
`/dock` exactly; the pattern is the binding template). Two-stage rewrite, in the SAME wave as the reshape:

### Stage A (B2.0, mechanical) — alias rewrite, paths still resolve
All 38 namespace imports go `../src/X` → `@glass/X` via the codemod. At this point `@glass/subpaths/aurora`,
`@glass/api`, `@glass/carousel` all still resolve (src/subpaths/ + src/api still exist). Pure depth-decouple, no
semantic change — test stays GREEN.

### Stage B (B2.1 glob-swap + B2.2 /api fold) — the BINDING re-point
When `src/subpaths/` is DELETED and `src/api/` is FOLDED, three import classes re-point:

| import class | count | current (post-Stage-A) | reshape target | binding role |
|---|---|---|---|---|
| `@glass/subpaths/<x>` | ~30 | `@glass/subpaths/aurora`, `@glass/subpaths/dock`, … | colocated barrel `@glass/components/{ui,custom}/<x>` (or `@glass/composables/<subtree>`) | the spec re-asserts the SAME symbol sets against the new colocated source → IS the no-vanish proof |
| `@glass/api` (`Api` surface) | 1 | `import * as Api from "@glass/api"` | **DROP** the import; re-point its 3 rows (`{subpath:"api", surface:Api, name:"MAX_NUCLEI"/"MAX_STOPS"/"DEFAULT_AURORA_CONFIG"}`, lines 173-175) to `surface: Aurora` — all 3 constants re-export from `/aurora` (`aurora/index.ts:21,27,28`, verified) | proves the 3 /api runtime constants survive on their owning subpath after the fold |

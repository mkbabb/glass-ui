# RESTRUCTURE-BACKEND

A reusable agent-dispatch prompt for restructuring non-component code — modules, services, composables-as-pure-logic, build/gate scripts, the export surface, DI seams, pipeline orchestration. Drop the body into `AGENT_DISPATCH_TEMPLATE.md` as the *Scope + Non-negotiables* payload.

**When to use:** a wave that moves/colocates/splits non-UI TypeScript, kills mirror/indirection layers, factors a god-runner into a service + pipeline, or designs a generated-not-hand-maintained registry. No `.vue` paint changes — that is [RESTRUCTURE-FRONTEND](./RESTRUCTURE-FRONTEND.md). Pairs with [LEGACY-EXCISION](./LEGACY-EXCISION.md) (run excision first so you move live code only).

---

```markdown
ROLE: backend-restructure agent for tranche {LETTER}, wave {WAVE}. "Backend" = the non-component
TypeScript: composables-as-logic, utils, services, the gate/script tree, the export surface, DI
seams, pipeline orchestration. No `.vue` paint changes.

GOAL: the modules in your bounds are logically grouped by COHESION DOMAIN (what they DO),
colocated with their owners, free of god modules, and reached through clean service / DI /
pipeline boundaries — without contrivance (no grouping that invents a fake shared concern).

COMPLETION: green typecheck + green build + green affected tests, AND the public import surface is
byte-equivalent OR carries a migration-map row for every changed path. Module moves are
import-isomorphic — every consumer re-points, no dangling barrel.

THE PRINCIPLE (cite by name):
- "No god modules": `utils.ts` / `helpers.ts` / `common.ts` and any file >500 L are god modules in
  gestation. Split by concern, name by behaviour, NEVER by namespace position.
- "Splits use directory modules": `feature/index.ts` + children in a same-named subdir, NOT flat
  `feature_leaf.ts` siblings. Cross-module isomorphism — a reader who knows one family's shape
  recognizes the neighbour's at a glance.
- "Typed-key + helper-pair DI": every provide/inject routes through a typed `InjectionKey<T>` in a
  module-local `keys.ts`/`context.ts` PLUS the paired `useFooContext()` (strict — throws on missing
  parent) AND `useOptionalFooContext()` (befitting silent default for primitives that may render
  outside the provider). Raw `inject(stringKey)` is the target.
- "Test files live outside src/": KEEP it. A restructure must never drag a `*.test.ts` into src/.
- KISS / DRY: simplest complete mechanism; remove duplication before adding policy. A
  pipeline-orchestration seam (one `resolveX → buildY → emitZ` chain) beats N scattered call sites
  — collapse to one pipeline with the surviving consumer.
- "No overfitting": every helper / module / export needs ≥2 consumers, or is public API, or is a
  private single-use helper INLINED. No module exists for symmetry alone.
- "Generated, not hand-maintained": a registry derivable from disk (an exports map, a manifest, a
  structure index) is GENERATED by a script with the disk as the single source of truth — never a
  hand-curated list that drifts. The generator is fail-CLOSED (an unclassified input is a hard
  error, never a silent default).

WHAT TO DO:
1. God-module carve: split a >500 L module by section cohesion (a measure/seat helper cluster, a
   lifecycle family, a uniform bridge), each carved leaf a coherent directory module under the
   owner's dir. MECHANICAL + behaviour-isomorphic — the carve changes file boundaries, not logic;
   the assembled behaviour is byte-equivalent. Re-point every reader (gate, sibling, barrel) that
   named the carved symbol INTO the leaf.
2. Colocation: a composable family lives WITH its component (`<dir>/composables/`), its constants in
   `<dir>/constants.ts`, its types beside it. A type a `.vue` SFC cannot re-export lives in the
   dir's `constants.ts` (the SFC-cannot-export-a-type colocated home). No composable orphaned in a
   global bucket when it belongs to one component family.
3. Logical grouping WITHOUT contrivance: group by what modules DO. Do NOT invent a `shared/` or
   `core/` bucket to host two unrelated helpers — that is a god module reborn. If two helpers do not
   share a real cohesion domain, they stay apart (judge, don't force — merge when surfaces want ONE
   core, keep apart when feature sets diverge).
4. Service / DI boundaries: where a subsystem reaches into another by string-key inject or a deep
   relative path, route it through a typed-key DI pair or an explicit service module. The reach-in
   surface is one named seam, not N scattered injects.
5. Pipeline orchestration: a god-runner that interleaves a data table, the prose, and the dispatch
   logic in one file splits into a DATA manifest (append-safe), a RUNNER (the orchestration), and
   the per-stage services — the runner reads the manifest, the manifest holds no logic.
6. Export reshape (if in bounds): a mirror-barrel indirection layer dissolves; a discovery-aggregator
   folds into typed per-subpath surfaces. Each published subpath is a coherent dist chunk with its
   own typed surface — no mega-barrel, no alias. The published exports map is GENERATED from the
   colocated barrels (the single source of truth), fail-CLOSED.

HOW (the discipline):
- Move-then-re-point in one pass: you edit the file contents + every import that named the old path.
  Run `npm run typecheck` after each module group.
- Preserve import-graph acyclicity: a carve must not introduce a circular import (verify with the
  build). A circular dep means the boundary is wrong — re-cut, do not paper it with a lazy `import()`
  inside a function. (A MARKED lazy-boundary that chunk-isolates a HEAVY PEER is fine; a lazy import
  to dodge a cycle is the anti-pattern.)
- NO new god module, NO `utils.ts`, NO opportunistic logic change riding a move.

NON-NEGOTIABLES: read-only git; stay in bounds; evidence (typecheck/build/test paths + the
import-isomorphism proof — every consumer re-points, no dangling barrel); STYLE.md prose; HALT on
scope reveal (a carve that needs a logic change is a different wave).

RETURN: per template, plus a path-migration table (old module path → new) for every move.
```

## Appendix — the colocation shape

A complex module is a directory, not a flat file family. The recognizable shape, recursively:

```
<feature>/
  index.ts            the public barrel (the only outside-reachable surface)
  <Feature>.ts        the orchestration / state machine
  composables/        the useX leaves it composes
  constants.ts        the literals + the types an SFC cannot re-export
  keys.ts             the typed InjectionKey<T> DI seam (if it provides context)
  README.md           the contract (canonical-readme-shape)
```

A new `utils.ts`/`helpers.ts`/`shared/` is the smell that the cohesion domain was not found. Name the leaf by what it does (`scheduler.ts`, `deviceAcquire.ts`, `backdropSample.ts`), not by where it sits.

## Findings (7)

### [critical] default-ramp-coexists — the scale is not enforceable as-is

**Claim:** The @theme bridge ADDS named rungs (text-caption/-small/-body/…) but never resets Tailwind v4's built-in size/leading/tracking ramp, so the entire default ladder (text-xs…text-9xl, leading-*, tracking-*) stays live and silently bypasses the √φ scale. 251 default-ramp size utilities ship (demo 232 across 42 files: text-sm×118, text-xs×100, text-base×6, text-lg×2, text-4xl×2, text-2xl×2, text-xl×1, text-3xl×1; src 19 across 16 files: text-sm×14, text-xs×2, text-lg×2, text-base×1). text-sm resolves to Tailwind's static 0.875rem and text-xs to 0.75rem — NOT the fluid clamp() --type-small/--type-caption registers, so the '27-inch font too small' fluid work is defeated wherever text-sm/text-xs are used (which is more than the named rungs: demo text-sm+text-xs=218 vs text-small+text-caption=195).

**Evidence:** src/styles/theme/bridges.css:16-57 bridges only NEW names (--text-caption:var(--type-caption) …) with NO `--text-*: initial` / `--*: initial` reset anywhere in src/styles (grep for `--text-(xs|sm|base|lg|xl):` and `initial` returns none); Tailwind imported un-reset at demo/demo.css:83 `@import "tailwindcss"`. Counts: `grep -rhoE '\btext-(xs|sm|base|…|9xl)\b' demo` = 232/42 files; src = 19/16 files. Only enforcement that exists is tests-visual/eyebrow-union.spec.ts (a CONSISTENCY gate for the mono-caption voice) and tests/styles/typography.test.ts (asserts the one 1/√φ proportional-ratio literal) — neither forbids raw sizes or the default ramp.

**Proposed:** To make the scale lintable: (a) add `--text-*: initial; --leading-*: initial; --tracking-*: initial` (or the Tailwind v4 `--*-... ` clears) in the @theme block so ONLY the named rungs exist, turning every `text-sm`/`text-xs` into a build-visible unknown-utility; then codemod the 251 default-ramp sites onto the named rungs (text-sm→text-small, text-xs→text-caption/text-micro per intent). (b) Add a lint/gate that fails on raw font-size/line-height/letter-spacing literals and on any `text-[…px|rem|em]` arbitrary type utility. Without (a) no linter can tell the scale rung `text-small` from the off-scale default `text-sm`.

### [major] raw-size-literals-off-scale — font-size literals bypass the --type-* ladder

**Claim:** Raw font-size literals live outside the scale in shipped src components and demo chassis, several off every rung. SRC: src/components/tabs/styles/segmented.css:171 `font-size: 0.8125rem` (13px — between micro 11px and caption 12px, on NO rung) and :184 `0.875rem` (14px = small floor but hard-coded, non-fluid); src/components/dock/styles/layer-group.css:205 `0.75rem` (12px = caption floor but hard-coded, non-fluid). DEMO bespoke sizings that fork the ladder: demo/chassis/hero/story-hero.css:81,110 `font-size: min(…)`, demo/chassis/landing/SectionPreviewCard.vue:116 `clamp(1rem,13cqmin,1.6rem)`, demo/stories/dock/overview.tile.vue:31 `clamp(0.7rem,7cqmin,1rem)`, demo/chassis/code/Code.vue:71 `0.92em`. Arbitrary Tailwind type utilities (9 demo sites, 0 src): demo/shell/BottomDock.vue:173,213,240,256 `text-[0.7em]`; demo/stories/navigation/carousel.vue:165, substrates/aurora/NucleiOverlay.vue:73, dock/overview.vue:332,364 `text-[10px]`; motion/springs.vue:444 `text-[0.7rem]`.

**Evidence:** `grep -rnE 'font-size:[[:space:]]*[^v;i]'` over src (7 hits, 3 true off-scale rem literals) and demo (5 clamp/em forks); `grep -rnE '(text|leading|tracking)-\[…(px|rem|em)'` src=0, demo=9. **Proposed:** Repoint the three src rem literals onto var(--type-*) (segmented 0.875rem→--type-small, layer-group 0.75rem→--type-caption; 0.8125rem needs a ruling — either accept the micro/caption rung or mint a rung). The bespoke demo hero clamps are container-query one-offs — acceptable only if the ladder genuinely lacks a container-fluid rung; otherwise fold into --type-display-*.

### [minor] scale-file-self-violation — the canonical typography files don't dogfood their own tokens

**Claim:** The typography scale's OWN files hard-code literals for line-height and letter-spacing instead of composing the --type-leading-* / --type-tracking-* tokens they are the home of, so even the canon undercuts the single-source claim. text-mono-prose sets `letter-spacing: 0.02em` (off every tracking rung) and text-mono-micro `letter-spacing: 0.025em` (= --type-tracking-wide, raw); text-micro (semantic.css:235) and text-mono-micro (utilities.css:65) both `line-height: 1.25` with no matching leading rung (the micro leading token is 1.2); text-admin-label (semantic.css:241) and fourier-f (utilities.css:93) `line-height: 1` raw; fourier-f `font-size: 1.35em` raw.

**Evidence:** src/styles/typography/utilities.css:59 `letter-spacing: 0.02em;`, :65 `line-height:1.25`, :66 `letter-spacing:0.025em`, :92 `font-size:1.35em`, :93 `line-height:1`; src/styles/typography/semantic.css:235 `line-height:1.25`, :241 `line-height:1`. Compare the token set at src/styles/tokens/scheme-motion.css:54-77 which these files exist to consume.

**Proposed:** Make the canon dogfood itself: 0.025em→var(--type-tracking-wide); either add a --type-leading-micro-tight (1.25) rung or reuse --type-leading-micro (1.2) for the two 1.25 line-heights; keep `line-height:1` where it is a deliberate single-glyph reset but tokenize the mono-prose 0.02em (mint a rung or fold to snug 0.01em/wide 0.025em).

### [minor] inline-eyebrow-reconstruction — hand-rolled eyebrows fragment the single-voice canon

**Claim:** Several sites rebuild the mono/uppercase eyebrow inline instead of using text-mono-caption, so they escape the eyebrow-union consistency gate (which only inspects .section-label/.text-mono-caption nodes) and can drift in family/tracking/size. demo/stories/navigation/carousel.vue:128,233 `text-xs uppercase tracking-widest` and :165 `text-[10px] uppercase tracking-widest` (uppercase caption WITHOUT font-mono → renders in the body family, a different voice); demo/stories/dock/overview.vue:332,364 `text-[10px] uppercase tracking-wider`; src/components/search/FuzzySearch.vue:161,213 Badge `font-bold uppercase tracking-wider` type-labels. demo/stories/substrates/aurora/NucleiOverlay.vue:73 stacks `text-mono-caption … text-[10px]` — overriding the caption's own size.

**Evidence:** `grep -rnE 'class="[^"]*uppercase[^"]*tracking-(wide|wider|widest)'` demo+src excluding the utility classes = 7 sites listed. The eyebrow-union spec (tests-visual/eyebrow-union.spec.ts:60-70) only queries `.section-label, .text-mono-caption` so these hand-rolled eyebrows are invisible to it.

**Proposed:** Fold the inline eyebrows onto text-mono-caption (or delete them per the meta-caption kill), and drop the NucleiOverlay text-[10px] size override. If these are NOT meant to be eyebrows, strip uppercase+tracking so they don't read as a competing voice.

### [note] story-hierarchy-flat (F10) — pages lean on the caps stamp for hierarchy instead of the size ladder

**Claim:** The F10 complaint (group header and field labels at equal weight; flat hierarchy) is reinforced by typography practice: story pages get their section demarcation from the uniform mono ALL-CAPS eyebrow (section-label / text-mono-caption on 65/128 pages) rather than from the √φ size ladder, which the pages barely climb — demo uses text-title only ×2 and text-heading ×8, versus text-small ×178 and the two-value eyebrow stamp ×157. A ladder that tops out in practice at 'caption caps + small body' cannot express header-vs-field hierarchy, so every level reads at the same visual weight.

**Evidence:** Named-scale adoption in demo: text-title ×2, text-heading ×8, text-subheading ×24, text-body ×4 vs text-small ×178, text-mono-caption ×126, section-label ×31 (grep per-utility counts). The hierarchy carriers (title/heading) are ~34 uses across 128 pages; the flat carriers (small + caps eyebrow) are ~335. VISUAL-GESTALT.md:63 names F10 'group header and field labels carry equal weight'; :89 routes the typography audit (F15) as the token wave feeding the configurator/story-standard cure.

**Proposed:** Pair the meta-caption kill with a hierarchy pass: give section headers a real ladder rung (text-heading/text-subheading), field labels text-small, values text-body — so weight comes from SIZE. This is the library-side token input to the configurator-standard / story-standard wave, not a spot fix.

## RED-1 — Toast spelling is fixed, but the live-writer grammar is not closed

The pinned Toast witness is now factually named. The committed SFC imports
`ToastRoot` from `reka-ui`, renders `<ToastRoot>`, and binds its class expression;
`ToastRoot:v-bind:class` is therefore the correct census spelling.

The broader claimed grammar still has two exact holes at
`GATE-SEMANTIC-ROSTER-C13.json:52-94,109-161`.

First, it admits both a static template class attribute and a `v-bind:class`
expression, plus both `StringLiteral` and `NoSubstitutionTemplateLiteral`, and
four bounded-flow arms. All seven current census entries exercise dynamic
bindings with ordinary string literals and `cn`/computed/const flows. There is
no static-class witness, no no-substitution-template witness, and no synthetic
GREEN/RED conformance matrix for the cross-product of the advertised arms. The
eight row mutations likewise contain no arm-preservation or arm-deletion bite.
A detector implementing only the currently observed dynamic-string arms can
therefore satisfy every named mutation while silently rejecting syntax C13
claims to admit.

The static arm is also structurally under-described. A direct
`@vue/compiler-sfc` probe parses `class="[--x:1rem]"` as an ATTRIBUTE node whose
value is a Vue TEXT node; it is neither a TypeScript `StringLiteral` nor a
`NoSubstitutionTemplateLiteral`. C13 supplies no template-node literal rule, so
a literal reading of `admittedLiteralNodes` conflicts with the admitted static
sink.

Second, `approvedBindingIdentities` binds only `computed` and `cn`.
`bindingResolution` is correspondingly wrapper-scoped. The Toast census records
only the local tag spelling and never binds that tag to `ToastRoot` from
`reka-ui` or proves that the component sink forwards the class to a rendered
element. Replacing the import with a wrong-module component under the same local
name, whose `inheritAttrs:false` root drops `class`, preserves the census string,
literal path and public SFC reach while eliminating the live writer. That
contradicts the candidate note's claim that spelling alone cannot pass.

C14 must define the Vue static-attribute literal representation, add synthetic
GREEN/RED coverage for every admitted sink/literal/flow arm, and either bind a
component-tag sink to an approved class-forwarding component identity (with a
wrong-module/drop-class mutation) or narrow component bindings out of the
grammar. The exact current Toast witness itself should remain.

## RED-2 — Chip does not prove its full hostile boundary

The strengthened endpoint assertions are useful, but the fixture at
`GATE-SEMANTIC-ROSTER-C13.json:644-671` mounts hostile `role`, `tabindex`,
`aria-pressed` and `onClick` only. It does not mount hostile `data-state` even
though both predicate and endpoint claim its absence. A regression that forwards
a caller's `data-state="on"` only in static mode passes this registration because
the caller never supplies that attribute. Checking absence cannot prove an
ingress filter without a hostile ingress value.

The predicate also says the final content has no **focusability**, while the
mechanism observes only a `SPAN` and absent `tabindex`. A span can be made
sequentially focusable through another admitted attribute, most plainly
`contenteditable="true"`, without a role, tabindex, pressed/state relation,
button descendant or click-listener delivery. The committed `staticAttrs`
currently forwards `contenteditable`, so this is not merely an exotic AST
lookalike; it is outside the promised detector input.

C14 must at minimum include hostile `data-state`. It must either include a
hostile alternate focusability source and assert actual non-focusability, or
narrow "focusability" to the exact no-`tabindex` fact. The static click bite and
node-reuse law otherwise pass.

## RED-4 — Avatar's pre-error state can already be terminal error

Avatar's same-node/name and one-owner requirements are materially stronger.
The remaining gap is the transition precondition at
`GATE-SEMANTIC-ROSTER-C13.json:718-744`.

The case key says `before-error:loading-one-identity`, the predicate says
loading-to-error, and the prose says to "flush the initial loading state". The
mechanism explicitly asserts only `data-image-state=error` after dispatch. It
does not require the pre-dispatch image's `data-image-state` to equal `loading`
or require a pre-dispatch `loading` status callback. Its terminal-only mutation
rejects absence of a pre-error witness, not a witness whose state is already
`error`.

A mutated implementation may therefore start in `error` despite the non-empty
source. The detector can capture the correct identity and hidden duplicates,
dispatch `error` on the same controlled probe, and reproduce the same terminal
identity, name, count and hidden state. Every explicit assertion and mutation
survives, but no loading-to-error transition occurred.

C14 must assert the pre-dispatch probe/image state is exactly `loading`, assert
the post-dispatch state is exactly `error`, and add an already-error-before-
dispatch mutation. Restoration of `window.Image` should be fail-safe so planted
RED mutations cannot poison later registrations. The same DOM-owner and name
law may remain.

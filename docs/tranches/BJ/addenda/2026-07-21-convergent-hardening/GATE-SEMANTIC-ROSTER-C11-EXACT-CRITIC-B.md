## RED-2 — Button selector exclusion is not effective-cascade proof

The Button predicate says the owned default selector excludes size-class SVG
children. Its mechanism retains the rendered `size-9` class/host assertions and
parses the owned stylesheet to prove that exclusion
(`GATE-SEMANTIC-ROSTER-C11.json:106-125`). The pinned source does contain:

```css
.button > svg:not([class*="size-"]) {
    inline-size: var(--ui-glyph);
    block-size: var(--ui-glyph);
}
```

The first three mutations address that exact rule. The fourth requires a later
owned rule retaking `inline-size` or `block-size` for size-class SVG children to
RED. Such a later rule does **not** change whether the default selector excludes
those children. A parser satisfying the stated mechanism can continue to pass
while the fourth required mutation is live.

If effective host-size survival is intended, the semantic law must define the
owned cascade, not only one selector string. A direct counterexample is to keep
the exclusion byte intact and append a later matching rule that assigns the
glyph size. Equivalent retakes can use logical or physical aliases
(`inline-size`/`block-size`, `width`/`height`), `all`, `!important`, an enclosing
conditional at-rule, or an equivalent selector spelling. PostCSS alone returns
selector text; C11 does not define selector matching, cascade order, declaration
aliasing or the parser/fixture used to decide the winner.

C12 must choose one coherent contract:

- narrow the row to exact default-selector exclusion and delete the unrelated
  later-cascade mutation; or
- retain effective survival, broaden the predicate/mechanism, directly own any
  selector parser, evaluate every owned rule matching the mounted size-class
  SVG in cascade order, and mutate later/important/logical/physical/conditional
  retakes.

A real computed-size fixture over the generated Button CSS is also sufficient
if it is immutable and its browser/CSS engine is named. No private consumer
rule or extra seat follows.

## 2. The original W5 contract is useful but not terminal

The original wave correctly makes W5 a review, requires Safari + Chrome captures, asks for both removal and addition, and routes fixes to named owners. Preserve all four decisions. Its gaps are:

1. **No common decision rule.** A marked roster can call one object too spacious, another too tight, and a third too bright without explaining what shared system those verdicts protect.
2. **No born-RED visual falsifier.** “A roster entry with no capture is RED” proves paperwork completeness, not whether the judgment is coherent or the after-state is better.
3. **Stale source premises.** At the pinned source, ordinary Card gold, F11's gapped cards, and F31's stretch mechanism no longer match the owner prose exactly.
4. **Cross-wave duplication risk.** Reach, type, tabs geometry, Slider action ownership, Card reduction, and Dock compact controls already have exact owners. A free-standing “proportion fix” can fork each one.
5. **Breath can be mistaken for ambient animation.** The amended restraint law and Visual Hardening already reject idle motion as an automatic virtue. W5 must judge state continuity, not demand a wandering gradient on every card.
6. **Material can be mistaken for decoration.** More blur, more highlight, more rounding, and more cream do not necessarily yield glass. The target is warm contextual frost with spatial transmission and restrained edge energy.

Therefore W5 remains **review-only**. Its output is an amended, falsifiable design contract and owner roster. It must not become a mega-wave that edits arbitrary CSS after a screenshot walk.

## 4. Three coherent grammars considered

### Grammar A — universal golden-ratio lattice

**Idea:** derive every type size, gap, inset, card dimension, and control body from φ or √φ.

**What it gets right:** it offers a repeatable relationship; the existing Card formula and 1.618 aperture show that ratios can produce calm macro rhythm.

**Why it fails:** it mistakes mathematical recurrence for semantic fitness. A 44px coarse reach floor, a 12px Slider track, a dense inspector, a 64px audacious Dock, and a page hero serve different jobs. A pure φ ladder either violates reach, inflates tools, or produces arbitrary rounding to make numbers comply. The current 25.9px Configurator section illustrates the danger: a valid ladder rung can still be the wrong role.

**Verdict:** **REJECT as a universal system.** Retain φ-derived macro spacing where content structure already earns it; do not use φ as a taste alibi.

### Grammar B — one comfort scalar

**Idea:** multiply box, glyph, padding, gap, and radius by one `--ui-scale`, as parts of Dock already do.

**What it gets right:** within one coherent control family, lockstep scaling can preserve glyph-to-box rhythm and keep coarse mode from looking like a desktop glyph stranded in a 44px cell.

**Why it fails:** an app-wide scalar cannot distinguish painted body from hit reach, content density from input mode, or layout topology from size. It can turn Dock chrome into ~80px furniture, enlarge a Slider that should remain visually compact, and leave source/target continuity unsolved. It also cannot decide when a phone interface should change posture rather than grow.

**Verdict:** **RETAIN only as a local family implementation tool; reject as W5's governing grammar.** Responsive topology and semantic role select the rung first.

### Grammar C — semantic mass / occupied body

**Idea:** proportion is the relationship between a thing's semantic job, occupied content, painted body, action reach, material boundary, and state transition.

**Why it wins:** it explains the historical defects and the extant good systems with one rule. F03 fails because the body is mostly remainder. F11 failed because one semantic group wore several islands. F46 fails because one preview wears two material boundaries. Slider succeeds by keeping paint compact but still owes reach. Dock densities can differ because their roles differ. Motion can be alive without moving layout because it transfers mass on a compositor-owned path.

**Verdict:** **SELECT.** This grammar becomes W5's judgment instrument. It mints no public API and no parallel axis.

## 5. Selected grammar: KISS laws and formulas

The formulas below are design tests, not a request to add a set of `--aristotle-*` custom properties. Luna maps a chosen result to existing spacing, type, radius, density, and touch-target tokens. If a source formula already expresses the same relationship, preserve it rather than restating it.

### 5.1 Reach is independent of paint

Let `H` be the existing role-resolved painted control height. Let `T` be the actual action region.

```text
fine pointer:   painted body = H; action region >= H
coarse pointer: T = max(H, 44px)
```

The coarse region must be owned by the actual action at its centre, four corners, and four edge midpoints. A pseudo-element with `pointer-events:none`, a computed `min-size`, an inert wrapper, or an element that disappears in a collapsed posture is not a target. Transparent slop must not overlap a sibling action. Keyboard focus must reveal the same action without scroll or Dock occlusion.

This folds directly into existing `R-COMPACT-HIT-FLOOR`, A11Y Slider, Tabs, and Dock rows. W5 never adds private sizes to consumers.

### 5.2 Painted body derives from the local role

For compact controls, a useful audit relation is:

```text
micro gap g      = snap(H / phi^4, existing spacing rung)  ≈ 4–6px for H 32–40
sibling gap      = 2g                                      ≈ 8–12px
inline padding p = snap(H / phi^2, existing spacing rung)  ≈ 12–16px
```

This is a comparison aid, not a mandate to introduce fractional pixels. Existing 4/6/8 gaps and 10/12/14-ish inline pads already sit near the band. A component fails when an unexplained literal breaks the local rhythm or when the ratio makes the content illegible; it does not fail merely because a value is not φ-exact.

For content surfaces, retain the Card candidate:

```text
block inset   ≈ inline inset × sqrt(phi)
footer inset  ≈ block inset / phi
title gap     ≈ inline inset / phi^2
media ratio   ≈ phi (1.618), when the content is genuinely visual
```

The formula is subordinate to occupancy. A short one-line Card must not acquire a giant empty block merely to preserve a nominal height.

### 5.3 Semantic group owns the boundary

One semantic group gets one primary material boundary. Inside it:

- a media aperture may clip and crop, but does not automatically add a second tint, inset highlight, border, and card radius;
- adjacent inspector sections use either one joined-group hairline **or** independent spacing/material boundaries, never both;
- a divider is allowed when it communicates adjacency, alignment, or state that spacing alone cannot; and
- a nested control inherits its parent plate's resolved contextual field and adds only its own restrained state tint/rim. It does not backdrop-sample the same scene again.

This is the Goal of Glass in proportion form: warm contextual frost, quiet edge hierarchy, no chrome-only skin, no generic milky lozenge.

### 5.4 Type follows semantic distance

Adjacent content roles use adjacent existing semantic rungs unless the page truly changes scale. The binding Configurator ruling is:

```text
page/story title       -> heading / display as already owned by StorySection
inspector section      -> subheading (~20.4px)
control row label      -> small (~14px)
token/spec metadata    -> micro (~11px), optional only
required explanation  -> meta/body rung, never micro-only
```

Therefore current `--configurator-section-size: var(--type-heading)` is rejected for the local inspector and returns to `--type-subheading` under the existing STORY/type owner. The old flatness is not repaired by a theatrical heading; it is repaired by joined grouping, one structural inset, a clear section-to-row ratio, and restrained tonal separation. The stale Configurator comment that still says 20.4px must be trued with the eventual owner cut.

StorySection adoption remains selective: title for page/cover protagonism, heading for major narrative sections, subheading for local groups. A global 269-site level attribute rewrite without a page-role roster is rejected.

### 5.5 Occupancy is evidence, not equal-height tidiness

Define an annotated **occupied-body ratio** for review purposes:

```text
occupied-body ratio = union(content + required interaction + intentional focus field)
                      / component inner body
```

No universal percentage becomes a token or gate. The ratio is a falsifier and comparison aid. Large unoccupied regions must have a named job: manipulation field, focus breathing room, viewport continuity, or anticipated content. Equal-height grid alignment, fixed intrinsic placeholders, or a stretched parent is not a job. A mutation that removes the useful content while the same box remains must expose the disproportion.

### 5.6 Movement preserves momentum and mass

Motion is proportion over time. For every animated body:

- source and destination share one visual identity and one director;
- the bounding footprint remains layout-stable unless the content topology itself changes;
- anticipation, travel, and settle are ordered on one timeline;
- velocity affects bounded deformation/specular intensity, not arbitrary blur radius or new layout dimensions;
- the moving/active boundary receives the strongest caustic; rest remains quiet;
- no autonomous ambient loop runs merely to prove “life”; any ambient effect obeys the ≤5s or pause/stop/hide rule; and
- PRM preserves geometry, state, names, focus, and final material while removing travel, smear, overshoot, and nonessential dissolve.

Safari and Chromium receive the same role, dimensions, target geometry, and endpoint. Progressive enhancement may refine optical detail; it may not create chrome-special behavior or a different control grammar.

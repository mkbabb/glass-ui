## RED-1 — Button does not prove the effective owned cascade

The row promises that a host-sized SVG “retains its size utility” and includes a
mutation for a later owned size-retaking rule
(`GATE-SEMANTIC-ROSTER-C11.json:106-125`). Its mechanism only keeps the current
DOM class/host assertions and parses the default selector's `:not([class*="size-"])`
exception. The committed body checks `size-9` is present but never observes a
computed size (`tests/components/ui/reka-binding-idiom.test.ts:28-36`).

An earlier, higher-specificity or `!important` owned declaration can therefore
set `inline-size`/`block-size` on `.button > svg.size-9` while the required
exception and every body assertion remain green. Restricting the falsifier to a
“later” rule is not an effective-cascade law; source order alone does not decide
CSS precedence.

C12 must strengthen the same Button seat in one of two exact ways: prove through
a browser/computed-style observation that the host utility wins, or parse the
complete owned cascade and reject every effective owned width/height declaration
that matches a size-class child, accounting for specificity, importance, layers
and order. Add earlier higher-specificity and earlier/later `!important`
retaking-rule mutations. No seat is added.

## RED-2 — Chip's transition predicate overclaims its body

The predicate says selectable -> action -> static transitions **replace the
host** and clear stale semantics (`GATE-SEMANTIC-ROSTER-C11.json:543-555`). The
committed body mounts selectable/true but makes no assertion before changing the
props. It then checks only the action tag and absent pressed attributes, followed
by the static tag and absence of any button
(`tests/components/chip.contract.test.ts:142-156`).

Consequently, a component that starts in action-like markup, omits initial
`aria-pressed="true"`/`data-state="on"`, or reuses the same button node across the
selectable-to-action branch can pass. Both the selectable Reka host and native
action host render as `BUTTON`, so tag equality does not prove replacement.

C12 must add a twelfth same-seat pre-binding redress. Capture the initial element
and assert its selectable identity, `aria-pressed="true"` and `data-state="on"`;
after each props transition capture the new element, assert node non-identity,
the exact action/static host, and absence of stale selectable semantics. Missing
initial state, branch collapse/node reuse and stale-state mutations must RED.
The active count remains 48; only the redress count changes from eleven to
twelve.

## RED-3 — class-sink wrapper identity and reach remain semantic guesses

C11's grammar successfully covers all current committed overlay-definition
carriers. A compiler-sfc/TypeScript traversal reproduced the two published names

| --- | --- |
| `DialogContent.vue` | top-level const -> computed conditional -> `cn` -> bound class |
| `SelectContent.vue`, `Toast.vue`, `DrawerFooter.vue`, `DrawerHeader.vue` | literal -> `cn` -> bound class |
| `TooltipContent.vue` | literal -> `computed` -> `cn` -> bound class |
| `PopoverContent.vue` | literal -> `computed` -> `cn` -> each of three alternative bound-class sinks |

This closes C10's carrier-shape ambiguity. It does not close identity or reach.
The grammar approves wrappers by the names `cn` and `computed`
(`GATE-SEMANTIC-ROSTER-C11.json:60-74`) but does not require `cn` to resolve to
the shared class combiner or `computed` to Vue. A local/shadowed same-named
function can discard its argument while satisfying the named syntax path. The
current real bindings are `cn` from `../_shared/class-names` and `computed` from
`vue`; those module identities are not frozen.

Nor does the grammar require the containing SFC to be reachable from a public or
rendered component root. After deleting every real exported carrier, an
unreferenced `.vue` file containing a genuine template class sink can keep the
token predicate green even though no consumer can receive the definition.

C12 must bind approved wrappers by resolved import identity, permitting aliases
of the real imports but rejecting local, shadowed and wrong-module lookalikes.
It must also require each admitted SFC to be in the frozen public component reach
graph (or freeze an equivalent exact carrier-root list). Add same-name wrapper,
shadowed wrapper, disconnected import, dead-SFC sink and exported-to-dead-SFC
mutations. This strengthens the existing token seat.

## RED-4 — frame-zero call existence is not painted-ground dataflow

The committed source has the intended full chain: the loading render calls
`auroraFallbackGround(shellAuroraConfig.value)`, binds its result to `ground`,
and sends `ground.backgroundImage` and `ground.backgroundColor` to the returned
vnode's style (`demo/shell/AppShell.vue:66-85`). C11 freezes only the import,
Aurora boundary and exact call string
(`GATE-SEMANTIC-ROSTER-C11.json:383-406`).

A hostile implementation can retain that exact call as an unused statement and
return an `h("div", ...)` whose background comes from unrelated values. The
mechanism's requirement that the render “calls” the binding remains satisfied.
Even the prose mutation “render a different eager wash” is not made exact enough
to require failure when the approved call survives dead beside it.

C12 must freeze the result lineage: the value returned by the exact imported
call must reach the loading component's returned vnode style at both
`backgroundImage` and `backgroundColor`. A mutation that preserves the correct
call but paints unrelated values, plus result-shadowing/disconnection and
single-property substitutions, must RED. This remains inside the existing
frame-zero seat.

## RED-5 — compiler-sfc is not locked equal to Vue

The new package law requires ranges and lock enrollment for TypeScript,
`@vue/compiler-sfc` and PostCSS (`GATE-SEMANTIC-ROSTER-C11.json:922-934`). It does
not require the resolved compiler-sfc version to equal the resolved `vue`
version. The declared future ranges (`vue` currently `^3.5.34`, compiler-sfc
required as `^3.5.40`) can select different releases after a lock refresh while
still satisfying every listed acceptance clause.

The pinned install happens to resolve both to `3.5.40`, but coincidence in the
current transitive tree is not a machine law. C12 must require
`lockVersion(@vue/compiler-sfc) === lockVersion(vue)` at the root selected
versions and include a mismatch mutation. This is package preflight, not a
semantic seat.

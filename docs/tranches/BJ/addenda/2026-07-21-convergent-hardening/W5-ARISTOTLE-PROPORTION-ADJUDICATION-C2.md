## 1. Binding W5 grammar: JOB / FIT / ROUTE

W5 asks exactly three questions of each named current-paint site:

1. **JOB — what user-visible job does this space or cue perform here?** Use one concrete verb phrase:
   separate groups, bind siblings, reveal state, prioritize a heading, preserve a media aperture, or
   provide operating room. “Semantic mass,” “premium,” and “Aristotelian” are not jobs.
2. **FIT — what does current paint show?** The cue either performs that job without visible
   duplication, duplicates/dilutes/obscures the job, under-signals the job, diverges by engine, or
   cannot be decided from the evidence. This is a comparative visual judgment, not a ratio.
3. **ROUTE — what exact disposition and existing owner follow?** Choose one classification below and,
   for a current defect, name one already-seated owner. No owner means no authorized fix.

Every roster row contains exactly:

`row id · route/site · named visible body/cue · candidate/artifact identity · current capture ids ·
historical capture id if any · JOB sentence · FIT observation · classification · existing owner/gate ·
notes/limits`.

The only allowed classifications are:

- `CURRENT DEFECT — REMOVE`;
- `CURRENT DEFECT — NEEDS MORE AFFORDANCE/SPACE/SIGNAL`;
- `CANDIDATE-FIXED — VERIFIED IN BOTH ENGINES`;
- `ENGINE DIVERGENCE — OWNER PROOF OWED`;
- `HISTORICAL ONLY — NO CURRENT DEFECT`; or
- `INCONCLUSIVE — NO FIX AUTHORIZED`.

This vocabulary is intentionally asymmetric with implementation. `REMOVE` and `NEEDS MORE` route an
already-owned repair; they do not prescribe its bytes. `CANDIDATE-FIXED`, `HISTORICAL ONLY`, and
`INCONCLUSIVE` authorize no source work. An engine divergence stays with the existing owner and cannot
be averaged into a pass.

W5 is complete only when one immutable current candidate has a ratified roster containing at least one
honest `CURRENT DEFECT — REMOVE` and at least one honest `CURRENT DEFECT — NEEDS MORE ...`. If current
paint does not support one direction, W5 records the truth and remains incomplete. It must not invent a
defect to satisfy A10's two-direction shape.

### 2.1 Configurator A/B is exact and non-authoritative

The 25.9px/20.4px question is decided only by a same-content, same-route, same-viewport, same-theme,
same-engine comparison:

- **A** is the unmodified current artifact at `--configurator-section-size: var(--type-heading)`,
  resolving to the current 25.9px rung;
- **B** is a session-only author override to exactly 20.4px, recorded as an experimental stylesheet
  with its own byte digest; it is not a product artifact and earns no source credit;
- use one dense real Configurator and one sparse real Configurator if both exist in the named current
  routes; if only one exists, do not fabricate a lab and record the coverage limit;
- compare heading scan priority, wrapping, control-room loss, and confusion with field labels; hold
  weight, line-height, width, content, spacing, and all other styles fixed; and
- blind the A/B labels for the Sol judgment. A tie or viewport/engine split is `INCONCLUSIVE` or
  `ENGINE DIVERGENCE`, not permission to pick the numerically prettier rung.

Current CSS describes why the section size was widened; it does not contain a stale requirement that
20.4px must win. The design critic's source wording is retuned accordingly.

Configurator descriptions remain `text-micro` at the pinned source. W5 records one required prose
example and one terse-spec example because those are different jobs; it does not decree
“description ≥ meta.” MATERIAL W6 owns role mapping. The 24px reset is a plain compact control, and
current `R-COMPACT-HIT-FLOOR` expressly excludes plain compact controls. With no overlap, miss, or
accepted broad floor, **reset 44px is struck as a false positive**.

## RED-2 — Chip proves absent tabindex, not absent focusability

C13 materially repairs the C12 Chip hole. Its one future registration now mounts
with hostile `role="button"`, `tabindex="0"`, `aria-pressed="true"` and a
consumer click spy. It observes:

- initial selectable `BUTTON`, pressed/on/selectable;
- action `BUTTON`, action, no pressed/state; and
- static `SPAN`, static, no role/tabindex/pressed/state/descendant button or
  delivered consumer click.

Those requirements match the current branch structure in `Chip.vue`: control
attrs filter role/pressed/state, and static attrs additionally filter tabindex
and all `on*` listeners. The previous role, tabindex, stale-state and click
holes are directly covered.

The new predicate nevertheless says the final static host has no
**focusability**, not merely no `tabindex`. A span can be focusable without a
`tabindex`; the simplest exact counterexample is:

```html
<span data-mode="static" contenteditable="true">Mutable</span>
```

It is a `SPAN`, has no role, tabindex, `aria-pressed`, `data-state` or descendant
button, and need not receive the consumer click listener. Every C13 assertion
and mutation remains GREEN, while the final host is keyboard-focusable/editable
and is not the promised static non-control content. The committed component also
currently forwards `contenteditable` because `staticAttrs` does not exclude it;
the proposed hostile fixture simply never supplies it.

The phrase “forwarded activation” is broader than the single click listener as
well. The mechanism and mutation list prove only consumer click delivery; they
do not bind pointer, key or other consumer activation listeners. The exact
formation must either use the exact narrow words it proves—no role, no tabindex,
no pressed/state, no descendant button, and no forwarded click—or add a bounded
focusability/activation grammar with hostile fixtures and mutations. “Every
activation affordance” cannot be inferred from one event name.

Required C14 correction, in the same Chip seat: preferably narrow the predicate
and node-identity law to the exact host attributes and click path already frozen.
If actual non-focusability is intended, include `contenteditable` (and any other
admitted focus-producing host attribute) in the hostile fixture and assert the
settled host is not focusable. If all activation listeners are intended, define
the bounded listener set rather than using the unbounded word “activation.”

## 3. P0 defect — the immersive scrim leaves the one-axis glass system

At exact commit `dc566e34`, `src/components/drawer/styles.css:379-380` paints:

```css
[data-stage-scrim][data-stage-immersive]:not([data-backdrop="graded"]) {
    backdrop-filter: blur(var(--glass-blur-deep-radius));
}
```

Every calm composed rung in `src/styles/tokens/glass.css:183-205` scales its radius by `var(--glass-level)`. The opt-in deep recipe does the same at `src/styles/glass/deep.css:62-81`. `src/styles/glass/a11y-fallback.css:12-17,33-44,67-72` then sets the common level to 0, 0.3, or 0 for reduced transparency, high contrast, and forced colors. The new scrim rule reads none of that machinery.

This is not a theoretical style preference. The source's own deep-material contract says the a11y brackets reach the deep plate “through the ONE level path” and collapse it to `blur(0)`; the immersive rule creates a direct exception. The existing `glass-cohesion.spec.ts` level-zero matrix cannot catch it because its `KINDS` are only Drawer surface, Slider range, and Notification—not the shared immersive scrim.

**Smallest redress.** Keep the existing endpoint and avoid a new public family. Compose the private scrim blur through the same clarity scalar (for example, a private composed token or `blur(calc(var(--glass-blur-deep-radius) * var(--glass-level)))`) and prove the actual Dialog and Drawer scrims at level 1/0.3/0. The exact final syntax belongs to the bounded Luna redress, but a second accessibility axis does not.

**Born-RED acceptance.** Mount the actual flat immersive Dialog and Drawer receivers. At `--glass-level: 1`, read the selected 16px depth; at 0.3, read the chosen scaled/mostly-solid result; at 0, read no real blur and an opaque/system-legible plate. Cover `prefers-reduced-transparency`, `prefers-contrast`, forced colors, and `.glass-opaque` where applicable. A mutation restoring the direct unscaled radius must RED.

## 4. Canon correction — roles, magnitudes, and the deep axis

The useful part of the W2 table is the explicit collision inventory. Its ontology should be corrected to:

- **five calm surface roles:** wash, quiet, resting, floating, overlay;
- **three calm standard-density magnitudes:** 1, 7, 11px;
- **one device-conditional overlay arm:** 17px at ≥2dppx, still awaiting Sol paint/perf judgment;
- **one opt-in deep axis:** 11→16px and 1.6→1.8 endpoints, graded by surface prominence; and
- **one shared immersive-scrim use:** currently the raw deep endpoint, which must rejoin the clarity axis and receive an actual role judgment.

The exact deep grades make the distinction concrete: with the shipped `.glass-deep` map, content, popover, and menu resolve intermediate-to-endpoint depths rather than all becoming 16px. The W2 table's `deep = 16px` is true only for the endpoint/full-depth case and the new direct scrim use.

“One material per role” should mean one **composed role recipe and one backdrop sample**, not one radius number. The current Dock exception proves why: it deliberately uses the resting radius with a different saturation recipe. That may be a valid component retune, but it falsifies “dock + Card + menu-row are one material.”

## Chip exact-host boundary

C15's Chip row is internally exact. One lifecycle supplies hostile
`role=button`, `tabindex=0`, `aria-pressed=true`,
`data-state=caller-state` and the hostile consumer `onClick`. It captures the
component host after each settled transition and requires:

- selectable: `BUTTON`, `data-mode=selectable`, pressed true and state on;
- action: `BUTTON`, `data-mode=action`, with pressed and state removed; and
- static: the exact `SPAN` host, `data-mode=static`, with no hostile role,
  tabindex, pressed/state relation or component-owned descendant Button.

The click is dispatched at that captured static host and the hostile spy must
remain zero. The born-RED listener mutation now puts that exact hostile
`onClick` on that exact host. Descendant-originating clicks, consumer-authored
slot descendants, `contenteditable` and unlisted event types are explicitly
outside the promise. A listener moved to a non-Button child therefore no longer
contradicts this host-only row, while forwarding it to the governed host fails
the required dispatch. This closes the host-versus-descendant ambiguity without
silently widening the seat.

The committed Chip source matches the formation: control attrs strip the
pressed/state/role relations, static attrs additionally strip tabindex and all
`on*` values, and the final static branch is a native `span` with no owned
button descendant.

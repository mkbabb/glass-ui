## Assay law

An item is not removed because its name sounds fanciful, because one story
imports it, or because a larger component could absorb it. It becomes a
subtraction candidate only when the exact boundary fails C45 and a simpler
surviving owner is named. The following distinctions govern every disposition:

1. **Route duplication is not component duplication.** A thin or repeated story
   can fold while its public component remains necessary.
2. **Demo infrastructure is not package API.** A helper used by many stories can
   remain private even though no application consumer needs it.
3. **A documentation fixture is not a component ontology.** Raw-source examples
   may survive next to the one story that renders them without living in a
   global pseudo-component folder.
4. **Two responsive presentations are not two state engines** when both consume
   one route/state authority and one presentation nests the other.
5. **A public prop is not justified by declaration alone.** A dead or one-fixture
   branch needs exact downstream prop-grain evidence before it survives a clean
   break.
6. **A low-level renderer survives when it has a distinct job.** Duplicate live
   demo canvases are folded before deleting the renderer they exercise.

## Exact candidate evidence

### 1. Story Chassis route versus the actual shared chassis

`demo/stories/compositions/chassis.vue` is a 120-line public-gallery route whose
only job is to demonstrate the demo kit using ordinary Button, Badge, and Switch
specimens. Its manifest prose promises five demo kinds, including “Stage,” while
the SFC renders Specimen, Interaction, Grid, and Composition sections and no
Stage. The route therefore documents its own private authoring machinery while
duplicating elementary component specimens.

That does **not** make the underlying demo chassis overfit:

- `StoryPage` is imported by 103 story SFCs;
- `StorySection` is imported by 88 story SFCs;
- `ShowcaseFrame` is imported by 28 story SFCs; and
- `FamilyTabs` is imported by seven story SFCs.

The shared helpers own consistent story identity, hierarchy, spacing, specimen
framing, and family navigation. Removing them would duplicate layout and
semantics across the gallery. The parsimonious cut is the **Story Chassis route**,
not `demo/chassis/`.

Disposition: **REMOVE-CANDIDATE** from the gallery. If author documentation is
still useful, reduce it to a non-routed contributor note derived from the actual
shared components. A mutation restoring the route without a truthful,
nonduplicated authoring job must fail route-taxonomy uniqueness.

### 2. Whole Compositions category and Gate Pattern

`demo/stories/compositions/` contains exactly six demo-only pages:
`auth-shell`, `chassis`, `empty-states`, `form-validation`, `gate-pattern`, and
`settings`. `ASK-REDUCTION.md` already records that none is a source or external
consumer and that the only direct test blast radius is Gate Pattern's import in
`tests/components/dialog.confirm-preset.test.ts`.

`gate-pattern.vue` is especially diagnostic. It declares itself a composition,
not a component; owns local `unlocked`/`invalid`/shake choreography and the
hard-coded key `wolfpack`; blocks Escape, outside interaction, and pointer
dismissal; and composes a Card preview with the real Dialog. The direct test's
only Gate-story assertion is that its opener begins with
`aria-expanded="false"`. Nothing here justifies a Gate producer, export, or
separate route.

Disposition: **FOLD Gate Pattern's useful non-dismissible/busy/focus evidence
into the canonical Dialog story and direct Dialog tests**, then delete the route.
The six-route category remains a **REMOVE-CANDIDATE**, but execution must first
map any unique auth, empty-state, validation, or settings recipe into the owning
component story or contributor documentation. No empty `scene` taxonomy is
minted to remember the category.

### 3. Motion Tempo, Spring Orchestrator, and Motion Lab

The underlying tempo mechanism is load-bearing:

- `src/composables/motion/core/motionTempo.ts` reads the one inheriting
  `--motion-tempo` scalar;
- `useSpring`, `useElementMorph`, Dock's `useDockSpring`, and Drawer's
  `useDrawerSnap` consume it; and
- the Springs story already reads it for named and playground projections.

The **route** is thin. `demo/stories/motion/tempo.vue` owns one slider, writes a
global root custom property from `watchEffect`, removes it on unmount, and
demonstrates ordinary overlay and Dock receivers. The Dock is keyed by the tempo
value, so changing the knob remounts the specimen instead of proving continuous
retuning. ASK-5 already selects the narrow solution: fold the global-time knob
into Spring Orchestrator and drop `/motion/tempo` without touching source motion
mechanics.

Motion Lab is different. `curve-gallery.vue` exercises the actual preset table,
direct keyframes playback, overlay register, and easing-authoring seam. Spring
Orchestrator owns spring parameter tuning and interruption. Those are two
distinct authoring jobs.

Disposition: **FOLD Motion Tempo; KEEP Spring Orchestrator and Motion Lab**.
The folded knob must use one reversible owner and prove real receiver retuning;
it may not keep root-state leakage or a keyed remount as the demonstration.

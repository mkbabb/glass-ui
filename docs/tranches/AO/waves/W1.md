## Scope

1. **W1.1 — gate-truth design.** WHAT — specify D1 (the gate measures the combined consumer draw): `scripts/profile-bundle.mjs` must measure `dist/styles/index.css` with its `@import` graph flattened (resolve `index.css` + the folded `glass-ui.css`), so the gated number is the ~10.2 KiB combined draw, not the 7805-gzip SFC fragment. Specify D2 (the dist-share fix): either fold `publishStyleAssets()` into a shared plugin list both `vite.config.ts` + `vite.iter.config.ts` consume (so iter-build is canonical-minus-dts), OR give iter-build a disjoint `dist-iter/` outDir; name `emptyOutDir` default-true as the cause. Specify D5 (per-subpath enforcement): promote the reported `subpathEntries` table to enforced caps (or a drift-% threshold against the committed baseline), starting with the heavy entries (`aurora`, `dock`, `configurator`, `command`). WHY — a gate that measures a file no consumer imports in isolation is a false witness (AO inv α); the cascade arm must be inside the gated number so a regression there fails CI; the dist-wipe footgun (AO inv β) is why the gate could never see the real artifact.
2. **W1.2 — CSS re-base + cascade-consolidation design.** WHAT — specify D4 (re-base the ceiling): derive the new ceiling from the real combined draw (~10.2 KiB gzip measured) plus a justified slack margin, retiring the SFC-only 8650 ceiling and the N.W0→P.W0→P.W3→Q.W4 bump-at-every-close cadence. Specify D6 (cascade consolidation): a per-rung plan across the 18 `styles/` files — dedup duplicated declarations, consolidate adjacent `@theme`/`@utility` recipes, retire any rung with zero consumers (gated by the overfitting audit before any retire). WHY — the budget must track what ships (a principled single re-base, not an arbitrary bump); the consolidation reclaims genuine headroom against the honest number, the gestalt-redesign answer over the patch-when-the-gate-trips reflex.
3. **W1.3 — legacy-purge + build-resync + changeset-release design.** WHAT — specify the inv-47 `useSpringOrchestrator` deletion + its migration map: delete `src/composables/motion/useSpringOrchestrator.ts`, drop the `export *` at `src/composables/motion/index.ts`, migrate the 3 demo sites (`demo/stories/motion/springs.vue`, `demo/stories/composables/use-spring-orchestrator.vue`, `demo/stories/manifest.ts`) + the 2 shim cases in `src/composables/__tests__/useNumericTransition.test.ts` to `useNumericTransition`, scrub the v3.0-retire comments in `src/motion.ts` + `src/index.ts`. Specify the heap-prefix drop sites (`package.json:481` build, `package.json:482` build:watch, `scripts/release.sh:81`, `.github/workflows/release.yml:31`) + the §Build resync target prose (describe the real `vue-tsc --project tsconfig.build.json` out-of-band dts emit; no api-extractor / vite-plugin-dts / 6.7 GB / 8 GB-required prose). Specify the changeset-driven version decision — default 3.0.0 (the alias-removal break, the first changeset-driven major), routed `changeset add` → `changeset version` → tag. WHY — the alias is the lone live inv-47 / L-inv-4 violation (clean break, zero external consumers, no replacement alias); the heap prefix is dead weight for a vanished api-extractor toolchain; the §Build prose is stale fiction; the alias removal is the natural occasion to exercise the first real changeset-driven release.

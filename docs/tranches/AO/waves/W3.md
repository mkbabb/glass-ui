## Scope

1. **R0G-1 — Aurora demand-driven / visibility-paused render loop (perf, existing primitive).** WHAT — the Aurora canvas runs a perpetual full-motion compositor loop at idle on every route (~4 fps / ~100% GPU measured at idle; the same surface holds 118 fps / 0 long-tasks under `prefers-reduced-motion`, proving the cost is the loop, not the paint). Convert the per-frame RAF loop to a **clock-owned, demand-driven** loop that pauses on steady-state (no active animation/interaction) and suspends on `document.visibilitychange` (tab hidden → stop scheduling; visible → resume), continuing to honor `prefers-reduced-motion` (which already renders a single static frame). The loop lives in `src/components/custom/aurora/` (the `useAurora` composable / `Aurora.vue` render-mode plumbing); read the existing `renderMode.ts` + the composable to find the RAF site. WHY — the idle full-motion loop is in the primitive; no consumer-side band-aid is possible. The fix is the idiomatic gestalt move (a loop that runs only when there is motion to render), not a throttle hack.
2. **R0G-2 — InstrumentChassis breakpoint-correct child-geometry reserve (CLS correctness, existing primitive).** WHAT — on mobile (390px) the `instrument-dial` re-seats ~326-331px AFTER the chassis settles → mobile-only CLS 0.32-0.38; desktop holds ≤0.013 (the desktop axis already uses transform-based idle centring). Make the chassis reserve its child (dial) FINAL box from frame 0 **at every breakpoint** (`aspect-ratio` / min-height reserve in `src/styles/instrument-chassis.css` + any `InstrumentChassis.vue` layout binding), and ensure any idle→active recentre is **transform-only** (no layout-affecting property animates). The chassis must not reflow children post-paint at the mobile breakpoint. WHY — the child layout is in the primitive; the consumer cannot fix it idiomatically (a consumer `min-height` band-aid is the workaround the directive forbids). Reserve-then-transform is the canonical no-CLS pattern.
3. **R0G-3 — `useIdleReady` composable (substrate promotion — clears the ≥2-consumer gate).** WHAT — create `src/composables/dom/useIdleReady.ts` as the canonical `requestIdleCallback` (+ `setTimeout(0)` fallback) post-mount idle gate, the rIC-sibling of the shipped `useViewportReady` (read `src/composables/dom/useViewportReady.ts` for the sibling signature/shape to stay consistent). Promote the scope-aware variant (the `useIPInfo` site passes a scope/target) as the canonical signature. Export it from `src/composables/dom/index.ts` (and thereby the `composables/` barrel + the curated root barrel, matching how `useViewportReady` surfaces). Add a co-located test mirroring `useViewportReady.test.ts`. WHY — speedtest hand-rolls this gate at **5 sites** (`App.vue`, `MapView.vue`, `DashboardMap.vue`, `useAutoStart.ts`, `useIPInfo.ts`); 5 consumers clear J inv 10 / L inv 8 — this is a justified promotion, not a substrate-without-consumer invention. It is the consumer-gap the W0 audit read as empty because AQ had not surfaced it.
4. **R0G-4 — `Toaster` `position` prop (API completeness).** WHAT — add a `position?: "top-center" | "top-right" | "bottom-right" | "bottom-center" | …` prop to `src/components/ui/toast/Toaster.vue` driving the teleported viewport anchor (the `ToastViewport` positioning classes); default to the current bottom-right so no consumer regresses. Co-export any new type from `src/components/ui/toast/index.ts`. WHY — `<Toaster>` hardcodes a bottom-right desktop anchor; speedtest needs a top anchor (a degraded-path error toast must not overlap the bottom dock) and currently overrides the published `.z-toast` utility from consumer CSS — a bridge, not a fix. The prop is additive API completeness; the default keeps every existing consumer unchanged.

## §4 — The changeset / version decision

The changeset rides ONE release for the alias break AND the five additive speedtest-AQ consumer items (R0G-1..5, landed in AO.W3 + AO.W4) — not a 2.2.0-then-3.0.0 two-step. The five additive items do not themselves force a major, but they ship in the same cut; the major comes from the alias removal.

### Command sequence (AO.W5 — the close ceremony; NOT W2)

The version bump is AO.W5's item, not W2's — W2 deletes the alias and leaves the version at 2.1.0; W5 cuts the release after W3/W4 land. The sequence:


The single changeset body (the markdown under the front-matter) MUST enumerate, in one summary, both the break and the five additive items:

- R0G-4 — `Toaster` `position` prop (additive; default unchanged).

The `changelog: "@changesets/cli/changelog"` config writes the CHANGELOG.md from this body. After `changeset version` the implementer commits the version bump + CHANGELOG; the **publish leg (`changeset publish` / `npm publish` / `git push` / tag) is user-domain** (needs the `NPM_TOKEN` secret + GitHub push authority — OMEGA perimeter).

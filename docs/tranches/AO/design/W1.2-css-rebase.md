The budget gate now measures the real combined `dist/styles/index.css` draw (W1.1: **80827 gzip**, 17 cascade rungs + the folded SFC). **§Style-discipline.** Consolidation is dedup against a true ceiling, not a budget-raise to paper over weight. D4 sets ONE principled number; D6 earns headroom by deletion, not by lifting the cap. No rung is retired without an overfitting-audit proof of zero consumers.

## § The proof:theme contract — preserve it through consolidation

`proof:theme` (`npm run proof:theme` → `scripts/proof-theme-style.mjs`) is the byte-clean gate the W4 consolidation must keep green. What it actually checks:

1. **Every cascade rung ships + resolves.** The probe imports `src/styles/index.css` (`:210`) — which `@import`s all 17 rungs — and builds it through real Tailwind, then asserts 30 probe classes generate (`:24-56`) AND 10 `@theme`-resolution assertions hold (`:58-69`, e.g. `rounded-card → border-radius: var(--radius-card)`, `z-dock → z-index: var(--z-index-dock)`, `animate-dock-in → animation: var(--animate-dock-in)`). If D6 drops or renames a token a probe depends on, or drops a rung from `index.css`'s `@import` list (`index.css:88-104`), the probe class vanishes and the gate FAILS.
2. **No self-referential `@theme` var, no forbidden namespace, no retired-token reintroduction, no brittle pattern** (`transition: all`, `z-50`, broad `:deep(*)`) — the static checks (`:119-196`).

**How the consolidation preserves it (binding rules for the W4 D6 implementer):**
- **No rung leaves `index.css`'s `@import` cascade** unless the overfitting audit proved zero consumers AND no probe/assertion depends on a token it uniquely declares. The "byte-clean" gate is "every rung ships" — a dedup that MOVES a declaration between rungs is fine; a dedup that DROPS a rung silently is the failure the gate catches.
- **Any token a `cssAssertion` references (`--radius-card`, `--card-shadow`, `--z-index-dock`, `--animate-dock-in`, `--font-display`, `--leading-display`, `--tracking-caps`, `--color-gold`) is load-bearing — do NOT rename or inline it.** The theme.css radius de-duplication (§D6 theme.css) specifically touches `--radius-card`, which `proof:theme:65` asserts — run proof:theme against that change before committing it.

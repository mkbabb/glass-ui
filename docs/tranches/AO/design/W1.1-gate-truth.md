# AO.W1.1 — Gate-truth design slice (D1 · D2 · D5)

The budget gate must measure what consumers draw, the two Vite configs must stop wiping each other's `dist/`, and the per-subpath table must graduate from informational to enforced. This doc specifies all three to implementation grain — an implementer writes the code with no further design choice. It binds AO.W2 (D1 + D2) and AO.W4 (D5).

Every number below is measured against the live `dist/` (canonical build at HEAD, timestamp 12:39), not invented. The build is fresh and complete (`dist/styles/index.css` + `dist/fonts/` present), so the numbers are ground truth.

**The honest combined consumer draw is 80827 gzip ≈ 79 KiB** — the gzip of the full resolved graph (the 17 cascade rungs + the folded SFC), NOT the 10.2 KiB the AO plan estimated. The plan's "~10.2 KiB" (and an earlier read of this doc) counted only `index.css`'s own entry text (2441 — comments + `@import` references) plus the folded SFC (7818); both were blind to the 17 cascade files `index.css` actually resolves. That undercount is itself a symptom of the gate-blindness inv α closes — nobody had measured the resolved cascade. `fonts.css` (139272 raw, 99 KiB-class) is correctly NOT in this number: `index.css` does not `@import` it (it is the separate `/styles/fonts` subpath).

**What the number means.** These cascade files are the CSS glass-ui publishes in its package and a consumer's bundler resolves through the single `@import "@mkbabb/glass-ui/styles"`. Most of the weight ships to the browser verbatim — the `@theme` custom properties (tokens.css), and all the plain CSS rules (`.glass-*`, `.dock-*`, the SFC scoped CSS). The `@utility`/`@apply` arm (utilities.css) is the one part the consumer's Tailwind tree-shakes, so gating its full source is a conservative over-count — acceptable for a package-weight gate, and the part the W4 consolidation (D6) most reduces. The gate measures glass-ui's published `/styles` source bytes: an honest, regression-sensitive proxy where a byte added to ANY rung moves the gated number (inv α). This is the number the gate gates.

The K W4 baseline JSON (`docs/tranches/K/audit/W4-bundle-profile.json`) carries exactly one CSS file entry — `dist/glass-ui.css` at gzip 7805 — and **no `dist/styles/index.css` entry at all**. That absence is the footgun's fingerprint: the baseline was generated through `iter-build`, which never emits `dist/styles/`. The gate has been blind to the cascade arm since K. The "90.2% near-breach" GAMMA surfaced (7805 / 8650 = 90.2%) was a measurement against a 7.8 KiB fragment no consumer imports in isolation, not a real crunch — the real draw is ~79 KiB, an order of magnitude past the old SFC-only ceiling, because the old ceiling measured the wrong (tiny) artifact.

## § D1 — the gate measures the real consumer artifact (inv α)

### WHAT

Change the CSS arm of `scripts/profile-bundle.mjs` so the gated CSS number is the **combined `dist/styles/index.css` draw with its one folded `@import` resolved** — the cascade entry plus the AN.W1-folded SFC bundle — gzipped as one stream. Retire `dist/glass-ui.css` as the gated CSS key.

### WHY

`@import "@mkbabb/glass-ui/styles"` resolves through `package.json` exports (`"./styles": "./dist/styles/index.css"`, line 217) to `dist/styles/index.css`. That file ends with `@import "../glass-ui.css";` (the AN.W1 fold, injected by `publishStyleAssets` at `vite.config.ts:104`), so the consumer's bundler inlines the SFC-scoped component CSS too. No consumer imports `dist/glass-ui.css` in isolation — it is reachable only via the `./styles.css` transparent export (line 219), which exists for a cascade-free consumer, not the default path. Gating the SFC-only file is a false witness: a regression in `tokens.css`, `theme.css`, or `utilities.css` never moves the gated number, exactly the blindness inv α closes.

### The @import-flatten approach — concrete

The gate resolves the FULL `@import` graph of `dist/styles/index.css` — both the 17 sibling cascade files (`./tokens.css`, `./theme.css`, `./utilities.css`, … `dist/styles/index.css:88-104`) AND the folded SFC (`@import "../glass-ui.css";`, `:110`) — and gzips the concatenation. This is the published `/styles` source the consumer's single `@import "@mkbabb/glass-ui/styles"` resolves; it is what glass-ui ships and the only number where a regression in ANY cascade rung (a token added to `tokens.css`, a rule grown in `glass.css`/`dock.css`) moves the gated value. Gating the SFC-only file (or the SFC + index-text only) is a false witness that leaves the cascade arm — 79 KiB of the 80 KiB draw — untracked, exactly the blindness inv α closes.

The cascade files have no nested `@import`s (they are leaf rungs), so this is a one-level resolve of the 18 references in `index.css` — a small inline resolver, no postcss dependency. The `@import` regex matches only real (non-commented) `*.css` references; commented examples in the doc-header (`@import "tailwindcss"`, `@import "@mkbabb/glass-ui/styles.css"`) either lack a `.css` target or resolve to a nonexistent path and fall through unchanged via the `existsSync` guard.

Concrete resolver (add to `scripts/profile-bundle.mjs`, a helper near `walk`):

```js
// AO.W2 (inv α) — the real consumer-draw CSS artifact.
// `@import "@mkbabb/glass-ui/styles"` resolves to dist/styles/index.css, which
// @imports the 17 sibling cascade rungs (./tokens.css …) AND the folded
// ../glass-ui.css (the AN.W1 SFC fold). Resolve ALL of them and gzip the
// concatenation — that is glass-ui's published /styles draw. A byte added to
// any cascade rung moves this number (the cascade arm is INSIDE the gate).
function combinedStylesDraw(distRoot) {
    const stylesDir = resolve(distRoot, "styles");
    const indexPath = resolve(stylesDir, "index.css");
    if (!existsSync(indexPath)) return null;
    let css = readFileSync(indexPath, "utf-8");
    // One-level resolve: ./*.css siblings + ../glass-ui.css both resolve under stylesDir.
    css = css.replace(/@import\s+["']([^"']+\.css)["'];?/g, (m, ref) => {
        const target = resolve(stylesDir, ref);
        return existsSync(target) ? `\n${readFileSync(target, "utf-8")}\n` : m;
    });
    return { raw: Buffer.byteLength(css), gzip: gzipSync(css).length };
}
```

### Gate wiring

- The `BUDGETS` map (`scripts/profile-bundle.mjs:78-81`) drops the `"dist/glass-ui.css"` key and gains `"dist/styles/index.css"` (the consumer-facing path). The JS budget (`"dist/glass-ui.js"`) is unchanged.
- The budget-evaluation loop (`:187-215`) currently does `files.find((f) => f.file === path)`. For the new CSS key it must use `combinedStylesDraw(distRoot)` rather than the per-file `files` lookup, because the gated bytes are the resolved concatenation, not any single file's on-disk size. Branch the loop: when `path === "dist/styles/index.css"`, source `{raw, gzip}` from `combinedStylesDraw`; otherwise keep the `files.find` path for the JS entry. A `null` return (the file absent — footgun not yet closed) reports `MISSING` and sets `anyBudgetExceeded`, the same fail-closed shape the existing loop uses for a missing entry.
- The ceiling value W2 ships for the CSS key is **the honest combined number, headroom-padded by W4** — W2 lands the measurement; W4's D4 re-bases the constant. For the W2 interim, set the CSS ceiling to the measured combined draw plus the canonical ~10% tranche-close headroom (gzip 80827 → ~89000), and leave the precise re-base to W4 D4 so the constant is set once against the post-W3-chassis-CSS, post-R0G-5-token, post-consolidation final cascade. The W2 hard gate (gate-passes-on-HEAD) only requires the gate exit 0 against whatever ceiling is in place — the interim padded number satisfies it.
- The persisted artifact (`W4-bundle-profile.json`) and the stdout budget report inherit the new key automatically through the same `budgetReport` rows — no separate change.

### Verification (W2 hard gate items 2-4)

- **Measures `dist/styles`** — `npm run profile:budget` reports a `[PASS|FAIL] dist/styles/index.css — gzip <n>/<ceiling>` line where `<n>` ≈ 80827, not the 7818 SFC fragment. The W2 audit doc records the measured combined number.
- **Fails on synthetic cascade-arm regression** — inject a large byte run into a cascade-arm file in the resolved graph (`dist/styles/tokens.css`, `theme.css`, or `utilities.css`) and confirm the resolved-draw gzip crosses the ceiling and the gate exits 1. Because the resolver inlines every cascade `@import`, the injection moves the gated number directly — this is the inv-α property the SFC-only gate lacked. (Inject into the BUILT `dist/styles/*.css` for the probe so no source is touched; revert by re-running the build. Equivalently a source-side `src/styles/*.css` injection that rebuilds into dist would trip it — the dist-side probe is faster and source-clean.) Record probe + revert in the audit doc.
- **Passes on HEAD** — against the W2 interim padded ceiling (~89000), `npm run profile:budget` exits 0; on HEAD pre-rebase it reports the honest ~80827 for W4's D4 to consume.

## § D2 — close the dist-wipe footgun (inv β)

### WHAT

Make `iter-build` produce the same `dist/` shape as the canonical build by **sharing `publishStyleAssets()` across both Vite configs** (Option (a), RECOMMENDED). Extract `publishStyleAssets` into a module both `vite.config.ts` and `vite.iter.config.ts` import; iter-build becomes canonical-minus-dts.

### WHY — root cause

Neither config sets `outDir` or `emptyOutDir`, so both default to `outDir: "dist"` with `emptyOutDir: true` (Vite empties an `outDir` that sits inside the project root by default). `vite.config.ts` carries `publishStyleAssets()` in its plugin array (`:156`); `vite.iter.config.ts` carries only `[tailwindcss(), vue()]` (`:12-15`) and omits it. So:

- The canonical `npm run build` emits the full `dist/`: the JS entries, the extracted SFC `dist/glass-ui.css`, AND `publishStyleAssets`'s `dist/styles/` (cpSync'd cascade + the AN.W1 fold) + `dist/fonts/`.
- `npm run iter-build` empties `dist/` (the default `emptyOutDir`), emits the JS entries + `dist/glass-ui.css`, but **never recreates `dist/styles/`** — no `publishStyleAssets`, no fold.

`scripts/profile-bundle.mjs`'s `runBuild()` (`:99-107`) invokes `npm run iter-build`. So every `profile:budget` run wipes the canonical `dist/styles/` and leaves the gate nothing to read at the D1 target path — the precise reason the K baseline JSON has no `dist/styles/index.css` entry, and the reason AN.W7 + muster G.W3 had to "re-run the canonical build last." `emptyOutDir` default-true is the root cause; the asymmetric plugin arrays are the trigger.

### The fix — Option (a), shared plugin

RECOMMENDED over Option (b) (a disjoint `dist-iter/` outDir) because (a) makes iter-build produce the **same dist shape** the gate reads — so `combinedStylesDraw` finds `dist/styles/index.css` after an iter-build, with no second canonical build needed. Option (b) leaves `dist/styles/` stale-or-absent under the iter path, so the gate would read a fork that drifts from what ships; (a) is the only option where the measured artifact and the published artifact are the same bytes. Option (a) also retires the AN.W7 / muster-G.W3 "re-run build last" workaround at its cause rather than routing around it.

`publishStyleAssets` is pure post-build file copy/rewrite gated `apply: "build"` (`vite.config.ts:63`) — it has no dts coupling, no extra build-time cost beyond the cpSync + the woff2 base64 inline. iter-build adopting it makes iter-build = canonical-minus-the-out-of-band-`emit-types`-step, which is exactly the contract `iter-build` already advertises (a fast build that skips dts emit).

### Exact edit shape

**New file `vite.style-assets.ts`** (greenfield voice — a shared plugin module, not "extracted from"):

Move the entire `publishStyleAssets` function body (`vite.config.ts:60-142`) into this module verbatim, including its leading doc-comment block (`vite.config.ts:14-59`). Keep `__dirname` resolution working — the module sits at repo root alongside the two configs, so `__dirname` resolves to repo root identically; the `closeBundle` body uses `const root = __dirname;` (`:65`), which stays correct.

**`vite.config.ts`** — delete the inlined function + its doc block (`:14-142`), add `import { publishStyleAssets } from "./vite.style-assets";` next to the other imports (`:7-12`). The plugin-array reference (`:156`) is unchanged.

### Verification (W2 hard gate item 5)

- After `rm -rf dist && npm run iter-build`, `ls dist/styles/index.css dist/fonts/` both succeed and `dist/styles/index.css` ends with the folded `@import "../glass-ui.css";`.
- A `npm run profile:budget` run (which calls iter-build) leaves `dist/styles/index.css` + `dist/fonts/` present afterward — the audit doc records the before/after `dist/` tree. No "re-run the canonical build last" step.

## § D5 — per-subpath enforcement (lands at AO.W4)

Designed here, implemented at W4 (D1 + D2 land first at W2 so the gate reads a stable `dist/styles` shape; D5 builds on the same `subpathEntries` table).

### WHAT

Promote the reported `subpathEntries` table (`scripts/profile-bundle.mjs:157-165`) from informational to **enforced via a drift-% threshold against the committed K W4 baseline**, not absolute per-chunk caps.

### WHY drift-% over absolute caps

The `subpathEntries` table already classifies every `dist/*.js` chunk as `entry` (a published subpath a consumer imports) or `shared` (a Rolldown-extracted leaf). The K baseline JSON carries the full per-chunk gzip ledger (`subpathTable`, 130 entries, 65 of kind `entry`). Absolute caps for 65 entries would be 65 hand-maintained constants that rot at every legitimate addition and invite the same per-tranche "re-baseline the constant" churn the CSS budget comment chain (`:26-77`) documents. A **drift-% threshold against the committed baseline** flags a *regression* (an entry that grew unexpectedly) while letting legitimate growth re-baseline by committing a new `W4-bundle-profile.json` — one artifact, one gate, no constant-per-chunk maintenance.

### Threshold shape — concrete

- **Baseline source.** Read `docs/tranches/K/audit/W4-bundle-profile.json`'s `subpathTable`, keyed by chunk `name`, kind `entry` only (shared leaves are content-hashed and their names rotate per build — they are not stable enough to drift-gate; the entry chunks have stable names). NOTE: the K baseline was generated through the footgun and predates D2, so its chunk names are valid but its CSS row is the false witness — D5 reads only its **JS entry** rows, never its CSS. **W4 must regenerate and re-commit `W4-bundle-profile.json` post-D1/D2** so the baseline itself reflects the honest dist shape; D5 then drifts against that fresh baseline.
- **Per-entry drift gate.** For each baseline `entry` chunk, compute `drift = (current.gzip - baseline.gzip) / baseline.gzip`. FAIL the chunk (under `--enforce`) when `drift > DRIFT_CEIL`, with `DRIFT_CEIL = 0.10` (10% — matching the tranche-close headroom convention the CSS budget uses). A chunk present in the baseline but absent from current dist is a `MISSING` FAIL (a published subpath vanished); a chunk in current but absent from baseline is reported but not failed (a new subpath — re-baseline to adopt it).
- **The heavy entries the threshold guards.** The chunks where a regression actually costs payload, from the live dist (gzip): **`aurora.js` 16307** (the standalone WebGL chunk the root barrel never reaches), **`glass-ui.js` 8644** (the root barrel), **`typewriter.js` 5630**, **`dock.js` 5189**, **`search.js` 4581**, `timeline.js` 4115. `configurator.js` (212 gzip) and `command.js` (196 gzip) are tiny re-export shims whose content lives in shared leaves — a 10% drift on a 212-byte shim is 21 bytes of noise, so the drift gate must apply a **floor**: skip the drift check for any entry whose baseline gzip is below `MIN_GATED_GZIP = 1024` (1 KiB), so the gate spends its enforcement on the chunks that move the payload (aurora, dock, glass-ui root, typewriter, search, timeline, …) and does not flap on shim-sized re-export entries.
- **Wiring.** Add a `subpathReport` array alongside `budgetReport` (`:184`) and fold its FAILs into `anyBudgetExceeded` (`:185`) so `--enforce` exits 1 on a subpath drift breach. Emit a per-chunk `[PASS|FAIL|MISSING] dist/<name>.js — gzip <cur> vs baseline <base> (drift +<n>%)` line in the same rg-friendly format as the CSS/JS budget report (`:294-303`). The informational table (`:241-287`) stays — D5 adds enforcement, it does not remove the disclosure.

### Verification (W4 hard gate — D5)

- The K baseline (regenerated post-D1/D2) drives the per-entry drift gate; on HEAD every `entry ≥ 1 KiB` chunk is within +10% and `profile:budget` exits 0.
- A synthetic gzip-inflating edit to a heavy entry's source (e.g. a large dead-code string in an `aurora/` module) pushes `aurora.js` past +10% drift and trips the gate; revert restores PASS. Probe + revert recorded in the W4 audit doc.

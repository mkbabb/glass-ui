## T3 — the aurora suspend-source set (binds AP.W3 scope item 3)

### The disease at HEAD

`running` (`runtime.ts:164`) is one boolean written by THREE uncoordinated suspend sources:

1. the runtime's OWN `document.visibilitychange` listener, added inside `arm()` at `runtime.ts:502-508` (`onVisibilityChange` → `pause()`/`resume()`);
2. the outer `pause()`/`resume()` API at `runtime.ts:483-494` (delegated through the returned object at `runtime.ts:567-574`), which the Vue wrapper drives;
3. `useIntersectionPause` wired in `useAurora.ts:239-242`, which observes BOTH viewport-intersection AND document-visibility and calls `inst.pause()`/`inst.resume()`.

So tab-visibility is observed TWICE (source 1 inside the runtime, source 3 inside `useIntersectionPause` which also watches `document.hidden`) and intersection once, all collapsing onto `running`. `resume()` (`runtime.ts:489-494`) early-returns on `if (running)` then unconditionally sets `running = true` and restarts `tick()`. The failure path is the classic un-refcounted suspend: scroll Aurora off-screen (source 3 → `inst.pause()`) THEN flip the tab away and back (source 1 → `onVisibilityChange` → `resume()`) → the loop resumes RAF while the canvas is still off-screen. The `if (running)` guard at `runtime.ts:490` does not catch this — after the off-screen `pause()`, `running` is `false`, so the tab-show `resume()` runs the loop back on.

The two prose blocks that exist ONLY to reconcile the two visibility observers:
- `runtime.ts:496-500` — the "Runtime-level document-visibility suspend (R0G-1) … Idempotent with that seam" comment.
- `useAurora.ts:561-566` — this exact line range in the wave spec maps to the deferred-path explanatory comment in `useAurora.ts`; at HEAD the equivalent prose is the `pause`/`resume` returned-object comment at `runtime.ts:561-566` (the "setting `running` here first would make the inner resume() early-return … the useIntersectionPause re-show seam" block). Both blocks RETIRE under T3 — once `running` derives from a set there is no "two observers don't fight" invariant left to explain.

### The gestalt — refcount the suspend-source set

Replace the `running` boolean with a `Set<SuspendReason>` named `suspended`. The loop runs IFF the set is empty.

```ts
type SuspendReason = "tab-hidden" | "off-screen" | "manual";
const suspended = new Set<SuspendReason>();
const isRunning = () => suspended.size === 0;
```

`suspend(reason)` adds the key; `resume(reason)` removes it. Only the EMPTY→non-empty transition stops RAF, and only the non-empty→EMPTY transition restarts it:

```ts
function suspend(reason: SuspendReason): void {
    const wasRunning = isRunning();
    suspended.add(reason);
    if (wasRunning && !isRunning()) {
        cancelAnimationFrame(raf);
        raf = 0;
    }
}

function resume(reason: SuspendReason): void {
    const wasSuspended = !isRunning();
    suspended.delete(reason);
    if (wasSuspended && isRunning()) {
        startTime = performance.now() - 1000;
        tick();
    }
}
```

`tick()` gates on `isRunning()` instead of `running` (replaces `runtime.ts:456`); `wake()` gates on `isRunning() && !raf` (replaces `runtime.ts:476`); the `if (running) raf = requestAnimationFrame(tick)` arm gate at `runtime.ts:467` becomes `if (isRunning()) …`. The capture-mode seed `running = options.mode !== "capture"` (`runtime.ts:164`) becomes: a capture runtime pre-seeds the set with `"manual"` (`if (options.mode === "capture") suspended.add("manual")`) so a capture instance never auto-runs, exactly matching today's `running = false` for capture.

### One observer per concern — lift tab-visibility OUT of arm()

The doubled visibility observation is the structural bug. Resolve it by OWNERSHIP:

- **Tab-visibility** — ONE owner. Lift the `document.visibilitychange` listener OUT of `arm()` (delete `runtime.ts:501-508`) and let it call `suspend("tab-hidden")` / `resume("tab-hidden")`. It is wired at the runtime level (not inside `arm()`) so every consumer — eager, capture-then-live, always-on-screen — still gets a tab-hidden pause, which was the whole point of the AO `runtime.ts:496-508` patch. Because the listener now keys on the dedicated `"tab-hidden"` reason and never touches `"off-screen"`, a tab-show can never clear an off-screen suspension.
- **Intersection** — ONE owner. `useIntersectionPause` in `useAurora.ts:239-242` keeps owning viewport-intersection, but it MUST stop double-observing document-visibility. The wrapper's `pause`/`resume` callbacks (`useAurora.ts:241-242`) map to `suspend("off-screen")` / `resume("off-screen")` via the public API (see below). To avoid the double tab-visibility observer, the deferred-path wiring passes `useIntersectionPause` an option that disables ITS document-visibility arm (intersection-only), OR — the cleaner shape per the disjointness note — the runtime owns ALL visibility and `useAurora` drives ONLY the `"off-screen"` reason through the public pause/resume. The W3 implementer picks the narrower of the two; the binding contract is: **exactly one observer writes `"tab-hidden"`, exactly one writes `"off-screen"`, and they never alias.**
- **Public `pause()`/`resume()`** — use the `"manual"` reason. The returned-object `pause`/`resume` (`runtime.ts:567-574`, and the armed closures at `runtime.ts:483-494`) call `suspend("manual")` / `resume("manual")`. The pre-arm branch (`else running = false` at `runtime.ts:569`, `else running = true` at `runtime.ts:573`) becomes `else suspended.add("manual")` / `else suspended.delete("manual")` — `arm()` then honors the seeded set via the `if (isRunning()) …` arm gate. This preserves the pre-arm-mutation contract documented at `runtime.ts:534-535`.

### Public-API shape decision

`useIntersectionPause`'s callbacks (`useAurora.ts:241-242`) currently call the bare `inst.pause()`/`inst.resume()`, which under the new model would map to `"manual"` — WRONG, because a manual consumer `pause()` would then be cleared by an intersection `resume()`. Resolve this by giving the intersection wiring its own reason. Two acceptable shapes; the W3 implementer picks one and records it in the audit:

- **(A) Reason-parameterized public API.** `pause(reason?: SuspendReason = "manual")` / `resume(reason?)`. `useAurora.ts:241-242` calls `inst.pause("off-screen")` / `inst.resume("off-screen")`; a bare consumer `inst.pause()` defaults to `"manual"`. Smallest surface, but leaks the reason vocabulary into the public type.
- **(B) Runtime owns intersection too.** The runtime owns ALL three observers internally; `useAurora` stops composing `useIntersectionPause` for pause/resume and instead the runtime mounts its own `IntersectionObserver` on the canvas. `useAurora` keeps `useIntersectionPause` ONLY for the first-intersection arm-trigger (`useAurora.ts:244-266`), not for suspend. Cleaner public surface (`pause()`/`resume()` stay reason-free and always mean `"manual"`), more runtime code.

**Decision: shape (A).** The runtime is the imperative substrate and already exposes `pause`/`resume`; threading an optional `reason` is the minimal honest change and keeps `useIntersectionPause` as the single intersection owner (it already exists, is tested, and disconnects on unmount). Shape (B) duplicates an observer the wrapper already owns. The `reason` param is optional and defaults to `"manual"`, so a bare consumer `pause()` reads identically to today. The W3 audit records the chosen `SuspendReason` union as the contract.

### Why resume-while-off-screen becomes structurally UNREACHABLE

The off-screen → tab-flip → resume path requires a single writer to both set `"off-screen"` and later clear it via a DIFFERENT trigger. Under the set:

1. scroll off-screen → `useIntersectionPause` → `inst.pause("off-screen")` → `suspended = {"off-screen"}`, RAF cancelled.
2. tab away → `document.visibilitychange` → `suspend("tab-hidden")` → `suspended = {"off-screen","tab-hidden"}`.
3. tab back → `document.visibilitychange` → `resume("tab-hidden")` → `suspended = {"off-screen"}`. `isRunning()` is STILL `false` (size 1), so the `wasSuspended && isRunning()` restart guard does NOT fire. **RAF stays parked.**
4. only scrolling back on-screen → `inst.resume("off-screen")` → `suspended = {}` → `isRunning()` true → loop restarts.

The resume-while-off-screen seam cannot exist because no reason-keyed `resume` can clear a reason it did not set, and the loop restarts ONLY on the full-empty transition. This is derive-don't-duplicate applied to control flow: `running` is no longer a writable flag three owners race on — it is a pure function of the set.

### Invariants W3 must hold (hard-gate inputs)

- `prefers-reduced-motion` still renders a single static frame then parks. The `needsAnimation()` reduced-motion gate (`runtime.ts:440`) is unchanged; reduced-motion is NOT a suspend reason (it draws one frame, then `tick()`'s `needsAnimation()` returns false and parks — orthogonal to the suspend set).
- `drawFrame` (`runtime.ts:417-426`) is byte-identical pre/post-W3 — T3 touches only the run-gate plumbing, never the draw path.
- `dispose()` (`runtime.ts:510-530`) removes the lifted tab-visibility listener (it currently removes `onVisibilityChange` at `runtime.ts:514-519`; the lifted listener's teardown moves with it) and clears the set.
- A π idle re-probe at W3/W5 confirms the loop parks at steady-state and resumes only on genuine on-screen + tab-visible.

## The false-witness coda (binds AP.W4 scope items 1 + 2)

### Coda-1 — proof-consumers-static scan-scope fix

`scripts/proof-consumers-static.mjs` `ignoredDirs` (`proof-consumers-static.mjs:28-37`) is `{.git, .vite, dist, build, coverage, node_modules, .output, .nuxt}` — it does NOT exclude `.claude` or `worktrees`. `walk()` (`proof-consumers-static.mjs:136-150`, the `if (ignoredDirs.has(entry)) continue` guard at line 140) therefore descends into every sibling consumer's `.claude/worktrees/agent-*/src/` stale-copy tree and lints those throwaway checkouts as live consumer source. GAMMA quantified the result: **78 violations, 100% under `speedtest/.claude/worktrees/agent-*`; the live consumer `src/` trees are already clean** (0 violations).

**Fix.** Add `.claude` AND `worktrees` to `ignoredDirs`:

```js
const ignoredDirs = new Set([
    ".git", ".vite", "dist", "build", "coverage",
    "node_modules", ".output", ".nuxt",
    ".claude", "worktrees",
]);
```

Both keys, belt-and-suspenders: `.claude` stops the descent at the `.claude` dir; `worktrees` defends the case where a `worktrees/` tree is rooted elsewhere. `walk()` already guards absent roots with `existsSync` (`proof-consumers-static.mjs:137`), so CI — where the sibling repos do not exist on the runner — is unaffected; this is a LOCAL-only green-up with zero signal loss (the live trees that the gate genuinely guards stay scanned and stay clean).

**W4 hard-gate proof.** `npm run proof:consumers:static` exit 0 locally; the audit records before (78) / after (0). Note `rootContractFiles` (`proof-consumers-static.mjs:109-125`) already correctly lists 7 cherry-picked custom packages (incl. `instrument-rail` at line 114) — that arm is NOT stale and is NOT touched by this fix.

### Coda-2 — profile-bundle D5 self-erasing-baseline split

`scripts/profile-bundle.mjs` reads the D5 drift baseline from `artifactPath` (the read at `profile-bundle.mjs:230` inside the `if (existsSync(artifactPath))` block, parsing `baseline.subpathTable` at lines 232-234) and WRITES the fresh profile to the SAME `artifactPath` (the `writeFileSync` at `profile-bundle.mjs:292-312`). `artifactPath` is defined ONCE at `profile-bundle.mjs:16-19` (`GLASS_UI_BUNDLE_ARTIFACT ?? docs/tranches/K/audit/W4-bundle-profile.json`). So every `profile:budget` run overwrites the baseline it just gated against — the next run drifts against numbers THIS run wrote, not against a committed reference. Drift is structurally ~0% in normal operation (the script always writes), so the D5 gate is a no-op. AO's probe (inject a smaller baseline → FAIL → restore) only worked because it hand-edited the artifact BETWEEN runs.

**Fix — split read-baseline from write-profile into two distinct paths.**

- **Committed baseline (read-only to the gate).** A new committed, reviewed reference at a STABLE path — `docs/tranches/AP/W4-bundle-profile.baseline.json` (the W4 File Bounds path). The D5 read at `profile-bundle.mjs:230` reads THIS path, never `artifactPath`. Introduce a `baselinePath` const beside `artifactPath` at `profile-bundle.mjs:16-19`:

```js
const baselinePath = resolve(
    process.env.GLASS_UI_BUNDLE_BASELINE ??
        resolve(root, "docs/tranches/AP/W4-bundle-profile.baseline.json"),
);
```

The D5 block's `if (existsSync(artifactPath))` (`profile-bundle.mjs:230`) and the `readFileSync(artifactPath, ...)` (`profile-bundle.mjs:232`) both retarget to `baselinePath`.

- **Ephemeral profile (write-only).** The run still writes the fresh measurement to `artifactPath` (`profile-bundle.mjs:292`) as the informational profile — unchanged. It is NOT the baseline the next run reads.

- **`--rebaseline` flag — the ONLY path that updates the committed baseline.** A deliberate opt-in:

```js
const rebaseline = process.argv.includes("--rebaseline");
```

When set, AFTER computing the profile, copy the fresh `subpathTable` (or the whole profile object) to `baselinePath`. This is a reviewed, committed git mutation — drift re-baselines only when a human runs `profile:budget -- --rebaseline` and commits the result. Without the flag, the baseline is immutable across runs.

**Seed the baseline.** W4 creates `docs/tranches/AP/W4-bundle-profile.baseline.json` by running `profile:budget -- --rebaseline` once against a canonical `npm run build` dist (NOT a `profile:budget`-collapsed dist — per GAMMA §3, an iter-build leaves no d.ts and a thin styles manifest; always `npm run build` last before seeding so the entry-chunk sizes are the publishable ones), then committing it.

**Co-ownership note (W2 vs W4).** `profile-bundle.mjs` is co-owned by topic: W2 owns the CSS-ceiling re-base (`BUDGETS`, `profile-bundle.mjs:38-41`, the `combinedStylesDraw` resolver `profile-bundle.mjs:49-60`); W4 owns the D5 baseline split (the `profile-bundle.mjs:206-289` D5 block + the new `baselinePath`/`--rebaseline` plumbing at the top). Disjoint sections. W2 lands first; W4 reads it settled.

**W4 hard-gate proof.** Two consecutive `npm run profile:budget` runs gate against the SAME committed `baselinePath` (no self-erase — drift is identical across the two runs); a `--rebaseline` run is the only path that moves it. The audit shows the stability proof.

# AQ.W1.3 — Motion, anchor positioning & top-layer (+ bundle guardrail) (design slice)

This slice designs the concrete impl for **AQ.W5** (motion → platform / the compositor cluster),
**AQ.W6** (anchor positioning & top-layer / the platform-UI cluster), and **AQ.W7** (bundle &
container-query / the consumer-payload guardrail) from the `AQ.W0` audit
(`docs/tranches/AQ/audit/W0-modern-web-baseline.md`). It is design-phase only — it changes **no**
`src/`, `server/`, or `styles/` file. It hands the implementer exact CSS/prop/token shapes, a
per-site migration map, a fallback ladder per feature, the retire-vs-keep disposition (the
no-backwards-compat-alias invariant), the AQ↔J coupling contract, and the hard gate each impl wave
closes against.

Binding browser-support policy (W0 §"Browser-support policy", confirmed):

| Baseline status | Disposition |
|---|---|
| **Widely Available** | Adopt natively, no fallback. |
| **Newly Available** | Adopt with a feature-detected fallback ≤ 20 LOC, no new deps. |
| **Limited** (`interestfor`, customizable `<select>`, `moveBefore`, container *style* queries) | Progressive-enhancement only behind feature detection; the existing JS/reka-ui path **stays the default**. |

No runtime-dependency polyfills (the guides reference `@oddbird/*` / `invokers-polyfill` /
`interestfor` polyfills — **all rejected**; glass-ui is a substrate, not an app, and a polyfill drag
breaks the vueuse-free / keyframes-free root-barrel discipline). Every Newly/Limited adoption keeps
the current path as the documented sole fallback so a consumer on any target degrades cleanly.

Honest-Baseline call per feature is stated inline in each subsection (do not infer — the W0 lever
column already records the guide's `web-feature-ids`; the call below is the *binding* disposition).

## Design

### 1. Scroll-driven-animation recipes + the DUAL-PATH (W5-a)

**Baseline call:** `scroll-driven-animations` = **Newly Available** → adopt CSS as primary, keep the
composables as the JS fallback (the sole writer in fallback mode). The composables are *not* retired —
they become the `@supports`-gated fallback path, but the **double-run** must be eliminated (CSS and JS
both writing the same target is the bug to avoid).

#### 1a. CSS recipes (new file `src/styles/scroll-driven.css`, cascade rung after `animations.css`)

Two token-first recipe families. Both gate on the **two-clause** `@supports` boundary the guides
mandate (`view()` partial-support filter) and on `prefers-reduced-motion: no-preference`.

```css
/* ── Scroll progress (scroll() timeline) — drives a 0..1 scaleX bar.
 * Consumers add class .scroll-progress on a position:fixed/absolute element;
 * the scroller is the nearest ancestor block scroller (root by default). */
@media (prefers-reduced-motion: no-preference) {
  @supports (animation-timeline: scroll()) {
    @keyframes gl-scroll-grow { from { transform: scaleX(0); } to { transform: scaleX(1); } }
    .scroll-progress {
      transform-origin: 0 50%;
      animation: gl-scroll-grow auto linear;
      animation-timeline: scroll(var(--scroll-progress-scroller, root) block);
    }
  }
}

/* ── View-driven entry/exit (view() timeline) — the useStaggerReveal replacement.
 * Each child of a [data-scroll-reveal] scroller fades + lifts on entry. The
 * stagger is implicit in the per-element timeline (each child has its own
 * view-timeline), so NO setTimeout cascade is needed. */
@media (prefers-reduced-motion: no-preference) {
  @supports ((animation-timeline: view()) and (animation-range: entry)) {
    @keyframes gl-reveal-in {
      from { opacity: 0; transform: translateY(var(--scroll-reveal-rise, 6px)); }
    }
    [data-scroll-reveal] > * {
      animation: gl-reveal-in auto linear both;
      animation-timeline: view(block);
      animation-range: entry 0% entry 60%;
    }
  }
}
```

Tokens (added to `tokens.css`, new `§SCROLL-DRIVEN MOTION` block; values mirror the composable
defaults so the two paths read identically): `--scroll-progress-scroller: root`,
`--scroll-reveal-rise: 6px`, `--scroll-reveal-range-end: 60%`. The `view-timeline` axis is `block`
by default; horizontal scrollers pass `view(inline)` via a `.scroll-reveal--inline` modifier
(`animation-timeline: view(inline)`), per the guide's axis note.

Reduced-motion is the **outer** gate (the whole `@supports` block sits under
`prefers-reduced-motion: no-preference`) — under PRM no scroll animation attaches at all and content
renders in its terminal state (the keyframe `from` is never applied because the animation never binds).

#### 1b. The composables become the FALLBACK-only writers (no double-run)

`useScrollProgress` and `useStaggerReveal` stay at `src/composables/motion/` and remain on the
`@mkbabb/glass-ui/motion-core` subpath (keyframes-free; root barrel already excludes them). They are
edited so the listener/observer machinery **does not attach** when the native feature is present:

```ts
// useScrollProgress.ts — gate the listener attach (top of onMounted)
const NATIVE = typeof CSS !== "undefined" && CSS.supports("animation-timeline", "scroll()");
// useStaggerReveal.ts — gate the IntersectionObserver construction
const NATIVE = typeof CSS !== "undefined"
  && CSS.supports("(animation-timeline: view()) and (animation-range: entry)");
```

- `useScrollProgress`: when `NATIVE`, skip `window.addEventListener("scroll"/"resize")` + the
  `ResizeObserver` (lines 61-67) entirely; `computeProgress()` runs once on mount for a correct
  initial value, then the ref is left static (the consumer that needs a *reactive* JS number on a
  native browser opted into the wrong tool — document that the composable is fallback-tier). The
  attach is the thing W0 measures: **0 scroll listeners when the engine supports `scroll()`**.
- `useStaggerReveal`: when `NATIVE`, do not construct the `IntersectionObserver` (line 36) and do not
  arm the `setTimeout` cascade; `register()` immediately sets `revealed[idx] = true` so the
  consumer's bound class lands its terminal state and the CSS view-timeline owns the entrance.

This is the **dual-path with a single writer**: native → CSS owns it, composable is inert; non-native
→ composable is the sole writer (the consumer's bound Tailwind class transitions normally). The CSS
recipe and the composable target the same visual axes (opacity/translateY/scaleX) so there is no
visual seam.

**Migration map (consumer-facing demos; library side is the gating edit above):**

| Old | New |
|---|---|
| `const p = useScrollProgress({ target })` + manual `:style` bind | add `class="scroll-progress"` to the fixed bar; keep the composable call for the fallback-tier number only |
| `const { register, revealed } = useStaggerReveal()` + `:ref`/`:class` per item | add `data-scroll-reveal` to the scroller; `register`/`revealed` stay for the fallback path |

**Retire vs keep:** CSS recipes are **new**; composables **kept as sole fallback** (no alias — the
public API of both composables is unchanged, only the internal attach is feature-gated). No double-run.

**Fallback ladder:** Native CSS (primary) → composable JS writer (sole, when
`CSS.supports` is false) → PRM disables both (content static). Gate code ≤ 8 LOC per composable.

### 2. Top-layer animation grammar for `animations.css` (W5-b)

**Baseline call:** `@starting-style` = **Widely Available**; `transition-behavior: allow-discrete` =
**Newly Available**; `overlay` = **Newly Available**. Net disposition: adopt natively, gate the
*feature-detected JS fallback* on `@supports (overlay: auto)` (the audit's gate clause). The
`useSpringMount` path is **kept** as the documented sole fallback for the `spring` opt-in (it is a
legitimate physics variant, not a duplicate — see retire-vs-keep below).

#### 2a. New `animations.css` block (`§TOP-LAYER ENTRY/EXIT`, appended after the scrim cascade)

A pure-CSS entry/exit grammar keyed off `[popover]:popover-open` and `dialog[open]`, plus a glass
`::backdrop`. This is the substrate the **native-`<dialog>` glass pilot** (§5) and any consumer
`[popover]` element consume — it is NOT applied to reka-ui's portaled overlays (those keep their
`tw-animate-css` data-state fade; distinct selectors, no cascade fight, mirroring the existing
`[data-scrim-animation]` discipline at `animations.css:290`).

```css
@supports (overlay: auto) {
  /* Base (closed/exit) + transition list — MANDATORY overlay + allow-discrete */
  .glass-top-layer[popover],
  dialog.glass-top-layer {
    opacity: 0;
    scale: var(--top-layer-enter-scale, 0.96);
    transition-property: opacity, scale, display, overlay;
    transition-duration: var(--duration-normal);
    transition-timing-function: var(--ease-apple-spring);
    transition-behavior: allow-discrete; /* after the longhands, never negated */
  }

  /* Open state + @starting-style entry (starting-style AFTER the open selector) */
  .glass-top-layer[popover]:popover-open,
  dialog.glass-top-layer[open] {
    opacity: 1;
    scale: 1;
    @starting-style { opacity: 0; scale: var(--top-layer-enter-scale, 0.96); }
  }

  /* Glass backdrop — blur + dim, animated discretely */
  dialog.glass-top-layer::backdrop {
    background-color: hsl(var(--background) / 0);
    backdrop-filter: blur(var(--top-layer-backdrop-blur, 8px));
    transition: display var(--duration-normal) allow-discrete,
                overlay var(--duration-normal) allow-discrete,
                background-color var(--duration-normal) var(--ease-standard);
  }
  dialog.glass-top-layer[open]::backdrop {
    background-color: hsl(var(--background) / var(--top-layer-backdrop-dim, 0.5));
    @starting-style { background-color: hsl(var(--background) / 0); }
  }
}

/* Reduced-motion carve — flatten transform, shorten to a fade (guide MANDATORY) */
@media (prefers-reduced-motion: reduce) {
  .glass-top-layer[popover],
  dialog.glass-top-layer {
    scale: none;
    transition-duration: var(--duration-fast);
  }
}
```

Uses `scale:` (the W3 longhand) not `transform: scale()` so it composes with the W3 identity-base
work and does not mint a stacking context that would fight `anchor()` (§4). Every visual axis reads a
`--top-layer-*` token (added to `tokens.css §GLASS`): `--top-layer-enter-scale: 0.96`,
`--top-layer-backdrop-blur: 8px`, `--top-layer-backdrop-dim: 0.5`. Backdrop dim uses the
`hsl(var(--background) / α)` channel form (matches the house convention; W2's `color-mix` migration is
orthogonal — backdrop alpha on a single token is the legitimate `hsl(... / α)` case).

#### 2b. Retire vs keep

- The `[data-scrim-animation]` scrim-breath cascade (`animations.css:249-298`) is **untouched** — it
  is a long-running ambient effect on reka-ui's portaled overlay, a different concern.
- `DialogContent.vue:81-107` `useSpringMount` path is **KEPT** (not retired). It is the `spring`
  opt-in (`DialogContent.vue:44-55`) — an iOS-physics overshoot variant with drag-dismiss continuity,
  not a duplicate of the CSS fade. The native top-layer grammar serves the *new native-`<dialog>`
  pilot* (§5) and consumer `[popover]`s, NOT reka-ui's `DialogContent`. So there is no double-path on
  the same element: reka-ui Dialog → `popover-animate`/`useSpringMount`; native pilot → `.glass-top-layer`.

#### 2c. Fallback ladder

Native (`@supports (overlay: auto)` true) → CSS entry/exit. Non-supporting → the element appears/
disappears instantly (acceptable for a *new* pilot; the guide's JS `transitionend` dance is **not**
adopted — glass-ui does not ship a JS top-layer coordinator, that is the consumer's call or they use
reka-ui Dialog which already has it). PRM → fade-only, fast duration.

### 3. `useViewTransition` substrate API (W5-c) — the J.W5 contract muster

**Baseline call:** `view-transitions` (same-document) = **Newly Available**; `view-transition-class`
= **Newly Available**. Disposition: ship a thin helper that wraps a DOM-mutating callback in
`document.startViewTransition` with an **instant fallback** when unsupported. THIS is the contract
J.W5 consumes — specified here so the seam is frozen.

#### 3a. The helper (new file `src/composables/motion/useViewTransition.ts`)

Keyframes-free + vueuse-free → it lives on the `@mkbabb/glass-ui/motion-core` subpath (joins
`useScrollProgress`/`useStaggerReveal`; the root barrel still excludes motion-core, so the heavy-peer
discipline holds). Exact shape:

```ts
export interface ViewTransitionResult {
  /** Resolves when the transition's `finished` promise settles (or immediately
   *  in the fallback path). Use to route focus per the a11y-routing MANDATORY. */
  finished: Promise<void>;
  /** True when the native API ran; false when the instant fallback ran. */
  transitioned: boolean;
}

/** Wrap a synchronous DOM mutation in startViewTransition with an instant fallback.
 *  `mutate` performs the DOM/state change; it is called synchronously in BOTH paths. */
export function startViewTransition(mutate: () => void): ViewTransitionResult;

/** Feature-detected predicate consumers gate optional VT-only styling on. */
export function supportsViewTransitions(): boolean; // 'startViewTransition' in document
```

Implementation contract (≤ 30 LOC):

```ts
export function startViewTransition(mutate: () => void): ViewTransitionResult {
  if (typeof document === "undefined" || !("startViewTransition" in document)) {
    mutate();
    return { finished: Promise.resolve(), transitioned: false };
  }
  const vt = (document as any).startViewTransition(() => mutate());
  return { finished: vt.finished.catch(() => {}).then(() => {}), transitioned: true };
}
```

The helper deliberately does **not** manage `view-transition-name` assignment — that is CSS the
consumer owns (the helper only wraps the mutation, per the guide's "wrap state changes" step). It
also does **not** route focus — focus routing is the consumer's MANDATORY (the helper returns
`finished` so the consumer can `await it` then `el.focus()`).

#### 3b. CSS recipe substrate (new `src/styles/view-transition.css`, rung after `scroll-driven.css`)

Token-first shared-class recipes for the group-transition case (the dock layer swap §7 and J.W5's
re-rank both consume these):

```css
@media (prefers-reduced-motion: reduce) {
  ::view-transition-group(*),
  ::view-transition-old(*),
  ::view-transition-new(*) { animation: none !important; }
}

/* Shared group class — consumers add view-transition-class: gl-list-item on
 * each tracked element and a unique view-transition-name per element. */
::view-transition-group(.gl-list-item) {
  animation-duration: var(--vt-duration, var(--duration-normal));
  animation-timing-function: var(--vt-ease, var(--ease-apple-spring));
}
/* Added/removed members (the :only-child trick from the group guide) */
::view-transition-new(.gl-list-item):only-child { animation-name: gl-vt-slide-in; }
::view-transition-old(.gl-list-item):only-child { animation-name: gl-vt-slide-out; }

@keyframes gl-vt-slide-in  { from { opacity: 0; translate: 0 var(--vt-rise, 8px); } }
@keyframes gl-vt-slide-out { to   { opacity: 0; translate: 0 var(--vt-rise, 8px); } }

::view-transition { pointer-events: none; } /* keep non-transitioned UI interactive */
```

#### 3c. Coupling / retire-vs-keep

- **Exposed to J.W5:** `startViewTransition` + `supportsViewTransitions` from
  `@mkbabb/glass-ui/motion-core`; the `.gl-list-item` view-transition-class + `--vt-*` tokens from
  `/styles`. J.W5's `useVerdictMoment` re-rank + dialog reveal call `startViewTransition(() => render())`
  and tag rows with `view-transition-class: gl-list-item; view-transition-name: row-<id>` (unique per
  row — the guide's MANDATORY single-name-per-state rule).
- **New** helper; nothing retired in this slice (the consumer-side hand-coordinated spring+stagger that
  W0-W5-c names lives in *muster*, retired in J.W5, not here).

**Fallback ladder:** native VT → animated swap; unsupported → instant `mutate()` (functional, no
animation); PRM → `animation: none` on all VT pseudos (instant visual, native path still runs the swap
without motion).

### 4. Anchor-positioned tab underline (W6-a)

**Baseline call:** `anchor-positioning` = **Newly Available** → adopt with the `border-bottom`
fallback ladder the guide gives; **RETIRE** the JS offset-FLIP + `ResizeObserver` (no alias — the
hand-rolled measure path is deleted, the CSS owns it, and the static `border-bottom` is the sole
fallback).

#### 4a. `UnderlineTabs.vue` (lines 27-52, 60-93 scoped CSS)

Replace the `underlineStyle` ref + `updateUnderline()` + the `modelValue`/`options` watchers + the
`onMounted`/`onUnmounted` `ResizeObserver` (lines 20-57) with pure CSS. The `.underline-indicator`
DOM node (line 61) is **deleted** — the indicator becomes a `::before` on `.underline-tabs`.

New scoped CSS:

```css
.underline-tabs { position: relative; display: flex; gap: 0.25rem; }

/* The active tab is the anchor */
.underline-tab[aria-selected="true"] { anchor-name: --gl-tab-active; color: var(--foreground); }

/* Indicator pseudo-element, tethered to the active anchor */
.underline-tabs::before {
  content: "";
  position: absolute;
  position-anchor: --gl-tab-active;
  inset-block-start: calc(anchor(bottom) - 2px);
  inset-inline-start: anchor(left);
  inset-inline-end: anchor(right);
  block-size: 2px;
  background: var(--foreground);
  border-radius: var(--radius-sm);
  @media (prefers-reduced-motion: no-preference) {
    transition: inset var(--duration-normal) var(--ease-apple-spring);
  }
}

/* Fallback ladder — static underline when anchor positioning is absent */
@supports not (position-anchor: --x) {
  .underline-tabs::before { display: none; }
  .underline-tab[aria-selected="true"] { border-bottom: 2px solid var(--foreground); }
}
```

The `transition: inset` is the only animation — the browser interpolates the indicator between anchors
on selection, **no JS, no reflow, no nextTick**. `aria-selected` (line 68) is **kept** (the
indicator is visual-only; the guide's MANDATORY ARIA-state rule).

Script reduces to: `props`, `emit`, `select()`. Deleted: `containerRef`, `buttonRefs`,
`underlineStyle`, `updateUnderline`, both watchers, `resizeObserver`, `onMounted`, `onUnmounted`,
`nextTick`. The `:ref` callback on the buttons (line 65) and `ref="containerRef"` (line 60) are
removed.

#### 4b. `BouncyToggle.vue` (lines 81-202)

Same swap for the **single-select** slider (`singleSliderStyle` + `updateSingleSlider`, lines 81-97).
The active button gets `anchor-name: --gl-toggle-active`; the `.bouncy-slider` div becomes anchored:

```css
.bouncy-btn[aria-pressed="true"] { anchor-name: --gl-toggle-active; color: var(--foreground); }
.bouncy-slider {
  position: absolute;
  position-anchor: --gl-toggle-active;
  inset: anchor(top) anchor(right) anchor(bottom) anchor(left);
  /* inset-block already shrunk via the existing 0.1875rem inset — keep as margin trim */
  @media (prefers-reduced-motion: no-preference) {
    transition: inset var(--duration-normal) var(--spring-snappy);
  }
}
@supports not (position-anchor: --x) {
  /* keep the JS-driven inline style path — see multiSlider note */
}
```

**Multi-select caveat (load-bearing):** `anchor-name` is single-target — two active values cannot both
be `--gl-toggle-active`. So the **multi-select** path (`updateMultiSliders`, lines 101-117, one slider
per active value) is **KEPT as the JS fallback for multi-select AND as the sole path when
`multiSelect` is true**. Disposition:

- `multiSelect === false` → anchor-positioned `::before`-style single slider (JS path deleted for this
  branch when anchor is supported; `@supports not` falls to the kept inline-style writer).
- `multiSelect === true` → JS `updateMultiSliders` path kept unconditionally (anchor positioning cannot
  express N simultaneous anchors cleanly; this is a documented honest limitation, not overfit).

The `animatePress` WAAPI bounce (lines 131-157) is **kept** — it is a press-feedback effect, orthogonal
to slider positioning, already PRM-gated (line 133). The `ResizeObserver` (lines 194-201) is **kept
only on the multi-select / `@supports not` path**; deleted when single-select + anchor supported.

#### 4c. Migration map

| Old site | New form |
|---|---|
| `UnderlineTabs.vue:27-52` `updateUnderline` + RO + watchers | deleted; `.underline-tabs::before` + `anchor()` |
| `UnderlineTabs.vue:61` `<div class="underline-indicator">` | deleted; pseudo-element |

| `BouncyToggle.vue:101-117` multi-slider JS | **kept** (multi-select + fallback) |

#### 4d. Fallback ladder

Native anchor → animated `transition: inset`. `@supports not (position-anchor: --x)` → static
`border-bottom` (UnderlineTabs) / kept JS inline-style (BouncyToggle single). PRM → indicator snaps
(no `transition`), ARIA state unchanged.

### 5. Native `<dialog>` glass pilot (W6-b)

**Baseline call:** `dialog-closedby` = **Newly Available**; `invoker-commands` (`commandfor`/`command`)
= **Limited**. Disposition: ship a **NEW** `<GlassDialogNative>` pilot component (subpath
`@mkbabb/glass-ui/dialog-native`) that renders a real `<dialog class="glass-top-layer">` with
`closedby="any"` light-dismiss. The `commandfor`/`command` declarative-open is offered as the
**preferred** trigger wiring but, because invoker-commands is **Limited**, the component also exposes a
`defineExpose({ showModal, close })` JS path as the kept default for non-supporting targets.

**reka-ui stays** for every compound focus-trap case — the existing `Dialog`/`Sheet`/`Popover`/
`DropdownMenu` are **untouched**. The pilot serves only the *simple confirm/settings* case (one
heading, optional form, a close action) where native `<dialog>` focus-trap + top-layer is sufficient.
This is the ≥2-consumer gate: the pilot ships only because **muster J.W6 adopts it** for its simple
confirm dialog (the W0 cross-repo coupling) — if J does not adopt, the pilot does not ship (it has a
demo story as the second consumer per the overfitting bar).

#### 5a. Component shape (`src/components/custom/dialog-native/GlassDialogNative.vue`)

```vue
<dialog ref="dlg" class="glass-top-layer glass-floating rounded-dialog"
        :closedby="lightDismiss ? 'any' : 'closerequest'"
        :aria-labelledby="titleId">
  <slot /> <!-- consumer owns the heading (aria-labelledby) + close button -->
</dialog>
```

Props: `lightDismiss?: boolean` (default `true` → `closedby="any"`), `id` (so a sibling
`<button commandfor=… command="show-modal">` can target it). Exposes `showModal()` / `close()`.

- **Declarative open (preferred, Limited):** consumer writes
  `<button commandfor="settings-dlg" command="show-modal">` and
  `<GlassDialogNative id="settings-dlg">`. When invoker-commands is supported, **no JS handler**.
- **Fallback (kept default):** consumer wires `@click="dlgRef.showModal()"`. The component does not
  ship an invoker polyfill; the JS open path is always available via `defineExpose`.
- **Light-dismiss:** `closedby="any"` natively. `@supports not` is via the JS feature-detect — when
  `'closedBy' in HTMLDialogElement.prototype` is false, the component installs the ≤ 12-LOC
  backdrop-click fallback from the guide (`light-dismiss-a-dialog/guide.md`) in `onMounted`,
  removed in `onUnmounted`. This is the ≤ 20-LOC Newly-Available fallback.

Entry/exit animation is **pure CSS** from §2 (`.glass-top-layer`) — no `useSpringMount` on the pilot.

#### 5b. Which reka-ui cases stay (binding table)

| Case | Path |
|---|---|
| Simple confirm / settings (1 heading, optional short form) | **GlassDialogNative** pilot |
| Compound dialog (nested focus zones, async content, drag-dismiss `spring`) | **reka-ui `Dialog`** (unchanged) |
| Sheet / bottom-drawer | **reka-ui `Sheet`/`Drawer`** (unchanged) |

### 8. `command`/`commandfor` + `moveBefore` re-parent (W6-e)

**Baseline call:** `invoker-commands` = **Limited**; `move-before` (`moveBefore`) = **Limited**. Both
are progressive-enhancement-only; the existing JS / `insertBefore` paths stay default.

#### 8a. `commandfor`/`command` on simple triggers

Already covered for the §5 dialog pilot. No other glass-ui component grows a `commandfor` trigger in
this slice (the dock/menu triggers are reka-ui-owned and keep their JS open-state). The
**declarative-button-actions** custom-command pattern (`command="--foo"`) is **not** adopted in the
library — it is a consumer-app pattern; the library exposes no custom-command registry (would be
substrate-without-consumer).

#### 8b. `moveBefore` on re-parent paths

Two re-parent sites risk closing an open top-layer element on re-mount: `ResponsiveTabs` (matchMedia
Select↔UnderlineTabs swap) and any dock teleport. Add a tiny shared util
(`src/utils/moveBefore.ts`, ≤ 20 LOC, exported from `src/utils` → root barrel):

```ts
/** Atomic state-preserving move when supported; insertBefore fallback otherwise. */
export function moveBeforeSafe(parent: Element, node: Node, ref: Node | null): void {
  if ("moveBefore" in Element.prototype) (parent as any).moveBefore(node, ref);
  else parent.insertBefore(node, ref);
}
```

Consumers/components that imperatively re-parent a subtree containing focus or an open popover call
`moveBeforeSafe` instead of `appendChild`/`insertBefore`. This is **opt-in at the call site** — the
default Vue render path (teleport, `v-if` swap) is unchanged; `moveBeforeSafe` is reached only where a
component already does manual DOM surgery.

**Retire vs keep:** `insertBefore` is the **kept sole fallback** inside the util. No alias.

**Fallback ladder:** `moveBefore` supported → atomic move (focus/animation/iframe state preserved);
unsupported → `insertBefore` (state resets — documented, acceptable degrade per the guide).

### Per-story repair pattern

Each repair is approximately 30 lines of `<template>` addition:

```vue
<StoryPage>
    <CreamSurface tone="warm" class="relative overflow-hidden">
        <DisplayHero size="display-3" variation="wonk" v-bind:title="..." />
        <FlourishDivider tone="section-N" />

        <!-- existing specimen content here, threaded with section-N accent color -->

    </CreamSurface>
</StoryPage>
```

Section accent (section-0..12) varies per story to spread the 13-stop palette. Body content keeps the specimen / spec table; the wrapper provides the design-language commitment.

For interactive stories (buttons, inputs, dialogs, etc.), the wrapper is the chassis; the components-under-demonstration sit inside.

### Lane decomposition

Split 41 stories across 3-5 lanes, ~10 stories per agent:

- Lane A: primitives 1-14
- Lane B: containers 1-12
- Lane C: motion + misc (4 + 8 = 12)
- Lane D (optional): settings + foundations residue

Each lane:
1. Reads its assigned story files
2. Adds the wrapper per the repair pattern
3. Threads section accent + display-hero
4. Runs `npm run typecheck` after each major file group
5. Verifies the design-fidelity gate per the audit criteria via Playwright probe (the W7 close ceremony will re-run; lanes may pre-verify their own)

Each lane writes its own proof: `docs/tranches/I/audit/W4-{A..D}-uplift-proof.md`.

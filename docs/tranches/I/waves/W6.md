## Purpose

Per H deep-audit ε performance lane: 5 critical findings include subpath sprawl (11 of 30 are zero-payload re-export stubs ≤ 0.16 kB), CI runs only stress (no test, no typecheck, no proof:package), and bundle/CSS size floors remain measurement-only across F/G/H. I.W6 promotes bundle to soft-fail gate and trims the subpath surface.

## Scope

### Lane I — Subpath retire (11 zero-payload candidates)

Per ε audit, 11 typed subpaths in `package.json` are zero-payload re-export stubs (just re-export the main barrel; consumers can use `@mkbabb/glass-ui` directly):

- `glyph-face`
- `dock-group`
- `disco-glyph`
- `icon-tooltip`
- `instrument-chassis`
- `paper-backdrop` (if not retired in W1)
- `pulse`
- `glass-panel` (if not retired in W1)
- `metric-badge`
- `status-dot` (if not retired in W1)
- `toggle-chip`

For each subpath:
1. Verify zero consumer imports the subpath specifically (vs the main barrel)
2. Remove the entry from `package.json` `exports` + `typesVersions`
3. Remove the entry from `vite.library.ts` if present
4. Remove the dist file (handled by build)

Net result: ~30 → ~19 typed subpaths. Public surface narrows; build-time dts emission cost reduces (per ε: 31 API Extractor invocations × per-subpath cost).

### Lane II — CI workflow extension

Per ε audit: CI runs only the H W5 stress workflow. Extend (or add) workflows for:

1. **Typecheck + test** (`.github/workflows/check.yml` or extend stress.yml):
   - `npm ci` → `npm run typecheck` → `npm run test`
   - Triggers: pull_request + push (master/main) + workflow_dispatch
   - Fails the workflow if any step exits non-zero
2. **Bundle budget** (extend `npm run profile:bundle` or add a `npm run profile:budget` script):
   - Captures current `dist/glass-ui.js` + `dist/glass-ui.css` sizes
   - Compares against a budget table in `package.json` or `scripts/profile-bundle.config.json`:
     ```json
     {
       "glass-ui.js": { "raw": 200000, "gzip": 38000 },
       "glass-ui.css": { "raw": 42000, "gzip": 7500 }
     }
     ```
   - Soft-fails (workflow status = failure but does NOT block branch protection unless explicitly configured) if budget exceeded
3. **Recovery-diary CI guard** (per W1 Lane D — verify it landed; if not, add here):
   - Runs the canonical grep against src/ + demo/
   - Hard-fails on any hit

### Lane III (optional) — dts caching exploration

Per ε audit: dts emission ranges 17s (settled) to 235s (mid-refactor) — 14× variance. Vite + dts run concurrently under one `vite build`. The bundled API Extractor logs the TS-version warning **31 times** (one per subpath entry). No content-hash cache.

W6 explores caching:
1. Profile what's slow: API Extractor or vue-tsc?
2. Check if `vite-plugin-dts` supports caching out of the box
3. If Lane I retires 11 subpaths, dts cost drops by ~⅓ for free
4. Document findings; don't necessarily land caching infrastructure (could be out of scope per "minimal new substrate")

Recommendation: Lane III is exploratory; if findings warrant a fix, escalate to a future tranche residual. If trivially fixable (e.g., enabling a dts plugin option), absorb in W6.

# AM.W1 — Aurora ergonomics + adaptive render-mode

## Goal criterion

A consumer mounts `<Aurora />` with no config and gets the canonical painterly look; mounts `<Aurora render-mode="auto" />` and the wash composites via WebGL on capable devices, via the CSS-gradient placeholder on low-power / reduced-motion / save-data devices, never disappearing. The shipped `initStrategy:"deferred"` lazy boot (CSS placeholder at FCP, WebGL armed on idle past first paint) stays intact — this wave is ergonomics + substrate-adaptivity, not a boot-path rewrite.

## Scope

1. **`config` optional, defaulting to `DEFAULT_AURORA_CONFIG` (gap 11).** `src/components/custom/aurora/Aurora.vue:39-62` declares `config: AuroraConfig` as required; `withDefaults` supplies only `opacityCeiling:1`. `DEFAULT_AURORA_CONFIG` is already exported (per CLAUDE.md `/api`). Make `config` optional and default it to `DEFAULT_AURORA_CONFIG` — via `withDefaults` (`config: () => DEFAULT_AURORA_CONFIG`) OR a `computed` merge so a partial config inherits the canonical fields. WHY — every consumer currently must import + author a config even for the canonical wash; the default removes that friction.
2. **`renderMode: "webgl" | "css" | "auto"` prop, default `"auto"` (NEW; consumer = muster E.W2).** Per `GLASS-UI-aurora-lazy-init.md §3.1`. The static placeholder already IS a complete CSS render of the palette (`Aurora.vue:120-124`, `paletteToCssGradient`). Wire the prop:
   - `"webgl"` — arm the WebGL path as today (the `initStrategy:"deferred"` default still defers `arm()` to idle).
   - `"css"` — never arm WebGL; leave the `paletteToCssGradient` placeholder as the permanent surface.
   - `"auto"` (default) — pick `"css"` when `navigator.hardwareConcurrency ≤ 4` OR `prefers-reduced-motion: reduce` OR `navigator.connection?.saveData`; else `"webgl"`. Resolve the device tier once at mount (guard for SSR / missing `navigator.connection`).
   Thread the resolved mode into the existing `useAurora`/`runtime` arm gate so `"css"` short-circuits the `arm()` schedule. WHY — the binary "Aurora is never retired" guarantee in code: even the weakest device composites the warm wash; only the substrate (animated WebGL vs static CSS) adapts.
3. **Preserve the lazy-init contract.** Do NOT touch the `scheduleAfterFirstPaint` / `requestIdleCallback` / intersection-gate logic (`useAurora.ts`) beyond reading the resolved `renderMode` to decide whether to schedule `arm()` at all. The reduced-motion `uTime` freeze (`runtime.ts:412-414`) stays. WHY — the deferred boot is already correct and off the FCP critical path; this wave adds adaptivity, not a rewrite.

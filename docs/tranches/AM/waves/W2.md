3. **§Consumer wiring — Vite 8 `manualChunks` recipe (gap 16).** Add to CLAUDE.md §Consumer wiring the Rolldown-compatible single-arg recipe (verified in `GLASS-UI-cross-repo-plan.md §4.2`):
   ```ts
   build: { rollupOptions: { output: { manualChunks(id) {
     if (id.includes("@mkbabb/glass-ui")) return "glass-ui";
     if (id.includes("@vueuse")) return "vueuse";
     if (id.includes("node_modules")) return "vendor";
   }}}}
   ```
   Note the order (glass-ui → vueuse → vendor so the `node_modules` catch-all doesn't swallow the named splits) and the caveat (do NOT also set `output.advancedChunks` — Rolldown ignores `manualChunks` if both are set). WHY — gap 6's true consumer-side fix.
4. **§Consumer wiring — subpath-import discipline (gap 6 docs).** Document that consumers import from subpaths (`@mkbabb/glass-ui/button`) not the root barrel for minimal payload. WHY — the root barrel re-exports 37 ui families; subpath imports tree-shake.
5. **Tabs-vs-ToggleGroup decision matrix (gap 13).** Add a CLAUDE.md paragraph: `<Tabs>` for mutually-exclusive PANEL navigation (`role="tablist"`, each tab reveals distinct content); `<ToggleGroup>` for independent-or-single-select TOGGLES mutating one surface (`role="group"`, no panel swap). WHY — guides the canonical pick (muster's ResultsStack view-toggle is a ToggleGroup case).
6. **§Consumer wiring — tw-animate-css requirement (from AM.W0 gap 15).** Document that consumers of the Dialog/Sheet/Popover/DropdownMenu animation grammar install `tw-animate-css` + `@import "tw-animate-css"`. WHY — AM.W0 declared the peer; the consumer-facing doc makes the requirement explicit.
7. **§component-architecture — GlassDock aria contract (from AM.W0 gap 3).** Document that the GlassDock root is presentational; `aria-expanded` belongs on the trigger child, not the root `<div>`. Cite `audit/W0-forms-a11y.md`. WHY — closes the consumer-authored axe `aria-allowed-attr` class with a contract, not a forced attribute.

## Scope

### AM.W0.1 — packaging + token (gaps 15, 1)

1. **Declare `tw-animate-css` as a peer (gap 15, BLOCKING).** `package.json:539` lists it under `devDependencies` only; the library `@apply`s `animate-in`/`fade-out-0`/`zoom-out-95` (`src/styles/utilities.css:9-11`) and ~11 components consume the data-state fade grammar, so a consumer that omits it gets a Tailwind-v4 unknown-utility build error. Add `"tw-animate-css": "^1.2.5"` to `peerDependencies` AND mirror it under `optionalPeerDependencies` (the hint surfaces without a hard install gate for Button-only consumers). Keep the `devDependencies` entry (the library's own build needs it). WHY — a fresh consumer build must not fail on a utility the library emits but does not declare a contract for.
2. **Darken `--muted-foreground` to clear AA (gap 1, MAJOR).** `src/styles/tokens.css:375` `--neutral-5: hsl(48 6% 45%)` feeds `--muted-foreground` (`:385`); L45 grey on the L98 paper (`--neutral-0`) computes ≈ 4.05:1 — under 4.5:1. Darken the light rung to ≈ L40 (`hsl(48 6% 40%)`, ≈ 4.8:1) or L38 for headroom; mirror the dark companion (past `:951`) lighter so it clears against the dark plate. Edit the library's OWN identity token — consumers keep override freedom. WHY — the AA body-text floor fails for every muted caption/label across every consumer.

### AM.W0.2 — forms-a11y + dock-aria re-derivation (gaps 4, 3)

3. **Forward aria to the NumberField inner input (gap 4, MAJOR).** `src/components/ui/number-field/NumberFieldInput.vue:6-8` forwards no aria attrs; `NumberField.vue:19-22` relays no label to the input descendant, so a labelled NumberField ships an unlabelled focusable input. Thread `aria-label`/`aria-labelledby` from a NumberField prop (or `$attrs`) down to `<NumberFieldInput>`, mirroring Slider's `:aria-label="$attrs['aria-label']"` pattern (`src/components/ui/slider/Slider.vue:163`). Set `inheritAttrs:false` + explicit forward on `NumberFieldInput.vue`. WHY — a labelled field with an unlabelled focusable input is a real screen-reader gap.
4. **Re-derive the GlassDock aria contract (gap 3, MINOR; read-only finding).** `src/components/custom/dock/GlassDock.vue:270-295` root is a presentational `<div class="glass-dock">` carrying no `aria-expanded` (grep `aria-expanded` in `dock/` → zero); `Slider.vue` thumb is reka-ui `SliderThumb` (`role="slider"`, a valid `aria-valuetext` host). The axe `aria-allowed-attr` violation muster traced here is consumer-authored (muster applies `aria-expanded` to the dock div). Read the dock source, confirm the root is presentational, and write the contract finding to `audit/W0-forms-a11y.md` (the doc lands in AM.W2): `aria-expanded` belongs on the dock TRIGGER child, not the presentational root; Slider needs no change. WHY — the root fix is a documented contract, not a forced attribute on a presentational element.

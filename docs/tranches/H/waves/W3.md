## Lane I — Dock-keep-open round-trip refactor

H.W1 Lane D retired the `DockLayerGroup.keepOpenWhile` Ref-based prop per H invariant 2 (single-primitive KISS — there was no in-repo consumer at HEAD). W3 now ships the leaf-side `dockKeepOpenSink` as the **canonical and sole** dock-keep-open primitive: a slider (or other interactive control) inside the dock can declaratively keep the dock open while pointer-active, then release.

Implementation:

- Add an inject-able `dockKeepOpenSink` provided by `<DockLayerGroup>` (or `<GlassDock>`). The sink exposes two methods: `acquire(): symbol` and `release(token: symbol): void`.
- `<DockLayerGroup>` keeps an internal counter; while count > 0, `keepOpen` is true. Pointer-up / unmount releases.
- `<Slider variant="glass-track">` accepts a `:keep-dock-open` prop (boolean; default `false`). When `true`, on `pointerdown` the slider calls `inject('dockKeepOpenSink')?.acquire()` and on `pointerup` / `pointercancel` releases the token.
- Token-based acquire/release is correct under React-or-Vue concurrent updates: a leaked token is a programming bug, not a leak in the dock chrome.

The retired `keepOpenWhile` prop is not restored. Future Ref-based consumers wrap a watcher around `acquire`/`release` themselves; the sink is the one primitive.

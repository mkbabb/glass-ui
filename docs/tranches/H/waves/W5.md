## Purpose

Close G's R2: capture actual measured Performance API numbers from the `_internal/blob-stress.vue` story under headless WebGL2 (Playwright + Chromium). The story exists; the threshold panel renders; the runtime profile measurement was deferred to "consumer-CI capture" — this wave brings that capture path inside glass-ui itself, so the SPEC.md §9 budget has hard-gate evidence.

Per H invariant 8: stress runtime profile is a hard gate, not a deferral.

## Scope

### A. Capture script

Create `scripts/stress/blob-stress-capture.mjs`:

- Boots `npm run dev` (or a Vite preview server) on a known port.
- Launches Playwright + Chromium with WebGL2 enabled (default for modern Chromium).
- Navigates to `http://localhost:<port>/?story=_internal/blob-stress`.
- Triggers the "Run profile" button via `page.click()`.
- Waits 5 seconds (the story's profile duration).
- Captures Performance API metrics from the story's exposed `window.__blobStressMetrics` global (the story will write its captured metrics to this global for headless extraction).
- Captures `performance.memory.usedJSHeapSize` if available.
- Tears down the browser.
- Writes results to `audit/W5-stress-baseline.md` with timestamp + Chromium version + GPU.

The story (`demo/stories/_internal/blob-stress.vue`) needs a small extension to expose metrics on `window.__blobStressMetrics` after the 5-second profile completes. This is a one-line addition.

### B. CI workflow

Create `.github/workflows/stress.yml` (or extend the existing CI workflow):

- Triggers: pull-request + main-branch push (manual dispatch fallback).
- Runs `npm install` + `npm run build` + `node scripts/stress/blob-stress-capture.mjs`.
- Uploads `audit/W5-stress-baseline.md` as a workflow artifact.
- Posts a comment on the PR with the captured numbers (max-frame-time + mean-frame-time + heap delta).
- Hard-fails the workflow if any threshold (per SPEC.md §9) is violated.

Threshold table embedded in the script (per SPEC.md §9):

| Metric | Budget |
|---|---|
| Per-frame GPU time | ≤ 2 ms (M1 / iPhone 12 / Pixel 5) |
| Per-frame CPU (renderer) | ≤ 0.5 ms |
| Per-frame CPU (state machine) | ≤ 0.3 ms |
| Memory per instance | ≤ 256 KB |
| 4-instance baseline | 60 fps |

Note: CI hardware is GitHub Actions ubuntu runners — typically slower than the SPEC.md §9 reference hardware (M1 / iPhone 12 / Pixel 5). The CI threshold is "≤ 2× the SPEC.md threshold" with a noted CI-vs-reference adjustment. Real-hardware capture remains the consumer-side responsibility; CI captures the regression signal.

### C. Baseline capture

Run the script once locally on M1 (or comparable) hardware and commit the baseline numbers in `audit/W5-stress-baseline.md`. Future PR runs compare against this baseline.

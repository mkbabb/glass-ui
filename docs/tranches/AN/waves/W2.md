## Goal criterion

A Tailwind-v4 consumer that imports `@mkbabb/glass-ui/styles` and runs Tailwind's content-scanner against its OWN `src/` only (no `@source` reaching into `node_modules/@mkbabb/glass-ui`) gets every utility class the library's templates emit — `h-full`, `w-full`, the CVA variant classes like `text-destructive-foreground`, the data-state fade grammar — without an unknown-utility build error or a runtime missing-style. Either the dist ships the utilities (Option A: the library owns its emission), or the consumer learns the binding `@source` contract one paragraph from the `tw-animate-css` requirement (Option B: the library documents its requirement).

## Completion criterion

Option A — `audit/W2-tailwind-utilities.md` carries a fresh-consumer build probe that omits the `@source ".../@mkbabb/glass-ui/dist"` directive and confirms `h-full` (and at least 3 other template-emitted utilities) resolve at runtime via classes the library ships in `dist/glass-ui.css`. Option B — CLAUDE.md §Consumer wiring carries the `@source` requirement as a binding contract paragraph with the same authority and same shape as the `tw-animate-css` paragraph; the audit doc captures the contract diff. `typecheck` + `build` exit 0. The W2 dispatch picks Option A by default; only flips to Option B if the W1 unified bundle's payload pressure or the Vite v4 source-of-truth makes A unattainable.

## Scope

1. **Decision: Option A or Option B (drive from the W0 intake recommendation).** The W0 intake table carries a default — Option A (emit the utilities). Pick A unless the W1 unified-bundle payload is already at the budget ceiling. WHY — F.W10.md §Scope item 1b names A as "the elegant one and the F-side default ask"; the AN dispatch honours that unless the substrate forces B.
2. **Option A — the library emits its template utilities.**
   - Inventory the utilities glass-ui's `<template>` blocks emit by static scan (`grep -r 'class=' src/components/**/*.vue | extract utility tokens`). The expected set: layout utilities (`h-full`, `w-full`, `flex`, `items-center`, …), the CVA variant-class strings the components compose, the data-state fade grammar (`animate-in`, `fade-out-0`, `zoom-out-95`) — the last set is already grounded on `tw-animate-css` (AM.W0 gap 15).
   - Emit those classes into `dist/glass-ui.css` via one of: (i) a content-scan step in the library's own Tailwind pipeline that runs over `src/components/**`, OR (ii) a static safelist appended to the Tailwind config the library publishes. Pick whichever leaves the dist smallest while still emitting every needed class.
   - The emission is additive — every existing CSS rung stays. The consumer's `@source "../node_modules/@mkbabb/glass-ui/dist"` directive becomes unnecessary; muster F.W10 deletes it.
3. **Option B — document the `@source` contract.**
   - Add a CLAUDE.md §Consumer wiring paragraph adjacent to the `tw-animate-css` paragraph naming the requirement: `@source "./node_modules/@mkbabb/glass-ui/dist"` (or the per-component path) must appear in the consumer's `styles.css` so Tailwind's content-scan reaches the library templates. The contract has the same authority as the `tw-animate-css` peer — without it, the library's templates emit classes the consumer's CSS does not contain.
   - The CLAUDE.md prose mirrors the `tw-animate-css` paragraph shape: WHAT (the directive), WHY (the library emits utilities that need to be in the consumer's content-scan reach), HOW (the exact directive line to add).
4. **Either option — re-verify `profile:budget`.** The emission (Option A) or the doc change (Option B) must not regress the bundle budget. The per-subpath gzipped table AM.W2 publishes is the verifier. WHY — AM's chunk-disclosure gate stays binding under AN.

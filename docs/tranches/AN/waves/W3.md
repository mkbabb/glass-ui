# AN.W3 — Detented Drawer variant

## State

- **Name** — ship a real `<Drawer>` variant that supports the mobile co-location pattern muster's F redesign needs: peek / half / full snap-points, `should-scale-background: false` (so the verdict behind stays at its native size, not scaled down), and non-modal (no focus trap, no page `aria-hidden`) so the verdict stays live AND reachable behind the sheet. Closes F.W10.md §Scope item 2 and gap 3 in the AN disposition ledger.
- **Opens after** — AN.W0 close.
- **Agents** — 1 (single-tree; `src/components/ui/drawer/` SFCs + composable wiring + demo proof + docs). If the prop-surface widens beyond a small carve, splits into AN.W3.1 (Drawer SFC) ‖ AN.W3.2 (demo + docs).
- **Hard gate** — see §Hard Gate.
- **Status** — planned.

## Goal criterion

A consumer mounts `<Drawer :modal="false" :should-scale-background="false" :snap-points="[0.12, 0.5, 1]">` (or the equivalent named-detent shorthand AN ships) and gets a non-modal, live-behind, peek / half / full bottom sheet. The page behind stays interactive and visible at its native size; the sheet's three detents are spring-snapped on drag release; no focus trap fires (the verdict behind retains focusability and screen-reader visibility); no `aria-hidden` reaches the page. The variant is opt-in (consumers opting into the existing modal/scale-background defaults are unaffected), and the F-side mobile co-location pattern (verdict full-bleed, instrument as bottom sheet at peek/half/full) builds on it directly.

## Completion criterion

`audit/W3-drawer-detents.md` carries: (a) a runtime probe mounting the Drawer at each of the three detents (peek 12% / half 50% / full 100% of viewport height) with a screenshot or DOM-rect proof per detent; (b) a focus-trap probe confirming `tabindex` flow does NOT capture inside the drawer when `modal:false`; (c) an `aria-hidden` probe on the page-root confirming the attribute is absent when `modal:false`; (d) a `scaleBackground:false` probe confirming the page-behind transform stays at `transform: none`. The `/drawer` subpath question is closed (default: root-barrel; the variant ships under the existing root-barrel Drawer export with new props). `typecheck` + `build` exit 0.

## Scope

1. **Audit vaul-vue's pass-through surface.** vaul-vue is the underlying primitive; its `DrawerRoot` already accepts `snapPoints`, `modal`, `shouldScaleBackground`, and the related grammar. The glass-ui `Drawer.vue` at HEAD forwards `DrawerRootProps` via `useForwardPropsEmits`, so the props ALREADY pass through. The W3 task is to: (a) confirm the props reach the runtime correctly under the new combinations; (b) flip the `shouldScaleBackground` default from `true` to a value compatible with the live-behind contract; (c) emit the detent grammar (the rounded handles, the spring snap, the drag-resistance feel) so the consumer does not author it from scratch. WHY — the F-side ask is "the Drawer's defaults fight the pattern"; AN's fix is the defaults + the detent grammar, NOT a rebuild.
2. **Decide the default — `shouldScaleBackground` flip.** Currently `true` (the iOS scale-down look). The F-side ask is `false` for the verdict-behind pattern. Two ways:
   - **Shape 1 (flip the default)** — change `withDefaults` to `shouldScaleBackground: false`. Clean but breaks any consumer relying on the default. A breaking change at v2.x.
   - **Shape 2 (keep the default; document)** — keep `true`; document that the live-behind pattern needs `:should-scale-background="false"`.
   - **Shape 3 (preset)** — ship a `<Drawer variant="bottom-sheet">` (or `mode="live-behind"`) shorthand that bundles `shouldScaleBackground:false` + `modal:false` + the default snap-points. Additive (no break) but introduces a new prop.
   Default recommendation — Shape 2 (no break; the F-side knows to pass the props). If the W0 intake records a strong F-side preference for Shape 3 (a single-prop ergonomic), the W3 dispatch flips. Shape 1 is the cleanest but the most invasive; reserved for a v3.0 break.
3. **Ship the detent grammar.** The three detents need styling — the rounded peek handle at the top, the snap-stop visual indicators (subtle line-rules), the drag-resistance spring curve. vaul-vue handles the snap math; glass-ui owns the look. Author the CSS at `src/styles/` or scoped on `DrawerContent.vue`. WHY — without a detent grammar, the consumer styles three sheets from scratch; AN's job is the substrate.
4. **Decide the `/drawer` subpath question.** Today Drawer is root-barrel-only. The W0 intake records the default: keep root-barrel (the prop additions don't warrant a new subpath; the existing root-barrel reach is correct). Document the decision in CLAUDE.md §Subpath surface (if a paragraph is warranted) and in the W3 audit doc. WHY — F.W10.md flags the question explicitly; AN must close it.
5. **Author the demo proof.** Add a demo SFC at `demo/stories/compositions/drawer-live-behind.vue` (or extend the existing Drawer story) showing the live-behind pattern over a verdict-shape surface. WHY — the proof story is the artefact a future consumer reads + the audit doc cites.

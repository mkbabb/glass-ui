## Findings

1. **Pin is `^3.3.0` optionalDependency, registry-resolved — NOT `file:../glass-ui`.** `package.json:89` declares `"@mkbabb/glass-ui": "^3.3.0"` under `optionalDependencies` (not deps, not `file:`). `package-lock.json:1013-1015` resolves it to `https://registry.npmjs.org/@mkbabb/glass-ui/-/glass-ui-3.3.0.tgz`, and `node_modules/@mkbabb/glass-ui/package.json` reads `"version": "3.3.0"` — a real directory, not a symlink. The lane brief's `file:../glass-ui` claim and the `vite.config.ts:139-144` comment ("`@mkbabb/glass-ui` … resolve through their own `exports` maps via the `file:` symlink") describe a dev-time workspace layout that is NOT the installed state at HEAD. **Adoption note:** `^3.3.0` already floats up to 3.4.0 on `npm update`, so the GlassDock fix arrives automatically once 3.4.0 publishes — no manual repin edit needed (semver permits it). The blocker is purely temporal: today's resolved 3.3.0 carries the regression.

2. **GlassDock two-layer collapse IS mounted — directly hits the 3.3.0 width-morph regression (HEADLINE BLOCKER).** `demo/@/components/custom/dock/TopDock.vue:118` mounts `<GlassDock :collapse-delay="2500" :start-collapsed="true" :fit-content="true" :always-expanded="isMobile">` with a default-slot `<DockLayerGroup>` + a `#collapsed` slot (lines 119-220). On desktop (`isMobile=false`) this dock STARTS collapsed and must width-morph open on hover — the exact path the 3.3.0 regression freezes ("width morph freezes on first expand"). This is the canonical broken surface. The fix is AW.W1 → 3.4.0.

3. **Second GlassDock site is NOT regression-exposed.** `demo/@/components/custom/animation-controls/AnimationMenuBar.vue:17` mounts `<GlassDock :always-expanded="true" :fit-content="true">` with a `#collapsed` slot (line 123) — but `:always-expanded="true"` disables the collapse morph, so this site never exercises the regressed first-expand path. Only TopDock (desktop) is broken.

4. **`@source` content-scan directive is ABSENT.** No `@source` anywhere in `demo/`, `src/`, or `vite.config.ts` (grep over `*.css`/`*.html`/`*.ts` returns nothing). The CLAUDE.md binding requirement (`@source "../node_modules/@mkbabb/glass-ui/dist"` — without it glass-ui's compiled-template utilities silently vanish) is not declared. The demo relies on `@tailwindcss/postcss` (`vite.config.ts:8,134`) default auto-detection to reach `node_modules/@mkbabb/glass-ui/dist`. This works in the current build (the demo is live), but it is the undeclared/fragile path the CLAUDE.md contract explicitly warns against; an explicit `@source` in `demo/@/styles/style.css` would make it contract-conformant.

5. **Other binding requirements PRESENT and correct.** `demo/@/styles/style.css`: `@import "tailwindcss"` (line 1), `@import "tw-animate-css"` (line 2), `@import "@mkbabb/glass-ui/styles"` (line 3, the single AN.W1 import — carries tokens AND SFC CSS), `@custom-variant dark (&:where(.dark, .dark *))` (line 9 — the Tailwind-v4 `@custom-variant` form, equivalent to the doc's `@variant dark`).

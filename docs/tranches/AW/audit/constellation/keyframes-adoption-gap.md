# keyframes-adoption-gap — keyframes.js is the HEAVIEST glass-ui consumer in the constellation AND the upstream spring supplier; the real ask is the 3.4.0 dock repin + a Configurator dogfood, NOT a fresh adoption

Lane verdict: the ledger's "keyframes demo adopts /keyboard" framing is badly stale. keyframes.js
already pins `@mkbabb/glass-ui ^3.3.0` (optionalDependency) and threads it through **48 demo files
across 13 subpaths** including dock, forms, labeled-field, icon-tooltip, status-dot, controls,
dark, keyboard, glass-panel, header-ribbon, motion-core. It is also the UPSTREAM spring supplier:
glass-ui's `--spring-*` tokens are generated from keyframes' `springLinearStops()`. The two genuine
findings are (1) a HARD 3.4.0 repin gate (its primary app dock uses the 3.3.0-broken collapse-morph)
and (2) a natural-fit Configurator dogfood across ~4 hand-rolled spring/easing parameter panels.

## Findings

1. **glass-ui is already a deep dependency, NOT a greenfield adoption.** `package.json:89`
   `"@mkbabb/glass-ui": "^3.3.0"` under `optionalDependencies`. Installed version is exactly
   `3.3.0` (verified: `node -e require('.../glass-ui/package.json').version` → `3.3.0`). 48 demo
   files import it across 13 subpaths (`grep -rhoE "@mkbabb/glass-ui(/[a-z-]+)?"` →
   `@mkbabb/glass-ui` ×38, `/forms` ×9, `/styles` ×8, `/icon-tooltip` ×6, `/dock` ×6, `/keyboard`
   ×3, `/controls` ×3, `/status-dot` ×2, `/motion-core` ×2, `/labeled-field` ×2, `/dark` ×2,
   `/header-ribbon` ×1, `/glass-panel` ×1). The consumer-wiring contract is already satisfied:
   `demo/@/styles/style.css:3` `@import "@mkbabb/glass-ui/styles"`.

2. **HARD 3.4.0 REPIN GATE — the primary app dock uses the 3.3.0-broken collapse-morph.**
   `demo/app/App.vue:2` mounts `<TopDock>` as the top-of-app chrome. `TopDock.vue:118`:
   `<GlassDock ref="dockRef" :collapse-delay="2500" :start-collapsed="true" :fit-content="true"
   :always-expanded="isMobile">` — this is exactly the simple two-layer collapse→expand width-morph
   that the CTX flags as broken in 3.3.0 ("the width morph freezes on first expand", fixed by
   AW.W1 → 3.4.0). On desktop (`isMobile=false`) the dock starts collapsed and must morph open on
   hover after the 2.5s collapse delay — the broken path. This repo MUST NOT stay on / bump to
   `^3.3.0`; the consume path is `^3.4.0` once AW.W1 ships. (The `^` range will silently pull a
   broken 3.3.x; it needs a `>=3.4.0` floor at repin.)

3. **Second dock site is NOT exposed to the regression (always-expanded).**
   `demo/@/components/custom/animation-controls/AnimationMenuBar.vue:17`:
   `<GlassDock ref="dockRef" :always-expanded="true" :fit-content="true">` — pinned open, so it
   never runs the collapse width-morph. This site is safe on 3.3.0; only `TopDock` is the live
   regression surface. (Both still benefit from AW.W2 dock motion-unify + AW.W3 layering polish.)

4. **CONFIGURATOR DOGFOOD — a natural fit across ~4 hand-rolled spring/easing parameter panels.**
   The demo hand-rolls the exact pattern `Configurator`/`ConfiguratorRow`/`useConfiguratorState`
   was built to be:
   - `demo/spring/SpringSidebar.vue:1-97` — a `glass-card` wrapping `Card`/`CardContent` with
     manual `<label>`+readout+`<Slider>` rows for `response` (line 8-21) and `dampingFraction`
     (line 24-38), PLUS a preset-button grid (line 44-57) over `SPRING_PRESETS`. This is a
     `ConfiguratorLayer` + two `ConfiguratorRow`s + `useConfiguratorState(cloneMode="per-preset")`
     near-verbatim (the four named spring presets ARE editable baselines the user tunes and returns
     to — the documented per-preset rationale).
   - `demo/easing/EasingSidebar.vue:1-93` — same `glass-card`+`Card`/`CardContent` shell with a
     manual duration slider+readout row (line 72-91), a step-options grid (line 35-70), and the
     EasingSelect. Another `ConfiguratorLayer` candidate.
   - `demo/@/components/custom/animation-controls/controls/AnimationControlsControls.vue:3-4` —
     `<Card class="… glass-card">` + `CardContent class="… grid grid-cols-[auto_1fr] gap-x-3 …">`,
     the label-column/control-column grid `ConfiguratorRow` emits.
   - `demo/@/components/custom/animation-controls/controls/TimingFunctionPanel.vue:17-78` — repeated
     `Card`/`CardHeader`/`CardContent` + `grid grid-cols-[auto_1fr]` panels (cubic-bézier, steps).
   `LayerConfigPanel.vue:49` already adopts `LabeledSelect`/`LabeledSlider`/`LabeledSwitch` from
   `/labeled-field` — the precedent that the labeled-control idiom is welcome here, so a
   Configurator lift is idiom-consistent, not a foreign import.

5. **THE SPRING SUPPLIER LOOP IS ALREADY CLOSED — keyframes IS the supplier; W31 is internal to
   glass-ui, not a keyframes ask.** glass-ui ships `--spring-{smooth,snappy,bouncy,gentle,dock}`
   tokens (`glass-ui/src/styles/tokens.css:159-163`) generated by
   `glass-ui/scripts/regen-spring-tokens.mjs`, which `import { springLinearStops } from
   "@mkbabb/keyframes.js"` (script line 18) and solves the four `(response, dampingFraction)` pairs
   in its PRESETS table (script lines 30-58). Those pairs MATCH keyframes'
   `demo/spring/springPresets.ts:17-42` exactly (smooth 0.5/0.86, snappy 0.35/0.65, bouncy 0.5/0.45,
   gentle 0.7/1.0) — keyframes' own comment confirms it: springPresets.ts:5-7 says "the same values
   glass-ui's `--spring-*` tokens were retuned to (G-AJ / AC.W*)". The supplier→consumer chain
   `keyframes.js → glass-ui` is live and bidirectional in CSS too: keyframes CONSUMES the emitted
   tokens (`ControlsPaneWrapper.vue:193` `transform var(--duration-slow) var(--spring-snappy)`) and
   legitimately OVERRIDES one on `:root` (`demo/@/styles/style.css:147` `--spring-snappy:
   var(--spring-smooth)` — a cascade override, not a dead-local, with an explaining comment at
   style.css:135-146). AW.W31's `proof:animation-coherence` is a glass-ui-internal audit; the only
   keyframes-side touchpoint is verifying the regen PRESETS still match `springPresets.ts` after any
   keyframes spring retune (a supplier-side canary, not an adoption wave).

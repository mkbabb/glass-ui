## Findings

1. **MISSING `@source` content-scan directive (binding requirement gap).** `web/src/style.css` carries `@import "tailwindcss"` (`:1`), `@import "tw-animate-css"` (`:2`), `@import "@mkbabb/glass-ui/styles"` (`:3`) — but NO `@source "../node_modules/@mkbabb/glass-ui/dist"`. There is no `tailwind.config.*` either (v4 CSS-first; verified absent). glass-ui CLAUDE.md (Consumer wiring) makes `@source` a binding requirement: the `/styles` bundle ships the token cascade + compiled SFC scoped CSS, but NOT the template-emitted Tailwind utilities (`h-full`, `shrink-0`, `text-destructive-foreground`, `rounded-pill`, …) — those must be generated by the consumer's content scan reaching glass-ui's `dist/*.js` render functions (AN.W2 rejected pre-generating them; `docs/tranches/AN/audit/W2-tailwind-utilities.md`). VERIFIED CONSEQUENCE: the installed `dist/glass-ui.css` has **0** occurrences of `.text-destructive-foreground` and `.h-full`; fourier's OWN built CSS (`web/dist/assets/index-57FkGzlZ.css`) also has `text-destructive-foreground` **ABSENT**. So the destructive variant of `<Button>`/`<Dialog>` (and any glass-ui-only utility no app SFC happens to also use) renders with that utility silently missing. Layout utilities that the app's own `src/` also uses (`h-full`, `w-full`, `shrink-0`, `pointer-events-none`, `rounded-pill`) ARE present — but only incidentally, because app code re-references them; remove an app reference and the glass-ui-only need vanishes too. This is the exact AN.W2 silent-vanish failure class.

Per CTX, 3.3.0 froze the width morph on first expand (AV.W9 shipped the fix-in-AW; the actual fix is AW.W1 → 3.4.0). So fourier's `^3.1.0` consumption path skips 3.3.0 entirely; the safe bump target is **3.4.0**. The pin currently floats `^3.1.0` (would allow `npm update` to pull 3.3.0 into these docks) — but the lockfile-resolved install is 3.1.0, so nothing is broken at HEAD today.

The value.js demo (`/Users/mkbabb/Programming/value.js/demo`, glass-ui pin `file:../glass-ui` → local 3.3.0 HEAD) is one of the heaviest glass-ui consumers in the constellation: 38 root-barrel imports + 15 `/dock` + a full `DockLayerGroup`/`DockLayer` multi-layer composition. ## Findings

1. **Dock is adopted at depth, and BOTH dock surfaces hit the AW.W1 simple-collapse regression.** Two `GlassDock` mount sites: `demo/@/components/custom/dock/Dock.vue:93` (`:collapse-delay="5000" :start-collapsed="isDesktop" :fit-content="true" :always-expanded="!isDesktop"` + a `<template #collapsed>` at line 197 — the SIMPLE two-layer collapse + a `DockLayerGroup` at line 94) and `demo/@/components/custom/panes/ConfigSliderPane.vue:131` (`:always-expanded="true"`). On desktop the main Dock is collapsible (`start-collapsed`, `collapse-delay`), so the 3.3.0 GlassDock width-morph freeze (AW.W1, AW.md:36/142) WILL regress this consumer's desktop top-dock. The `:always-expanded` sites dodge the collapse path. The local `dock/index.ts` re-exports `GlassDock, DockLayerGroup, DockLayer` straight from `@mkbabb/glass-ui/dock` — clean passthrough, no fork.

2. **The blob is a LOCAL FORK of glass-ui's `/goo-blob`, same lineage, identical config schema.** `demo/@/components/custom/goo-blob/{GooBlob.vue,types.ts,composables/*,shaders/*}` is a complete local copy. Field-set diff of `types.ts` `BlobConfig` against `src/components/custom/goo-blob/types.ts` is IDENTICAL (verified). `BlobMood` union matches (`idle|happy|curious|sleepy|excited`, local types.ts:3). This is the AU.W7 extraction ancestor — adoption is a clean swap, not a port.

3. **The demo's OWN CLAUDE.md flags both forks as extirpate-on-ship — this adoption is PLANNED and UNEXECUTED.** `demo/CLAUDE.md:78`: goo-blob "**consumes glass-ui pending — extirpation routes to a successor tranche post-glass-ui-ship**"; `demo/CLAUDE.md:86`: watercolor-dot "extirpation routes to successor tranche (**BlobDot ship pending**)". glass-ui 3.3.0 ships `/goo-blob` AND `/watercolor-dot` (`package.json:297`), so the pending precondition is now MET; the demo just hasn't executed the swap.

4. **ZERO ColorResolver injection — the local fork resolves color via a DOM-bound 2D canvas, the exact anti-pattern glass-ui's injected seam replaces.** `grep` for `colorResolver`/`color-resolver` across the demo returns NOTHING. The local renderer `demo/@/components/custom/goo-blob/composables/useMetaballRenderer.ts:58-68` resolves CSS color via `document.createElement("canvas").getContext("2d")` + `fillStyle`/`getImageData` (browser's color parser, DOM-required, returns `[0.5,0.5,0.5]` under SSR at line 62). glass-ui's `GooBlob` (`src/components/custom/goo-blob/GooBlob.vue:31-35`) requires a `colorResolver: ColorResolver` prop and THROWS on a no-resolver mount. value.js is the canonical injection target: `defaultBlobColorResolver` (`src/composables/color/index.ts:101`) is ITSELF built on value.js's `cssToOklch → oklchToGammaRgb` (Ottosson path) — so the value.js demo would inject a value.js-NATIVE, DOM-FREE resolver (a direct `parseCSSColor`/`colorUnit2` call from its own `src/index.ts` color classes), replacing the canvas hack. This makes the value.js demo the showcase the UNION-COORDINATION name-forward names.

5. **HeroBlob ALREADY drives mood + nudge — it is the live consumer AW.W10/W11 claim does not exist.** `demo/@/components/custom/color-picker/visual/HeroBlob.vue` calls `gooBlobRef.setMood("sleepy"|"happy"|"excited"|"idle")` (lines 45/52/59/78) on an idle/rapid-change timer + `nudge()` (line 60), and `demo/color-picker/App.vue:218-219` `provide(BLOB_CONFIG_KEY, blobConfig)`. AW.W10's HEADLINE finding (AW.md:151) is "`setMood`/`nudge`/`pointerAttraction` are exposed but no consumer calls them" — that is true of the glass-ui DEMO STORY but FALSE of value.js, which is the canonical mood/interaction consumer. AW.W10/W11's "demo exercises every shipped mood OR excise" gate (AW.md:151-152, inv §301) should target the value.js HeroBlob driver as the proof-of-life, OR coordinate that the local mood wiring ports onto the shipped surface.

6. **`pointerAttraction`/`pointerStrength` are exposed in the demo's BlobPane sliders but the deflection is unwired.** `demo/@/components/custom/panes/BlobPane.vue:73-75` ships a "Pointer" section (`pointerAttraction` -1..1, `pointerStrength` 0..0.3) — the very axes AW.W10 wires (AW.md:151). The demo authors the control surface but the local renderer has no felt soft-body deflection; adopting the AW.W10 shipped interaction lights up controls the demo ALREADY exposes.

7. **AW.W13 names the resolver-injection THROW edge the value.js demo must avoid.** AW.md:154: the goo-blob `var(--primary)` throw — `defaultBlobColorResolver→cssToOklch` feeds a `var()` token to value.js which throws. The value.js demo feeds CONCRETE color strings (`cssColorOpaque` from `COLOR_MODEL_KEY`, HeroBlob.vue:30/7 — a resolved opaque color, never a raw `var()`), so it dodges the W13 trap by construction — but the adoption wave's resolver must preserve that (inject value.js's parser, feed concrete strings, never a CSS custom-property token).

8. **Aurora is the ONE substrate already on the live subpath — the integration pattern is proven.** `demo/color-picker/App.vue:107` imports `useAurora, DEFAULT_AURORA_CONFIG, AuroraConfig` from `@mkbabb/glass-ui/aurora` and runs it (line 213) with a reactive `auroraConfig`. AuroraPane is a W0-stub delegating to `ConfigSliderPane` (`demo/@/components/custom/panes/AuroraPane.vue:4-8`), already rebound to the live `AuroraConfig` schema (`warpAmount`, `softmaxBeta`, `nucleiDrift`). This proves the demo can consume a glass-ui substrate subpath + drive it from a reactive config pane — the same pattern the blob swap follows.

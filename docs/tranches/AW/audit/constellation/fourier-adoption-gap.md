# fourier-adoption-gap — deepest constellation consumer; adoption is narrow (W17 Canvas2D + W22-26 atoms + the W1 dock-regression GATE), not broad

fourier-analysis is the single most-integrated glass-ui consumer in the constellation: 40+ import sites across `web/src`, already consuming GlassDock (3 sites), Configurator (3 sites), View-Transitions (router-level morph), the native `.scroll-progress` scroll-driven recipe, AnimatedDigit, MetricBadge, InfiniteScroll, useSidebarState, useClipboard, HoverPopover, the full reka surface (Dialog/Select/DropdownMenu/Collapsible/Tabs/Switch/Checkbox). It is NOT a greenfield adopter — most "adopt X" asks are already satisfied. The genuine AW openings are surgical, and one is a BLOCKING gate, not an opportunity.

## Findings

### 1. [BLOCKING — W1 dock regression] All three docks use the simple two-layer collapse that 3.3.0 breaks
fourier mounts `GlassDock` with the `#collapsed`-slot + default-slot two-layer pattern at THREE sites — the exact surface the 3.3.0 width-morph regression freezes on first expand:
- `web/src/components/visualization/EditorControlsDock.vue:56` — `<GlassDock :collapse-delay="2000" :start-collapsed="true" fit-content>` with `<template #collapsed>` at `:58`.
- `web/src/components/visualization/CanvasControlsDock.vue:41` — `<GlassDock ref="dockRef" fit-content :start-collapsed="true">` with `#collapsed` at `:98`; it also surfaces `dockRef.value?.expanded` to the parent at `:35`.
- `web/src/components/visualization/AnimationControls.vue:58` — `<GlassDock … :start-collapsed="true">` with `#collapsed` at `:65`.
The package.json pin is `"@mkbabb/glass-ui": "^3.1.0"` (`web/package.json`), which resolves to 3.3.0 on a fresh `npm install` — but the on-disk linked copy is still 3.1.0 (`web/node_modules/@mkbabb/glass-ui/package.json` version `3.1.0`). So fourier is currently SAFE only because it has not reinstalled. **Any bump must skip 3.3.0 and land on the AW.W1 fix (3.4.0).** This is the headline sequencing edge for fourier.

### 2. [W17 Constellation / useCanvas2D — REAL, 2 consumers] fourier hand-rolls the DPR-aware Canvas2D substrate twice
fourier owns a duplicated DPR + ResizeObserver Canvas2D init that W17's planned `useCanvas2D` substrate would absorb:
- `web/src/components/visualization/composables/useCanvasSetup.ts:16-46` — `setupCanvas()` does `devicePixelRatio`, `canvas.width = round(w*dpr)`, `ctx.setTransform(dpr,0,0,dpr,0,0)`, ResizeObserver lifecycle. Consumed by `BasisCanvas.vue` (the epicycle viz).
- `web/src/components/equation/ConvergencePlot.vue:80-95` — byte-for-byte the same DPR boilerplate (`canvas.width = round(rect.width*dpr)`, `ctx.setTransform(dpr,0,0,dpr,0,0)`, `ctx.lineCap="round"`), inline, NOT routed through `useCanvasSetup`.
These two are independent DPR-Canvas2D surfaces — the ≥2-consumer bar for the W17 `useCanvas2D` substrate is met INSIDE fourier alone. The W17 `Constellation` COMPONENT (a particle/point field) is a poorer fit — fourier's canvas work is epicycle chains + convergence curves + trails (`TrailManager`, `BasisCanvas.vue:53`), not a constellation point field; do NOT propose the component, only the substrate.

### 3. [W22-26 GLASS ATOMS — REAL via the cartoon-card shim] fourier carries a 15-site dead-class shim that the atoms sweep can retire
`web/src/style.css:103-112` defines `@utility cartoon-card { @apply cartoon-surface; … }` — a consumer-local shim resurrecting the `.cartoon-card` recipe glass-ui removed at C.W5. It has **15 application sites** across the tree (verified `grep -rln cartoon-card src` = 15 files; e.g. `MorphShapePreview.vue:4`, `GalleryCard.vue` cartoon shadows at `:193`/`:212`). The W22-26 "glass-card perfection" + "ONE unified .glass-material" + "cross-primitive four-state/tap-squish sweep" should DECIDE whether glass-ui re-ships a first-class card surface that subsumes `cartoon-card`, retiring this shim. This is the existing coordination ask `cartoon-card` (ADOPTION-ASKS booked) — a real card surface to land on.

### 4. [W4-8 derive-color front door — PARTIAL fit] fourier has a viz-color resolver + a token-contrast override that a derive-color door could simplify
`web/src/lib/colors.ts:22-50` (`cssVarToHex`) reads glass-ui's `--viz-*`/`--section-color-*` tokens out of computed style and converts hsl→hex for the Canvas2D paths (Canvas can't read CSS vars directly). It also re-resolves on `.dark` mutation (`App.vue:11-17`). fourier additionally OVERRIDES `--viz-amber`/`--section-color-5` at `web/src/style.css:118-126` (a legitimate `:root` cascade override, NOT a dead local — the token IS glass-ui's, shipped at `node_modules/@mkbabb/glass-ui/dist/styles/tokens.css:444,464`) to clear WCAG-AA contrast (3.54:1 → 4.6:1). The W4-8 "hand it ONE brand color, it derives the gamut-mapped palette" front door is INTERESTING but does NOT cleanly fit: fourier's viz palette is a fixed semantic set (section-color-1..N, rainbow, golden), not a single-brand derivation, and the override is a one-token contrast carry, not a palette regen. Treat as an anti-finding lean (see Anti-findings 4) — the contrast rebaseline is the real ask, not derive-color.

### 5. [Peer-dep divergence — adoption blocker note] fourier still uses `lucide-vue-next`; glass-ui 3.x moved to `@lucide/vue ^1.16.0`
`web/package.json` pins `"lucide-vue-next": "latest"` and 35 src files import from `lucide-vue-next` (e.g. `PaperView.vue:23`, `MobileFloatingToc.vue:5`). glass-ui 3.x renamed its icon peer to `@lucide/vue ^1.16.0` (CLAUDE.md Dependencies table). This is not a hard break (fourier imports lucide directly, not through glass-ui), but on the 3.4.0 bump the maintainer should align the icon peer to avoid two lucide copies in the bundle. Worth a one-line note in any wave that touches fourier's bump.

### 6. [a11y bump gate — already booked, flips on adoption] 2 e2e keystones are `test.fixme`'d pending the bump
`web/e2e/visualization-ux.spec.ts:110` and `:133` are `test.fixme`'d against the glass-ui `ConfiguratorLayer` `aria-hidden-focus` defect. Per the hub ledger that defect SHIPPED FIXED in glass-ui 3.1.1 (`ConfiguratorLayer.vue:144` `:inert`). On the AW 3.4.0 bump the maintainer un-`fixme`s these two — they flip to live asserts. Sequencing: the bump that adopts W1's dock fix ALSO clears this booked a11y residual in one move.

## Anti-findings (verified FINE / already done / poor fit)

1. **View-Transitions: already adopted at the SOTA level.** `web/src/router/index.ts:2` imports `supportsViewTransitions`, brackets viz-morph navigations in `document.startViewTransition` with a PRM carve and a parked-promise update callback (`router.beforeResolve`/`afterEach`). There is NO useViewTransition gap — fourier consumes the substrate's CSS half + the router seam correctly. Do not propose `useViewTransition` here.
2. **Scroll-progress: already on the native scroll-driven recipe.** `PaperView.vue:314` uses `<div class="paper-progress-bar scroll-progress" />` driving `scaleX` off a `scroll()` timeline with a JS fallback gated on `CSS.supports("animation-timeline","scroll()")` (`PaperView.vue:158`). W16 DeckProgress / scroll-driven needs NOTHING here — the SOTA path is live.
3. **Aurora / GooBlob backdrops: NO fit.** The app backdrop is `paper-texture` (`App.vue:23`, used at 2 sites only) — a deliberately quiet paper substrate behind a typeset Fourier treatise + precision viz canvases. A WebGL aurora/blob behind a math paper or epicycle canvas would FIGHT the content (legibility + the canvas's own color semantics). No decorative full-bleed WebGL surface exists or is wanted. Honest negative: do not propose aurora/blob adoption for fourier.
4. **derive-color front door (W4-8): poor fit.** fourier's palette is a fixed semantic viz set resolved from glass-ui's `--viz-*`/`--section-color-*` tokens (`colors.ts:22`), not a single-brand derivation. The only real color ask is the AA-contrast token rebaseline (Finding 4 / Wave input). Do not propose the one-brand-color derive door.
5. **useCountup: AnimatedDigit already covers it.** Coefficient amplitudes animate via `AnimatedDigit` (`CoefficientsSpectrum.vue:99`, consumed at 3 panels: `CoefficientsPanel.vue`, `EqCoefficientsPanel.vue`, `CoefficientsSpectrum.vue`). The `[data-countup]` editorial walker is for prose number runs; fourier's numbers are reactive viz values better served by the existing damped-numeral component. No gap.
6. **vReveal: no real surface.** The gallery grid (`GalleryInfiniteGrid.vue:30`, `v-for` over `GalleryCard`) and tab panels use a local `[data-state="active"][role="tabpanel"]` slide-in (`style.css:80`) + cartoon hover-lift. A `[data-reveal]` entrance directive would be a marginal nice-to-have, not a ≥2-consumer demand. Skip.
7. **Local `GlassTimeline.vue` is correctly app-local, NOT a duplicate.** `web/src/components/visualization/GlassTimeline.vue` is a thin epicycle-`t` scrubber over glass-ui's `<Slider variant="glass-scrubber">` with dock-keep-open wiring (`:21`) — a domain wrapper, not a re-implementation of glass-ui's exported GlassTimeline. No retirement ask.
8. **Configurator parameter panels: already adopted, no gap.** `BasisSelector.vue:5`, `CoefficientsPanel.vue:4`, `ContourSettings.vue:19` use `ConfiguratorLayer`/`ConfiguratorRow`. The density/dividers/cloneMode surface is sufficient; no W-wave Configurator ask from fourier.
9. **No audio.** The lane question re: audio is a negative — no AudioContext / WebAudio surface exists (the one `audio` grep hit is `AdminAuditLog`, unrelated). No audio-reactive adoption.

## Findings

1. **glass-ui's OWN `@mkbabb/*` peer ranges are stale vs the published upstreams — the single substantive constellation hazard.** glass-ui/package.json:615 peers `@mkbabb/keyframes.js: "^2.2.0 || ^3.0.0"` and :616 peers `@mkbabb/value.js: "^0.10.0"`. The registry-latest of both is **keyframes 4.0.0** (keyframes.js/package.json:3) and **value.js 0.11.0** (value.js/package.json:3), verified via `npm view`. `^2.2.0 || ^3.0.0` does NOT admit 4.x; `^0.10.0` (= `>=0.10.0 <0.11.0`) does NOT admit 0.11.0. Both are flagged optional in `peerDependenciesMeta` (glass-ui/package.json:627-642) so `npm install` emits a WARN, not an ERESOLVE — but any consumer that bumps keyframes→4 / value→0.11 alongside a glass-ui bump gets a peer-mismatch warning AND a dual-instance risk on the shared color/spring singletons. This is a glass-ui-side fix (widen the peer ranges), not a consumer fix.

2. **keyframes.js 4.0.0 bundles value.js 0.11.0 as a HARD dependency (not peer) — the dual-value.js-instance trap.** keyframes.js/package.json:86 declares `"@mkbabb/value.js": "^0.11.0"` under `dependencies` (not peer). glass-ui peers value.js `^0.10.0`. A consumer that has glass-ui (wanting value 0.10) + keyframes 4 (forcing value 0.11) installs TWO value.js instances. value.js is a color-singleton seam (glass-ui's `ColorResolver` / OKLCh core consumes `@mkbabb/value.js`) — two instances = two color caches / two `Color` prototypes, the classic `instanceof` + module-singleton break. No consumer is in this state YET (all resolve value 0.10.0 today), but it is the precondition that detonates on the first keyframes-4 bump.

3. **No tailwind-3 / vue-<3.5 breakage anywhere — every consumer is already on the glass-ui-required floor.** All six resolve `tailwindcss 4.3.0` (≥ glass-ui's `^4.0`), all resolve `vue 3.5.34/3.5.35` (≥ `^3.5`), all resolve `reka-ui 2.8.2–2.9.9` (within `^2.0`), all resolve `@vueuse/core 14.3.0` (within `^14.0`), all carry `tw-animate-css 1.4.0` (≥ `^1.2.5`). A glass-ui bump breaks NO consumer on the framework-peer axis. (Verified per-repo resolved pins, all cites in the matrix.)

4. **file:-link vs registry-resolve discipline is CORRECT and CI-proven for both file:-link consumers.** value.js (`file:../glass-ui`, package.json:69) and keyframes.js (`file:../glass-ui` optionalDep, package.json:89 = `^3.3.0`) are the only two file:-shaped consumers. value.js CI (.github/workflows/ci.yml:46-58) checks out `mkbabb/glass-ui` to `../glass-ui` then `npm ci` — the file:-link resolves from source, the documented inv-K-4 shape. keyframes.js CI (.github/workflows/ci.yml:14-25) runs its LIBRARY gate glass-ui-FREE (the dangling `file:../glass-ui` optional link is tolerated non-fatally, exit 0) and its DEMO gate (lines 154-159) `git clone --branch v3.2.0` PINS glass-ui to a tag, not HEAD — the reproducibility-correct shape. Both CIs use `npm ci` (lockfile discipline). The monorepo-layout cascade lesson is HONORED: registry-resolve in CI for the app consumers, file: in dev for the two library siblings, tag-pin where a sibling source build is needed.

5. **keyframes.js is the staging ground for the 4.0.0 cascade — its lock already carries glass-ui 3.3.0 + value.js 0.11.0 co-resolved.** keyframes.js/package-lock.json resolves `@mkbabb/glass-ui 3.3.0` (registry) + `@mkbabb/value.js 0.11.0` + `reka-ui 2.9.9`. So the repo that will FIRST exercise "glass-ui 3.3.0 standing next to value.js 0.11.0" is keyframes.js's own demo. Because keyframes' library gate is glass-ui-free and its demo gate pins glass-ui v3.2.0 (NOT 3.3.0/3.4.0), the peer mismatch is currently MASKED in keyframes CI — it will surface the moment the demo pin advances to a glass-ui that itself pulls value 0.10 against the demo's value 0.11.

6. **words/floridify resolves glass-ui through the WORKSPACE ROOT, not its frontend dir — and there is a STALE vendored 3.1.1 snapshot that is NOT the live resolution.** words/package.json:6-8 declares `workspaces: ["frontend"]`; frontend deps hoist to the root `node_modules`. 7. **muster declares NO keyframes dep yet its lock carries keyframes 2.2.0 — a transitive optional-peer auto-install.** muster/frontend/package.json has no `@mkbabb/keyframes.js` line, but the lock (line 2174-2176) resolves keyframes **2.2.0**, pulled as glass-ui 3.1.0's optional peer (npm auto-installs satisfiable optional peers). muster's `@keyframes first-run-walk-in` (FirstRunWalk.vue:296) is a CSS at-rule, not the package — no direct keyframes consumption.

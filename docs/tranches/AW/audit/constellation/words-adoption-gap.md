# words-adoption-gap — heavy, mature glass-ui adopter (143 import sites); one MISSING `@source` content-scan + one dock-regression-EXPOSED site are the only real gaps; Command-palette is a NON-fit (custom search shell wins); most AW waves are upstream-internal with words only needing token-name stability

words/Floridify (frontend, `@mkbabb/glass-ui ^3.0.0`, `@mkbabb/keyframes.js ^2.2.0`) is one of the deepest consumers in the constellation: 143 glass-ui import lines across 23 subpaths. It is NOT a shadcn-base consumer (no `src/components/ui/` dir) — it composes glass-ui's `custom/`+`ui/` PACKAGES (button 29×, hover-card 13×, toast 11×, tooltip 9×, card 8×, badge 7×, popover/forms/confirm-dialog 5× each, dropdown-menu/dialog/sidebar 4× each, dock 2×, dark 2×, carousel 2×, typewriter 1×) into its OWN heavy chrome (a `ThemedCard` mastery-themed card system, a bespoke `SearchBar` shell, a `themed-cards/` CSS tree). All cites verified at HEAD `master` today.

## Findings

1. **MISSING `@source` directive — the binding content-scan is absent.** `src/assets/index.css:1-6` carries `@import 'tailwindcss'` + `@import 'tw-animate-css'` + `@import '@mkbabb/glass-ui/styles'` + `@variant dark (&:where(.dark, .dark *))` — three of the four binding consumer-wiring requirements. The fourth, `@source "../node_modules/@mkbabb/glass-ui/dist"`, is **absent everywhere**: `grep -rn "@source"` over `src/` returns nothing (exit 1). Vite config uses the auto-detecting `@tailwindcss/vite` plugin (`vite.config.ts:7,42`) whose content scan EXCLUDES `node_modules` by default, so glass-ui's compiled `dist/*.js` render-functions (layout utilities `h-full`/`shrink-0`/`flex-col`, CVA variant classes `text-destructive-foreground`/`rounded-pill`) are NOT scanned. Per glass-ui CLAUDE.md this is "a binding requirement for any consumer mounting glass-ui components" — without it those utilities "render silently absent." That words renders today suggests its OWN broad utility usage (36 glass-* atom sites, 62 `duration-fast`, etc.) happens to materialize the overlapping set, but any glass-ui-internal-only utility on a mounted primitive is a latent silent-vanish. This is the single highest-value adoption fix and is a SHIPPED-surface gap (not AW-gated).

2. **ThemeSelector dock is EXPOSED to the 3.3.0 width-morph regression; the other two dock sites are immune.** `ThemeSelector.vue:6` mounts `<GlassDock ref="dockRef" manual :start-collapsed="!editModeEnabled">` — a collapse/expand dock that animates the width morph, i.e. the exact 3.3.0 regression (width morph freezes on first expand). It is admin-gated (`ThemeSelector.vue:3` `v-if="isMounted && isAdmin"`) so blast radius is small, but a naive `^3.0.0`→`^3.3.0` bump would visibly break it. The other two mounts — `WordListView.vue:22` and `WordListView.vue:109` — both use `always-expanded` and never run the morph, so they are immune. Verdict: words must NOT bump to 3.3.0; consume path is **3.4.0** (AW.W1 dock-collapse fix) for the admin dock site.

3. **`useGlobalDark` is wired but the FOUC anti-flash script is hand-rolled, not glass-ui's.** `App.vue:20,29` imports + calls `useGlobalDark()`; `useStateSync.ts:5` also imports it. The FOUC pre-paint guard at `index.html:41-46` is a hand-written Pinia-persisted-store reader (`uiState.theme`), NOT glass-ui's shipped `darkModeSyncScript()`/`installDarkModeSync()` (the `/dark` subpath FOUC helpers, AU.W9). This works but is a small adoption gap — glass-ui ships the exact primitive words re-implements. Low priority (the local one reads from words' own Pinia store, which glass-ui's generic helper does not know about), so likely a justified local override, not a defect.

4. **Cartoon-shadow override is on a PARTIALLY-DEAD token.** `theme.css:86-89` (+ dark arm `125-128`) overrides `--shadow-cartoon-color{,-soft,-hover,-hover-soft}` on `:root`/`.dark`. glass-ui's `.shadow-cartoon-{sm,md,lg}` utilities (consumed in 10+ words sites — `Sidebar.vue:7`, `NotificationToast.vue:14`, `SidebarContent.vue:20,58,75,103`, `SidebarSection.vue:22`, `SidebarWordListItem.vue:10`) read `--shadow-cartoon-{sm,md,lg}` (glass-ui tokens.css:543-551), which are built from `var(--shadow-color)` — NOT from `--shadow-cartoon-color`. glass-ui's own comment calls `--shadow-cartoon-color` "kept for tiered cartoon utilities" (tokens.css:538) but the live sm/md/lg formulas do NOT reference it. So words' four-token color override is a partial dead-orphan: it does NOT retint the cartoon stamp words actually paints. The cartoon stamp IS still dark-adaptive (via `--shadow-color`←`--foreground`, which `.dark` re-resolves at theme.css:120), so it works by accident of the construction, but the override block is doing nothing the consumer thinks it is. Reconcile-or-delete candidate.

5. **Command palette is a NON-fit; the bespoke `SearchBar` shell is the right call.** `SearchBar.vue` (348 lines) composes `SearchBarShell` + `SearchBarDropdowns` + `ExpandModal` + autocomplete/navigation/focus/scroll composables with a dual-mode (lookup/wordlist/stage) orchestrator, scroll-shrink animation, inline autocomplete-text completion, and a thin loading-progress bar. glass-ui's `Command`/`Combobox` (reka-ui cmdk) is a flat single-list filter — it cannot host this multi-mode scroll-aware orchestrator. The only glass-ui search-adjacent symbols words uses are `ConfirmDialog` (SearchBar.vue:105). HONEST NEGATIVE: do NOT propose a Command-palette adoption for words; the custom shell is correctly bespoke.

6. **Typewriter is adopted (1 site, admin/title); scrolling-text is NOT used and has no obvious gap.** `AnimatedTitle.vue:11` uses `TypewriterText` with a tuned config (ngram, errorRate, cursor) for the word title. `grep` finds zero `ScrollingText`/marquee usage — definition titles use `truncate`/`line-clamp` (`WordListView.vue:17-18`) rather than overflow-marquee. No demand for the scrolling-text subpath. HONEST NEGATIVE.

7. **Carousel renders in the HIGH-TRAFFIC definition surface.** `ImageCarousel.vue:84-90` imports the full `Carousel*` family + `CarouselApi` from `/carousel` (vueuse-bearing subpath, correctly chosen over the root barrel); it mounts in `DefinitionDisplay.vue:91`. AW.W30 (carousel redesign) is an internal restyle of the SAME family — words inherits it free on a 3.4.0+ bump with zero code change, PROVIDED W30 holds the `Carousel*` public API + `useCarousel`/`CarouselApi` types stable.

8. **Glass-atom CSS classes are used in 36 sites — these are AW W22-26 restyle surfaces.** `glass-wash` (17×), `glass-floating` (10×), `glass-quiet` (5×), `glass-overlay` (4×) appear across words templates+CSS. AW W22-26 (GLASS ATOMS — unified `.glass-material` rim/specular, glass-card perfection, the four-state/tap-squish sweep) reworks these class IMPLEMENTATIONS. words inherits the visual upgrade free IF the class NAMES (`glass-wash`/`glass-floating`/etc.) survive the consolidation. The risk is a rename to `.glass-material`-keyed classes; words needs the old names kept as the public CSS surface (or a documented migration).

9. **Heavy animation-token consumer — W31's load-bearing constraint for words is token-NAME stability.** words reads glass-ui motion tokens pervasively: `--ease-*` 65×, `duration-fast` 62×, `ease-spring-snappy` 35× (a glass-ui `@theme` alias at theme.css:337 → `--spring-snappy`), `duration-normal` 20×, `--spring-*` 14×, plus `var(--ease-spring-snappy)`/`var(--ease-spring-smooth)` raw in `transitions.css:91-104`. AW.W31 (animation-coherence audit — "ONE spring vocabulary", `--spring-*`/`--ease-*`/`--duration-*` canon) is an INTERNAL glass-ui audit, but its `proof:animation-coherence` could RETUNE or rename the spring/ease family. words is NOT adopting a new W31 surface — it is EXPOSED to W31 token churn. The adoption-relevant ask: W31 must preserve the `--ease-spring-{snappy,smooth,bouncy,gentle}` + `--ease-standard` + `--spring-*` + `--duration-{fast,normal,slow}` NAMES (retuning values is fine, renaming/removing breaks 180+ words sites).

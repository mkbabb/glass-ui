# words-consumption — heaviest-surface consumer (23 subpaths, 100+ import sites), THREE minors stale (3.0.0), and a LIVE GlassDock collapse-regression mount that pins it OFF ^3.3.0

Lane verdict: words/Floridify is the constellation's broadest glass-ui consumer by import count, pinned to `^3.0.0` (`frontend/package.json:27`) with `3.0.0` installed from the npm registry tarball (NOT a `file:` link — `package-lock.json:888` resolves `registry.npmjs.org/.../glass-ui-3.0.0.tgz`). Its peer stack is fully compatible with 3.4.0. Two real adoption blockers: (1) it mounts a `manual` collapse/expand GlassDock — the exact path the 3.3.0 regression breaks, so its consume target is **3.4.0 (post-AW.W1)**, never ^3.3.0; (2) it carries **no content-scan reaching glass-ui's dist** (no `@source`, no `@config`), a latent binding-requirement gap.

## Findings

1. **Pin is `^3.0.0`, installed `3.0.0` from the registry (not a workspace link).** `frontend/package.json:27` `"@mkbabb/glass-ui": "^3.0.0"`; `node_modules/@mkbabb/glass-ui/package.json` → `version: 3.0.0`; lockfile `package-lock.json:886-888` resolves the npmjs tarball. This is the **biggest version gap in the constellation** (3.0 → 3.3 = three minors: the AT/AU/AV cuts — color-core, WebGL substrate, procedural-color, offscreen-pause, DI factories, motion surfaces all missing). value.js/keyframes.js are `file:../glass-ui` links; words is a registry consumer, so it only moves on a published bump.

2. **HEADLINE — words mounts a regression-bearing GlassDock.** `ThemeSelector.vue:6` `<GlassDock ref="dockRef" manual :start-collapsed="!editModeEnabled">` with a `#collapsed` slot (`:8`) and **programmatic `dockRef.value?.expand()` / `.collapse()`** (`ThemeSelector.vue:178,186`). This is precisely the simple two-layer collapse→expand width-morph that the KNOWN 3.3.0 regression freezes on first expand. A bump to ^3.3.0 would visibly break this admin edit-mode toolbar. The 3.0.0 surface words uses (`manual`, `start-collapsed`, `always-expanded`, exposed `expand()`/`collapse()`, `orientation`) is all present and unchanged at 3.3.0 (`dist/components/custom/dock/GlassDock.vue.d.ts`), so the consume path is prop-stable — the ONLY blocker is the morph bug. **Consume target = 3.4.0 (AW.W1 fix).**

3. **The other two docks are `always-expanded` → NOT regression-affected.** `WordListView.vue:22` `<GlassDock always-expanded class="flex-shrink-0">` and `WordListView.vue:109` `<GlassDock always-expanded>` never enter the collapse-morph path, so they are safe even on a hypothetical 3.3.0. Only the ThemeSelector dock is the blocker.

4. **Content-scan BINDING-REQUIREMENT GAP: no `@source` reaching glass-ui's dist, and likely no `@config` loading the content array.** `src/assets/index.css` has the token cascade correct (`@import 'tailwindcss'` :1, `@import 'tw-animate-css'` :2, `@import '@mkbabb/glass-ui/styles'` :3, `@variant dark` :6) but **no `@source "../node_modules/@mkbabb/glass-ui/dist"`** anywhere in `src/` (verified: zero `@source` hits). `tailwind.config.ts:16` sets `content: ['./src/**/*.{ts,tsx,vue}']` — but the build uses `@tailwindcss/vite` (`vite.config.ts:45`) with **no `@config` directive** in any CSS, so v4 likely does not even load that config's content array. Either way the scan never reaches glass-ui's compiled templates. I verified the installed `/styles` bundle (`dist/styles/index.css`) does NOT pre-generate utilities: `dist/glass-ui.css` grep for `shrink-0|text-destructive-foreground|rounded-pill` = **0 hits**. So glass-ui-unique CVA variant utilities (e.g. `text-destructive-foreground`, `rounded-pill`) silently vanish unless words coincidentally authors the same class in its own `src/`. It renders today because the common layout utilities (`h-full`, `flex`, `shrink-0`) ARE authored in words' own source — but this is a latent, fragile gap, not a clean wiring.

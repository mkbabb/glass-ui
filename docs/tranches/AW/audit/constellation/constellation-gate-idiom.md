The lane question: how does each consumer verify (npm scripts / `proof:*` / vitest / playwright / CI workflows)? Does it have a gates manifest? What is the house born-RED convention? Then: the recommended gate SHAPE a glass-ui-adoption wave lifts into each repo so the adoption carries a native, born-RED gate.

All cites are files read at HEAD on 2026-06-07. Pins below are the ACTUAL `package.json` reality at HEAD, which diverges from the constellation ledger (the ledger says several are `^3.1.0`; HEAD shows fourier/speedtest/muster at `^3.1.0`, words at `^3.0.0` — verified file:line below).

### F4 — keyframes.js: the `proof:*` MOTHERLODE — 26 `proof:*` scripts, a `proof:all` aggregate, a `proof:ci-coverage` self-gate, AND `proof:repin-safe` — the ONE directly-liftable upstream-adoption gate in the whole constellation
`/Users/mkbabb/Programming/keyframes.js/package.json` has 26 `proof:*` scripts; `proof:all` chains ~22 of them + `vitest run`. The house convention is explicit born-RED: each `proof-*.mjs` collects `fail[]`, prints `✗`/`✓`, `process.exit(1)` on any fail. Critically:
- **`proof:ci-coverage`** (`scripts/proof-ci-coverage.mjs:34-52`) is a META born-RED gate: every `proof:*` in package.json MUST appear as `npm run <gate>` in `ci.yml` or it reds (3 recorded exclusions, ci-coverage.mjs:28-32). So an adoption gate authored here is STRUCTURALLY forced into CI — you cannot author a gate and forget to run it.
- **`proof:repin-safe`** (`scripts/proof-repin-safe.mjs`) is the template the glass-ui-adoption waves should COPY. It certifies an upstream re-pin (`@mkbabb/value.js ^0.10→^0.11`) is NON-BREAKING *before the lockfile moves*: it `npm pack`s the PUBLISHED target version into a throwaway tmp dir, derives the consumer's LIVE imported-name set from `src/` (repin-safe.mjs:79-109), and reds if any consumed name is missing from the published export table (repin-safe.mjs:234-254). It is deliberately NOT in `proof:all` (it reads the published registry artifact, not the source tree — repin-safe.mjs:5-8). This is EXACTLY the gate a `^3.3.0 → ^3.4.0` glass-ui re-pin wants: pack `@mkbabb/glass-ui@3.4.0`, assert every subpath symbol the consumer imports (`GlassDock`, `DockIconButton`, …) survives, BEFORE bumping the pin.
CI (`/Users/mkbabb/Programming/keyframes.js/.github/workflows/ci.yml:93-127`) invokes each `proof:*` as its own named step; a `demo gate` job (ci.yml:130+) checks out + builds the `file:../glass-ui` sibling (ci.yml:154-159) then runs Playwright inv-γ (paints) + inv-δ (no occlusion). Note keyframes.js consumes value.js (`^0.11.0`) but NOT glass-ui as a dep — glass-ui appears only as a DEMO devDep resolved `file:../glass-ui`; its demo mounts GlassDock (`demo/app/App.vue`, `demo/@/components/custom/dock/TopDock.vue`).

### Step 2 — `<NumberField keep-dock-open>` decision

Read `src/components/ui/number-field/{NumberFieldInput,NumberFieldIncrement,NumberFieldDecrement}.vue` — which interaction holds the dock open? Likely:

- The +/- buttons fire as discrete events; no drag duration. `keep-dock-open` semantically applies to a continuous interaction.
- If the user holds the +/- button for repeat-firing, that's a quasi-drag; `keep-dock-open` would suppress dock collapse during repeat.
- If the user types a numeric value via the input, that's keyboard input; `keep-dock-open` would suppress collapse during input editing.

**Decision tree**:
- **Option A — Wire NumberField input editing to `keep-dock-open`**: while focused-and-editing, hold the dock open. Default `true`. ≥ 2 consumer mature substrate.
- **Option B — Document Slider-only**: the contract is for continuous-pointer-drag interactions. NumberField interaction model differs. Document in DESIGN.md + Slider's keep-dock-open prop comment.

**Default decision**: Option B. Per Rε B5 cross-substrate coupling research, NumberField input is keyboard-driven; the dock-keep-open contract optimizes for pointer-drag (where pointer leaves the dock surface). NumberField's edit-mode is pointer-anchored; the existing dock collapse-after-blur semantics already handle it correctly.

If Option A is taken instead, verify `<NumberField>` exposes `keepDockOpen?: boolean` + injects `dockKeepOpen`/`dockRelease`/`dockHeld` similarly to Slider. Add a demo cell demonstrating.

### 1. `ORCHESTRATION.md` — add **Worktree Isolation** section

Append after the `## Wave Model` section:

```markdown
## Worktree Isolation

For parallel multi-agent waves with potentially-shared file bounds,
dispatch each agent with `Agent isolation: "worktree"`. The Agent tool
creates a temporary git worktree so each agent works on an isolated
copy of the repo; the orchestrator integrates at wave close.

- **REQUIRED** when ≥ 2 parallel agents may write `src/styles/*` or
  any shared component territory (cornerstone refactors, vocab migrations,
  rename lanes, etc.).
- **RECOMMENDED** for any wave with ≥ 3 parallel agents.
- **OPTIONAL** for 2-agent waves with strictly disjoint trees (verified
  by file-bound enumeration before dispatch).
- **NEVER** for single-agent or read-only audit waves (cost without benefit).

The orchestrator's integration step at wave close: read each worktree's
final state (via the worktree path returned by the Agent tool), apply
the changes via Edit/Read in the main repo, then commit the integrated
diff. Agents NEVER commit themselves (per the Git Discipline section
in AGENT_DISPATCH_TEMPLATE.md).
```

### 2. `tranche/AGENT_DISPATCH_TEMPLATE.md` — add **Hardened Agent Git Clause**

Replace any existing "no destructive git" guidance with:

```markdown
## Hardened agent git clause (binding non-negotiable)

NEVER run any working-tree-mutating git subcommand for ANY reason.
Forbidden subset:
- `git add` / `git commit` / `git stash` / `git stash pop`
- `git checkout HEAD --` / `git checkout <branch>` / `git restore`
- `git reset` (any flag) / `git rm` / `git mv`
- `git rebase` / `git merge` / `git pull` / `git fetch` with mutation
- `git branch -D` / `git tag -d` / `git push`

Read-only git permitted: `git status` / `git log` / `git diff` /
`git show` / `git ls-tree` / `git rev-parse` / `git config --get`.

The orchestrator owns the index, the branch, the working-tree state.
Agents own only file edits in their bounded scope. If a stash-like
operation seems necessary, halt and report to the orchestrator instead.

Per the working-directory hygiene precept: NEVER run `cd <dir> && git
<cmd>`. Use `git -C <dir> <cmd>` so the shell pwd doesn't drift across
subsequent Bash calls.
```

```markdown
## 2026-05-06 - Worktree Isolation For Multi-Agent Shared-File Waves

- **Source**: glass-ui J W3 + W4 + W5 + W6 parallel-agent dispatches.
- **Failure**: J's parallel-agent waves shared a single working tree;
  W3 Lane B reported "external rollback between tool calls" as parallel

  orchestrator integrates at wave close.
- **Check**: ORCHESTRATION.md ## Wave Model + ## Worktree Isolation
  sections; dispatch templates name the isolation policy.

## 2026-05-06 - Agents Never Stage Or Commit

- **Source**: glass-ui J W1 + W4.A `git stash` precept violations
  (recurrence under prior "as recovery mechanism" loophole) +
  J W3 commit accidentally absorbing W4.A's PresetEditor rename adds
  (index pollution from agent's own `git add`).
- **Failure**: prior precept ("never run `git stash` as recovery") had
  a loophole agents drove through (state-inspection probe); agents
  also ran `git add` independently, polluting the orchestrator's
  staging.
- **Rule**: agents NEVER run any working-tree-mutating git subcommand
  for any reason. Read-only git only. The orchestrator owns the index.
- **Check**: AGENT_DISPATCH_TEMPLATE.md ## Hardened agent git clause;
  dispatch prompts cite it explicitly.

## 2026-05-06 - Use `git -C <dir>` Not `cd <dir> && git`

- **Source**: glass-ui J W0 Lane II shell drift after `cd docs/precepts
  && git ...` invocation; subsequent Bash calls operated from the
  submodule path until orchestrator manually `cd`'d back.
- **Failure**: working directory persists across Bash calls; chained
  `cd && git` patterns leak into subsequent commands.
- **Rule**: always use `git -C <dir> <cmd>` for git operations in
  subdirectories. Same rule for any other tool that supports `-C` /
  `--directory` / similar (npm: `npm --prefix <dir>`, etc.).
- **Check**: dispatch templates + ORCHESTRATION.md cite the idiom.
```

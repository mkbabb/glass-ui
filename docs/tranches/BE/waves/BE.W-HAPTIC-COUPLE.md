## BE.W-HAPTIC-COUPLE — `useHaptic`: feature-detected `navigator.vibrate` coupled to snap / detent / completion

**Band:** 8 (JUBILANCE primitives + lock) · **Severity:** major · **Deps:** the SITED couplings ride W-DOCK-FISSION (the detent snap), W-DRAG-MORPH (the fling-snap — SHIPPED), W-DOCK-NOWPLAYING-PILL (the transport tap), and `useCelebrationBurst` (the completion). Gate-locked by `proof:jubilance`. No π (haptic is non-visual — a device-free + feature-detect assertion only).

**Goal.** Ship `useHaptic()` (`@mkbabb/glass-ui/motion-core` — vue-only, NO keyframes/vueuse peer, so it is root-barrel-eligible AND `/motion-core`-safe) — the library's ONE haptic-feedback primitive: a thin, feature-detected `navigator.vibrate` wrapper with a small named-pattern register (`tap` / `snap` / `detent` / `completion` / `error`) coupled to the platform's confirm-moments. The iOS-27 betters-claim: on Apple hardware a control SNAP (a drag releasing into a detent, a toggle flipping, a download completing) confirms with a crisp Taptic pulse — the gesture lands in the BODY, not only the eye. The web's `navigator.vibrate` is the only cross-platform proxy (no Taptic API in the browser), and it is genuinely useful on Android/Chrome; on iOS Safari (where `vibrate` is unsupported) it feature-detects to a clean no-op — so the coupling is SAFE everywhere and FELT where the platform allows. glass-ui's snap moments (the `useDragMorph` fling-to-nearest, the dock detent, the completion seal) confirm visually but NEVER haptically — this couples the body-confirm onto the EXISTING snap callbacks with zero new gesture engine.

**Starting state — the born-RED anchor (verified on disk).**
- `grep -rn "useHaptic|navigator.vibrate|vibrate(" src/` returns **ZERO** — the composable and every `navigator.vibrate` call are genuinely ABSENT (verified 2026-06-20). No haptic path exists anywhere in the library.
- The snap callbacks the coupling targets ALL exist + fire today with NO haptic: `useDragMorph.ts` `onSnap(value)` fires ONCE on settle (the fling-to-nearest commit, the `committed` guard); `useSpringPress` `press()`/`release()`; `CompletionSeal.vue` `play` (the earned moment); the W-DOCK-FISSION detent (to land). Each is a clean call-site for the body-confirm — the haptic rides the EXISTING callback, it adds no listener.
- The PRM precedent: a haptic is motion-adjacent; but `prefers-reduced-motion` is a VISUAL-vestibular signal, NOT a haptic one — a haptic pulse is not a vestibular trigger, so it does NOT auto-suppress under PRM. The correct suppression axis is a consumer opt-out (`enabled` flag) + the browser's own permission model. (This is the load-bearing distinction the gate records.)

**Build (mechanism).**
1. **`src/composables/motion/core/useHaptic.ts`** (new, ~70L; lives in the keyframes-FREE + vueuse-FREE `core/` so it ships on `/motion-core` AND the root barrel — vue-only, no peer edge). `useHaptic(opts?: { enabled?: MaybeRefOrGetter<boolean> })` returns `{ supported: boolean; pulse: (pattern: HapticPattern | number | number[]) => void }`. `HapticPattern` is a named register (`'tap' | 'snap' | 'detent' | 'completion' | 'error'`) mapping to small `navigator.vibrate` ms arrays — `tap: 8`, `snap: [12]`, `detent: [6, 18, 6]` (a tiny double-tick), `completion: [10, 40, 18]`, `error: [20, 30, 20]` (the standard short-pattern vocabulary; all sub-100ms total, never a buzz). `supported` is the feature-detect (`typeof navigator !== 'undefined' && typeof navigator.vibrate === 'function'`); `pulse()` is a NO-OP when unsupported or `enabled` is false (so iOS Safari + an opted-out consumer get a clean no-op, never a throw). SSR-safe (the `typeof navigator` guard). NO own rAF, NO listener — `pulse()` is a pure imperative call the consumer fires from inside an EXISTING callback.
2. **The coupling seams (the consumer call-sites, NOT a new engine).** The library WIRES `pulse()` into the snap callbacks it already owns — each is a one-line addition inside an existing handler, never a new event path:
   - `useDragMorph.ts` `onSnap` → `haptic.pulse('snap')` (the fling lands → body-confirm). This is consumer-#1 (a SHIPPED gesture with a snap commit).
   - the W-DOCK-FISSION detent settle → `haptic.pulse('detent')` (the fission piece seats — consumer-#2, lands with W-DOCK-FISSION).
   - `useCelebrationBurst` completion / `CompletionSeal` `play` → `haptic.pulse('completion')` (the earned moment).
   The couplings are OPT-IN per call-site (each composable threads an `enableHaptic` prop default `false` so a silent consumer is byte-identical; a consumer flips it on).
3. **Barrel.** `export * from "./useHaptic"` in `src/composables/motion/core/index.ts` (the `/motion-core` engine-free barrel) — and it flows to the root barrel through the existing `motion/core` re-export (vue-only, root-barrel-safe, the `useLiquidFlex`/`usePointerVelocityField` precedent).

## BE.W-ANTICIPATE-FOLLOW — the anticipation pre-dip + follow-through overshoot register

**Band:** 8 (JUBILANCE primitives + lock) · **Severity:** minor · **Deps:** composes the SHIPPED `useSpring`/`useSpringPress` + `SPRING_PRESETS`; the SITED uses ride W-DOCK-NOWPLAYING-PILL (the transport press) + the existing Button/Card press register. Gate-locked by `proof:jubilance`. π rides the existing press-unify capture (extend, not new).

**Goal.** Ship the anticipation-and-follow-through register — a small `useAnticipate(spring, opts)` modulation (`@mkbabb/glass-ui/motion`, keyframes-bearing) that gives a deliberate one-shot action a tiny PRE-DIP before it launches (the wind-up) and a follow-through overshoot past the target before it settles (the classic Disney 12-principles anticipation + follow-through). The iOS-27 betters-claim: Apple's emphatic controls don't snap rigidly — a play button dips ~2% inward at the moment of press *before* the icon morphs (the anticipation tells the eye "something is about to happen"), and a card that lifts on tap overshoots its rest by a whisper *after* it lands (the follow-through reads as ALIVE mass, not a frozen target). glass-ui has the `press` spring (the sub-100ms tap) and `bouncy` (the emphatic overshoot) but has NO ANTICIPATION leg — every press goes straight to target with no wind-up. This adds the pre-dip as an opt-in modulation over the EXISTING spring, compositor-only + PRM-instant.

**Build (mechanism).**
1. **`src/composables/motion/useAnticipate.ts`** (new, ~80L). `useAnticipate(opts?: { dip?: number; dipMs?: number; preset?: SpringPresetName; respectReducedMotion?: boolean })` returns `{ play: () => void, value: Readonly<Ref<number>> }`. It composes ONE `useSpring` (reading a `SPRING_PRESETS` row, default `bouncy` for the follow-through overshoot). `play()` runs a TWO-PHASE target sequence on the SAME spring: phase 1 (the anticipation) sets `spring.target = -dip` (default `dip: 0.04`, a 4% pre-dip) for `dipMs` (default ~80ms, the wind-up); phase 2 sets `spring.target = 1` — the spring, now moving with negative velocity, launches FORWARD through 1 and overshoots (the ζ<1 bouncy follow-through), then settles. The consumer binds `value` to `transform: scale(1 + value·amplitude)` (the press-squish) — so the surface dips inward, launches, overshoots, settles. ONE spring, no second clock, no new rAF (the `useSpring` engine owns the loop). The follow-through is the spring's NATIVE overshoot (the `bouncy`/`press` ζ<1, never a hand-coded overshoot).
2. **The coupling (opt-in over the press register).** `useSpringPress` (and the Button/Card press surfaces that compose it) gain an OPT-IN `anticipate?: boolean` (default `false` — byte-identical default) that routes `press()` through the 2-phase `useAnticipate.play()` instead of the direct target-to-1. The CSS `--*-press-t` drive (the W-PRESS-UNIFY coupled brightness/specular leg) reads the SAME `value`, so the coupled effects leg dips + follows-through in lockstep (W-MOTION-CANON P3 fade-coupled-to-transform). The DEFAULT press is UNCHANGED (anticipate off → the existing direct-to-target press, byte-identical).
3. **Compositor-only + PRM-instant.** The modulation writes ONLY `transform: scale(...)` + the `--*-press-t` custom (never a layout property — the `proof:no-layout-animation` floor). Under `prefers-reduced-motion: reduce` the 2-phase sequence COLLAPSES to a direct target-to-1 with zero dip/overshoot frames (the `useSpring.respectReducedMotion` snap — the gesture confirms, the wind-up/follow-through motion is off; mirrors `useLiquidReveal.ts:186`). The dip/overshoot are vestibular-adjacent motion → correctly dropped under reduce.
4. **Barrel.** `export * from "./useAnticipate"` on `/motion` (keyframes-bearing via `useSpring`→kf, NEVER root-barrel).

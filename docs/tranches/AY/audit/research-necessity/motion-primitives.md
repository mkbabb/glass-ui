## §2 — The real keyframes.js surface (the parity-manifest ground truth)

**The version fork is the headline finding.** glass-ui's devDependency pins `^2.2.0`
(installed: 2.2.0); the peer range in `package.json` is `^2.2.0 || ^3.0.0 || ^4.0.0`; the
registry has 4.1.0 PUBLISHED; the sibling repo HEAD is 4.1.0.

**Installed 2.2.0 — 11 runtime exports** (enumerated from the dist):
`ElementMorph, ManualTimeline, NumericAnimation, RAFPlayback, ScrollTimeline, SmoothProgress,
SpringProgress, Timeline, loadAnimationEngine, springLinearStops, springTimingFunction`
(+ ~30 types incl. the heavy-class `Animation`/`CSSKeyframesAnimation`/`AnimationGroup` types and

**Published 4.1.0 — 24 static runtime exports** (from `src/animation/index.ts:29-114`): the
2.2.0 set PLUS `createNativeTimeline, stagger, flip, flipShared, drag, Draggable, decay,
decayRest, Sequence, resolveEasing, toEasing, AnimationOptionError, UnknownEasingError`; ~50
types (adds the stagger/flip/drag/decay/Sequence option types, `Easing`, `Tickable`,
`AnimateInput/AnimateOptions/KeyframeMap`, `MotionPathOptions/OffsetPath`,
`DrawSVGOptions/SVGDrawTarget`); and a 16-member `AnimationEngine` dynamic surface behind
`loadAnimationEngine()` (`Animation, CSSKeyframesAnimation, AnimationGroup, getAnimationId,
getTimingFunction, resolveKeyframes, animate, MotionPath, fromMotionPath, DrawSVG, fromDrawSVG,
presets, DIRECTIONS, FILL_MODES, defaultOptions, defaultLayerConfig`).

**Consequence:** W-MOTION2 §2.1 names `Sequence` explicitly, and §1's gap statement implies the
orchestration tier (stagger/flip/drag/decay) — NONE of which exists in the pinned 2.2.0. As
written, gate §3.1 SUITE-COMPLETE ("every public export of the PINNED keyframes.js appears in the
/motion dts") is either trivially small (pin stays 2.2.0 → 11 symbols, and the spec's own named
example `Sequence` is unsatisfiable) or requires a dev-pin bump to 4.1.0 the spec never states.
The fix is a one-line scope amendment, not research (§4 R1).

## §4 — Divined refinements (concrete, file:line)

**R1 — State the 4.1.0 dev-pin bump as move 0 (spec amendment).** `package.json` devDep
`@mkbabb/keyframes.js: ^2.2.0` installs a dist WITHOUT `Sequence`/`stagger`/`flip`/`drag`/
`decay`/`toEasing`/`resolveEasing`; 4.1.0 is published and the peer already allows `^4.0.0`.
Without the bump, `vue-tsc` fails on the first re-export and SUITE-COMPLETE cannot go GREEN.
Bump risk is LOW and verifiable in-repo: every glass-ui call site already passes a CALLABLE
`timingFunction` (`useNumericTransition.ts:43,52`; `useCountup.ts:11-12,120`), matching 4.x's
fail-explicit easing redesign (`keyframes.js src/animation/easing.ts:1-17`); the three classes
glass-ui constructs (`SpringProgress`, `SmoothProgress`, `NumericAnimation` — 9 import sites in
`src/`) persist across 2.2.0→4.1.0.

**R2 — The parity manifest must split STATIC vs DYNAMIC.** "Re-export the WHOLE public suite
verbatim" must NOT flatten the heavy engine onto the static barrel: in 4.x the heavy symbols
(`Animation`, `animate`, `presets`, `MotionPath`, `DrawSVG`, …) are reachable ONLY via
`loadAnimationEngine()` (`index.ts:116-220`) — that boundary is the package's deliberate
value.js isolation (`index.ts:1-27`). Verbatim re-export = the 24 static symbols + the erased
types + `loadAnimationEngine` itself; the manifest's heavy rows assert reachability THROUGH the
loader, not presence in the static dts.

**R3 — Single-source the spring pairs.** `MOTION_CURVES` should not re-type the (response, ζ)
pairs: lift the PRESETS table out of `scripts/regen-spring-tokens.mjs:57-83` into a shared
`src/` module that BOTH the regen script and `MOTION_CURVES` import (the no-second-authority
discipline the regen header itself names). Each spring row's JS twin is then
`springTimingFunction(preset)` — drift-proof against future retunes.

**R4 — Close the alias set in CURVE-TABLE-BOUND.** Gate §3.2 sweeps "tokens.css §2" — the
theme.css `--ease-spring-*` quartet (`theme.css:410-413,420`) would escape it. Either widen the
sweep to theme.css or record the fence (aliases resolve through their target's row). Same for
the alias rows inside tokens.css (`:203-214`): decide row-per-alias vs resolve-through, so the
gate is deterministic.

**R5 — Decide the value.js static-edge placement by MEASUREMENT, not research.** Re-exporting
the value.js `ease*` family statically from `/motion` adds value.js to `dist/motion.js`'s eager
graph — the exact edge keyframes 4.x keeps OFF its light barrel by design. The in-corpus
precedent is the AP.W3 carve (`src/motion.ts:17-31`: a cheap import must not drag a heavy peer).
Options: (a) accept the edge on `/motion` (value.js is already a transitive peer `^0.10.0`);
(b) carve the curves to a flat sibling (`/motion-curves` or onto the existing value.js-only
`/color`-style leaf pattern). `npm run profile:bundle` answers this in minutes.

**R6 — Name `cssTwinFor` in the no-fork clause.** keyframes 4.x already ships the JS→CSS
direction (`src/animation/easing.ts:50` `cssTwinFor`); `MOTION_CURVES` is the reverse
(CSS-token→JS-callable). Gate §3.4's grep should name `cssTwinFor` as the existing helper a
re-implementation would fork.

**R7 — value.js pin note.** Installed value.js is 0.10.0; the sibling repo is 0.11.2. The
0.10.0 dist already carries the full registry maps (verified live), so NO bump is required for
W-MOTION2 — but the parity manifest should record WHICH value.js version it enumerated against,
so a later bump re-runs the sweep instead of silently widening.

**R8 — CLAUDE.md staleness (motion rows).** (a) The dependency table says
`@mkbabb/keyframes.js ^2.2.0 || ^3.0.0` — the actual peer is `^2.2.0 || ^3.0.0 || ^4.0.0`.
(b) The `composables/motion/` tree listing names `useSpringOrchestrator` (zero hits in `src/`)
and `useDarkModeSync` (renamed `installDarkModeSync`, relocated to `composables/dark/` —

move should fold these corrections in.

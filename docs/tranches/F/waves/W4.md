# F.W4 - Tailwind Theme And Style Authority

**Opens after**: F.W3 component contract proof passes
**Agents**: 4 lanes with orchestrator-owned token decisions
**Hard gate**: Tailwind v4 theme compile proof passes; duplicated/global brittle CSS is removed or localized with parity evidence
**Status**: complete

## Purpose

Make the style system coherent before any plugin extraction or CSS byte target. F.W4 aligns Tailwind v4 theme namespaces, runtime tokens, component-local style authority, and story surfaces without changing visual language gratuitously.

## Scope

Included:

- Correct Tailwind v4 theme variable namespaces for font, text, leading, tracking, blur, shadow, easing, color, radius, and animation utilities.
- Replace self-referential `@theme` variables with explicit theme/runtime bridges.
- Add a compile probe that proves expected utility classes exist.
- Resolve undefined shimmer/progress/notification tokens.
- Converge dock CSS authority after W2.
- Move component-sized global utilities into component scope or documented shared primitives.
- Replace brittle selectors, broad `:deep(*)`, raw z-index constants, viewport traps, and magic `calc()/min()/max()` chains where W0 names risk.
- Repair story/configurator surface token drift where it hides the real design system.

Excluded:

- No Tailwind plugin extraction unless W4 proves the theme/style authority is stable and W6 accepts it as a measured follow-on.
- No aesthetic redesign.
- No single-hue palette shift.

# F.W0 Challenge

Challenge question: does F contain speculative work, hidden deferrals, compatibility fallback, or implementation before current-state proof?

## Challenges Sustained

1. **Old plugin-first F is premature.**
   - The style audit found invalid or inert Tailwind v4 theme namespace usage and split CSS authority.
   - Resolution: F fixes theme/style correctness in W4. Plugin extraction or byte floors require W4/W6 evidence and are not opening gates.

2. **Consumer drift must be fixed before trimming public surface.**
   - Active consumers still appear to import non-core root symbols.
   - Resolution: W0 records exact drift and W1 migrates/enforces static policy before export/internalization work depends on those imports.

3. **Proof commands are not yet proof substrate.**
   - Some profiling/runtime checks are doc-local or label-only.
   - Resolution: W1 promotes package fixture, consumer static policy, runtime smoke, and profile artifacts into scripts.

4. **Dock has two authorities for behavior and style.**
   - Rail orientation, popover layering, teleport ownership, transition cleanup, and CSS duplication are split across runtime and styles.
   - Resolution: W2 repairs behavior and proves blur/layer/animation before W4 consolidates style authority.

5. **Unsafe HTML and stale state are correctness issues, not polish.**
   - `v-html` consumer strings and global search cache can create real safety or data-integrity defects.
   - Resolution: W3 treats them as hard gates before cosmetic component splits.

6. **Aurora visual ambition must follow runtime correctness.**
   - Dead uniforms/config fields and oil-flow defects make further visual expansion unreliable.
   - Resolution: W5 first aligns public config, shader behavior, live/capture modes, and benchmarks.

7. **Story substrate cannot be dismissed as demo-only.**
   - The storybook is the product surface for this library and carries package/runtime proof.
   - Resolution: route/source/nav/style story fixes are routed through W2, W4, and W6.

## Challenges Rejected

1. **"Treat the current rail as not a dock."**
   - Rejected. The correct model is `GlassDock variant="rail"` with stronger inherited orientation, styling, and proof.

2. **"Restore heavy dock blur."**
   - Rejected. The default blur was intentionally reduced. F may rename and prove the tier, but it should not increase blur without visual/runtime evidence.

3. **"Skip W0 because the agent audit already found enough."**
   - Rejected. The prelude shaped F, but W0 is the formal current-state ledger wave that amends file ownership before implementation.

4. **"Split every component over 500 lines mechanically."**
   - Rejected. Splits must reduce coupling, improve ownership, and preserve behavior in the same wave.

5. **"Move Aurora to a new renderer because WebGL2 feels old."**
   - Rejected. Current WebGL2 remains the path unless W5 profiling proves a concrete bottleneck and browser support justifies a different runtime.

## Result

F is accepted as a tranche plan and W0 is closed. Implementation may proceed through W1-W5 in order using the amended ownership. W0 did not find unrelated scope requiring a new tranche before implementation.

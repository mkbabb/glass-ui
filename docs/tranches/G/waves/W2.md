## Scope

### Lane I (orchestrator-owned) — paper / cream surface tiers

Edit `src/styles/paper.css`, `src/styles/cards.css`:

- **paper.css** — `.paper-1`, `.paper-2`, `.paper-3`, `.paper-4` tier classes (paper texture + opacity step + elevation shadow + `paper-grain-overlay`, **no `backdrop-filter`**); `.paper-card` shorthand; `.paper-rule` (lined-paper tapered horizontal rule); `prefers-reduced-transparency` and `@supports not (backdrop-filter)` fallbacks (paper has no blur, but contrast-more boost still applies).

**No `.glass-skeuo` tier.** Per user direction in G.md invariant 7, modern-skeuomorphic shadowing is delivered through the existing cartoon-shadow family extended with `--shadow-cartoon-accent` (W1). The four glass tiers stay as-is.

### Lane III — math substrate (new file, default-included)

Create `src/styles/math.css`:

- **Default-included** via `src/styles/index.css` cascade — consumers using `@import "@mkbabb/glass-ui/styles"` get math utilities automatically; no per-consumer remembering. KaTeX `@font-face` boilerplate stays consumer-side (consumer responsibility per the C-lane risk register).
- Tokens consumed: `--type-formula` (W1), `--space-phi-{1..4}` (W1).
- Utilities:
  - `.math-display` (overflow-x scroll, padding-y, margin).
  - `.math-inline-pill` (chip-shaped inline math container).
  - `.formula-block` (paper-cream surface + accent-color left rule + centered tabular-nums + φ leading).
  - `.text-formula` (CM italic + tabular-nums + leading-loose).
  - `.production-rule` (BBNF-style `lhs ::= rhs` formal-grammar typography). `display: grid; grid-template-columns: max-content auto; gap: 0 var(--space-phi-1); font-family: var(--font-mono);` plus `.production-rule .lhs::after { content: " ::= "; color: var(--muted-foreground); }`. Bbnf is the lead consumer; sibling math-paper (latex-paper) prospective.
  - `.perf-number` and `.perf-unit` (the bbnf markdown.ts post-processor surface): `.perf-number { font-family: var(--font-mono); font-variant-numeric: tabular-nums; font-weight: 600 }` and `.perf-unit { font-family: var(--font-mono); color: var(--muted-foreground); margin-left: 0.125em }`. Numeric+unit pair typography.
- KaTeX selector: `.math-display .katex { font-size: var(--type-math-display); }` with `--type-math-display: clamp(1.1em, 1em + 1vw, 1.8em)`.

### Lane IV — Prism/Shiki theme bridge (new file, opt-in)

Create `src/styles/prism-theme.css`:

- **Opt-in** via consumer `@import "@mkbabb/glass-ui/styles/prism-theme"` after their Prism base import. Not bundled into the default cascade because consumers without Prism shouldn't pay for it.
- Single source of truth: canon viz-basis CSS variables. Light/dark mode handled automatically through canon's existing `.dark` cascade — no JS bridge.
- Targets Prism's standard `.token.*` classes: `.token.comment`, `.token.keyword`, `.token.string`, `.token.number`, `.token.function`, `.token.operator`, `.token.punctuation`, `.token.tag`, `.token.attr-name`, `.token.attr-value`, `.token.boolean`, `.token.constant`, `.token.symbol`, `.token.deleted`, `.token.inserted`, `.token.builtin`, `.token.class-name`.
- Values resolve to canon tokens — e.g. `.token.keyword { color: var(--viz-fourier); }`, `.token.string { color: var(--viz-amber); }`, `.token.number { color: var(--viz-chebyshev); }`, `.token.function { color: var(--viz-legendre); }`, `.token.comment { color: var(--muted-foreground); font-style: italic; }`.
- Exact mapping decided in W2 implementation; DESIGN.md documents it post-W2.

Shiki users: read the same CSS variables via `getComputedStyle()` at runtime to construct a JSON theme. Glass-ui does not ship the JSON form; that's a one-line consumer-side wrapper. (Defer JS form until a Shiki-using consumer surfaces.)

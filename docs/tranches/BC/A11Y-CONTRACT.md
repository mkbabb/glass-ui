# BC A11Y-CONTRACT — the cross-cutting WCAG/aria/focus/PRM matrix

The per-element accessibility contract every BC interactive-surface wave must PRESERVE (no silent drop) and, where thin, ENRICH. This is the consolidated a11y summary across the controls/dock/tabs/affordance bands — the single artefact a reviewer reads to confirm "the iOS-27 re-skin did not regress a single a11y axis."

**Grounding precedents (the binding lineage):**
- **AN.W4** (`docs/tranches/AN/audit/W4-role-contracts.md`) — role contracts on intrinsic primitives: `role="img"` IFF labelled, `role="button"`+`tabindex=0` on a span grip, the accessible name on the FOCUSABLE element, the `aria-allowed-attr` floor (a role's host must not carry a disallowed aria attr).
- **AM.W0** (`docs/tranches/AM/audit/W0-forms-a11y.md`) — the NumberField input-level label binding (name on the inner `role="spinbutton"`, not the group wrapper) + the GlassDock gap-3 contract (the presentational root carries NO `aria-expanded`; the expand-state aria belongs on the interactive trigger child).
- **AN.W6** (`docs/tranches/AN/audit/W6-dock-panelhost-chassis-phase.md`) — the chassis phase canon (the WCAG-twin `*-label` color pairs).
- **MEMORY `feedback_glass_ui_binding_verification`** — stale reka-ui prop/emit bindings silent-no-op; vue-tsc + units MISS them, only a LIVE e2e catches the dead toggle. The aria-state flip (`aria-checked`/`aria-pressed`/`aria-selected`/`aria-expanded`) IS the binding-truth AND the a11y-state truth at once — a control that paints but does not flip its aria-state reds both arms.
- **CLAUDE.md** — `.focus-ring` (the `--focus-ring-shadow` token utility, the AW.W26 token-first divergence, PRM-carved at `a11y-overrides.css:79`); the 44px WCAG-2.5.5 floor (`--touch-target` at `:root`, `touch-hit-area`, `--dock-control-floor`); P6 PRM (fade-keeps / transform-drops).

## The four cross-cutting a11y axes (every wave answers all four)

1. **ROLE / STATE (WCAG 4.1.2)** — the correct role per element-type + the live aria-state reflected. Reka OWNS the roles at HEAD; the BC waves re-SKIN (CSS/material/layout) and must NOT re-author or conflict with the reka role (the AN.W4 "role via reka, no SFC re-author" discipline; the `aria-allowed-attr` floor — a `role="radio"` host must not also carry `aria-pressed`).
2. **FOCUS (WCAG 2.4.7 / 2.1.1)** — a visible focus indicator (`.focus-ring` OR roving-tabindex focus) on EVERY keyboard-operable element + full keyboard operability (Tab reach, Space/Enter activate, arrows nav). Keyboard operability is the floor BESIDE the pointer affordance, never a substitute (a drag/hover has no keyboard equivalent — the click/arrow path stays operable).
3. **TOUCH TARGET (WCAG 2.5.5)** — ≥44×44px hit box on coarse pointer, decoupled from the (smaller) visual paint (`touch-hit-area` on form atoms, `max(..., --dock-control-floor)` on the dock, `--touch-target` on menu rows).
4. **PRM (P6, the reduced-motion carve)** — every animated affordance keeps the fade/color/state leg + drops the scale/translate physics under `prefers-reduced-motion: reduce`. The gesture stays OPERABLE (the selection commits, the aria-state flips); only the physics is off. a11y is absolute — PRM drops physics, never function or the focus-ring.

## The three a11y GAP classes the BC waves close (the binding-verification chronic)

- **GAP-A (the reka stale-binding silent-no-op — §F):** Switch/Radio/Slider/Checkbox/the picker carry the affordance + the reka binding, but the binding can silent-no-op (invisible to vue-tsc + units). The aria-state flip (`aria-checked`/`aria-pressed`/`aria-selected`/`aria-expanded`) is the LIVE e2e truth — every owning wave's π drives a REAL click/tap/key and asserts the aria-state reflects. Caught by: BC.W-RADIO-FIX (R1 binding π), BC.W-DROPDOWN-FIX (D5 live), BC.W-AFFORDANCE-MAP (the reka-stale-binding catch).
- **GAP-B (the re-skin drops an a11y contract):** a CSS/material/layout wave silently regresses a role/focus/aria/PRM contract while making it prettier. Closed by the per-wave no-regression assert (TABS-IOS T4/T5, CONFIG-RIGHT reading-order, CONTROL-SMOOTH visual-only fence, DOCK-VERTICAL-FIX V5). **The matrix above is the no-silent-drop ledger — a wave's gate cites the cell it must preserve.**
- **GAP-C (the icon-only control ships nameless):** an icon button (dock control, LabeledField action, collapsed-pill expand) ships with no accessible name (the AN.W4 "name on the focusable element" floor). Closed by the per-wave assert that icon-only controls bind `:aria-label` (CONTROL-SMOOTH C5, DOCK-COLLAPSED-BOTH C6, the affordance map A2).

## The non-negotiable floors (never `—`, never PRM-dropped, never re-skinned away)

1. **The FOCUS-RING is the hard floor** — every keyboard-operable element resolves a visible focus indicator. F is NEVER `—` on an operable element (only the reveal-surface set is exempt — the surface traps focus, the trigger carries the ring). A pointer-only affordance with no keyboard cue is the axe 2.4.7 gap the affordance-map A2 reds.
2. **Keyboard operability beside (never replacing) the pointer affordance** — a drag (LIQUID-TAB), a hover-lift, a gleam-track is a SIGHTED enhancement; the click + arrow + Enter/Space path stays the full operable mechanism (WCAG 2.1.1).
3. **The dock root stays presentational** — no `aria-expanded`/`role` on the `glass-dock` div (AM.W0 gap-3); the expand-state aria rides the trigger child via `defineExpose`.
4. **The reka role is preserved, never re-authored or conflicted** — the BC waves re-skin material/layout; they read reka's roles, never add a disallowed aria attr (the AN.W4 `aria-allowed-attr` floor).
5. **The aria-state IS the screen-reader truth** — the material distinctness (a brighter pill, a filled dot) must never be the SOLE selection signal; the `aria-pressed`/`aria-checked`/`aria-selected` state is present alongside the sighted cue.
6. **PRM drops physics, never function** — the gesture commits, the aria-state flips, the focus-ring paints; only the scale/translate physics is off under reduce.

### T1 — The distribution: the Fibonacci phyllotaxis sphere (research/viz/dot-matrix.md §3.1)
For dot `i` of `N`, the area-centered half-offset variant (admits ANY `N`, the cheaper no-`acos` `y = cos(polar)` form):
```
phi_golden  = (1 + sqrt(5)) / 2                  // ≈ 1.6180339887
goldenAngle = 2*PI / phi_golden = PI*(3 - sqrt5) // ≈ 2.39996 rad ≈ 137.508°
y     = 1 - 2*(i + 0.5) / N                       // y ∈ (-1,1), the cos(polar) — even by AREA
r     = sqrt(1 - y*y)                             // ring radius at that latitude
theta = i * goldenAngle                           // the golden-angle azimuth spiral
unitPos = vec3(cos(theta)*r, y, sin(theta)*r)     // on the UNIT sphere
```
This beats lat-long (which clusters at the poles → banded rings) because the irrational golden ratio gives each point near-equal AREA with no resonance gaps (extremelearning.com.au; arXiv 0912.4540 — the near-equal-area property). The phyllotaxis layout is **time-INVARIANT** — computed STATICALLY ONCE into the `dots` buffer; only the spin matrix + the depth-fade are per-frame (research/viz/dot-matrix.md §4.4).

### T2 — The depth-fade: the part that makes it READ as a sphere (research/viz/dot-matrix.md §3.2)
After rotation, modulate per-dot opacity + size by the dot's camera-facing-ness — a SOFT falloff, NOT a binary back-face cull (the soft fade is what reads as a translucent shell vs a flat disc). For a sphere centered at origin the surface normal IS the normalized dot position, so the facing term is the rotated-normal's z:
```
n       = spin * unitPos                          // the rotated surface normal (unit)
facing  = clamp(n.z * 0.5 + 0.5, 0, 1)            // 1 = dead-front, 0 = dead-back
opacity = baseOpacity * (facingLo + facingHi * facing)   // facingLo 0.15, facingHi 0.85
size    = baseSize    * (0.6 + 0.4 * facing) * dpr       // depth-of-field dot-size taper, DPR-aware
```
The `0.15 + 0.85·facing` opacity ramp + the `0.6 + 0.4·facing` size taper are the procedural-refs §1 pinned values (the SOTA addition the bare phyllotaxis article omits — Will Howard dot-spheres / COBE / Stripe lineage). On dark, `baseOpacity ≈ 0.35–0.6`, dots a soft warm-cream; slow Y-spin `≈ 0.05–0.1 rad/s`.

### T4 — The render: instanced billboard quads + crisp SDF fragment (research/viz/dot-matrix.md §5)
NO compute pass at the default count (the layout is closed-form — nothing to integrate; the dots never move relative to each other). ONE render pass over the static `dots` buffer + a small per-frame uniform block.
- **WebGPU `point-list` is hardwired to 1×1 px** (the underlying Metal/Vulkan/DX/GL APIs do not agree on point size) — USELESS for sized dots (webgpufundamentals — *WebGPU Points*). The SOTA shape is **instanced billboard quads**: `draw(6, N)` — 6 quad corners selected by `vertex_index`, per-dot data read by `instance_index`. The quad is built in NDC (camera-facing by construction — only the dot CENTER rotates; the quad always faces the screen). This is the SAME instanced-billboard pipeline `flow-field.render.wgsl.ts:98-153` ships (research/viz/dot-matrix.md §5.2).
- **The fragment is the crisp `fwidth`-smoothstep SDF circle** (the ONE AA canon across the suite — the goo-blob `fwidth` sites + the constellation crisp-circle + the concentric ring extraction all use it): `d = length(uv) - 1`, `aa = fwidth(d)`, `coverage = 1 - smoothstep(-aa, aa, d)`, `discard` outside. The `smoothstep(-aa, aa, d)` band is ALWAYS ~1px wide regardless of DPR/zoom/dot-size — fine dots stay crisp even sub-2px (research/viz/dot-matrix.md §5.3; Red Blob Games SDF AA; numb3r23 fwidth AA). The `fwidth` lives in `fs_main` ONLY (never a `vs_main`-reachable helper — the dual-module WGSL-validation trap).
- **No depth-test sort needed.** The translucent dot-shell uses additive/premultiplied blend with the depth-fade opacity doing the occlusion implicitly: far dots are already dim → they read as behind. The COBE/Stripe register; avoids the per-frame sort (research/viz/dot-matrix.md §5.2).

## Goal (the gestalt)
Two small, surgical motion-preset gaps closed. (1) The brand "convergence-reveal" — the partial-sum settle, where N elements (the epicycle terms, the equation's growing sum) build up and SETTLE on the signature curve — becomes a NAMED, reusable preset (`MOTION_CURVES["--ease-convergence"]` + the orchestration helper) any surface drives, instead of fourier re-deriving the curve + stagger by hand; it composes the SHIPPED kf spring + the existing stagger orchestration (no new engine). (2) The `[data-scroll-reveal]` `view()` CSS recipe re-fires its entrance EVERY time an element re-enters the viewport — wrong for a virtualized/teleporting list where a row scrolls out + back; the `once` latch makes the entrance play ONCE per element (matching `useStaggerReveal`'s already-shipped `once: true` JS leg). Both are cheap: a `MOTION_CURVES` row + an orchestration note, and a one-block CSS recipe extension.

### #8 — the scroll-reveal `once` latch (absent on the CSS recipe)
- **`useStaggerReveal` ALREADY honors `once`** (`src/composables/motion/useStaggerReveal.ts:9,45,70-71`): `once?: boolean` defaults `true`; on cross it sets `revealed` + `if (once) observer?.unobserve(el)` (`:70`), and `else if (!once)` re-fires (`:71`). The JS leg is correct.
- **The CSS recipe RE-FIRES on every re-entry** (`src/styles/scroll-driven.css:56-68`): `[data-scroll-reveal] > * { animation: …; animation-timeline: view(); animation-range: entry 0% entry var(--scroll-reveal-range-end, 60%); }`. A `view()` timeline re-runs its `animation` EVERY time the element re-enters the entry range — so a virtualized/teleporting row that scrolls out + back re-plays the fade-lift (the wrong behavior fourier names). There is NO `once` opt-in on the CSS recipe (the JS leg has it; the CSS recipe does not — the gap).
- **The native `view()` timeline has no built-in once** (the CSS limit): a scroll/view timeline drives the animation on every range-entry; "play once" is not a native timeline feature. The latch is a `[data-scroll-reveal-once]` opt-in that swaps the entry-driven animation for a ONE-SHOT `@keyframes`-on-first-intersection (a small JS-assist `IntersectionObserver` adds a `data-revealed` attr once, the CSS plays the entrance keyed off `[data-revealed]` not the live `view()` range) — the dual-path single-writer the library already speaks for the `once` case.

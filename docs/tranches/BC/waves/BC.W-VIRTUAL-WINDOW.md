## Goal (the gestalt)
A consumer with a 1000-section document (or a 5000-result fuzzy list) renders only the ~20 sections near the viewport — spacer divs hold the full scroll height so the scrollbar is honest, scrolling re-windows smoothly with no jank, and jumping to a far section (a ToC click, a search-result select) WARMS that section into the render window a beat before the scroll lands so it is painted-and-measured when the scroll arrives (never a blank target). What a reader carries away: **the section-windowing engine glass-ui pruned at v1.0 is HOME again — one canonical pure-layout core + the reactive composable + the sliding-window store, generic over `FlatSection`, published OFF the root barrel as a heavy DOM-measure leaf, so words deletes its three transposed forks and the dock-search results list composes the SAME primitive.** This is a homecoming, not a new mint — the lineage (v0.9.4 → retired v1.0 → returned BC) is recorded, the machinery is byte-faithful to the proven words copy.

### 1. The pure layout engine — `src/composables/virtual/virtualSectionLayout.ts` (stateless, NO Vue, NO DOM)
A verbatim re-publication of the words copy's pure fns, with ONE refinement:
- `FlatSection {id, index, depth, parentId, rootId, rootIndex, estimatedHeight}` — the generic windowing input (the producer — `flattenPaperSections` in latex-paper, the dock-search result-flattener — stays in the consumer; glass-ui owns only the contract).
- `buildSectionLayout(items, getHeight)` — sequential `top`/`bottom` offsets, `Math.max(1, Math.round(getHeight(item)))`.
- `findStartIndex`/`findEndIndex` (internal) — binary search, O(log n).
- `resolveSectionWindow(layout, scrollTopPx, viewportHeightPx, overscanBeforePx, overscanAfterPx, forcedRange?)` — the windowed range + `topSpacerPx`/`bottomSpacerPx`; `forcedRange` is the warm-target injection (clamped into bounds).
- `resolveActiveSection(layout, activeOffsetPx)` — binary search, last section whose top ≤ offset (the windowing-LOCAL render-active reader; see the active-id reconcile in Fences below).
- `findSectionOffset(layout, id)` — **REFINED to binary search** off `layout.entries` (the words copy is a linear scan, `virtualSectionLayout.ts:244-252`; the entries are top-sorted by construction, so a `top`-keyed binary search is correct + O(log n)). This is the one functional refinement; a fixture pins the offset output byte-identical to the linear scan over a 1000-item layout.
- Types: `SectionLayout`, `SectionWindowRange`, `ForcedSectionWindowRange` co-exported.

### 2. The reactive composable — `src/composables/virtual/useVirtualSectionWindow.ts`
Byte-faithful to the words copy's full API (the surface `DefinitionContentView`/`ProgressiveSidebar` consume). Composes `useResizeObserver` (the house `composables/dom/` leaf — the words copy hand-rolls a raw `new ResizeObserver`; the re-mint routes through the house leaf for the cleanup discipline) + a rAF-coalesced scroll listener (the dual-path discipline). The full returned surface:
- `visibleItems` (the windowed slice), `topSpacerPx`/`bottomSpacerPx` (the spacer-div sizes).
- `measureSection(id, el)` (template-ref callback, estimated→measured height swap; `null` disconnects).
- `ensureTargetWindow(id)` (warm-target with `warmTargetBefore`/`After` defaults 2/3 + the 320ms auto-release).
- `getOffsetFor(id)`, `recalculate()`.
- `activeId`/`activeRootId` (the 20%-viewport-mark reader — RETAINED but documented as the windowing-LOCAL render-active reader; the ToC's binding active-id is `useScrollTracker.activeId`, the reconcile recorded below).
- Config: `items` (`MaybeRefOrGetter`), `scrollContainer`, `contentEl` (the non-virtualized-header offset seam), `overscanBeforePx`/`After` (defaults vpH / 2×vpH), `warmTargetBefore`/`After` (2/3).

### 3. The sliding-window store — `src/composables/virtual/useWindowedStore.ts`
Byte-faithful: `useWindowedStore<T>({maxResident=200})` → `{items, windowStart, generation, set, prepend, clear, appendIfCurrent}`. The generation-counter stale-append rejection (`appendIfCurrent`) is the load-bearing concurrency primitive — preserved verbatim.

### 4. The SESSION_HEIGHT_CACHE scoping decision (recorded)
The words copy uses a MODULE-LEVEL `SESSION_HEIGHT_CACHE` (`:55`) shared across all instances — correct for one app (a section's measured height survives a remount), a memory note for a library leaf. **DECISION: keep the module-global, DOCUMENTED as deliberate** (a `MEMORY` note in the file header + the CLAUDE.md leaf line) — a per-instance cache would lose the survives-remount property the words consumer relies on (a definition view that unmounts/remounts on word-change re-uses the prior heights). The cache is keyed by section `id` (consumer-namespaced ids avoid cross-app collision); the keep is the proven shape, not a regression. A `clearSessionHeightCache()` escape is exported for a consumer that wants to evict (the documented retune path).

## Goal (the gestalt)
Every floating overlay carries the SAME golden customization surface — so a consumer who knows Dialog/Popover knows Dropdown/Select/Tooltip too. The `surface?: Surface` axis (`glass` default · `veil` · `opaque`) lets a dropdown over a busy backdrop read as `surface="veil"` (the legibility feather) exactly like a Popover; the φ `--overlay-pad-inline/-block` ladder gives every overlay the SAME golden breath cadence (the sqrt-φ block-over-inline rhythm); the dropdown/select min-width + the tooltip text + the Select chevron opacity read TOKENS so a `:root` override retunes all overlays in lockstep. The overlay band is INTERNALLY INCONSISTENT at HEAD (5 of 11 overlays have the axis, 6 do not, one — Tooltip — has neither surface nor φ-pad nor a token-backed type); this wave makes it UNIFORM by THREADING the existing register onto the gap surfaces. Zero new register; the bare default is byte-near-identical (the new axes are additive default-`glass`).

## Fences / invariants (must NOT regress)
- **ZERO new register — thread the EXISTING `Surface` axis + the φ overlay-pad ladder.** Both have ≥5 consumers; this widens their enrolled set onto the six LACK overlays. A wave that forks a second surface axis OR a parallel overlay-pad ladder reds `proof:surface-axis` W1. The `--overlay-min-width`/`--overlay-max-block`/`--tooltip-text`/`--select-chevron-opacity` tokens are the token-BACKING of existing raw literals (the magnitudes move onto `:root`-overridable customs), NOT a new compositing register.
- **DON'T over-prop — the φ-pad/min-width/max-block are TOKENS, not props.** Only the `surface` choice is a prop (semantic: glass/veil/opaque). The padding/min-width/max-block/tooltip-text MAGNITUDES stay `--overlay-*` tokens a consumer overrides from `:root`. A wave that added a `padding`/`minWidth` prop is the anti-pattern.
- **The bare default is byte-identical.** `surface="glass"` resolves `surfaceClass('glass','floating')` = `glass-floating` (byte-identical); the token-backed literals default to the HEAD magnitude (`--overlay-min-width: 8rem` = `min-w-32`, `--tooltip-text: --type-caption` ≈ `text-sm`-ish, `--select-chevron-opacity: 0.5` = `opacity-50`). A bare overlay at HEAD is pixel-unchanged; the additive `surface` axis owes no MIGRATION row (it is default-glass).
- **The per-overlay inline pad ANCHOR is preserved (a tooltip ≠ a dialog).** The φ ladder is the RATIO (block = inline × 1.272), uniform everywhere; the inline ANCHOR magnitude is per-overlay (tooltip tight, dialog `--spacing(6)`). The thread gives each LACK overlay its golden inline anchor + the derived block — it does NOT force one absolute pad onto every overlay (which would cramp a dialog or balloon a tooltip).
- **The behavioral overlay fixes are NOT this wave's.** `BC.W-DROPDOWN-FIX` (Band 6) owns the no-shift-on-open / align-to-trigger / selected-dot-reads BEHAVIORAL fix; `BC.W-DESHADCN` owns any shadcn-neutral token reskin on these overlays. This wave owns the `surface`/φ-pad/token-backing CUSTOMIZATION axis ONLY — the two assert different facts on the same files and never contradict.
- **The Select precompiled `[data-slot="select-content"]` `max-height` rule is KEPT** (BA.W-EMISSION — the consumer-content-scan-reach floor; a 16-item dropdown bounds inside the viewport in EVERY consumer regardless of JIT reach). The `--overlay-max-block` token threads the OTHER overlays' max-block; the Select precompiled rule is the on-the-line KEEP (recorded in the census).
- **`glass-reveal` (the liquid-open bloom) is UNTOUCHED** — every overlay keeps its `glass-reveal` recipe (BB.W-LIQUID-REVEAL); the `surface` thread changes the PLATE decoration, not the entrance.
- **reka behavior is INVIOLATE** — the threads touch only the content plate's `:class`/props; the portal/collision/roving-tabindex/focus-trap reka logic is untouched (`proof:binding-verification` stays green by construction).

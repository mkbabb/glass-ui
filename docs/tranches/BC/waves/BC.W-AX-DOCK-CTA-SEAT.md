## Goal (the gestalt)
A CTA flies into a dock control (the BB.W-DOCKMORPH-CTA bloom INVERSE — `useDockCtaReceive`'s `receive()` already morphs the external CTA onto the foreign dock-control rect, fades, congests, hands off) AND the dock control it lands on is a SEAT that was visibly RESERVED for it: while the CTA is in flight (or pending), the target dock control shows a quiet `[data-cta-pending]` placeholder state (a dim ghost of the control awaiting its arrival), the CTA lands, and the seat REVEALS its real content with a plain `transition: opacity` FLIP (NOT the dock morph-stagger — the seat is a content swap, not a box morph). The consumer drives the seat through `setPending()`/`clearPending()` on the `useDockCtaReceive` return — `setPending()` arms the seat (the ghost shows, the resting control geometry is reserved so the dock box does not jump when the CTA lands), `receive()` flies the CTA, `clearPending()` reveals the seated content. The whole seam ships on the `/dock` subpath (the dock consumer's natural import home, beside `GlassDock`/`useDockState`), not only the `/motion` barrel. A reader sees: the CTA does not just vanish onto a static control — the control was WAITING for it, the box never jumps, and the reveal is a calm opacity FLIP, not a janky morph-restart.

## Target spec (grounded)
Four moves: the pending-state API on the return, the `[data-cta-pending]` seat partial, the FLIP reveal, and the `/dock` re-export. The morph half (`useDockCtaReceive`'s `receive()`) is UNTOUCHED — this wave adds the SEAT around it.

### T1 — `setPending()` / `clearPending()` on the `useDockCtaReceive` return (folds BC-W3's pending API)
`UseDockCtaReceiveReturn` gains two methods + a reactive `pending` flag:
- **`setPending(): void`** — arms the landing seat: writes `data-cta-pending` on the `dockControl` element (the target reads its `[data-cta-pending]` ghost state) AND reserves the resting control geometry so the dock box does not jump when the CTA lands (the un-gate, T2). Idempotent. Sets `pending.value = true`.
- **`clearPending(): void`** — clears the seat: removes `data-cta-pending` from the `dockControl`, so the seat reveals its real content with the FLIP `transition: opacity` (T3). Idempotent. Sets `pending.value = false`. The default `onReceived` flow calls `clearPending()` on hand-off (the seat reveals as the CTA lands) UNLESS the consumer opts to drive it manually.
- **`pending: Readonly<Ref<boolean>>`** — the reactive seat state (the consumer binds `:class`/`v-if` off it).
The methods write a DATA ATTRIBUTE on the target (the `[data-cta-pending]` seam), they do NOT animate a layout property — `setPending`/`clearPending` toggle a CSS state, the seat partial owns the paint. The morph (`receive()`) stays compositor-only.

### T2 — the resting geometry is UN-GATED so the seat reserves its footprint (the no-box-jump)
The dock control, when `[data-cta-pending]`, RESERVES its resting footprint (the `--dock-control-size`/`--dock-layer-height` box it will occupy when seated) so the dock box's shrink-wrap is already at the seated width — the CTA lands into an already-sized hole, the box does NOT jump on `clearPending()`. The reserve is a STATIC `min-inline-size`/`min-block-size` on the seat (the W-DESKTOP-RESERVE static-frame-0-reservation precedent — NEVER an animated dimension; `proof:no-layout-animation` holds). The control's CONTENT (the icon/label) is what fades in on reveal; the BOX is reserved from the moment `setPending()` fires. This is the "un-gate the resting geometry" the intake names — the seat is sized for its arrival from frame 0, not grown when the CTA lands.

### T3 — the FLIP reveal is a plain `transition: opacity`, NOT the morph-stagger
When `[data-cta-pending]` clears, the seat's real content (the icon/label) reveals with a PLAIN `transition: opacity var(--cta-seat-reveal-duration) var(--ease-out)` — a calm content fade-in, NOT the dock collapse/expand morph-stagger (`--dock-expand-t`/child-stagger). The seat is a CONTENT swap on an already-sized box; it is NOT a box morph, so it must NOT ride the morph clock (which would read as a janky stagger-restart on a content reveal). The ghost (`[data-cta-pending]`) state is a dim `opacity: var(--cta-seat-ghost-opacity, 0.35)` placeholder; the cleared state is `opacity: 1` on the `--ease-out` no-overshoot register (a content reveal must not overshoot — W-MOTION-CANON P2). PRM-gated: under `prefers-reduced-motion: reduce` the reveal is an instant opacity swap (the duration drops to ~0, the seat snaps to content — the vestibular floor; the reveal is correct, the transition off).

### T4 — the `/dock` re-export (folds BC-W3's subpath ask)
`useDockCtaReceive` (+ its `UseDockCtaReceiveOptions`/`UseDockCtaReceiveReturn`/`DockCtaReceivePreset` types) RE-EXPORTS from `src/components/custom/dock/index.ts` (the `/dock` subpath barrel) — so a dock consumer reaches it from `@mkbabb/glass-ui/dock` beside `GlassDock`/`useDockState`/`DockIconButton`. The `/motion` export STAYS (it is a motion primitive; the `/dock` re-export is ADDITIVE, the natural-home discoverability fix — a re-export, NOT a move, so no clean break is owed). `/api` already publishes the types (`api/types-extra.ts`); the `/dock` barrel adds the value + type re-exports.

## Goal (the gestalt)
Open any route and the body reads as cleanly DELIMITED sections — each named section carries the SAME canonical heading rung (the √φ 20.4px section `<h2>`), and consecutive sections are separated by a visible hairline rule (or sit in their own sub-card), so the page is never an undelimited gap-stack where every block blurs into the next. The hierarchy is consistent + recognizable: ONE chassis hero (the dominant display title) → the body's section headings (the secondary rung) → the supporting mono eyebrows + blurbs (the tertiary rung), every page the same shape. The 41 pages that hid a SECOND `border-l-[3px]` IconChip header INSIDE the body card no longer double-describe — that identity is the chassis hero's icon ON TOP of the card; the body holds only delimited sections. EVERY PAGE is standardized.

## Starting state (measured, file:line)
The hierarchy primitives exist (`StorySection`'s `heading`/`label`/`blurb` rungs) but are bypassed across the route set (route-census.md §1-2):

- **THREE competing header idioms** (route-census.md §1): idiom-A = the audacious chassis hero (12 `hero:true` rows); idiom-B = a hand-rolled `border-l-[3px]` IconChip header INSIDE the StoryPage body slot (`grep -c "border-l-[3px]"` → **41 SFCs**) — a SECOND header redundant with StoryPage's chrome `<header>` above it (a literal double-descriptor, e.g. `forms/inputs.vue:23-41` repeats "Forms · Inputs"/"Forms · Text entry"); idiom-C = the plain 32.9px `text-title` chrome `<h1>` (~60 routes). No single recognizable page shape.
- **38 SFCs hand-roll `<h2 class="text-subheading">` directly**, bypassing `StorySection`'s `heading` rung (route-census.md §2 — e.g. `display/card.vue` (9), `dock/overview.vue` (11), `forms/inputs.vue` (6)). `StorySection.vue:58-83` provides the canonical `heading` → semantic `<h2 class="text-subheading">` (20.4px / 600) rung, but **70 SFCs import StorySection and only 13 pass `heading=`** — the other 57 use it as a label/blurb wrapper, leaving sections as bare `flex flex-col gap-3` stacks with no visible heading.
- **Section DELIMITERS are essentially absent**: only 3 routes use `<Separator>` and 1 uses `<hr>` across 113 routes (route-census.md §2). Sections flow as undelimited gap-stacks (`gap-10` between StorySection blocks, `StoryPage.vue:120`). Live-probed `forms/inputs`: 7 sections, 0 separators. The user's "delimit with hr OR different cards" bar is met by ~0%.
- **What exists (KEEP/REUSE):** the `StorySection` `heading` rung (the canonical `<h2 class="text-subheading">`, `StorySection.vue:58-65`); the shipped `<Separator>` component (the hr-rule register, `src/components/ui/separator/`); the `<Card>` sub-card register; the chassis `.scroll-cascade` section-build (`StoryPage.vue:118-123`). No new primitive is needed — the gap is APPLICATION + a chassis delimiter affordance.

## Target spec (grounded)
Demo-private (zero `src/` paint — the chassis SFCs + a per-route migration sweep). THREE moves:

**Part A — every named section reaches the canonical heading rung.** Migrate the 38 hand-rolled `<h2 class="text-subheading">` + the 57 StorySection-without-heading SFCs onto `StorySection`'s `heading=` rung (route-census.md §2). The canonical hierarchy: the chassis hero `<h1>` (display, dominant) → `StorySection heading` `<h2 class="text-subheading">` (20.4px, secondary) → the `label` mono eyebrow + `blurb` (tertiary). No hand-rolled `text-subheading` `<h2>` survives off `StorySection` (the route-census §2 collapse).

**Part B — the section-delimiter chassis affordance.** Add a `delimited` register to `StorySection` (or the `StoryPage` section stack): consecutive named sections are separated by a visible hairline (the shipped `<Separator>` component, reading the `--border-hairline` / `--configurator-divider` dark-adaptive token — CLAUDE.md §BA.W-CONFIG-CHASSIS, so the rule survives the dark glass plate) OR each section sits in its own sub-`<Card>` (the user's "hr lines OR in different cards"). The chassis applies it automatically — a page declares its sections and the delimiter register draws the seams; no per-SFC hand-rolled `<hr>`. The delimiter is a hairline whisper (the `.glass-menu-section` `--border-hairline` register precedent — CLAUDE.md §BA.W-MENU-GLASS), never a hard `1px solid` rule.

**Part C — the idiom-B second-header fold (couples `BC.W-HERO-AUDACIOUS`).** The 41 `border-l-[3px]` IconChip headers INSIDE the body collapse: the IconChip + category identity moves UP into the chassis hero (the per-category hero icon — `BC.W-HERO-AUDACIOUS` Part C; the user's "all headers ON TOP of the card"). The body then holds ONLY delimited sections — no second header repeating the descriptor. The chrome `<header>` (the chassis eyebrow→title→blurb) is the ONE descriptor; the in-body double is deleted.

The KISS architecture: ONE heading rung (`StorySection heading`), ONE delimiter register (the shipped `<Separator>` / sub-`<Card>` on the dark-adaptive hairline token), the idiom-B identity folded UP into the chassis hero. No new primitive; the hierarchy is the chassis hero → section heading → eyebrow/blurb, every page.

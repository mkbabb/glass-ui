## Goal (the gestalt)
A grid of seeded watercolor dots, each a soft organic pastel blob with a wet bleeding edge — and now each dot's wet edge is UNIQUELY displaced (today all twelve share one displacement, twelve clones). Beside the solid dots, the ghost register reads as a clean evenly-spaced DASHED stroke that traces the SAME organic blob silhouette — a hand-drawn placeholder outline, not a solid ring and not a dashed rectangle. On Safari it sits still and crisp: no screen flash, no flicker — the animated mode breathes via a compositor transform, never re-rasterizing the filter graph. The empty-palette slot reads as a dashed ghost blob ("add a color here"). Warm-cream identity by default; not one teal-on-navy literal anywhere.

## Starting state (measured, file:line)
The wet-edge SVG technique is the right primitive and stays; the defects are the WRONG ghost affordance, a Safari-flashing animation, a shared (non-unique) filter seed, and a too-broad gate (research/viz/watercolor-dot.md §1):

- **The ghost is a SOLID stroke, not dashed (the headline defect).** `WatercolorDot.vue:182-202` paints the `[data-variant="ghost"]` register as `border: 2px solid color-mix(in srgb, var(--watercolor-color) 70%, transparent)` over a `12%` low-alpha fill. The source comment (`:27`, the `variant` prop doc; the `.watercolor-swatch[data-variant="ghost"]` block comment) justifies it as "NOT a CSS dashed rectangle" — but that conflated two things: the user did NOT ask for a dashed RECTANGLE, they asked for a dashed OUTLINE following the silhouette (research/viz/watercolor-dot.md §1.1, §2.2).
- **The gate FORBIDS all dashes (too broad).** `scripts/proof-emission.mjs:304-308` (the W5 ghost arm) reds ANY dash: `const isDashedRect = /border-style\s*:\s*dashed|border\s*:\s*[^;]*dashed/.test(watercolorStripped)`; the assert (`:312-320`) greens only `hasVariantAxis && hasGhostValue && reusesBlob && !isDashedRect`. The intent ("not a dashed BOX") is right; the implementation (forbid all dashes) is too broad and must narrow (research/viz/watercolor-dot.md §1.1, §7).
- **Safari flashes — the per-frame filter re-raster (the §H arm).** When `animate` is true, `useWatercolorBlob.ts:110-114` (the `tick`) runs an rAF loop mutating the inline `border-radius` EVERY frame (`borderRadius.value = radiiToCSS(current); rafId = requestAnimationFrame(tick)`), while `WatercolorDot.vue` applies `filter: var(--watercolor-filter)` (`url(#…)`) to the SAME `.watercolor-swatch` element (the `:161` `:style` bind → `filter` in the scoped `:` block). `border-radius` is a PAINT property (CSS-Tricks "Animating Border" — vector clipping on content/bg layers), so each frame re-paints, forcing the SVG `<filter>` graph (`feTurbulence` 6-octave → `feDisplacementMap`) to RE-RASTERIZE per frame — Safari "in severe cases … might not render such elements at all" / "flicker" (SVGator; O'Reilly Using SVG). HandMark already learned this exact lesson: its filter "rasters ONCE … and is cached … it NEVER animates under the filter" (`handmark/texture.ts:24-27`). WatercolorDot violates the very idiom HandMark cites as the WatercolorDot idiom (research/viz/watercolor-dot.md §1.2, §2.4).
- **The filter seed is HARDCODED (the uniqueness bug).** `WatercolorDot.vue:140` `<feTurbulence … seed="2" …>` — a constant `2`, so all dots share ONE wet-edge displacement (twelve clones), defeating the mark's whole point (per-color uniqueness). The `border-radius` IS seeded per `color + seed` (`useWatercolorBlob.ts:46` `mulberry32(hashString(getColor() + seed))`), but the filter is not (research/viz/watercolor-dot.md §1.1, §2.3).
- **`numOctaves="6"` is pure cost.** `WatercolorDot.vue:139`: octave 6 is "practically imperceptible" beyond 5 (Codrops) — a Safari raster saving for free (research/viz/watercolor-dot.md §2.1).
- **Safari renders SVG filters in sRGB regardless of `color-interpolation-filters`.** `WatercolorDot.vue:134` sets `color-interpolation-filters="linearRGB"` (for the AZ.W-BLOB-PAGE device-px smooth-edge AA) — Safari silently uses sRGB (a known WebKit bug; FrontendMasters/Master.dev SVG Filters Guide). So the wet edge is a Chrome/FF-only nicety; the comment must be honest (research/viz/watercolor-dot.md §1.2, §2.5).
- **The widened filter region + `stitch` are CORRECT, KEEP.** `WatercolorDot.vue:130-133,141` `x/y="-15%" width/height="130%"` + `stitchTiles="stitch"` are the cross-Safari tiling-seam mitigations (the pre-26.4 `feDisplacementMap` reference-filter tiling-gap bug, fixed Safari 26.4 / 2026-03-24 — WebKit; we do not rely on the fix being present on every visitor). KEEP.
- **No `isolation`.** The residual Safari `border-radius`+transform flicker is fixed by `isolation: isolate` on the swatch root (Apple Dev Forums 705172; Steven Woodson) — absent today, safe here (no `multiply` blend to wall, unlike HandMark's highlighter — research/viz/watercolor-dot.md §1.3, §2.4).
- **The morph is a real per-vertex rAF.** `useWatercolorBlob.ts:75-119` runs an 8-vertex sinusoidal-eased `tick` writing `border-radius` per frame + a `nudge()` (`:118-129`) retargeting all 8 on hover — the liveness that must move off the per-frame paint onto a compositor transform.

## Target spec (grounded)
A MARK gets a MARK's treatment — Safari-first + ghost-first, NOT a WebGPU port (research/viz/watercolor-dot.md §0, §3). The wet-edge SVG technique (`feTurbulence` → `feDisplacementMap`) is the SOTA and is unchanged in KIND; the fixes are the ghost affordance, the Safari-safe animation, the per-instance seed, and the honest color. KISS.

### 1 — The ghost: a DASHED stroke FOLLOWING the blob silhouette (the headline; pick technique (b))
The user wants a dashed OUTLINE that follows the seeded blob silhouette — NOT a dashed rectangle (research/viz/watercolor-dot.md §2.2). The chosen technique is **an SVG `<ellipse>` dashed stroke carrying the SAME wet `<filter>`** (the cheapest high-fidelity form):
- Render the ghost outline as an SVG `<ellipse>` (filling the swatch box) with `stroke="var(--watercolor-color)"`, `fill="color-mix(in srgb, var(--watercolor-color) 12%, transparent)"` (the low-alpha fill kept), `vector-effect="non-scaling-stroke"`, and **`stroke-dasharray`** (the canonical SVG dash mechanism — MDN/CSS-Tricks; "the first number a distance for the filled area, the second for the unfilled," arc-length-uniform along the stroked path).
- The ellipse stroke is displaced by the SAME `feDisplacementMap` filter the solid dot uses — the displacement wobbles the dashed ellipse INTO the organic blob outline, so the ghost is literally the solid dot's silhouette drawn as dashes, distorted by the same wet edge (research/viz/watercolor-dot.md §2.2.1). This satisfies the gate's "ghost matches the solid seed's silhouette" intent AND delivers the evenly-spaced dashed outline that is NOT a dashed box.
- **The dash pattern is the config axis** (NEW, ghost-only): `--watercolor-dash` / `--watercolor-gap` (default `8px` dash / `5px` gap — the hand-drawn-placeholder register; tunable). The dashes are arc-length-uniform along the ellipse (the dashed-rounded-rect bunching problem that `border-style: dashed` on a `border-radius` box would produce is avoided by stroking a path, not a box — research/viz/watercolor-dot.md §2.2(a)).
- The higher-fidelity "reconstruct the exact 8-vertex super-ellipse `<path>`" form is BOOKED (only marginally better than the displaced ellipse, heavier — a path generator; research/viz/watercolor-dot.md §2.2.2), NOT the default.
- **PRM/reduced-transparency:** the dash stroke is static (no animation) → PRM-neutral; under `prefers-reduced-transparency` the low-alpha fill firms up (mirrors the glass brackets) — the dashed outline still reads.

### 2 — Safari-safe animation: static filter + compositor transform wobble (the §H fix — load-bearing)
Decouple the morph from the filter (the HandMark idiom + the Safari guidance; research/viz/watercolor-dot.md §2.4):
- **Keep the SVG `<filter>` STATIC + cached** — it rasterizes once per (mount, resize, scheme-flip), NEVER re-rasterizes per frame (the HandMark `texture.ts:24-27` idiom this mark currently violates).
- **Express the organic liveness via a COMPOSITOR `transform`** — a sub-perceptual seeded `scale`/`skew`/`rotate` wobble the compositor handles WITHOUT re-rastering the filter graph ("animate only GPU-accelerated `transform`/`opacity`; avoid properties that trigger layout or paint" — the hardware-accelerated-animations canon; the SAME compositor-only split the whole liquid-glass band uses, `proof:no-layout-animation`). The `border-radius` per-frame write (`useWatercolorBlob.ts:110`) RETIRES in `animate` mode — the rAF instead drives a seeded transform wobble (or the morph rides a one-shot CSS transition on a NON-filtered layer; the cleanest is the static-filter + transform-wobble).
- **Add `isolation: isolate`** on the `.watercolor-swatch` root — fixes the residual Safari `border-radius`+transform flicker (Apple Dev Forums 705172). Safe here (no `multiply` blend to wall).
- **PRM** → the wobble drops to a single static frame (`animate` inert under `prefers-reduced-motion: reduce`); the filter is static either way. The default `animate: false` (`WatercolorDot.vue:48`) is already safe; the demo grid sets `animate` (the live-Safari risk surface), so the wobble must be Safari-clean there.

### 3 — Per-instance filter seed (the uniqueness fix)
Derive the `<feTurbulence>` `seed` from the SAME `hashString(props.color + props.seed)` the shape PRNG uses (`useWatercolorBlob.ts:46`) — one seed leaf, the house identity (`src/utils/prng.ts` single-source, AV.W14; the HandMark grain-sub-seed precedent, `handmark/texture.ts:38-40`). The `:140` `seed="2"` hardcode is REPLACED with `:seed="filterSeed"` (a computed int off the shared hash). Each dot's wet edge is then uniquely displaced, coherent with its silhouette (research/viz/watercolor-dot.md §2.3).

### 4 — Honest cross-engine color + cheaper octaves
- Drop `numOctaves` `6 → 5` (`WatercolorDot.vue:139`) — octave 6 is imperceptible (Codrops) + pure Safari raster cost (research/viz/watercolor-dot.md §2.1).
- KEEP `color-interpolation-filters="linearRGB"` (`:134`) — it costs nothing and helps Chrome/FF; **fix the COMMENT** to record that Safari renders SVG filters in sRGB (a known WebKit limitation), so a future reader never trusts smooth AA on Safari (research/viz/watercolor-dot.md §2.5). The finer-noise + small `scale=1.3` keep the sRGB edge acceptable for a soft decorative mark.
- KEEP `stitchTiles="stitch"` + the widened `-15%/130%` region (the cross-Safari tiling-seam mitigation, the pre-26.4 bug; `:130-133,141`).

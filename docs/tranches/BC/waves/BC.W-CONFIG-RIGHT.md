## Goal (the gestalt)
Open any studio on `:5199` at a desktop width — aurora, blob, fourier-studio, the `/compositions/configurator` reference, the gear PresetEditor — and the layout is the SAME everywhere: the **live specimen stage fills the left**, the **controls column sits on the RIGHT**, a single coherent two-column inspector. No studio renders its controls stacked below the stage on a wide screen; no studio puts controls on the left or floats them off-axis. The panel reads as one rounded glass inspector, corners clean, the controls scrolling internally on the right while the stage holds the viewport on the left. The user's "configurator misplaced → must be on the RIGHT" is true on every configurator at once, because they all read the SAME standardized layout from the ONE chassis.

## Starting state (measured, file:line)
The `<Configurator>` chassis ALREADY defaults to controls-on-right — but the desktop two-column grid **silently does not engage**, so every studio renders single-column (controls below the stage) on desktop. The root is the BA.W-EMISSION arbitrary-utility-not-emitted class recurring on the configurator's OWN layout.

**Live-probed at `/substrates/aurora` (2026-06-18, innerWidth 1280, well past the `lg` 1024px breakpoint):**
- The configurator element carries the class `lg:grid-cols-[minmax(0,1fr)_minmax(var(--configurator-aside-min,280px),var(--configurator-aside-max,360px))]` (present in `classList`).
- `window.matchMedia('(min-width: 1024px)').matches === true` (the `lg` media query SHOULD apply).
- **BUT `getComputedStyle(cfg).gridTemplateColumns === "1131px"` — a SINGLE column.** The aside is NOT on the right; live: `stageLeft === asideLeft === 116`, `sameRow: false` (the aside is stacked BELOW the stage).
- **AND the CSS rule for that `lg:grid-cols-[minmax(...var(--...)...)]` utility is NOT in any stylesheet** (`gridRuleFound: false` — a full sheet-walk for a rule containing both `configurator-aside-max` and `grid-template-columns` found nothing). The class is INERT: present in the DOM, never emitted as a rule.
- So the chassis's intended layout (`Configurator.vue` `containerClass`):
  - `src/components/custom/configurator/Configurator.vue` `containerClass` line: `"grid grid-cols-1"` + `"grid-rows-[minmax(var(--configurator-stage-min,18rem),auto)_minmax(0,1fr)] lg:grid-rows-none"` + `"lg:grid-cols-[minmax(0,1fr)_minmax(var(--configurator-aside-min,280px),var(--configurator-aside-max,360px))]"`.
  - The base `grid-cols-1` (single column) emits fine; the `lg:grid-cols-[...]` arbitrary utility with nested `var()` + commas + `minmax()` does NOT JIT-compile in the demo's content-scan (the same failure class as BA.W-EMISSION: complex arbitrary brackets with nested `var()` die silently). So the chassis stays `grid-cols-1` on ALL widths.
- `Configurator.vue` defaults `asideSide: "right"` and the `asideColumnClass`/`stageColumnClass` flip is `lg:col-start-*` (also arbitrary-`lg:` — same risk). So even the side-placement logic is gated behind the same dead `lg:` utility.
- **Every studio inherits this:** aurora (`aurora.vue`), blob (`blob.vue`), fourier-studio (`fourier-studio.vue`), the `/compositions/configurator` reference all compose `<Configurator>` — all render single-column on desktop. The gear `PresetEditor.vue` is intentionally single-column (no stage — correct, exempt).

**The "not rounded" rider:** the aurora configurator computes `borderRadius: 12px` (`--radius-panel`, rounded at the root) — but `overflow-hidden` on the root + a child stage that bleeds to the corner, OR the `aurora-studio` height class `h-[min(78vh,720px)]` with `shadow-cartoon`, can make the corner read square if a child overflows the clip. (The root IS rounded; the user's "not rounded" is the corner being overrun by the stage content or the fullscreen `rounded-none` leaking — verify live.)

## Target spec (grounded)
The fix is to make the desktop two-column layout RELIABLY engage (kill the dead-arbitrary-utility class) + standardize the controls-right on every studio, at the ONE chassis. The architectural transposition: move the layout OFF the fragile arbitrary-`lg:` Tailwind utilities onto a ROBUST source that always ships.

**A — the desktop two-column grid must always emit (the EMISSION fix).** Re-express the `lg:grid-cols-[minmax(...var(...)...)]` arbitrary utility as a recipe that SHIPS regardless of content-scan reach — the BA.W-EMISSION precedent (structural arbitrary brackets precompile into shipped CSS, never load-bearing on JIT reach):
- Move the configurator grid template into `src/styles/configurator.css` as a real precompiled rule scoped to `[data-slot="configurator"]` (or `.configurator`): a `@media (min-width: 1024px)` block setting `grid-template-columns: minmax(0, 1fr) minmax(var(--configurator-aside-min, 280px), var(--configurator-aside-max, 360px))` + `grid-template-rows: none`. This is the SAME mechanism BA.W-EMISSION used for the Select collision-bound (`[data-slot="select-content"]` max-height in `select.css`) — the structural layout lives in shipped CSS, not a dead arbitrary utility.
- The `Configurator.vue` `containerClass` keeps `grid grid-cols-1` (the base single-column, emits fine) + the row template for mobile; the `lg:grid-cols-[...]` arbitrary utility is DELETED (clean break — it never worked). The desktop columns come from the precompiled `configurator.css` rule.
- The `asideSide` flip (`lg:col-start-*`) likewise moves into `configurator.css` as `[data-slot="configurator"][data-aside-side="left"]` rules (the side is a data-attr the SFC binds, not an arbitrary `lg:` utility); `right` (default) is the natural source order, no override.

- The gear `PresetEditor.vue` is the SANCTIONED single-column exception (a gear panel with no stage — controls-only, no side to place). Recorded in the gate's exempt list (the dock-FEATURE-exempt precedent).

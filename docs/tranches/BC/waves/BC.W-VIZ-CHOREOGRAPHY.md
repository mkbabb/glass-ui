## Goal (the gestalt)
Navigate INTO a substrate page and the viz does not just snap on — it MATERIALIZES: a coupled fade + a settle-from-scatter (the dots spring out from a collapsed point, the aurora blooms in, the constellation settles from a scatter into its drift) on the iOS-26 liquid-build-in feel. Switch a preset or a variant and the surface MORPHS with a spring glide, never a hard cut. Navigate AWAY and it fades + parks cleanly (no flash, no abrupt black). Hit restart and it re-seats velocity-continuously — if you restart mid-build it inherits the live position+velocity, not a jarring jump-to-zero (the iOS interruptible contract). And EVERY one of these beats — start, transition, end, restart — runs off the SAME keyframes.js clock the whole library speaks, so the viz feel is coherent with the dock morph, the dialog bloom, the tab squish. No setTimeout, no ad-hoc rAF, no per-viz hand-rolled timing — ONE source, ONE clock, the coupled fade the user named.

### A — START: the coupled liquid build-in (the user's "liquid fade-in")
A `SpringProgress` (the one-clock primitive) drives a `revealT ∈ [0,1]` scalar on the page-enter. The SAME scalar drives BOTH legs (the coupled fade, W-MOTION-CANON P3): (1) the canvas OPACITY ramps 0→1, AND (2) the viz's build-in uniform — a "settle-from-scatter" (the dots spring from a collapsed point `R=0`/a seeded scatter out to their lattice/phyllotaxis positions — dot-matrix.md §8, constellation.md §8; the aurora nuclei bloom in; the fourier curve assembles). ONE drive, both legs, on the spring's OWN settle clock (the `--spring-<name>-duration`, NOT a generic `--duration-*` — the W-GLASS-CAL per-spring-clock fence). The reveal reads a SPRING_PRESETS register (`bouncy` for the playful bloom / `smooth` for the calm settle — the per-viz wave picks; the dot-scatter build-in uses `stagger` so the dots appear core-out). The substrate already PRM-parks; this threads the reveal ON the kf clock (kf-vjs §5.1, §5.3).

### B — TRANSITION: the spring-glide preset/variant morph
A preset switch (aurora `medium`, dot-flow `coherence`) or a variant cross-fade (goo-blob `dot-field → dither → lattice`) reads `springTimingFunction(SPRING_PRESETS.smooth)` so the config-interpolation glides as a coherent spring, not a hard cut (kf-vjs §5.3; goo-blob.md §9, fourier-field.md §6.1). The config tween is a `SmoothProgress`/`SpringProgress`-driven uniform lerp, never a CSS class swap.

### C — END: the coupled fade-out + park
Route-leave fades the SAME `revealT` scalar back 1→0 (opacity + the uniform settle-out) then parks on the kf clock — no flash, no abrupt black (kf-vjs §5.4; goo-blob.md §9). The exit rides the no-overshoot `--ease-out` register (a closing surface must not overshoot past gone — W-MOTION-CANON P2), distinct from the bouncy enter.

### D — RESTART: velocity-continuous (the iOS interruptible contract)
`SpringProgress.set target` (or `reseatToSpring(probe, newTarget)`, kf-vjs §1.8) re-seats the closed form from the CURRENT (value, velocity) so a restart mid-build inherits the live trajectory — never a CSS-transition jump-to-zero (kf-vjs §5.3, §6; the `useSpringPress`/W-PRESS-UNIFY interruptible precedent). `seek(0)` on the `Sequence` restarts a multi-beat reveal. The cursor BURST (BC.W-VIZ-INTERACTION) decays on the SAME spring family (`decayRest` projects the rest).

### E — The Sequence orchestration (the multi-beat reveal)
A viz with a multi-beat reveal (the aurora masthead bloom → the field settle → the interactive arm) rides a LIGHT `Sequence` (kf-vjs §1.5): `label("intro")` → `.add(SpringProgress-driven-writer, at)` → `label("loop")` → `label("outro")`; `seek(0)` restarts; the renderer steps it via its frame `tick`. The SCC fence is binding: the Sequence orchestrates `SpringProgress`-driven shader-uniform writers (the LIGHT path), NOT `CSSKeyframesAnimation`/`AnimationGroup` (which would pull the HEAVY value.js engine into the viz chunk — kf-vjs §1.5 SCC FENCE).

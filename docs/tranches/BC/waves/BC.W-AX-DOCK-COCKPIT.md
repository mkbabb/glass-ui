## Goal (the gestalt)
A `<GlassDock data-preset="cockpit">` (or a `[data-preset="cockpit"]` ancestor scope) resolves a TIGHT, fixed cockpit geometry: the dock control floors at exactly `2.75rem` (the Q6-ratified fixed value — the dense-instrument-cockpit register, between the comfortable `2.5rem` default and the spacious `2.75rem` but as a NAMED preset, not a density rung), and the dock LABEL scales as a RATIO of the control height (`--dock-label-ratio`) so a tighter cockpit control carries a proportionally tighter label — the label never reads OVERSIZE relative to its pill. The chronic the speedtest A-9 ask names — the dock reading too large on the cockpit surface — closes: the cockpit preset is the named tight-geometry register a consumer opts into, the label tracks the control by ratio (not a fixed `--type-subheading` that reads big on a tight pill), and a `:root`/scope override of `--dock-label-ratio` retunes the whole dock label family from ONE knob. A reader sees: the cockpit dock is a tight, proportioned instrument strip — the control is `2.75rem`, the label is sized in proportion to it, nothing reads oversize.

## Target spec (grounded)
Two moves: the `[data-preset="cockpit"]` geometry register + the `--dock-label-ratio` label-tracks-control knob.

### T1 — the `[data-preset="cockpit"]` preset: a FIXED 2.75rem control floor (Q6)
A NEW `.glass-dock[data-preset="cockpit"]` block (in `src/styles/dock/density.css`, beside the density rungs — it is a geometry register on the SAME axis) sets:
- `--dock-control-size: max(calc(2.75rem * var(--dock-scale)), var(--dock-control-floor))` — the FIXED cockpit floor (Q6: `2.75rem`, not a range), riding `--dock-scale` + the 44px clamp (the cockpit dock never drops the touch target below 44px on coarse pointer).
- `--dock-layer-height: max(calc(2.75rem * var(--dock-scale)), var(--dock-control-floor))` — the control height in lockstep.
- The TIGHT chrome: `--dock-padding-block`/`--dock-padding-inline`/`--dock-gap`/`--dock-tile-pad` resolve the COMPACT-rung tightness (NOT the spacious loosening) — the cockpit is a DENSE instrument strip: a `2.75rem` control with compact padding/gap, so the dock reads tight, not loose. (The distinction from `spacious`: `spacious` is `2.75rem` control + the LOOSEST padding/gap; `cockpit` is `2.75rem` control + the TIGHTEST padding/gap — the instrument-cockpit register.)
- `--dock-control-safe-inset: calc(var(--dock-control-size) * 0.1)` — the 10%-per-side painted-plate inset (the BA.W-DOCK-GEOMETRY register, in lockstep with the rungs).
The preset is a `[data-preset="cockpit"]` ATTRIBUTE on `.glass-dock` (or an ancestor scope — the substitution-vs-inheritance discipline: a `[data-preset="cockpit"]` ancestor re-declares the geometry tokens, so descendant docks inherit). It composes WITH a `data-density` (the preset is a geometry OVERRIDE on top of a density base — `[data-preset="cockpit"]` wins the control-size/label by source-order). The cockpit is NOT a 5th density rung (it is a named preset — the density axis stays four rungs; the preset is a distinct register the consumer opts into).

### T2 — `--dock-label-ratio`: the label tracks the control height by proportion (the no-oversize-label fix)
The `@utility dock-label` (`typography/semantic.css:165-170`) re-points its `font-size` so the label is a RATIO of the control height, NOT a fixed subheading rung:
- mint `--dock-label-ratio` (default the ratio that resolves the HEAD `--type-subheading` at the comfortable `2.5rem` control — so the bare default is byte-near-identical; e.g. if subheading ≈ 1.275rem and comfortable control = 2.5rem, the ratio ≈ 0.51 → `font-size: calc(var(--dock-control-size) * var(--dock-label-ratio))`).
- the `dock-label` `font-size` becomes `var(--dock-label-size, calc(var(--dock-control-size, 2.5rem) * var(--dock-label-ratio)))` — the explicit `--dock-label-size` knob STILL wins when set (the audacious-mobile carve precedent, KEPT), else the label is a proportion of the control height. So a `cockpit` control (`2.75rem`) carries a label sized `2.75rem * --dock-label-ratio` — proportional, not the fixed subheading rung that read oversize.
- the ratio is the consumer retune knob: a `:root`/`[data-preset="cockpit"]` `{ --dock-label-ratio: … }` override retunes the whole dock label family in one write (the token-first axis). The cockpit preset MAY tighten the ratio further (a cockpit-specific `--dock-label-ratio` on the `[data-preset="cockpit"]` block) so the cockpit label reads even tighter relative to its control — the A-9 close.
The HEAD default (no preset, comfortable density) resolves the SAME label size it does today (the ratio is calibrated to reproduce `--type-subheading` at `2.5rem`) — byte-near-identical, no MIGRATION row.

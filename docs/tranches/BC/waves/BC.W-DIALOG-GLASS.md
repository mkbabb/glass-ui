## Goal (the gestalt)
A user opening a Dialog over the demo sees the page CLEARLY through it — a real frosted glass sheet floating over content, the backdrop's color and shapes diffusing through, the way the iOS-27 control center glass shows the home screen behind it. The modal reads unmistakably as GLASS: partially transparent (you can see through it), warm-cream tinted, blur-diffused, with a bright catch-light rim on the top edge (no dark hairline bar) and a soft under-shadow lifting it off the scrim. The text on it is legible and warm-inked (not harsh pure-black, not a washed muted whisper) because the tint+contrast adapt to whatever's actually behind it. The padding breathes — the heading clears the top edge, the body has room, the close button is not jammed in a corner. It is "different + glassy," the opposite of the current opaque slab.

**The apple-glass parity + the bested-with-paper differentiation (research/apple-glass.md §1.2/§2/§3.2).** apple.com's ONLY full-frost overlay is the dropdown CURTAIN — a `blur(20px)` cool-grey scrim (`rgba(232,232,237,0.4)`) that DIMS the page, materializing by an OPACITY fade (`0→0.95` over `0.32s cubic-bezier(0.4,0,0.6,1)` +0.08s, blur CONSTANT — research/apple-glass.md §1.2). That is the achievable web floor: a flat opacity fade of an already-blurred scrim. glass-ui's `.glass-reveal` is RICHER (it RAMPS `filter: blur(4px)→0`, the iOS materialize-by-light-bending the web never shipped) AND it floats over the warm-cream paper-grid craft, not a cool dimming scrim — so the dialog reveals the page's color/shapes/IconChip/math beneath it, where apple.com's curtain DIMS them to grey. apple.com has NO glass content modal at all (its cards are flat `#f5f5f7` — research/apple-glass.md §1.3); glass-ui's transparent warm-cream dialog over craft is a register apple.com's web simply does not have. The differentiation, stated: **Apple's overlay glass DIMS the page to a cool scrim; ours REVEALS the warm craft beneath.**

## Starting state (measured, file:line)
Live probe (open dialog at `/containers/dialog`, 2026-06-18 — research/glass-dock-codebase.md §1.5):
- dialog `bg = oklab(0.942574 … / 0.808)` — **80.8% alpha.** It composes `.glass-floating` (`DialogContent.vue:108` `surfaceClass(props.surface, 'floating')`), the LEAST-transparent tier short of overlay: `--glass-opacity-floating: 0.80` (`tokens/glass.css:57`). The iOS-27 control-center modal sits ~60% transparent; 80% reads as a near-opaque slab — "NOT glassy at all."
- `borderColor = oklab(0.216128 … / 0.19)` — **the dark warm-ink black bar at 19% alpha** (`--glass-border-floating`, `tokens/glass.css:194`, `color-mix(in srgb, var(--foreground) 19%, transparent)` where `--foreground = hsl(24 10% 10%)` is the near-black warm ink). EVEN DARKER than the card's 16% (§1.2 recurs on the floating tier).
- `backdropFilter = blur(13px) saturate(1.18)` — the blur IS there and correct (`--glass-blur-floating`, the W-GLASS-CAL calm value). So the diffusion mechanism works; the OPACITY occludes it.
- `color = rgb(0, 0, 0)` — **PURE BLACK ink.** The overlay band self-engages the `contrast-color()` flip UNCONDITIONALLY (`ladder.css:302-306`: `:where(.glass-floating, .glass-overlay) { color: contrast-color(var(--card)); --foreground: contrast-color(var(--card)); --muted-foreground: contrast-color(var(--card)); }`). On a translucent cream-over-light plate `contrast-color(--card)` resolves to pure black — harsh on the cream, AND `--muted-foreground` flips to the same so captions lose their muted register.

So "NOT glassy" is a COMPOSITE of three roots: (a) 80% opacity is too opaque, (b) the dark-ink border rings it (the D2 black bar, `tokens/glass.css:194`), (c) the unconditional contrast-color flip blackens all ink. The architecture is RIGHT — `surfaceClass` + `.glass-reveal` (DialogContent.vue:108/97) are correct; the TIER, the rim, and the over-eager flip are wrong. Padding: `DialogContent.vue:90` already carries the BB.W-CARD-PAD overlay golden ladder (`--overlay-pad-inline: --spacing(6)` = 24px, `--overlay-pad-block: calc(*1.272)` ≈ 30.5px) — so the padding source is present but UNVERIFIED in paint (BB never ran W-REFLECT3; the "dialog padding wrong" read may be the composite muddiness, not the pad math — this wave VERIFIES it lives).

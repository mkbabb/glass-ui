## Goal (the gestalt)
A user opening a Dialog over the demo sees the page CLEARLY through it — a real frosted glass sheet floating over content, the backdrop's color and shapes diffusing through, the way the iOS-27 control center glass shows the home screen behind it. The modal reads unmistakably as GLASS: partially transparent (you can see through it), warm-cream tinted, blur-diffused, with a bright catch-light rim on the top edge (no dark hairline bar) and a soft under-shadow lifting it off the scrim. The text on it is legible and warm-inked (not harsh pure-black, not a washed muted whisper) because the tint+contrast adapt to whatever's actually behind it. The padding breathes — the heading clears the top edge, the body has room, the close button is not jammed in a corner. It is "different + glassy," the opposite of the current opaque slab.

## Starting state (measured, file:line)
Live probe (open dialog at `/containers/dialog`, 2026-06-18 — research/glass-dock-codebase.md §1.5):
- dialog `bg = oklab(0.942574 … / 0.808)` — **80.8% alpha.** It composes `.glass-floating` (`DialogContent.vue:108` `surfaceClass(props.surface, 'floating')`), the LEAST-transparent tier short of overlay: `--glass-opacity-floating: 0.80` (`tokens/glass.css:57`). The iOS-27 control-center modal sits ~60% transparent; 80% reads as a near-opaque slab — "NOT glassy at all."
- `borderColor = oklab(0.216128 … / 0.19)` — **the dark warm-ink black bar at 19% alpha** (`--glass-border-floating`, `tokens/glass.css:194`, `color-mix(in srgb, var(--foreground) 19%, transparent)` where `--foreground = hsl(24 10% 10%)` is the near-black warm ink). EVEN DARKER than the card's 16% (§1.2 recurs on the floating tier).
- `backdropFilter = blur(13px) saturate(1.18)` — the blur IS there and correct (`--glass-blur-floating`, the W-GLASS-CAL calm value). So the diffusion mechanism works; the OPACITY occludes it.
- `color = rgb(0, 0, 0)` — **PURE BLACK ink.** The overlay band self-engages the `contrast-color()` flip UNCONDITIONALLY (`ladder.css:302-306`: `:where(.glass-floating, .glass-overlay) { color: contrast-color(var(--card)); --foreground: contrast-color(var(--card)); --muted-foreground: contrast-color(var(--card)); }`). On a translucent cream-over-light plate `contrast-color(--card)` resolves to pure black — harsh on the cream, AND `--muted-foreground` flips to the same so captions lose their muted register.

So "NOT glassy" is a COMPOSITE of three roots: (a) 80% opacity is too opaque, (b) the dark-ink border rings it (the D2 black bar, `tokens/glass.css:194`), (c) the unconditional contrast-color flip blackens all ink. The architecture is RIGHT — `surfaceClass` + `.glass-reveal` (DialogContent.vue:108/97) are correct; the TIER, the rim, and the over-eager flip are wrong. Padding: `DialogContent.vue:90` already carries the BB.W-CARD-PAD overlay golden ladder (`--overlay-pad-inline: --spacing(6)` = 24px, `--overlay-pad-block: calc(*1.272)` ≈ 30.5px) — so the padding source is present but UNVERIFIED in paint (BB never ran W-REFLECT3; the "dialog padding wrong" read may be the composite muddiness, not the pad math — this wave VERIFIES it lives).

## Target spec (grounded)
THREE coordinated moves; the dialog becomes the specimen that proves the Band-1 floor on the floating/overlay tier.

1. **Drop the modal to a MORE-TRANSPARENT tier (the partial-transparency the user demands).** The iOS-27 control-center glass is ~60% transparent (research/apple-ios27.md §1.5 "the user wants the modal MORE transparent (the iOS-27 control-center ~60%, not 80%)"; §5 bake-table BC.W-DIALOG-GLASS "lower toward 0.80-0.85… the user wants it GLASSY"). The modal must read THROUGH. Mechanism, token-first: the dialog reads a DIALOG-SCOPED opacity that sits between `floating` (0.80) and a genuinely-transparent register. Two options, KISS-decide at build:
   - **(a, preferred)** keep `.glass-floating` as the base tier but re-point the dialog's effective plate to a **`--glass-bg-dialog`** composed at ~**0.68 opacity** (between resting 0.65 and floating 0.80 — transparent enough to read through, opaque enough for AA legibility against the bright bucket), declared the `--glass-bg-dock` self-re-point way (`tokens/glass.css:172` precedent — a per-surface composed bg the surface re-declares on its scope, NOT a raw rung override that won't re-compose; research/glass-dock-codebase.md §"substitution-vs-inheritance trap"). The blur (`--glass-blur-floating` 13px) STAYS (it is the diffusion; the W-GLASS-CAL value is correct).
   - **(b)** drop the base tier to `.glass-resting` (0.65). Rejected unless (a) fails AA — resting drops the floating-tier under-shadow/edge that lifts the modal off the scrim; the modal wants the floating LIFT with the resting TRANSPARENCY, which is exactly what the `--glass-bg-dialog` re-point at 0.68 gives.
   The `--glass-bg-dialog` opacity is the iOS `.regular` modal register, NAMED so a consumer retunes it; the value is the LIBRARY identity (presets-in-consumers).
2. **The rim → catch-light, no black bar (inherited from BC.W-BLACK-BAR).** This wave does NOT re-author the border token (that is BC.W-BLACK-BAR's single-source fix at `tokens/glass.css:191-196`). It VERIFIES the dialog's top edge reads as a bright catch-light + a faint bottom under-shadow, NOT a dark 19%-ink hairline. If BC.W-BLACK-BAR lands the directional rim (research/apple-ios27.md §1.6 option (a): top catch-light `inset 0 1px 0 hsl(0 0% 100%/0.3)`, bottom shadow `inset 0 -1px 0 hsl(0 0% 0%/0.06)`, retiring the uniform warm-ink top), the dialog inherits it for free — the dialog's acceptance is the binding paint check that it DID.
3. **Gate the contrast-color flip to the actually-darkened plate (inherited from BC.W-ADAPTIVE-RECONCILE; this wave fixes the overlay-band half).** The unconditional flip (`ladder.css:302-306` `:where(.glass-floating,.glass-overlay)`) blackens ink even on a calm modal over a light page. Re-shape it the way the content-tier flip was already gated (`ladder.css:309-315` scope-7 note: "the content-tier ink flip is GATED on the bright signal"): the overlay band's `contrast-color` flip moves INTO the `@container style(--glass-backdrop: light)` bright bucket (where the plate ACTUALLY darkens to AA), so a calm modal over a light page keeps the WARM-INK `--foreground` register (legible, not pure-black), and only a modal over a genuinely-bright/busy backdrop flips to the dark contrast ink. The `--muted-foreground` lifts in LOCKSTEP only in the bright bucket (the scope-6 selection-lockstep), keeping the muted caption register on the calm modal. This is the dialog's contribution to closing the adaptive loop (BC.W-ADAPTIVE-RECONCILE owns the dock/content arms; this owns the overlay-band arm).
4. **VERIFY the padding lives (the dialog-padding half of "padding wrong").** Confirm `DialogContent.vue:90`'s overlay golden ladder paints: heading clears the top by ≥ the block pad (~30.5px), 24px inline, the close button (DialogContent.vue:159 `right-4 top-4`) is clear of the heading. If the close-button `right-4 top-4` (16px) collides with the heading at the new pad, retune to read the overlay-pad tokens (`right-(--overlay-pad-inline) top-(--overlay-pad-block)`) so the dismiss tracks the pad ladder.

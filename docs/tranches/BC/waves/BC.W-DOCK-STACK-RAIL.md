## Goal (the gestalt)
The dock rail is the macOS Dock stack the user asked for — a thin rail extending beyond the dock's edge, carrying a small set of core stack items. Hover (or focus) a stack item and its members fan OUT next to the rail — a column of glass icons springing open beside the line, each on the iOS liquid clock, never a flat dropdown. The rail shows a few configurable items at rest (the default is 3) and scrolls if there are more, so a long stack is reachable by scrolling the rail, not by overflowing the dock. The bottom-most stack item sits at the dock's bottom edge; the rest sit in the dock (the one anchored item) and fan against the rail (the n scrollable members). At any moment you see one-or-n items expanded — and they are FULLY VISIBLE glass icons, never the ghostly shadowed half-tucked chips the old divider-carousel painted. The divider-carousel — the floating chip strip that BB shipped — is gone entirely. The rail clears the page title and any form field by topology: it lives beyond the dock edge in its own gutter, so it never grazes `<main>` (the chronic chip-graze that revoked the BA dock/shell PASS ends here).

## Target spec (grounded)
A from-scratch rail — the macOS hover-expand stack — built on the KEPT `.glass-dock-frame` non-clipping escape, the divider-carousel cleanly retired. The verbatim spec (research/deferral/memory.md `rail-spec-contradicted-divider-carousel`): *"rail EXTENDS beyond the dock; on hover of a core rail item its icons EXPAND OUT next to the rail; 3 configurable items visible/scrollable; bottom-most stack item extends to dock bottom, rest sit in dock(1)+against rail(n scrollable); only 1-or-n displayed NOT shadowed."* Token-first, component-over-class, Tailwind-first (re-express the macOS-stack reference via `@theme`/`@utility`, never a raw CSS paste — MEMORY `precept-tailwind-first`).

1. **The rail extends beyond the dock edge** (the KEPT escape). The rail is a thin glass line/spine hanging off the dock edge into its own gutter, anchored to the `.glass-dock-frame` (the non-clipping sibling context). It NEVER changes the dock box (the box-INVIOLATE R-arm STAYS — the rebuild keeps the `deltaW = deltaH = 0` discipline). Reuse `--dock-rail-extend-length` (the beyond-edge extent, rail-extend.css:39, `calc(2.5rem * --dock-scale)`) as the rail's reach into the gutter; the seam axis keys off the dock `orientation` (a vertical dock's rail runs vertical alongside, a horizontal dock's runs horizontal). The rail seats at the dock EDGE (the `position` start/end prop), NOT a `[data-rail-anchor]` divider seam (the seam-locator RETIRES).

2. **The stack: a core item that hover-expands its members OUT next to the rail.** A `<DockStack>` is one stack: a CORE item (the always-visible anchor glyph, sitting in the dock(1)) + N members (the stack's contents). On hover (pointer-enter) OR focus of the core item, the members FAN OUT next to the rail — a column (vertical dock) / row (horizontal dock) of glass icons springing open beside the line, each member a FULLY-VISIBLE glass icon (the `--glass-bg-floating` selected-reads-as-glass register + the corrected catch-light rim, NOT a shadowed half-tucked chip). The fan-out is the iOS materialize choreography (apple-ios27.md §2.1): coupled scale + translate ON the spring + opacity + a `filter` blur-settle, each member staggered by `--dock-stack-stagger * var(--i)` in reading order (the `.scroll-build` stagger idiom). The hover-collapse (pointer-leave / focus-out) reverses on the no-overshoot `--ease-out` (P2 — exit never overshoots past gone). Mouse-leave carries the `useDockState` hover-hysteresis (the `HOVER_INTENT_MS = 60` intent-dwell, `constants.ts:93 + EDGE_BAND_PX = 24`) so a sweeping-edge enter does not flash the stack open (the AZ.W-DOCK-FLICKER pattern reused, not re-forked).

3. **3 configurable items visible, scrollable, n-stack.** The rail shows `visibleCount` core items at rest (DEFAULT **3**, a consumer prop). A stack with more than `visibleCount` members SCROLLS — the members fan into a scroll port (the `<FadingScroll>` primitive, the single scroll-fade port the divider-carousel already used, reused here for the fanned column) so the n-stack is reachable by scrolling the rail, NOT by overflowing the dock box. The `visibleCount` default is 3 (the verbatim "3 configurable items visible"); the scroll handles the rest (the verbatim "scrollable, n-stack"). The embla-on-overflow momentum-paging fold (research/deferral/{az,ba}.md, the >budget arm) is SUPERSEDED — the scrollable-stack IS the overflow mechanism; the embla book is DECIDED-superseded (recorded in `BC.W-FOLD-LEDGER`).

4. **The bottom-most stack item extends to the dock bottom; the rest sit in dock(1) + against rail(n scrollable).** The stack's anchor topology (the verbatim spec): the bottom-most member sits at the dock's bottom edge (the dock-anchored end), the CORE item sits in the dock(1) (the always-visible anchor), and the n members fan against the rail (the scrollable column). This is the macOS Dock-stack anchoring — one item docked, the fan extending into the rail gutter, the bottom member reaching the dock floor. Express via the rail's flex layout + `align-self` anchoring on the `.glass-dock-frame` (NOT a hand-positioned `inset`).

5. **Only 1-or-n displayed, NOT shadowed.** At rest only the core (1) item shows; expanded, the n members show. Every displayed member is a FULLY-OPAQUE-ENOUGH glass icon (the `--glass-bg-floating` tier reading the W55 tint seam + the catch-light rim) — NEVER the half-tucked, low-alpha, shadowed chips the divider-carousel painted (the "NOT shadowed" verbatim ask). No member renders at a dimmed/ghost alpha behind another; each is a clear glass icon.

6. **Clears the title + form field BY TOPOLOGY** (THE HEADLINE — research/deferral/ba.md `ba-dock-shell-gestalt-fail-revoked` + `ba-breadcrumb-overlap-tension` + `ba-chip-graze`). The rail lives BEYOND the dock edge in its own gutter (the off-canvas lower/side gutter the BB.W-DOCK-RAIL-SEAT-FINAL `chipOverMain: false` topology established, demo `dock-nav.css` `.demo-sidebar-rail`), so the fanned members NEVER reach `<main>` / the `<h1>` / a form field at ANY y by construction. The fan extends into the gutter AWAY from content, not over it. This is the band-agnostic `chipOverMain: false` on ALL routes — the chip-graze that revoked the dock/shell PASS cannot recur.

## Goal (the gestalt)
Open `/forms/checks` and the RadioGroup behaves like a real iOS-27 radio set: tap any option — by mouse, by touch, by keyboard arrow — and it **immediately** snaps selected, the previously-selected one releases, and there is exactly one filled dot in the group. The selected ring reads as a clear, legible glass-tinted fill with a confident centre dot (not a near-invisible hairline outline that you have to squint to tell apart from the unselected siblings). The disabled `drone` option stays inert and dim. Switch to dark mode and the selected dot still reads. Nothing in the group "does nothing when clicked" — the headline §F bug is gone on every input path.

## Starting state (measured, file:line)
The radio is broken on TWO axes: a **binding/interaction** axis (the headline "don't work") and a **legibility** axis ("no proper toggle states").

**1. The interaction is path-dependent — a bare click does nothing, only a full pointer sequence toggles.** Live-probed at `/forms/checks` (2026-06-18, GPU Playwright):
- A bare `radioItem.click()` → **`data-state` stays `unchecked`, `aria-checked` stays `false`, no indicator** (the toggle never fires).
- A full `pointerdown → mousedown → pointerup → mouseup → click` sequence → `data-state: checked`, `aria-checked: true` (it DOES toggle).
- So reka's `RadioGroupItem` listens on the pointer sequence, not a synthetic `click`. The deeper risk (the MEMORY `glass_ui_binding_verification` chronic — "stale reka-ui prop/emit bindings silently no-op; vue-tsc+units miss them, only e2e catches"): the model wiring through `RadioGroup.vue`'s `useForwardPropsEmits` must be re-verified live, because the route-census + the user both report the live tap doing nothing.
- The binding surface: `src/components/ui/radio-group/RadioGroup.vue` forwards `RadioGroupRootProps & RadioGroupRootEmits` via `useForwardPropsEmits(delegatedProps, emits)`. reka's `RadioGroupRoot` (node_modules/reka-ui/src/RadioGroup/RadioGroupRoot.vue:8,25-27) uses `modelValue` / `update:modelValue` with `useVModel(... passive: (props.modelValue === undefined))`. The demo binds `<RadioGroup v-model="plan">` + `<RadioGroupItem :value="p">` (`demo/stories/forms/checks.vue:88-93`). The `delegatedProps` computed strips ONLY `class` — `modelValue` passes through — so the forward LOOKS correct; the live no-op means the failing path is the consumer tap → reka pointer handler reaching the item, NOT the model forward. The candidate culprits below sit between the tap and reka's handler.
- `touch-hit-area` + `tap-squish` on `RadioGroupItem.vue:24` — these wrap the 16×16 item; if `touch-hit-area`'s expanded pseudo-element or `tap-squish`'s transform intercepts/eats the pointer before reka's listener, the tap is swallowed. Live: `transition-control` is also on the item (`transition: background-color,color,box-shadow,border-color 0.2s cubic-bezier(0.4,0,0.2,1)`), which does not block pointers but confirms the surface stack.

**2. The selected-state barely reads.** `src/components/ui/radio-group/RadioGroupItem.vue`:
- The ring is `h-4 w-4 rounded-pill border border-primary text-primary` — a 1px `--primary` outline, 16px.
- The indicator is `<Circle class="h-2.5 w-2.5 fill-current text-current" />` inside `RadioGroupIndicator` — a 10px filled circle in `--primary`.
- Live `borderRadius: 9999px` (pill, correct), `borderColor: rgb(28,25,23)` = the near-black warm ink `--primary` light. So the unchecked ring is a thin dark hairline and the checked dot is the SAME dark `--primary` — the selected/unselected delta is "dot present vs absent" with no surface/fill change, no glass tint, no lift. Against the warm-cream page at small size the toggle-state reads weak (the user's "no proper toggle states").
- There is NO glass register on the radio: Checkbox got `data-[state=checked]:bg-[color-mix(in srgb,var(--primary) 88%,var(--glass-bg-floating))]` (`Checkbox.vue`), the Switch track got `.glass-wash` (`Switch.vue`), but the radio ring kept the bare `border-primary` outline (AY.W-PRIM-POLISH ARM B left the 16px atoms on the opaque allowlist).

## Goal (the gestalt)
Tap the collapsed dock pill and it MORPHS — continuously, via the metaball bridge, not a hard swap — into a search field; type and the fuzzy dropdown ranks live with subsequence-match highlighting and an autocomplete ghost-text completion of the top match; ArrowDown/Up walks the results, Enter routes, a select scrolls-to-and-warms the windowed target; tap away and the dock returns to a compact persistent bar. The morph is the reward (the iOS-27-retained delight); the dock NEVER auto-collapses on a passive scroll (that costs a tap — the iOS-27 lesson). The active search field reads CLEARLY forward over whatever backdrop it floats on (≥4.5:1, the W55 darken seam) — never the pale-ghost-fading-into-content trap. It is the dock the words app wants: the bespoke 7-composable search bar replaced by `<GlassDock search>`, the consumer plugging its own async data source while the dock owns the gesture, the shrink, the dropdown.

## Target spec (grounded)

### 1. `<GlassDock search>` / the `useDockSearch` seam — the dock-search register (a NEW mode BESIDE `useDockState`, NOT a `dockMorphContext` edit)
A `search?: boolean` prop on `<GlassDock>` (additive, default false — the dock is a nav/feature chrome by default; search is the opt-in mode) backed by a NEW composable `src/components/custom/dock/composables/useDockSearch.ts`:
```ts
export interface UseDockSearchOptions<T extends SearchableItem = SearchableItem> {
  dockState: UseDockStateReturn;        // composes the existing state machine (no fork)
  /** The search items (sync) — OR an async source via onSearch (the words network case). */
  items?: T[] | (() => T[]);
  /** The pluggable async data source (the consumer owns abort/network — the dock owns the gesture). */
  onSearch?: (query: string, signal: AbortSignal) => Promise<T[]>;
  /** Opt-in collapse-on-scroll (composes useScrollChrome — persistent-default). */
  collapseOnScroll?: boolean;
  scrollContainer?: MaybeRefOrGetter<HTMLElement | Window | null>;
  /** Result-select hook: wires ensureTargetWindow + scrollTo (the ToC subsume). */
  onResultSelect?: (result: SearchResult<T>) => void;
}
export interface UseDockSearchReturn<T extends SearchableItem = SearchableItem> {
  fuzzy: FuzzySearchState<T>;            // the composed useFuzzySearch handle
  autocompleteText: Ref<string>;        // the ghost-text top-match completion
  armSearch: () => void;                // tap/focus → expand + hold (composes onClickCollapsed + keepOpen)
  disarmSearch: () => void;             // close → release the hold
  acceptAutocomplete: () => void;       // Tab/Space/ArrowRight fills the ghost-text
}
```
- **Expand-on-tap/focus** — `armSearch()` composes `dockState.onClickCollapsed()` (collapsed → pinned) + `dockState.keepOpen()` (the ref-counted hold so the dock stays open through the search gesture — the existing seam, `useDockState.ts:328-345`); `disarmSearch()` calls `dockState.release()`. NO new state machine.
- **The dropdown** — composes the hardened `useFuzzySearch` (`BC.W-FUZZY-HARDEN`'s confirmed surface: `query`/`results`/`selectedIndex`/`onKeydown`/`selectResult`) for the result list + the keyboard nav (Arrow/Enter/Escape already in `onKeydown`). The results render in a `useVirtualSectionWindow`-backed list (`BC.W-VIRTUAL-WINDOW`) — only the windowed slice paints.
- **Autocomplete ghost-text** — `autocompleteText` is the words `useAutocomplete` pattern generalized off the fuzzy `results[0]`: when `results[0].item.label` starts-with the query (case-insensitive), the ghost-text is the unmatched suffix; `acceptAutocomplete()` (Tab/Space/ArrowRight) fills it. Generic over the fuzzy result — NO words type.
- **The async source** — `onSearch(query, signal)` is the pluggable data source (the words network case): the consumer owns the abort/generation race-guard (`useLookupSearch`-shape — words-LOCAL, plugged here); the dock owns the gesture/shrink/dropdown. When `items` is set the dock runs the sync fuzzy; when `onSearch` is set it awaits the async source (the dock debounces + cancels the prior `AbortController` on a new query — the generic race-guard `BC.W-FUZZY-HARDEN` mints IF the ≥2-bar holds, else the dock's own thin abort). The two are mutually exclusive (sync XOR async).
- **The result-select → ToC subsume** — `onResultSelect` wires `BC.W-VIRTUAL-WINDOW.ensureTargetWindow(id)` (warm the window so the target is rendered) + `BC.W-TOC-RECONCILE.useScrollTo(id)` (the rAF-retry scroll-to-and-land). The dock-search result-select scrolls-to + warps the windowed target — the words `scrollToSelectedResult` generalized onto the shipped ToC + windowing leaves.

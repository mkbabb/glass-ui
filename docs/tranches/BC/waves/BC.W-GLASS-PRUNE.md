## Goal (the gestalt)
A developer opening `/substrates/glass-panel` and `/display/card` sees TWO clearly-distinct things, not seven overlapping ones. **Glass MATERIALS** (`/substrates/glass-panel` becomes the MATERIALS gallery): the five-rung `.glass-{wash,quiet,resting,floating,overlay}` ladder shown bare over a live aurora — the raw iOS liquid-glass plate, with its depth (`.glass-deep`) and refraction (`.glass-lens`) AXES toggled live, each rung visibly more present than the last. **Glass CARDS** (`/display/card`): the `<Card>` component — a material wrapped in a content chassis with the golden padding ladder, header/body/footer. The `<GlassPanel>` component is GONE; there is no third "panel" thing that does what Card does. When a developer asks "which glass do I reach for?" the answer is binary and obvious: a bare surface → a `.glass-{rung}` MATERIAL; a content container → a `<Card>`. The Apple precedent backs it exactly — Apple ships ONE material with TWO variants (`.regular`/`.clear`), not a panel-plus-card-plus-surface zoo.

## Target spec (grounded)
TWO registers; everything else folds onto them as AXES or RETIRES.

**Glass MATERIALS** = the ONE material expressed as the 5-rung ladder + atom + the two modifier AXES:
- the `.glass-{wash,quiet,resting,floating,overlay}` ladder (`glass/ladder.css`) — the iOS `.regular`↔firmer variant continuum (opacity+blur+tint). KEEP byte-identical (BC.W-GLASS-IDENTITY owns the values).
- the `.glass-material` atom (`glass/material.css`) — the specular `::before` + rim. KEEP.
- the `.glass-deep` DEPTH axis (`glass/deep.css`) — the opt-in maximal-iOS tier (the Apple home-nav 16-20px register). KEEP as an axis modifier, NOT a register.
- the `.glass-lens` REFRACTION axis (`glass-refract.css`) — the squircle `feDisplacementMap` lens (n=1.5, scale=28, `⁴√(1-(1-x)⁴)`; research/apple-ios27.md §1.2). KEEP as an axis modifier.

**Glass CARDS** = `<Card>` — a material wrapped in a content chassis (`tier` selects the rung; `surface` the {glass·veil·opaque} decoration; the golden padding ladder; header/body/footer slots). KEEP.

**RETIRE `<GlassPanel>`** (clean break, no alias — MEMORY no-backwards-compat). It is a true duplicate:
- its `variant` (the 5-rung selector) ≡ Card's `tier`. A consumer wanting a bare material rung writes the `.glass-{rung}` CLASS directly (component-over-class applies to INTERACTIVE elements; a bare glass plate IS a static CSS pattern — design-axis 2). A consumer wanting a content container writes `<Card tier="…">`.
- its `surface` ≡ Card's `surface` (the SAME `useSurfaceAxis` resolver, GlassPanel.vue:16/79).
- its `tier` (svg-filter/css/fallback renderer-preference) folds onto the `.glass-lens` axis: the `createGlassFilter` `feDisplacementMap`-in-`backdrop-filter` (`useGlassRenderer.ts:147-235`) is byte-mechanically the SAME thing as `#glass-refract` (`glass-refract.css`). The lens is the ONE refraction source.

**`useGlassRenderer` disposition (the unique-facility decision):** `createGlassFilter`/`destroyGlassFilter`/`createGlassPattern` are the runtime-built per-element SVG displacement filter. The W-LENSING `#glass-refract` is a STATIC document-level SVG filter the `.glass-lens` class references via `@supports (backdrop-filter: url(#…))`. Decision: RETIRE the runtime `useGlassRenderer` filter-builder (GlassPanel was its only consumer) onto the static `.glass-lens` axis — ONE refraction source (research/glass-dock-codebase.md §1.4: "its `useGlassRenderer` SVG-displacement filter folds onto `.glass-lens`/`.glass-refract` (the SAME `feDisplacementMap`-in-`backdrop-filter` mechanism)"). IF a per-instance runtime scale is needed later (the CSS-var-in-url() limit, W-LENSING booked successor), it re-enters as a `.glass-lens`-axis refinement, never a parallel component. The `GlassTier` type + `useGlassRenderer.ts` retire WITH GlassPanel unless a second non-GlassPanel consumer is found by the registry+constellation probe (below) — if found, fold that consumer onto `.glass-lens` first.

**The `/substrates/glass-panel` route becomes the MATERIALS GALLERY** (NOT deleted — the user explicitly asks for the prune to PRODUCE the two-register clarity, and the MATERIALS gallery is where the MATERIALS register lives): re-author `demo/stories/substrates/glass-panel.vue` to render the five bare `.glass-{rung}` rungs over a live `<Aurora>` (the glass-over-a-live-field demo, manifest.ts:308-311 confirms it already self-stages aurora), each rung labeled, with live toggles for the `.glass-deep` and `.glass-lens` axes — composing the bare CLASSES, NOT `<GlassPanel>`. This is distinct from `/display/card` (the CARDS gallery). The route stays at the same path (it teaches the MATERIALS register); the component behind it changes from `<GlassPanel>` to bare classes. (Page-chassis standardization — hero-shrink, ONE card — is BC.W-PAGE-CHASSIS's; this wave owns the component swap + the two-register clarity.)

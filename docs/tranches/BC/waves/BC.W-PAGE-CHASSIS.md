## Goal (the gestalt)
Open ANY route on `:5199` and you read the SAME confident page idiom: a LARGE audacious display title sitting over a live procedural field, a quiet mono eyebrow above it carrying the route's explicit import subpath in Fira Code (`@mkbabb/glass-ui/aurora`), a one-line subtitle beneath, and the whole page body in exactly ONE warm-cream glass card floating over that field — never two cards, never a grid-card-inside-a-page-card, never a header buried inside the body card. Scroll down and the hero title smoothly SHRINKS (a buttery compositor scale, no reflow) into a slim sticky page-header that holds title + subpath, the way iOS-27 collapses a large-title nav bar — the body slides up under it. Every page is the same recognizable shape; only the title, the subpath, the per-category icon, and the procedural field differ. The "double card on a grid" mess and the three-competing-header-idioms are gone — one chassis, every page.

The hero `<h1>` entrance is a one-shot mount fade-rise ONLY (`story-hero.css:191-204` `@keyframes story-hero-title-rise`). Live-measured: the homepage has exactly ONE sticky element (the nav, NOT the hero) (route-census.md §0 gap 1). The user's headline bar ("SHRINKS as you scroll") is **0% implemented at the page level**.
- **The hero `<h1>` is hardcoded `text-display-3` (~67.78px peak).** `StoryHero.vue:292` AND `:333` both render `class="story-hero-title story-hero-title--enter text-display-3"`. The √φ ladder peaks at `--type-display-audacious` (352px, `scale.css:146-149`) but the chassis caps every hero at display-3. (The audacious-tier lift is `BC.W-HERO-AUDACIOUS`'s primary scope; this wave adds the `heroScale` PROP MECHANISM it threads.)
- **THREE competing header idioms** (route-census.md §1): A = audacious chassis hero (12 `hero:true` rows), B = hand-rolled `border-l-[3px]` IconChip header INSIDE the body (41 SFCs — a literal double-descriptor, e.g. `forms/inputs.vue:23-41`), C = plain 32.9px `text-title` chrome `<h1>` (~60 routes). - **The subpath is NOT explicit.** The eyebrow is `"{Category} · {Story}"` (`StoryPage.vue:26-30`, e.g. "Forms · Inputs"), NEVER the import subpath. The `Story` interface (`manifest.ts:34-53`) has NO `subpath` field. The user's "subpath explicitly defined" bar (USER-DEFECTS §E) is unmet.

- **4 SFCs BYPASS the chassis** (route-census.md §6): `substrates/aurora.vue` hand-rolls `<header>` with a `<span class="text-display-3">Aurora</span>` (NOT a semantic `<h1>` — an a11y defect, live-confirmed) + does NOT import `StoryPage`.
- **What is already correct (KEEP, do not re-author):** the `StoryHeader` 3-stage GRAVITY entrance + reading order (eyebrow→title→blurb, `StoryHeader.vue:53-86`, BB.W-HIERARCHY2 — correct); the ONE-card-over-field architecture (`StoryHero.vue:212-216` `cardTier`); the `cardTier` drop to `wash`/`quiet` over a live field (`StoryHero.vue:212-216`); the full-bleed escape for live-substrate heroes (`StoryHero.vue:197`).

## Target spec (grounded)

   - The hero cluster wrapper is `position: sticky; top: 0` over an `animation-timeline: scroll()` (the `<main>` route-scroller timeline, the `--card-scroll` `<ScrollCardHeader>` precedent generalized — CLAUDE.md §BB.W-SCROLL-CARD).

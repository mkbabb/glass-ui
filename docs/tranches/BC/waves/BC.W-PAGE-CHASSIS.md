## Goal (the gestalt)
Open ANY route on `:5199` and you read the SAME confident page idiom: a LARGE audacious display title sitting over a live procedural field, a quiet mono eyebrow above it carrying the route's explicit import subpath in Fira Code (`@mkbabb/glass-ui/aurora`), a one-line subtitle beneath, and the whole page body in exactly ONE warm-cream glass card floating over that field — never two cards, never a grid-card-inside-a-page-card, never a header buried inside the body card. Scroll down and the hero title smoothly SHRINKS (a buttery compositor scale, no reflow) into a slim sticky page-header that holds title + subpath, the way iOS-27 collapses a large-title nav bar — the body slides up under it. Every page is the same recognizable shape; only the title, the subpath, the per-category icon, and the procedural field differ. The "double card on a grid" mess and the three-competing-header-idioms are gone — one chassis, every page.

## Starting state (measured, file:line)
The chassis architecture EXISTS (the `StoryPage` → `StoryHero` → `StoryHeader` 3-file stack) but is under-applied and carries three structural gaps (route-census.md §0-1, awwwards-herostudios.md §6-7, deferral/herostudios.md):

- **NO scroll-to-shrink anywhere.** `demo/stories/StoryHero.vue`, `demo/stories/story-hero.css`, `demo/stories/StoryPage.vue` carry NO scroll-timeline / `position: sticky` hero / scroll-handler. The hero `<h1>` entrance is a one-shot mount fade-rise ONLY (`story-hero.css:191-204` `@keyframes story-hero-title-rise`). Live-measured: the homepage has exactly ONE sticky element (the nav, NOT the hero) (route-census.md §0 gap 1). The user's headline bar ("SHRINKS as you scroll") is **0% implemented at the page level**.
- **The hero `<h1>` is hardcoded `text-display-3` (~67.78px peak).** `StoryHero.vue:292` AND `:333` both render `class="story-hero-title story-hero-title--enter text-display-3"`. The √φ ladder peaks at `--type-display-audacious` (352px, `scale.css:146-149`) but the chassis caps every hero at display-3. (The audacious-tier lift is `BC.W-HERO-AUDACIOUS`'s primary scope; this wave adds the `heroScale` PROP MECHANISM it threads.)
- **THREE competing header idioms** (route-census.md §1): A = audacious chassis hero (12 `hero:true` rows), B = hand-rolled `border-l-[3px]` IconChip header INSIDE the body (41 SFCs — a literal double-descriptor, e.g. `forms/inputs.vue:23-41`), C = plain 32.9px `text-title` chrome `<h1>` (~60 routes). No single recognizable page shape.
- **The subpath is NOT explicit.** The eyebrow is `"{Category} · {Story}"` (`StoryPage.vue:26-30`, e.g. "Forms · Inputs"), NEVER the import subpath. The `Story` interface (`manifest.ts:34-53`) has NO `subpath` field. The user's "subpath explicitly defined" bar (USER-DEFECTS §E) is unmet.
- **The double-card-on-grid persists.** When a page declares `background:"grid"` the grid SHOULD be the full-bleed page wash (`story-hero.css:283-296` `.story-bg-grid` reads through the card), but some content pages render a `bg-card` grid-card INSIDE the page card (USER-DEFECTS §C). - **4 SFCs BYPASS the chassis** (route-census.md §6): `substrates/aurora.vue` hand-rolls `<header>` with a `<span class="text-display-3">Aurora</span>` (NOT a semantic `<h1>` — an a11y defect, live-confirmed) + does NOT import `StoryPage`.
- **What is already correct (KEEP, do not re-author):** the `StoryHeader` 3-stage GRAVITY entrance + reading order (eyebrow→title→blurb, `StoryHeader.vue:53-86`, BB.W-HIERARCHY2 — correct); the ONE-card-over-field architecture (`StoryHero.vue:212-216` `cardTier`); the `cardTier` drop to `wash`/`quiet` over a live field (`StoryHero.vue:212-216`); the full-bleed escape for live-substrate heroes (`StoryHero.vue:197`).

## Target spec (grounded)
The chassis is REFIT, not re-invented (the architecture exists; the gaps are scroll-shrink + the subpath chip + the heroScale prop + the standardization sweep). FIVE moves, all demo-private (zero `src/` paint — these are the demo chassis SFCs + `story-hero.css`):

1. **The scroll-shrink hero lane (the CSS-native SOTA — no JS, no Lenis/GSAP).** Add a `.story-hero-shrink` register to `story-hero.css` (awwwards-herostudios.md §3 recipe; the binding fence is no-Lenis/GSAP — CLAUDE.md §BB.W-SCROLL-MOTION):
   - The hero cluster wrapper is `position: sticky; top: 0` over an `animation-timeline: scroll()` (the `<main>` route-scroller timeline, the `--card-scroll` `<ScrollCardHeader>` precedent generalized — CLAUDE.md §BB.W-SCROLL-CARD).
   - `@keyframes story-hero-shrink` scales the title `transform: scale(1 → 0.45)` (the display-mega→heading-equivalent ratio; COMPOSITOR-ONLY — `font-size→scale`, the text lays out ONCE, the BB.W-CARD-COMPOSITE / `proof:no-layout-animation` floor), `transform-origin: left top` (the title shrinks toward the leading edge → the slim sticky header), coupled `opacity`/`translateY` on the eyebrow+blurb (they fade + lift away, leaving title + subpath).
   - `animation-range: 0 240px` (the shrink completes within the first ~240px of scroll, awwwards-herostudios.md §3) + `animation-fill-mode: forwards` (HOLDS the shrunk state).
   - `@supports (animation-timeline: scroll())` gates it (progressive enhancement — non-supporting engines paint the static large hero, the correct fallback; Baseline: scroll-driven animations shipped Chrome 115+ / Safari 26+ — apple-ios27.md, MDN scroll-timeline cited awwwards-herostudios.md §3 sources). PRM → drop the shrink, hold the large static hero (vestibular floor, the `@media (prefers-reduced-motion: no-preference)` outer-gate the `story-hero-title-rise` keyframe already sits behind, `story-hero.css:191`).
   - The shrunk hero becomes a slim sticky page-header (title scaled + subpath chip) — the herostudios persistent-feel + the iOS-27 large-title-collapse.
2. **The `heroScale` prop on the chassis (the audacious-tier MECHANISM, consumed by `BC.W-HERO-AUDACIOUS`).** Add `heroScale?: "audacious" | "mega" | "hero" | "5" | "4" | "3"` to `StoryHero.vue` (threaded `StoryPage`→`StoryHero` + a `manifest.ts` `Story.heroScale?` field). Replace the hardcoded `text-display-3` at `StoryHero.vue:292,333` with a `computed` class `text-display-${heroScale}` (mega/hero/5 map to `text-display-mega`/`-hero`/`-5`). Default per-variant: front-door=`mega`, marquee-substrate=`hero`|`5`, content-hero=`4`. This wave ships the MECHANISM + the default-`3` byte-identical-to-HEAD path (the canary); `BC.W-HERO-AUDACIOUS` sets the per-category tiers.
3. **The explicit subpath chip (the "subpath explicitly defined" bar; couples `BC.W-CODE-BLOCKS`).** Add `Story.subpath?: string` to `manifest.ts:34-53` (e.g. `"@mkbabb/glass-ui/aurora"`, `"@mkbabb/glass-ui/dock"`; foundations/motion/compositions routes carry the route path `/substrates/aurora` where no import subpath fits). `StoryHeader` renders it as a Fira-Code code-chip (`<code class="fira-code">`, the canonical code rung — `typography/utilities.css:81`) in the eyebrow cluster, beneath the mono eyebrow. The chip persists into the shrunk sticky header (it is the route identity). The `subpath` is resolved from `current.value.story.subpath` in `StoryPage.vue` and passed to `StoryHero`→`StoryHeader`.
4. **ONE glass card, never two (the double-card kill).** Enforce the architecture: the page body sits in exactly ONE `<Card>` (`StoryHero.vue:303-339`) over the per-category procedural substrate; NO nested grid-card-over-card. When a page declares `background:"grid"`, the grid is the full-bleed page wash (`.story-bg-grid` reads THROUGH the single card — already the mechanism); the page body NEVER renders its own second `bg-card` grid-card. The audit sweep: the per-route SFCs that hand-roll a `bg-card`/grid-card inside the body (`display/card.vue`'s embedded `<Aurora>` at `:128`, the idiom-B `border-l-[3px]` second headers) collapse onto the ONE chassis card. (The 41 idiom-B headers fold their IconChip identity into the chassis hero icon — `BC.W-HERO-AUDACIOUS` Part C / `BC.W-PAGE-HIERARCHY`; this wave owns the ONE-card enforcement + the gate.)
5. **Route the 4 chassis-bypassers through the chassis.** `substrates/aurora.vue` (and the 3 others) import `StoryPage`; the hand-rolled `<header>`/`<span class="text-display-3">` is deleted; the title becomes the chassis semantic `<h1>` at `heroScale` (route-census.md §4 — the a11y `<span>`→`<h1>` fix). The aurora configurator placement (controls-on-the-right) is `BC.W-CONFIG-RIGHT`'s; this wave makes aurora a chassis page so the hero shrinks + the subpath shows.

The KISS architecture: ONE chassis stack (`StoryPage`/`StoryHero`/`StoryHeader` + `story-hero.css`), ONE scroll register (`.story-hero-shrink`, sticky+`scroll()`, compositor-only), ONE subpath source (`manifest.ts:Story.subpath`), ONE card. - **hero title** = the `manifest.ts` `Story.title` (the displayed `<h1>` text). NEVER re-authored per-SFC.

- **subpath** = the explicit Fira-Code eyebrow chip. The `s()` factory cannot infer this (title≠subpath, e.g. "GooBlob"→`/goo-blob`), so the subpath is an EXPLICIT per-row field, defaulted from this table.
- **bg** = the resolved procedural background — the `Story.background` if explicit, else the `CATEGORY_DEFAULT_BG` inherit (W-STAGE map: foundations·display·feedback→`paper`, substrates·navigation→`aurora`, forms·containers·dock·data·compositions→`grid`, motion→`constellation`). - **scroll-shrink** = YES on EVERY row by construction (the `.story-hero-shrink` register is the chassis default; no per-route opt-out). The column is listed to make "EVERY PAGE shrinks on scroll" literal.
- **ONE-card body** = the chassis `<Card>` (KEEP). The column flags the routes that TODAY hand-roll a second `bg-card`/grid-card inside the body (the PC3 collapse targets) vs the routes already clean.
- **section delimiter** = the body-section delimiting register (`BC.W-PAGE-HIERARCHY` owns the rule; the column names the per-page delimiter MODE — `hr` (the `<Separator>` hairline between named sections) vs `cards` (each section in its own sub-`<Card>`) — so the two waves agree per-route).

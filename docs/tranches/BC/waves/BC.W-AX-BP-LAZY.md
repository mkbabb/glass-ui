## Goal (the gestalt)
A consumer imports `@mkbabb/glass-ui/border-progress`, binds `<BorderProgress :value>` on its hot first-paint card, and the `dist/border-progress.js` chunk it pulls is value.js-FREE — the OKLCH/shorter-hue spectrum walk (the only value.js consumer in the leaf) loads on demand, the first time a consumer passes CONCRETE color anchors (a `#hex`/`oklch(…)` stops set) that actually need the perceptual walk. The library DEFAULT spectrum is pure `var(--section-color-*)` tokens — they pass through the cascade and never touch value.js at all — so the default `<BorderProgress>` (and every consumer riding the brand ramp) carries ZERO value.js weight on its critical path. The public API is byte-identical: `<BorderProgress>` renders the same ring, `spectrumStops()` stays a synchronous export with the same signature, the `var()` pass-through is unchanged. The only delta is WHERE the value.js code lands in the bundle graph — behind a dynamic boundary, off the eager first-paint walk.

## Target spec (grounded)
The spectrum walk's value.js-bearing path moves behind a dynamic `import()` boundary; the synchronous public surface (the `var()` pass-through + the `spectrumStops()` signature) is preserved.

### T1 — `spectrumStops` stays a SYNCHRONOUS export; the value.js branch is the dynamic-load path
`spectrumStops(stops, samples?)` keeps its signature + sync return — it MUST stay sync (the SFC calls it inside a `computed`, and a consumer may call it synchronously). The split is by RAMP KIND:
- **The `var()` / default ramp (the hot path) — fully synchronous, value.js-FREE.** A ramp containing any `var(` (the library default + every brand-ramp consumer) returns `[...stops]` synchronously, never importing value.js (the existing `:76` short-circuit — KEPT, now the value.js-free fast path with NO static value.js edge above it).
- **The CONCRETE-anchor walk (the cold path) — the dynamic boundary.** When a consumer passes concrete `#hex`/`oklch(…)` anchors, the OKLCH walk is the value.js-bearing work. `spectrumStops` returns the SYNCHRONOUS interim — the raw stops passed through as evenly-spaced gradient stops (a correct, if un-perceptual, banded ramp) — AND kicks off a `import("./spectrum-walk")` (the value.js-bearing module) whose resolution re-computes the perceptual walk and updates the reactive output. The SFC's `spectrum` computed reads a `ref` the dynamic-load resolution writes (the load-once-then-cache pattern): first render shows the synchronous pass-through ramp, the next tick (after the dynamic chunk resolves) shows the perceptual OKLCH walk. A concrete-anchor consumer is the RARE case (presets-in-consumers — most consumers ride the brand `var()` ramp); the one-tick upgrade to the perceptual ramp is imperceptible on a determinate progress surface.

### T2 — the value.js-bearing math moves to a SEPARATE dynamically-imported module
A NEW `src/components/custom/border-progress/composables/spectrum-walk.ts` carries the value.js-bearing body: the `interpolateHue` import, the `cssToOklch`/`oklchStopToHex` `/color`-leaf import, `spectrumAt`, and the concrete-anchor sampling loop (`useBorderSpectrum.ts:30-58,81-86`). `useBorderSpectrum.ts` retains ONLY the sync `spectrumStops` shell (the `var()` short-circuit + the synchronous-interim pass-through + the `import("./spectrum-walk")` boundary + the cache) — and carries ZERO top-level value.js / `/color` import. So `useBorderSpectrum.ts`'s static graph is value.js-free; `spectrum-walk.ts` is the dynamic leaf.

### T3 — the SFC wires the load-once reactive seam
`BorderProgress.vue`'s `spectrum` computed (`:88-90`) becomes a `spectrum` REF the `spectrumStops`-with-callback writes (or `spectrumStops` returns `{ sync, ready }` where `ready` is a Promise the SFC awaits to swap in the perceptual ramp). The DEFAULT/`var()` case resolves the ref synchronously at construction (no dynamic load, no flash). The concrete-anchor case shows the synchronous interim first, swaps to the perceptual walk when the dynamic chunk resolves. The conic-gradient `--border-progress-spectrum` reads the ref — byte-identical paint for the default ramp.

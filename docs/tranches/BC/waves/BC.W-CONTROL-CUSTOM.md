## Goal (the gestalt)
The input register (Input, Switch, Textarea, NumberField + the form wells) gains the SAME size-customization surface Button has had since AX.W51: a `size?: "sm" | "default" | "lg"` prop selecting the `--control-h-*` height rung + the `--control-text`/`--control-text-sm` font rung — the EXACT cohort Button/Badge/NumberField already read. A bare `<Input>` reads as the canonical golden pill (the `--control-h-md` height, the `--control-text` font); a `<Input size="lg">` beside a `<Input size="sm">` lets a consumer express primary-vs-secondary control hierarchy from a prop, golden-by-construction. AND the control type register reads `--control-text`, NOT a bare `text-sm` literal, so a consumer retunes the whole form family's type from ONE `:root { --control-text: … }` override. Switch — hardcoded `h-6 w-11` at HEAD with NO size axis — gains the axis (track height/width from the cohort). The user's "fully customizable with golden defaults that afford hierarchy" bar, met on the input register by THREADING the existing register — zero new register, no over-prop.

## Starting state (measured, file:line)
The `--control-*` cohort EXISTS (`tokens/sizing.css:64-93`): `--control-h-{xs:1.75rem, sm:2.25rem, md:2.5rem, lg:2.75rem}` (each `max(calc(rem * --ui-scale), --control-floor)`, the WCAG-44px coarse clamp), `--control-text` (`calc(--type-small * --ui-scale)`), `--control-text-sm` (`calc(--type-caption * --ui-scale)`), `--ui-glyph`/`--ui-glyph-sm`. Button reads all of it (`button/index.ts:101-116`: `h-(--control-h-md)`/`-xs`/`-sm`/`-lg` + `text-[length:var(--control-text)]` + `size-(--ui-glyph)`); Badge + NumberField read it too. The input register does NOT expose it:

- **Input (`input/Input.vue:81`)** — `'input-pill [--control-surface-bg:var(--input-on-glass)] text-sm file:border-0 file:bg-transparent file:text-sm file:font-medium'`. NO size/tier axis (one fixed height). The bare `text-sm` is the C1 forbidden literal. NUANCE: the `.input-pill` recipe (`glass/surfaces.css:282-321`) already pins `height: var(--control-h-md)` + `font-size: var(--control-text)`, so the bare `text-sm` is INERT for the input's own font (the recipe wins by source-order specificity over the utility) — but it is still a forbidden literal the gate flags, AND the `file:text-sm` modifier-scoped one IS the real consumer (the file-upload pseudo-element register). To add a size AXIS, the height/font must override `--control-h-md`/`--control-text` AT THE ELEMENT per the chosen rung (the `.input-pill` recipe reads them, so a per-element `[--control-h-md:var(--control-h-sm)]` re-point or a more honest `[--control-pill-h:var(--control-h-sm)]` rung indirection retunes it).
- **Switch (`switch/Switch.vue:37`)** — `'glass-wash glass-specular-track focus-ring … h-6 w-11 … rounded-pill border-2 …'` + the thumb `'block h-5 w-5 … bg-background ring-0 data-[state=checked]:translate-x-5'`. The `h-6 w-11` track + `h-5 w-5` thumb + `translate-x-5` throw are HARDCODED, NO size axis. (The thumb `bg-background` is `BC.W-DESHADCN`'s reskin, NOT this wave's.)
- **Textarea (`textarea/Textarea.vue:73`)** — `'input-pill [--control-surface-bg:var(--input-on-glass)] rounded-field py-2 text-sm'`. Reads `.input-pill` (good — the `--control-h-md`/`--control-text` recipe) BUT pins to ONE size, and the bare `text-sm` is the C1 literal (here it overrides the recipe `font-size` because `text-sm` is `0.875rem` static while `--control-text` is the scaled register — a real desync under `--ui-scale`).
- **NumberFieldInput (`number-field/NumberFieldInput.vue`)** — reads `--control-h-md` only (PARTIAL — pinned to one size, `text-sm` hardcoded per the research).

The size union shape Button uses is `'sm' | 'default' | 'lg'` (plus `xs`/`icon`/`icon-sm` icon-only rungs Button-specific). The input register wants the THREE meaningful control rungs (`sm`/`default`/`lg`); the `xs`/icon rungs are Button-specific (an input has no icon-only register).

## Target spec (grounded)
1. **The shared control-size union, published.** `export type ControlSize = "sm" | "default" | "lg"` on `_shared/` (beside `useSurfaceAxis.ts` — the form-family shared home) + re-exported on `src/api/index.ts` (the discovery layer, beside `ButtonVariants`). A `size?: ControlSize` prop on Input/Switch/Textarea/NumberFieldInput, default `"default"` (byte-near-identical to HEAD — `--control-h-md` + `--control-text`).
2. **The size rung selects the cohort token (token-beats-prop).** The prop maps to the height + font rung via an element-level token re-point (NOT a per-size class explosion): `size="sm"` → the `--control-h-sm` + `--control-text-sm` rung; `size="default"` → `--control-h-md` + `--control-text`; `size="lg"` → `--control-h-lg` + `--control-text` (the lg rung keeps the workhorse font; only the height grows — matching Button's lg, which is `h-(--control-h-lg)` with the base `--control-text`). The magnitudes STAY the `--control-*` tokens; only the RUNG choice is a prop (the DON'T-over-prop fence — a consumer still retunes the absolute height/font from `:root`). The cleanest mechanism: a tiny `controlSizeClass(size)` helper returning the element-level token-override class string (e.g. `size="sm"` → `[--control-pill-h:var(--control-h-sm)] [--control-pill-text:var(--control-text-sm)]`), with `.input-pill` reading `--control-pill-h`/`--control-pill-text` (defaulting to `--control-h-md`/`--control-text` so the bare default is byte-identical). One indirection rung, no recipe fork.
3. **The control type register reads `--control-text`, not bare `text-sm`.** Input/Textarea drop the unscoped bare `text-sm` (the `.input-pill` recipe already supplies `font-size: var(--control-pill-text)` after the indirection; the desync is closed). The `file:`-modifier-scoped `file:text-sm` is KEPT or re-pointed to `file:text-(length:--control-text-sm)` (the file-upload sub-element register, a distinct C1-clause-exempt modifier scope — see Fences).
4. **Switch gains the size axis off the cohort.** The track `h-6 w-11` → a size-derived height/width pair, the thumb `h-5 w-5` + `translate-x-5` throw scale with it (the thumb is `height − 2*track-pad`, the throw is `track-w − thumb-w − 2*pad` — derived, not three magic literals per size). A `--switch-track-h`/`--switch-track-w`/`--switch-thumb`/`--switch-throw` token quad keyed off the chosen `--control-h-*` rung (a Switch is a special control-height geometry, so it derives its track/thumb from the rung, not the bare cohort — the no-contrivance line: Switch's geometry IS control-height-derived). Default `size="default"` resolves the HEAD `h-6 w-11`/`h-5 w-5`/`translate-x-5` exactly (byte-identical).
5. **Golden default affords hierarchy.** A bare control reads as the canonical pill; `size="lg"`/`size="sm"` express primary-vs-secondary control hierarchy out of the box; a `:root { --control-text: … }` / `:root { --control-h-md: … }` override cascades into every form control (the token-first axis). Published on `api/index.ts` as the shared `ControlSize` union.

The architecture: ZERO new size/font register — the `--control-*` cohort is the source (Button reads it, this threads it). The ONE indirection minted is the `--control-pill-h`/`--control-pill-text` element-override seam (defaulting to the cohort so the bare default is byte-identical) — the SAME substitution-vs-redeclaration discipline `--glass-bg-dock`/`--dock-scale` already teach.

## Fences / invariants (must NOT regress)
- **DON'T over-prop — only the RUNG is a prop.** The absolute height/font MAGNITUDES stay the `--control-h-*`/`--control-text` tokens; the `size` prop selects WHICH rung, it does not encode a magnitude. A consumer still retunes the absolute control size from `:root` (the token-first axis). A wave that added a `height`/`fontSize` prop instead of the rung-token indirection is the anti-pattern.
- **DRY — ZERO new size/font register.** The `--control-h-*`/`--control-text` cohort is the source (Button reads it). The ONLY indirection minted is the `--control-pill-h`/`--control-pill-text` element-override seam (defaulting to the cohort) + the Switch `--switch-*` geometry quad (derived from the rung). No parallel `--input-h-*` ladder; no per-size recipe class explosion.
- **The bare default is byte-identical.** `size="default"` resolves `--control-h-md` + `--control-text` + (Switch) `h-6 w-11`/`h-5 w-5`/`translate-x-5` EXACTLY — a bare `<Input>`/`<Switch>` at HEAD is pixel-unchanged. The additive axis owes no MIGRATION row.
- **The `file:`/`placeholder:`/`[&_…]:`-modifier-scoped literal is a distinct sub-element register, exempt from C1.** Input's `file:text-sm` styles the file-upload pseudo-element, NOT the input's type register. The gate flags the BARE unscoped `text-sm` on the control root; a modifier-scoped one is the file/placeholder sub-element. Keep or re-point it to a token; do NOT delete the file-upload register.
- **The Switch thumb `bg-background` reskin is `BC.W-DESHADCN`'s, not this wave's.** This wave threads the Switch SIZE axis (track/thumb geometry from the cohort); the thumb's MATERIAL (`bg-background` → the warm glass/paper thumb register) is the de-shadcn paint fix. The two assert different facts on `Switch.vue` and never contradict.
- **The `.input-pill` recipe MECHANISM is untouched** — only the `height`/`font-size` values gain the `var(--control-pill-h, …)` indirection wrapper (byte-identical at unset). The `--control-surface-*` REST register (BA.W-SURFACE-AXIS scope 7), the focus/invalid rings, the blur — all unchanged. No second well recipe.
- **`--ui-scale` lockstep preserved.** The cohort tokens already ride `--ui-scale` (the comfort axis); the size axis selects a rung WITHIN that scale, it does not multiply by `--ui-scale` a second time (the no-double-vw discipline `tokens/sizing.css:76-84` records). A `size="lg"` under coarse-pointer is `--control-h-lg` (already `* --ui-scale`), not `* --ui-scale` again.
- **No contrivance — the size axis is the input register ONLY.** Input/Switch/Textarea/NumberField get the `size` axis (control-size hierarchy is real). Checkbox/Radio (16px fixed atoms), Label, Separator do NOT (no size hierarchy — the census records them `token-only-correct`). A speculative `size` on a 16px checkbox would be over-prop.

## Goal (the gestalt)
A calm, crisp, evenly-ruled engineering-graph-paper page background — the foil to glass, the brand math/grid pillar — done with restraint. A fine 1rem rule + a bolder 5rem major rule, every line a hairline-crisp single device-pixel at any DPR, on a uniform LARGER rhythm. It is the WHOLE-PAGE wash behind the content, NOT a layer trapped inside a rounded card and NOT blurred through a glass plate. It re-tints with the theme (warm-ink on light, lifting off near-black on dark) by construction. It is the keyframes.js `EditorShell` look — byte-faithful: the user looks at it and reads "a simple, clean graph-paper page," never "a blurry oddly-spaced grid clipped inside a card." It is static — it does not animate (the liquid breathe is the `BC.W-VIZ-PAPERGRID` sibling's job).

## Starting state (measured, file:line)
The "blurry mess" is THREE concrete mechanisms, all measurable (research/viz/grid-simple.md §0, §2):

- **Mechanism A — the grid is CLIPPED INSIDE the rounded card (the "in card" / "WTF clipped" defect).** The demo grid `<div class="story-hero-bg story-bg-grid">` is mounted at `StoryHero.vue:256-260` as a child of `.story-hero`, which declares `position: relative; isolation: isolate; overflow: hidden; border-radius: var(--radius-card)` (`story-hero.css:50-56`); the grid sits at `z-index: -10` (`story-hero.css:69-73`, `.story-hero-bg`). So the grid is a `-z` layer TRAPPED inside the rounded, clipped, isolating card box — to the user it reads as a grid INSIDE a rounded card, not as a page background. The full-bleed escape (`.story-hero-bg--bleed` → `position: fixed; inset: 0; z-index: -5`, `story-hero.css:79-85`) is granted ONLY to LIVE substrates (`StoryHero.vue:198` `fullBleed = isHero && liveBackdrop`) — the STATIC `grid`/`paper` kinds (`StoryHero.vue:201` `staticBackdrop`) are left BOXED.
- **Mechanism B — the grid is BLURRED through the glass plate (the "blurry mess").** Over a declared `grid`/`paper` backdrop the card drops to the `wash`/`quiet` glass tier so the grid "reads through" (`StoryHero.vue:211-216` `cardTier` → `quiet` hero / `wash` page). Those tiers carry `backdrop-filter: blur(--glass-blur-{wash,quiet})` (the W-GLASS-CAL calm ladder, quiet 8px); a `backdrop-filter: blur()` CONVOLVES whatever is behind the plate, so the crisp 1px grid lines reading through the card are Gaussian-blurred into soft fuzz. The grid is literally being blurred by design (to "read through") — the user's "blurry mess."
- **Mechanism C — "oddly spaced."** The demo pitch is 28px (`--story-grid-size: 28px`, `story-hero.css:14`); the library is 32px (`--paper-grid-texture-size: 32px`, `scale-paper.css:118`) — two drifting copies, neither rem-relative, neither matching the kf clean 1rem/5rem (16px/80px) rhythm. The 4×-major step (28→112px, 32→128px) is a non-round multiple of the body rhythm; at fractional-DPR zoom the integer-px sizes land on sub-pixel boundaries → the anti-aliaser softens the 1px lines. `background-position: center center` (`story-hero.css:295`) offsets the tile by a half-cell on odd-pixel viewports → the lines drift OFF the device-pixel grid → further softening.
- **The two parallel static-grid systems (both reconciled here).** The DEMO story grid (`.story-bg-grid` + `--story-grid-*`, `story-hero.css:14-16,283-296`) is THIS wave's primary scope (the "new grid background" the user condemns). The LIBRARY card grid (`.paper-grid` + `--paper-grid-*`, `cards.css:52-63`, `scale-paper.css:118-134`, consumed by `math-paper.vue:21`) is the card-interior register — its 28px-vs-32px drift unifies onto ONE rhythm here, and the card-interior PAINT is abrogated (it is the "displayed in the card" defect for the static document register). The optionally-LIQUID card-interior register is `BC.W-VIZ-PAPERGRID`'s scope; the two share ONE rhythm (research/viz/grid-simple.md §2.1, §5.1).

### 1 — The token rhythm (the SINGLE source, re-pointed to share with paper-grid)
The keyframes.js engineering-graph-paper magnitudes, re-expressed as glass-ui `--grid-*` tokens (research/viz/grid-simple.md §1.2, §5.1):
```css
:root {
    --grid-pitch:  1rem;   /* fine cell — rem-relative, divides cleanly at DPR 1/2/3 */
    --grid-major:  5rem;   /* major rule — 5× the fine pitch (the engineering-graph rhythm) */
    --grid-line:        color-mix(in srgb, var(--foreground) 3%,  transparent);
    --grid-line-major:  color-mix(in srgb, var(--foreground) 11%, transparent);
}
```
- 1rem (=16px at the default root) and 5rem (=80px) divide cleanly at DPR 1, 2, 3 — the device-pixel-crisp rule (research/viz/grid-simple.md §3.1; n12v *CSS, Retina, and Physical Pixels*). For the user's "LARGER" a consumer can dial `--grid-pitch: 1.25rem` (20px) / `--grid-major: 6.25rem` (100px) at `:root`; the DEFAULT is the kf 1rem/5rem (the binding reference reproduction).
- The 3% fine / 11% major strengths are the kf calibration — the major "DELIBERATELY held STRICTLY ABOVE the 10% legibility floor" (`design-idioms.css:285-290`), the fine "dropped to 3% … the user's 'less busy substrate'" (research/viz/grid-simple.md §1.2).
- The dark arm re-tints FOR FREE — `--foreground` flips dark→light, the `color-mix` re-resolves; NO parallel `--grid-*-dark` family (the `cards.css:65-76` precedent; research/viz/grid-simple.md §5.1). The blend may flip `multiply` → `screen` on a tinted host for legibility (the `cards.css:73-76` arm), but on a transparent full-bleed page-bg the plain mix reads.
- The demo `--story-grid-*` (`story-hero.css:14-16`) and the library `--paper-grid-*` (`scale-paper.css:118-134`) BOTH re-point onto `--grid-*` — ONE pitch/strength source, not two drifting copies (the two-parallel-systems fix, research/viz/grid-simple.md §2.1, §5.1).

### 2 — The crisp grid recipe (the four hard-stop lines, `0 0` aligned, NO filter)
```css
.grid-bg {                       /* the full-bleed page grid (NOT a card interior) */
    background-color: var(--background);
    background-image:
        /* major rule first — x + y, hard-stop, the bolder tier (drawn UNDER the fine so it dominates intersections) */
        repeating-linear-gradient(to right,  var(--grid-line-major) 0 1px, transparent 1px var(--grid-major)),
        repeating-linear-gradient(to bottom, var(--grid-line-major) 0 1px, transparent 1px var(--grid-major)),
        /* fine rule — x + y, hard-stop, the quiet tier */
        repeating-linear-gradient(to right,  var(--grid-line) 0 1px, transparent 1px var(--grid-pitch)),
        repeating-linear-gradient(to bottom, var(--grid-line) 0 1px, transparent 1px var(--grid-pitch));
    background-position: 0 0;    /* pixel-aligned to the box origin — NOT center center */
    /* NO filter, NO backdrop-filter, NO opacity layer, NO transform — one static raster */
}
```
The hard color stops (`var(--line) 0 1px, transparent 1px …`) are a sharp transparent↔ink edge, NOT a soft gradient ramp (a ramp is what blurs a gradient grid; research/viz/grid-simple.md §3.1, §3.3). The `repeating-linear-gradient` form keeps the pitch in ONE place (the gradient) — marginally cleaner than the equivalent four-`linear-gradient` + `background-size` stack (identical output; research/viz/grid-simple.md §3.3). `background-position: 0 0` (not `center center`) pins the tile to the box origin so every line lands on a device-pixel boundary (the alignment fix). NO filter / NO opacity layer / NO transform — one compositor-cached static raster (the `cards.css:46-48` paint-path discipline; research/viz/grid-simple.md §3.1).

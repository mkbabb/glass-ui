## Goal (the gestalt)
EVERY interactive element in glass-ui answers the pointer the same liquid way. Hover a button and it lifts a hair, its glass gleam wakes and follows your cursor, the surface brightens a touch — three coupled legs, one motion. Press it and it squishes on the iOS press spring with a coupled brightness bump, the gleam illuminating under the touch-point. Hover a menu row, a tab, a dock control, a card — the SAME register answers, scaled to the element's weight. Grab a draggable thing and it follows ~1:1 with a gel-squish; release and it flings to its slot. Nothing is dead — no element sits inert under the cursor, no affordance is a fast-color-snap-then-slow-spring desync, no control lags. The user reads the whole surface as ALIVE and COHERENT (the iOS-27 "the interface responds to me as one material") because every element composes the SAME small set of affordance primitives — hover-lift + gleam-track + press-squish + (where it earns it) drag-morph — off the SAME eased springs. This wave is the BRAINSTORM made into a binding per-element MAP + a gate that reds an interactive element shipped inert.

## Target spec (grounded)
KISS — the affordance primitives are built; this wave BRAINSTORMS the full set, MAPS each interactive element class to its required affordance(s), and GATES that the map holds (no inert element, no desynced affordance). It composes the existing primitives — it mints NO new affordance engine.

### The brainstorm — the affordance vocabulary (the small closed set)
Every interactive element draws from ONE of five affordance primitives, all on the eased springs (`BC.W-SPRING-EASE`), all compositor-only (`proof:no-layout-animation`), all PRM-carved (P6). Each is ONE delivery (the closed vocabulary — a sixth would need its own wave). The brainstorm names, for each, the CUE (what the user reads), the TOKEN/PRIMITIVE that delivers it (file:line), the MOTION register it rides, and the PRM behavior:

1. **HOVER-LIFT** — *"this is touchable."* A sub-perceptual scale lift (`--scale-hover-btn` 1.05 / `--scale-hover-dock` 1.1 / `--scale-hover` 1.08, `scale-paper.css:9,24,25`) on `--spring-smooth`, the surface bg shifting to the next glass tier, the gleam waking — the 3 legs as ONE motion (`scale-paper.css:18-22`; the `transition-control` utility `btn.css:55` carries border/shadow/transform/color TOGETHER so they co-time). PRM: the scale/translate drops, the bg/color leg keeps (P6 — the surface still answers, the geometry holds still).
2. **GLEAM-TRACK** — *"the light bends toward my finger"* (apple-ios27.md §1.2 specular). The specular catch-light following the pointer: ONE position-write source `createSpecularWriter` (`useSpecularTracking.ts:64`) delivered as the `v-specular` directive (`vSpecular.ts`, zero-wiring tier-root auto-arm) or `useSpecularPointer` (the angle-adding leaf for the rim glint, `useSpecularPointer.ts:36`). It writes `--specular-x`/`--specular-y`/`--specular-intensity`/`--specular-angle` (the `@property`-registered drives, `property-regs.css:91,97,103,116`) into the `.glass-material::before` core (`--glass-specular-core`/`--glass-specular-size` 36%, `material.css:134,148`). The position-tracked leg rides `--ease-standard` (motion-canon.md §6 "Position-tracked → --ease-standard"). PRM: the gleam snaps to the cached PRM-rest (no live tracking) — the `createSpecularWriter` cached-PRM gate.
3. **PRESS-SQUISH** — *"I activated it"* + touch-illumination (apple-ios27.md §2.5). The iOS interruptible coupled spring-press: `--scale-press` 0.96 (`scale-paper.css:26`; the `--scale-press-btn`/`--scale-press-dock`/`--scale-press-sm` rungs `scale-paper.css:39,40,41`) on the `press` register (response 0.15 / ζ 0.86, minted by `BC.W-SPRING-EASE`, the `--spring-press`/`MOTION_CURVES.press` twin), the coupled `--*-press-t` brightness/gleam-illumination leg on the SAME spring scalar (P3 — `--glass-btn-press-t` `property-regs.css:285`, `--card-press-t`), velocity-continuous re-seat on rapid re-press (`useSpringPress.ts:62` → `useLiquidPress.ts:122` → the `useLiquidFlex` reciprocal X/Y squish `useLiquidFlex.ts:135`, `squishLaw:"linear"` capped LOW). The CSS `.tap-squish:active`/`.glass-press` is the no-JS floor. PRM: `SpringProgress.respectReducedMotion` snaps the value (the gesture confirms, the physics off — zero in-between transform frames).
4. **DRAG-MORPH** — *grab → follow ~1:1 → gel-squish → fling-to-nearest* (`useDragMorph.ts:153` — kf `Draggable` + `SpringProgress`(snappy 0.35/0.65) + `useLiquidFlex` `squishLaw:"tanh"` capped ≤`--tab-indicator-max-stretch` + `decayRest`-projected nearest-snap), for elements that EARN a pull (the tab pill `:draggable`, the DockLayerGroup rail pull-to-switch, the Slider track, the SortableHandle reorder). NOT every element (the proportion fence — motion-canon.md "morph the meaningful transition, never everywhere-jitter"). PRM: the gesture STILL functions (the drag follows, the snap commits) but the squish is OFF (`--stretch` stays 1) and the release is an instant nearest-snap.
5. **FOCUS-RING** — *the keyboard-reachable cue,* the non-motion a11y affordance distinct from hover. The `.focus-ring` utility keyed off `--focus-ring-shadow` (CLAUDE.md "the .focus-ring CSS utility over inline focus-visible"; consumed at `dock.css:137`, `dark-mode-toggle.css:39`, every interactive atom CVA base). EVERY interactive element carries it (keyboard parity — a pointer-only affordance with no keyboard reach is the a11y gap A2 reds). NOT a motion register (it does not ride a spring); it is the always-present a11y floor beside the 4 motion affordances.

**The sixth register is OUT of this set by design (the reveal-surface bloom).** The top-layer reveal surfaces (Tooltip/Popover/Dialog/Drawer/HoverCard/menu content) carry the `.glass-reveal` SURFACE-BLOOM (the iOS-27 materialize, `glass/reveal.css` + `useLiquidReveal`), which is a SURFACE that APPEARS, not an ELEMENT a pointer touches. It is recorded in the map (the reveal-surface row) so the gate does not red a Dialog for "no hover-lift," but it is NOT one of the 5 pointer affordances — it carries the bloom + focus-trap as its own floor. A SEVENTH affordance (a new pointer cue) would need its own wave (the proportion fence — the 5 is the closed set).

The map is the BINDING contract: an interactive element NOT on the map (or on it but shipping inert in a cell the map marks `✓`) reds the gate. A `—` cell is recorded-not-befitting (a checkbox has no gleam, a hairline does not squish) — the proportion fence; the gate does NOT demand every affordance on every element, it demands the MAPPED floor. The map lives in `docs/precepts/affordance-map.md` (the canon home — the affordance idiom), cited by every interactive-component wave.

**The reveal-surface SIXTH register (recorded, off the 5-pointer-affordance set).** The top-layer reveal surfaces (Tooltip/Popover/Dialog/Drawer/HoverCard/menu content) do NOT carry the 5 POINTER affordances — they carry the `.glass-reveal` SURFACE-BLOOM (the iOS-27 materialize: scale+fade+blur-settle on `--spring-snappy`, `transform-origin: var(--reka-popper-transform-origin)`, the `useLiquidReveal` source-rect JS refinement — `glass/reveal.css`). This is a DISTINCT register (a surface that APPEARS, not an element a pointer touches), so it is NOT counted against A2's "no inert pointer-element" floor; it carries the `.glass-reveal` recipe + the focus-trap as ITS floor. The map records it so the gate does not red a Dialog for "no hover-lift" (a Dialog does not hover — it blooms). The GAP it has IS the §F class: the trigger that opens it must answer (the trigger is on the map as a Button/AccordionTrigger row); the reka `data-state` open/close binding must actually fire (the π LIVE catches a dead trigger).

**The three GAP classes the map surfaces (the gate's RED at HEAD):**
- **GAP-1 (the press feel, §F lag):** the press is on the uncalibrated `useSpringPress` 0.25/0.7 — `BC.W-SPRING-EASE` re-points it onto the minted `press` 0.15/0.86 register; this wave's A1 records the assignment, SPRING-EASE lands the curve. (A3 reds a desynced hover-visual channel — a fast-color-bezier vs slow-scale-spring — the OTHER §F lag root.)
- **GAP-2 (the reka stale-binding silent-no-op, §F):** Switch/Radio/Slider/Checkbox carry the affordance CLASS (the thumb spring, the `.tap-squish`, the `data-held` reflect) but the reka binding (`:checked`/`:value`/`aria-checked`/`data-held`) can silent-no-op — invisible to vue-tsc + units (MEMORY feedback_glass_ui_binding_verification). The π LIVE-click is the ONLY catcher; A2's live arm + the π's reka-stale-binding catch close it.
- **GAP-3 (the unmapped/inert new element):** a future interactive component shipped absent from the map OR mapped-but-inert (a `✓` cell with no wired class). A1's self-test bite reds a planted unmapped `<button>`; A2 reds a mapped-but-inert cell.

### The wiring (the gaps the map surfaces)
- **No inert interactive element.** Every element class in the map carries AT LEAST hover-lift + focus-ring (the floor); the glass-variant elements carry gleam-track; the press-able elements carry press-squish on the eased register. The gate enumerates the inventory + reds an interactive element with NO affordance.
- **No desynced affordance (the §F lag fix).** The hover-visual channel (bg/border/color/shadow + scale) rides ONE register (`--spring-smooth` for surface+scale, motion-canon.md), NOT a fast-color-bezier desynced from a slow-scale-spring (the §F "laggy" read = the desync OR an inert control). The press rides the eased `press` register (`BC.W-SPRING-EASE`), NOT the uncalibrated 0.25/0.7.
- **The reka stale-binding e2e check** (MEMORY feedback_glass_ui_binding_verification): the affordance is verified LIVE (a real pointer hover/press/click in the π), not a source assert — a `:pressed`/`v-model` that silently no-ops is caught only by the e2e (the class that bit Switch/Toggle/Radio, USER-DEFECTS §F).

This is the gestalt: the affordance thinking becomes an EXPLICIT brainstorm + a BINDING per-element map + a gate that reds an inert or desynced interactive element — so "every element answers the pointer the same liquid way" is provable, not aspirational.

## Mechanism / files
- **NEW `docs/precepts/affordance-map.md`** — the brainstorm (the 5-primitive vocabulary) + the per-element MAP table + the wiring rules. The canon home cited by every interactive-component wave (the `affordance idiom`).
- **NEW `scripts/proof-affordance-map.mjs`** (`["local","ci","release"]` SOURCE arm + a LOCAL live arm) — the completeness gate: enumerates the interactive-element inventory (the components with a `role`/`@click`/`@pointerdown`/`tabindex`), cross-checks each against the map, reds an interactive element NOT mapped OR mapped-but-inert (no hover/press/focus class). The map is READ from `affordance-map.md` (gate + canon single-sourced — the `proof:precept-current` precedent).

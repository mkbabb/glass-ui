## R1 ios27-liquid-glass

> glass-ui is already unusually mature: analytic single-sourced springs + a per-spring duration clock, a genuinely SOTA adaptive-glass legibility seam (the W55 bucket + self-engage + contrast-color() flip + a sampled luma observer), useLiquidFlex's volume-preserving squish, useViewTransition, and the kf FLIP + springTimingFunction facilities sitting ready in the sibling repo. The SOTA leap is therefore about CLOSING FIVE specific gaps, not a rebuild. (1) THE BIG ONE: there is no real refraction — glass is blur+tint+rim only, no light-bending; iOS-26's signature is edge-LENSING, reproducible via a precomputed-squircle SVG feDisplacementMap (kube.io math, Chromium-gated, scale-animated, blur fallback elsewhere). (2) No liquid open/fade-in primitive — the marquee app/control-centre bloom-from-source-rect; kf flipShared+springTimingFunction make this a ~30-line useLiquidReveal composing the TRUE iOS overshoot on the compositor. (3) The spring clock isn't threaded into the entry keyframes — presses spring but reveals still ride fixed beziers; re-pointing them onto --spring-<name>+--spring-<name>-duration with coupled fade is the cheapest high-impact win. (4) The draggable PULL/morph/squish tab doesn't exist — only click-travel; the useSpringMount drag state-machine + useLiquidFlex velocity-squish + SpringProgress release-handoff are the ready template. (5) The specular is a static centered disc and the adaptive tint is binary — both want the motion-reactive edge highlight + a continuous luma ramp iOS-27 uses. All adopts honor the house fences: transform/opacity-only, PRM-safe by construction, token-first on the existing --glass-* + oklab tint seams (no new color tokens, no demo color into library), and graceful-degrade off-Chromium. CSS-reachable: useLiquidReveal, W-ENTER-SPRING, W-DRAG-TAB, the continuous luma ramp, the edge-specular sweep. WebGL/Chromium-only flourishes: the feDisplacementMap lensing + chromatic-aberration rim (the one technique that separates 'frosted glass' from 'Liquid Glass')."

- **[high] No real refraction/lensing — glass is blur+tint only; the iOS-26 signature edge-lensing is the biggest visible gap**
  - The 5-rung ladder (glass/ladder.css) composes ONLY backdrop-filter: blur()/saturate() + an oklab color-mix tint + a box-shadow rim + a low-alpha radial ::before specular (material.css L108). There is NO displacement of the backdrop. iOS-26 Liquid Glass's defining move is LENSING — it bends and concentrates light at the EDGES (real-time framebuffer sample via Metal), which on the web is reproducible via an SVG feDisplacementMap fed a precomputed normal-map (kube.io: surface height f(distFromEdge), normal = {-derivative, 1}, Snell n1=1/n2=1.5, polar magnitudes → RGBA R=128+x*127/G=128+y*127, applied as backdrop-filter:url(#filter) scale=maxDisplacement). The reflect captures confirm: the dock + cards read as flat frosted plates, not refractive glass — the rims are present (good) but the backdrop passes straight through with no bend. This is the single technique that separates 'frosted glass' from 'Liquid Glass'.
  - → W-LENSING: add an OPT-IN refraction layer as a new --glass-* axis, NOT a default (it's Chromium-only for backdrop-filter:url() + costly). Precompute ONE squircle-profile displacement-map data-URL (Apple's preferred ⁴√(1-(1-x)⁴) curve — stays smooth when stretched) at a few bevel widths; ship as a tiny SVG <filter> + a `.glass-lens` class gated `@supports (backdrop-filter:url(#x))`. Animate the cheap `scale` param (not the map) for the press/morph swell. Cross-engine + PRM degrade to today's blur+tint (the no-workaround floor). Edge-concentrated refraction (thin interior, strong rim) is the cheapest convincing read. Capture DELTA: a glass card over the live aurora, refraction ON vs OFF, both modes.

## R2 awwwards-sota

> The SOTA (awwwards Fluid Glass/liquid-layout + iOS-26 Liquid Glass + Material 3 Expressive + the 2026 trend surveys) converges on five patterns: (1) refractive/lensing glass (feDisplacementMap + chromatic aberration + specular rim as backdrop-filter:url()) that ADAPTS to its backdrop; (2) orchestrated spring-physics entrance choreography (premium loader -> hero builds -> sections cascade) with a spatial-overshoot / effects-no-overshoot split that exactly validates glass-ui's §6 doctrine; (3) bold + KINETIC typography; (4) calm-base + saturated accent POPS; (5) gestural liquid morphs. glass-ui is already SOTA on the ADAPTATION axis (W55 adaptive-tint + the sampled-luminance observer) and owns nearly every motion ingredient (useLiquidFlex, useViewTransition/navigate, useSpringPress/useStagger/useSpringMount, the --spring-* + duration clock, the procedural moving specular) plus a rich kf facility (Draggable fling, flip/flipShared+springTimingFunction, stagger, decay, morph, MotionPath, SpringProgress) — but it has NOT composed them into the headline primitives: there is no liquid app-open reveal, no pull/drag-morph tab, no optical refraction layer, and no page-load choreography. Six BB waves follow directly, each activating existing seams over inventing new physics. The binding fences: refraction is a Chromium-only @supports PREVIEW (token-glass floor everywhere, ship-vs-preview on a recorded throttle perf number per the §7 mechanical-fall precedent); compositor-only transform/opacity (no layout animation); PRM-safe by construction; presets-in-consumers (no demo hue into library tokens); keep useLiquidFlex's LOW squish cap; and the plan NAMES the own-surface DELTA each wave captures (no faked verification).   - → Add a REFRACTION layer as a perf-gated PREVIEW on the existing --glass-level axis, not the floor (mirror the AZ.W-MORPH-SHOWCASE arm-a/arm-c mechanical-fall: VT-crossfade floor, metaball-bridge preview). The floor stays the token glass + procedural specular on ALL engines; an @supports(backdrop-filter:url()) refraction arm (a single shared SVG filter id, edge-concentrated displacement) refines on Chromium only.

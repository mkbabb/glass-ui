## Goal criterion

The CardHeader scroll-shrink choreography runs entirely on the compositor — every animated property is `transform`/`opacity` (or a custom prop that resolves onto them), ZERO reflow per scroll frame — so the live scroll-shrink demo's CLS drops from 1.03 to ≤ 0.1, and the library can NEVER ship a layout-animating keyframe again (a future agent re-adding `padding`/`font-size`/`grid-template-rows` to ANY keyframe reds `proof:no-layout-animation`). ## The miss (A'-3 — the source-green/architecturally-wrong layout animation)

`<CardHeader shrink>` (`src/components/ui/card/CardHeader.vue`) binds a 3-lane scroll-driven choreography to the `--card-scroll` named scroll-timeline (emitted by `.card-scroll-host` on the scroll-overflow ancestor). The choreography is type-correct, PRM-bracketed, and tested green — but every lane animates a LAYOUT-TRIGGERING property, so the browser must re-layout the header on EVERY scroll-timeline frame:

- **Lane 1 (header padding)** — `@keyframes card-header-shrink` animates `padding-top: 1rem → 0.5rem` + `padding-bottom: 0.5rem → 0.25rem` (`CardHeader.vue:110-119`). Padding is a box-model property; a padding change reflows the header AND every following sibling.
- **Lane 2 (title font-size)** — `@keyframes card-title-shrink` animates `font-size: var(--type-heading) → var(--type-prose)` (`CardHeader.vue:121-128`). `font-size` re-measures the text run on every frame (the most expensive lane — it forces a text-layout pass).
- **Lane 3 (description collapse)** — `@keyframes card-desc-shrink` animates `grid-template-rows: 1fr → 0fr` + `margin-top: 0.125rem → 0` (`CardHeader.vue:130-141`). The grid-track collapse is a layout animation by construction; `margin-top` reflows the box.

The `opacity` channel in lane 3 IS compositor-safe (the one correct property in the set); every other animated property triggers reflow. The cumulative effect under the scroll-timeline is **CLS 1.03** — the A'-3 worst-cluster the value.js A′ perf-cluster audit (L25) measured, the P0 that shipped in 4.0.0. This is the exact "source-green / architecturally-wrong" class the BB PERFORMANCE band exists to close: vue-tsc green, the choreography visually correct, the mechanism a per-frame relayout storm.

The pattern was migrated verbatim from value.js's `PaneHeader.vue` (the SFC comment names the donor at `CardHeader.vue:22-26`) — so the layout-animation is a LINEAGE defect, not a one-off: the donor pattern itself animated layout properties, and the migration carried the architectural error forward. The fix re-expresses each lane as the compositor-transform equivalent the house ALREADY speaks: `scroll-driven.css:38-48` is the canonical idiom (a `transform: scaleX()` scroll-progress bar + a `translateY()`/`opacity` view-reveal, `@supports`-gated, PRM outer-gated). The CardHeader lanes adopt that idiom.

1. **Lane 1 — header padding shrink → a transform.** Replace `@keyframes card-header-shrink` (the `padding-*` animation) with the compositor equivalent. The header's vertical compression is re-expressed as a `transform` the browser composites without reflow — either a `scaleY` on a padding-spacer pseudo-element/inner-wrapper (the box stays its layout size, the visual padding shrinks via the transform) OR a `translateY`-driven reposition of the header content within a fixed-height box, whichever keeps the 3-lane gestalt identical. 2. **Lane 2 — title font-size shrink → a transform: scale.** Replace `@keyframes card-title-shrink` (the `font-size` animation) with a `transform: scale()` on the title (`[data-slot="card-title"]`), scaled so the glyph visually shrinks from `--type-heading` to `--type-prose` (the scale factor = `--type-prose / --type-heading`, a static ratio resolved from the scale tokens — NOT a per-frame `font-size` re-measure). The `transform-origin` anchors the title's leading edge so it shrinks in place (not toward center). The text run lays out ONCE at `--type-heading`; the scroll-timeline only composites the scale — zero text-layout re-measure per frame.

## The charge

speedtest AW v2.1 ("The Living Instrument") names five control-register refinements as **P2** — the polish tier it ships green WITHOUT, but which close real defects in the chooser-tile / metric-ledger / toast surfaces (the ask-brief P2 block, `speedtest/docs/tranches/AW/coordination/glass-ui-BB-ask-brief.md:164-176`). Each is a primitive-INTERNAL control a consumer cannot reach idiomatically — the exact "consumer scoped CSS can't reach without `:deep` (precept-forbidden)" trap the ask names verbatim. The remedy is the library's own canon: a primitive exposes the control as a TOKEN or a prop, never as an internal a `:deep()` reach has to override (Design Axis 2 — "component over CSS class"; tokens cascade, internals do not). Five concerns, re-grounded at HEAD:

1. **TOGGLEITEM-CARD-RADIUS (N11) — the 10px-radius-on-a-card-shape defect.** `toggleVariants` (`src/components/ui/toggle/index.ts:34`) bakes `rounded-button` into the base CVA string; the `card` variant (`:42`) is a full glass-card recipe (`glass-card w-full transform-gpu cursor-pointer flex-col gap-4 p-8 text-center …`) that NEVER overrides the corner radius, so a `<ToggleGroupItem variant="card">` chooser tile paints the small `--radius-button` (0.625rem ≈ 10px) corner on a large p-8 card shape — a button radius on a card silhouette (the WV1 chooser-tile defect). The card variant must read `--radius-card` (`= --radius-2xl`, 1rem) to match its own surface vocabulary.

2. **TOGGLEGROUP-RADIO-SEMANTICS — the single-select chooser is mis-typed for AT.** reka's `ToggleGroupRoot` carries a `type` prop (`single` | `multiple`, `ToggleGroupRoot.js:55-58`) but renders its items as `aria-pressed` toggle buttons in BOTH modes — there is no `role="radio"`/`aria-checked` arm. A `type="single"` group is semantically a single-select chooser (a radio group), but a screen reader announces N independent toggles, not "1 of N selected" (the WV1 chooser a11y defect). The glass-ui wrapper (`ToggleGroup.vue`/`ToggleGroupItem.vue`) must thread the radio semantics on the single-select arm — `role="radiogroup"` on the root + `role="radio"`/`aria-checked` per item — so the single-select chooser reads correctly to AT (the multiple arm keeps `aria-pressed`, the correct toggle-strip semantic).

3. **MetricRow label-align + icon-color tokens — the cert-grid needs internal control the consumer can't reach.** `MetricRow` (`src/components/custom/metric-stack/MetricRow.vue`) has a full `--metric-row-*-clamp-*` token family for the value/label/unit SIZE register, but (a) the label is hard-`text-transform: uppercase` with NO `text-align` token (`:170-184`) — a consumer building the completion certificate-grid wants the label RIGHT-aligned at a fixed seam (a labelled ledger), and there is no knob, so it would reach `:deep(.metric-row__label) { text-align: right }` (precept-forbidden); and (b) the leading glyph reads `color: phaseColor` inline ONLY (`:116`) — there is no `--metric-row-icon-color` token, so a consumer that wants the icon a different ink from the phase tint has no idiomatic reach. Two consumer tokens close the trap: `--metric-row-label-align` (default `left`, the existing behavior) + `--metric-row-icon-color` (default the existing phase/muted cascade). The MetricCell precedent is the model — its `iconColor` prop already reconciles onto `<IconChip bare :tone>` (`MetricCell.vue:147`), but `MetricRow` ships a raw inline-style icon with no token; this wave gives MetricRow the SAME consumer reach via tokens.

4. **The a11y pair — Toaster live-region + the FocusScope trap.** The ask-brief P2 block names "a11y pair (Toaster, FocusScope live-region/focus-trap)" (`:174`). At HEAD: `Toaster.vue` renders a `ToastViewport` inside a `ToastPortal` (`:82-84`) — reka's `ToastViewport` carries the role, but the viewport is NOT marked `aria-live` for the toast-announcement contract (a screen reader does not get the "polite" live-region announce on each toast). And glass-ui ships NO published `<FocusScope>` surface — reka exposes `FocusScope` + `VisuallyHidden` (confirmed at HEAD), but glass-ui never re-exports a focus-trap primitive for a consumer's modal/dialog-shaped focus-trap need (speedtest's WV survey + thank-you facilities want a focus-trap host without re-importing reka directly). The pair: mark the Toaster viewport region `aria-live="polite"` (the announce contract) + publish a thin `<FocusScope>` wrapper (the trapped/loop focus host) on a subpath so the consumer reaches the a11y pair idiomatically.

The seam across all five: **a control a consumer must reach is exposed as a token/prop/published primitive, never as an internal selector a `:deep()` overrides.** This is a token-first / component-over-class wave — small, idiomatic, no new register, no new color.

## Scope

1. **(N11) The `card` variant resolves `--radius-card`, not the base `rounded-button`.** Add `rounded-card` to the `card` variant arm in `toggleVariants` (`toggle/index.ts:42`) so the card tile paints the 1rem `--radius-card` corner that matches its `glass-card` surface vocabulary, NOT the inherited 10px `--radius-button`. CVA emits `variants` classes after the base string, so a `rounded-card` in the `card` arm wins the source-order race against the base `rounded-button` (the same source-order mechanism the existing `h-auto` compoundVariant relies on). The other variants (`default`, `outline`) keep the base `rounded-button` — a button shape gets a button radius. This is a one-token add (the radius vocabulary already exists in `theme/radius.css`), no new token.

2. **(RADIO) Thread the single-select radio semantics on the `type="single"` arm.** The glass-ui `ToggleGroup.vue` wrapper reads the forwarded reka `type` prop; on `type="single"` it sets `role="radiogroup"` on the root, and `ToggleGroupItem.vue` sets `role="radio"` + binds `:aria-checked` to the item's selected state (the reka `data-state="on"` / pressed state, reachable via the item context or the `data-state` attribute) — on `type="multiple"` (or unset) the items keep reka's native `aria-pressed` toggle semantics (the correct multi-toggle strip). The semantic is threaded at the WRAPPER, not forked into a second component — ONE `<ToggleGroup>` with the role-per-type discipline. (Coordination with the CLAUDE.md Tabs-vs-ToggleGroup canon: a single-select chooser is the radio case the ToggleGroup register serves; the SegmentedTabs panel-nav `role=tab` register is distinct and untouched.) Re-grep at HEAD how reka surfaces the per-item selected state (the `data-state`/context) so the `:aria-checked` binding reads the live selection, not a stale prop.

3. **(METRIC) Mint the `--metric-row-label-align` + `--metric-row-icon-color` consumer tokens.** In `MetricRow.vue`'s scoped CSS: (a) the `.metric-row__label` rule gains `text-align: var(--metric-row-label-align, left)` (default `left` — byte-identical to today; a consumer sets `--metric-row-label-align: right` at `:root`/per-row for the cert-grid fixed-seam ledger); (b) the leading glyph's color reads `var(--metric-row-icon-color, …)` where the fallback is the EXISTING phase/muted cascade (the inline `phaseColor` becomes a token-WITH-fallback so a consumer can override the icon ink independently). The defaults preserve every current consumer byte-for-byte (zero breakage — the W-NO-GRAY/presets discipline); the tokens are the NEW idiomatic reach. The MetricCell `iconColor`→IconChip precedent is the model — MetricRow gets the same consumer reach via a token (it ships a raw `<component :is="icon">` not an IconChip, so the token is the right seam; folding MetricRow's icon onto IconChip is a larger refactor NOT in scope — the token is the minimal idiomatic fix). Record the two tokens in the `--metric-row-*` family's documented home (tokens §METRIC, beside the clamp family) so they are discoverable.

4. **(A11Y) Mark the Toaster viewport `aria-live` + publish `<FocusScope>`.** (a) `Toaster.vue` marks its `ToastViewport` region `aria-live="polite"` (the screen-reader announce-on-toast contract; reka's viewport carries the landmark role, this adds the live-region politeness so each toast announces). Re-grep at HEAD whether reka's `ToastViewport` already threads `aria-live` internally — if it does, this is a documentation/no-op confirmation (record it); if not, the attr is added on the viewport. (b) Publish a thin `<FocusScope>` wrapper — a glass-ui SFC (`src/components/ui/focus-scope/FocusScope.vue`) composing reka's `FocusScope` primitive (the trapped/loop focus host) — on a `/focus-scope` subpath + the relevant barrel, so a consumer reaches the focus-trap idiomatically without importing reka directly. The wrapper is a thin pass-through (`trapped`/`loop`/`as` props forwarded); it is the published a11y primitive the pair names. (If the investigation finds glass-ui already re-exports a focus-trap surface, the publication is a no-op confirmation — re-grep first.)

5. **(SEAM) The no-`:deep`-needed predicate is the binding contract.** The wave's success is that the speedtest cert-grid consumer (and any consumer) can set `--metric-row-label-align`/`--metric-row-icon-color` from its OWN stylesheet (`:root`/a parent/a per-row inline style) and have it cascade into the MetricRow internals WITHOUT a `:deep()` reach — the Design-Axis-2 "component over CSS class" bar. The gate asserts the tokens are read with a fallback (so a consumer override cascades) AND there is no consumer `:deep(.metric-row__*)` needed for the label-align/icon-color cases. This is the precept the ask names; it is the wave's reason for being.

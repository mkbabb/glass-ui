## Goal criterion

This wave succeeds if, when work ends, a tranche close CANNOT be tagged `complete` on a `--run local`-only (or `--run release`-only) gate run: the close/release path runs the FULL gate set — the deduped union of the `local`, `ci`, and `release` tag sets — in a siblings-absent clean checkout (the CI-accurate environment) before the irreversible tag leg, and a born-RED meta-gate asserts that path so a future close cannot quietly narrow the battery again. The `gates.mjs --run full` union mode is the ONE command that runs it; `proof:close-battery-parity` is the structural lock that the close-doc/release path actually invokes it.

## The miss (file:line evidence — RE-GREP at HEAD)

The BA close declared `gates.mjs --run local` green (`docs/tranches/BA/FINAL.md:109` — "`gates.mjs --run local` | green … `proof:gate-script-parity` + `proof:tag-parity` GREEN"). The BB Batch-0 census (`docs/tranches/BB/audit/ci-red-census.md:4-5`) proved that claim **substantially false**: `ci ⊂ local` (156 ⊂ 195 at the census; re-grounded at HEAD: 156 ci, 195 local, 203 total — confirmed below), so the 18 siblings-absent ci reds it lists were ALSO local reds. The `--run local` claim was over-claimed on the gate front, and the release path NEVER ran the union to catch it.

The structural root cause has TWO legs, both live at HEAD:

1. **No close/release path runs the UNION.** `scripts/release.sh:80` runs ONLY `node scripts/gates.mjs --run release` (43 gates). `.github/workflows/release.yml:50-51` runs ONLY `node scripts/gates.mjs --run release`. The wf-close orchestrator prompts (`scripts/wf-ay-close.js:43`, `scripts/wf-ay-close2.js:43`) instruct the close agent to run "the FULL local gate suite via `scripts/gates.mjs --run local`" — but `--run local` is NOT the full set: it MISSES the 4 release-only gates (`proof:az-reflect`, `proof:ba-final`, `proof:ba-gestalt`, `gates:verify-ci` — confirmed at HEAD) and `audit:stash` (the one ci-only gate). So no single command and no close-path step runs `local ∪ ci ∪ release`. The closest is `--run local`, which the BA close ran (and over-claimed green) while the union's release-and-ci-only members went unverified at the close.

2. **No siblings-absent demand.** The census's load-bearing finding (`ci-red-census.md:3`) is that the CI-accurate environment is a **siblings-absent clean checkout** — four sibling-dependent gates (`consumers:static`, `motion-demo`, `motion2`, `phantom-classes`) skip-pass on the clean runner but the OTHER reds are genuine. A dev-machine `--run local` run WITH siblings present is NOT the truth the tag ships against; the truth is the clean-checkout union. Nothing in the close path demands or records the siblings-absent run.

There is no `--run full` mode in `gates.mjs` (`scripts/gates.mjs:1421-1436` dispatches only `--run <local|ci|release>` / `--verify-ci` / `--emit-ci` / `--list`), so the union is not even RUNNABLE as one command today — a close agent that wanted to run the union would have to run three modes and dedupe by hand. And no meta-gate asserts the close-doc/release path invokes the union: `proof:gate-manifest-sound` (`scripts/proof-gate-manifest-sound.mjs`) proves the manifest is WELL-FORMED and the three filters DERIVE from one manifest (clause 3 only asserts `--run local` *completes*, not that the close runs the union), but it does not assert the CLOSE invokes the full set siblings-absent.

The mechanism this wave closes: **the close-class lie has no structural guard. A close can run `--run local`, over-claim it green, and tag — exactly what BA did.**

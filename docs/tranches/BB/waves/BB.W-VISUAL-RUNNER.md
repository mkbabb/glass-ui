## Triumvirate Dispatch

- **Spec-rot that invalidates the run (the expected first-run reds).** When `--run pi` runs the ~57 orphans for the first time, a subset WILL red on stale bindings (a moved demo route, a renamed token a `getComputedStyle` reads, a selector drift — the `feedback_glass_ui_binding_verification` class, which is EXACTLY what running-nowhere let accumulate). A red that is a simple route/selector re-point INSIDE the spec is local-edit-recoverable (the spec re-points to the live route — recorded in PROGRESS). A red that reveals a GENUINE rendered defect on a component surface (the spec is correct, the surface regressed) is a register/component miss owed BY NAME to that component's wave — triumvirate (research the surface, book the fix to the owning wave, record the red), do NOT loop editing the spec to make it pass over a real defect (the green-over-broken close-class this whole tranche kills). The wave's job is to make the suite RUN + enrolled, not to silently green every rotted spec.
- **File-bounds expansion that invalidates the wave.** If wiring `--run pi` into the close path forces an edit to `release.sh`/`release.yml`/the `--run full` union shape (W-CLOSE-BATTERY's bound, Batch 0, landed and frozen for this batch), that is a scope-reveal — triumvirate (the close-battery owns the union; this wave declares the `pi` mode + tag, W-CLOSE-BATTERY reaches it via the manifest's `gatesFor("pi")`), do NOT widen into the close-battery's release-path files unilaterally.

- **Diagnostic loop halt.** If `proof:visual-runner`'s CI-side enrollment arm still reds after three iterations and it is not isolated whether the failure is an un-enrolled committed spec, a stale EXCLUDE rationale, or a `--run pi` dispatch case that does not register in `gatesFor("pi")`, halt and triumvirate (a half-registered mode that the manifest derives but the dispatch does not handle is the suspect — the `gates.mjs` runMode/dispatch coupling).

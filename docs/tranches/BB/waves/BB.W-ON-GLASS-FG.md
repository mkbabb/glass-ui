## The defect / charge (N13 — the whisper collapse; file:line, RE-GREP at HEAD)

`--muted-foreground` is calibrated against the CANVAS, not the glass plate it renders ON. At HEAD (`color-radius.css:85`) it resolves `var(--neutral-5)` = `hsl(30 22% 40%)` (light, L40 — "WCAG AA: 5.21:1 vs page"); the dark arm (`dark-arm.css:47`) is `hsl(34 14% 62%)` (L62 — "WCAG AA: 7.64:1 vs page"). Both AA bars are quoted **against the opaque page surface** (`--neutral-0`). But the glass-first MAXIMAL default (AX.W54) makes the COMMON case a caption rendering on a TRANSLUCENT glass plate (`.glass-card`/`.glass-resting`/`.glass-quiet`), which composites the page UP toward the lifted `--card` fill — so the effective background luminance behind the muted ink rises and the contrast COLLAPSES. The speedtest ask measured the live result: **1.15-3.29:1** on glass in dark theme — the "dark-theme whisper collapse" (the ask-brief N13, `speedtest/docs/tranches/AW/coordination/glass-ui-BB-ask-brief.md §4`: "`--muted-foreground` is calibrated against the canvas but renders over translucent glass that composites to a mid-grey, so it never clears AA on its own surface").

The BA adaptive-glass seam (`glass/ladder.css`) already handles the OTHER half — the **bright-bucket** case. When a plate darkens to full AA (the overlay band unconditionally, `ladder.css:200-204`; the declared/sampled `@container style(--glass-backdrop: light)` bucket, `ladder.css:134-152`), it lifts `--muted-foreground` ALL the way to `--foreground` (`ladder.css:150`, `:203`) because "the muted L40 tier cannot clear 4.5:1 on a translucent FULL-AA-darkened plate." That lift is correct WHERE THE PLATE DARKENS. The N13 gap is the **calm-light content-tier floor** (`ladder.css:206`+, the R9-1 slides gray-slab fix): the plain content tiers self-engage only the SUB-PERCEPTUAL `--glass-tint-strength-floor` (4%), NOT the full AA darken — so the plate stays near-ground translucent (warm cream / luminous dark), the `--muted-foreground` → `--foreground` lift does NOT fire, and the muted ink keeps its PAGE-calibrated `--neutral-5` value over a plate it does not actually clear AA on. The whole-app result: a caption on a content card reads as a whisper in dark mode, a too-faint ghost in light.

This is NOT a fork of the adaptive seam — it is the **third state it never expressed**: (a) bright/darkened plate → full ink (BA, shipped); (b) opaque canvas → page-muted (the original `--neutral-5`, correct); (c) **calm translucent glass plate → a register whose contrast target is the COMPOSITED FILL** (this wave — between the two, AA over the plate's own composited luminance without going all the way to full ink, which would over-darken the quiet-subordinate hierarchy the muted register exists to carry). Plus the two sibling rungs the ask names: `--input-on-glass` (the form well over glass — same collapse on the input substrate) and `--progress-track-on-glass` (the meter track over glass).

The slides deck ALREADY proved the fix in a consumer override — `slides/src/styles/deck.css §1` re-declares `--muted-foreground: light-dark(hsl(24 6% 44%), hsl(45 12% 64%))` + a `-strong` rung (`deck.css:80-81`) specifically because "every LIGHT-slide site that reads them in scoped CSS … had the var resolve to nothing … the intended two-rung quiet-subordinate hierarchy was dead deck-wide (SLIDES-REVIEW §3.6, P0)," and its TRUE-GLASS register (`deck.css:113-192`) lifts the glass-bg-* mix + the rim/crest specifically so "the `--foreground` text holds well above 4.5:1 on both (π-readback: ~10:1 body / ~7:1 home)." That is a CONSUMER override, not a portable rung set — this wave MINES it for the approach + the dark-arm value family and builds the token system FRESH in the library (the ask-brief §"Slides donor reality": "build the token system fresh in glass-ui, slides recipe as reference").

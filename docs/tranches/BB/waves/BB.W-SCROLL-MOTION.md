## The charge

The LIVE awwwards SOTA audit (`docs/tranches/BB/audit/awwwards/findings.md`, finding 2 + the NEW-candidate note) names ONE genuinely-new SOTA element the liquid-glass band UNDER-covers: **scroll-driven CHOREOGRAPHY** — the page-load build → section-cascade → scroll-pinned reveals + the smooth-scroll register. Every motion winner carries "Scrolling/Transitions" (the-power-of-storytelling, pacome, the broader collection); the live anchor (pacomepertant.com) runs **Lenis smooth-scroll + GSAP ScrollTrigger** with 19 `will-change`-promoted compositor elements. The Codrops/sticky-grid SOTA pattern is the canonical shape: *"Scrolling does not move the scene, it advances time inside it"* — a `position: sticky` fixed stage whose internal animation TIME is driven by scroll progress, with column-staggered cascade reveals (60ms increments), `scrub`-bound timeline progress, and a phased sequence (grid-reveal 0-45%, expand 45-90%, settle 90-100%).

**glass-ui owns the SUBSTRATE but composes none of the CHOREOGRAPHY.** Three facilities exist at HEAD and are individually correct but isolated:

1. **`scroll-driven.css`** ships `.scroll-progress` (a `scroll()`-timeline 0..1 scaleX bar) + `[data-scroll-reveal] > *` (a `view()`-timeline per-child fade+lift, the implicit stagger — NO `setTimeout` cascade) under the EXEMPLARY `@media (prefers-reduced-motion: no-preference)` + `@supports (animation-timeline: …)` outer-gate. These are the two PRIMITIVES — but they are POINT recipes (a progress bar, a list-fade), NOT the SOTA page-orchestration (the page builds in on route-enter; sections cascade as a coordinated sequence; a showcase pins and advances through phases).
2. **`useScrollProgress` + `supportsCssTimeline`** is the dual-path single-writer fallback (the JS listener attaches ONLY when `supportsScrollTimeline()` is false — `useScrollProgress.ts:28,80`). The feature-detection harden (`supportsCssTimeline.ts` — the garbage-value rejection that filters always-true SSR/jsdom shims) is the canonical guard the whole register reuses.
3. **The demo shell ALREADY declares the named scroll-timeline.** `<main class="demo-main-scroller">` carries `scroll-timeline-name: --demo-main-progress` (`dock-nav.css:155-160`) and the `.scroll-progress` bar resolves `--scroll-progress-scroller: --demo-main-progress` — the route-scroller named-timeline is LIVE. `StoryPage.vue:85-90` already wraps the section stack in `<section data-scroll-reveal>` (the section-cascade is HALF-WIRED — the recipe binds but it is the bare 6px-lift `view()` fade, not the SOTA coordinated build).

**The 2026 SOTA convergence (the strategic point):** native CSS scroll-driven animations are UNIVERSALLY SUPPORTED in 2026 and run OFF the main thread on the compositor (the search canon: "Native execution guarantees 60fps performance and high layout stability… eliminating the need for JavaScript-based scroll libraries"). The award-winners hand-roll on Lenis+GSAP what the platform now ships natively — glass-ui is NOT behind on the SUBSTRATE (it has `scroll()`/`view()`); the gap is the CHOREOGRAPHY register (the orchestrated page-build/section-cascade/scroll-pinned recipes) + the missing native primitive for scroll-pinned sections (**`timeline-scope`** — links one element's named `scroll-timeline` to animate a sticky descendant, the SOTA fixed-stage-advances-time mechanism `scroll-driven.css` does not yet carry). This wave mints the CHOREOGRAPHY on the native substrate — NO Lenis/GSAP/Locomotive dependency (the no-net-dep fence — a bundled smooth-scroll lib is a 20-40KB runtime cost glass-ui's native-first identity refuses), the smooth-scroll opt-in is the native `scroll-behavior: smooth` CSS-first path (PRM-gated).

## Scope

1. **Re-write `waveRows` to locate columns by HEADER NAME (the column-order-robust parser).** The parser scans for the table HEADER row — the first pipe-row whose lowercased cells include BOTH `wave` and `status` — and records the header's column INDEX for `wave` and for `status`. Subsequent pipe-rows read `cells[waveIdx]` and `cells[statusIdx]` (the named columns), not `body[0]`/`body[last]`. The wave-id regex `/^W(\d|-[A-Z])/` stays the row filter (it still skips the header + separator + prose rows), now applied to the CORRECT cell. The status-cell `**bold**` markers some tables wrap the close-token in (`**complete**`, `**live-verified**` — BA's idiom) are stripped before `statusToken` so the token reads through the markdown. This is the gestalt fix — NOT a per-tranche special-case map (which would just be a second positional table); the parser reads the table's OWN header, so a future tranche may order its columns however it likes.

2. **Fall back EXPLICITLY when no header is found (fail-loud, never silent).** If a PROGRESS file has no header row carrying both `wave` and `status` (a malformed or pre-header table), the gate ERRORS with a named diagnostic (`could not locate the wave/status columns by header — the table must carry a header row naming both`) and exits non-zero. A silent 0-row green is the precise failure this wave kills — the fallback is a loud RED, never a vacuous pass. (The current `process.exit(1)` on a missing PROGRESS file at `:505-508` is the precedent.)

3. **Grow the self-test with a COLUMN-ORDER bite (born-RED witness).** Add a synthetic check to the self-test block (`:511-582`) that feeds the parser a `batch`-first / `status`-NOT-last table fixture (e.g. `| batch | wave | status | notes |\n|---|---|---|---|\n| 0 | W-TEST | live-verified | x |`) and asserts the parser returns exactly ONE row with `wave === "W-TEST"` AND `status` token `live-verified` — the row the OLD positional parser dropped to 0 / mis-read. The check is PURE over the fixture string (no on-disk file), deterministic every run, and is the RED-witness inverse: if `waveRows` regresses to positional, the synthetic row mis-parses and the self-test reds loudly.

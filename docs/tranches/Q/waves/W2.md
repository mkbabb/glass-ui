## Lane A — glass-ui `Card` props fail-explicit (invariant 31)

Per Q-card-2 + Qα R3. glass-ui's `Card` accepts `tier` / `shadow` / `grain`; a consumer passing `variant="pane"` (or any undeclared prop) gets it silently swallowed as an inert attr-fallthrough → the card falls back to `tier:"resting"` + `shadow:true` (the hard black drop-shadow the user saw).

Apply invariant 31 (component props fail-explicit):
- The `Card` `defineProps` boundary warns on undeclared props. In Vue 3.5, undeclared attrs fall through to the root element by default — the fix is a dev-mode `attrs`-inspection warning when a known-stale prop name (`variant`) appears in `$attrs`.
- **Posture at W2 = dev-WARN** (not typed-reject) — see the Lane C posture constraint: the bbnf-buddy cartoon site keeps the stale `variant=` API until W4, so a typecheck-hard-reject at W2 would red-break bbnf-buddy for the W2→W4 window. The runtime dev-warning surfaces the staleness without breaking builds.
- The typed-`defineProps` hardening (a `vue-tsc` failure on `variant=`) is the stronger end-state — it lands at **W6** once the fleet is verified `variant=`-free. W2 spec records this as the planned hardening; W6 close-precept executes it.

Audit the OTHER primitives for the same silent-swallow class — if `Card` has it, siblings may too. Scope: report sibling occurrences; fix `Card` definitively + the ≥ 2 worst siblings.

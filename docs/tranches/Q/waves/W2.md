## Lane A — glass-ui `Card` props fail-explicit (invariant 31)

Per Q-card-2 + Qα R3. glass-ui's `Card` accepts `tier` / `shadow` / `grain`; a consumer passing `variant="pane"` (or any undeclared prop) gets it silently swallowed as an inert attr-fallthrough → the card falls back to `tier:"resting"` + `shadow:true` (the hard black drop-shadow the user saw).

Apply invariant 31 (component props fail-explicit):
- The `Card` `defineProps` boundary rejects/warns on undeclared props. In Vue 3.5, undeclared attrs fall through to the root element by default — the fix is a dev-mode `attrs`-inspection warning (e.g., warn when a known-stale prop name like `variant` appears in `$attrs`), OR a typed-`defineProps` posture that makes the stale prop a typecheck error at the consumer.
- Idiomatic gestalt: prefer the typecheck-error path — a consumer on the glass-ui `development` condition gets a `vue-tsc` failure the moment it passes `variant=` to `Card`. Pair with a runtime dev-warning for consumers not running typecheck.
- The decision is a Q design choice — the lane spec author resolves dev-warn vs typed-reject vs both at lane open, per the invariant-31 codification intent.

Audit the OTHER primitives for the same silent-swallow class — if `Card` has it, siblings may too. Scope: report sibling occurrences; fix `Card` definitively + the ≥ 2 worst siblings.

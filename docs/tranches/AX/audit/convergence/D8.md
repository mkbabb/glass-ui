## TL;DR

`.glass-material` (the library CSS grammar in `glass.css` + `glass-refract.css` + `glass-specular-track.css`)
is **NOT broken** — it is the exact modern, token-driven, dark-adaptive, `@supports`-gated grammar that
**W09** retuned (subtle/dormant-at-rest), **W20** re-points GlassPanel onto as the survivor, and **W25b**
documents-not-carves. The breakage is entirely in `demo/stories/substrates/glass-material.vue` — authored at
**AW commit `8554e33`** (W22/W23) and **never updated through the entire AX tranche**, so it now stages a
showcase for behaviours the demo itself fails to enable, against a recipe that W09 deliberately made dormant
at rest. The story reads as dead plates: no moving specular, dead tint buttons, an abused `glass-btn`, and a
near-invisible rim.

## Source-level diagnosis

### The library side is healthy (do NOT touch glass.css for D8)

- `src/styles/glass.css` `.glass-material` selector-GROUP (the five rungs + `.glass-card` + `.glass-btn` +
  `.dock-icon-button`) carries the unified `::before` catch-light, the `--glass-material-rim` (=
  `--glass-edge-light`) inset ring, the grain `::after`, the adaptive-tint `color-mix(in oklab, …)`, and the
  `.glass-chromatic` dispersion fringe. All `@supports`-gated, dark-arm-bearing, fallback-bearing.
- `src/styles/glass-refract.css` ships the `#glass-refract` convex-lens filter as an inline data-URI behind
  `@supports (backdrop-filter: url("#glass-refract"))`. Sound; Chromium-only by design.
- The CSS is fully imported via `src/styles/index.css` rungs 4 / 4a / refract. No missing wire.

The W09/W20/W25b plans are explicit that **W20 touches no glass.css** (W20 §C.2 / §Scope line 155-156: "NOT
a `.glass-material`/glass.css rewrite … the specular `.glass-material::before` is W09's exclusive glass.css
write") and **W25b documents glass.css NOT-carved** (W25b RED-witness 3). So the CSS grammar is settled and
owned. D8 is NOT a CSS-grammar defect.

### The demo side is broken — four root causes, ALL in `glass-material.vue`

The file was last touched at `8554e33` (AW); `git log -- demo/stories/substrates/glass-material.vue` shows
ONLY that one commit. Meanwhile `93696b3` (W09) retuned the recipe to dormant-at-rest. The demo was authored
against the **pre-W09 louder specular** and never rewired:

1. **Headline "specular + rim across the band" section shows NOTHING static (the core "totally broken"
   read).** `src/styles/tokens.css:1825` sets `--glass-specular-intensity-rest: 0` (W09's correct dormancy).
   The `::before` `opacity: var(--specular-intensity)` is therefore `0` at rest. The demo blurb promises
   "Every rung + card reads the same **pointer-anchored** catch-light" — but `glass-material.vue` wires **no**
   `--mouse-x/--mouse-y` write and **never composes `useSpecularTracking`** (`grep mouse-x|useSpecular
   demo/stories/substrates/glass-material.vue` → none). So the headline feature is invisible until a hover
   lifts intensity to `0.22`. A static frame (and the screenshot the user saw) reads as flat dead plates.
   `src/composables/glass/useSpecularTracking.ts` is the shipped, DRY pointer-write seam built for exactly
   this — the demo must bind it (`:style="specularStyle" @pointermove="onPointerMove"`) on each plate, or the
   headline is structurally unfulfillable.

2. **Adaptive-tint buttons are DEAD (a concrete wiring bug).** `glass-material.vue:124-126` sets only
   `--glass-tint-source` inline; it **never sets `--glass-tint-strength`**, which stays at its default `0%`
   (`tokens.css:772`). The rung background is `color-mix(in oklab, <bg>, var(--glass-tint-source)
   var(--glass-tint-strength))` — at `0%` strength the mix is a no-op, so clicking "aurora rose"/"aurora
   teal" changes nothing. The tint demo demonstrates the opposite of working. (`grep tint-strength demo/` →
   none.)

3. **`glass-btn` abused in the squircle section.** `glass-material.vue:92-94` writes
   `class="glass-btn !h-12 !w-44"`. `.glass-btn` (glass.css:394) is a `display:flex` **circular icon button**
   fixed at `--size-icon-btn` (2.5rem) with `border-radius: var(--radius-pill)`; forcing it to a 11rem × 3rem
   bar via two `!important` overrides is non-idiomatic and reads as a broken/misshapen control. The squircle
   fold should be shown on `.glass-card` + (if a button is wanted) a real `<Button variant="glass">`, not a
   coerced icon-button.

4. **"Edge-rim across the band" reads as nothing.** `--glass-edge-light: inset 0 0 0 0.75px hsl(0 0% 100% /
   0.18)` (tokens.css:757) is a 0.75px, 18%-α white inset ring — deliberately sub-perceptual (W09). With no
   contrast device (no dark plate, no zoom, no side-by-side rim-on/rim-off), the section's claim is
   unverifiable on screen. The demo over-promises what a single static frame can show.

### Compounding: the Aurora staging is the right idea but unguarded

The demo correctly stages the matrix over `<Aurora :config="DEFAULT_AURORA_CONFIG">` (glass needs busy color
behind it). Aurora autostarts on mount and W07 (aurora-core-unblock) is COMPLETE, so the backdrop paints.
This is NOT a current breakage (unlike the W20-flagged card-story Aurora-staging at the time W20 was written),
but it does mean the glass-material demo is **shared-fate** with Aurora — and it stages the *moving* Aurora,
which makes a static screenshot of dead plates look doubly broken.

## Gestalt fix direction (no patch, no workaround)

Reauthor `demo/stories/substrates/glass-material.vue` so the story DEMONSTRATES the grammar it documents,
idiomatically, by binding the shipped seams rather than narrating absent ones:

1. **Wire the moving specular via the shipped seam.** Compose `useSpecularTracking()` (already exported from
   `@mkbabb/glass-ui` glass composables) and bind `:style="specularStyle" @pointermove="onPointerMove"` on
   each rung/card plate, so the headline "pointer-anchored catch-light" is actually live. This is the DRY,
   library-blessed path — no hand-rolled `--mouse-x` math, no per-component copy. (PRM-safe by construction.)
2. **Make the tint demo real.** The tint buttons must set BOTH `--glass-tint-source` AND a non-zero
   `--glass-tint-strength` (e.g. the ≤30% house ceiling) on the demo plate, so the `color-mix` actually
   biases the surface. Without strength the source is inert by definition.
3. **Drop the `glass-btn` abuse.** Show the squircle fold on `.glass-card` and, where a button is wanted, a
   real `<Button variant="glass">` — never an icon-button coerced wide with `!important`.
4. **Give the subtle rim a contrast device.** A rim-on/rim-off side-by-side (or a dark-plate sample) so the
   0.75px 18%-α ring is legible as a deliberate-subtle feature, not a missing one — matching the W09 "subtle
   by design" intent instead of contradicting it.
5. **Consider folding into the D6 blob/substrate consolidation pass.** D8 is the same META-CLASS as **D7**
   (blob-mood "totally broken") and the **W20 card-story** finding: *a demo authored against a prior behaviour
   and never rewired after the library moved underneath it.* The cardinal-lesson fix is not just this one
   file — a `proof`-style guard that a substrate story actually exercises (writes) the tokens/seams it claims
   would catch the whole class. Keep this wave demo-scoped, but record the meta-class for the W33 close /
   overfitting pass.

This is a demo-content reauthor on the EXISTING library grammar — zero library edits, zero new primitives,
binding the already-shipped `useSpecularTracking` seam + the already-shipped tint/dispersion/refract tokens.

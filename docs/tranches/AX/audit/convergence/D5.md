## Root cause — TWO distinct mechanisms behind one symptom

### A. "Far too dramatic" — the lean + squash magnitudes (LIBRARY; W15-owned)

The dramatic culprit is `src/components/custom/goo-blob/types.ts` `BLOB_CONFIG_DEFAULTS`
(`:299-302`):

```
pointerAttraction: 0.35,
pointerStrength:   0.45,   // ← W15-REDRESS bumped 0.11 → 0.45
stretch:           0.5,
clickImpulse:      0.5,
```

plus the **paired smoothstep-falloff widen** in `shaders/metaball.frag.ts` `main()` (`:322`):
`smoothstep(0.65, 0.0, pointerDist)` (W15-REDRESS widened 0.4 → 0.65).

The in-shader UV pull is `influence = smoothstep(0.65,0,dist) · uPointerAttraction ·
uPointerStrength`, then `uv -= normalize(dir)·influence` (`metaball.frag.ts:319-324`). With
`uPointerStrength = pointerStrength · POS_SCALE = 0.45·0.625 = 0.281` and the body painted at
`bodyRadius·POS_SCALE = 0.22·0.625 = 0.1375 uv`, the **peak field pull as a fraction of body
radius**:

| mood | uPointerAttraction | peak lean (uv) | **/ bodyR** |
|------|-------------------:|---------------:|------------:|
| idle (rest) | 0.454 | 0.128 | **0.93×** |
| **curious** (auto on pointer-over) | 0.574 | 0.161 | **1.17×** |
| happy | 0.745 | 0.210 | **1.52×** |
| **excited** (auto on click, held 900ms) | 0.830 | 0.233 | **1.70×** |

`uPointerAttraction` is `config.pointerAttraction (0.35) + params.pointerAttraction` and the mood
machine **compounds** it: `useBlobMood.ts:54` `pointerAttraction: lerp(-0.2,0.6,…)·(0.4+0.6·arousal)`
reaches +0.48 at excited. Crucially the **normal hover path is NOT idle** — `useBlobMood.ts:162`
auto-promotes to `curious` the instant the pointer is over the blob, and `:156-158` latches
`excited` for 900ms after a click. So a plain hover lands in the **1.17× regime** and a click in the
**1.70× regime**: the whole creature lurches the better part of a full body-width at the cursor.

The squash compounds it on a flick: `sa = 1 + speed·uStretch` (`metaball.frag.ts:206`) with
`speed = |uVelocity| = |springVel·0.5·POS_SCALE|` and `uStretch = 0.5`, against an **unbounded
spring velocity** (the critically-damped follow spring can peak O(5–8)/s on a fast flick) →
`sa ≈ 1.78–2.25×` — the body elongates to ~2× length / ~0.5× width, a violent taffy-pull layered
on top of the lean.

**Why it shipped this dramatic — the cardinal AX lesson, again.** `W15-blob-contained-droplet.json`
records it verbatim: the live π-lane FAILED the centroid-shift assertion (`live shift 0.0011, must
be ≥ 0.012`), and the re-solve drove `pointerStrength 0.11 → 0.45` + the falloff `0.4 → 0.65` to a
**modeled ≈0.111 width centroid shift — 9× the 0.012 gate floor** — with the live attenuation
**guessed** ("the centroid-shift margin assumes ~5× live attenuation … if the real attenuation is
worse, the lean still clears"). The value was tuned to **clear a synthetic readPixels gate by 9×**,
never validated as tasteful against a human eye. A 9×-over-floor lean is, on the real GPU, exactly
"far too dramatic." This is the same class as the W04 `min(max-content)` and the
`var(--dock-morph-t,1)` defects — headless-green over a visually-wrong surface.

### B. "Totally broken" — the demo clip + the listener/canvas coordinate mismatch (DEMO; W18/W40)

Two demo-side mechanisms make the hover read as broken (not the magnitude):

1. **`overflow-hidden` clips the 160% canvas.** `demo/stories/substrates/blob-interaction.vue:57`
   wraps `<GooBlob>` in `<div class="relative aspect-square w-56 overflow-hidden rounded-card">`.
   The `.goo-blob-canvas` is `width:160%; height:160%` and **intentionally overflows the wrapper**
   so satellites + the wet meniscus paint beyond the layout footprint (GooBlob.vue:238-250 + the
   `contain: layout style` / no-`paint` comment at `:212-221`). The demo's `overflow-hidden` hard-
   clips that overflow at the card edge — satellites and the leaned/stretched body get sliced off,
   so the interaction reads as glitchy/broken rather than as an organic creature.

2. **Listener host ≠ painted field — the coordinate mismatch W15's audit already documented.**
   `useBlobPointer(wrapperRef)` (GooBlob.vue:77) attaches `pointermove` to the **wrapper**, but the
   canvas is 160% of the wrapper **centered**, so the wrapper spans only canvas-fraction
   `[0.1875, 0.8125]`. The pointer normalizes to `[-1,1]` over the *wrapper*, but the field is
   painted over the *canvas* — so the cursor's felt position and the painted lean target are on
   different scales, and a cursor near the wrapper edge fires `pointerleave` (active→false, the blob
   snaps home) while the visible droplet still extends past that edge. `W15-blob-contained-droplet.json`
   names this exactly as the reason its first gate read 0.0011 ("fx=0.82 lands OFF the wrapper's right
   edge → pointerleave → relaxes home"). The audit fixed the *gate driver* (drive over the wrapper
   box) but the **product mismatch** — listener on the wrapper, field on the 160% canvas — was never
   reconciled, so a real user hovering the visible droplet's outer ring gets no response or an abrupt
   snap-home.

## Gestalt fix direction (no patch, no gate-chasing)

1. **Re-tune the lean + squash to a TASTEFUL live target, not a 9×-over-floor synthetic one
   (W15-REDRESS-2).** The lean should read as a gentle *lean*, not a lurch — cap the peak field pull
   at a fraction of body radius (a ~0.2–0.35× bodyR pull reads as "the creature notices you," vs the
   current 0.93–1.70×). Concretely: drop `pointerStrength` back toward ~0.12–0.18, **decouple the
   mood compounding** so a hover doesn't auto-jump into the excited regime (clamp
   `uPointerAttraction` or flatten `useBlobMood.ts:54`'s arousal multiplier), and **bound the squash
   velocity** (`sa` should saturate — `1 + tanh(speed·k)·maxStretch` — so a fast flick can't reach
   2.25× elongation). The smoothstep falloff at 0.65 is fine to keep (it's what makes the lean
   *coherent* across the whole creature) — the magnitude lives in strength, not falloff.

2. **Replace the centroid-shift gate's FLOOR-only assertion with a BAND** (`tests-visual/
   blob-render.spec.ts`). The gate that drove this overshoot only asserts `shift ≥ 0.012` — it has no
   upper bound, so "more lean" always passes "more." Re-author it as `0.012 ≤ shift ≤ <tasteful-cap>`
   so an over-dramatic lean goes RED. This converts the gate from a one-sided ratchet (which rewards
   exactly the overshoot D5 reports) into a two-sided taste band — the structural antidote to the
   cardinal lesson on THIS surface.

3. **Reconcile the listener host with the painted field (library, mechanism B-2).** Either attach the
   pointer listener to the **canvas** (the actual painted extent) instead of the wrapper, OR normalize
   the wrapper-pointer into canvas space by the 1/1.6 factor, so the cursor position the user feels
   matches the field they see and the visible outer droplet ring stays interactive (no premature
   `pointerleave` snap-home).

4. **Demo: drop `overflow-hidden`, honor the 160% overflow (W18/W40).** The blob showcase frame must
   let the canvas overflow (the satellites + meniscus + lean are designed to paint past the layout
   box); size the showcase so the droplet sits centered with breathing room rather than clipped at a
   card edge.

The whole fix is a magnitude/coordinate reconciliation + a gate-band — **no new interaction code**
(the spring/trail/squash/mood machinery is sound; W16's quiescence/pause integration is untouched).

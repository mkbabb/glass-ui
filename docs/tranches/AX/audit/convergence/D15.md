# D15 — dock mobile sizing ~1.5x

**Defect (USER-DEFECTS-2026-06-08 D15, severity major):** "The dock on mobile should be
~1.5x bigger — bigger touch targets, bigger icons on mobile." Dedup anchor: "relates the
coarse-pointer touch floor in dock-controls.css."

**Verdict:** `net-new-wave` (a thin token-first responsive wave) — W06 carries only the
WCAG-44px *floor* hoist, NOT a 1.5x mobile up-scale; no existing wave covers the headline.

---

## Root cause — the dock has a coarse-pointer FLOOR, not a coarse-pointer SCALE

The only mobile/touch responsiveness the dock ships today is a single WCAG-2.5.5 *minimum*:

1. **`src/styles/dock.css:1405-1409`** — `@media (pointer: coarse) { .glass-dock[data-density]
   { --dock-control-size: var(--dock-touch-target, 2.75rem); --size-icon-btn:
   var(--dock-touch-target, 2.75rem); } }`. This is a FLOOR: it pins the control box to 44px
   on touch, but only when the comfortable/spacious defaults sit *below* 44px (comfortable
   `--dock-control-size` = 2.5rem/40px → lifted to 44px; spacious 2.75rem is already at the
   floor → no change; audacious 4rem already exceeds → no change). It is a +10% bump on the
   default density, not the user's ~1.5x.
2. **`src/styles/dock-controls.css:483-488`** — the companion per-button floor on a STANDALONE
   `.dock-icon-button:not(--compact)` (`min-block-size`/`min-inline-size: var(--dock-touch-target,
   2.75rem)`), reaching a dock-less routed gear. Also a floor, also 44px.

Neither lifts: dock **padding** (`--dock-padding-*`), **gaps** (`--dock-layer-gap`),
**tab geometry** (`--dock-tab-h`, `--dock-tab-padding-*`), **trigger geometry**
(`--dock-trigger-*`), **tile-min** (`--dock-tile-min`), the dock **radius**, or the **icon
glyph** itself. So on mobile the box snaps up to 44px while the glyph, padding, and inter-item
gaps stay at their desktop values — the dock reads cramped/under-scaled, exactly the user's
complaint.

**The icon-glyph gap is the sharpest miss.** `DockIconButton.vue` slots its glyph
(`<slot/>`, line 72) and `dock-controls.css` has NO `.dock-icon-button > svg` sizing rule (the
only `& > svg` is on `.dark-mode-toggle-button`, dock-controls.css:158). So a dock icon's
visual size is whatever the consumer's lucide class bakes in (`size-5`/`h-5 w-5` etc.) — the
library cannot up-scale "bigger icons on mobile" at all today, because it never owns the glyph
size. Lifting the BOX without lifting the GLYPH gives a 44px box around a 20px icon swimming in
padding — worse, not better.

**Why a floor was the right call then and is the wrong shape for D15.** O.W6 Lane D / AP.W3 R0G-6
correctly shipped a WCAG floor (a11y minimum). D15 is an ergonomic/visual ask: a *coordinated
1.5x of the whole dock chrome* on touch, not a per-control minimum. A floor cannot express it —
it clamps one axis up to a constant and leaves every co-dependent axis (padding, gap, glyph,
radius) at desktop scale, breaking the proportion the dock's density cascade so carefully tunes.

---

## Gestalt fix direction — a coarse-pointer `--dock-scale` density-multiplier, token-first

The dock already routes EVERY geometry axis through a named token under the
`.glass-dock[data-density="…"]` cascade (dock.css:221-326): `--dock-control-size`,
`--dock-padding-{block,inline}`, `--dock-layer-{height,gap}`, `--dock-tab-{h,padding-*}`,
`--dock-trigger-{padding-*}`, `--dock-tile-min`. That cascade is the seam — D15 needs ONE
multiplier the whole cascade reads, not 12 hand-tuned mobile overrides.

**The transposition:** introduce a single `--dock-scale` knob (default `1`, tokens.css §10 dock
block) and re-express the density geometry as `calc(<base> * var(--dock-scale))` at the token
edge — or, cleaner, set the per-density tokens to already-`calc`'d products so the multiplier
threads through without touching every consumer rule. Then ONE `@media (pointer: coarse)` rule
sets `.glass-dock[data-density] { --dock-scale: var(--dock-mobile-scale, 1.5); }`, and the
control box, padding, gaps, tab/trigger geometry, tile-min, and radius all grow in lockstep —
the proportion the desktop density cascade tunes is preserved, just scaled.

Concretely:
- **Retire the two existing coarse floors INTO the scale** (no legacy double-path): the
  dock.css:1405 floor and the dock-controls.css:483 floor become a single `--dock-scale`-driven
  block. At 1.5x, comfortable's 40px control → 60px and spacious's 44px → 66px, both already
  past the 44px WCAG floor, so the scale SUBSUMES the floor (the floor was a special case of
  "make it bigger on touch"; the scale is the general case). Keep a `max(…, 44px)` clamp inside
  the scaled control-size so a consumer who dials `--dock-mobile-scale` below 1.0 cannot drop
  under the WCAG target — the a11y guarantee survives as a clamp, not a parallel rule.
- **Own the icon glyph, finally.** Add `.dock-icon-button > svg { width: var(--dock-icon-glyph,
  1.25rem); height: var(--dock-icon-glyph, 1.25rem); }` (mirroring the dark-mode-toggle's
  existing `& > svg` ownership) so the glyph rides `--dock-scale` too (`--dock-icon-glyph: calc(
  1.25rem * var(--dock-scale))`). This closes the "library never sizes the glyph" gap — the
  glyph scales WITH the box instead of swimming. A consumer passing an explicit lucide size
  class still wins (utility layer > component layer), so it's a default, not a ceiling, matching
  the `.dock-tab-button` font-size comment (dock-controls.css:227-231).
- **Token-first + consumer-overridable per axis.** `--dock-mobile-scale` (the multiplier) and
  `--dock-icon-glyph` (the glyph size) are public knobs; a consumer who wants 1.3x or 1.75x sets
  one token on `:root` or a dock scope. The 1.5x is the library DEFAULT identity (per the
  presets-in-consumers precept), not a magic number sprinkled across rules.

This is one knob threaded through the existing density cascade — no new media-query sprawl, no
per-control re-declaration, no glyph special-casing per consumer. It composes with (and SUBSUMES)
the existing coarse floor rather than stacking a second mobile path. PRM is unaffected (scale is
geometry, not motion). The morph scalar (`--dock-morph-t`) and the FLIP px-measurement are
geometry-agnostic — they measure whatever natural size the scaled box produces, so the W01 morph
keeps working at 1.5x with zero changes.

  W06's close criterion (line ~338) is "a standalone DockIconButton presents a ≥44×44 hit

  different surface (glyph ownership + the whole density cascade + a new multiplier token).

  on the carved `src/styles/dock/` partials (the coarse `@media` block lands in the carved

  glyph-`svg` rule + the `--dock-scale` coarse block as a D15 ADDITION to W06's `dock-controls.css`

- **W39 (lighthouse perf/a11y route matrix)** — runs a 375×667 mobile viewport in its π audit
  but only MEASURES (Lighthouse + frontend-design verdict); it authors no dock sizing. It is the
  natural live-audit verifier that the 1.5x reads correctly on mobile, not the owner.
- **W40 (demo-shell dock-nav reaudit)** — rebuilds `SidebarDock`/`BottomDock` and explicitly

- No existing wave introduces a `--dock-scale` multiplier or sizes the dock icon glyph. **D15 is
  net-new substrate** (a coarse-pointer geometry multiplier + glyph ownership), best landed as a
  small wave trailing W06's carve, or folded into W06's `dock-controls.css` touch.

## Overfitting check

`--dock-scale` / `--dock-mobile-scale` / `--dock-icon-glyph` are exported public tokens
(token-first, consumer-overridable) → clears the bar. The glyph `> svg` rule has ≥2 consumers
(every `DockIconButton` host: speedtest dock + bbnf-buddy ToolsLayer + the demo SidebarDock/
BottomDock). No speculative substrate.

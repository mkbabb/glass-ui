# D2 — van-Gogh medium not discoverable in the aurora configurator

**Lane** D2 · **Severity** major · **Defect (USER-DEFECTS-2026-08 D2):** "Where are the
van-Gogh items?" — the W13 van-Gogh medium is not surfaced / discoverable in the configurator.
**Cross-ref** W13 (shipped the medium body), W38 (configurator restyle), W10 (atoms door + presets).

---

## TL;DR — the verdict

The van-Gogh *medium body* (W13) is real, first-class, and **IS** in the medium `<select>` of
BOTH the live atoms surface and the advanced layer. So the literal "is the option in the picker"
question is GREEN. **But the defect is real and net-new:** the user scans the most-prominent
discoverability surface — the **PresetPickerRow thumbnail strip** at the top of the aurora story —
and finds **no item that says "Van Gogh"**. The one preset literally keyed `OIL_VANGOGH` is
**labeled "Oil Swirl"** and **still bakes `medium:"oil"`** (the pre-W13 energy-graded oil), not the
new first-class `medium:"vangogh"` body. And **zero named presets use `medium:"vangogh"` at all.**

So W13 shipped the medium but left the *exposure layer* untouched: the showcase preset that should
be the van-Gogh hero was never renamed or repointed onto the new body, and the new oil-pastel body
was never given a hero preset either (the three "Pastel" presets use `oil-pastel` but the label
hides the medium). The medium is reachable only by a power-user drilling into Advanced/Atoms →
medium → "Van Gogh"; nothing in the visible chrome advertises it. **No existing wave owns this
preset-exposure/labeling seam — it fell between W13 (medium body), W10 (atoms-door structure), and
W38 (visual restyle).**

## Source-grounded diagnosis

### The discoverability surfaces (what the user actually sees)

The live aurora story (`demo/stories/substrates/aurora.vue`) presents the aurora medium through
THREE surfaces, in descending prominence:

1. **`PresetPickerRow`** (`demo/stories/aurora/PresetPickerRow.vue:64+`) — a horizontal thumbnail
   strip at the TOP of the story, keyed off `PRESET_KEYS` and labeled from `PRESET_META`
   (`v-for="key in PRESET_KEYS"`, each card shows `PRESET_META[key].label` + `.sub`). This is the
   **primary** discoverability surface — a user picks visually here.
2. **Atoms tab medium `<select>`** (`AuroraConfigDock.vue:119` → `AuroraAtomsPanel.vue:43-51,161`)
   — the DEFAULT dock surface (`dockTab` defaults to `"atoms"`), a `MEDIA` array
   `["smooth","pastel","watercolor","oil","crayon","vangogh","oil-pastel"]` rendered as raw
   `<option>`s. **Van Gogh IS here.**
3. **Advanced → Medium layer** (`AuroraConfigDock.vue:140` → `config/MediumLayer.vue` →
   `config/options.ts:13-23` `mediumOptions`, label `"Van Gogh"`). **Van Gogh IS here too**,
   behind the Advanced disclosure.

So the medium-`<select>` exposure (surfaces 2+3) is GREEN — van-Gogh and oil-pastel are both
present and correctly labeled, verified present at the defect-capture commit `e2c9995` AND at HEAD
`c075467`. The defect is the **top-of-page preset strip** (surface 1).

### The smoking gun — `PRESET_META` (`demo/stories/aurora/presets.ts:491-504`)

```
OIL_VANGOGH:    { label: "Oil Swirl",     sub: "swirl flow · directional",   medium: "oil" },
CRAYON_SUNSET:  { label: "Pastel Sunset", sub: "creamy · warm",              medium: "oil-pastel" },
CRAYON_RAINBOW: { label: "Pastel Rainbow",sub: "creamy · full spectrum",     medium: "oil-pastel" },
CRAYON_OCEAN:   { label: "Pastel Ocean",  sub: "creamy · cool",              medium: "oil-pastel" },
```

- The preset KEYED `OIL_VANGOGH` shows the user **"Oil Swirl"** — the string "Van Gogh" appears
  **nowhere a user can see**. The key is invisible; only `label`/`sub` paint.
- That same `OIL_VANGOGH` config (`presets.ts:257`, def at `:23,29`) bakes **`medium:"oil"` +
  `strokeMode:"oil"`** — the OLD energy-graded oil, NOT the new first-class `medium:"vangogh"`
  body W13 shipped. So even if you click it, you get oil, not van-Gogh. (Its palette is already
  the iconic Starry-Night indigo/cobalt/sky/yellow/cream ramp — it is *visually* the van-Gogh
  preset; only the medium + label are stale.)
- **`grep -nE "medium:\s*['\"]vangogh['\"]" demo/stories/aurora/presets.ts` → ZERO matches.** No
  named preset uses the van-Gogh body. The W13 medium ships with no hero preset.

### Why this is a W13-incompleteness, not a W13 bug

W13's gate `proof:aurora-vangogh-preset` and its "live bake of the vangogh + oil-pastel presets"
operate over a `vangogh` config the GATE constructs internally to exercise the SHADER body — NOT
the demo's named `OIL_VANGOGH` preset (W13 FileBounds touch `mediums.glsl.ts`/`brush.glsl.ts`/
`aurora.frag.ts`/`uniformBridge.ts`/`presets.ts` [the SRC `StrokeMode` union] + the proof scripts;
they do **not** touch `demo/stories/aurora/presets.ts` — the DEMO preset table). So W13 correctly
shipped + gated the medium and was live-verified GREEN against a constructed vangogh config, while
the demo's named-preset exposure layer silently stayed on pre-W13 oil. Classic
green-headless / not-surfaced-live gap (the AX cardinal lesson, at the exposure layer this time).

## The gestalt fix (architectural, no patch, no legacy)

The fix is a **demo-content reconciliation in `demo/stories/aurora/presets.ts`** — repoint the
showcase presets onto the first-class W13 mediums and surface them by name, so the prominent
PresetPickerRow strip advertises the mediums the engine now ships. This is content-truth, not a
new primitive:

1. **Hero the van-Gogh medium on its eponymous preset.** `OIL_VANGOGH` already carries the
   iconic Starry-Night palette + swirl flow — it WAS always meant to be the van-Gogh showcase.
   Repoint its config to `medium:"vangogh"` (+ `strokeOrient:"tensor"`, the painterly hug
   `resolveAtoms` already forces) and rename its `PRESET_META` label `"Oil Swirl"` → `"Van Gogh"`
   with a `sub` that reads the medium (e.g. `"vangogh · swirl-row dabs"`). The key `OIL_VANGOGH`
   itself is a clean-break rename candidate to `VANGOGH` (no backwards-compat aliases per MEMORY;
   the demo is the only consumer of these keys — `PRESET_KEYS`/`PRESET_META`/`PRESETS` are all
   demo-internal).
2. **Hero oil-pastel under its true name.** The three `CRAYON_*` keys already bake
   `medium:"oil-pastel"` but label as "Pastel" — at least one should read "Oil Pastel" in the
   label so the new deposition body is named. (And the `CRAYON_*` keys are themselves stale —
   crayon is now its own first-class medium; the keys lying about their medium is the same
   key-vs-content drift.)
3. **Optionally add a `crayon` hero preset** so the third W13 first-class medium (dry
   tooth-multiply) is also visible by name on the strip — currently NO preset uses `medium:"crayon"`
   either (the `CRAYON_*` keys all moved to `oil-pastel`).
4. **One-source the medium label.** The medium display names live in TWO places —
   `config/options.ts` `mediumOptions` (label "Van Gogh") and `PRESET_META[*].medium` (the bare
   `AuroraMedium` value). The preset `sub` could derive the human medium name from a single
   medium→label map so a future medium add can't drift a preset's `sub` stale (KISS, demo-internal).

This keeps the fix where the truth lives (the demo preset roster), mints no library primitive/token,
and makes the prominent surface advertise exactly the mediums W13 shipped. It is a content
transposition: the engine grew a van-Gogh body; the showcase roster must name and exercise it.

## 3. The gestalt fix — ONE `substrates/blob` story, sections not pages

`StoryPage` renders a vertical stack of `<StorySection>` blocks (the canonical chassis —
e.g. `goo-blob.vue` already stacks 3 sections). The consolidation is idiomatic and needs
no new primitive: collapse the three SFCs into ONE `demo/stories/substrates/blob.vue` with
five sections, each a `<StorySection label blurb>`:

1. **The lit contained droplet** — the WatercolorDot grid for the ambient/static register
   (CSS/SVG, zero GL) replacing the 4-color GL grid, so the page does not itself burn 5 contexts.
2. **Interaction** — the ONE pointer-reactive GL hero (lean-in / squash / pseudopod / click)
   + the stretch/attraction/clickImpulse sliders (folded from `blob-interaction.vue`).
3. **Mood + palette** — mood buttons driving `setMood` + the `deriveBlobPalette` seed/harmony
   controls previewed as WatercolorDots (folded from `blob-mood.vue`).
4. **Pause seam (WCAG 2.2.2)** — the `DockBackgroundToggle` `v-model:paused` section.
5. *(optional)* a one-line WatercolorDot static-register note.

**WebGL-cap discipline (binding, the W16 incident class).** The consolidated page must hold
**≤ 2 live `<GooBlob>` contexts at once** (one interaction hero + one mood hero, or a single
shared hero whose config switches per active section), with every ambient swatch routed to
`WatercolorDot` (zero GL). The README §Best-practices "reserve GooBlob for the interactive/lit
hero; route the static register to WatercolorDot" is the governing rule — a single page with
all three former heroes mounted is still well under the ~8 cap, but the static grid MUST stay
WatercolorDot. Consider a single hero whose `config` + `mood` rebind as the user scrolls/tabs
between the interaction and mood sections (the leanest context budget), or two heroes if the
demo reads better with both visible.

**No new chassis.** Do NOT invent a tabbed-sub-nav primitive — `StoryPage` + stacked
`StorySection` is the shipped pattern and reads as one coherent page. The interaction sliders
and mood buttons are existing demo-local controls, kept inline.

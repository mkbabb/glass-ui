# D4 — goo-blob too skeuomorphic (lighting/shading must be toned down)

**Lane:** D4 · **Surface:** `/substrates/goo-blob` · **Severity:** major
**Verdict:** augment-existing-wave (**W15**) — a born-RED re-tune slice, NOT a net-new wave.

## The defect (live truth)

The default GooBlob reads as a glossy, wet, plastic bead — a skeuomorphic blown-out
glass droplet, not the calm warm-cream membrane the W15 charter intended. The demo page
mounts `BLOB_CONFIG_DEFAULTS` verbatim (`demo/stories/substrates/goo-blob.vue:72`), so
what the user sees IS the shipped default identity — there is no demo-local over-tune to
blame.

## Root cause — source-grounded

The blob lighting magnitudes live in `BLOB_CONFIG_DEFAULTS`
(`src/components/custom/goo-blob/types.ts`):

```
specStrength: 0.9,      // L272 — Blinn-Phong glint weight
specShininess: 32,      // L273
rimPower: 2.5,          // L274
rimStrength: 0.5,       // L275
iridescence: 0.18,      // L262
sssScale: 0.2,          // L265
coreGlow: 0.1,          // L267
```

Two coupled problems, both at the magnitude layer (not the math):

### 1. The Blinn-Phong glint clamps to pure white (the "wet plastic" highlight)

The shader (`metaball.frag.ts:434-437`) applies an energy-conserving normalization:

```glsl
float shininess  = uSpecShininess / (1.0 + 24.0 * nVar);  // 32 at the flat dome centre
float energyNorm = (shininess + 2.0) / 8.0;               // (32+2)/8 = 4.25
float spec = pow(max(dot(N,H),0.0), shininess) * uSpecStrength * energyNorm;
```

At the glint peak (`N·H → 1`) this is `1.0 × 0.9 × 4.25 ≈ 3.83` — multiplied by the
linearized `warmCream` tint (`metaball.frag.ts:424`, linear ≈ 0.93) and ADDED in linear
space (`lin += highlight`, L462). That is a **~3.6× over-unity additive highlight** that
`clamp(linearToSrgb(lin), 0, 1)` (L465) crushes to pure white over a hard-edged spot. The
`energyNorm` factor is correct physics (it decouples the shininess and strength knobs per
the W15 [9] note), but it means `specStrength: 0.9` is NOT a "0.9 of something" — it is a
3.8× peak. The strength was never re-derived against the energyNorm; it is a raw W9.b-era
value.

### 2. Four-to-five lighting layers stack simultaneously on one small bead

A single resting frame composites: the specular glint, the Fresnel rim
(`rimStrength: 0.5`, `metaball.frag.ts:456-462`), the warm-pearl iridescence
(`iridescence: 0.18`, L371-381), the fast-SSS back-light (`sssScale: 0.2`, L394-398), AND
the Beer-Lambert core glow (`coreGlow: 0.1`, L393). Each is individually "low", but they
co-add into a busy, over-described surface — the textbook skeuomorphic tell (too many
cues for one object). The blob is ~0.14 uv radius painted; five lighting models on a
thumb-sized dome is over-shaded.

### Why it shipped — the regression mechanism

`git blame` on the lighting magnitudes:

- `specStrength`/`specShininess`/`rimPower`/`rimStrength`/`lightDir`/`rimColor` →
  **`29dd5f38`** (W9.b era, 2026-06-07 16:26) — authored when `lit` defaulted **OFF**.
  These were demo-toggle-only values, never validated as a default identity.
- W15 (`9d0ec2f7`) flipped `lit: false → true` (L269) and set the iridescence/SSS/coreGlow
  **floors** (L262/265/267) — but **carried the W9.b specular/rim magnitudes UNCHANGED**.

So W15 turned the whole stack ON without re-deriving the highlight weights for the
on-by-default case. The "tasteful low floors" the W15 charter promised
(`AX.W15…md:106-108`, "a wet warm-cream bead, not a garish thin-film") were applied to
iridescence/SSS/coreGlow but **never to the specular/rim pair** — the brightest
contributors. This is a W15 incompleteness, surfaced as a live defect. **No existing AX
wave touches `specStrength`/`specShininess`** (grep over `docs/tranches/AX/waves/`
returns zero hits) — the magnitude layer is unowned.

## Gestalt fix direction (idiomatic, no-patch, no-legacy)

This is a **default-identity re-derivation inside W15's existing surface**, not a new
mechanism — every uniform, the energyNorm math, the warm-cream tint, and the OKLCh
pipeline already exist and are correct. The transposition:

1. **Re-derive `specStrength` against `energyNorm`, not as a raw weight.** The peak
   highlight should land a contained warm gleam (target linear peak ≈ 0.4-0.6, not 3.8),
   so `specStrength` drops to ≈ 0.12-0.18 (cancelling the 4.25× energyNorm to a
   sub-unity add). Optionally clamp the linear highlight before the OETF so a worst-case
   normal can never blow to white. The glint then reads as a soft catch-light that
   *defines the dome curvature* (the W09 "rim/normal-driven highlight, not a flat bloom"
   principle, applied to the WebGL surface this time).
2. **Drop the stacked-layer count to the load-bearing two.** Keep the Fresnel rim (it
   reads the silhouette) + a whisper of core-glow; pull `iridescence` and `sssScale`
   floors DOWN further (≈ half) so the sheen is felt, not seen — one perceptual cue, not
   four. The smooth warm-cream dome plus a subtle rim is the calm membrane; the
   iridescent/SSS shimmer becomes mood headroom (excited) rather than the resting state.
3. **Soften `specShininess` (32 → ≈ 18-22)** so the glint lobe is broader/softer (wet
   plastic = tight bright spot; soft glass = wide gentle gradient), congruent with the
   Toksvig fwidth-widen the shader already does on high-variance normals.
4. **Born-RED witness:** a `proof:blob-lit-subtle` arm asserting the rendered worst-case
   highlight pixel's linear value stays sub-unity (never clamps to 255,255,255) AND the
   resting-frame mean-lightness lift over the flat-fill baseline stays under a subtle
   ceiling — the headless analogue of "toned down". This rides the W00 π-lane readPixels
   substrate the blob already uses (`proof:substrate-paints-color`).

Token-first note: the rim already reads `rimColor: "var(--foreground)"` (correct); the
re-tune is pure config-magnitude in `BLOB_CONFIG_DEFAULTS` + the optional shader highlight
clamp — no new uniform, no consumer break (a consumer wanting the glossier look passes a
higher `specStrength`).

## Not-the-cause (ruled out)

- The smin/geometry regime (W08/W15 F0) is correct and contained — not a lighting issue.
- The hover blowout is a SEPARATE defect (D5, W16 interaction) — pointer-lean/click, not
  resting shading. D4 is the *resting* skeuomorphism.
- The renderer DOM-free seam, color resolver, and OETF are all correct — the over-bright
  is purely the magnitude of `specStrength × energyNorm` and the layer-count, not a
  gamma/space bug.

# D1 — aurora configurator not idiomatic (demo-chrome arm)

**Lane** D1 · **Surface** `demo/stories/aurora/` · **Severity** major · **Verdict** augment-existing-wave (W38)

## Defect (USER-DEFECTS D1)

> The configurator design is poor + does NOT use idiomatic glass-ui / shadcn-vue /
> Tailwind components. Hand-rolled chrome instead of the library's own primitives.

This is a DEMO-CHROME defect, distinct from the LIBRARY-primitive restyle W38 already
owns. The aurora studio shell is `<Configurator>` (correct), but the controls it hosts —
the panels inside `AuroraConfigDock.vue` → `AuroraAtomsPanel.vue` + `config/*Layer.vue` —
are a SPLIT-BRAIN: half idiomatic, half hand-rolled native controls.

## Source-level root cause

### 1. `AuroraAtomsPanel.vue` is the DEFAULT surface and is 100% hand-rolled

The atoms panel is what the user sees FIRST (`dockTab` defaults to `"atoms"`,
`substrates/aurora.vue:79`). Every control is a raw native element with ad-hoc Tailwind,
NOT a library primitive:

- `AuroraAtomsPanel.vue:82-87` — native `<input type="color" class="h-8 w-full rounded">` (seed).
- `:92-99,128-135,156-163,182-189` — FOUR native `<select class="rounded border bg-card px-2 py-1">`
  (harmony, arrangement, medium, motion) — the library has **`LabeledSelect`** (a `Select`
  + `LabeledField` compound) and `Select`/`SelectTrigger`/`SelectContent`; **0 uses** in the
  aurora demo (census: `grep LabeledSelect demo/stories/aurora` = 0).
- `:101-111,115-125,138-150,165-176` — FIVE native `<input type="range">` (energy, zone
  count, noise, texture) with the value hand-formatted into a `<span>` — the library has
  **`LabeledSlider`** (already used by every `config/*Layer.vue` panel), bypassed here.
- `:80,90,101,…` — each row is a hand-rolled `<label class="grid gap-1 text-sm">` with a
  magic `text-admin-label`/`text-sm` literal instead of the `LabeledField` label+tooltip
  contract the rest of the aurora chrome speaks.

Census (`grep -cE 'type="color"|type="range"|<select'`): `AuroraAtomsPanel.vue` = **9**
native controls; `OklchStopRow.vue` = 2 (the inline hex-paste swatch, a deliberate
affordance); `PaletteLayer.vue` = 1 (the derive-seed swatch). The atoms panel is the
overwhelming offender and it is the DEFAULT-visible surface.

### 2. Enum-as-panel-nav category error (`BouncyTabs` misuse)

`MediumLayer.vue` (5×), `FlowLayer.vue` (2×), `CompositionLayer.vue` (2×), and
`AuroraConfigDock.vue` (Advanced layer switch) reach for `BouncyTabs variant="pill"` to
pick a SINGLE value out of an enum (medium, stroke-mode, flow-pattern, warp-mode). Per
CLAUDE.md §Tabs-vs-ToggleGroup: `<Tabs>`/`BouncyTabs` are for **mutually-exclusive PANEL
navigation** (`role="tablist"`, each tab reveals a distinct content panel). A 7-way medium
ENUM that mutates one canvas surface and shows no panel is the canonical **`Select`**
case (or `ToggleGroup` for a short list) — NOT a tablist. The atoms panel then makes the
OPPOSITE error for the SAME conceptual control (medium): native `<select>`. So `medium`
is rendered as `BouncyTabs` in Advanced and native `<select>` in Atoms — two non-idiomatic
renderings of one enum, neither canonical. (`AuroraConfigDock.vue`'s Atoms↔Advanced toggle
IS a legitimate `BouncyTabs` use — that one is panel-nav.)

### 3. The atoms chrome ignores the Configurator row/layer primitives

`AuroraConfigDock.vue` hand-rolls its header (`:86-98`), section dividers
(`border-b border-border/40` literals), and section labels (`text-admin-label`) instead of
composing `ConfiguratorLayer`/`ConfiguratorRow` — the library's own preset-driven controls
column. The Advanced disclosure even mis-uses `DockLayerGroup`/`DockLayer` (a DOCK
primitive — named panes with crossfade/inert) as a plain tab-content host (`:134-158`),
which is a heavier, semantically-wrong substrate than `ConfiguratorLayer`'s collapse
section. (The hand-authored `DockLayerGroup` chrome at the TOP aurora-studio level is a
documented design choice per the Configurator §Per-preset rationale; its reuse here as a
generic layer-switcher inside Advanced is the over-reach.)

### Why the gates missed it

This is exactly the AX cardinal lesson: `proof:configurator-glass-atoms` (W38) probes the
LIBRARY Configurator SFCs as rendered in the story; it does not assert anything about the
DEMO panel controls inside the `controls` slot. `proof:design-idiom-localization` scans
`src/` for arbitrary wraps, not `demo/`. Native `<select>`/`<input>` render fine headless
— only a live frontend-design read catches the off-idiom chrome.

## Gestalt fix direction (idiomatic, no patch)

Transpose the aurora DEMO controls onto the library's OWN form primitives — this is
dogfooding, not new surface:

1. **`AuroraAtomsPanel.vue`** — replace all 9 native controls: the 4 `<select>` → **`LabeledSelect`**
   (the `Select`+`LabeledField` compound, which already ships glass styling + label/tooltip);
   the 4 `<input type="range">` → **`LabeledSlider`** (identical to the pattern every
   `config/*Layer.vue` already uses); the seed `<input type="color">` → a small glass swatch
   affordance. NOTE: glass-ui ships **no color-picker primitive** today — there are 3 native
   `type="color"` sites (atoms seed, palette derive-seed, `OklchStopRow` hex-paste). If the
   swatch is to become idiomatic, that is a ≥2-consumer case for a real `ColorSwatch`/color
   primitive (RATIFY-BEFORE-IMPL — minting a library primitive is a scope class W38 forbids;
   route to a dedicated sub-wave or keep the native swatch as a deliberate hex-paste
   affordance, matching `OklchStopRow`'s documented rationale).
2. **Enum pickers** — the medium/stroke-mode/flow-pattern/warp-mode `BouncyTabs variant="pill"`
   become **`LabeledSelect`** (the canonical single-select-of-an-enum idiom per
   Tabs-vs-ToggleGroup), unifying with the atoms panel so ONE enum renders ONE way. Short
   binary/ternary enums (stroke-layers, motion) may use `ToggleGroup` if a visible segmented
   control is wanted — but never `BouncyTabs` (no panel swap). Keep `BouncyTabs` ONLY for the
   Atoms↔Advanced panel-nav (legitimate tablist).
3. **Section chrome** — `AuroraConfigDock.vue`'s hand-rolled header/dividers/labels compose
   `ConfiguratorLayer`/`ConfiguratorRow` (the library's preset-controls column), retiring the
   `border-b border-border/40` + `text-admin-label` literals onto the configurator's own
   section recipe. Drop the `DockLayerGroup`/`DockLayer` mis-use inside Advanced for a
   `ConfiguratorLayer` collapse section.

No new token, no new CVA variant (the W38 compose-only precept extends here). The single
exception requiring RATIFY is the color-swatch primitive (mint-or-keep-native).

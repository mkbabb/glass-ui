facilities should properly leverage the latex-paper lib (the sibling `../latex-paper`).
The math-paper composition + math rendering should compose that lib, NOT a hand-rolled path.

**Verdict:** `net-new-wave` — NO existing AX wave covers it. **Severity:** major.

## 1. The current hand-rolled math path (the defect, at source)

`demo/stories/compositions/math-paper.vue` (109 lines) is a **fully hand-rolled** math
surface. There is no LaTeX, no KaTeX, no real math typesetting anywhere in it:

- Display math is faked with **Unicode glyphs + `<sub>`/`<sup>`** strung inline:
  `Sₙ(x) = a₀ + ∑ <sub>k=1</sub><sup>n</sup> (aₖ cos kx + bₖ sin kx)` (`:76-89`),
  `lim<sub>n→∞</sub>`, `∫<sub>−π</sub><sup>π</sup>` (`:102-104`).
- The summation `∑`, integral `∫`, the partial-sum `S`, the `½·[f(x⁺)+f(x⁻)]` are all
  **literal characters** styled with `.fira-code` + ad-hoc `text-[1.15rem] leading-loose
  tabular-nums` (`:73-74`) — not glyphs a math renderer laid out. Sub/superscripts are not
  positioned; they sit on the text baseline as `<sub>`/`<sup>` (no nesting, no proper
  cramped style, no over/under for the sum limits).
- The "equation block" is a hand-built `border-l-[3px] bg-muted/30 px-6 py-6` div
  (`:69-95`) — a one-off recipe, not a `MathBlock` primitive.
- No cross-references, no theorem/proof environments, no equation numbering — the things a
  real paper-rendering lib provides.

**Result:** the composition reads as a *mock-up of a math paper*, not a math paper. It is
the canonical "hand-rolled where a primitive exists" anti-pattern (CLAUDE.md
component-over-class + the overfitting bar): the sibling lib that does exactly this ships,
unused.

### The other "math facilities" in glass-ui

There are **no other math facilities** in the library — grep for `katex`/`latex`/`math`

## 2. The latex-paper sibling — it exists, with a ready Vue surface

`../latex-paper` (`@mkbabb/latex-paper@0.2.1`, built `dist/` present) is the SOTA path. Its
`/vue` subpath ships exactly the primitives math-paper should compose:

- **Components** (`src/vue/index.ts`): `MathBlock`, `MathInline`, `Theorem`, `CodeBlock`,
  `PaperSection`, `PaperSectionBlocks`, `PaperSectionContent`.
- **Composables**: `useKatex` (the context-free render seam — `renderInline`/`renderDisplay`/
  `renderTitle`, KaTeX with a module-level cache), `usePaperReader`, `useSidebarFollow`,
  `useVirtualSectionWindow`, `flattenPaperSections`.
- **DI context**: `PAPER_CONTEXT` + `createRenderTitle`.
- **Theme**: `@mkbabb/latex-paper/theme` (`src/vue/theme.css`).
- **Build-time path**: `@mkbabb/latex-paper/vite` (the `virtual:paper-content` virtual
  module for whole-`.tex` papers) — NOT needed for the demo's single hand-authored snippet.

`katex` is an **optional peer** (`peerDependenciesMeta.katex.optional`), vite + vue too.

### The two integration grains the lib offers

1. **Lightweight (the right grain for the demo):** `useKatex()` returns `renderInline(tex)`
   / `renderDisplay(tex)` — pure `string → katex-html`. The demo authors the equations as
   real LaTeX strings (`S_n(x) = a_0 + \sum_{k=1}^{n}(a_k\cos kx + b_k\sin kx)`,
   `\lim_{n\to\infty} S_n(x) = \tfrac12[f(x^+)+f(x^-)]`) and renders them via
   `v-html`/`MathInline`/`MathBlock`. No `PAPER_CONTEXT`, no virtual module.

2. **Full paper (overkill here):** the `MathBlock`/`MathInline`/`Theorem` SFCs `inject
   PAPER_CONTEXT` (`MathBlock.vue:11`, `MathInline.vue:6`) — they require a provided
   `PaperContext` ({sections, labelMap, renderInline, renderDisplay, …}). Using them
   verbatim means `provide(PAPER_CONTEXT, …)` with a `useKatex`-built render pair at the
   composition root — a one-`provide` cost, fine for a self-contained demo.

## 3. The gestalt fix direction (NOT a patch)

The fix is an **architectural transposition**, not glyph-shuffling: stop hand-faking math
and compose latex-paper's render seam. Concretely:

1. **Add `@mkbabb/latex-paper` (+ `katex`) as a demo-side devDependency** of glass-ui — it
   is a DEMO composition, so the lib goes in the demo/dev surface, NOT a runtime/peer dep of
   the published library (math typesetting is not a glass-ui library concern; the
   substrate-with-consumer bar is met by the single demo consumer, which is the correct
   altitude — a demo-private compose, like `useStoryDemo`). The sibling resolves via the
   contract-v2 dev-resolution path (`docs/precepts/cross-repo-dev-resolution.md`) the same
   way `@mkbabb/keyframes.js`/`value.js` already do (vite.config.ts §contract-v2 note).

2. **Rewrite `math-paper.vue` to author equations as LaTeX** and render via latex-paper.
   Two viable shapes:
   - **Minimal:** `const { renderInline, renderDisplay } = useKatex()` at the script root,
     drop the Unicode `∑`/`∫`/`Sₙ` + `<sub>`/`<sup>` salad, and emit `<span v-html=
     "renderInline('f')">` / a display block via `renderDisplay('S_n(x)=\\dots')`. Delete the
     hand-built `border-l-[3px] bg-muted/30` equation div in favour of latex-paper's
     `MathBlock` (which already owns the equation-rail recipe).
   - **Fuller (recommended for a "real paper" feel):** `provide(PAPER_CONTEXT, ctx)` (ctx
     built from `useKatex`) and use `<MathBlock tex="…" numbered :number="…"/>`,
     `<MathInline tex="f"/>`, and a `<Theorem>` for the du Bois-Reymond statement — the
     Dirichlet–Jordan criterion becomes a real numbered display equation, the inline `f`/
     `[−π,π]`/`S_n` become real KaTeX, and the blockquote/criterion become first-class
     environments. This is the composition that actually demonstrates the library.

3. **Token-bridge latex-paper's theme onto glass-ui's tokens — do NOT import its theme.css
   raw.** latex-paper's `theme.css` is authored against the **legacy `hsl(var(--token))`
   pattern** (`.paper-ref { color: hsl(var(--primary)) }`, `hsl(var(--border) / 0.4)`, etc.)
   — the EXACT double-wrap CLAUDE.md forbids ("NEVER `hsl(var(--token))`; the token is
   already a color"). glass-ui's tokens are complete `hsl()` colors, so importing
   latex-paper's theme.css verbatim would **never paint** (the `hsl(hsl(…))` is invalid).
   The demo must re-express the few math/theorem rules it needs in glass-ui's idiom (`color:
   var(--primary)`, `color-mix(in srgb, var(--border) 40%, transparent)`) — a small,
   demo-private CSS surface that composes the existing `paper-grain-overlay` /
   `.paper-texture` backdrop. KaTeX's own stylesheet (`katex/dist/katex.min.css`) is
   imported as-is (it is self-contained, font-metric CSS — not token-bearing).
   **This is a Tailwind-first / token-first re-expression, the same precept that governs any
   imported standalone CSS (MEMORY feedback_tailwind_first).**

4. **Cross-ref paper-backdrop / cards.css paper-texture (already aligned, keep).** The story
   already wraps the article in `paper-grain-overlay` (`math-paper.vue:15`) — that is the
   correct glass-ui paper substrate. The fix KEEPS the glass-ui paper chrome (the grain
   overlay + `bg-card/60 backdrop-blur-sm` rounded-card frame) and swaps only the MATH body
   from hand-rolled glyphs to latex-paper-rendered KaTeX. No change to `PaperBackdrop.vue`,
   `paper.css`, or `cards.css` is needed — the math layer composes ON the existing paper
   substrate.

**Upstream note (do NOT absorb into this wave):** latex-paper's `theme.css` shipping the
`hsl(var(--token))` legacy pattern is an UPSTREAM `../latex-paper` defect — file it to the
latex-paper repo (it is the same never-paint class the W34 ledger flags in consumers). This
wave does NOT edit latex-paper source; it routes around the broken theme by re-expressing
the rules demo-side. If latex-paper later token-modernizes its theme + emits a glass-ui-
compatible skin, the demo can import `@mkbabb/latex-paper/theme` directly.

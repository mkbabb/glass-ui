# D13 — dock persistent controls + proportion + dividers

**Defect (USER ledger D13, major):** "The dock controls should PERSIST on the dock.
Structure the vertical + horizontal docks for better persistent elements, a better
sense of proportion, and proper dividing lines."

**Scope:** `src/components/custom/dock/{GlassDock.vue, DockLayerGroup.vue, DockLayer.vue}`
+ `src/styles/dock.css` (+ the `dock/*.css` partials after the W06 carve).
**Cross-ref:** W06 (dock storybook + honest rail + dock.css split), W40 (demo nav shell).

---

## Three distinct sub-defects, source-grounded

### D13-a — there is NO "persistent control" concept (the headline)

The horizontal dock is a strict **two-layer crossfade**: `dock-layer--full` (the default
slot — the WHOLE expanded control set) and `dock-layer--summary` (the `#collapsed` slot).
On collapse the `--full` layer goes `inert` + `position:absolute` (out of flow) and the
`--summary` pane becomes the only in-flow content (`GlassDock.vue:488-507`;
`dock.css:611-623`). **Every** control vanishes into a single summary glyph — nothing
PERSISTS through the morph. The only way a consumer keeps a control visible while
collapsed today is to hand-duplicate it into BOTH the default slot AND the `#collapsed`
slot (the demo's `<Home>` in both, `dock.vue:85` + `:90-92`) — a manual, drift-prone
double-authoring, not a persistent-element contract.

This is the literal ask "controls should PERSIST." The iOS dock / Now-Playing / Stage
Manager idiom the dock evokes has a STABLE rail of always-present affordances (the
transport buttons, the gear) with an expand-on-demand content region beside them. The
glass-ui dock collapses the entire control set to a single icon, so the persistent-rail
read is structurally impossible without duplication.

Root cause: the `outerActiveLayer` model (`GlassDock.vue:261-263`) is binary
(`"full" | "summary"`) — the dock has NO third region for controls that live in BOTH
states. The morph orchestrator (`dockMorphContext.ts`) crossfades the two panes whole;
there is no persistent slot threaded through the FLIP.

### D13-b — H and V docks have NO proportion/structure parity

The horizontal dock is the fully-modelled surface: density tiers (`dock.css:222-306`),
the `--dock-expand-t` single-scalar morph (padding/radius/shadow co-interpolate), the
two-layer grid. The vertical dock is a **thin wrapper**: `orientation === "vertical"`
forces `alwaysExpanded` (`GlassDock.vue:188-193`) and the template drops the two-layer
grid for a single bare `<slot />` (`:509-511`). `.glass-dock.vertical`
(`dock.css:463-491`) is a plain `inline-flex` column with `gap:0.25rem` HARDCODED — it
does NOT read the density `--dock-layer-gap`/`--dock-padding-*` cascade the horizontal
dock tunes, so a `density="spacious"` vertical dock looks identical to `compact`. The
vertical dock has no summary/persistent structure, no proportion model, no morph. The two
orientations are architecturally lopsided — exactly "structure the V + H docks for a
better sense of proportion."

The `instrument-strip`/`rail` variants further force-vertical (`GlassDock.vue:168-172`)
but inherit the same bare single-slot body, so a multi-section vertical dock has no
in-built sectioning rhythm.

### D13-c — the divider is a raw CSS-class `<div>`, axis-blind (component-over-class violation)

"Proper dividing lines" today = a hand-placed `<div class="dock-separator" />` the
consumer authors inline (5 sites across `demo/stories/navigation/dock.vue`,
`dock-layers.vue`, `compositions/dock-with-slider.vue`). `.dock-separator`
(`dock.css:1174-1180`) is hardcoded `width:1px; height:var(--dock-separator-height)` —
a VERTICAL hairline. In a VERTICAL dock (column flex) this paints a 1px-wide,
half-height sliver floating in the column gap — it does NOT divide the stack (a vertical
dock needs a HORIZONTAL rule: `height:1px; width:<inline-extent>`). The separator is
**axis-blind** and **not a component** — it violates the house component-over-class
contract (interactive/structural elements that bundle a state/axis contract are
components; only static decoration is a bare class). There is no `DockSeparator` export
in the `/dock` barrel (`dock/index.ts`). `.dock-spacer` (`dock.css:1182-1184`,
`@apply flex-1`) is the same anti-pattern (a hand-placed flex-grow `<div>`).

Additionally `--dock-separator-height` (`dock.css:83`,
`calc(var(--dock-h, var(--size-icon-btn)) * 0.5)`) reads `--dock-h`, which is **never
defined** anywhere in the dock CSS — the fallback `--size-icon-btn` always wins, so the
"track separator to the dock height" intent is dead (same dead-fallback class as the W06
USF-2 `--dock-icon-padding`).

## Gestalt fix direction (architectural transposition, no patch)

ONE coherent restructure of the dock's region model — turn the binary `full|summary`
crossfade into a **three-region morph** with a first-class divider primitive, applied
symmetrically to both axes.

**1. A persistent region (`#persistent` slot).** Thread a THIRD region through the morph
orchestrator that lives in flow in BOTH `collapsed` and `expanded` states (never `inert`,
never crossfaded out). The dock becomes `[persistent][divider][morph-region]` where the
morph-region is the existing `full↔summary` crossfade. The persistent rail is the
always-present affordances (transport/gear/home); the morph-region is the expand-on-demand
content. This is the Now-Playing mini-bar idiom done structurally — no double-authoring
into both slots. The `outerActiveLayer` model stays binary for the MORPH region; the
persistent region sits OUTSIDE the crossfade, co-laid by the root flex/grid. Retires the
`<Home>`-in-both-slots duplication the demo currently needs.

**2. H/V proportion parity.** Make `.glass-dock.vertical` read the SAME density cascade
(`--dock-padding-*`, `--dock-layer-gap`) the horizontal dock tunes — delete the hardcoded
`gap:0.25rem`/`padding` and route through the density tiers, so `density` paints
identically on both axes. Give the vertical dock the same three-region structure (the
persistent rail + divider + content stack) so a multi-section vertical dock has built-in
rhythm rather than a bare slot. The proportion is one token ladder, both orientations.

**3. `<DockSeparator>` component (component-over-class).** Promote `.dock-separator` to a
`<DockSeparator>` primitive that reads the dock's `orientation` via
`useOptionalDockContext()` (already provided, `dockContext.ts`) and paints a vertical OR
horizontal hairline accordingly — a 1px rule perpendicular to the layout axis, sized to
the cross-extent, off the `--surface-tint-*` ladder. KISS: it is a thin oriented `<div>`
that bundles the axis contract the raw class cannot. Fix the dead `--dock-h` fallback (or
delete it for a token that resolves). The same axis-aware treatment gives `<DockSpacer>`
or just keep `.dock-spacer` as a true decoration class (a flex-grow gap is genuinely
static — defensible as a class; the SEPARATOR is not, because it carries an axis contract).
Export `DockSeparator` from the `/dock` barrel; migrate the demo sites off the raw class.
The W06 carve then relocates the SETTLED separator rule, and W40 consumes the component.

All three folds are one region-model restructure — gestalt, not three patches. The morph
orchestrator already factors the FLIP; the persistent region is a new registration class
on the SAME spring (no second clock), consistent with W02's one-orchestrator design.

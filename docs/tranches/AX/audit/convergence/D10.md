# D10 — destructive / alert unreadable in dark mode

**Lane** D10 · **Severity** major · **Verdict** net-new-wave · **Surface** `src/styles/tokens.css` (the `.dark`
+ `light-dark()` destructive arms) · **Live witness** the "Session expired" Alert (screenshot 15.02.13):
dark-red text on near-black card, illegible.

---

## Root cause (source-grounded)

glass-ui's dark `--destructive` is the **unmodified shadcn-vue STOCK dark-destructive value**, minted at AQ.W2
(`659458b feat(styles): AQ.W2 color/theming`). Two co-located declarations carry it:

- `src/styles/tokens.css:1460` — `--destructive: light-dark(hsl(0 72% 50%), hsl(0 62.8% 30.6%))` (the
  `@supports (color: light-dark())` enhancement arm)
- `src/styles/tokens.css:1582` — `--destructive: hsl(0 62.8% 30.6%)` (the `.dark` class fallback floor)
- `src/styles/tokens.css:1461` / `:1583` — `--destructive-foreground: hsl(48 10% 90%)` (off-white)

The shadcn dark value `hsl(0 62.8% 30.6%)` is calibrated for ONE role only: a **saturated PLATE with a light
foreground on top** (`bg-destructive text-destructive-foreground`). At L≈30.6 it is intentionally dark so the
off-white glyph rides it at high contrast. It was NEVER calibrated to be used AS foreground text.

But glass-ui's **Alert destructive variant uses `--destructive` as the TEXT color over a card**, by design
(AW.W25 "content-band, not a loud saturated plate"):

`src/components/ui/alert/index.ts:14`
```
destructive: 'text-destructive bg-card [&>svg]:text-current *:data-[slot=alert-description]:text-destructive/90'
```

So in dark mode the alert paints `--destructive` text (`hsl(0 62.8% 30.6%)`, L≈30.6) over `--card`
(`hsl(24 8% 10%)`, L≈10) — a dark red on near-black. **This is the defect.**

### Computed WCAG 2.1 contrast (dark mode, sRGB relative luminance)

| Surface | fg | bg | ratio | floor | verdict |
|---|---|---|---|---|---|
| **Alert destructive TITLE** (`text-destructive`) | `--destructive` `hsl(0 62.8% 30.6%)` | `--card` `hsl(24 8% 10%)` | **1.75:1** | 4.5:1 | **FAIL** |
| **Alert destructive DESCRIPTION** (`text-destructive/90`) | `--destructive`@90% | `--card` | **1.62:1** | 4.5:1 | **FAIL** |
| error PLATE vs page (graphic distinctness) | `--destructive` | `--background` `hsl(24 8% 6%)` | **1.91:1** | 3.0:1 | **FAIL** |
| Notification/Toast/Badge error TEXT (off-white on plate) | `--destructive-foreground` `hsl(48 10% 90%)` | `bg-destructive/90` over page | 8.84:1 | 4.5:1 | pass |
| Toast/Badge error TEXT (solid plate) | `--destructive-foreground` | `--destructive` | 8.10:1 | 4.5:1 | pass |

Light-mode reference (for parity): Alert destructive text over `--card` = **4.69:1** (passes). The defect is
**dark-mode-ONLY** — the light token `hsl(0 72% 50%)` clears the floor; the dark token does not.

Two distinct failure modes, ONE root token:
1. **Text-on-card (Alert, Label `required *`, ComboboxInput `aria-invalid`, glass `.input-pill` invalid ring,
   `--field-label-color`)** — all read `--destructive` AS ink. All fail in dark (1.75:1).
2. **Plate distinctness** — the red plate itself is only 1.91:1 against the black page, so even where the
   off-white-on-plate text passes, the plate reads as a muddy dark rectangle barely lifted off the page (the
   "unreadable dark-red on black" the user described).

## The tension (why this is not a one-line bump)

`--destructive` is dual-role: it is BOTH the plate background (Toast/Badge/Notification/Button-destructive)
AND the foreground ink (Alert/Label/invalid rings). Lifting its L to clear text-on-card erodes off-white-on-
plate, because brighter red → less headroom for the off-white glyph:

| candidate `--destructive` (dark) | text over `--card` | off-white over it (plate) | plate vs page |
|---|---|---|---|
| `hsl(0 62.8% 30.6%)` (HEAD) | 1.75 **FAIL** | 8.10 | 1.91 **FAIL** |
| `hsl(0 75% 55%)` | 4.02 (large-text 3:1 ok; body marginal) | 3.52 | 4.40 |
| `hsl(0 80% 60%)` | 4.60 **pass** | 3.07 (marginal) | 5.03 |
| `hsl(0 80% 65%)` | 5.32 **pass** | 2.66 **FAIL** | 5.81 |

A single mid value (~L60) makes text-on-card pass AND keeps the plate distinct, but pushes off-white-on-plate
toward 3:1 — the off-white foreground would no longer be the right partner for a brighter plate. The clean
gestalt is therefore **not** "pick a compromise red" — it is to RESOLVE the dual-role, the same two-token
discipline glass-ui already uses for `--chart-{phase}` vs `--chart-{phase}-label` (canvas hue vs label hue)
and for `--warning` vs `--warning-foreground` (luminous plate + dark glyph).

---

## Gestalt fix direction (net-new wave)

A small token-first transposition in `tokens.css`, dark-arm-only, no component edits, no new component props:

1. **Lift the dark `--destructive` to a brighter red** so the PLATE reads as red against the black page and
   the plate stays the saturated-plate role (e.g. `hsl(0 ~72% ~58–60%)` — clears the 3:1 graphic floor vs
   page at ~5:1 and keeps the off-white `--destructive-foreground` over it ≥3:1 for large glyph text; the
   exact L ratified against the live π-lane contrast pass). This is the SOURCE for the plate surfaces
   (Toast/Badge/Notification/Button-destructive) which all use `bg-destructive` + `--destructive-foreground`.

2. **Mint a dark-aware destructive-TEXT token for the ink role**, the chart-label precedent: a
   `--destructive-text` (or fold into a single `--destructive` that is already AA-as-text — the simpler path
   if a lifted red clears BOTH 4.5:1-over-card AND keeps the plate role; at L≈60, `hsl(0 80% 60%)` is 4.60:1
   over card AND 5.03:1 vs page — a SINGLE value can satisfy both the body-text floor and the plate
   distinctness, leaving only the off-white-on-plate at 3.07:1 which is fine for large glyphs/icons but
   should be RATIFIED for body label text). Decide at ratify whether ONE lifted token suffices (preferred —
   one path) or the two-token split is needed; the math says a single `hsl(0 80% 60%)` is the cleanest
   single-token candidate that clears every consumer EXCEPT body text directly on the saturated plate (which
   no glass-ui surface does — plates carry large glyph/short-label text, not body copy).

3. **Update both arms in lockstep** — the `light-dark()` enhancement arm (`:1460`) AND the `.dark` fallback
   floor (`:1583`), keeping them in agreement per the §2c fallback-floor contract. Light arm UNCHANGED
   (already 4.69:1).

4. **Sweep the sibling reds for the same dark-text-on-surface trap** — `--like`/`--delete`/`--accent-red`
   are oklch and brighter in dark, but the audit should confirm any that are consumed as text-over-card
   (currently they are plate/icon hues, lower risk) clear AA; record the disposition.

Token-first, component-over-class preserved: ZERO Alert/Notification/Toast SFC edits, ZERO new props — the
fix re-resolves every `text-destructive` / `bg-destructive` site library-wide from one token override. The
born-RED→GREEN witness is a **π-lane `axe-core` `color-contrast` + readback** over the Alert-destructive /
Notification-error / Toast-destructive surfaces under `.dark` at ≥3 viewports (the same π lane W00 stands up).

## What BouncyTabs actually is (the motion topology)

`BouncyTabs.vue` is a 44-line shim — it forwards every prop to `BouncyToggle` with `:multi-select="false"`
and narrows the emit. ALL motion lives in `BouncyToggle.vue`. There are **two independent motion paths**, and
they must be diagnosed separately:

1. **The slider glide** (the active-pill that slides between tabs). CSS-driven.
   - Anchor engine (single-select): `.bouncy-slider--anchor { transition: inset var(--duration-normal)
     var(--spring-snappy) }` (BouncyToggle.vue:373) — the browser interpolates `inset` between the active
     button's `anchor-name`. **CONTROL register, ~+6.8% overshoot — correct, smooth, not the defect.**
   - JS fallback engine: `.bouncy-slider--js { transition: transform … var(--spring-snappy), width …
     var(--spring-snappy), opacity … ease }` (BouncyToggle.vue:350-355), driven by `useBouncySlider`'s
     `offsetLeft`/`offsetWidth` measure. Same CONTROL register. **Not the defect.**

2. **The press bounce** (the button's own scale-pop on click). WAAPI-driven — `animatePress()`
   (BouncyToggle.vue:125-155). **THIS is the jarring motion.**

The slider glide is already smooth and governed. The egregious feel is the **press bounce**.

## Root cause — the press bounce double-springs (BouncyToggle.vue:143-154)

```js
btn.animate(
    [
        { transform: "scale(1)" },
        { transform: `scale(${press})`, offset: 0.25 },   // press = --scale-press = 0.96
        { transform: `scale(${hover})`, offset: 0.7 },    // hover = --scale-hover = 1.08
        { transform: "scale(1)" },
    ],
    { duration: 200, easing },                            // easing = --spring-bouncy
);
```

The motion is **abrupt because it composes an overshoot ON TOP OF an overshoot**:

- The **keyframe TRACK is already an overshoot shape**: `1 → 0.96 → 1.08 → 1`. The +8% pop at offset 0.7
  (`--scale-hover` = 1.08, tokens.css:1090) is a hand-authored bounce on top of the press dip.
- The **easing then applies a spring `linear()` register over that track**. `--spring-bouncy`
  (tokens.css:164) is itself an overshooting spring (analytic peak ~+20.5%, `linear()` peak ~1.205). A
  `linear()` easing function is applied **between every adjacent keyframe pair** — so the segment
  `0.96 → 1.08` is itself overshot by the bouncy spring, and the segment `1.08 → 1` rings past 1.0 again.
- Net: the glyph snaps down, springs up past 1.08, rings, and resettles — **all in 200 ms**. The compressed
  duration + the compounded overshoot is what reads as "egregious / abrupt" (the W05 SOTA restraint rule it
  cites: bounce>0.4 reads "too exaggerated for a UI element"; here the *effective* bounce is the product of
  two overshoots, well past that floor).

This is the canonical anti-pattern: **a keyframe array that bakes positional overshoot AND a spring easing
that adds its own overshoot.** You author overshoot ONCE — either as the keyframe-position shape with a
monotonic ease, OR as a 2-keyframe `scale(1)→scale(press)→scale(1)` track with a spring easing that supplies
the rebound. Never both.

A secondary contributor: `--scale-hover` (1.08) is a **HOVER-state token** mis-recruited as the press
*rebound peak*. The press recovery should not pop to the hover-grow size — it should settle to rest (1.0).
Using the hover scale as the rebound peak is what makes the pop read as a "grow", not a "settle".

## Why W05 did NOT fix this (and is still the right home)

W05 (COMPLETE) is the covering wave for the spring-*vocabulary* axis, and it **explicitly handled this very
line**: it re-pointed `BouncyToggle.vue:135` `readToken("--ease-apple-spring", …)` → `readToken("--spring-bouncy",
…)` and recorded in `W05-one-ios-spring-vocabulary.json` the close note *"BouncyToggle still bounces (PLAYFUL
— overshoot survives the map)"*. W05's mandate was *register coherence* (excise the legacy apple-spring
bezier, one governed `--spring-*` source). It deliberately **kept the bounce shape** — the +27.5% apple-spring
was even swapped for a *lower* overshoot (`--spring-bouncy` ~+20.5%), so W05 made it marginally calmer but
left the **double-spring keyframe topology untouched**. D3 is the post-W05 live-truth observation that the
register swap was necessary-but-insufficient: the abruptness is the *keyframe shape × easing* composition,
not the easing register alone.

W05 is the right home because (a) it already owns this exact file+line and the surface-class register map,
(b) the fix is a motion-shape correction in the SAME spring-governance frame W05 established, and (c) W05's
HardGate already runs the VISUAL-TRUTH live audit on "BouncyToggle still bounces" — that audit clause is
exactly where "still bounces but is now SMOOTH not abrupt" belongs. A net-new wave would fork the
spring-governance story across two waves.

## Gestalt fix direction (no patch, no hand-rolled curve)

**Collapse the press feedback to a single overshoot source — the governed spring supplies the rebound; the
keyframe track stops baking its own.** Concretely:

1. **Drop `--scale-hover` (1.08) from the press keyframes.** Author the press track as the iOS press-squish
   shape `scale(1) → scale(--scale-press) → scale(1)` (down-and-settle), and let `--spring-bouncy`'s tail
   supply the single, governed rebound past 1.0. The peak overshoot is then the spring's ~+20.5% ONCE, not
   the product of two. (This also removes the semantic error of recruiting the hover token as a press peak.)

2. **Reach for the CONTROL register, not PLAYFUL, for a tab press.** A configurator tab is a *structural
   control*, and W05's own SOTA restraint rule (facets 5/14/16/18, quoted in W05) is explicit: "structural
   morphs ride the CONTROL register, never bouncy … bounce>0.4 reads too exaggerated for a UI element …
   reserve bouncy for deliberate emphatic one-shots (dialog entrance, success)." A tab-toggle clicked dozens
   of times in the aurora configurator is the textbook high-frequency action that W05 says must NOT be
   bouncy. The press should ride `--spring-snappy` (CONTROL, ~+6.8%) — matching the slider glide it sits
   beside, so the press and the glide read as ONE coherent motion instead of two competing springs. (RATIFY
   at the visual audit: if the toggle genuinely *wants* playful emphasis as a brand signature, keep
   `--spring-bouncy` but ONLY after the double-spring is collapsed — single-overshoot bouncy may already
   read fine. The double-spring is the non-negotiable defect; the register is the RATIFY dial.)

3. **Lengthen the duration off the cramped 200 ms.** A spring needs room to settle; 200 ms forces the ring
   into a snap. Read `--duration-fast` (0.2 s) / `--duration-normal` (0.3 s) from the cascade (the WAAPI path
   already token-resolves scale via `readToken` — resolve the duration the same way) rather than the
   hardcoded `200` literal, and prefer `--duration-normal` so the governed spring has room to settle
   smoothly. (Idiomatic: WAAPI `duration` is a number, so resolve the ms from the duration token at runtime,
   the same `readToken` pattern already in the file — no new hand-rolled value.)

The combined effect: ONE governed overshoot, on the register that matches the surrounding glide, with enough
duration to settle — the abruptness comes from the compounded-overshoot-in-200ms, and removing the second
overshoot source is the architectural fix, not a magic-number tweak.

## Scope / overfitting

`BouncyToggle` is exported (`src/components/custom/tabs/index.ts`) and consumed by `BouncyTabs` + directly
across the aurora configurator (AuroraConfigDock, MediumLayer, FlowLayer, CompositionLayer) and
`demo/stories/navigation/tabs.vue`. The press bounce fires on EVERY config-tab click — which is precisely why
the user flagged it as egregious on the configurator surface (D1's surface). The fix is one `animatePress()`
rewrite + (optionally) the register/duration token reads; zero new tokens, zero new files. Cross-checked: no
literal-scale gate violation is introduced (the WAAPI keyframes already resolve from the `--scale-press*`
cohort via `readToken`, so `proof:animation-coherence`'s press-fork detector stays GREEN — it never saw the
*shape* defect, only literal scales).

# BF.W-LIQUID-GROW-ON-EVENT — the dock/sheet grows + shrinks under the user's hand (scroll · touch)

**Band 3 · Tier T6 · depends: W-DOCK-INTEGRATE**

## The defect / the ask

The audit's DEFERRED-CENSUS **D20** (SEED §1 **R14** "Growing/shrinking on events (scroll, touch)", status **NOT BUILT**). The dock is event-INERT: there is no scroll-condense (the dock does not shrink as the page scrolls down and re-grow at the top — the iOS-27 Safari URL-bar / Apple-Music mini-player condense), and no touch-drag-to-grow (you cannot PULL the dock/sheet bigger with your finger). The library's own scroll + press primitives are unused for this. Three concrete gaps, each against a shipped primitive the wave must COMPOSE (never re-fork):

- **No scroll-condense.** `src/styles/scroll-choreography.css` ships the native `scroll()`/`view()` choreography substrate (`.scroll-build`/`.scroll-cascade`/`.scroll-pin`/`.smooth-scroll`, all `@media (prefers-reduced-motion: no-preference)` + `@supports (animation-timeline: …)`-gated, compositor-only) — the EXACT idiom a scroll-driven `--grow` scalar belongs in. NO dock surface binds a `scroll()` timeline today; `grep -rn "scroll-condense\|--dock-grow" src/` returns ZERO.
- **No touch-drag-to-grow.** `src/composables/motion/useDragMorph.ts` (`:153`, the grab-pull gesture — pointer-capture follow + velocity-squish + fling-to-nearest single-commit) and `src/composables/motion/useLiquidPress.ts` (`:122`, the interruptible coupled spring-press exposing `pressStyle` + `handlers`) are SHIPPED and unused by the dock/sheet for a grow gesture. The bloom sheet/player cannot be pulled bigger.
- **No event-feed into the dock registry.** `src/components/custom/dock/composables/useDockState.ts` is the ONE dock state machine (`"collapsed" | "hover" | "pinned"` + the `keepOpen`/`release` ref-counts + the `AZ.W-DOCK-FLICKER` hover hysteresis). A scroll-condense state is a NEW input to THIS machine, not a second machine beside it (the one-registry discipline — a parallel scroll state desyncs against `expanded`/`isHeld`).

The ask is: the dock/sheet GROWS and SHRINKS reactively — it condenses as you scroll the page down (re-grows at the top) and you can PULL it bigger with your finger — built by COMPOSING the shipped scroll-choreography substrate + `useDragMorph`/`useLiquidPress` + extending the ONE `useDockState` registry, compositor-only and PRM-carved.

## The mechanism

ONE inheriting `--dock-grow` scalar drives the whole geometry; two event sources FEED it (scroll-driven CSS + a touch gesture), and the dock registry carries the condense STATE — never a second machine, never a re-forked loop.

1. **Mint the `--dock-grow` typed scalar (the ONE grow axis).** Register `@property --dock-grow { syntax: "<number>"; inherits: true; initial-value: 1; }` in `src/styles/tokens/property-regs.css` §18 (the `--glass-level`/`--glass-depth`/`--dock-morph-t` cascading-scalar precedent — a bare `var()` snaps between scroll frames; the `@property` reg lets it INTERPOLATE). `1` = full size (the rest identity, byte-identical to today), `→0.7` = condensed. The dock/sheet box reads it as a COMPOSITOR transform ONLY — `transform: scale(var(--dock-grow))` over a RESERVED settled footprint (the BB.W-DOCK-MORPH-FAMILY discipline the dock already speaks: reserve the `to` footprint once, drive the live scalar on `scale`, transform-origin at the pinned edge — NEVER an animated `inline-size`/`block-size`/`padding`). The glyph/label legs read `--dock-grow` only through the same transform (no font-size animation). DISTINCT from `--dock-morph-t` (V↔H orientation) and `--dock-scale` (the density multiplier) — grow is the event-reactive size axis, disjoint.

2. **Scroll-condense — bind `--dock-grow` to a `scroll()` timeline (the scroll-choreography idiom).** Add a `.dock-condense-on-scroll` recipe to `scroll-choreography.css` (the cascade home for scroll-driven recipes) under the SAME outer-gate discipline the file already enforces (`@media (prefers-reduced-motion: no-preference)` + `@supports (animation-timeline: scroll())`): a `@keyframes gl-dock-condense { from { --dock-grow: 1 } to { --dock-grow: var(--dock-grow-condensed, 0.78) } }` bound `animation-timeline: scroll(nearest block)` with `animation-range: 0 var(--dock-condense-range, 240px)` — so the dock condenses across the first ~240px of scroll then holds. The dock consumer (`<GlassDock>` shell, the bloom sheet) adds the class; the named scroll-source is the app `<main>` scroller (the `scroll(nearest)` resolves the dock's own scroll-port ancestor). Compositor-only (the keyframe animates ONLY the registered `--dock-grow` custom property, which resolves onto `transform: scale` — `proof:no-layout-animation` holds; a `@property`-registered custom that resolves onto a compositor channel is in the compositor-safe set the gate already allows for `--dock-morph-t`/`--progress-crescendo`). Under PRM the whole register never binds (the outer gate) so the dock renders at full size — the genuine P6 read (the condense is non-essential motion; a scrolling user under reduce keeps the dock at rest size, NOT a layout jump).

3. **Touch-drag-to-grow — compose `useDragMorph` on the bloom sheet/player.** Wire `useDragMorph` (`:153`) onto the sheet's grip with a SINGLE morph axis (the block axis) and two snap targets — the condensed endpoint (`--dock-grow: condensed`) and the full endpoint (`--dock-grow: 1`) — resolved off the sheet's live geometry. The grab follows the finger, the velocity-squish swells the plate (capped LOW via the shared `--tab-indicator-max-stretch` getter the drag-morph already reads), and the fling-to-nearest commits the grow state via `onSnap(value)` which writes `--dock-grow` (the single-commit `committed` guard). The press-grow micro-gesture on the dock CONTROLS composes `useLiquidPress` (`:122`) — its `pressStyle` writes the consumer-named `--dock-press-t` drive the dock control's gleam already reads (the W-BUTTON-GLASS coupling precedent). ONE squish writer (both primitives compose `useLiquidFlex`); NO hand-rolled pointer-velocity sampler (the no-second-engine fence — `useDragMorph` owns the gesture; a forked `pointermove` sampler REDs the gate).

4. **Extend `useDockState` with a condense STATE-FEED (one registry).** Add to `useDockStateOptions` an OPTIONAL `condensed?: Ref<boolean>` (or a `growProgress?: Ref<number>` feed) the scroll/drag sources WRITE, and expose a derived `growScalar`/`condensed` on `UseDockStateReturn` — so `expanded`/`isHeld`/`condensed` are ONE coherent state object, not a parallel ref the box reads beside `useDockState`. The condense feed NEVER fights the collapse machine: a condensed dock is still `pinned`/`hover` (condense is a SIZE axis, not the collapse axis); the existing `AZ.W-DOCK-FLICKER` hysteresis + `keepOpen` ref-counts are byte-untouched (the condense write is additive, not a new transition in the state graph). This is the SEED §2.2 one-registry bar: the scroll-condense + the drag-grow + the press feed ONE `useDockState`, never a second machine.

Compositor-only throughout (transform/opacity/filter + the `--dock-grow`/`--dock-press-t` registered customs — never a layout property; `proof:no-layout-animation` scans `src/styles` + `src/components` + `demo/stories/**`). PRM-carved: the scroll recipe never binds under reduce (outer gate); `useDragMorph`/`useLiquidPress` carry their own `respectReducedMotion` snap (instant grow-state commit, no squish frames). Born consumer of the shipped scroll substrate + `useDragMorph` (its existing consumers: SegmentedTabs `:draggable`, DockLayerGroup pull-to-switch) + `useLiquidPress` (Button, `<Card :pressable>`).

# BF.W-ICON-PRESENCE — the DockStack glyph reads + the receding facet keeps a legibility floor

**Band 3 · Tier T6 · depends: W-DOCK-INTEGRATE**

## The defect / the ask

The audit's CHRONIC #18 (DEFERRED-CENSUS **D18**, `chronic ✓`; SEED §1 **R12** "Icons not visible enough", status **PARTIAL / REGRESSED**). Two concrete legibility defects on `DockStack`, both against the source:

- **The glyph is too small AND below the library's own register.** `src/components/custom/dock/DockStack.vue` paints the core glyph `<component :is="CoreIcon" class="size-4" .../>` (`:187`, 16px) and each member glyph `<component :is="item.icon ?? CoreIcon" class="size-4" .../>` (`:234`, 16px). Worse, the CSS `src/styles/dock/stack-rail.css:251` `.dock-stack-fan .dock-stack-member svg { inline-size: 0.875rem; block-size: 0.875rem }` OVERRIDES the member glyph DOWN to **14px** — below even the Tailwind `size-4`. Meanwhile the library's nav-icon register `--dock-icon-glyph` (`src/styles/tokens/sizing.css:240`) is `max(calc(--dock-layer-height × --dock-icon-glyph-ratio), --dock-icon-glyph-floor)` ≈ **20px** (a `0.5` ratio of the ~2.5rem layer height, 16px WCAG floor) — the size the dock-icon-button family (`dock-controls/icon-button.css:147`) paints. So the DockStack glyph reads at 14-16px against a library that ships a 20px nav-glyph register — the "not visible enough" defect, REGRESSED by the 0.875rem CSS down-size.
- **The receding facet fades to ZERO (no legibility floor).** `src/components/custom/dock/composables/railProjection.ts` `DEFAULT_GEOMETRY.fadeMinAlpha: 0` (`:81`) — so in `mode="facets"` a receding chip's `opacity` floors at `0` (the `projectFacets` fade: `opacity = adist === 0 ? 1 : baseAlpha * expand`, `baseAlpha` clamped to `fadeMinAlpha`). A facet two slots off the active reads INVISIBLE — the carousel's context icons vanish instead of receding-but-legible (the iOS-27 dock recedes the off-axis icons to a DIM read, never to nothing — they must stay reachable + identifiable).

The ask is: the DockStack icons READ — the glyph rides a ≥20px named register (off the bare `size-4`/0.875rem) and the receding facets keep a ~0.35 legibility floor (recede-but-visible), token-first, both modes.

## The mechanism

Token-first, two seams — a glyph token off the bare class + a fade FLOOR in the projection geometry. NO new component, NO magic numbers re-pinned at the consumer.

1. **Mint `--dock-stack-glyph` off the library register (the ≥20px floor).** Add `--dock-stack-glyph` to `stack-rail.css`'s `:root` token block (beside `--dock-stack-member-size`/`--dock-stack-gap`/`--dock-stack-stagger`, `:40-43`), declared `var(--dock-icon-glyph, 1.25rem)` — so the DockStack glyph INHERITS the SAME `--dock-icon-glyph` register (`sizing.css:240`, ~20px, `--dock-scale`-threaded + WCAG-floored) the nav-icon family already paints (the one-register discipline — NOT a DockStack-local magic number). Re-point the CSS: `.dock-stack-fan .dock-stack-member svg` (`stack-rail.css:251`) reads `inline-size: var(--dock-stack-glyph)` / `block-size: var(--dock-stack-glyph)` (DELETING the 0.875rem down-size — the clean break), and ADD a `.dock-stack-core svg` rule reading the SAME token (the core glyph today has no svg-size CSS, so it floats at the `size-4` Tailwind class — both glyphs now read the ONE token). In `DockStack.vue` the `class="size-4"` on both `<component>` glyphs (`:187`/`:234`) is DROPPED (the CSS token rule is the sole sizer — a Tailwind `size-4` utility beside the token rule is the dual-path the no-legacy law forbids; the CSS `dock-stack-fan svg`/`dock-stack-core svg` rules are `@layer components` and the bare utility would win, so the class MUST go). The token is `--dock-scale`-threaded by construction (it reads `--dock-icon-glyph`, which is); a consumer retunes the dock glyph family in ONE write (`--dock-icon-glyph` or `--dock-stack-glyph` override) — the token-first axis.

2. **Floor the facet recession opacity (~0.35 legibility floor).** Change `railProjection.ts` `DEFAULT_GEOMETRY.fadeMinAlpha` from `0` (`:81`) to a legibility floor `~0.35` (a named constant — the iOS-27 recede-but-visible floor; the off-axis facet recedes to dim, never to nothing). This is the ONLY geometry-default change (the `slotSpacing`/`tierRatio`/`scaleStep`/`fadeStart`/`fadeRange` are byte-untouched — the φ-tier spacing + the scale recession are correct; only the fade FLOOR was wrong). The floor multiplies through the SAME `projectFacets` math (`opacity = adist === 0 ? 1 : baseAlpha * expand`, `baseAlpha = min(1, max(fadeMinAlpha, faded))`) — so a fully-fanned receding facet floors at ~0.35 (visible), a collapsed facet still resolves `* expand → 0` (the fan still folds shut, the floor is the EXPANDED recession floor, not a collapsed-state leak). A consumer that wants a different recession depth passes a `geometry.fadeMinAlpha` override (the `RailProjectionGeometry` knob already exists, `:64` — this only moves the DEFAULT off the illegible `0`).

Both seams are token/geometry-first (no per-consumer magic number, no new component). Compositor-only by construction (the glyph size is a static `inline-size`/`block-size` on the svg — NOT an animated dimension; the facet opacity is the projection's compositor-only `opacity` channel — `proof:no-layout-animation` holds, neither seam animates a layout property). Both modes: the glyph register + the opacity floor are mode-agnostic (the `--dock-icon-glyph` token is one value across modes; the recession floor is a pure alpha) — the dark facet chip's accent rim + the floored opacity read in lockstep.

# BF.W-SCROLL-FLUIDITY — re-home the continuous-position slow-glide rail scroll onto DockStack

**Band 3 · Tier T6 · depends: W-DOCK-INTEGRATE**

## The defect / the ask

The audit's CHRONIC #4 (DEFERRED-CENSUS **D4**, `chronic ✓`; SEED §1 **R11** "Scrolling not fluid / not slow enough", status **REGRESSED**). The BE prototype's `useLiquidRail` carried a continuous-position SLOW-GLIDE scroll (a `SCROLL_PX_PER_SLOT` mapping — the rail glided fluidly between facet slots, slow and liquid, with a spring-snap to the nearest slot on release). WF-3 DELETED `useLiquidRail` wholesale (the clean-cut harvest-then-delete) and delegated the rail's overflow to the NATIVE `<FadingScroll>` port — which is a discrete native scrollbar (edge-feathered, but a plain native scroll, NOT the slow continuous-position glide + spring-snap the user asked for). So the fluid slow-glide the user wanted is GONE; the native scroll reads fast + discrete, the regression R11 names. Read the two:

- **The harvested math (the keepable, already on disk):** `src/components/custom/dock/composables/railProjection.ts` — the PURE φ-tier/ring projection harvested out of the deleted spike. `projectFacets(count, active, expand, geometry)` (`:97`) returns each facet's compositor-only `{ translate, opacity, scale }` off a CONTINUOUS `active` index (it accepts a FRACTIONAL `active` — `ringOffset(ringIdx - active, n)` and the `tieredSpan` accumulation are continuous in `active`), so the slow-glide is a matter of driving `active` continuously between integer slots and projecting — the math is ALREADY there. STATELESS (no spring, no rAF, no DOM measure — the header is explicit: "DockStack already speaks the ONE `--spring-dock` clock; the facet mode rides the dock's own CSS spring, NOT a re-forked JS spring").
- **The current DockStack scroll (the discrete native port):** `src/components/custom/dock/DockStack.vue:174-218` (the `<FadingScroll :axis>` port). `scrolls` (`:130`) routes the >`visibleCount` fan through `<FadingScroll>` — a NATIVE scroll-port (edge-fade only). The facet projection (`:147`) is computed at a HARDCODED `expand: 1` (`projectFacets(members.value.length, activeFacetIndex.value, 1)`) — a STATIC layout, never a continuous-position glide. There is no continuous `active`-glide, no spring-snap-to-nearest.

The ask is: the rail scrolls FLUIDLY — a slow continuous-position glide between facet slots (the deleted `SCROLL_PX_PER_SLOT` feel) with a spring-snap to the nearest slot on release — re-homed onto `DockStack` as a compositor-only OPT-IN BESIDE `<FadingScroll>` (NOT a re-fork of the scroll port, NOT a re-minted JS spring engine).

## The mechanism

Re-home the slow-glide as a continuous `active`-driven projection over the EXISTING `railProjection` math + the EXISTING `--spring-dock` clock — an OPT-IN mode on `DockStack`, beside (not replacing) `<FadingScroll>`.

1. **The `glide` opt-in axis (beside FadingScroll, not a re-fork of the port).** Add `scrollMode?: "fade" | "glide"` to `DockStack` (default `"fade"` — the current native `<FadingScroll>` path, byte-identical). `"glide"` is the re-homed slow-glide: the fanned strip is positioned by the CONTINUOUS-`active` projection (a `transform: translate` per facet off `projectFacets(count, activeContinuous, expand)`) instead of routed through a native scrollbar. The `<FadingScroll>` port STAYS for the `"fade"` mode (no deletion — it is the right primitive for a plain overflow); the glide mode is the OPT-IN second axis the user asked for. NO second component, NO re-forked scroll port.

2. **The continuous-position glide (the `SCROLL_PX_PER_SLOT` feel, re-expressed).** A wheel/drag delta on the rail moves a CONTINUOUS `activeGlide` ref (a fractional slot position) at a SLOW rate (the `--dock-rail-px-per-slot` tunable — the deleted `SCROLL_PX_PER_SLOT` re-homed as a token, default ~80px/slot so the glide reads slow + liquid). `projectFacets(count, activeGlide, expand)` re-projects every frame off the fractional `activeGlide`, so the facets GLIDE continuously (the `translate` is continuous in `activeGlide` via `tieredSpan` — the φ-tier slots flow past, never snap-jump). The drive is the pointer/wheel delta → `activeGlide` (no rAF loop owned here — the projection is a pure render-time computed off the ref, the DockStack render re-runs on `activeGlide` change; the `--spring-dock` CSS clock smooths the per-facet transform settle, the macOS-stack discipline `railProjection.ts` documents).

3. **Spring-snap-to-nearest on release (the SHIPPED clock, no re-fork).** On wheel/drag END, snap `activeGlide` to the nearest integer slot via the EXISTING dock spring — compose `useDragMorph` (`src/composables/motion/useDragMorph.ts:153`) with the facet slots as snap targets (the fling-to-nearest single-commit `onSnap` writes `selected` + seats `activeGlide`), OR drive the snap through the dock's `--spring-dock` token directly (a CSS-transition over the projected resting transform — the `railProjection.ts` header's stated discipline). The snap REUSES `DOCK_SPRING`/`--spring-dock` (the W-GLASS-CAL spring fence — NO re-minted `useLiquidRail` JS spring, the clean-cut the spike-delete enforced; a re-forked `SpringProgress` loop in DockStack REDs). The `onSnap` writes the consumer-owned `v-model:selected` (the ONE registry — no shadow active state).

4. **Wire the dead `expand` projection arg (the W-RAIL-FIDELITY adjacency).** The continuous-position glide is the FIRST real consumer of `projectFacets`'s continuous `active` (today hardcoded `expand: 1`, `active` = the integer `selected` index). The glide passes the fractional `activeGlide` and the live `expand` (the fan progress) — so the φ-tier projection math finally drives a continuous read (the D15 dead-math adjacency; W-RAIL-FIDELITY owns the `expand`-fan wiring, this wave owns the continuous-`active` glide — disjoint reads of the SAME pure function).

Compositor-only throughout (the glide is `transform: translate` + `opacity`/`scale` off the projection — `proof:no-layout-animation` scans `src/styles` + `src/components` + `demo/stories/**`; the rail position is a transform, NEVER an animated `scroll-left`/`inline-size`). PRM-carved: under `prefers-reduced-motion: reduce` the glide SNAPS to the nearest slot with zero glide frames (the projection seats at the integer `active`; `useDragMorph`/the spring snap carries the PRM instant-commit) — the slow-glide motion is non-essential, dropped under reduce, the selection still commits.

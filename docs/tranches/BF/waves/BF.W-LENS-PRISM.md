## The mechanism

The chromatic rim is a PER-CHANNEL displacement split in the SVG filter graph — the SAME squircle bevel map, displaced at THREE slightly-different magnitudes (R less, G mid, B more — the dispersion ordering), then re-composited per-channel. It composes the shipped `.glass-lens` seam; it edits ONLY the SVG filter data-URI + the `@property` axis, never a GL shader, never the squircle CURVE (the map stays the baked Apple-preferred profile).

1. **The filter-graph evolution — three per-channel displacement passes (`src/styles/glass-refract.css`, the `--glass-refract-filter` data-URI).** The shipped graph's single `feDisplacementMap` (`scale='28'`, displacing SourceGraphic by the squircle map) is evolved to the dispersion chain — the canonical SVG chromatic-aberration recipe (the wavelength-split the `feDisplacementMap` + `feColorMatrix` channel-isolation idiom encodes):
   - **Isolate each channel** off the SourceGraphic with three `feColorMatrix` channel selectors (R-only, G-only, B-only — the standard channel-mask matrices).
   - **Displace each by the SAME squircle map at its OWN scale** — `feDisplacementMap scale='<base - δ>'` for R, `scale='<base>'` for G, `scale='<base + δ>'` for B (the dispersion: blue bends most, red least — n_blue > n_red). The split magnitude δ is the dispersion amount.
   - **Re-composite the three displaced channels** with `feBlend mode='screen'` (additive channel recombination — `screen` over black recovers the full color where the channels align, and FRINGES where they diverge at the steep rim, which is exactly the prismatic edge).
   - The existing `feImage` specular catch-light + the final `feBlend screen` are PRESERVED (the polished-glass highlight is untouched — dispersion adds the rim fringe, never removes the catch).
   The whole graph stays ONE self-contained data-URI `url("data:…")` token (the DDR-LENS-BAKE discipline — bundler-safe, parses as a `backdrop-filter` value); the squircle MAP is byte-reused (the dispersion is the SAME map at three scales, NOT three maps — the rim concentration is the squircle's, the split is the scale-delta).

2. **The `--glass-edge-dispersion` axis (the dispersion-amount knob).** A new token `--glass-edge-dispersion` (default the iOS-faint whisper — a small δ in the [0, ~6px] band off the base `scale='28'`, so the fringe is a subtle prismatic hairline at the rim, NOT a neon rainbow blowout — the §6 calm register / warm-cream identity). At `--glass-edge-dispersion: 0` the three scales collapse to the SAME base scale and the graph reduces to the ACHROMATIC shipped lens BYTE-IDENTICAL (the no-op floor — dispersion off === today's lens). **The DDR-LENS-BAKE constraint inherited (binding):** a `feDisplacementMap scale` cannot be CSS-`var()`-driven inside a self-contained data-URI (CSSWG #542 — proven on the real Chromium edge: a var()-spliced `scale` emits a multi-token `url(…) <n> url(…)` a `backdrop-filter` rejects, AND breaks the bundler url()-rewriter). So `--glass-edge-dispersion` is a DOCUMENTED knob with the dispersion δ BAKED into the shipped graph at the default whisper (the lived value), and a consumer who wants a different δ re-bakes via a successor variant — the EXACT tradeoff the shipped `--glass-refract-bevel` knob already records (the knob documents the encoded magnitude; the data-URI bakes the literal). The token is the SEMANTIC axis name the SEED requires; the baked literal is the rendered value (mirroring `--glass-refract-bevel: 14%` documenting the baked `28`-scale rim band).

3. **The whole thing rides INSIDE the shipped `@supports (backdrop-filter: url(#…))` block.** The dispersion is a Chromium-supported `backdrop-filter: url()` graph (WebKit bug 245510 keeps `backdrop-filter: url()` off Safari — the SAME gate the shipped lens already sits behind). A non-supporting engine NEVER reaches the dispersion block and paints the un-gated `--glass-blur-*` + `--glass-tint-*` base ALONE (the no-broken-`url()`-reference degrade floor, PRESERVED — the prism is progressive enhancement over the blur base, never the sole rim). **Safari fall (the §6 matrix, recorded):** Safari paints the blur + tint base + the `.glass-material::before` rim glint (the achromatic edge-glint, untouched); the chromatic FRINGE is the Chromium-only refinement. The `safari-support-matrix` row (W-SAFARI-CAPTURE) records: lens-prism · Safari-26 status `backdrop-filter: url() UNSUPPORTED` · degrade fall `blur + tint + ::before edge-glint (achromatic rim)`.

4. **The GL-fence (ABSOLUTE) + the rim-color disjointness.** The dispersion is the SVG `backdrop-filter: url()` graph — ZERO `aurora.frag`/`metaball.frag`/`*.wgsl`/`procedural-color.*` edit (the §7 GL color-seam is a DIFFERENT axis — the in-shader OKLCh path; this is the CSS filter graph). The chromatic rim is DEPTH-dispersion (a per-channel displacement of the BACKDROP), NOT a hue INJECTION — it carries no color of its own (the fringe is the page's own backdrop split by wavelength, the warm-cream identity HOLDS — the rim does not paint a rainbow, it disperses what is already behind). It COMPOSES W-LENSING's geometry: the squircle map + the `--glass-refract` axis + the `.glass-lens` class are reused; the dispersion is the per-channel split ON the existing displacement, file-line-disjoint from the `.glass-material::before` specular/edge-glint (W-LENSING owns the glint GEOMETRY, this owns the displacement SPLIT).

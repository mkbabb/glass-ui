## What a KEYSTONE SPEC is

Each hallmark gets ONE perfected spec at `docs/tranches/BG/keystones/KS-<NAME>.md` that becomes the
BINDING detailed spec for its named plan waves (the folded cursor ids — the wave SET is frozen by the
audit; these specs perfect the CONTENT, they do not restructure). Every spec carries:
1. **The hallmark delineated** — what this signature IS, stated as identity (the bar a stranger would
   recognize the library by).
2. **SOTA grounding** — live web research (named references, techniques, the 2026 state of the art) +
   the existing corpus (BUILD on it, never re-derive).
3. **First-principles design** — the greenfield loop applied: ≥3 brainstormed directions → the GOLDEN
   choice with rationale → self-challenge (what breaks it, what's contrived about it) → the final form.
4. **Wave binding** — the exact cursor ids this spec details, per-wave deliverable deltas (what the
   perfected spec ADDS/SHARPENS vs the folded row), preconds untouched.
5. **Precepts conformance** — explicit checks against `docs/precepts/` (design-idioms, motion-canon,
   tunable-anim) + the folded cross-cutting rules (overhead floor; gates as family arms; Fable arm +
   DesignSync surface per visual wave; compositor-only + PRM; clean breaks; ≥2-consumer; warm identity).
6. **The gestalt bar** — the acceptance language (√φ proportion · animation laws · technicolor
   cartoon-punch · SUBTLE-where-subtle) this hallmark's paint verdict is judged by.

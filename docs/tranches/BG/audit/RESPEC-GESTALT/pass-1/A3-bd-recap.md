sessions, driven by a first-principles greenfield-hardening framework (brainstorm-3 → golden →
challenge-3 → delta-assay → wave-amendment per item), grounded in frame-by-frame video audits

substrate size-unify, ScrollCard) is real on disk and the greenfield's "union-not-fork" thesis

**And yet BD is the single tranche the user's "disastrous" verdict indicts hardest** — because BD

The failure was NOT the primitives; it was three compounding things: (1) **the integration/shell

compositions were NEVER audited to convergence — ~52 of 156 pages got a full 3-context synthesis).

The good news for BG: the P-bd-coverage RE-DO waves (route-transition, field-aurora, hero-fit,
persistent-cut, in-place-morph) are **already landed on `tranche/BG`** (26 DONE rows; commits

## The five critique axes — where BD's shipped work fails them

1. **Missing obvious issues.** The route-transition freeze (`AppShell.vue` three coexisting
   mechanisms: `<Transition>` + `.scroll-build` mount-animation + a bloom-find-child DOM hack + two
   no-op VT watchers) hid EVERY shipped page — a defect any developer opening the app sees in one
   nav. It shipped behind a 356-gate green close. This is the cardinal headless-green/visually-broken
   gap at tranche scale (`P-bd-coverage.md` root cause #1).

2. **Gestalt cohesion.** `TRANCHE-GESTALT-META.md §1` names the systemic ONCE: "the COMPONENTS are
   architecturally sound (~90%); the DEMOS are spec-sheets (~22%)" — N locally-correct patches, not
   one designed product. The metallic page-field vs the wanted-aurora, the hero-over-scale
   inverting its own directive, and the modal-morph-vs-in-place all read as *locally-plausible
   decisions that violate the whole*. The best evidence is `TRANCHE-GESTALT-META §3.1`: the
   "buttons-invisible" defect is ONE root (glass-over-flat is invisible-by-construction), which the
   audits treated as N separate symptoms.

3. **Over-contrivance.** Two flavors. (a) In the SHIPPED product: the AppShell route trio; the
   `heroScale ≥ 4` FLOOR forcing audacious-tier (352px) on every hero. (b) In the PROCESS: the Band-E
   "consistency gate" was a string-presence `re.test` never summed into exit code (`P-bd-coverage`
   Band-E "fake-gate-fraud self-finding") — a ceremony gate that certified nothing, which is *why*
   356-green ≠ working UX. The greenfield engine's own §6 ledger honestly measured Band-C at ~70%
   then closed the 30% on paper.

4. **Poor encapsulation.** `AppShell.vue` reaches into `[...main.children].find(c =>
   !c.classList.contains("section-landing-skeleton"))` — the shell parsing page-internal class names
   to find a bloom target (`P-bd-coverage` finding #1). The persistent-ℱ + `f-redraw` Fourier
   easter-egg wove demo-brand chrome into the layout shell. `forms-inputs-SYNTHESIS` documents the
   inverse: the W-PRESS-UNIFY/W-LIQUIDHOVER registers wired onto Button+dock never REACHED the
   `.input-pill` (a 3-of-6-layer composite) — encapsulation gaps in BOTH directions.

5. **Lacking elegance.** The static-metallic `.paper-field` (`paper.css` conic cel-sheen + 4
   high-chroma radials + feTurbulence speckle + a 42s `field-cel-drift`) was an *accreted* composite

   simpler architectural transposition (one offscreen-paused `<Aurora>` per route) exists. BG's
   `BG.W-FIELD-AURORA` is exactly that transposition; BD shipped the accretion.

## The sharpest un-carried finding — the AX.W54 glass-first over-reach

`TRANCHE-GESTALT-META §3.3` (BD's own second-eyes challenge) raises the architectural-transposition
question the user explicitly invited: **is the glass-first MAXIMAL default (AX.W54 — glass is the
maximal default for EVERY surface) itself over-reached?** CLAUDE.md AX.W54 admits "the glass blur is
imperceptible over a flat substrate." So glass-everywhere-without-a-colorful-backdrop is
invisible-by-construction — the DOMINANT user frustration ("buttons largely invisible," the gray
glass). The fix is three-fold and BD only ever prescribed the first: (a) warm the glass (necessary,
insufficient); (b) a MANDATORY colorful field behind every glass surface; (c) a DEFINED-EDGE floor
so a control reads as a SHAPE over ANY backdrop. **Grep confirms NO BG wave carries the
over-reach question or the defined-edge-default transposition** (only the incidental
`GLASS-CONSUMER-BAND`/`GLASS-DYNAMICS`/`GLASS-SOTA-LADDER` retire-matrix waves, none of which asks
whether the default control should carry more definition). This is the single most load-bearing
first-principles question in the whole lineage and it has no home.

## FOLD CANDIDATES (concrete, for the BG/BH plan)

### 1. NEW-WAVE — `BG.W-GLASS-DEFAULT-DEFINITION` (the AX.W54 over-reach transposition) [CRITICAL]
The idiomatic architectural transposition BD's own §3.3 invited and no wave carries. **Gestalt
approach, not a patch:** split the glass register into TWO tiers on the ONE `--glass-level`/edge
machinery — a *transmissive* tier (the current maximal glass, for surfaces that HAVE a colorful
backdrop) and a *defined* tier (a stronger rim + a floor fill + the W-BUTTON-GLASS lit register)

backdrop. Pairs with the (now-landed) mandatory field-aurora so transmissive glass finally has
something to bend. Gate: computed-contrast of a default `<Button>`/`.input-pill` over a *flat* page

# tunable-anim — the tunable-animation registry (the one motion-tuning index)

Motion in glass-ui is a TUNABLE surface, not a fixed black box. There is ONE
registry — this file — that names every animatable axis: each is a TOKEN a
consumer (or a live demo control) can re-tune, watch update in real time, and read
back as a re-parseable value. The library's OWN tokens ARE its motion identity
(presets-in-consumers); a consumer re-themes the whole feel from a handful of
documented tokens (`--spring-<name>`, `--scale-hover-*`, …). This is the index the
viz studios (`BC.W-VIZ-CONFIGURATOR-SUITE`) + the `/motion` storybook read.

`proof:tunable-anim` reads the binding tables below: a token in the registry must
RESOLVE in source (T2), a tunable axis has ONE re-tune authority (T4), the live
controls compose the REAL value.js/keyframes.js math (T3 — the boundary law), and a
new animatable axis cannot ship un-indexed (T1, anti-gameability). The registry is
the single index — gate + canon single-sourced.

## The brainstorm — the five tunable kinds

Every animatable axis is ONE of five kinds. The brainstorm names, per kind, the
AUTHORITY (where the value lives), the RE-TUNE path, and whether it carries a LIVE
control:

1. **SPRING shape** — a `(response, ζ)` pair. AUTHORITY: the ONE `SPRING_PRESETS`
   table (`src/composables/motion/spring/springPresets.ts`) → the CSS `--spring-*`
   `linear()` generated by `regen-spring-tokens.mjs`; JavaScript consumers pass the
   same row directly to an upstream keyframes.js primitive. RE-TUNE: edit the ONE
   table (library identity, `BC.W-SPRING-EASE`) OR override `--spring-<name>` on an
   instance (consumer). LIVE control: a `(response, ζ)` editor → a live spring
   preview composed from `SPRING_PRESETS` and keyframes.js (never a hand-rolled
   spring).
2. **CLOCK** — the per-spring settle duration `t_s = −ln(0.02)/(ζ·ωₙ)`. AUTHORITY:
   DERIVED from the spring's own `(response, ζ)`, generated. RE-TUNE: NEVER
   hand-set (truncating re-introduces tail-jank — the W-GLASS-CAL fence). NO live
   control — the registry exposes it READ-ONLY (a "tune the clock" control is
   forbidden).
3. **EASING curve** — a bezier / steps curve. AUTHORITY: the CSS `--ease-*` tokens
   and direct `@mkbabb/value.js/easing` callables (`bezierPresets`, `jumpTerms`,
   `CSSCubicBezier`, `steppedEase`). RE-TUNE: the `<EasingPicker>` live authoring
   chassis OR override `--ease-<name>` (consumer). LIVE control: the draggable
   bezier handles + the steps staircase + the live steppedEase `n + jumpTerm`
   generator.
4. **AFFORDANCE magnitude** — the hover/press scales + caps. AUTHORITY: the
   affordance-map (`scale-paper.css`; `BC.W-AFFORDANCE-MAP`). RE-TUNE: the token
   (consumer override on an instance). NO live control (the proportion fence —
   these are the affordance-map's, not a debug overlay); the registry INDEXES them
   with their anti-taffy bounds.
5. **REVEAL/MORPH drive** — the `@property`-registered 0..1 drive scalars + the
   scroll-choreography knobs. AUTHORITY: the spring under them (kind 1) + the
   per-instance token. RE-TUNE: the spring + the per-instance token. The registry
   indexes the drive scalars + their default + their range.

## Kind 1 — SPRING shape

The single authority is the `SPRING_PRESETS` table; the registry INDEXES it. CSS
`--spring-*` curves are generated from it, and JavaScript passes the same rows to
keyframes.js directly. There is no reverse token-to-callable table.

| spring | token | default (response, ζ) | bound (overshoot) | re-tune | PRM | live control |
|---|---|---|---|---|---|---|
| smooth | `--spring-smooth` | 0.5, 0.86 | ≤0.02 (kept sub-perceptual alive-peak) | table (identity) or `--spring-smooth` override | snap or intensity-scaled | the spring editor preview |
| snappy | `--spring-snappy` | 0.42, 0.78 | ≤0.08; 90%-travel ∈ [0.55,0.70] of clock | table or override | snap | preview |
| bouncy | `--spring-bouncy` | 0.5, 0.55 | ∈ [0.12,0.18] (the Apple band) | table or override | snap | preview |
| gentle | `--spring-gentle` | 0.7, 1.0 | 0 (critically-damped, no overshoot) | table or override | snap | preview |
| dock | `--spring-dock` | 0.68, 0.64 (BD.W-ANIM-IOS27-TUNE weighty-gooey) | ≤0.08 (+7.3% liquid overshoot) | table (`springPreset("dock")` — ONE row, no fence) | snap | preview |
| press | `--spring-press` | 0.15, 0.86 (iOS interactiveSpring) | ≤0.08 | table or override | snap (zero transform frames) | preview |

## The named-FUTURE axis (recorded, not built — the proportion fence)

The live `linear()` multi-stop editor: value.js `cssLinear(stops)` is shipped, but
the live multi-stop-drag editor exceeds the gallery-card register (deferral/az.md
item 12 — "hold-with-rationale if it exceeds the gallery register"). Recorded here
as a FUTURE EASING-kind (kind 3) axis with its token-home named (a `--ease-*`
authored from a multi-stop `linear()`), NOT built this wave.

## The live controls (the boundary law)

The boundary law (CLAUDE.md W-EASING-PRIMITIVE): curve MATH = value.js · playback /
spring = keyframes.js · the editor COMPONENT = glass-ui. Every live control COMPOSES
the real math — it re-implements NONE:

- **bezier editor** — reads value.js `CSSCubicBezier` (through `useEasingPicker`).
- **steps generator** — the `n` `<Slider>` + the 7-term `<Select>` drive value.js
  `steppedEase(n, term)` + `jumpTerms`; the `steps(n, term)` readout round-trips
  through value.js `parseSteps` (re-parseable). NO re-implemented staircase
  evaluator.
- **spring preview** — passes `SPRING_PRESETS` rows directly to keyframes.js; NO
  hand-rolled spring and no Glass republishing of the engine.
